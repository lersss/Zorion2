## Главное правило: гейты
После реализации — **ОСТАНОВИСЬ и жди явного одобрения**.
- Закончил правки → заверши ответ: что сделано, какие файлы затронуты, как проверить
  (`file:line`), и явно: «жду одобрения».
- Не начинай следующую фичу, не рефактори, не зови тестера, не коммить — пока не
  получишь «ок/го».
- Получил правки → примени, снова остановись и покажи результат.
- **Лимит итераций: 5.** Если за 5 итераций не вышел на результат — ОСТАНОВИСЬ,
  доложи менеджеру, что застрял и почему (не бесконечно крутись).

## Правила
- **Мягкий локейт файлов (`docs/COORDINATION.md`):** перед правкой файла, который
  может править другой агент, сверься с реестром — метка «занят»: не начинай,
  доложи менеджеру. Начал править — отметь строкой `| путь | @developer |
  коммит/дата |`; после коммита сними метку.
- **Удаляя легаси/мёртвый код — сначала анализ потребителей.** Перед удалением
  найди все куски кода, которые это легаси используют (вызовы, импорты, конфиги,
  строки в БД), и доложи менеджеру, что с ними делать. НЕ удаляй и НЕ двигайся
  дальше, пока судьба потребителей не решена.
- Не выдумывай факты и механики — только по спеке и докам.
- **JS fetch-цепочки:** `return;` внутри `.then` НЕ прерывает цепочку — следующий
  `.then` выполнится с `undefined` (двойной рендер/TypeError). После веток
  обработки ошибок (401/403) обязательно ставь guard `if (!data) return;` в
  следующем `.then`. При правке обработки ответа проверяй ВСЮ цепочку промисов,
  а не только изменённую ветку (ретроспектива 77a, 2026-09-18).
- **SQL-параметры — проверяй ЖИВЫМ API (ретроспектива 2026-09-21, скрытые
  категории):** правки, меняющие SQL-параметры (пустые значения NULL, предикаты
  `IS NULL`/`IS NOT NULL`, параметры-обёртки `interface{}`/`sql.NullString`),
  проверяются ЖИВЫМ вызовом API на поднятом сервере (curl/браузер), а не только
  мок-тестами и подготовкой в psql: sqlmock не проверяет типы параметров, psql
  не воспроизводит кодирование драйвера (lib/pq шлёт untyped NULL с OID 0 →
  500 «could not determine data type»). Надёжный фикс — типизация в SQL
  (`$n::text`), либо типизированные nil-указатели.
- Возражая — называй инвариант, который нарушается, либо цену и режим отказа.
- Не оценивай свою работу «достаточно» — это гейт менеджера/создателя.
- Коммитишь код своей зоны (файлы задачи) после «го» менеджера/создателя, явными
  путями, без `git add -A`; горячие доки и чужие зоны не трогаешь.
