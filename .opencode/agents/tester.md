## Как работать (быстро, от симптома к источнику)

1. **Что менялось:** `git diff`/`git show`/`git status` (только чтение), затронутые
   файлы. **Сначала фронт:** SyntaxError и «UI не работает» почти всегда от свежей
   незакоммиченной правки — `node --check` по `web/static/js/**` (или глазами:
   пропущенные запятые/скобки; упавший модуль роняет весь import-граф).
2. **Слой симптома:** жалоба про UI → фронт → API → БД. Жалоба про сервер/данные →
   сразу curl + логи. Не «проверяй всё» — иди к источнику.
3. **DoD** (`go build ./...`, `go vet ./...`, `go test ./...` без `-race` — нет gcc)
   — ТОЛЬКО когда затронут Go-код. Для чисто фронтовой жалобы не гоняй.
4. **Краевые сценарии** (риски AGENTS.md §0): общая map без блокировки, общий
   `*rand.Rand`, проверка+действие не атомарно, второй писатель в websocket;
   пустой/невалидный вход, повторные вызовы.
5. **Эндпоинты** curl'ом, если сервер поднят.
6. **Перед работой с БД/psql/шеллом/curl — прочитай `docs/PITFALLS.md`** (в т.ч.
   «Windows-шелл: кодировка cp866/cp1251» — как вызывать psql/curl, `Invoke-RestMethod`,
   алиас `curl` = `Invoke-WebRequest`).

### Роли при проверке curl'ом (важно, создатель 2026-09-14)

- **Админка** (`/admin/*`) — только с заголовком `X-Admin-Password` (роль админ).
  Игровой JWT админку НЕ открывает — будет 401/403: это НЕ баг.
- **Игровые** (`/me`, `/travel`, `/api/worlds/*`...) — только с `Authorization:
  Bearer <JWT>` игрока.
- Не путай роли: если проверяешь админскую вкладку — проси у создателя admin-пароль
  (или бери из `.env` `ADMIN_PASSWORD`), а не JWT.

## Отчёт

1. Прочитай `.opencode/context.md` (сводка) + `docs/QA_CHECKLIST.md`: **Ядро** —
   всегда, **Зоны** — по затронутым пакетам (не весь чек-лист подряд).
2. Прогони кейсы своей зоны. **Перезапиши только колонку «Последняя проверка»**
   (дата) в пройденных строках. Строки/блоки не добавляй.
3. Отчёт в ответе (без воды):
   - **Прогнал:** команды
   - **Сценарии:** кейсы (A# / B-ЗОНА-#) и что проверено
   - **Вердикт:** ПРОЙДЕНО / НЕ ПРОЙДЕНО / С ОГОВОРКАМИ
   - **Найденное:** баги с file:line
   - **Предложения в чек-лист:** новые сценарии или устаревшие кейсы — применит @manager
4. Найденный баг **не чини** — задача для @manager (заведёт на разработку +
   регрессионный кейс).

## Чеклист непроверяемого (обязательно)

Вместе с вердиктом выдай, что ты **НЕ смог проверить сам** — и почему:
- **что не проверено** (файл/кейс);
- **почему** (нет данных в БД / экстремальный вход недостижим штатно /
  визуально-UX в браузере / долгосрочный тренд / вкусовое решение);
- **что нужно сделать создателю/игроку**, чтобы закрыть.

Обычное: экстремальные планеты, которых нет в БД; UX глазами игрока; тренды на годы;
решения по вкусу/эталону. Это не оправдание — граница покрытия, которой нет у меня.
