## 3. Что дальше

Порядок по соотношению «риск / стоимость»:

1. **Бэкапы БД** — `pg_dump` по расписанию. Таблица `users` с паролями уже терялась однажды (см. `AGENTS.md` §8). До любого роста нагрузки.
2. **CI** (`.github/workflows/ci.yml`): `go build` + `go vet`. Сейчас CI нет вообще. `go test -race ./...` из DoD локально не запускается — нужен cgo, gcc в PATH нет. Тесты уже есть (`generator/planet`, `generator/galaxy`, `repository`, `handlers`, `auth`); `-race` на них гоняется только на CI, которого нет. См. §4.
3. **Нагрузочный тест** — 100 синтетических клиентов на `/ws`, `/travel`, `/api/contracts`. Рекорд по реальным игрокам — 7, почти наверняка не одновременно. Пока теста нет, «многопользовательская игра» ничем не проверена.
4. **Убрать перемещение из дашборда** — убрать блок/кнопку перемещения с дашборда.
5. **Попап звезды** — при открытии сейчас сразу показывается список планет. Перенести его в инфо по звезде (компактно, можно второй колонкой рядом с информацией о звезде); если планета не выбрана — показывать инфо по звезде (в т.ч. по клику в пустое пространство).
6. **Градации цвета звёзд на карте** — оттенки по светимости с небольшим разбегом, чтобы визуально различать звёзды одного спектрального класса.
7. **Плотность звёзд к краям карты** — чем ближе к краям, тем плотность должна снижаться (сейчас края не разрежены).
8. **Переход на новую ресурсную модель** — дизайн переработан и зафиксирован (`docs/gamedesign/05_economy.md` и семейство). План работ, предпосылки (B9, B11, две таблицы ресурсов) и чем проверять — `docs/gamedesign/99_roadmap.md` §99.2.5. Блокируют два вопроса из `05_economy.md` §5.5 (состав осей свойств) — решить до кода.

Долгосрочный бэклог — `docs/gamedesign/99_roadmap.md`.

## 4. Открытые решения

- **`-race` в definition of done.** `AGENTS.md` §2 называет его основным инструментом против риска из §0, но локально он не запускается — нужен cgo, gcc в PATH нет. Тесты при этом есть в 11 пакетах и проходят. Ставить mingw локально или оставить `-race` только в CI?
- **Стратегия скоупа.** Обсуждалось, решения нет: резать ли roadmap (LLM-описания, аномалии как контент, расширение описаний, константы в админку) в пользу вертикального срезa игровой петли `контракт → полёт → добыча → сдача → мир изменился`. Аргумент: вселенная уже готова (100k миров), а контракты существуют как `/api/contracts/complete-test`.
- **`.env` в истории git** (`5253b8c` → `44e3cfc`). Чистить историю или просто ротировать креды? Практично второе, и это совпадает с B6.
- **Блок «корабли/полёты»** — фиксировать в GDD или оставить как есть?
