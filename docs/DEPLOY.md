# Как развернуть сервер Zorion

> Пошаговая инструкция: от нуля до рабочей игры. Если правка в коде затрагивает
> полноценное развёртывание — добавляй пункт/поправляй этот документ.

**Обновлено:** 2026-09-15

---

## 1. Переменные окружения

| Переменная | Обязательность | Дефолт | Описание |
|---|---|---|---|
| `DATABASE_URL` | **обязательна** | — | PostgreSQL, `sslmode=disable`. Пример: `postgres://zorion:zorion123@127.0.0.1:5432/zorion?sslmode=disable` |
| `REDIS_URL` | **обязательна** | — | Redis. Пример: `redis://localhost:6379` |
| `JWT_SECRET` | **обязательна** | — | Минимум 32 байта. Без неё сервер падает на старте |
| `TICK_INTERVAL_SEC` | необязательна | `3` | Интервал игрового тика (секунды) |
| `SKYCOMPOSER_BOOTSTRAP_USERNAME` | необязательна | — | Создаёт первого skycomposer'а при старте, пока их 0 в БД |
| `SKYCOMPOSER_BOOTSTRAP_PASSWORD` | необязательна | — | Пароль первого skycomposer'а |
| `BALANCER_PRESETS_FILE` | необязательна | `config/balancer_presets.json` | Путь к JSON-файлу пресетов кривых балансировщика (99.2.17). Файл пишется из админки («Сохранить как пресет»), читается при старте (активные пресеты переживают рестарт). На проде задать путь в место с правом записи (config/ может быть read-only) |
| `SERVER_PORT` | необязательна | `8080` | Порт HTTP |

Прод задаёт env через панель Amvera. Локально можно через `.env` в корне проекта (godotenv) или через терминал.

## 2. Локальный запуск

### Требования

- Go 1.21+, PostgreSQL 15+, Redis 7+
- PostgreSQL: слушает `127.0.0.1:5432` (путь: `C:\pgsql\pgsql\bin`)
- Redis: `127.0.0.1:6379`

### Шаг 1 — Задать переменные

```powershell
$env:DATABASE_URL = "postgres://zorion:zorion123@127.0.0.1:5432/zorion?sslmode=disable"
$env:REDIS_URL    = "redis://localhost:6379"
$env:TICK_INTERVAL_SEC = "3"
```

`JWT_SECRET` вручную не задавать — берётся из `.env` в корне проекта (godotenv) или через `run.ps1`. Свой секрет вручную перекрывает `.env` и делает невалидными все ранее выданные токены — у всех залогиненных «сессия истекла» (идея 58a).

### Шаг 2 — Запустить

```powershell
go run cmd/server/main.go
```

Сервер apply'ит миграции автоматически при старте (вшиты в бинарник), создаст первого skycomposer'а если заданы `SKYCOMPOSER_BOOTSTRAP_*` и он единственный.

Проверка: `curl http://127.0.0.1:8080/health` → `OK`.

## 3. Прод (Amvera)

### Как работает деплой

1. `git push origin master` → Amvera подхватывает последний коммит.
2. Собирает образ по `Dockerfile` (golang:1.21-alpine → alpine:latest, порт 8080).
3. Бинарь стартует → автоматически apply'ит миграции к прод-БД → bootstrap skycomposer.

**Stamina mount:** `/tmp` (персистентный). БД внешняя PostgreSQL Amvera.

### Проверка после деплоя

```
https://zorion-game-skycomposer.amvera.io/health     → OK
https://zorion-game-skycomposer.amvera.io/status     → All systems ready
```

## 4. Первичная настройка прод-БД

После первого деплоя (или при чистой БД) — зайди в админку (`/admin.html`) и последовательно:

### 4.1 Генерация вселенной

Вкладка **🌌 Генерация** → сгенерируй звёзды и планеты.

### 4.2 Генерация кораблей

Вкладка **🚀 Корабли** → на каждой из 5 категорий (Корпус, Нос, Крылья, Двигатели, Хвост) нажми **＋10** (минимум 10 форм на категорию, спека 99.2.15).

Детали генерируются на бэкенде, каталог в памяти перезагружается автоматически — рестарт сервера **не нужен**.

### 4.3 NPC-агенты (по надобности)

Вкладка **👁️ NPC** → генерация.

### 4.4 Тестовый пользователь

На проде зарегистрирован `amvera_test` (удаление не предусмотрено).

## 5. VACUUM (ANALYZE)

После массовой перегенерации карты видимости деградируют (фильтры по
`planets.data`: 63 → 306 мс). `VACUUM (ANALYZE)` нужно делать **руками**
напрямую в БД — миграцией нельзя (не идемпотентно, не работает в транзакции).

**Когда:** событийно, после каждой массовой операции, переписывающей `planets` —
генерация вселенной, очистка, регенерация планет по мирам, большой прогон
«близнецов» в проверке гипотез. Единичные операции не требуют. Не уверен —
замерь фильтр карты: деградировал (300 мс) — пора, вернулся к 63 мс — хватило.

**Как на Amvera:** встроенной SQL-консоли нет; внутренние имена
(`…-cnpg-…-rw`) доступны только внутри кластера. Вариант A: в панели у БД
создать **домен типа POSTGRES** («Сетевое взаимодействие») и подключиться
локальным клиентом с SSL (`psql "<url>"` по домену `<project>-<user>.db-msk0.amvera.tech`,
sslmode=require; pgAdmin ≤ 8.12 или DBeaver). Вариант B: развернуть **pgAdmin**
как преднастроенный сервис («Утилиты для баз данных»), Host = внутреннее имя
`…-rw` со страницы «Инфо» СУБД. В обоих — `VACUUM (ANALYZE) planets;` вне транзакции.
