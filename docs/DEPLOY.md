> полноценное развёртывание — добавляй пункт/поправляй этот документ.

## 1. Переменные окружения

| Переменная | Обязательность | Дефолт | Описание |
|---|---|---|---|
| `DATABASE_URL` | **обязательна** | — | PostgreSQL, `sslmode=disable`. Пример: `postgres://zorion:zorion123@127.0.0.1:5432/zorion?sslmode=disable` |
| `REDIS_URL` | **обязательна** | — | Redis. Пример: `redis://localhost:6379` |
| `JWT_SECRET` | **обязательна** | — | Минимум 32 байта. Без неё сервер падает на старте |
| `TICK_INTERVAL_SEC` | необязательна | `3` | Интервал игрового тика (секунды) |
| `SKYCOMPOSER_BOOTSTRAP_USERNAME` | необязательна | — | Создаёт первого skycomposer'а при старте, пока их 0 в БД |
| `SKYCOMPOSER_BOOTSTRAP_PASSWORD` | необязательна | — | Пароль первого skycomposer'а |
| `BALANCER_PRESETS_FILE` | необязательна | `config/balancer_presets.json` | Путь к JSON-файлу пресетов кривых балансировщика (99.2.17). Файл пишется из админки («Сохранить как пресет»), читается при старте (активные пресеты переживают рестарт). На проде задать путь в место с правом записи (config/ может быть read-only) |
| `PLANET_IMAGE_CACHE_DIR` | необязательна | `data/planet_images` | Каталог диск-кэша большой картинки планеты (PNG 512). Формат имени: `{ImageGenVersion}_{sha256(planet_id|mode)}.png` (префикс версии генератора — явная сегрегация поколений, спека 2026-09-21 §5.2). При старте `InitPlanetImageCacheDir` удаляет файлы, чьё имя НЕ начинается с текущего префикса `{ImageGenVersion}_` — включая легаси-файлы без префикса (старый путь писал `{sha256}.png`), иначе легаси остаются в LRU-лимите 1000 и вытесняют новые. На проде задать в место с правом записи (data/ может быть read-only) |
| `CONTENT_CATALOG_PATH` | необязательна | `content/catalog.json` | Путь к файлу-снимку контента каталога (спека `2026-09-24-каталог-экспорт-импорт-контента-на-прод` §4/§5). Кнопка «экспорт контента» в студии пишет сюда и отдаёт тот же JSON на скачивание; запись — best-effort (на проде ФС эфемерна/read-only, скачивание от неё не зависит) |
| `SERVER_PORT` | необязательна | `8080` | Порт HTTP |

Прод задаёт env через `.env` в `/opt/zorion` (файл compose). Локально можно через `.env` в корне проекта (godotenv) или через терминал.

## 2. Локальный запуск

Локально удобнее всего поднимать всё батником `start-all.cmd` в корне проекта (двойной клик): база → игровой сервер → генерация картинок → учёт агентов → арт-студия → ИИ-помощник. Живоe пропускается, в конце печатается сводка портов; состав (картинки/учёт агентов/арт-студия/ИИ-помощник) переключается в начале файла. Альтернатива — ручной `go run ./cmd/server` (тогда базу и Redis поднимать самому).

### ИИ-помощник студии (`opencode serve`, порт 3456)

ИИ-кнопки студии товаров (`/studio`) ходят в локальный `opencode serve`. Сервис поднимается батником `start-all.cmd` последним (`[7/7]`), переключатель — `set "AI=1"` (рядом с `COMFY`/`STUDIO`/`DASH`); команда запуска:

```
start "ИИ-помощник" /min cmd /c "npx -y opencode-ai serve --port 3456 >> logs\opencode_serve.log 2>&1"
```

Лог — `logs/opencode_serve.log` (append; тот же файл пишет кнопка «запустить» в студии). Порт 3456 задан в **двух местах** — `start-all.cmd` и `OPENCODE_URL`; при смене править оба.

Переменные окружения (дефолты — `internal/config/config.go`, прод задаёт через `.env` в `/opt/zorion`):

| Переменная | Дефолт | Описание |
|---|---|---|
| `OPENCODE_URL` | `http://127.0.0.1:3456` | Адрес локального `opencode serve` (порт берётся отсюда и для пробы, и для запуска) |
| `OPENCODE_MODEL` | `opencode/deepseek-v4-flash` | Модель ИИ |
| `OPENCODE_AGENT` | `build` | Агент opencode (пустой резолвится в default_agent проекта — отвечает прозой менеджера) |
| `OPENCODE_TIMEOUT_S` | `120` | Таймаут запроса к ИИ |
| `OPENCODE_MAX_RETRIES` | `2` | Повторы при сетевой ошибке/5xx |
| `OPENCODE_START_TIMEOUT_S` | `300` | Таймаут готовности при запуске из студии (первый `npx` качает пакет). `≤0` → берётся 300. При таймауте процесс не гасится |

**Прод:** управление помощником (кнопки «запустить»/«остановить») доступно только на Windows + loopback + `npx` в PATH (`managed`); на проде (не Windows/нет `npx`) студия честно показывает «ИИ: недоступен», ручки `/studio/api/ai/*` отвечают 409. `OPENCODE_SERVER_PASSWORD` **не задавать** — помощник потребует basic-auth, которого клиент студии не умеет (401).

### Требования

- Go 1.21+, PostgreSQL 15+, Redis 7+
- PostgreSQL: слушает `127.0.0.1:5432` (путь: `C:\pgsql\pgsql\bin`)
- Redis: `127.0.0.1:6379`

### Шаг 1 — Задать переменные

```powershell
$env:DATABASE_URL = "postgres://zorion:zorion123@127.0.0.1:5432/zorion?sslmode=disable"
$env:REDIS_URL    = "redis://localhost:6379"
$env:TICK_INTERVAL_SEC = "3"
```

`JWT_SECRET` вручную не задавать — берётся из `.env` в корне проекта (godotenv). Свой секрет вручную перекрывает `.env` и делает невалидными все ранее выданные токены — у всех залогиненных «сессия истекла» (идея 58a).

### Шаг 2 — Запустить

```powershell
go run cmd/server/main.go
```

Сервер apply'ит миграции автоматически при старте (вшиты в бинарник), создаст первого skycomposer'а если заданы `SKYCOMPOSER_BOOTSTRAP_*` и он единственный.

Проверка: `curl http://127.0.0.1:8080/health` → `OK`.

## 3. Прод (skylab.ru)

> **Amvera — легаси.** Прод переехал на собственный сервер (домен `skylab.ru`,
> 2026-10-07). Amvera пока не потушена, но будет выключена отдельным чекпоинтом;
> основной прод — новый сервер.

### Как работает деплой

1. `git push origin master` → GitHub Actions (`.github/workflows/deploy.yml`)
   собирает образ по `Dockerfile` (golang:1.21-alpine → alpine:latest, порт 8080)
   и публикует `ghcr.io/lersss/zorion2:latest` в GHCR. Сборка идёт на стороне
   GitHub — сервер ресурсы на неё не тратит.
2. На сервере `watchtower` (контейнер `zorion_watchtower`, `--interval 60 --cleanup`,
   фильтр по метке `com.centurylinklabs.watchtower.enable`) сам забирает новую
   версию и перезапускает `zorion_app`.
3. Бинарь стартует → автоматически apply'ит миграции к прод-БД → bootstrap skycomposer.

### Сервер и конфиг

Сервер: Ubuntu + Docker, IP `109.73.203.245`, домен `https://skylab.ru`
(DNS `skylab.ru` A → `109.73.203.245`; NS у anti-maidan.com). HTTPS — сертификат
Let's Encrypt, выпускает и продлевает Caddy автоматически.

Прод-конфиг в `/opt/zorion`: `docker-compose.yml`, `Caddyfile`, `.env`. Те же файлы —
в репозитории (`deploy/docker-compose.yml`, `deploy/Caddyfile`); правки вносятся
в репо и раскладываются на сервере.

Контейнеры: `zorion_app` (игра, порт 8080), `zorion_postgres` (БД, том `pg_data`),
`zorion_redis`, `zorion_caddy` (обратный прокси, держит порты 80/443),
`zorion_watchtower`. Прямой порт приложения (8080) и порт БД (5432) наружу
не публикуются.

`deploy/Caddyfile` отдаёт домен `skylab.ru` → `app:8080` (Caddy сам делает HTTPS).

**Состав образа:** `Dockerfile` копирует `server`, `web`, `config` и `content/` — каталог снимка контента каталога (спека `2026-09-24-каталог-экспорт-импорт-контента-на-прод` §5: без `content/` в образе штатный импорт «из файла» на проде упрётся в «файла нет»). Файл `content/catalog.json` кладёт в репозиторий кнопка «экспорт контента» студии (коммитит создатель/менеджер), оттуда он попадает в образ. **Перед первым импортом на прод — обязательный бэкап БД** (решение создателя В4, §12.2); рабочий рецепт — подраздел «Бэкап перед первым импортом контента» ниже. Импорт — кнопка «импорт контента» в студии (`POST /studio/api/content/import`, два шага: «Проверить» (сухой прогон) → «Применить»); при непустых `blocked`/`unmatched` применение запрещено (полная замена с предсчётом мировых ссылок, §5.4); аварийный путь — загрузка файла через студию (`{"snapshot": {…}}`).

**Реестр кораблей игры** — файл данных `config/ships_registry.json` (не Go-константы); попадает в образ через `COPY config`. Правится арт-студией локально и коммитится. Удаление корабля из игры не требует пересборки Go — на локальном сервере достаточно перезапуска; на прод доезжает обычным коммитом/деплоем.

### Операционная заметка: порты 80/443 и панель

На сервере стоит хостинг-панель FastPanel. Её **сайтовый веб-сервер `nginx.service`
отключён и убран из автозапуска** — иначе он перехватывает порты 80/443 и показывает
заглушку «site waiting for content» вместо игры. Порты 80/443 должны принадлежать
контейнеру `zorion_caddy`; веб-интерфейс самой панели (`fastpanel2-nginx`, порт 8888)
при этом работает.

Если после перезагрузки/операций панели домен снова отдаёт заглушку — проверить, что
`nginx.service` не поднялся (`systemctl is-active nginx`), и при необходимости снова
`systemctl stop nginx; systemctl disable nginx`. Caddy должен владеть 80/443.

### Бэкап перед первым импортом контента

Импорт контента (`POST /studio/api/content/import`) — полная замена каталога,
поэтому перед первым «Применить» **обязателен бэкап, из которого данные реально
восстанавливаются** (решение создателя В4, §12.2).

Дамп **только контентных таблиц** (`pg_dump -t goods -t producer_types …`) —
**не восстановим в чистую БД**: он несёт `DEFAULT catalog_next_code(...)`
(миграция `000084`), но `-t` не тянет зависимости — ни саму функцию, ни счётчики
`*_code_seq` (они не `OWNED BY`), и `psql -f` падает на `CREATE TABLE`
(`relation "public.effect_types_code_seq" does not exist`). Такой бэкап — не
страховка (подробнее — `docs/pitfalls/db-shell.md`).

Рабочий рецепт — **полный логический дамп**: восстанавливается целиком, вместе с
функцией и счётчиками меток. Внешнего доступа к порту 5432 нет — дамп делается
внутри контейнера `zorion_postgres` и выгружается на хост:

```text
docker exec zorion_postgres pg_dump -Fc -U zorion -d zorion -f /tmp/zorion_prod_<дата>.dump
docker cp zorion_postgres:/tmp/zorion_prod_<дата>.dump zorion_prod_<дата>.dump
```

Восстановление (если импорт всё-таки сломал контент) — в **отдельную** БД
(завести пустую: `docker exec zorion_postgres createdb -U zorion zorion_restore`):

```text
docker cp zorion_prod_<дата>.dump zorion_postgres:/tmp/
docker exec zorion_postgres pg_restore --no-owner -U zorion -d zorion_restore /tmp/zorion_prod_<дата>.dump
```

Дамп тяжёлый (на проде ~76k планет, §5), но `-Fc` сжат, а это разовая плата за
гарантию. Файл хранить вне контейнера (ФС контейнера эфемерна — пересоздаётся
при обновлении образа).

Прямой доступ к БД (psql без дампа) — через тот же контейнер:

```text
docker exec -it zorion_postgres psql -U zorion -d zorion
```

## 4. Первичная настройка прод-БД

После первого деплоя (или при чистой БД) — зайди в админку (`/admin.html`) и последовательно:

### 4.1 Генерация вселенной

Вкладка **🌌 Генерация** → сгенерируй звёзды и планеты.

### 4.2 Генерация кораблей

Вкладка **🚀 Корабли** → на каждой из 5 категорий (Корпус, Нос, Крылья, Двигатели, Хвост) нажми **＋10** (минимум 10 форм на категорию, спека 99.2.15).

Детали генерируются на бэкенде, каталог в памяти перезагружается автоматически — рестарт сервера **не нужен**.

### 4.3 NPC-агенты (по надобности)

Вкладка **👁️ NPC** → генерация.

## 5. VACUUM (ANALYZE)

После массовой перегенерации карты видимости деградируют (фильтры по
`planets.data`: 63 → 306 мс). `VACUUM (ANALYZE)` нужно делать **руками**
напрямую в БД — миграцией нельзя (не идемпотентно, не работает в транзакции).

**Объём планет (реализм распределения, 2026-09-21):** на 20 000 миров теперь
~76 000 планет (было ~35 500, ×2.1 — mean числа планет подняты). Фильтры
карты / VACUUM после массовой генерации — **событийно обязателен** (как сейчас).

**Когда:** событийно, после каждой массовой операции, переписывающей `planets` —
генерация вселенной, очистка, регенерация планет по мирам, большой прогон
«близнецов» в проверке гипотез. Единичные операции не требуют. Не уверен —
замерь фильтр карты: деградировал (300 мс) — пора, вернулся к 63 мс — хватило.

**Как на новом сервере:** БД — контейнер `zorion_postgres`, внешнего доступа к
порту 5432 нет. Выполнять через `docker exec` (вне транзакции):

```text
docker exec -it zorion_postgres psql -U zorion -d zorion -c "VACUUM (ANALYZE) planets;"
```

Если правка кода затрагивает процесс развёртывания (новый env, новый шаг первичной
настройки, изменение порта/миграций/зависимостей) — **обновить этот документ**:
добавить или поправить пункт. Инициатором правки может быть любой агент
(менеджер — дельтой в свою идею, раздел «Разнос по докам»); вносит в файл
владелец документа — `@developer` (реестр владельцев — `docs/INDEX.md`).
