## Найденное

### BUG-1 (🔴 блокер) — краш `renderPalette` на `state.banned = null`
- **Где:** `cmd/goods-studio/web/index.html:609` — `$("bannedList").innerHTML = state.banned.map(...)`; сервер `handlers/state.go:670-675` (Banned/Unused — nil-слайсы → JSON `null` при пустоте)
- **Симптом:** `/api/state` отдаёт `"banned": null` (и `"unused": null`, `"report": null`), когда забаненных нет. `renderPalette` вызывает `.map` на null → TypeError → `renderAll` обрывается до `renderCatSelects` → селекты категорий (`#catFilter`, `#catManage`, `#newGoodCat`) пустые → «+ товар» не работает (`if (!name || !cat) return`), фильтр по категории мёртв. Ошибка тихая (unhandled rejection внутри async `fetchState` — pageerror не возникает).
- **Воспроизведение:** свежая загрузка страницы при 0 banned → `newGoodCatOpts=0`, `catFilterOpts=1`; pageErrors: `TypeError: Cannot read properties of null (reading 'map') at renderPalette (index.html:609)` (ловится при input-событиях).
- **Обход для теста:** тест банит один неиспользуемый ресурс заранее (banned → массив) и разбанивает в cleanup.
- **Фикс (для @developer):** `(state.banned || []).map(...)` или сервер отдаёт `[]` вместо null (сервер менять нельзя по дельте §6 — фикс на клиенте).

### BUG-2 (🟡) — спиннер загрузки не показывается при первичной загрузке
- **Где:** `cmd/goods-studio/web/index.html:684-692` (`updateOverlays` вызывается только из `fetchState`/`renderAll`, на старте — ни разу)
- **Симптом:** спека §4.2 требует спиннер «Загрузка…» пока первый `/api/state` не пришёл; фактически оверлей `#loadingOverlay` (CSS `display:none`) никогда не активируется при первичной загрузке — только при СБОЕ fetch (тогда показывает «Загрузка…» рядом с пилюлей «нет связи» — вводящий в заблуждение текст). Проверено браузером: при задержке первого ответа спиннер не виден.
- **Фикс:** вызвать `updateOverlays()` при старте (до первого fetchState).

### BUG-3 (🟡) — нет повтора при сбое ПЕРВОГО /api/state
- **Где:** `cmd/goods-studio/web/index.html:166-169` — `setInterval(fetchState, ...)` стартует только при успешном fetch
- **Симптом:** спека §4.2 «fetch упал (повтор 3 с идёт)»; пилюля «нет связи, повтор через 3 с» обещает повтор, но если сервер недоступен в момент загрузки страницы — повтор НЕ идёт (интервал не запущен), страница висит в офлайне до ручного reload. Проверено браузером: после восстановления сети без reload оверлей/пилюля не уходят.
- **Фикс:** в catch запускать `setTimeout(fetchState, 3000)` (или стартовать интервал до первого fetch).

1. **Деплой-ловушка:** студия товаров embed'ит HTML в бинарь (`main.go:22-23`). Правки index.html не видны до пересборки+рестарта. Стоит зафиксировать в `docs/PITFALLS.md` или DEPLOY-доке студии (в `docs/PITFALLS.md` уже есть похожий раздел про статику игрового сервера — для студии правило обратное).
