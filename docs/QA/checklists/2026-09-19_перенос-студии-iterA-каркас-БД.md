## Найденное (баг)

**BUG-1 (критичный для контракта): нормализация имён с кириллицей — name_norm (SQL `lower()`) не совпадает с Go `graph.NormalizeName`.**

- Файлы: `migrations/000045_create_goods_catalog.sql:9-10,22-23` (generated-колонки `name_norm` через `lower()`); `internal/repository/goods_repository.go:187-193, 236-243, 320-326, 386-394` (проверки дубликатов по `name_norm` с Go-нормализацией).
- Причина: dev-БД `zorion` создана с `datcollate = C` — PostgreSQL `lower()` НЕ приводит кириллицу к нижнему регистру (`lower('QA-Категория-Тест')` = `qa-Категория-Тест`). Go `strings.ToLower` кириллицу приводит (`qa-категория-тест`). Проверка приложения ищет `name_norm = 'qa-категория-тест'`, в БД хранится `qa-Категория-Тест` → проверка не находит дубликат.
- Следствия (воспроизведено):
  1. **Дубликат-регистр кириллицы проходит**: «QA-Категория-Тест» + «qa-категория-тест» → обе созданы (201), UNIQUE (kind, name_norm) не срабатывает (байты разные). Нарушен инвариант 4 спеки («имена уникальны в одном пространстве»). Каталог целиком кириллический — риск реальных дублей «Железо»/«железо».
  2. **Дубликат с пробелами («X»/« x ») → 500 вместо 409**: «QA-Категория-Тест» + « QA-Категория-Тест » → проверка приложения промахивается, INSERT упирается в UNIQUE → сырая ошибка БД → 500 (контракт §7 требует 409). Воспроизведено для категорий (CreateCategory) и товаров (CreateGood). Латинские имена работают корректно (409).
- Затрагивает: категории (create/rename), товары (create/update), bulk (пачка с кириллическим дублем-регистром упадёт целиком с 500).
