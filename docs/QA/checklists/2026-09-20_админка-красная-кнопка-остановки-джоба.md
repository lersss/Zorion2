- `web/admin.html:106-112` — `#genStopBtn` рядом с `<h2>🌌 Генерация</h2>`, `display:none` по умолчанию, `onclick="stopRunningJob()"` — соответствует ТЗ §3.1.

- `main.js:138` + `tabs.js:72` — `restoreJobStates()` при загрузке админки и при активации вкладки «Генерация». Двойной вызов безопасен: второй пропускает уже запущенные интервалы (`if (pollIntervals[ui.key]) continue`).
- Сервер/API не тронуты (ТЗ §3.3) — подтверждено диффом.

## Найденные проблемы

1. **[среда, не код] Внешний актор на общем сервере отменял пакмана и стёр галактику.** Запуски 2 и 3 прерваны: пакман отменялся на ~8 съеденных мирах (~8 с) БЕЗ клика по стопу в моём скрипте; затем БД оказалась пустой (0 миров, 0 планет — проверено psql напрямую, `/admin/stats` кэшируется). Мой скрипт шлёт только GET статуса, POST `/admin/pacman/start` и POST `/admin/generate-cancel` по клику; серверный код автозамены не содержит (`statusManager.Cancel` вызывается только из HTTP-хендлера `CancelGeneration`, `admin_universe.go:677-691`; grep по `JobPacman`/`time.After` — ватчдога нет). Вывод: кто-то параллельно тестирует тот же сервер (отменяет джобы, затем «Удалить все миры»/полный вайп). Это вмешательство в среду, не баг фикса. **Следствие: галактика пуста — для повторного прогона нужна регенерация миров.**
2. **[не проверено] P4: 1 console error в запуске 1 без содержимого.** В полном прогоне `consoleErrors=1` (содержимое не логировалось в первой версии скрипта; в запусках 2–3 до P4 не дошли из-за внешней отмены). Наиболее вероятно — `console.error('Poll error:', e)` в `poll.js` при оборванном in-flight запросе в момент отмены (интервал чистится, запрос мог упасть). Повторяющихся ошибок поллинга нет (`newPollsAfterCancel=0`), `pageErrors=0`. Требует подтверждения одним чистым прогоном на непустой галактике.

## Не проверено (чеклист непроверяемого)

- **Повторный полный прогон P1–P5 на непустой галактике** — БД пуста (внешний актор стёр миры), регенерация 30k миров — тяжёлая операция на общем сервере; нужен чистый прогон после регенерации.
- **Содержимое console error из P4** — см. проблему №2; нужен один чистый прогон с логированием `consoleErrors`.
- **Восстановление состояния НЕ-пакманных джобов** (generate_universe/planets/… после F5) — код общий (`restoreJobStates` + `JOB_UI`), но живой прогон был только с пакманом (единственный джоб, который можно запустить быстро и безопасно на 1 мир/с).
- **Кнопка-стоп при нескольких running-джобах одновременно** — серверно джобы взаимоисключают друг друга (409), `stopRunningJob` берёт первый из `runningJobs`; штатно недостижимо.
- **Визуальный UX кнопки** (размер 20×20, красный квадрат, позиция рядом с заголовком) — скриншоты в `tools/e2e/artifacts/` для создателя.

### Console error (оговорка №2 закрыта)

- **Текст:** `Failed to load resource: the server responded with a status of 404 (Not Found)` — ровно 1 раз за прогон, в каждом прогоне.
- **Причина:** отсутствующий `/favicon.ico` (и `/favicon.png`, `/static/favicon.ico`, `/manifest.json` — все 404, проверено curl'ом). Автоматический запрос браузера при загрузке любой страницы; в playwright не проходит через request/response-события (в списке всех 54 запросов страницы favicon нет, ни одного ответа ≥400 нет), но даёт console error.
- **Не связано с фиксом:** все запросы `restoreJobStates` (9 джобов) и поллинга — валидные 200 (подтверждено списком запросов); ошибка не повторяется (1 раз, не «повторяющиеся ошибки поллинга» из ТЗ P4); `pageErrors=0`.
- **Вердикт по оговорке:** закрыта — это косметический 404 favicon, не баг фикса. (Опционально для @developer: положить `favicon.ico` в `web/` — вне скоупа фикса.)
