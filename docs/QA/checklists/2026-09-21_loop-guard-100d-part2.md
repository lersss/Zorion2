## Отклонения / найденное

- **Багов по чек-листу не найдено.** Продление включается один раз на заявку (`extendedUntil`
  не даёт дублировать `extend`), сбрасывает `reminded`/`afterReminder`, поднимает только
  объёмный предел; критерий по содержимому и порог памяти продление не отменяет — как заявлено.
- **Наблюдение (не дефект, вне чек-листа):** `server.mjs:99-108` `readBody(limit=4096)` при теле
  больше лимита делает `req.destroy()` — на пробу (тело ~5 КБ) клиент получает разрыв соединения
  (`fetch failed`) вместо HTTP-ответа 400/413. Для кнопки (тело ~120 байт) недостижимо; поведение
  можно ужесточить, отдав 413, — на решение @manager.
- Продление на срок без изменения `extra` (extra=0) валидно: `extension()` возвращает объект,
  идёт сброс счётчиков и запись `extend` — соответствует «продление только на срок».

## Не проверено (граница покрытия)

- **Живой клик кнопки в браузере.** Страница рисует кнопку только для сессий из `/api/stats`
  с полем `id` (работающий прямо сейчас агент); гарантировать наличие активной сессии в момент
  прогона нельзя. Закрыть: открыть `http://127.0.0.1:8790` при живом агенте, нажать «продлить»
  и увидеть плашку «продлено ещё N мин».
- **Связка «реальная сессия opencode ↔ файл в корне репозитория».** Harness звал хуки плагина
  напрямую и клал заявку во временный `directory`; путь по умолчанию у сервиса
  (`server.mjs:17` → `../../.opencode/loop-guard.override.json`) и у плагина
  (`loop-guard.js:45`, `directory/.opencode/...`) сверены строкой, но в бою не прогонялись.
- **Реальный агент, 60+ правящий один файл, с продлением на лету** — не воспроизводил (кейс
  требует живой сессии).
- **Одновременные POST'ы** (несколько заявок в один файл) — атомарность через `.tmp`+rename
  проверена на одном запросе, гонку двух писателей не нагрузочно не тестировал.
- **Вкусовые пороги** (extra по умолчанию 15, потолки 240 мин / 200 действий) — работают как
  заявлено, но калибровка — решение создателя.
