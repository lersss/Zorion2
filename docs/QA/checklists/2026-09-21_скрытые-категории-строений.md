## Найденный баг (функциональный, стоп-критерий)

**B1. Список справа ветки «Производители» не показывает подтипы автоматических
категорий (все подтипы Фабрики/Автофабрики/Добывающей платформы) — ни видимые,
ни скрытые, ни при галке.**

- **Симптом:** `renderProdSprav` показывает только типы (parent_id NULL) и
  одиночные подтипы вне автоматики (лаборатории). Видимая «Фабрика топлива»
  (id=40) и скрытая «Фабрика топлива F1» (id=43) в списке отсутствуют на любом
  уровне расовости и при любой галке. Кейс 12 спеки §3.3 («скрытая запись с
  галкой — видна с пометкой "скрыта"», «клик ведёт на существующий узел») не
  работает.
- **Причина:** `prodNodeVisible` (`web/studio.html:1766`) вызывает
  `prodAppliedRecords(t, p.category_id)` — передаёт **число** `p.category_id`,
  а `prodAppliedRecords` (`web/studio.html:1742-1744`) ожидает **объект
  категории** и сравнивает `s.category_id === c.id` (`c.id` = undefined для
  числа) → `applied` всегда пуст → `if (!applied.length) return false;`
  (строка 1767) → `prodNodeVisible` = false для всех подтипов автоматических
  категорий. Фильтр «клик не повисает» (п.4 §3.3, `renderProdSprav:1496`)
  выкидывает их из списка.
- **Дерево НЕ затронуто:** `buildProdTree` (1829) вызывает `prodAppliedRecords`
  с объектом категории (`cats.forEach(c => ...)`) — K8/K9/K10 прошли.
- **Файлы:** `web/studio.html:1766` (передача числа), `1742-1744`
  (ожидание объекта). Ожидаемый фикс: передавать объект категории
  (`state.categories.find(c => c.id === p.category_id)`) либо сравнивать по
  числу.
- **Затрагивает:** кейс 12 (список справа, спека §3.3).

## Найденный баг (функциональный, стоп-критерий)

**B2. DELETE /studio/api/slots/{id} → 500 «pq: could not determine data type
of parameter $3» для любого слота.**

- **Симптом:** DELETE слота (universal «Фабрика+Минералы», расовый
  «Фабрика+продовольствие+F0+humans») → 500 `{"error":"ошибка каталога: pq:
  could not determine data type of parameter $3"}`. Слот не удаляется.
  Воспроизведено 5 раз (K4a/K4b/K4c-2 + ручные повторы) — детерминированно.
- **Причина:** `DeleteProducerSlot` (`internal/repository/producer_repository.go:704-709`)
  передаёт параметры `$3`/`$4` через `nullStr(slotFamily.String)` /
  `nullStr(slotRace.String)` — `nullStr` возвращает `interface{}` (nil для
  NULL). lib/pq не определяет тип параметра → PostgreSQL 500 при подготовке.
  SQL сам по себе валиден (проверено PREPARE/EXECUTE с типизированными
  text-параметрами — работает). Соседний `producerSlotApplied` (125–134)
  использует тот же паттерн `nullStrPtr`, но там параметры не попадают в
  `IS NULL`-выражения с невыводимым типом — работает (POST подтипа 201).
- **Затрагивает:** весь DELETE /slots/{id} — кейсы 4а (снятие переопределения),
  4б (RESTRICT базы при заводах), 4в (расовый слот при семейной/расовой
  записи); спека §4 (DELETE), §1.4 п.2 (RESTRICT), §5.3 («− слот»).
  Редактор слотов в UI («− слот») тоже сломан (тот же роут).
- **Ожидаемый фикс:** передавать типизированные NULL (например, `sql.NullString`
  или `*string`) вместо `interface{}` от `nullStr`, либо кастовать в SQL
  (`$3::text`).

## Найденный баг (функциональный, стоп-критерий)

**B3. Изменение слотов не перерисовывает UI: после галки «скрытая» / «− слот» /
«+ слот» попап редактора и дерево не обновляются.**

- **Симптом:** в карточке «Фабрики» на F1 клик по галке «скрытая» у
  унаследованного «топлива» → слот создаётся в БД (проверено: id=68,
  hidden=true), но строка в попапе остаётся «скрытая топливо унаследован»
  (не становится «переопределён»); после «−» у переопределения строка не
  возвращается к «унаследован»; хинт «база скрыта» (K11) не появляется.
  Дерево и список тоже не обновляются до ручного рендера (переключение
  уровня/ветки/F5).
- **Причина:** `fetchState` (`web/studio.html:407`) вызывает `renderAll()`
  только при изменении `goods`/`categories` (`gj !== lastGoodsJSON ||
  cj !== lastCatsJSON`); `producer_slots` (и `producer_types`) не входят в
  сравнение → после POST/PUT/DELETE `/studio/api/slots` UI не перерисовывается.
  `toggleProdSlot`/`removeProdSlot`/`addProdSlot` (1736–1792) вызывают только
  `fetchState()`.
- **Затрагивает:** K10 (редактор слотов — действия не видны), K11 (хинт
  «база скрыта»/пометка «переопределён»), дерево (скрытая категория не
  исчезает до ручного рендера), список справа (фильтр скрытости не
  применяется до ручного рендера). Спека §3.2 (редактор слотов — результат
  действия должен быть виден).
- **Ожидаемый фикс:** включить `producer_slots` (и `producer_types`) в
  сравнение в `fetchState` (407) либо вызывать `renderAll()` явно после
  мутаций слотов.
