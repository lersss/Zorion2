## Как проверял

Плагин импортирован обычным ESM-скриптом с фиктивным `client`
(`tui.showToast`/`session.abort` — пустые async) и временным `directory`;
журнал читался из `<tmp>/.opencode/loop-guard.log`. Плагин НЕ правился.
Скрипты вне репозитория: `%TEMP%\opencode\qa-guard-run.mjs`, `qa-stats-newformat.mjs`.

```
node %TEMP%\opencode\qa-guard-run.mjs        -> ИТОГО: 8/8 пройдено (exit 0)
node %TEMP%\opencode\qa-stats-newformat.mjs  -> old peak=500000, new peak=0
```

Фон (реальный `.opencode/loop-guard.log`): 14 срабатываний, из них `mem:0` — 14,
строк `probe` — 0. Исходная проблема (критерий памяти не срабатывал ни разу) подтверждена.

## Вердикт: ПРОЙДЕНО (8/8)

## Найденное / наблюдения

1. **[вне 8 пунктов, смежный риск] `tools/agent-dash/stats.mjs:11-13` не понимает новый формат
   сообщения.** Константы жёстко зашиты под старую форму:
   `AS_ASSISTANT = data LIKE '%"role":"assistant"%'`, `CTX = tokens.input + tokens.cache.read`.
   Доп. прогон: на старом формате `peak=500000`, на новом (`type:"assistant"`, `cacheRead`)
   `peak=0` — т.е. если приложение реально эмитит новый формат, метрики «пик памяти» и число
   турнов дашборда агентов сломаны тем же корнем, что и сторож.
   → предложение @manager: завести на доработку `stats.mjs` (читать обе формы, как в плагине).
2. Наблюдение по пробнику (не дефект): строки `probe` пишутся на **любой** тип события.
   12 строк могут израсходоваться на нерелевантных событиях раньше первого `message.updated`
   — диагностика целевого события может не попасть в журнал. Для одноразового пробника
   приемлемо; при повторном использовании стоит фильтровать по типу.
3. `probe` не удалён из боевого плагина (строки 179-188) — это ожидаемо (помечено «ВРЕМЕННО»),
   но перед коммитом плагина пробник надо снять, иначе он и впредь будет писать 12 строк в журнал.

## Не проверено (границы покрытия)

- **Реальный поток событий opencode.** Проверял харнессом с подставными событиями; какой формат
  (`role` vs `type`, `cache.read` vs `cacheRead`) реально шлёт текущий билд — не проверено, нужен
  живой прогон приложения и строки `probe` в боевом `.opencode/loop-guard.log` после перезагрузки
  плагина. → закрыть: создателю перезапустить сессию и прислать новые `probe`-строки.
- **Пороговые эффекты на реальных 700k/900k.** Значения памяти в живом приложении не воспроизводимы
  без долгой сессии агента; проверял синтетическими числами.
- **Взаимодействие с `tools/agent-dash` на живом сервисе** (вкладки/подсчёт по дням) — проверял
  только `createStore().report()` на временной SQLite, не UI сервиса.
