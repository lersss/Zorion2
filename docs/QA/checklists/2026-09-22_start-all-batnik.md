## Побочный эффект

Файл-приёмник stdout при запуске с редиректом (`... --no-pause > out 2>&1`) остаётся **заблокирован** для чтения спустя минуты после завершения батника — для прогонов 2 и 3 (там поднимались сервисы), прогон 1 (только пропуск) — файл читается. Причина: дескриптор редиректа наследуется отвязанными дочерними процессами (`start ... cmd /c ... >> log`), которые живут постоянно, и держит файл открытым. На «двойной клик» (вывод в консоль) не влияет; проявляется только при скриптовом редиректе. Файлы прочитаны в режиме `FileShare.ReadWrite`.

- Поведение переключателей `COMFY`/`STUDIO`/`DASH`=0 (строки «отключён в настройках») и ветки провала старта (таймауты/`[нет]`) — штатно недостижимы без гашения сервисов и правки файла.
- UX/внешний вид свёрнутых окон серверов — визуально, глазами создателя.
