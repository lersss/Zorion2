## Пункт 9 — одна точка формулы (факт)

- Единственный носитель формулы `dist·speedFactor, min 3с` для контракта/полёта —
  `internal/models/contract_travel.go:20-26` (`TravelDuration`): `d := time.Duration(dist*speedFactor) * time.Second`, `if d < 3*time.Second`.
- Обёртки, не дубли формул:
  - `internal/npc/travel.go:14` — `FlightDuration` → `return models.TravelDuration(dist, speedFactor)`;
  - `internal/handlers/travel_handlers.go:109` — `calcTravelDuration` → `return models.TravelDuration(dist, speedFactor)`.
- `reserve` и `offer_window` — только в `models`:
  `ContractDeadlineReserve = 0.5` (`contract_travel.go:10`), `ContractOfferWindowMult = 10.0` (`contract_travel.go:13`); тела `TravelDeadline`/`TravelOfferWindow` (`:37-44`) — единственные.
- `speed_factor_ref` = `models.EngineSpeedDefault = 0.3` (`internal/models/ship.go:54`), значение одно; в хендлере
  `contractTravelGearSpeedFactorRef = models.EngineSpeedDefault` (`contract_handlers.go:37`) — алиас порога требования, числа не дублирует.
- **Посторонний (не контрактный, не затронут диффом) второй экземпляр min-3:**
  `internal/handlers/intrasystem_handlers.go:75-77` — интрасистемный полёт, своя формула (`distAU·speedFactor` с хвостом `0.1`, `min 3с`). Это отдельная механика 99.2.27 (внутрисистемный сегмент), не срок контракта; в фокус B2b не входит.

## Пункт 11 — живой сценарий

**Сделано:** свежий бинарь из рабочего дерева (`go build -o … ./cmd/server`) поднят на свободном порту **:8095** (8080/8098 не трогал). `GET /health` → **200 OK**, тело `OK`. Сервер остановлен по завершении.

**SKIP живого взятия/закрытия агентом.** Точная причина:
- в dev-БД **`npc_agents` = 0** и **`contracts` = 0** (проверено `psql`: `SELECT count(*) FROM npc_agents` = 0, `FROM contracts` = 0; миры есть — mapcache загрузил 50 000);
- API/фикстуры для постановки **одного** агента с управляемым маршрутом нет: цель полёта выбирает планировщик (`g.pickTarget(cx, cy, …)`, `internal/npc/manager.go:387`) случайно, совпадение с `dest` контракта не гарантируется;
- чтобы «совпало», нужно гонять тяжёлый джоб генерации агентов, пишущий в общую БД — запрещено поверх чужого джоба (AGENTS §16). Живой путь проверен юнит-интеграцией (пп. 3–8, `sqlmock`+fakeStore) на реальном SQL-контракте.

**Тестовые данные:** не создавались. Временный бинарь/логи/pid удалены.

## Чеклист непроверяемого

| Что не проверено | Почему | Что нужно, чтобы закрыть |
|---|---|---|
| Живое взятие/закрытие перелёта агентом (п. 11) | В dev-БД 0 `npc_agents` и 0 `contracts`; маршрут агента выбирает планировщик случайно, совпадение с `dest` контракта непостановочно; генерация агентов — тяжёлый DB-джоб (AGENTS §16) | Сгенерированная вселенная с агентами ИЛИ спец-фикстура/отладочный путь «агент с заданным маршрутом»; тогда повторить живой сквозной прогон |
| Многоагентная конкуренция за один контракт на живом сервере | Нужны ≥2 агента на том же маршруте в одной системе | Фикстура 2 агентов + 1 контракт на маршрут |
| Поведение при реальном таймауте `expires_at` в полёте (ленивое истечение агентского перелёта) | Требует длительного живого прогона с истёкшим сроком | Живой прогон с коротким дистанционным контрактом |
| Нагрузочный профиль `CloseArrivedTravels` при ~2000 прибытий/тик | На живом сервере столько агентов не поднять в QA | Отдельный нагрузочный прогон |
