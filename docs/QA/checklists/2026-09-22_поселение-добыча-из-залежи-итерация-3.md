## Найденное

**Блокирующих багов нет.** Замечания (не дефекты кода фичи):

1. **[среда, побочный эффект прогона]** Для проверки порядка «крупная→мелкая» (п.5) потребовались две контролируемые залежи одного ресурса, поэтому **предсуществующая сгенерированная залежь Мясо** на тестовой планете (`deposits.id = 4a8007fd-…`, `amount = 607.1888`) была заменена и после прогона **не восстановлена**. Тестовая планета теперь несёт только залежь Растения(358). Данные сгенерированные, восстанавливаются перегенерацией планеты/мира. Следствие прогона, не баг кода.
2. **[ограничение доказательства]** T15 (§4.4 спеки — явный риск инверсии локов студии) проверен **одной** параллельной попыткой: дедлок не воспроизведён, `pg_stat_database.deadlocks = 0`. Отсутствие дедлока этим **не доказывается** — нужен выделенный нагрузочный прогон (много итераций `DeleteGood || синк`).
3. **[наблюдение, UI]** Проходной вход подтверждён: при живой залежи `input` остаётся 0; админский инкремент входа расходуется первым (F4-A). Соответствует п.24/§4.3.

## Не проверено (границы покрытия)

- **Экстремальные/редкие залежи из реальной игры** — контролировались сконструированные залежи; поведение на «естественных» распределениях `amount/wealth` генератора (в т.ч. `wealth` как «только показ») в живом прогоне не гонялось — нет гарантированного набора под рукой. Закрыть: `@balancetester` на сценарии «две ветки делят одну залежь».
- **T15 / дедлок студии × синк** — только одна попытка (см. выше).
- **UX глазами игрока** (карточка поселения у player, «проходной вход» vs ожидания) — визуальная оценка за создателем.
- **Долгосрочный тренд** (истощение залежи за сутки–неделю, расхождение с легаси-сводкой `planets.data.resources`, C6 спеки) — по симуляции/калибровке, не за один прогон.
- **Много миров одновременно** (пакетные чтения `attachBranches` на большой выборке) — не нагрузочный прогон; отдельная задача оптимизации.
