## Найденное

Дефектов нет. Замечания (не баги):
- Живой admin-JSON вида `planets[].settlements[]` не отдаёт поле `eat`-норм — так и задумано (§6: нормы не выводятся в карточку).
- В админской карточке подписи блока идут в UPPERCASE из-за `text-transform:uppercase` («ОСТАТОК (ОСАДОК)») — визуал, не дефект.
- **Репо-гигиена (для @manager/@dispatcher, не дефект фичи):** `internal/handlers/admin_universe.go` содержит правку типа поселения (строки 629–643, вызов `repository.ResolveDefaultSettlementTypeID`), но `git status --porcelain`, `git diff` и `git diff --cached` по этому файлу **пусты** — по мнению git файл совпадает с HEAD. Сам `ResolveDefaultSettlementTypeID` определён только в **незакоммиченном** `internal/repository/economy_repository.go` (в диффе строка `+func …`). Если файл действительно уже в HEAD, то HEAD ссылается на отсутствующий символ и **чистая копия HEAD не собирается** (риск «красной сборки в чистой копии» из `PITFALLS`); альтернатива — файл помечен `assume-unchanged`/`skip-worktree`. Перед коммитом фичи проверить (`git ls-files -v` / `git diff HEAD -- <файл>`) и включить правку в коммит.

## Предложения в чек-лист

- **Новый кейс (B-ECO-11, итерация 4):** «Потребление населением на ветке» — у поселения тип с `params.eat`, две ветки («Вода» рец.73, «Пища» рец.69), Δt ≥ 30 мин → `output` растёт на произведённое и убывает на съеденное (порядок «производство→потребление»), `produced/eaten/eaten_rate` в карточке админа, остаток ≈10 % при complexity=1, игроку деталей нет.
- **Новый кейс (регресс):** «нормы изолированы по товару» — изменение `eat` одного товара не меняет еду другой ветки (живой прогон; тест T19).
- **Новый кейс:** «удаление типа поселения со ссылками → 409» (студия; `TestDeleteProducerTypeSettlements409`) + «подтип без товарной категории под типом без слотов создаётся, под фабрикой — 400».
