  `.env`-значение не подходит ни к одной учётке — проверено `POST /login`, все 401). Это не связано с

  (`POST /register` → роль повышена до `admin` SQL-ом), **после прогона удалён** (см. п.17).

- Два вспомогательных manual-скрипта жили во временной папке (`%TEMP%\opencode`), в репозиторий не писаны.
- e2e-скрипты студии прогнаны со `STUDIO_USER=qa_studio_tester` (роль admin).

## Находки

1. **`goods-studio-server-check.js` шаг 9a — FAIL из-за данных каталога (не регресс).**
   Severity: low (качество e2e). Источник `copy-universal` в живом каталоге отсутствует → шаг не проверяет
   заявленное. Предложение: либо сид/QA готовит универсальный производитель с рецептами, либо 9a честно
   `SKIP` при `uniSrc==null` (сейчас безусловный FAIL маскирует состояние данных).
2. **`goods-studio-server-check.js` шаг 8 — 409 (известное), зафиксировано.**
   Severity: info. Локальный opencode занят → `fill` 409. Поведение скрипта при этом шумное (двойной FAIL:
   `8 fill start` + `8 fill negative`). Предложение: считать 409 отдельным статусом, не гонять 135-секундный опрос.
3. **Наблюдение (вне объёма, pre-existing): после прогона ИИ-описаний авто-открывается `#descPopup`/`#descOverlay`
   и перехватывает клики.** Обнаружено при тесте (после создания товара с включённой галкой «описание ИИ»).
   Переделка студии этого не касалась (ТЗ §7.5 — попапы описаний не трогать), это поведение существующей фичи
   ИИ-описаний, а не регресс. Фиксирую как наблюдение.

## Не проверено (граница покрытия)

- **Пункт 13** (`+ ресурс` серая без ресурсных категорий): в каталоге есть ресурсные категории; безопасно
  удалить их нельзя (портит каталог). Воспроизвести `disabled` можно только на стенде с пустыми ресурсными
  категориями. Код-путь при этом выглядит перенесённым корректно (`web/studio.html` — `renderCatSelects`
  ставит `#btnNewResOpen.disabled = !resOpts`), но живое подтверждение не получено.
- **Пункт 6б ТЗ / §7.7 п.7** («+ товар» при выбранной фабрике: селект категории заблокирован, подпись
  «категория определяется выбранной фабрикой», товар привязан к фабрике) — в жёсткий чек-лист не входил;
  проверялся косвенно (селект и подпись формируются `renderCatSelects`/`openNewGoodPopup`, e2e шаг 3 проходит).
  Полный сценарий с выбранной фабрикой — за `goods-studio-server-check.js`-режимом (вне моего прогона).
- **Точная числовая проверка фильтра по категории**: подтверждено сужение списка (134→0 для выбранной
  категории), но категория с неиспользуемыми товарами в каталоге подобрана не была — численное совпадение
  ожидания/факта не снято. Не критично: фильтры объявлены вне объёма правки (§2 п.6).
- **Визуальная эстетика нового ряда вкладок** (насколько «читается» активная синяя вкладка) — глазами игрока;
  по коду используется существующий `.branch-btn.on`, новых палитр нет. Вкусовое решение — создатель/`@uidesigner`.
- **`go build ./...` / `go vet ./...`** не гонял: правка чисто фронтовая (`web/studio.html` + e2e-скрипты),
  Go-код этой задачей не менялся (DoD для чисто фронтовой жалобы не требуется).
