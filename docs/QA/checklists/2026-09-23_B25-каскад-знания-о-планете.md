## Находки

### F1 (блокирующая) — миграция 000073 не применена к живой dev-БД
`schema_migrations` содержит только `000070`/`000071`; `player_planet_knowledge_planet_id_fkey`
в dev-БД — `confdeltype='a'` (NO ACTION). Значит **на запущенном сервере фикс B25 не действует**:
любой путь `DELETE FROM planets` (GeneratePlanets/RegeneratePlanets/DeleteWorld) по-прежнему
падает с ошибкой FK, если у планеты есть знание. Это воспроизведено (см. Команды, вывод:
`ERROR: update or delete on table "planets" violates foreign key constraint
"player_planet_knowledge_planet_id_fkey"`).

- Причина: dev-сервер поднят до появления файла миграции; миграции применяются при старте
  (`cmd/server/main.go:89` → `migrations.Apply`), рестарт не сделан (`AGENTS.md` §4 п.13).
- Сам файл миграции корректен: его SQL проверен в транзакции — каскад удаляет знание
  (п.3, п.4), ошибки FK нет, откат возвращает state без изменений.
- Что требуется: перезапустить dev-сервер (применятся 000073), затем повторить п.2–4 на
  живой БД. Правка кода не нужна — вопрос применения миграции к окружению.

### Мелкое наблюдение (не баг)
`docs/PITFALLS.md` в рабочем дереве содержит лишнюю пустую строку перед `## Прочее`
(диф: `+` пустая строка после правки вырезов кораблей) и убрана строка про
`internal/core/`, `pkg/` — это внешние правки дерева, к B25 не относятся.

## Что не проверено и почему

- **Живой путь удаления планет на dev-сервере** (GeneratePlanets/RegeneratePlanets/DeleteWorld
  через админ-API) — не запускался: (1) джобы пишут в БД, а на dev-БД работают другие агенты
  (`AGENTS.md` §16); (2) без применённой миграции такой прогон гарантированно упал бы на FK
  и оставил БД в неопределённом состоянии. Проверено SQL-эквивалентом в транзакции.
- **DeleteWorld-путь** (каскад `worlds → planets`) — напрямую не запускался; проверен
  RegeneratePlanets-путь (п.4), который удаляет планеты того же мира.
- **Поведение `clearUniverseTx`** (TRUNCATE-путь с временным снятием FK) — вне рамок B25,
  не трогался.
- **Прод/Amvera**: применённость миграции на проде не проверялась (нет доступа).
