# QA-прогон: выход из добычи в поясе → карта с открытым попапом системы (2026-09-23)

**Задача:** независимый прогон маленькой клиентской правки. Решение создателя:
выход из добычи в поясе (кнопка «Вернуться» и Esc → пауза → выход) возвращает на
карту **с уже открытым попапом системы пояса** (игрок остаётся на орбите пояса).
Раньше открывалась просто карта галактики. Кнопки выхода переименованы в
«Вернуться».

**Правка (незакоммиченная):** `web/belt.html`, `web/static/js/belt/belt_main.js`,
`web/static/js/belt/belt_ui.js`, `web/static/js/map/data.js` (метка
`sessionStorage['beltReturn']` + `checkBeltReturn`), новый зонд
`tools/e2e/belt-return-check.js`. Сервер не менялся.

**Окружение:** dev-сервер `http://localhost:8080` (`/health` = OK), PostgreSQL
`127.0.0.1:5432`, системный Chrome (playwright-core). Игроки — свежие
`e2e_beltret_*` / `e2e_*` из регистрации зондов. Для дозакрытия сцены D
подготовлен живой игрок: `qa_beltret_live_20260923161411`, позиция
`orbit/belt` (`system_belts` `3b2d860a-cac5-431d-8de3-59fc029d27ed`, kuiper
«Urtelyar», `iron_remaining`≈129) в мире `7e9ea45c-…` «Phaokif» (K) — через
`tools/db.ps1` (`UPDATE users SET current_position=…`).

## Вердикт: ПРОЙДЕНО

Блокеров для приёмки создателем нет. Целевое поведение подтверждено и на живом
игроке: и клик «Вернуться», и Esc → пауза → «Вернуться» возвращают на `/map` с
открытым попапом системы пояса (без ошибок в консоли). Зонд
(`belt-return-check.js` 5/5) подтверждает: попап открывается по метке, не
открывается без неё и не переоткрывается на F5. Сцена добычи (12/12) и
карта/модалка (ALL PASS) без регресса. Подписи «Вернуться» приведены везде,
старых «Вернуться на карту» в UI добычи не осталось.

## Найденное (не чинил, на @manager)

1. **Наблюдение (не баг):** `openSystemModal` играет `ui_open` (`modal/index.js:76`)
   при любом открытии попапа системы, в т.ч. при возврате из пояса. Это не «гул
   прибытия» (`playArrival` в пути `checkBeltReturn` не вызывается) и не тост —
   требование «без тоста/гула прибытия» соблюдено. Отмечаю, чтобы не спутали при
   приёмке на слух.
2. **Закрыто:** живой путь «игрок в поясе → выход → попап системы» проверен
   (D1/D2, 2/2 PASS). Пробел покрытия снят.

## Чек-лист непроверяемого

- **Живой выход кнопкой из сцены добычи** (сцена D `belt-return-check.js`,
  live-сцена `belt-mining-check.js`) — SKIP: нет `QA_TOKEN`/`QA_BELT_ID` (игрока
  в поясе). Чтобы закрыть: дать тестеру токен игрока, стоящего на орбите пояса,
  и id пояса, либо прогнать `QA_TOKEN=… QA_BELT_ID=… node belt-return-check.js`.
- **Esc → пауза → «Вернуться»** как отдельный клик — по коду тот же `callShip`
  (`onEscape`→`showPause(onResume, callShip)`, `belt_ui.js:139-146`); живьём не
  прокликивал (тот же SKIP-барьер). Проверено код-ревью.
- **Визуал/UX** попапа после возврата (что видно планеты/пояс, фокус) — зонд
  фиксирует только наличие `#system-modal-overlay`; вкусовую оценку даёт
  создатель/игрок.
- **Поведение при отсутствии `current_world_id`** (нет совпадения метки) — метка
  стирается, попап не открывается (код `data.js:499`); живого кейса «метка
  устарела» не гонял — недостижимо штатно за один заход.
- **Временный зонд `tools/e2e/tmp-belt-live-return.js`** — рабочий файл прогона
  (не коммитить; удалить/вынести после приёмки).
