# QA-прогон: заход в пояс при NULL-запасе (фикс 2026-09-23)

**Задача:** точечный прогон фикса блокирующего бага — клиентский пред-чек
`beltMineVerdict` больше не блокирует заход, если `remaining_level` пуст
(`system_belts.iron_remaining IS NULL`; запас инициализируется лениво на первом
`enter`).

**Правка:** `web/static/js/modal/events.js` — удалена ветка «пусто → „Нет данных о
запасе пояса“». Остаются проверки: не в поясе / «выработан» / трюм полон.

**Окружение:** dev-сервер `http://localhost:8080` (`/health` = OK), PostgreSQL
`127.0.0.1:5432`, системный Chrome (playwright-core). Игрок — существующий
`testtest` (`d1afd2a4-…`), мир `Ozyal` (`46cdbffa-…`), пояс
`3c6e168a-04c7-4c5c-abda-70738d8232de` (kind=kuiper, состав iron 0.062).
Токен игрока — HS256 из `.env` `JWT_SECRET` (как в прошлых прогонах).
Перед прогоном пояс сброшен в исходное состояние: `iron_remaining = NULL`,
`current_position = orbit/belt` (SQL-обёртка `tools/db.ps1`).

## Вердикт: ПРОЙДЕНО (5/5 в целевом прогоне; слои 31/31)

Фикс подтверждён: пустой `remaining_level` больше не блокирует заход; сервер
инициализирует запас лениво на первом enter (NULL → 123.797), заход и добыча
работают, `pageerror=0`. Регресс «выработан»/«трюм полон»/стек попапов — без
изменений.

## Найденное (не чинил, на @manager)

1. **`web/static/js/modal/events.js:905-907` — мёртвая ветка.** Ветка
   `if (level === 'выработан') openAlert(...)` находится внутри `else`
   (обработчик клика навешивается только когда `mineTitle` пуст). При
   `level==='выработан'` (`events.js:892`) `mineTitle` непуст → обработчик не
   навешивается → ветка недостижима. Следствие: у выработанного пояса пункт
   «Добывать» дизейблится с `title`, но **алерта по клику нет** (только тултип).
   Спека §4.2 (стр. 276) перечисляет алерт «Пояс выработан», при этом стр. 269
   допускает «алерт/`disabled`», а стр. 281-287 — что disabled-причины «клик не
   проходит вовсе». Формально блокировка соблюдена; несоответствие — между
   комментарием `events.js:903-904` («финальный ответ по клику — алерт»), мёртвой
   веткой и текстом спеки.
2. **`docs/specs/2026-09-23-слои-интерфейса-и-стек-попапов.md:277` — устаревшая
   строка матрицы вердикта.** Строка «запаса нет данных (поле пусто) → „Нет
   данных о запасе пояса“» противоречит фиксу (ветка удалена). Требует правки
   владельцем доков.
3. Наблюдение (не баг): в live-сцене после сброса корабль к жиле индикатор подсказки
   показывал «Подлетите ближе», но добыча всё равно шла (HUD «добыто» росло) —
   подсказка ориентируется на наведение носа в кадре, не влияет на сбор.

## Чек-лист непроверяемого

- **Реальный пояс «выработан»** (`iron_remaining = 0`) — в БД таких нет (0/9674),
  почему: перегенерация оставила только NULL/инициализированные. Закрыто
  интерцептом на клиенте (код-путь), без живого серверного отказа. Чтобы закрыть
  полностью — нужен пояс, реально доеденный до 0 (например, долгий прогон добычи).
- **Алерт «Пояс выработан» по клику** — см. «Найденное» п.1: текущий код алерт не
  показывает (disabled). Это поведение, а не сбой окружения; нужно решение
  создателя/менеджера — оставляем disabled без алерта или навешиваем алерт.
- **Визуал/UX** захода и сцены добычи (красиво/удобно) — скриншоты сняты, но
  вкусовую оценку даёт создатель/игрок.
- **Долгосрочный тренд** (инициализация запаса переживает рестарт сервера,
  поведение при одновременном заходе двух игроков в один пояс) — вне чек-листа,
  не проверял.
