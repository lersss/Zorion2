## Наблюдения (не баги, к сведению)

1. **«набор рецептов: 0» → «Производит».** Спека шага 2 §3.2/§11.4 называет блок «набор рецептов: N»,
   но спека карточек (ревизия 2, §4.2) переименовала его в блок «Производит»; реализация следует
   карточкам. Формулировки двух спек конфликтуют — тестер шёл за фактическим UI (блок «Производит»,
   пустой = подсказка). Дельта для @manager: согласовать текст в спеке шага 2 либо принять ревизию карточек.
2. **Тост «рецепт не создан» практически недостижим через студию.** `POST /studio/api/goods` сразу
   создаёт рецепт (`CreateGood` → `recipe_id != 0`), в каталоге нет good-товаров с `recipe_id=0`,
   а у ресурса раньше срабатывает ветка «ресурс нельзя». Ветка кода остаётся, но покрыть её живым
   флоу без правки данных нельзя.
3. **Смена категории существующего подтипа с рецептом в текущем каталоге даёт законный 409**
   (уникальность кортежа «родитель+категория+семейство+раса», `producer_repository.go:592`), а не
   снятый мёртвый 409 «сначала отвяжите рецепты» (`producer_repository.go:1050`). Все валидные
   категории-слоты у parent=2 заняты (по одной записи на пару категория/семейство), поэтому живой
   сценарий «200» проверен на временном подтипе с свободным кортежем (T9). Это не баг фичи.
4. Порядок нескольких выходов в надписи — «Вода · т1, Пища · т1» (по тиру, затем по имени, `ru`),
   а не в порядке добавления, как в примере спеки «Пища · т1, Вода · т1». Соответствует канону §4
   («порядок устойчивый: по тиру, затем по имени»), пример спеки — иллюстративный.
5. В новом виде карточек попап заметно крупный (CSS `#detailPopup` до `min(1080px, …)`, кегль
   крупнее) — визуально подтверждён скриншотами; вкусовая оценка «читаемость» — за создателем.

## Что не проверено (границы покрытия)

- **Товар без рецепта → «рецепт не создан»** (T7): недостижимо — `CreateGood` всегда создаёт рецепт,
  в каталоге нет good-товаров с `recipe_id=0`. Закрыть можно только правкой данных/кода.
- **Экстремальные/редкие узлы дерева**: подтипы `kind=items`/`energy` с рецептом, узлы-заглушки
  `hstub:*`, многорасовые уровни (family/race) — проверены только дефолтные universal-узлы и
  найденные invite; редкие конфигурации в dev-БД отсутствуют.
- **Визуальная пиксельная проверка 3-й строки на canvas-карточке** (наличие и обрезка текста): подтверждено
  функционально (`prodProducesText`) и скриншотом, но без OCR/пиксельного сравнения («не вылезает ли
  за карточку» на длинных наборах из многих выходов — не проверено, у «Городка» максимум 2 выхода).
- **Копирование набора с непустым собственным набором** (k>0 и m>0 одновременно, частичное копирование)
  — проверено только чистое добавление (k=1, m=0).
- **Оценка «глазами игрока»** (читаемость крупного попапа, шрифты студии) — вкусовое, за создателем.
