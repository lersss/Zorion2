## Найденное

1. **(замечание, не баг спецификации)** `GET /admin/owner-candidates?type=faction` → 422 «type должен быть player|agent» (`internal/handlers/admin_structures.go:152-154`). Спека §11 прямо говорит: «Для `type=faction` отдельный запрос не нужен — полный список в `build-options`». Т.е. поведение соответствует спеке, но расходится с формулировкой пункта 3 задания («работает для player/faction/agent»). Клиент (`build.js`) фракции берёт из `build-options`, эндпоинт faction не зовёт — функционально не ломает. Предлагаю привести формулировку чек-листа к спеке (faction — только через `build-options`).
2. **(мелочь)** Тело `POST /admin/planets/{id}/structures` отвергает `population <= 0` до резолва класса (`admin_structures_create.go:75-78`), т.е. и для строений (у которых поля населения нет). На валидном клиентском флоу недостижимо; поведение безопасно, но калибровка порядка проверок отличается от §5.1 (тип → класс → владелец → население).

Настоящих багов (нарушение спеки/падение/регресс) не найдено.
