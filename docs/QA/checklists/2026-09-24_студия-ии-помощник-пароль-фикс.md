# Прогон @tester — фикс: помощник студии не наследует `OPENCODE_SERVER_PASSWORD`

**Дата:** 2026-09-24
**Суть фикса:** помощник, которого запускает студия (`POST /studio/api/ai/start`), больше не
наследует basic-auth из окружения игрового сервера. Было: помощник требовал авторизацию →
ИИ-кнопки студии падали «401».
**Дифф:** новый `internal/goodsstudio/aiserve/env.go` (чистая `helperEnv`: вырезает
`OPENCODE_SERVER_PASSWORD`/`OPENCODE_SERVER_USERNAME`, регистронезависимо, остальное не трогает),
`env_test.go`; правка `internal/goodsstudio/aiserve/proc_windows.go` (`cmd.Env = helperEnv(os.Environ())`
в `spawnHelper`).
**Сервер:** dev `http://127.0.0.1:8080` на новой сборке (`zorion-server.exe`, PID 46648), `/health` OK.
Помощник на 3456 поднят исправленным спавном.

## Прогнал

```
curl http://127.0.0.1:3456/global/health            # без авторизации
curl -X POST http://127.0.0.1:3456/session          # без авторизации
curl -X POST /studio/api/ai/stop                    # 200
curl -X POST /studio/api/ai/start                   # 202 → poll state=running + version
POST /studio/api/descriptions/fill {"good_ids":["3"]}   # 202 → poll desc_report
POST /studio/api/goods {name:"QA_AI_fix"} → recipes/{id}/components → /goods/{id}/fill   # 202 → poll report
DELETE /studio/api/goods/{QA_AI_fix}                # cleanup
```

## Вердикт

**ПРОЙДЕНО.** Ключевая проверка фикса (п.1) — `/global/health` без заголовка авторизации отвечает
**200** (было 401); первый вызов клиента студии `POST /session` без авторизации — **200** с непустым
`id` (п.2). Помощник после перезапуска студийным `start` поднимается уже без пароля и опознаётся
как `running` с `version=1.18.32` по health-JSON (п.3), а оба живых ИИ-потока (описания и
`goods/fill`) отдают 202 и отчёт без «401»/«connection refused» (п.4–5). Утечка пароля из окружения
игрового сервера в дочерний процесс устранена (`cmd.Env = helperEnv(os.Environ())`,
`proc_windows.go`; `helperEnv` — `env.go`).

## Наблюдения (не FAIL фикса)

- Отчёты п.4/5 — `opencode: пустой ответ`: это **ответ модели/разбора** (честная ошибка ИИ-уровня),
  а не транспорт. Транспорт до помощника подтверждён (health/session 200, fill дошёл до клиента).
  Пустой ответ зависит от модели/промпта и вне объёма этого фикса.
- `version` теперь приходит из health-JSON (`/global/health` 200), поэтому `detail` содержит
  `(v1.18.32)` — то есть fallback «running по владельцу порта» больше не нужен при исправном помощнике.

## Не проверял сам

- **Ветка `managed=false` / прод-путь** — в среде Windows+loopback+npx недостижима; фикс касается
  только Windows-спавна (`proc_windows.go`), вне Windows `helperEnv` не вызывается.
- **Юнит-тесты `env_test.go` и полный Go DoD** (`go vet`, `go test -race -short`) — вне 6 пунктов
  задания; не гонял.
- **Реальный клик по кнопкам студии в браузере** — проверял ручки (`curl`) и живые ИИ-потоки, не
  визуальный UX.
