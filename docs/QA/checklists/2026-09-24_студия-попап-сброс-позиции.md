## Вердикт

**ПРОЙДЕНО.** Правка решает заявленную проблему: после перетаскивания и повторного открытия
(как той же карточки через крестик, так и другой карточки без закрытия) попап возвращается
в исходную центральную позицию (`top=162`, inline `left/top` очищены). Исходный симптом
`bottom=1142 > 800` не воспроизводится при открытии.

## Наблюдения (не FAIL правки)

- **Попап не «центр канваса», а центр `#main`.** `resetPopupPos()` возвращает CSS
  `left:50%;top:50%;transform:translate(-50%,-50%)` (`web/studio.html:184`), а containing block —
  `#main` (full-width, `position:relative`, `web/studio.html:36`). Центр попапа `x=640` = центр
  `#main`, тогда как область канваса `#canvasWrap` (`right:320px`) центрирована на `x≈474`.
  Попап шириной `1082` (`left=99..right=1181`) заходит на правую панель `#right` (`x=948..1268`)
  на ~233px. Это поведение CSS попапа, правкой не менялось (до и после — центр `#main`).
- **Первый drag «прыгает».** Drag-математика (`web/studio.html:4401`) берёт `offsetLeft/offsetTop`,
  которые для transform-центрированного попапа равны `50%` контейнера (≈640/324), а не визуальному
  `99/162`. Поэтому первое смещение мыши на ~89px по X дало скачок `left` на 630px и увели попап
  за нижний край (`after bottom=1102 > 800`). Код drag правкой не тронут (`git diff` — только
  `resetPopupPos`), это предсуществующее поведение; после закрытия/переоткрытия позиция
  корректируется (п.3/4).
