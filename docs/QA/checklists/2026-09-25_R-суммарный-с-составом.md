## Сценарии (чек-лист задачи)

1. **DoD — PASS.** `go build ./...` → exit 0; `go vet ./...` → exit 0;
   `go test -race -short` по 4 пакетам → `ok` (settlement, repository 1.9s,
   handlers 19.1s, web). Точечные прогоны новых тестов — PASS, без skip.
   *Оговорка среды:* первый `go build ./...` упал на
   `internal/repository/content_import.go:588` (`resolveImportMode`) — это
   **чужой незакоммиченный файл** (фича «импорт контента», `?? content_import.go`),
   не относящийся к R-витрине; через ~1 мин файл был доправлен другим агентом,
   повторный build/vet — зелёные. К R-фиче претензий нет.

2. **Сервер: `r_breakdown` у поселения — PASS.** `GET /api/worlds/<Meredsha>/planets`
   с админ-токеном: у `b09380fc…` есть `r_breakdown` (7 рядов: natural, heat, cold,
   gravity, radiation + 2 ряда эффектов). Сумма значений = 0.00119999999366238,
   `r_per_sec` = 0.0011999999936623824, **diff = 2.17e-19** (≤ 1e-12). Ряды эффектов
   несут имя: `code="голод" name="Голод"`, `code="жажда" name="Жажда"` (значения
   0.0006 каждый — тестовая кривая голода). Раса `archivists` → 5 средовых рядов
   без `birth` (нетто в `natural`) — соответствует расовой модели.

3. **Инвариант `EnvBreakdown`/`EnvComponents` — PASS.** `TestEnvBreakdownHumansSumAndCodes`
   (сумма == `EnvComponents`, 6 кодов, нулевые вклады) и
   `TestEnvBreakdownRaceSumAndCodes` (5 кодов, нет `birth`) — PASS; `EnvComponents`
   теперь суммирует `EnvBreakdown` (единый источник, `change_components.go:131-137`).

4. **Утечка игроку (presence) — PASS (покрытием).** Живого игрока с присутствием
   на Meredsha нет (только админ-токен), поэтому проверено покрытием:
   `TestPlayerEffectsDTO` и `TestPresenceSettlementNoCheckpoints` (оба PASS) —
   `stripPlanetDetails` в presence-режиме обнуляет `RBreakdown` (`planet_visibility.go:283`),
   в сыром JSON `r_breakdown`/`r_per_sec` отсутствуют. Живой player-запрос не выполнялся.

5. **Утечка в snapshot/scan/none — PASS.** `TestStripSnapshotModeFrozenPicture`
   (snapshot: `RBreakdown == nil`), `TestStripScanMode`/`TestStripNoneMode`
   (поселения в этих режимах отсутствуют целиком), `TestEffectsOnlyInPresence` —
   все PASS, без skip. `stripSnapshotSettlementSecrets` обнуляет `RBreakdown`
   (`planet_visibility.go:352`).

6. **Клиент, реальный браузер — PASS.** `map-check.js` карточку поселения не
   открывает, поэтому написан временный read-only смоук
   `tools/e2e/tmp-qa-rbreakdown.js` (по шаблону `qa-i23-settlement-view.js`, без
   записи в БД): логин админом → карта → карточка планеты → вкладка «Поселения».
   Результат: `[inline-percent] PASS span="0,120%/с"`,
   `[tooltip-summary] PASS`, `[tooltip-effect-names] PASS` (Голод/Жажда),

   `Жара: 0,000%/с` / … / `Голод: +0,060%/с` / `Жажда: +0,060%/с` /
   `(+ убыль, − рост)`. Скриншот `tools/e2e/artifacts/qa-rbreakdown-admin.png`.

7. **Регресс стрелки — PASS.** `TestKnowledgeTabsInNode` (PASS) проверяет: под

## Найденное

- **Косметика (не баг по спеке):** ряд `natural` у расы `archivists` = −6.34e-12
  (не ровно ноль) → в тултипе `Естественная: −0,000%/с` со знаком минус. Спека
  оговаривает «ровно ноль — без знака»; −6.34e-12 не ноль, поэтому знак
  сохраняется. Выглядит слегка странно, но правилу не противоречит. Решение —
  за создателем (можно считать «шумом» и не трогать).
- **Среда (не баг фичи):** транзиентный провал `go build ./...` из-за чужого
  незакоммиченного `internal/repository/content_import.go` (см. п.1). К R-витрине
  отношения не имеет; на момент повторного прогона дерево собиралось.

## Не проверено (граница покрытия)

- **Живой player-запрос `planets` в режиме presence** (п.4): нет живого игрока с
  присутствием на Mreeredsha и нет его пароля; проверено покрытием
  `stripPlanetDetails`/`playerSettlements`. Чтобы закрыть — нужен player-аккаунт
  с `current_position` на орбите планеты (или разрешение создать его).
- **Визуальная оценка тултипа «глазами игрока»** (перенос строк, читаемость
  подсказки при наведении): проверено DOM-текстом `title` в headless-браузере,
  не наведением мыши в живом окне. Вкусовое/UX — за создателем.
- **Экстремальные значения R** (очень большие/отрицательные, `Inf`/`NaN` в
  разбивке): в БД такого поселения нет; штатно недостижимо. Покрыто только
  обычными значениями.
