## Вердикт

**ПРОЙДЕНО.** Новое поведение (фокус-пауза) подтверждено на живом браузере с
реальными данными: пока фокус на `input`/`select` внутри `#right-panel`, панель не
перерисовывается (0 запросов, DOM не пересобирается, курсор и значение/выбор целы);
по `blur` отложенное обновление применяется. Регресс «неразрушающей перерисовки»
(форма «Построить», скролл, раскрытые детали, админ-формы «Залежи»/«Контракты»,
активная вкладка, изоляция планет A→B) — держится. Явные пути (ручная «Обновить»)
фокусом не блокируются. JS-ошибок в браузере нет.

## Найденное

- **⚠️ Наблюдение (не блокер): лишний запрос при ручном обновлении с фокусом в поле.**
  Ручная «🔄 Обновить» при фокусе в `#build-population` даёт **2** запроса планет
  за 0.6 с, а не 1. Механика: `refresh-planet-btn` (`panel.js:652-657`) сразу зовёт
  `refreshPlanets` → `renderCard` заменяет `panel.innerHTML`, удаляемый
  сфокусированный `input` рождает `focusout` → `onPanelFocusOut` (`panel.js:182-189`)
  видит, что фокус уже вне панели, и применяет «отложенный» флаг
  (`autoRefreshDeferred`, выставлен предыдущим тиком) → второй `refreshPlanets`
  (`panel.js:170-177`). Функционально числа свежие, это лишний запрос/перерисовка.
  Место: `web/static/js/modal/panel.js:182-189` + обработчик `refresh-planet-btn`.
- **6d: вкладка «Магазин» недоступна админу by design** (`marketTabVisible`,
  `tabs.js:626-631`: `knowledgeMode()==='admin'` → false) — не баг фикса, но её
  персистентность слота живьём админ-прогоном не закрыть.
- `panel.js` без newline в конце файла (косметика, тянется с прошлого прогона).

## Не проверено живьём

- **Слот магазина через автообновление (п.6d).** Почему: вкладка скрыта админу
  (`marketTabVisible`), а для игрока нужен отдельный сценарий «знание + орбита +
  `debugAutoRefreshPlanet=1`». Логика выбора покрыта юнит-тестами `resolveMarketSlot`.
  Чтобы закрыть: e2e игрока как в `tools/e2e/market-check.js` + тумблер автообновления.
- **Реально раскрытый нативный `<select>` (п.3).** Почему: headless-браузер не
  показывает системный popup; проверено, что фокус остаётся на `select` и DOM не
  пересобирается (значит, список не закрывался бы перерисовкой). Визуально «список
  открыт 8 с» — за создателем/headed-прогоном.
- **Карточка спутника (регресс старого фикса).** Почему: у доступных планет в БД
  спутников нет (в мир с постройкой не попал газовый гигант со спутниками).
  Чтобы закрыть: мир с газовым гигантом со спутниками.
- **Изоляция формы «Построить» A→B→A (часть п.7).** Почему: п.7 закрыт на «Залежах»;
  buildForms-изоляция (`modalState.buildForms` + `cardPlanetId`) проверена чтением
  кода, не живым A→B для самой формы «Построить».
- **«Вид с орбиты»** — вне задачи (мигание оставлено решением создателя).
- **UX-ощущение паузы** (игрок не видит обновления, пока стоит в форме) — вкусовое,
  решается создателем.

## Предложения в чек-лист (применит @manager)

- Добавить в регрессионный кейс **фокус-паузу**: фокус в `input`/`select` правой
  панели → ≥2 тика (8 с) без запросов планет и без пересборки DOM (probe-атрибут) →
  `blur` → запрос ушёл, значения живы.
- Отдельно: **явный путь** — «🔄 Обновить» при фокусе в редактируемом поле обновляет
  немедленно (запрос < 1 с, фокус не блокирует).
- Пометить, что вкладка «Магазин» админу недоступна by design — нужен игрок со знанием.
- Кандидат-наблюдение для @developer (лишний запрос при ручном обновлении с фокусом) —
  решить, надо ли глушить `focusout`-эффект при программной перерисовке.
