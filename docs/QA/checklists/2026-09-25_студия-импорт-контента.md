## Наблюдения и дефекты

### D1 (minor, фронт) — после «Экспорта» кнопка «Импорт» остаётся неактивной до перезагрузки

**Где:** `web/studio.html:2147-2168` (`exportContent`) не вызывает `refreshImportStatus()`
(объявлена `web/studio.html:2180`; вызывается только на старте `web/studio.html:5092` и в
импорте 2199/2202/2204).

**Шаги:** открыть `/studio` без файла снимка → «импорт контента» неактивна → нажать
«экспорт контента» → файл создан → кнопка **всё ещё неактивна**; активной становится только
после F5.
**Ожидание (§7):** «при наличии файла — активна». **Факт:** активна лишь после перезагрузки.
**Важность:** косметическая (нужен F5), но это ровно критерий T1.
**Готовый кейс:** `T1-obs export-no-refresh` в моём временном скрипте.

### F2 (риск/наблюдение, требует подтверждения @manager/@developer) — метки `code` на dev и на
свежей БД расходятся; импорт dev-снимка на свежую прод-подобную БД падает 409

Вопреки критерию И3 спеки (строка 533) «прод-подобная БД становится точной копией dev».

**Репро:** свежая БД `zorion_qa_import` (миграции + стартовый сид) → копия
`content/catalog.json` из dev → POST `/studio/api/content/import` → **409**
`duplicate key ... "goods_name_norm_key"`; dry-run при этом `mode=managed`, create суммарно 152,
delete 36, blocked 0, unmatched 0.

**Причина (измерено):** метки `code` назначались бэкфиллом по порядку `id`, а `id` dev
разошлись с свежей БД — на dev удалены первые записи, порядок сдвинут:
`goods`: dev `id=3 → метан-ресурс = g_0001`, а свежая БД `id=1 → вода-ресурс = g_0001`;
dev имеет 152 товара против 131 на свежей. Совпадает по имени, но не по метке —
managed-сопоставление по `code` (`internal/repository/content_import.go:508-515`) не находит
запись, делает INSERT и ловит `UNIQUE(name_norm)` (обёрнуто в 409, `content_import.go:1859-1874`).
Импорт **отказывает, не портя БД** — это безопасно, но основная задача «dev → прод» на свежем
проде (после миграций) в текущем состоянии dev недостижима.
**Не утверждаю, что это дефект именно И3** — похоже на расхождение бэкфилла меток (И1) /
нерепродуцируемости dev-БД. Нужно подтверждение, считать ли это ожидаемым (перенос только на
клон dev / предварительное выравнивание) или дефектом.

## На какой БД гонял «Применить» и почему

- **«Применить» гонял ТОЛЬКО на изолированной БД** `zorion_qa_import` (второй сервер :8090),
  через **HTTP** (реальный роут `POST /studio/api/content/import`), а также через интеграционные
  тесты (scratch-схемы `zorion_it_*` внутри той же изолированной БД). Dev-БД `zorion` для
  применения **не использовалась**.
- **Почему:** импорт с полной заменой удаляет записи и на общей dev-БД без бэкапа недопустим.
  На dev выполнил только **безопасные** операции: `status`, `export` (только чтение БД + файл) и
  `import?dry_run=true` (ROLLBACK, БД не пишется). Кнопку «Применить» на dev **не нажимал**.
- **Изоляция:** БД `zorion_qa_import` создана отдельно, миграции накатаны стартом второго
  сервера, после прогона **удалена** (`DROP DATABASE ... WITH FORCE`), сервер :8090 остановлен,
  временный файл снимка удалён. Dev-БД `zorion` структурно не менялась.

## Что не удалось проверить (граница покрытия)

1. **`mode=bootstrap` в браузере/HTTP живьём.** На пустой цели записей с метками нет вовсе, а
   bootstrap требует цель «с записями без меток». Проверено только интеграционным тестом
   `TestContentImportBootstrap`; для живого кейса нужна цель с неразмеченными записями
   (снять `code` у четырёх таблиц на изолированной БД).
2. **Реальный сценарий «dev → свежий прод»** (см. F2): на свежей мигрированной БД метки `code`
   не совпали с dev, импорт вернул 409. Успешный перенос проверен только на предварительно
   **очищенной** цели. Нужно подтверждение от создателя/@developer: прод — клон dev или свежая
   миграция? Если свежая — нужна операция выравнивания/пересборки меток.
3. **Визуальное UX попапа** (удобство диффа, цвета, читаемость blocked-строк) — вкусовое; только
   скриншоты `tools/e2e/artifacts/studio-import-diff-zero.png`, `…-delete.png`, `…-blocked.png`.
4. **Конкурентность:** одновременный импорт двумя админами и импорт поверх активного
   мира/джоба — не запускал (advisory-лок проверен только кодом, не живой гонкой).
5. **Импорт файла, изменённого вручную в редакторе с BOM** — только зафиксировал 400 (см. выше).
