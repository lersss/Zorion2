## Найденное

### Н-1 (дефект, отдать @developer) — 401 на `GET /api/cargo` уводит на вход, но токен не стирает

`web/static/js/dashboard/cargo.js:93-95` — `redirectToLogin()` только меняет `location.href`:

```js
const redirectToLogin = () => {
    if (globalThis.location) globalThis.location.href = '/login-page';
};
```

Остальные четыре обработчика 401 в игровом клиенте токен стирают:

| Файл:строка | Стирает `token`? |
|---|---|
| `web/static/js/dashboard/money.js:110` | да |
| `web/static/js/dashboard/property.js:233` | да |
| `web/static/js/map/data.js:80` (`handleUnauthorized`) | да |
| `web/static/js/modal/index.js:48` | да |
| `web/index.html:904` | да |
| **`web/static/js/dashboard/cargo.js:93`** | **нет** ← расхождение |

`/login-page` (`web/login.html`) тоже не подчищает за собой токен: `localStorage.setItem('token', …)`
только после успешного входа (строка 56), удаления на старте страницы нет. Итог: игрок видит
страницу входа, но в браузере остаётся мёртвый игровой токен.

**Почему это не регресс текущей правки:** `redirectToLogin` в этой правке не трогали
(`git diff` по `cargo.js` меняет только проверки кодов ответа и добавляет `forbiddenText`).
Расхождение было до П-1 и пережило его — но П-1 сформулирован как «стирать вход **только**
на 401», то есть на 401 стирание и объявлено эталоном.

**Влияние (оценка, не замерено в браузере):** страница входа показана, цикла разлогина нет;
эффект — протухший токен в `localStorage` и лишний шаг при возврате «назад» в дашборд.
Проверить «назад → редирект обратно на вход» не гонял — за рамками 7 пунктов.

**Что нужно:** @developer — привести `cargo.js:93-95` к остальным четырём (снять токен перед
редиректом), @manager — регрессионный кейс «401 на любой из 6 точек → `localStorage['token']` пуст
после редиректа».
