### Как вызывалась смерть (п.1, 4, 5)

Смерть на прогулке недостижима «естественно» на мягкой планете: `serverHp` (client) и `surfaceHPAt` (server) считают hp от `landed_at`, при `hazard.total = 0` hp = 100 всегда. Поэтому взята планета с малой, но ненулевой опасностью
(`9890f166-ee80-4733-8719-da18b060061e`, 322 K / 1.88 атм / рад 0.4 → `hazard.total ≈ 0.0143 HP/с`, прогулка длится часы), а hp сбрасывался **правкой своей тестовой учётки через `tools/db.ps1`**:

```sql
UPDATE users SET current_position = jsonb_set(current_position, '{landed_at}', '"2020-01-01T00:00:00Z"')
WHERE id='<uid>' AND current_position->>'status'='surface';
```
Затем — перезагрузка страницы прогулки и клик «Продолжить» в брифинге (цикл кадров стартует только после него, иначе hp не считается). Первая попытка на «жёсткой» планете (2500 K, `hazard.total = 38.9`) была некорректна по двум причинам: смерть наступала за 2.6 с (не успевал нажать «вызвать корабль» в п.2) и без клика по брифингу экран смерти не появлялся вовсе.

## Вердикт: ПРОЙДЕНО (7/7)

## Найденное (не чинил — задача @manager/@developer)

1. **Баг (средний): сетевой сбой на `leave` при смерти оставляет игрока намертво замороженным.**
   `web/static/js/surface/surface_main.js:211` — `const res = await leave();` без `try/catch`. `surface_net.js:9` (`fetch`) отклоняет промис при обрыве сети → `onDeath()` бросает исключение до `ui.showDeath(...)` (`surface_main.js:213`).
   Факт (п.5a): экран смерти не показан, редиректа нет, `pageerror: TypeError: Failed to fetch`, при этом `state.dead = true` и `state.running = false` уже выставлены (`surface_main.js:209-210`) → цикл кадров встал, `Escape`/`pause` заглушены (`surface_main.js:235 if (state.dead) return`), кнопки ухода нет. Игрок без UI и без пути назад до перезагрузки страницы.
   Ожидаемое поведение (на усмотрение разработчика): показать экран смерти с причиной «среда» и дать кнопку (редирект ставится в момент нажатия, сетевой сбой ему не мешает).
2. **Наблюдение (низкий): `leave` с HTTP 500 → редирект на карту есть, а серверный статус остаётся `surface`.**
   `surface_main.js:207-213`: при `res.ok === false` код всё равно показывает экран смерти, и кнопка уводит на карту с окном системы; `Leave` (`internal/handlers/surface_handlers.go:715`) при сбое `UpdatePosition` не пишет позицию. Итог: маркер возврата съеден, игрок на карте с окном системы, а в БД он «на поверхности». Расходится ровно тогда, когда сервер реально не записал позицию (сбой БД), т.е. редко и уже в аварийной ситуации. Ничего не чиним — только фиксируем.
3. **Флак детекта (не регресс):** `surface-walk-check.js` кейс `10g` (прыжок/визор) — прогон 1 FAIL (`idleY=-1`, эталон визора не найден), прогон 2 PASS (`rise=21.5`). Скрипт сам это допускает в комментариях (`rejectOutliers`, до 8 с на поиск эталона, до 3 попыток прыжка).

## Предложения в чек-лист (применит @manager)

- **A-ЗОНА-прогулка, кейс «смерть на прогулке»:** клик «На орбиту» → карта + окно системы **с фокусом на планете прогулки** (не просто карта). Проверять `modalState.selectedPlanetIndex`/`planets[idx].id` = планета прогулки, `worldId` = система.
- **кейс «маркер одноразовый»:** второй F5 карты — окно системы само не открывается, `sessionStorage.surfaceReturn` = `null`.
- **кейс «уход без нажатия»:** смерть без клика → уход со страницы → обычный заход на карту → окно системы не открывается. Суть — маркер ставится **в момент редиректа**, а не при показе экрана смерти (именно это комментирует `surface_return.js:6-8`).
- **кейс «смерть ≡ вызвать корабль»:** сравнение двух исходов (планета в окне системы одна и та же).
- **кейс «сбой сети на `leave` при смерти»:** зафиксировать поведение (сейчас — нет редиректа, страница заморожена). Заведёт на баг 1.
- Устарело/уточнить: способы вызова смерти. Смерть **недостижима на мягкой планете** (`hazard.total = 0` → hp = 100): для тестов нужен либо `landed_at` в прошлом, либо планета с ненулевой опасностью. Это стоит записать в чек-лист, иначе следующий прогон потратит попытку вслепую.
- Способ прогона e2e-скрипта из `%TEMP%`: `playwright-core` импортируется абсолютным путём (`file:///C:/Zorion2/tools/e2e/node_modules/playwright-core/index.mjs`) — NODE_PATH для ESM не работает.
