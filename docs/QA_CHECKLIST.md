# QA Check-List Zorion

> Реестр ручных проверок «проблема → время последней проверки» (критичные точки).
> Файл НЕ растёт: при каждом прогоне перезаписывается только колонка «Последняя проверка».
> Источник структуры: `docs/gamedesign/ideas/qa-checklist.md` (согласовано игроком 2026-09-14).
> Единственный писатель — @manager (63a): состав критичных точек, даты из отчётов инстансов.
>
> **Правило прогона:** полный прогон — после больших релизов / раз в 3–4 мелких релиза;
> при обычной задаче — только затронутые диффом кейсы, списком от @manager.
> Отчёты инстансов @tester — журнал `docs/QA/checklists/<дата>_<задача>.md` (сюда не пишут).

## Актуализация

- Кейсы в чек-лист — только то, что Go-автотесты НЕ покрывают (сквозное, конкурентность, UI). Автотесты не дублируем.
- Кейсы зон добавляются в основном из найденных багов (регрессионные).
- Перевод кейса в Ядро — только по решению игрока, критерий: «поломка = нельзя играть / краш / потеря прогресса». Удаление из Ядра — тоже решение игрока.
- Новая подсистема/пакет → новая зона (добавляет @manager при маршрутизации).
- Владелец файла — @manager (63a): решает состав критичных точек, переносит даты из отчётов инстансов (@tester сюда не пишет).
- Полный прогон — после больших релизов / раз в 3–4 мелких релиза; при обычной задаче — затронутые диффом кейсы, списком от @manager.
- Отчёт инстанса @tester — файл `docs/QA/checklists/<дата>_<задача>.md` (журнал прогонов, растёт); строка «Предложение в чек-лист: …» — в этом отчёте, применяет @manager.
- В отчётах: «прогнал: <список кейсов>».
