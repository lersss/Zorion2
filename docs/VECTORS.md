## Как разносить

1. Определи вектор по **зоне кода** (таблица выше) или по смыслу:
   - генерация/миры/планеты/звёзды/ресурсы/аномалии → **Генерация**
   - системные механики: контракты, эмиссия денег, автозаводы, ретрансляторы → **Новые механики**
   - поселения, население, смертность/рождаемость, тир, заводы, балансировка → **Поселения**
   - NPC, агенты, планировщик, толпы на карте → **Агенты**
   - корабли, спрайты, внешний вид, ассеты → **Визуал**
   - аккаунт/вход/профиль, UI игрока, полёт, инвентарь, деньги игрока, корабль игрока → **Игрок**
   - баг (B-номер, 🔴/🟡/🟢) → **Баги** — фикс по месту бага, зона не важна; 🔴 сразу в работу, 🟡/🟢 в бэклог
2. Мелочь/косметика/баг-фикс ≤ ~30 строк — решай сам по быстрому пути @manager, вектор не обязателен.
3. Сырая идея — оставь в `docs/gamedesign/ideas/`, вектор не запускай.
4. Пожелание не попадает ни в один вектор — **спроси создателя**, не додумывай.

## Правила на горячих точках (идея 46a §3)

1. **Миграции** — бронь номеров через @manager до начала работы (актуальный номер — `docs/DB.md`). Два вектора одну миграцию в одном релизе не добавляют.
2. **`cmd/server/main.go`** — только свои блок-секции: маршруты + инициализация своего менеджера отдельным блоком; общую часть не трогать.
3. **Вкладки админки** — один JS-файл на фичу (AGENTS.md §4.24); в `tabs.js`/`admin.html`/`main.js` — точечные вставки («добавил в конец, не переписал»).
4. **Стык planet ↔ settlement** (Генерация vs Поселения) — владелец общего файла назначается на релиз; второй вектор в этот релиз туда не лезет.
5. **Общие модели/репо** — каждый вектор трогает только свои файлы; правка чужого — через дельту/менеджера, не напрямую.
