# 01. Общая концепция

**Обновлено:** 2026-09-10

---

## 1.1. Что такое Zorion

Zorion — платформа для симуляции живых, самоподдерживающихся миров.

Игрок управляет агентом (кораблём, пчелой, персонажем) и влияет на развитие мира через выполнение контрактов. Мир не привязан к конкретному сеттингу: космос, улей, муравейник, фэнтези — всё это разные «шкурки» одной архитектуры.

**Ключевые сущности:**
- **Мир** — звёздная система с планетами и спутниками.
- **Агент** — сущность, которой управляет игрок.
- **Фракция** — NPC-организация, действующая в мире.
- **Контракт** — единственный способ изменения мира.

---

## 1.2. Ключевые принципы

- **Мир живёт независимо от игрока.** Симуляция идёт 24/7. Фракции воюют, торгуют, колонизируют, даже если игрок офлайн.
- **Все изменения — через контракты.** Игрок не может «просто изменить» мир: он берёт контракт и выполняет его. Это упрощает логику и делает все изменения отслеживаемыми.
- **Информационная асимметрия.** Игрок видит только то, что находится в его мире или доступно его агенту.
- **NPC-фракции активны.** Они создают контракты, воюют, торгуют, колонизируют. Игрок — не центр вселенной, а один из её обитателей.

---

## 1.3. Абстрактные сущности

Архитектура проекта построена на абстрактных сущностях, чтобы легко менять сеттинг:

| Абстракция | Космос | Улей | Фэнтези |
|-----------|--------|------|---------|
| Мир | Звёздная система | Улей | Королевство |
| Локация | Планета / спутник | Соты | Поселение |
| Агент | Корабль | Пчела | Персонаж |
| Фракция | Империя / корпорация | Колония | Гильдия |
| Ресурс | Минералы, газы | Пыльца, воск | Руда, травы |

В MVP «шкурка» — космическая, но код не завязан на неё.

---

## 1.4. Технологический стек

- **Бэкенд:** Go 1.21+
- **БД:** PostgreSQL 15+ (Event Store, снэпшоты)
- **Кеш/брокер:** Redis 7+
- **Фронтенд:** HTML5, CSS3, Vanilla JS (ES-модули)
- **Деплой:** Docker + Amvera (PaaS)

---

## 1.5. Архитектурные решения

| Решение | Обоснование |
|---------|-------------|
| Go + акторы | Производительность, малый размер контейнера |
| Event Sourcing + CQRS | Аудит, откат времени, масштабируемость |
| JSONB для состояния | Гибкость, быстрая эволюция схемы |
| Гибридное время | Детерминизм + плавность симуляции |
| Контракты — единственный способ изменения | Упрощает логику, делает изменения отслеживаемыми |
| Монолит на старте | Быстрый старт, простота деплоя; разделение позже |
| Абстрактные сущности | Универсальность для любых сеттингов |
| Числовые свойства ресурсов | Гибкость, сложные рецепты |
| Асинхронные решения фракций | Снижение нагрузки, естественное поведение |
| Админка с настраиваемыми параметрами | Гибкость тестирования и балансировки |
| Откаты = «Флуктуации Вакуума» | Игровое объяснение технических сбоев |
| Кластерная генерация вселенной | Естественный вид карты |
| Генерация планет отдельно от вселенной | Контроль, предотвращение дублирования |
| Архетипы планет (конструктор) | Гибкость, ~500 комбинаций |
| Серверная генерация текстур | Детерминизм, контроль качества, кеширование |
| Фильтры на бэкенде | Минимальный размер ответа, масштабируемость |
| Матрица совместимости в БД | Редактируется через админку, применяется сразу |
| Композиция вместо типа планеты | Гибкость, реалистичность |
| Ядро как первичная сущность | Физическая обоснованность температуры |
| Масса первична, размер через плотность | Реализм, R = (M/ρ)^(1/3) |
| Спутники газовых гигантов как локации | Расширение геймплея без усложнения |

## 1.6. Политика логирования

- **INFO** — основные этапы работы (генерация миров, планет, запуск симуляции).
- **ERROR** — критические ошибки, требующие внимания.
- **DEBUG** — используется только для отладки и удаляется после исправления бага.

В MVP дебаг-логи отсутствуют. При необходимости они включаются через переменную окружения `DEBUG=true`.

## 1.7. Симуляция мира

**Тик** — базовая единица времени симуляции. По умолчанию 3 секунды, настраивается через `TICK_INTERVAL_SEC`.

**Периодичность процессов:**

| Процесс | Как часто |
|---------|-----------|
| Экономика (производство, потребление ресурсов) | Каждый тик |
| Операционные расходы фабрик | Каждый тик |
| Энергобаланс планетарного рынка | Каждый тик |
| Генерация контрактов фракциями | Асинхронно (30–60 тиков + смещение) |
| Решения фракций (расширение, войны, дипломатия) | Асинхронно (30–60 тиков + смещение) |
| Демография (рост/убыль населения) | Событийно и при чтении (ленивый пересчёт) |
| Пересчёт силы фракций | При изменениях (захват мира, потеря ресурсов, конец войны) |
| Пересчёт цен на товары | По запросу (при покупке, продаже, открытии рынка) |

**Почему асинхронно:** каждая фракция принимает решения по своему внутреннему таймеру. Это снижает нагрузку на сервер (не все фракции думают одновременно) и делает поведение NPC естественнее — они не «дёргаются синхронно».

**Большой Тик** — условный цикл, в конце которого применяются эффекты выполненных контрактов. Игрок видит результат не мгновенно, а с небольшой задержкой (следующий Большой Тик). Это создаёт ощущение живого мира, где изменения «докатываются» постепенно.
