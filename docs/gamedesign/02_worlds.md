## 2.1. Генерация миров

- **Алгоритм:** Пуассона с кластерной структурой.
- **Координаты:** целочисленные, внутри круга радиуса MapSize.

**Параметры (настраиваются в админке):**

| Параметр | По умолчанию |
|----------|--------------|
| Количество миров | 1000 |
| Количество кластеров | 20 |
| MapSize (радиус круга) | 8000 |
| minDist (мин. расстояние) | 150 |
| Радиус кластера | 1200 |
| Расстояние между кластерами | 200 |
| Процент выбросов | 30% |
| Форма кластера | blob (бесформенное облако) |

**Кластеры и выбросы** (с 2026-09-12):
- **Форма кластера** — параметр `shape` в админке: `blob` (по умолчанию,
  бесформенное облако из 2–4 перекрывающихся гауссовых очагов, `clusterPointsBlob`)
  или `circle` (классический круг, `clusterPointsCircle`).
- Точки кластера — **гауссовой плотностью**: плотнее к центру, реже
  к краям (std = `ClusterRadius`×0.7 для круга; 0.25–0.5 радиуса у очагов blob).
- Граница кластера **размытая**: внутри радиуса принимается всё, на кольце
  `R…1.25R` — с линейно убывающей вероятностью (`clusterEdgeAccept`). Жёсткий
  обрез убран — он давал видимое «кольцо» из звёзд.
- Выбросы распределяются **гауссовым смещением от случайного кластерного
  центра** (std = `ClusterRadius`×3) — тяготеют к кластерам, но заполняют
  пустоты между ними (`generateOutlierPosition` в `poisson.go`).

**Типы систем и объектов (распределение; эталон менеджера, идея 29a §4ж):**

| Тип системы / объекта | Доля |
|---|---|
| Одиночная обычная звезда | 85% |
| Двойная обычная | 5% |
| Кратная (3+) обычная | 2% |
| Чёрная дыра | 1% |
| Нейтронная звезда | 1% |
| Белый карлик | 2% |
| Протозвезда | 1% |
| Прочая экзотика (сверхгиганты, фаза I) | 3% |

«Экзотическая ~5%» старой версии = белый карлик ~2% + прочая экзотика ~3%
(решение §4ж.4в.1). Детали модели (3 ортогональных слоя: тип системы / тип
объекта / модификаторы), модификаторы и их гейты — спека
`99.2.4-exotic-stars.md` §2–4.

## 2.2. Спектральные классы

**Распределение** близко к реальному (M — самая частая), но с чуть большим количеством «интересных» звёзд для геймплея:

| Класс | Доля | Диапазон T (K) |
|-------|------|----------------|
| O | 0.5% | 30000–50000 |
| B | 2% | 10000–30000 |
| A | 4% | 7500–10000 |
| F | 7% | 6000–7500 |
| G | 12% | 5200–6000 |
| K | 17% | 3700–5200 |
| M | 32% | 2400–3700 |
| L | 8% | 1300–2400 |
| T | 8% | 700–1300 |
| Y | 9.5% | 300–700 |

**Почему не «как в реальности»:** в Млечном Пути 76% звёзд — класса M, а O/B/A встречаются крайне редко. Если бы мы сделали так же, игрок почти не видел бы «интересных» (горячих, ярких) звёзд. Поэтому распределение сдвинуто в сторону более разнообразных систем.

## 2.4. Параметры звезды

Каждая звезда имеет:
- **Название** — генерируется по слогам (латиница).
- **Спектральный класс** — O, B, A, F, G, K, M, L, T, Y (у экзотики NULL).
- **Температуру в K** — согласована со спектром (см. таблицу выше); у ЧД и
  нейтронных — честная T из спеки 99.2.4 §5.1.
- **Цвет на карте** — определяется спектральным классом (экзотика — своим
  типом, спека 99.2.4 §8).
- **Тип системы** (`system_type`) — одиночная / двойная / кратная.
- **Тип объекта** (`star_type`) — обычная звёзда / белый карлик / нейтронная /
  чёрная дыра / протозвезда.
- **Модификаторы** (`stellar_mods`) — фаза, переменность, подтипы, параметры
  системы (открытый JSONB-набор; спека 99.2.4 §2, §4.3).
- **Масса** — M☉ (`worlds.stellar_mass`), диапазоны по классу/типу (спека
  99.2.4 §4м, 99.2.3 §4).

## 2.4а. Эталоны (FAQ)

> Формат: вопрос — эталон, заданный менеджером/создателем (идея 29a) и
> зафиксированный дизайнером 2026-09-15. Источник сути — идея `29a` (§4а,
> §4г/§4е — вердикты астронома, §4ж — финальный список, §4и — дополнения
> создателя про админку) и спека 99.2.4. Ответов без эталона здесь нет.

**Вопрос:** Какой финальный список типов систем/объектов и их доли?
**Ответ (эталон менеджера, идея 29a §4ж):** одиночная 85%, двойная 5%, кратная
3+ 2%, чёрная дыра 1%, нейтронная 1%, протозвезда 1%, белый карлик ~2%, прочая
экзотика ~3%. («Экзотическая ~5%» старой редакции = WD ~2% + прочая ~3%.)

**Вопрос:** Какие светимости и температуры у экзотических объектов (порядки)?
**Ответ (эталон астронома §4е, зафиксирован 2026-09-15):** WD L 10⁻²–10⁻⁴ L☉,
T 5–30 тыс. K; нейтронная L 0.01–1, T 10⁵–10⁶ K; ЧД без аккреции L ≈ 0, с
аккрецией диск L 10²–10³, T 10⁵–10⁷ K; протозвезда L 1–10², T 3–4 тыс. K.
Fallback «ЧД как Солнце» (L=1.0) запрещён (§4д.4).

**Вопрос:** Сколько планет у разных типов звёзд?
**Ответ (эталон менеджера §4и.3, на базе вердикта астронома §4е; mean O–Y обновлены 2026-09-21, реализм распределения):** среднее
число планет по типу (mean): M ~5.5 / K ~5.5 / G,F ~6.5 / A ~1 / O,B ~0.3 /
L,T,Y ~1; типично 5–7 планет у солнцеподобных, 8 — через множители/конфиг;
потолок 8 (Kepler-90); ЧД 0–2 (чаще 0), нейтронная 0–3 (чаще 0), WD 0–2 (+ пояс),
протозвезда — диск; двойные широкие ×0.8–1.0, тесные ~0.2. Механика:
`n = floor(mean) + Бернулли(frac)`, потолок 8. Дефолты конфига — спека 99.2.4 §5.2.
> Примечание (уточнение 2026-09-15): диапазоны «0–2»/«0–3» у остатков —
> **наблюдаемая вилка астронома**, не mean и не обещание генератора: при
> mean < 1 механика даёт максимум 1 планету, «чаще 0» сохраняется. См. спека
> 99.2.4 §5.2.
> Примечание (2026-09-22, пояса): у белого карлика `disk_state='debris'`
> материализуется поясом малых тел (`system_belts`, спека
> `2026-09-21-пояса-малых-тел-объект-системы`); для видимых игроку поясов показ
> пояса вытесняет прежний `disk_state='debris'` (спека поясов этап 2, РБ3).

**Вопрос:** Как устроены генераторы в админке (раздел D ТЗ)?
**Ответ (эталон создателя §4и, зафиксирован 2026-09-15):** генеративные
вкладки получают подвкладки-дропдаун (Звёзды / Планеты / Поселения / Гипотезы /
NPC-агенты); генератор звёзд = параметры вселенной + блок весов спектральных
классов (O–Y) + блок весов типов систем/объектов (+ автоподсчёт процентов) +
таблица «среднее число планет по типу звезды»; генератор планет — **без
весов** (§4и.2). Детали — спека `99.2.3-generation-tuning.md`.

## 2.6. Регионы галактики

Регион — сектор галактики вокруг кластерного центра. Нужны, чтобы на малом зуме
карта показывала структуру галактики (цветные «туманности» с названиями), а не
бессмысленный набор точек.

**Генерация** (в `internal/generator/galaxy/galaxy.go`):
- Один регион на кластерный центр, радиус = `ClusterRadius`.
- Выбросы и добивка приписываются ближайшему региону (`WorldCount`).
- Имя — `internal/names.GenerateRegionName`: кириллица, курируемые корни +
  окончания, правило созвучия (согласная+гласная на стыке), ~30% с префиксом
  («Сектор …», «Туманность …»). Пространство ~540 базовых имён — хватает
  на сотни регионов.
- Цвет — из палитры `regionColors` (по индексу региона).

**Хранение:** таблица `regions` (миграция `000015`), заполняется в той же
транзакции, что и `worlds` при `GenerateUniverse`. На старых данных пусто.

**API:** `GET /api/regions` — регионы, пересекающие viewport.

### 2.6.1. Профиль региона

Регион несёт **профиль** — набор типичных для него кризисов и благ,
обусловленный конкретной причиной: квазар, звезда с токсичными выбросами,
база пиратов, древняя катастрофа, неземная жизнь.

**Профиль — атрибут региона, не событие.** Кризис — событие, которое
профиль делает вероятным. Профиль задаёт **тип**, не частоту.

**Правила:**

- **1–2 профиля на регион, чаще один.** Игрок читает регион как единицу
  внимания. Два профиля — уже текст, а не картинка.
- **Классы, не уникальные записи.** Десять–пятнадцать классов на всю
  галактику, расширяются по мере написания игры. Список открытый.
- **Интенсивность: слабая / средняя / сильная.** Даёт градиент без
  второй сущности. Слабый квазарный регион — почти нормальный.
- **Причина физическая или контентная.**
  - Физическая (квазар, токсичная звезда) — видна на карте с любого
    расстояния. Это астрономия, не разведка.
  - Контентная (пиратская база, древняя катастрофа) — скрыта, открывается
    разведкой или наблюдением.
- **Последствия скрыты всегда.** Профиль не публикуется ярлыком.
  Игрок видит причину и сам выводит следствия. Типичные кризисы и блага
  открываются наблюдением.
- **Двусторонность — у части профилей.** Квазарный, токсичный, хищный —
  и проблема, и благо. Пиратский, мёртвый — только проблема. Плодородный —
  только благо. **Моно-регионы законны.** Если у каждого профиля есть
  благо, смертельных мест не остаётся, и градиент сада/фронтира теряет
  вторую половину.

**Примеры классов:**

| Профиль | Причина | Типичные кризисы | Типичные блага |
|---|---|---|---|
| Квазарный | Квазар | Бури, помехи связи, радиация | Редкие элементы, аномальные ресурсы |
| Токсичный | Звезда с выбросами | Коррозия, отравление | Химическое сырьё, катализаторы |
| Пиратский | База NPC-пиратов | Набеги, грабежи | Чёрный рынок, наёмники |
| Мёртвый | Древняя катастрофа | Радиация, упадок | Артефакты, редкие сплавы |
| Хищный | Агрессивная жизнь | Нападения | Биоматериалы, оружие |
| Плодородный | Полезная жизнь | — | Избыток продовольствия |
| Заброшенный | Брошенный флот | Обломки, ловушки | Металлолом, технологии |

Список открыт. Новый класс — одна запись в конфиге, не правка кода.
