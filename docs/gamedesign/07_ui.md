# 07. Интерфейс

**Обновлено:** 2026-09-12

---

## 7.1. Карта миров

- **2D Canvas.**
- **Зум** (колёсико + кнопки) — от 2% до 1000%.
- **Панорамирование** (перетаскивание).
- **Кнопка «Найти меня»** — центрирование на текущем мире.
- **Цвет миров** соответствует спектральному классу звезды.
- **Размер миров** зависит от спектрального класса.
- **Клик по миру** → открывается модальное окно системы.
- **Фильтры** — панель под шапкой:
  - Фильтрация по планетам (наличие, жизнь, обитаемость, тип поверхности, ресурсы).
  - Бэкенд-фильтрация, debounce, счётчик активных фильтров, спиннер.
- **Сохранение вьюпорта** — позиция и масштаб в `sessionStorage`.

### 7.1.1. Регионы (малый зум)

- При зуме ниже порога (`scale < 0.05`) вместо «бессмысленных шариков» кластеров
  карта показывает **регионы галактики**: диаграмма Вороного по кластерным центрам,
  каждая ячейка залита своим цветом, границы — цветные линии, название — в центре.
- Регионы генерируются при `GenerateUniverse` (по одному на кластерный центр),
  хранятся в таблице `regions`.
- Цвет — из палитры генератора, имя — `names.GenerateRegionName`.
- Данные: `GET /api/regions` (все регионы — для Вороного нужны все центры).
- На малом зуме звёзды не рисуются — только регионы.

### 7.1.2. Зум

- `minZoom` привязан к размеру галактики.
- Отображение зума: минимум «1%», при масштабе «вся галактика» — подпись «Галактика».
- Отдаление ускоряется при приближении к минимуму.

### 7.1.3. Трафик как разведданные

**Статус:** дизайн — решено · код — нет

С введением контракта на перелёт (`11_contracts.md` §11.3.4) карта получает новый
слой: **корабли в пути**.

- **Полёт детерминирован.** Хранится `(откуда, куда, t_вылета, t_прибытия)`,
  рисуется интерполяцией.
- **Считается только при попадании в радиус радара** (`06_factions.md` §6.7.7).
- **Радар становится капитальным предметом.** Кто видит трафик, тот знает, куда
  едут люди.
- **Карта миграции.** Видно, куда стекаются агенты, где точка притяжения. Это
  бесплатная разведка о чужих планах — по контрактам на перелёт, которые видны
  как опубликованные заказы.

**Ограничение.** Корабли не рисуются вне радиуса радара. Владелец без радара не
видит ничего.

### 7.1.4. Запрет: живое состояние поселений в галактических фильтрах

**Статус:** дизайн — решено · код — нет

**Живое состояние поселений не выносить в галактические фильтры.**
Ленивый пересчёт (`11_production.md` §11.1.2) не покрывает случай «показать все
голодающие планеты разом»: пришлось бы оценить все протухшие поселения за один
запрос. Прецедент — B9, фильтр по ресурсам на 319k планет стоит ~1 с.

Если такой фильтр всё же нужен — только через грубый материализованный снимок,
обновляемый редко.

## 7.2. Модальное окно системы

### 7.2.1. Общее

- Отображает **звезду** (цвет и размер по спектру) и **планеты на орбитах**.
- Планеты имеют **процедурные текстуры**, генерируемые на сервере.
- **Зум** (колесо мыши) и **панорамирование** (перетаскивание).
- **Мини-карта** в углу — общий вид системы (TODO: несовпадение вьюпорта).
- **Закрытие:** клик на оверлей или ESC.

### 7.2.2. Правая панель

Список планет (таблица) или детальная карточка с вкладками:
- Общее
- Ресурсы
- Поселения
- Фракции

**Клик по планете** — выбор планеты, подсветка золотым кольцом, показ детальной
информации.

### 7.2.3. Газовые гиганты

Отображаются как центральное тело. Вокруг — **спутники** (`04_composition.md`
§4.3). Клик по спутнику — открывается его карточка.

## 7.3. Карточка планеты

### 7.3.1. Общее
- Тип (геймдизайнерский).
- Температура.
- Вода (%).
- Атмосфера.
- Биосфера.

### 7.3.2. Ядро
- Тип (металлическое, силикатное, ледяное, экзотическое).
- Активность (0–100).
- Радиоактивность (0–100).
- Возраст (млрд лет).
- Флаги: активное / металлическое / радиоактивное.

### 7.3.3. Физика
- Масса (в земных).
- Размер (радиус, в земных).
- Плотность (в единицах Земли).
- Альбедо.

### 7.3.4. Поверхность
Только ненулевые компоненты.

```
Поверхность: 30% скалы, 40% ледники, 30% океаны
```

### 7.3.5. Недра
Только ненулевые типы.

```
Недра: 60% пустая порода, 25% рудные жилы, 15% подземные воды
```

### 7.3.6. Ресурсы
Список с иконками категорий (🪨 Атрокс, 🔥 Бролин, 💨 Зорнит).

**Разделение на слои.** Универсальный слой (`09_resources.md` §9.2.2) показывается
отдельно от полевых веществ: фон — известен сразу, поля — требуют разведки.

### 7.3.7. Поселения
Список поселений на планете, каждое — с четырьмя числами (§7.4.1). Клик —
раскрытие.

### 7.3.8. Фракции
Список присутствующих фракций.

### 7.3.9. Профиль риска

**Статус:** дизайн — решено · код — нет

**Профиль риска известен заранее и виден до постройки** (`18_needs.md` §18.3.3).
В карточке — отдельный блок рядом с климатом:

- Вулканическая активность (трясётся / спокойна).
- Плотность атмосферы (бури).
- Близость к звезде (вспышки).
- Общая оценка: **автономия до катастрофы** в сутках.

**Сравнительное.** «Автономия: 4 часа» — число. «Автономия: 4 часа. На
землеподобной планете — 9 суток» — решение (`18_needs.md` §18.3.2).

### 7.3.10. Правило отображения
**Нулевые значения не показываются.** Ни в поверхности, ни в недрах.

## 7.4. Поселения

**Статус:** дизайн — решено · код — заглушка (вкладка есть, пустая)

### 7.4.1. Видимость: смотреть — все, управлять — владелец

**Карточка поселения видна всем, включая роевого игрока.** «Сложность
добровольна» (`11_production.md` §11.1.3) означает «не обязан управлять», а не
«не видит». Магнатами не рождаются.

Более того, карточка чужого поселения — **рабочий инструмент роя, а не витрина**:

```
Стабильность 34 ▼   запас топлива: 1.2 сут
```

Это заявка на поставку, видимая с орбиты. Продовольственный и топливный торговцы
находят клиентов именно так. **Карточка поселения — доска спроса**, с которой
берутся контракты.

### 7.4.2. Четыре числа

```
население / занято / стабильность / запас по жёсткой потребности в сутках
```

Больше ничего на верхнем уровне. Всё остальное — за раскрытием.

### 7.4.3. Раскрытие стабильности

**Список причин, отсортированный по ущербу**, а не набор индикаторов:

```
Стабильность 34 ▼

  ✖ Отопление        −30    топлива на 1.2 сут   [заказать]
  ✖ Медикаменты      −20    нет 6 сут            [заказать]
  ✖ Последствия бури −16    восстановление 3 сут [ремонт]
  ✔ Продовольствие     0    запас 9 сут
```

Требования к экрану:

- **Сложность для игрока постоянна независимо от числа потребностей.** Три их
  или пятнадцать — читается верхняя строка. Список растёт, нагрузка на внимание
  нет.
- **Каждая строка подразумевает одно и то же действие — разместить контракт.**
  Новых глаголов не появляется. Drill-down поселения фактически является
  конструктором контрактов.
- **Жёсткие потребности помечены отдельно.** Игрок должен различать «плохо» и
  «скоро конец» с одного взгляда.
- **Цифра рядом с причиной — её вклад.** Формула стабильности прозрачна.

> **Ни одна вторичная потребность не получает собственной панели управления.**
> Это условие, при котором интерфейс выдерживает произвольное число потребностей.

### 7.4.4. Терпение

**Статус:** дизайн — решено · код — нет

Терпение (`18_needs.md` §18.2.2) — запас, который тратится на перебои.
Отображается в карточке поселения как второе число рядом со стабильностью:

```
Терпение 6 сут ▼   (тратится при простое завода)
```

Когда терпение кончается — рабочие уходят. На землеподобной планете в поля, на
ледяном спутнике — умирают. Игрок должен видеть порог до того, как он наступит.

### 7.4.5. Предполётная проверка

**Статус:** дизайн — решено · код — нет

**Второе место предупреждения после карточки планеты** (`18_needs.md` §18.3.2).
Перед отлётом — диалог:

```
Тея-4 · отопление на 4 ч 20 мин · поставок не назначено
Улететь?
```

**Первое информирует, второе предотвращает.** Без предполётной проверки механика
честна по правилам, но ощущается ловушкой.

**Сравнительное.** «Автономия: 4 часа» — число. «Автономия: 4 часа. На
землеподобной планете — 9 суток» — решение. Одна строка, а держит человека на
переходе из роя в владельцы.

## 7.5. Экран магната: управление по исключениям

**Статус:** дизайн — решено · код — нет

Карточка поселения — для диагностики. Со ста поселениями её не открывают.
`11_production.md` §11.1.3 требует управления по исключениям, значит основной экран —
один список на всё хозяйство, отсортированный **по времени до коллапса**:

```
Тея-4      отопление      1.2 сут    [заказать]
Кассис-2   продовольствие 3 сут      [заказать]
Ирн-9      медикаменты    стабильно, −20
Вулкан-7   ущерб 78 %     [переделать на роботов]
```

Столбцы:

- **Точка** — планета и поселение.
- **Что не так** — доминирующая причина падения стабильности.
- **Сколько осталось** — время до коллапса или до исчерпания бюджета.
- **Действие** — одно, контекстное: заказать, переделать, эвакуировать.

**Сортировка по времени, а не по алфавиту.** Владелец смотрит верхнюю строку,
чинит её, смотрит следующую. Без этого списка сто поселений неиграбельны, сколько
бы ни был хорош drill-down.

### 7.5.1. Кошельки автоматических заводов

**Статус:** дизайн — решено · код — нет

Автоматический завод требует постоянного снабжения (`14_money.md` §14.6.3).
Бюджет — кошелёк, который тратится по факту поставок. В экране магната —
отдельный столбец:

```
Тея-4      бюджет 4 200 кр.  ≈ 8 сут
Кассис-2   бюджет 800 кр.    ≈ 1.5 сут   [пополнить]
```

Сортировка та же: по времени до исчерпания.

## 7.7. Страница контрактов

- Список контрактов с фильтрами.
- Фильтр **«с выводом»** — подряды (`15_monetization.md` §15.4.4). Главный фильтр.
- Кнопка «Взять».
- Для тестовых контрактов — кнопка «Выполнить».

### 7.7.1. Карточка контракта на перелёт

**Статус:** дизайн — решено · код — нет

Отдельный вид карточки, потому что контракт на перелёт (`11_contracts.md` §11.3.4)
устроен иначе, чем поставка.

```
Перелёт: Атрокс-3 → Тея-4
Требования: двигатель не хуже класса B
Цена: 4 200 кр.
Ожидаемый профит: ≈ 1 200 кр. после топлива
Срок: 6 ч 20 мин
[Взять]
```

**Ожидаемый профит виден до взятия** — тот же принцип, что `15_monetization.md`
§15.4.3 для подрядов. Без этой строки игрок не может решить.

**Зачем контракт — не пишется.** Дело заказчика.

### 7.7.2. Карточка подряда

**Статус:** дизайн — решено · код — нет

```
Подряд: разведка сектора Тея, 3 отчёта, глубина — недра
Оплата: 12 000 кр. · из них выводимо ≈ $2.40
[Взять]
```

**Сумма вывода видна до того, как игрок взялся** (`15_monetization.md` §15.4.4).
Без этой строки механизм не работает вообще.

**Для присутствия** — диапазон, потому что точная сумма неизвестна:

```
Подряд: присутствие на Тее-4, срок — 7 суток
Оплата: доля 15 % от выработки, ожидаемо 8 000–14 000 кр.
        из них выводимо ≈ $1.60–2.80
```

## 7.8. Карточка завода

**Статус:** дизайн — решено · код — нет

### 7.8.1. Тип рабочей силы

Завод может быть человеческим или автоматическим (`19_robots.md` §19.1).
В карточке — явно:

```
Завод «Тея-4, линия 2»
Тип: человеческий, привязан к поселению Тея-4
Смена: укомплектована (1/1)
```

или

```
Завод «Тея-4, линия 2»
Тип: автоматический
Содержание: энергия, комплектующие, запчасти
```

### 7.8.2. Переделка

Кнопка **«Переделать»** с выбором направления (`11_production.md` §11.1.1). Стоит
времени и ресурсов, как переключение категории. Одна кнопка, два применения.

### 7.8.3. Накопленный ущерб

**Статус:** дизайн — решено · код — нет

Постройка копит ущерб от катастроф (`18_needs.md` §18.3.4). Заживает, пока
работает. При превышении порога — обрушение.

```
Накопленный ущерб: 34 / 100   (заживает: −2/сут, работает)
```

или

```
Накопленный ущерб: 82 / 100   (не заживает: завод простаивает)
                        ⚠ через 9 суток — обрушение
```

**Порог виден всегда.** Игрок должен понимать, сколько осталось, до того как
постройка рухнет.
