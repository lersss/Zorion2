## 8.2. Крупные блоки в разработке

### 8.2.1. Аномалии как контент

Редкие «нарушения» физики — не баги, а фичи мира. Библиотека **готова** (22 JSON-файла
в `config/anomalies/`). Осталось превратить её в рабочий контент:

1. **Go-код:** чтение `config/anomalies/` при старте, кеш в памяти под `RWMutex`.
   Ошибка чтения JSON — `log.Fatal`, а не старт с полупустым кешем.
2. **API:** эндпоинт, отдающий тексты фронту.
3. **Детекция на фронте:** по кодам из аудита (см. `internal/audit/planet/`).
4. **Показ:** отдельный блок в карточке планеты, под описанием.
   Может быть несколько аномалий на одной планете.

Формат и список — в `config/anomalies/README.md`.

### 8.2.2. LLM-генерация описаний

**Идея:** при создании планеты (в `GeneratePlanets`) генерировать уникальные описания
через LLM и сохранять в БД. Детерминизм обеспечен — читается из БД, а не генерится
на каждый запрос.

**API на выбор:**
- **Groq** — быстрый, 1000 запросов/день бесплатно.
- **YandexGPT 5 Lite** — 10 млн токенов/месяц, работает из РФ.
- **Google Gemini** — 30 запросов/день.
- **OpenRouter** — 26+ бесплатных моделей.

**Что генерировать:**
- Обычные описания планет (вместо библиотеки `config/descriptions/`).
- Описания аномалий.

**Fallback:** если API недоступен — библиотека `config/descriptions/` + библиотека аномалий.

**Архитектура:**
- Пакет `internal/llm/` — обёртка над API.
- Вызов из `GeneratePlanetsForWorld` после генерации планеты.
- Батчи по 100 планет с параллельным запросом.
- Поле `description` уже есть в JSON планеты — не надо миграций.

### 8.2.3. Тонкая настройка генерации

Все хардкод-константы вынести в конфиг, редактируемый через админку:
- Спектральные классы (веса, диапазоны T).
- Планеты (количество, возраст, шансы газовых гигантов).
- Классификатор (пороги).
- Физика (альбедо, парниковые факторы).
- Ядро (пороги массы, диапазоны).
- Композиция (множители по T и воде).

**Хранение:** JSON-дефолты + override в БД (как у матрицы совместимости).

### 8.2.4. Экзотические типы звёзд

**Идея:** добавить в генерацию редкие «экзотические» звёзды и системы вокруг них.
Список типов систем с распределением уже заявлен в `02_worlds.md` §2.1
(нейтронная звезда 1%, чёрная дыра 1%, протозвезда 1%, экзотическая ~5%),
но **в коде не реализован** — `internal/generator/galaxy/galaxy.go` генерирует
только обычные спектральные классы O–Y.

**Продумать (главный открытый вопрос):**
1. **Список типов** — нейтронные звёзды, пульсары, магнетары, чёрные дыры,
   белые карлики, квазары, красные гиганты, протозвёзды. Что входит, что нет.
2. **Генерация объектов в таких системах** — как это отличается от обычной
   звезды: аккреционные диски, приливное разрушение, пульсарные ветра,
   отсутствие планет у чёрных дыр, «выжженные» внутренние орбиты,
   спутники вокруг экзотических тел.
3. **Влияние на физику** — `luminosityBySpectral` (светимость для формулы
   температуры), `determineSystemAge`, `determinePlanetCount`, шансы
   газовых гигантов, архетипы планет.
4. **Влияние на спектральные классы** — хранить тип звезды отдельным полем
   или расширять `spectral_class` (нужна миграция `worlds`).
5. **UI и карта** — как рисовать и отличать такие системы на карте.

**Ограничения:** не в MVP. Каждый тип — редкий (≤1%), не должен ломать
баланс аудита и статистики (см. `internal/audit/`, `admin_stats_anomalies.go`).

## 8.5. Инструменты анализа галактики (черновик)

1. **Карта плотности.** Тепловая карта — где какие типы планет, где жизнь, где ресурсы.
2. **Аналитика по ресурсам.** Каких больше, где дефицит, карта распределения.
3. **Экономическая аналитика.** Цены, дефициты, торговые потоки.
4. **Демографическая.** Распределение населения по фракциям.
5. **Фракционная.** Сила, территории, войны, карта влияния.
6. **Проверка реалистичности.** Автотест на инварианты (уже есть аудит).
7. **Динамика во времени.** Как менялась галактика за тики.
8. **Экспорт.** JSON / CSV / отчёты.
9. **Сравнение галактик.** Какая «здоровая», какая перекошена.
10. **Отладка генератора.** Показать seed → планеты, replay.
