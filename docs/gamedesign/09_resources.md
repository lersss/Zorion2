## 9.1. Вещества

### 9.1.1. Что такое вещество

**Статус:** дизайн — решено · код — нет

Вещество — это **вектор физических свойств** плюс категория и имя. Из чего его
делают, решает рецепт товара (`05_economy.md` §5.2), а не само вещество:
«железная руда», «нефть», «аммиак» — это роль, назначаемая профилем свойств.

Подкатегории отсутствуют намеренно.

**Масштаб уникальности — галактика (или сезон), а не планета и не система.**
Одно имя означает одно вещество для всех игроков. Это условие существования
торговли, контрактов и общего языка сообщества: игрок должен иметь возможность
сказать «нужен зорнит» и быть понятым.

Общее количество веществ в галактике — тысячи. Точное число выводится из
распределения радиусов (§9.2.4) и из того, сколько веществ должно быть доступно
в одной системе (открытый вопрос, `05_economy.md` §5.5).

### 9.1.2. Свойства

**Статус:** дизайн — частично решено · код — нет

**Правило, по которому ось попадает в модель: ось существует, только если названо
решение игрока, которое она меняет.** Ось, не влияющая ни на одно решение, — это
украшение профиля, которое вдобавок размывает метрику качества
(`05_economy.md` §5.2.3).

**Физические константы (Кельвины):**

| Константа | Смысл |
|---|---|
| `T_melt` | температура плавления |
| `T_boil` | температура кипения |

**Агрегатное состояние вычисляется, не хранится:** `T_планеты < T_melt` → твёрдое;
`T_melt ≤ T_планеты < T_boil` → жидкое; `≥ T_boil` → газ. Точки плавления и кипения
принадлежат веществу и от планеты не зависят.

Состояние учитывается **только на планете**. Температура хранилища, фабрики и
трюма после добычи — открытый вопрос, он ведётся в `99_roadmap.md` §99.4.

Состояние — не флавор: оно определяет, каким оборудованием вещество добывают и
можно ли его добыть здесь вообще. Этим же словарём описывается **среда**
(`10_exploration.md` §10.2.5) и **снаряжение**: оборудование имеет те же
характеристики, что и материалы, и должно выдерживать условия планеты. Одна
физическая модель обслуживает вещество, место и инструмент.

**Независимые оси (0–100), обоснованные:**

| Ось | Решение, которое она меняет |
|---|---|
| Твёрдость | Броня, инструменты, стройматериалы; износ оборудования |
| Проводимость | Электроника, ретрансляторы связи (`10_exploration.md` §10.3.2) |
| Плотность | Масса груза; верхнее ограничение для брони и транспорта |
| Энергоёмкость | Топливо, реакторы |
| Биосовместимость | Продовольствие, медикаменты |
| Радиоактивность | Реакторы, оружие, вред населению. Градации: `<20` фон, `20–60` опасно, `>60` оружейное |

**Оси, требующие обоснования до реализации** (`обсуждается`):

| Ось | Чего не хватает |
|---|---|
| Эластичность | Только резина и амортизация. Одно применение на ось — мало |
| Химическая активность | Механики нет вовсе, только вклад в профиль |
| Токсичность | Идея верная (лекарство лечит и травит), но механики передозировки и отходов не описано |
| Горючесть | Отдельно от энергоёмкости оправдана, только если есть возгорание склада или разделение топлива по типам станций |

**Производные оси:** термостойкость выводится из `T_melt`, летучесть — из `T_boil`.
Так физически невозможные сочетания (твёрдое и летучее одновременно) не возникают:
корректность следует из модели, а не из списка запретов.

> **Известная проблема.** `T_melt < T_boil` всегда, поэтому термостойкость и
> летучесть жёстко антикоррелированы — это одна ось температуры, представленная
> как две, и в метрике качества температура получит двойной вес. Решение не принято
> (`05_economy.md` §5.5).

### 9.1.3. Категории

**Статус:** дизайн — решено · код — реализовано

Категория отвечает на вопрос **«где добывается и как выглядит в интерфейсе»**, а
не «что это за вещество». Свойства категорией не определяются: два минерала могут
отличаться сильнее, чем минерал от газа.

| Категория | Иконка | Типичное назначение |
|---|---|---|
| Минералы | 🪨 | Металлы, стекло, инструменты |
| Органика | 🌿 | Пища, ткани, лекарства |
| Редкие | ⭐ | Детали, электроника, оружие |
| Топливо | 🔥 | Энергия для заводов, транспорт |
| Вода | 💧 | Питьё, орошение, химия |
| Газы | 💨 | Удобрения, химия, топливо |

В интерфейсе — иконка рядом с названием, тултип с названием категории при
наведении.

### 9.1.4. Имена

**Статус:** дизайн — решено · код — реализовано частично (масштаб неверный)

Имена генерируются по слогам, в двух вариантах: кириллица и латиница
(Атрокс / Atrox).

Два обязательных свойства:

- **Уникальность в пределах галактики.** Одно имя — одно вещество. Иначе
  межрегиональный контракт бессмыслен.
- **Фонетика зависит от происхождения.** Регионы группируются в 12–15 крупных
  кластеров, у каждого свой набор слогов. По звучанию названия слышно, из какой
  части галактики вещество, — то есть дальний ли это груз. Двести отдельных
  звучаний игрок не различит, поэтому привязка идёт к кластерам, а не к регионам.

**Право имени первооткрывателю** — кандидат на расширение (`обсуждается`):
процедурное имя заменяется человеческим, у вещества появляется история. В
многопользовательской игре это сильный крючок и решает проблему неразличимости
сотен сгенерированных названий.

## 9.2. География веществ

### 9.2.1. Два независимых генератора

**Статус:** дизайн — решено · код — нет

Вещества создают **два разных генератора**, и смешивать их нельзя:

| Генератор | Что делает | Сколько веществ | Где присутствует |
|---|---|---|---|
| Универсальный слой (§9.2.2) | Фон, общий для всей галактики | 20–30 | Везде, где категория уместна |
| Генератор полей (§9.2.3) | Всё остальное: дом + радиус | тысячи | Только внутри своего радиуса |

Порядок при генерации галактики:

1. Сгенерировать **универсальный слой** — 20–30 веществ. Ни домашней точки, ни
   радиуса у них нет; поля к ним не применяются вообще.
2. Сгенерировать **остальные вещества полями** — каждому домашняя точка и радиус
   по распределению из §9.2.4.
3. Состав, доступный в системе = универсальный слой **плюс** те вещества полей,
   чьи области её накрывают. И то и другое затем фильтруется по форме поверхности
   и типу недр планеты (§9.2.6).

> **Почему универсальный слой нельзя выразить полем.** Чтобы вещество было
> действительно везде, радиус должен равняться размеру галактики. Тогда домашняя
> точка теряет смысл, а в степенном распределении радиусов появляется выброс,
> ломающий настройку остальных тиров. Это отдельная сущность, а не крайний случай
> поля.

### 9.2.2. Универсальный слой

**Статус:** дизайн — решено · код — нет

20–30 веществ, примерно по 4–5 на каждую из шести категорий. Генерируются один раз
на галактику (или сезон) **вне генератора полей**.

Зачем нужен:

- **Контракт должно быть на чём сформулировать.** Без общего знаменателя
  межрайонная сделка невыразима: у продавца и покупателя нет ни одного общего
  вещества, чтобы сравнить цены.
- **Новичок должен уметь начать где угодно.** Если базовое производство требует
  привозного сырья, первые часы игры превращаются в логистическую задачу до того,
  как игрок понял правила.
- **Общий словарь.** Двадцать-тридцать имён, которые знают все с первого дня, —
  это язык, на котором говорят об остальных тысячах.

Свойства слоя:

| Свойство | Правило |
|---|---|
| Присутствие | Гарантировано на любой планете, где категория уместна. Фильтр по форме поверхности и типу недр сохраняется: водное универсальное вещество не появляется в лавовых полях |
| Известность | **Заранее известны.** Разведки не требуют, в каталоге игрока с нуля. Именно это делает их полом, а не находкой |
| Имена | Нейтральной фонетики, не принадлежащей ни одному кластеру регионов (§9.1.4). Услышал региональное звучание — груз местный или дальний; нейтральное — это фон |
| Качество свойств | **Намеренно посредственное.** Достаточные, но никогда хорошие |
| Истощение | Обычное. Гарантировано присутствие, а не бесконечность: каждое месторождение вырабатывается (`10_exploration.md` §10.1) |

> **Жёсткое ограничение по свойствам.** Ни одно универсальное вещество не должно
> быть конкурентоспособным ни по одному профилю товара. Иначе этот профиль
> перестаёт нуждаться в торговле, и правило намеренной неполноты (§9.2.7)
> ломается именно там, где оно несущее.
>
> Что фон закрывает: продовольствие, стройматериалы, дешёвое топливо.
> Что он **не** закрывает на приемлемом качестве: электронику, оружие, броню,
> медикаменты, станки.

Локальное истощение фона — это нормально и полезно: оно заставляет возить даже
банальное сырьё и даёт базовую логистику, с которой начинает средний слой.

### 9.2.3. Поля вместо иерархии

**Статус:** дизайн — решено · код — нет

У каждого вещества есть **домашняя точка и радиус распространения**. Доступное в
системе — это те вещества, чьи области её накрывают.

Иерархия «сектор → регион → пояс» **не используется**: она даёт искусственные
границы, при которых химия меняется скачком между соседними системами, и требует
согласования трёх уровней вместо одного.

Что даёт модель полей:

- **Градиенты вместо заборов.** Соседние системы почти совпадают по составу,
  далёкие не совпадают вовсе. Новизна растёт плавно с расстоянием.
- **Бедные месторождения на краю ареала** возникают сами, без отдельной механики.
- **Одна ручка настройки.** Распределение радиусов задаёт и общее количество
  веществ, и темп новизны при перелёте, и остроту дефицита.

Арифметика: если в произвольной системе должно быть доступно порядка сорока
веществ, а средняя область накрывает несколько сотен систем, всего веществ
получается несколько тысяч.

### 9.2.4. Редкость

**Статус:** дизайн — решено · код — нет

**Редкость пространственная, а не вероятностная.** Редкое вещество — это малый
радиус, то есть несколько конкретных систем, а не низкий шанс выпадения при
сканировании.

Разница принципиальная: вероятностная редкость порождает гринд (игрок крутит
рулетку, пока не выпадет), пространственная порождает географию — точку можно
найти, скрыть, продать, за неё можно воевать. Вся ценность разведки как профессии
держится на этом.

Распределение радиусов — степенное:

| Тир | Охват | Роль |
|---|---|---|
| Распространённые | сотни систем | Основная масса, различают районы |
| Специализированные | десятки систем | Причина для торговли между районами |
| Редчайшие | единицы систем | Именные достопримечательности, предмет войн |

Тира «обычные, доступные везде» здесь **нет намеренно**: эту роль исполняет
универсальный слой (§9.2.2), который генерируется вне полей. Два механизма для
одной роли привели бы к тому, что непонятно, какой из них отвечает за фон.

Самый верхний тир имеет смысл делать именованными объектами, а не строчками в
таблице.

### 9.2.5. Два слоя географии

**Статус:** дизайн — решено

Политическая и ресурсная география **не совпадают и не обязаны совпадать**.

| Слой | Единица | Что несёт |
|---|---|---|
| Политический | Регион (200 на 100 000 звёзд, ~500 систем каждый) | Фракции, присутствие, охрана, рынки, карта |
| Ресурсный | Универсальный слой (§9.2.2) и поля веществ (§9.2.3) | Что где добывается |

Регион слишком крупен, чтобы быть носителем химии: он в десять-двадцать раз
больше рабочей зоны игрока, и при привязке веществ к его границам средний игрок
за всю игру увидел бы одну-единственную таблицу веществ.

**Географию никто не проживает перелётом.** Роевой игрок за всю жизнь посещает
10–20 планет и ни одной границы не пересечёт; магнат не летает вовсе. Отсюда
вывод, определяющий приоритеты разработки: **география должна читаться в рыночных
данных, а не в ощущении от перелёта.** Разброс цен между районами, дефицитные
позиции, карта того, где чего не бывает, — вот интерфейс географии, и он один на
оба типа игроков.

### 9.2.6. Связь с поверхностью и недрами

**Статус:** дизайн — решено · код — реализовано

Поля определяют, **какие вещества** доступны в районе. Форма поверхности и тип
недр определяют, **какие категории** встречаются на конкретной планете и в каком
количестве. Списки форм и типов — `04_composition.md`.

**Поверхность → категории:**

| Скалы | 🪨 ⭐ |
| Пески / пустыни | 🪨 |
| Кратеры | 🪨 ⭐ |
| Стеклянные поля | ⭐ 🪨 |
| Металлические поля | 🪨 ⭐ |
| Лавовые поля | 🪨 ⭐ 🔥 |
| Вулканические поля | 🪨 🔥 |
| Ледники | 💧 |
| Мёрзлые газы | 💨 💧 |
| Океаны | 💧 🌿 |
| Озёра / реки | 💧 🌿 |
| Луга / степи | 🌿 |
| Леса | 🌿 |
| Джунгли | 🌿 |
| Болота | 🌿 🔥 |
| Коралловые рифы | 🌿 💧 |

**Недра → категории:**

| Тип | Категории |
|---|---|

| Магматические породы | 🪨 |
| Метаморфические породы | 🪨 |
| Осадочные породы | 🪨 |

**Доли композиции должны влиять на вероятность, а не только служить порогом.**
Планета с 90 % рудных жил и 5 % подземных вод обязана давать руду существенно
чаще воды. То же для поверхности: учитываться должна не только доминирующая
форма.

### 9.2.7. Намеренная неполнота

**Статус:** дизайн — решено · код — нет

Это правило несущее, а не балансировочное. Без него региональные различия
становятся косметикой — переименованием без последствий.

- **В произвольной точке не должны закрываться все 20 профилей товаров.** Часть
  профилей обязана требовать привозного сырья, и у разных районов дыры разные.
- **Крупные части галактики должны быть лишены отдельных профилей целиком.** Это
  постоянная причина для дальней торговли, не исчезающая с развитием игрока.

Второе применение правила — верх игры. Оно единственное надёжно мешает
**вертикальной интеграции**: магнат не может завести у себя всю цепочку, потому
что лучшего проводника в его землях геологически нет. Без этой стены экономика
распадается на изолированные самодостаточные империи, между которыми нет
торговли.
