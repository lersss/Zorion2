## 13.13.1. Дельта схемы

`settlements` — существующая таблица (`migrations/000018_create_economy_tables.sql`).
Смысл трёх колонок меняется, ни одна не удаляется:

| Колонка | Было | Становится |
|---|---|---|
| `level` | Ярлык от населения, не читается нигде | **Тир** (§13.9). Читается при подборе завода и расчёте пола зарплаты |
| `population` | Рандом 100k…1B (**B21**) | Выводится, зажато потолками (§13.8) |
| `capacity` | `population × 2`, минимум 1000 (**B19**) | **Нижний потолок** — аграрная ёмкость из среды планеты |
| `stability` | Рандом 40–80, не читается | В этой правке не трогается (`18_needs.md` §18.2) |

Добавляется:

| Колонка | Тип | Смысл |
|---|---|---|
| `tier_progress` | `integer` | Счётчик в товарах (§13.9.2). Может быть отрицательным до срабатывания §13.9.3 |
| `wage_rate` | `integer` | Ставка. Дефолт — пол зарплаты тира |
| `stock` | `jsonb` | Остаток естественного запаса на момент последнего снятия. Вектор по позициям |
| `last_harvest_at` | `timestamptz` | Точка отсчёта для §13.12.2 |
| `computed_at` | `timestamptz` | Точка отсчёта ленивого пересчёта (§13.13.3) |

**Запас и `last_harvest_at` живут на поселении, а не на планете:** на одной
планете может быть несколько поселений (`13_settlements.md` §13.2.1), у каждого
своё незанятое население и свой осадок.

**`wage_rate` тоже на поселении.** По `13_settlements.md` §13.4.3 развилки в коде
нет: ставка — поле с разумным дефолтом. Если по итогам симуляции победит режим
«владельцы перебивают ставку друг другу», поле переедет на завод, и конкуренция
за смену станет аукционом. Пока — одно поле на поселение.

### Данные планеты

Пишутся генератором в JSONB `planets.data`, статические, считаются один раз:

| Поле | Смысл |
|---|---|
| `agrarian_capacity` | Нижний потолок населения (§13.8) |
| `natural_tier_cap` | Природный потолок тира (§13.9.4). Почти всегда 1 |
| `coverage` | Вектор местного покрытия (§13.10.2). **Рваный, не сглаженный** |
| `stock_rate` | Вектор скорости накопления запаса (§13.12.2) |
| `stock_cap` | Вектор потолка запаса. Разный по планетам |

Все пять выводятся из уже существующих данных планеты: температура, атмосфера,
вода, биосферные и прочие формы поверхности, композиция недр. Ничего нового
генерировать не требуется.

### Рецепты

Требуется поле `complexity int`: завод производит товар, только если тир
поселения ≥ сложности рецепта (§13.9.1).

Рецепты не реализованы вовсе (`05_economy.md` §5.4), поэтому это требование к
будущей структуре, а не миграция.

## 13.13.2. Формулы

```
занятые   = min(Σ рабочих мест активных заводов, население)
кошелёк   = занятые × wage_rate                       — лимит периода, не счёт
нагрузка  = занятые × норма(level) − coverage         — вектор, попозиционно
излишек   = wage_rate − стоимость(корзина(level))     — на душу
запас     = min(stock_cap, stock + stock_rate × (now − last_harvest_at))
```

Порядок трат кошелька жёсткий (§13.10.1):

```
1. еда              → не закрылась: голод, `18_needs.md` §18.3
2. корзина тира     → не закрылась: tier_progress вниз
3. излишек          → tier_progress вверх, но только товарами
                      привезёнными и прошедшими порог качества
```

Неистраченный кошелёк **не переносится и не чеканит денег** (§13.11.2).

### Денежные потоки

```
владелец  −= занятые × wage_rate       переток, расход владельца
поселение −= цена × объём              переток
продавец  += цена × объём × (1 + m)    m × цена × объём — эмиссия
```

Эмиссия возникает **только при фактическом потреблении товара**. Скупка
естественного запаса — наоборот, печь: деньги покупателя сгорают (§13.11.3).

### Величины, которые здесь не назначаются

Норма чеканки `m`, пол зарплаты по тирам, нормы корзины, гистерезис тира, темпы
населения, `stock_rate` и `stock_cap`, распределение `natural_tier_cap`. Все —
балансные, определяются симуляцией (`13_tiers.md` §13.15). В коде это
конфигурация, а не константы в теле функций.

## 13.13.3. Ленивый пересчёт

**Тика нет.** Пересчёт по образцу энергии (`11_production.md` §11.1.2).

```
recompute(settlement, now):
    Δt = now − computed_at
    1. запас        ← min(stock_cap, stock + stock_rate × Δt)
    2. занятые      ← min(рабочие места, население)
    3. кошелёк      ← занятые × wage_rate
    4. покупки по приоритету §13.10.1 из фактически поставленного
    5. tier_progress ± ; переход тира по §13.9.2 / §13.9.3 с гистерезисом
    6. население    ← дрейф к потолкам §13.8
    7. level        ← дрейф к natural_tier_cap, если ниже (§13.9.4)
    8. computed_at  ← now
```

Триггеры: открытие карточки поселения, постройка или снос завода, поставка,
изменение ставки, снятие запаса.

> **Поселение без заводов не считается никогда.** Занятых нет, кошелька нет; тир
> дрейфует только к природному потолку, и то при обращении. Стоимость
> пропорциональна числу поселений, до которых **кто-то дотронулся**, а не числу
> планет в галактике. Это и есть выполнение инварианта 2.

## 13.13.4. Конкурентность

`AGENTS.md` §0. Два опасных места, оба обязательны к исполнению.

**1. Снятие запаса.** Два торговца снимают одновременно — гонка в чистом виде.
Состояние обязано жить в транзакции БД, не в памяти:

```
BEGIN
  SELECT ... FROM settlements WHERE id = $1 FOR UPDATE
  recompute(...)
  списание запаса
COMMIT
```

Тот же класс, что остаток контракта в `14_money.md` §14.6, и такой же опасный.

**2. Пересчёт против чтения.** Карточку читают HTTP-обработчики, пишет пересчёт.
Голая `map` поселение → состояние **недопустима** — Go убивает процесс на
`concurrent map writes`. Если понадобится кэш, то неизменяемый снимок с атомарной
подменой указателя, как в `internal/mapcache`.

**3. Локальный `rand`.** Общий `*rand.Rand` не потокобезопасен. Генератор уже
держит один на структуру (`internal/generator/settlement/generator.go`) — при
переходе от батч-генерации к пересчёту по запросу это станет гонкой.

## 13.13.5. Тесты

Пишутся вместе с фичей (`AGENTS.md` §4.12): до кода — красные, после — зелёные.

| # | Что проверяет |
|---|---|
| 1 | Население не выходит за нижний потолок без рабочих мест и поставок |
| 2 | Верхний потолок растёт с числом рабочих мест и падает с прекращением поставок |
| 3 | На планете с нулевым подножным кормом население без снабжения уходит в ноль |
| 4 | Тир не поднимается без поставленных товаров, каким бы ни был кошелёк |
| 5 | Тир не поднимается от товаров ниже порога качества |
| 6 | Тир падает при незакрытой корзине и не опускается ниже 1 |
| 7 | Гистерезис: серия коротких перебоев не роняет тир |
| 8 | Тир сам дрейфует к `natural_tier_cap` и не выше него |
| 9 | Нагрузка уменьшается на `coverage` попозиционно, а не общим процентом |
| 10 | Неистраченный кошелёк не переносится и не чеканит денег |
| 11 | Чеканка происходит только при фактическом потреблении товара |
| 12 | Запас насыщается на потолке и не растёт дальше при любом `Δt` |
| 13 | Два одновременных снятия запаса не выдают больше, чем есть (гонка) |
| 14 | Поселение без заводов не меняет состояния между двумя чтениями, кроме запаса и дрейфа тира |
| 15 | Стоимость пересчёта не зависит от числа поселений в БД |

Тест 13 — единственный, которому по-настоящему нужен `-race`; он же самый
вероятный источник порчи данных. `-race` локально недоступен (`AGENTS.md` §2),
поэтому гонка проверяется логически: параллельные `go`-рутины против общей БД,
сверка итоговой суммы выданного с исходным запасом.

## 13.13.7. Порядок работ

Модель большая, вертикальный срез важнее полноты. Предлагаемый порядок:

1. **Потолки населения и ёмкость** (§13.8) — закрывает B19/B21, не требует ни
   корзины, ни денег, ни запаса. Первый срез, видимый в карточке.
2. **Естественный запас** (§13.12) — не зависит от тира и от кошелька, даёт
   локальному рынку товар и сразу играбельный цикл «прилетел — снял — увёз».
3. **Тир и корзина** (§13.9, §13.10) — требует номенклатуры товаров, то есть
   упирается в генератор веществ (`STATUS.md` §3 п.3).
4. **Деньги** (§13.11) — последним: до появления бирж и контрактов чеканить
   некому и не на что.

Пункты 1 и 2 выполнимы на текущем коде. Пункты 3 и 4 — после разблокировки
номенклатуры.
