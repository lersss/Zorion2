## 21.2. Модель визуала: статичный спрайт

Корабль — **цельный статичный спрайт**, не схема из деталей:

> **Статичный спрайт корабля** = цельный PNG 200×200 (нос вправо), единственный
> источник визуала корабля игрока и агента. **Перекраска** — тонирование спрайта
> доминирующим цветом с сохранением градиентов/текстуры (§21.4). **Оригинал** —
> спрайт без перекраски.

### Ассеты

- **21 PNG** из `ai_drafts/final_accepted/` копируются в `web/static/sprites/` и
  коммитятся: `anchor, book, boomerang, crater, crescent, crystal, drop, egg,
  heart, helmet, jellyfish, manta, mushroom, octopus, pyramid, shark, shell,
  spiral, star_celestial, trident, volcano` (все — `.png`, 200×200).
- Файлы `race_*.png` (6 шт. из той же папки) **не копируются** — это задел
  расового визуала, вне скоупа (создатель: «расы не проектировать сейчас»).
- **Ориентация:** нос вправо (как рендер `drawFlight`, поворачивающий по курсу от
  угла 0 = «вправо»). Если ассет ориентирован иначе — фиксированная константа
  поворота на спрайт в `ship_sprites.js` (не переэкспорт, не правка арта).

### Реестр спрайтов (один источник на сервере)

`internal/models/ship_sprites.go` (Go-константы, не конфиг — список статичен и
коммитится вместе с ассетами):

- `ShipSprites` — массив из 21 записи `{id, name, file}`: `id` = имя без `.png`
  (`anchor`, `book`, …), `name` — человеческое имя (Якорь, Книга, Бумеранг, Кратер,
  Полумесяц, Кристалл, Капля, Яйцо, Сердце, Шлем, Медуза, Манта, Гриб, Осьминог,
  Пирамида, Акула, Ракушка, Спираль, Звезда, Трезубец, Вулкан), `file` = `"<id>.png"`.
- `LegacyShipIconMap` — маппинг 21 старого SVG-имени → новое PNG-имя (§21.4,
  биекция).
- `DefaultShipIcon` — `"crescent.png"` (§21.4).
- `ShipColorPalette` — 9 хроматических цветов (§21.4).
- Порядок массива **фиксирован** — он же источник индексов для `spriteForAgent(id)`
  (добавление спрайта в конец не меняет индексы существующих; вставка в середину —
  меняет, запрещена без осознанного решения).

### Хранение выбора игрока

- `users.ship_icon` (существующая колонка, миграция `000011`) — имя файла: теперь
  PNG-имя (`"crescent.png"`). Старые значения (SVG-имена) в БД **не переписываются**
  (бэкфилл запрещён, решение создателя 2026-09-14): маппятся при чтении (§21.4).
  Новые записи и `PUT /me/ship-icon` пишут только имена из реестра.
- `users.ship_color` (**новая колонка**, миграция `000037_add_users_ship_color.sql`):
  `TEXT NULL` — hex выбранного цвета из палитры; `NULL` = «Оригинал» (без
  перекраски). Валидация при записи: `NULL` или hex ∈ палитры, иначе 400.
- Дефолт `ship_icon`: `bootstrap.go` и `admin_users.go` — `"crescent.png"`
  (константа `DefaultShipIcon`).

## 21.3. Потребители

### Игрок

- **Дашборд `/`** (блок «Корабль»): сетка 21 спрайта из `/me.ship_options`
  (`{id, name, file}`), миниатюра — `recolorShipSprite(file, текущий цвет)`
  (52 px); палитра 9 свотчей + «Оригинал» (NULL); сохранение —
  `PUT /me/ship-icon` (`{ship_icon: "shark.png"}`) + `PUT /me/ship-color`
  (`{ship_color: "#ef4444"}` или `null`); выбранные спрайт/цвет подсвечиваются.
- **Полёт** (`map_render.js`, `drawFlight`): источник спрайта —
  `state.userShipIcon` (PNG-имя из `/me`, уже смаппленное) + `state.userShipColor`
  → `recolorShipSprite(icon, color)`; поворот по курсу, пламя, размер
  `shipSize*3.2` — **без изменений**.

### Агент (NPC)

- **Мини-спрайт на карте** (`npc_agents.js`): ромб-фолбэк заменяется на мини-спрайт
  — `spriteForAgent(id)` возвращает **пару `{file, color}`** (детерминированно от id,
  §21.4) → `recolorShipSprite(file, color)` **из кэша** (перекраска не в хот-пате,
  а при первом запросе комбинации; прелоадер ниже).
- Поворот по курсу — существующий `npcAngle` (вектор движения между сэмплами),
  размер — существующий `npcScreenRadius` (`max(3.5, 4.5*scale)`), порог видимости
  `nameDisplayThreshold` — без изменений.
- Фолбэк: спрайт не загружен → текущий ромб (И4).
- Следствие (принятое): добавление спрайта в конец реестра не меняет визуал
  существующих агентов; вставка в середину — меняет (запрещена, §21.2).

### Рендер на карте

- **Прелоадер всех вариантов** (`preloadShipSprites()`, создатель 2026-09-16):
  прогревает кэш `recolorShipSprite` для всех 21×9 = 189 комбинаций + 21 оригинал
  (Image) при старте клиента (вызов из `main.js` init, после `/me` и получения
  `ship_options`). После прелоада отрисовка агентов/игрока — всегда из готового
  кэша, ноль ленивых перекрасок в рантайме. Стоимость: 189 офскрин-канвасов
  (200×200), однократно, фоном; загрузка 21 PNG параллельно.
- `spriteForAgent` — **единственная точка замены под расовый визуал**: будущий
  расовый визуал меняет тело этой функции (например, `raceOf(id)` → подмножество
  спрайтов), сигнатура и потребители не меняются.

## 21.4. Маппинг legacy → PNG и перекраска

### Дефолт

**Дефолт: `crescent.png` (Полумесяц).** Обоснование:

- **Читается на малом размере:** компактный симметричный силуэт без мелких деталей —
  на размере полёта (~9 px) и иконки агента (7–14 px) не превращается в кашу.
- **Нейтрален по характеру:** не хищный (не `shark`/`trident`), не «органический»
  (не `mushroom`/`octopus`), не агрессивный — подходит и игроку-новичку, и агенту.
- **Не сливается со звёздами карты:** в отличие от `star_celestial` (звезда-корабль
  будет путаться с фоновыми звёздами на близком зуме), серповидная форма уникальна.
- Преемственность: старый дефолт `ship_strela.svg` (Стрела) — нейтральный быстрый
  корабль; Полумесяц — та же роль в новом наборе.

одно место). `PUT /me/ship-icon` принимает **только** имена из реестра (21);
legacy-имена и прочие → 400.

### Перекраска (тонирование `gCO='hue'`)

Спрайты — AI-арт с градиентами и текстурой; «залить одним цветом» нельзя.
Создатель хочет выбор **доминирующего цвета** (оттенок поверх градиентов).
**Принят вариант «в» (создатель 2026-09-16, живой показ):**

- **Тонирование `globalCompositeOperation='hue'`:** offscreen canvas →
  `drawImage(спрайт)` → `gCO='hue'` → `fillRect(выбранный цвет)` → результат в кэш.
  Hue каждого цветного пикселя заменяется на hue выбранного цвета, S/L пикселя
  сохраняются — **градиенты и текстура полностью сохраняются**. Ахроматические
  пиксели (тёмный контур, белые блики, серые панели, S≈0) не меняются — контур и
  металл сохраняются, силуэт читается на тёмном фоне карты.
- **⚠️ Обязательно восстановление альфы.** Blend-режим 'hue' НЕ сохраняет
  прозрачность фона: после `fillRect` обязателен `globalCompositeOperation=
  'destination-in'` + `drawImage(оригинал)` — вернуть альфу спрайта (без шага —
  цветные квадраты вместо кораблей).
- **Принятое следствие:** цветные акценты (стекло кабины, навигационные огни,
  свечение двигателей) тоже принимают выбранный оттенок — теряют цветовую
  идентичность. На размере полёта (~9 px) и иконки агента это незаметно; на превью
  дашборда (52 px+) заметно. Многоцветный спрайт становится однооттеночным
  (текстура через S/L сохраняется). Альтернатива (пиксельный HSL-сдвиг с маской по
  hue-дистанции) отклонена как избыточная.
- **Палитра: 9 хроматических цветов** (hex, из которых берётся hue): красный
  `#ef4444`, оранжевый `#f97316`, жёлтый `#eab308`, зелёный `#22c55e`, бирюзовый
  `#14b8a6`, голубой `#0ea5e9`, синий `#3b82f6`, фиолетовый `#8b5cf6`, розовый
  `#ec4899`. Критерии: читаемость на тёмном фоне карты, различимость между собой.
  **+ «Оригинал»** (`NULL`) — спрайт без перекраски (обязателен: AI-арт — эталон
  красоты). Серые/металлические «цвета» в палитру **не входят**: у ахроматических
  цветов нет hue, тонирование 'hue' их не выражает.

### Реализация (клиент)

`web/static/js/map/ship_sprites.js` (новый, заменяет `ship_render.js`):

- `getShipImage(name)` — кэш `Map<name, Image>` (21 шт), загрузка
  `/static/sprites/{name}.png`; `onload` → `scheduleRedraw`.
- `recolorShipSprite(name, color)` — кэш `Map<"name|color", canvas>`: offscreen
  canvas → `drawImage` → `gCO='hue'` → `fillRect(color)` → `destination-in` →
  вернуть canvas. `color = null` → исходный `Image`. Лениво: комбинация создаётся
  один раз при первом запросе.
- `spriteForAgent(id)` — детерминированный выбор: `file = ShipSprites[FNV-1a(id)
  % 21]`, `color = ShipColorPalette[FNV-1a(id+1) % 9]` (FNV-1a — существующий
  `hashSeed` из `ship_render.js`, переносится). **Единственная точка замены под
  расы** (§21.3).
- `preloadShipSprites()` — прелоадер 189 комбинаций + 21 оригинал (§21.3).
- Фолбэк (И4): спрайт не загрузился / неизвестное имя → `null`, рисующий код
  использует примитив-корабль (текущий `bodyGrad` в `map_render.js`) / ромб
  (агент).

## 21.5. Инварианты

| # | Инвариант | Как держится |
|---|---|---|
| И1 | **Статичный спрайт — цельный PNG, не схема**; реестр `ShipSprites` — единственный источник имён (сервер) | клиент не дублирует список/маппинг; `ship_options` из `/me` |
| И2 | **Детерминизм агента** | `spriteForAgent(id)` — чистая функция (FNV-1a), порядок массива фиксирован; один и тот же визуал на любом клиенте, ноль хранилища |
| И3 | **Полнота маппинга** | все 21 legacy-имени смапплены (биекция), неизвестное → дефолт; тест на полноту |
| И4 | **Фолбэк без падений** | спрайт не загрузился/имя неизвестно → примитив-корабль (полёт) / ромб (агент); цвет вне палитры или `null` → «Оригинал» |
| И5 | **Косметичность** | спрайты и цвет **не влияют на механику** (скорость, груз, контракты, население); тех-характеристики — далёкое будущее, не проектируются (эталон создателя) |
| И6 | **Производительность** | агенты рисуются из **кэша 189 прелоаженных вариантов** (21 спрайт × 9 цветов, перекраска один раз на комбинацию при прелоаде, не в хот-пате); 30k `drawImage` в кадре при плотном вьюпорте — одной операцией; стоимость не от размера галактики (инвариант 2 проекта) |
| И7 | **Полёт не меняется** | поворот по курсу, пламя, размер, интерполяция — как сейчас; полёт неотменяем и детерминирован (`06_factions.md` §6.7.7) |
| И8 | **Расширяемость** | `spriteForAgent` — единственная точка замены под расовый визуал (тело функции, сигнатура фиксирована); реестр открыт (добавление — PNG в `web/static/sprites/` + строка в `ShipSprites`, индексы существующих не сдвигаются — только в конец) |
| И9 | **Разнообразие агентов** | `spriteForAgent(id)` даёт пару (спрайт из 21, цвет из 9) → **189 различимых комбинаций**; детерминизм — та же чистая функция, ноль хранилища |

## 21.6. Числа

- Спрайтов: **21** (PNG 200×200, нос вправо).
- Палитра: **9 хроматических** + «Оригинал» (NULL).
- Кэш перекраски: **≤ 21×9 = 189** вариантов, лениво, один раз на комбинацию;
  прелоадер прогревает все 189 + 21 оригинал при старте клиента.
- Рендер полёта: **`shipSize*3.2` ≈ 9 px** (`shipSize = 2.8`); иконка агента:
  `max(3.5, 4.5×scale)`, порог видимости `nameDisplayThreshold = 0.5` (как сейчас).
- Агент: `FNV-1a(id) % 21`; при 100k агентов ~**4 762 агента на спрайт** в среднем.
  На галактическом обзоре агенты скрыты (порог 0.5); в типичном вьюпорте — десятки,
  дубли редки. Цвет агента: `FNV-1a(id+1) % 9` → 189 различимых комбинаций.
- Маппинг: **21 биекция** (§21.4) + правило «неизвестное → дефолт».

## 21.7. Эталоны (FAQ)

Формат: вопросы → дословные эталоны создателя. Вопросы генератора деталей
(99.2.15) **закрыты решением 2026-09-16** (идея 61b): параметрический генератор
отменён целиком, заменён статичными спрайтами. Открытых вопросов нет.

**Вопрос:** каков полный список категорий деталей корабля? (В1)
**Ответ (эталон создателя, 2026-09-15):** двигатели, крылья, носы + «ещё что-то
(категории предложи ТЫ)». **Закрыт 2026-09-16 (61b):** генератор деталей отменён —
корабль — цельный статичный спрайт (21 PNG, §21.2), категорий и сборки нет.

**Вопрос:** какова палитра цветов кораблей (сколько и каких)? (В2)
**Ответ (эталон создателя, 2026-09-16, 61b):** **9 хроматических цветов** —
красный `#ef4444`, оранжевый `#f97316`, жёлтый `#eab308`, зелёный `#22c55e`,
бирюзовый `#14b8a6`, голубой `#0ea5e9`, синий `#3b82f6`, фиолетовый `#8b5cf6`,
розовый `#ec4899` (критерии: читаемость на тёмном фоне карты, различимость между
собой) **+ «Оригинал»** (`NULL`, без перекраски). Серые/металлические в палитру не
входят (у ахроматических нет hue — тонирование 'hue' их не выражает). Инвариант
«весь корабль — один цвет» сохранён: перекраска тонирует весь спрайт одним
оттенком.

**Вопрос:** допустимы ли акцентные элементы другого цвета внутри корабля (кабина,
стёкла, огни, свечение) — или корабль строго один цвет?
**Ответ (эталон создателя, 2026-09-15):** «совсем одноцветные корабли — некрасиво;
кабина, например, может иметь внутренние детали другого цвета, для красоты. Иначе
будет монотонно». **Уточнение 2026-09-16 (61b):** в статичных спрайтах акценты —
часть AI-арта (кабина, стёкла, огни, свечение нарисованы в PNG); при перекраске
'hue' они принимают оттенок выбранного цвета (принятое следствие, §21.4) —
«Оригинал» возвращает исходный арт с акцентами.

**Вопрос:** допустима ли любая комбинация деталей в сборке корабля, или есть
ограничение на целостность/пропорции силуэта? («не франкенштейны»)
**Ответ (эталон создателя, 2026-09-15):** «корабли не должны быть
"франкенштейнами", но должны быть красивыми». **Закрыт 2026-09-16 (61b):**
генератора и сборки нет — статичные спрайты цельные по построению, каждый ассет —
самостоятельный цельный корабль; целостность гарантирована самим артом.

**Вопрос:** где хранятся сгенерированные детали (БД / конфиг / файлы)? (В3)
**Ответ (эталон создателя, 2026-09-16, 61b):** генератора нет — реестр спрайтов —
**Go-константы `internal/models/ship_sprites.go`** (список статичен и коммитится
вместе с ассетами, не конфиг). Таблица `ship_parts` (миграция 000027) удалена из
кода и остаётся мёртвой схемой в БД (не трогается, down-миграции не пишем).

**Вопрос:** как агент получает корабль — детерминированная функция от seed или
сохранение схемы при создании агента? (В4)
**Ответ (эталон создателя, 2026-09-16, 61b):** агент = **пара {спрайт, цвет} от id**:
`spriteForAgent(id)` возвращает `file = ShipSprites[FNV-1a(id) % 21]`,
`color = ShipColorPalette[FNV-1a(id+1) % 9]` — детерминированно (чистая функция,
ноль хранилища, дешево при 100k), **189 различимых комбинаций**. Отрисовка — из
кэша (перекраска при прелоаде, не в хот-пате).

**Вопрос:** что происходит с существующим блоком (`ships.json`, 21 SVG,
`users.ship_icon`) — замена или коэкзистенция? (В5)
**Ответ (эталон создателя, 2026-09-16, 61b):** **замена с маппингом**: 21 SVG +
`ships.json` **удалены из репо** (отменяет прежнее «оставить до 1.0»);
`users.ship_icon` остаётся колонкой (теперь PNG-имена), старые SVG-значения в БД
не переписываются — маппятся при чтении (биекция 21→21, неизвестное → дефолт
`crescent.png`, §21.4); `users.ship_visual` остаётся мёртвой колонкой (миграция
000028, не трогается).

**Вопрос:** каков список спрайтов и дефолт? (эталон 61b)
**Ответ (эталон создателя, 2026-09-16, 61b):** **21 PNG** — `anchor, book,
boomerang, crater, crescent, crystal, drop, egg, heart, helmet, jellyfish, manta,
mushroom, octopus, pyramid, shark, shell, spiral, star_celestial, trident, volcano`
(200×200, нос вправо); **дефолт — `crescent.png` (Полумесяц)** — читается на малом
размере, нейтрален, не сливается со звёздами карты (§21.4).

**Вопрос:** как перекрашивается спрайт в выбранный цвет? (эталон 61b)
**Ответ (эталон создателя, 2026-09-16, 61b):** **тонирование `gCO='hue'` +
обязательное восстановление альфы `destination-in`** (принято на живом демо
2026-09-16; без `destination-in` — цветные квадраты вместо кораблей). Hue каждого
цветного пикселя заменяется на hue выбранного цвета, S/L сохраняются — градиенты
и текстура полностью сохраняются; ахроматика (контур, металл) не меняется (§21.4).
