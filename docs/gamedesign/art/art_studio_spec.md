## 1. Цель

Инструмент для генерации и отбора **аватаров рас** (нечеловеческих + людей) для игры Zorion. Заменяет ручной пайплайн художника: художник (создатель) генерирует пачки аватаров, отбирает, назначает эталоны расам — без ручного запуска Python-скриптов.

Продукт = **локальный веб-инструмент** (десктопная утилита художника/дизайнера), НЕ игровая фича. Работает поверх ComfyUI (AI-генерация) и локальных скриптов пост-обработки.

## 2. Что уже работает в прототипе (перенести в продукт)

Прототип доказал пайплайн. Продукт повторяет его UX и логику:

### 2.1. Пайплайн аватара (цепочка)
1. **Генерация** — ComfyUI (Juggernaut XL, API `http://127.0.0.1:8188`), txt2img 1024×1024, steps 28 (быстрее 40, качество то же).
2. **Вырезка фона** — rembg (`isnet-general-use`): прозрачный PNG.
3. **Посаженность** — объект прижат к нижнему краю кадра (для голов/бюстов), для «нечто» (вихрь) — парение допустимо.
4. **200×200** — финальный размер аватара (ImageOps.pad, центр/низ).

### 2.2. Две студии (в продукте — вкладки одного инструмента)
- **Студия людей (F0 Люди):** генерация портретов с рандомом по осям (пол/раса/возраст/причёска/одежда/броня/шлем), галка «без голых» (негатив), отбор, обрезка снизу ползунком.
- **Студия рас (F2–F9):** генерация неантропоморфных аватаров + эталоны.

### 2.3. Поток «эталон → вариации» (ключевой)
1. **Кандидаты эталона** — широкий поиск: генерация N картинок (по умолчанию 12) по всему семейству, **каждая с РАЗНЫМ форм-фактором** (словарь форм). Галка «антропоморфный» — гуманоиды из материала расы.
2. **Карточка кандидата** — select «в какую расу пойдёт эталон» (раса выбирается при назначении, не при генерации) + кнопка «Эталон».
3. **Эталон сохранён** — `ref_<FAM>_r<race_id>.png`, подсветка в списке рас: где эталон есть (✓), где нет.
4. **Вариации** — img2img от эталона (denoise 0.55), N штук, «узко вокруг формы эталона» (доводка). Результат — в пул отбора.
5. **Сброс эталона** — кнопка, удаляет ref-файл расы.

### 2.4. Отбор
- Сетка картинок (300px, по 4 в строку), кнопки **Принять / Удалить** на каждой.
- Принятые → `final_accepted/` (автонумерация), удалённые → `rejected/`.
- Обрезка: клик по картинке → модалка с ползунком «обрезать снизу» + **живое превью** результата (на подложке).
- Подложка для просмотра: фон-среда (кабина корабля) — чтобы видеть, чисто ли вырезан фон.

### 2.5. Сервисные функции (обязательны)
- **Прогресс генерации** в реальном времени (N/M + текущий кандидат).
- **СТОП** — мягкая остановка: текущая пара картинок догенеривается (~15с), следующие не стартуют. Без kill.
- **Индикатор состояния генератора** всегда виден: «⏳ Генерируется N/M» / «✓ Простаивает» / «⏹ Остановлено».
- **Авто-обновление** каждые 3с (новые картинки появляются сами).
- **Сохранение состояния** при обновлении страницы: активная вкладка, выбранное семейство/раса (localStorage).
- **Выбор не сбрасывается** таймером (select-ы сохраняют значение при перерисовке).

## 3. Данные и конфиги

### 3.1. Словарь форм (`race_forms.py` → в продукте JSON/конфиг)
- Комбинаторный словарь **300k+ форм**: 28 базовых форм × 25 модификаторов структуры × 20 характеров × 25 деталей.
- Категории форм: crystal, cold, hot, gas, liquid, sulfur, organic, mech, energy, sphere.
- **Антропоморфные формы** (18 шт): «humanoid face with angular features» и т.п. — для галки.
- Подбор форм под семейство: `CATEGORY_KEYS[F2] = [cold, crystal, gas, organic, sphere]` и т.д.

### 3.2. Конфиг семейств (`race_gen.py FAMILIES` → JSON)
Сейчас заполнен **только F2** (6 рас: 5 Аммиачники, 6 Крио-лесные, 7 Ледяные пастухи, 8 Туманники, 9 Крио-рои, 48 Крио-небесные). Для каждой расы: формы/материалы/свечения по основе из спеки 99.2.21. **Нужно заполнить F3–F9** (из спеки).

### 3.3. Негатив (общий для неантропо)
Запрещает: человеческое (face, eyes, head, human anatomy, portrait), постройки (building, structure, machine, chimney, castle), органику-плоть (flesh, meat), паттерны (seamless, pattern), голых.

### 3.4. Память
- `races_pool/` — пул для отбора (r01.png...).
- `races_pool/ref_cands/` — кандидаты эталона (c01.png..., + meta.json: раса кандидата). Очищаются при новом запуске кандидатов.
- `races_pool/ref_<FAM>_r<id>.png` + `.json` — эталоны рас.
- `final_accepted/` — принятые (race_NN.png / race_f1_humans_NN.png).
- `rejected/` — удалённые.

## 4. Ограничения/грабли (проверено на прототипе)

1. **Juggernaut игнорирует хромакей** (magenta/зелёный → полутон) — фон режем rembg, не цветом.
2. **«No clothes» игнорируется** для людей — люди генерируются в одежде/форме (это ок, «голых нет» через негатив).
3. **Портреты рисуются на весь кадр** — голова/плечи у краёв. Решение: обрезка снизу ползунком + прижатие к низу.
4. **«Lifeform/creature» тянет к антропоморфной голове** — для неантропо писать «abstract mineral structure» + жёсткий негатив.
5. **Steps 28** — быстрее, качество не падает.
6. **Параллельность ×2** (ThreadPoolExecutor) — на RTX 4060 Ti оптимум; больше воркеров упрутся в VRAM.
7. **Два python-процесса на один порт** — баг прототипа (venv + системный Python310): один слушает, другой висит. В продукте — один процесс, фиксированный порт, защита от дублей.

## 5. Требования к продукту (для разработки)

### 5.1. Стек
- Локальный веб-сервер (Python/FastAPI или Node — на выбор команды).
- Один процесс, фиксированные порты (например 8798 — расы, 8799 — люди, или один инструмент с вкладками).
- Фоновые задачи генерации (не блокируют HTTP).
- Слой интеграции с ComfyUI API (существующие workflows: txt2img, img2img).
- Слой пост-обработки: rembg (isnet), resize 200×200, прижатие к низу, обрезка.

### 5.2. UI
- Вкладки: «Отбор», «Эталон» (+ «Люди» если отдельно).
- Сетка карточек 300px, кнопки Принять/Удалить, select расы в карточке кандидата.
- Модалка обрезки с живым превью.
- Прогресс + СТОП + индикатор состояния.
- Подсветка наличия эталонов (✓/·).
- Сохранение состояния (localStorage) + no-cache заголовки.

### 5.3. Конфигурация
- Все словари/конфиги (формы, семейства, негативы, оси рандома) — в JSON, редактируемые без кода.
- Конфиг F2 как эталон формата; F3–F9 заполнить из спеки 99.2.21.

### 5.4. Критерии приёмки
1. Художник генерирует пачку рас (F2) и отбирает аватары без ручного запуска скриптов.
2. Поток «кандидаты → эталон → вариации» работает: кандидаты с разными формами, эталон привязан к расе, вариации вокруг него.
3. Прогресс/СТОП/индикатор работают; авто-обновление не сбрасывает выбор и вкладку.
4. Вырезка фона чистая (проверка: аватар на подложке-кабине без артефактов).
5. Принятые аватары — 200×200 прозрачные PNG в final_accepted, готовы к использованию в игре.
