> красивыми, современными, реактивными.»

## Уточнение (вопросы @manager → ответы создателя, 2026-09-19)

1. **Границы с @gdesigner (главная развилка).** Ответ создателя: **«интерфейсы
   даже первичнее стиля. Если в новых идеях много UI, надо брать его в команду
   после геймдева, но до разработки»**. Деление по плоскости работы:
   - **@gdesigner** — стиль мира: палитры, формы, спрайты, генераторы визуала,
     стилистика как таковая (как выглядит корабль, планета, общий вид).
   - **@uidesigner** (новый) — интерфейсные решения: компоновка экранов,
     компоненты, состояния (загрузка/пусто/ошибка), UX-потоки, реактивность
     (что происходит при действии — тосты, переходы, анимации), спеки для
     разработчика. Приоритет интерфейса выше стиля.
   - **Место в цепочке:** при фиче с большим UI — геймдизайн (@designer) →
     UI-дизайн (@uidesigner) → разработка (@developer).
2. **Зона ответственности:** подтверждено полностью — аудит существующих
   интерфейсов (карта, модалки, дашборд игрока, вкладки), проектирование новых
   экранов/компонентов, ТЗ для @developer в исполнимом формате, описание
   реактивности (поведение при действиях, состояния, анимации, тосты).
3. **Охват интерфейсов:** «Все, включая студии» — игровые интерфейсы (карта,
   модалки, дашборд), админка, арт-студия (`cmd/art-studio`, веб-UI порт 8798).
4. **Параметры роли:** ок — как у остальных дизайнеров: модель
   `opencode/deepseek-v4-flash`, температура 0.7, гейты (стоп после каждого
   результата, лимит итераций 5), git запрещён, задачу не закрывает. Имя агента —
   `@uidesigner`. Спеки — в `docs/specs/` (единый каталог, отдельную папку не
   плодим).
5. **Вектор:** «По интерфейсам и взаимодействию пользователя с игрой, админкой,
   системой. Он должен ответить как именно пользователю будет удобно пользоваться
   нашим продуктом, и зафиксировать это в спецификации» — UI-пожелания (любая
   зона) → @uidesigner; код → @developer. Отметить в VECTORS.md (документ
   менеджера, правлю сам).

## Зона роли (итог)

- **Аудит** существующих интерфейсов: что неудобно/некрасиво/не реактивно.
- **Проектирование** новых экранов и компонентов: компоновка, состояния
  (загрузка/пусто/ошибка), UX-потоки.
- **Реактивность:** поведение при действиях пользователя — тосты, переходы,
  анимации, обновление данных.
- **Спеки для @developer** в исполнимом формате: что меняем, где (файлы/поля),
  критерий проверки, что не трогать.
- **Охват:** игровые интерфейсы, админка, арт-студия — все интерфейсы продукта.
- **Критерий качества:** удобно, красиво, современно, реактивно.

## Границы (что НЕ входит)

- Не стиль мира (палитры/формы/спрайты — @gdesigner).
- Не механики и баланс (@designer/@balancetester).
- Не код (Go/JS/CSS — @developer).
- Не ассеты (спрайты — @artist).
