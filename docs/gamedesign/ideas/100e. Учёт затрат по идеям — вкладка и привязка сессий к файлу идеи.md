## Пожелание (слова создателя, 2026-09-25)

> «А теперь интересный вопрос. Могу ли я отдельный отчет сделать, сколько мне
> стоила та или иная идея?»

> «на отдельной вкладке какой-то»

> «причем желательно именно привязку к идее, а не к окну сессии, потому что одну
> идею чаще всего разрабатываем в несколько сессий»

> склеивай не думай»

## Разведка (менеджер, 2026-09-25)

- **Ключа «идея» в сессии нет.** Есть только свободное название, которое opencode
  придумывает из первого сообщения; продолжения линии называются по-разному
  («Прогулка», «Продолжаем прогулку: вулканизм, 7 биомов», «Прогулка по мирам —
  чк4»). Корневых сессий проекта 589, из них 429 — вкладки менеджера; полностью
  совпадающих названий только 17. По названию не группируется (создатель
  подтвердил: «они часто по названию не группируются»).
- **Привязка вычислима по файлу идеи.** Сессия менеджера почти всегда создаёт или
  правит файл `docs/gamedesign/ideas/*.md`. По истории: 266 из 429 вкладок
  менеджера писали/правили файл идеи, из них у 187 — ровно один файл, у 79 —
  несколько, ~163 — ни одного (разговоры/разведка).
- **Самоидентификация сессии работает:** сессия менеджера надёжно находится по
  первому сообщению создателя (проверено — нашлась ровно одна наша сессия). Но
  для привязки к идее это не нужно: файл идеи в данных уже есть.
- **Файлы идей:** 157 всего; 116 названы датой (`2026-09-25_…`) — у них номерной
  семьи нет; 37 «номерных»: 96 — 10 файлов, 100 — 4, 77/26/14 — по 2, остальные
  одиночки.
- **Порядок величин:** 584 текущие «фичи» (деревья сессий) на $499.67 за всё
  время; верх списка — ранние прямые сессии `build` (напр. «Экономика поселений:
  генерация ресурсов» — $40.18).

## Решения создателя (2026-09-25)

1. Отдельная **вкладка** в сервисе учёта (не строка в существующей таблице).
2. Привязка — **к идее** (файлу идеи), не к окну сессии.
3. Файлы, отличающиеся только «ведущий номер + буква» (`14c`, `14d`; `96a…96j`;
   `100a…100d`), **склеивать автоматически** в одну линию (без ручного
   подтверждения).
4. **Дата-названные файлы не склеивать** (иначе 116 файлов схлопнутся в «2026»).
   Склейка — только для имён вида «число + буква + точка».
5. **Каждая сессия считается один раз** — в линии, на которую работала больше
   (созданный файл в приоритете). Прочие затронутые файлы — пометкой, без деления
   цены (чтобы сумма по линиям сходилась с реальными тратами).

## ТЗ (что сделать)

1. **Серверная привязка** (новый модуль, не раздувать `stats.mjs`):
   - читать хранилище сессий opencode **только на чтение**;
   - по каждой сессии (в дереве сессий) собрать файлы идей
     (`docs/gamedesign/ideas/*.md`), которые сессия **писала или правила**
     (`tool=write` / `tool=edit`, поле `filePath` во входе вызова — не путать с
     упоминанием файла в тексте/контенте);
   - семья файла: ведущий `число + необязательная одна буква + точка` → ключ =
     число (`96a…96j` → `96`; `99a.3-…` → `99`). Дата-названные файлы — ключ =
     полное имя файла (сами по себе);
   - дерево сессий относится к семье, у которой больше всего затронутых файлов;
     при равенстве приоритет у семьи, чей файл был **создан** (`write`);
   - цена линии = сумма цены дерева (сессия менеджера + подсессии) **с нарезкой
     по периоду**, как везде в сервисе;
   - дорогое сканирование кэшировать (отдельный кэш-файл, ключ — `time_updated`
     сессии), чтобы `/api/stats` не тормозил.
2. **Эндпоинт** `/api/ideas?period=today|7|all` — отдельно от `/api/stats`,
   чтобы тяжёлая привязка не считалась на каждом 20-секундном обновлении
   главной страницы. Возвращает: линии (название, цена, сессий, роли, токены),
   разрез по сессиям внутри линии и список **неприкаянных** сессий.
3. **Вкладка «Идеи»** на странице: переключатель «Обзор | Идеи»; список линий по
   убыванию цены; клик по линии — из каких сессий сложилась цена и сколько съела
   каждая роль; отдельный блок «Непривязанные сессии»; переключатель периода.
   Клиентскую логику вкладки держать в **отдельном файле**, чтобы `index.html`
   (уже 604 строки) не разросся (серверу добавить отдачу этого файла).
4. **Тесты** — на синтетическом хранилище: склейка семей (96a+96c → 96), приоритет
   созданного файла, дата-названные не склеиваются, неприкаянные сессии,
   нарезка цены по периоду.
5. **README** — описать вкладку и правила привязки.

**Зачем:** создателю нужна цена идеи целиком, а не цена окна сессии; одна идея
обычно живёт в нескольких вкладках менеджера, поэтому привязка — к файлу идеи, а
номерная склейка даёт уровень «линия».

**Маршрут:** фича средней величины в собственном инструменте → `@developer` (DoD →
`@tester` → гейт создателю). Дизайн-прогон не требуется: семантика привязки задана
решениями создателя выше.
