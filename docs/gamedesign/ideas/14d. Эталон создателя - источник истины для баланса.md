# 14d. Эталон создательа — источник истины для баланса

**Создано:** 2026-09-14

## Сырое пожелание (создатель, 2026-09-14)

> «Некоторые задачи по балансу невозможно решить, не зная моего эталона
> качества: нет в жизни примеров, на которые можно опереться. Геймдизайнер не
> должен имплементировать несуществующие правила, может только предложить, как
> можно сделать. Если я сообщу формулу или общее видение, его надо будет
> отразить в документах и ориентироваться на него, а не на отсутствующий факт.»

Уточнение формулировки «эталон не задан»:

> «У меня нет чёткого референса по данному вопросу, не могу найти ничего
> похожего в интернете, и моя база знаний не может однозначно ответить на
> вопрос "как правильно". Нужно твоё решение.»

## Правило

1. **Эталон задан** (жизненный/физический аналог, формула/видение создательа) →
   источник фиксируется в идее/спеке/GDD («решение создательа», дословно), дизайн
   и проверка идут строго от него.
2. **Эталона нет** — агент обязан честно сказать: «чёткого референса нет
   (жизнь/интернет/база знаний не дают однозначного ответа) — нужно решение
   создательа». Не имплементировать несуществующее правило как факт: только 2–3
   варианта с ценой каждого + гейт-вопрос создательу.
3. **Матрица исходов баланс-тестера** (два измерения: противоречит ли дизайн
   здравому смыслу/физике; задан ли эталон):
   - **В1. Противоречие + эталон не задан** → отдать @designer на анализ
     противоречия (не менеджеру, не просто «решение создательа»).
   - **В2. Нет противоречия + эталон не задан** → пропустить в разработку,
     фиксируя «эталон не задан» в тематическом GDD-доке по теме фичи (не блок).
   - **В3. Противоречие + эталон задан** → двигаем по эталону, но уведомляем
     КАПСОМ «ЭТАЛОН ПРОТИВОРЕЧИТ ЗДРАВОМУ СМЫСЛУ» — warning, не блок.
   - **В4. Нет противоречия + эталон задан** → действуем по эталону.
   Баланс-тестер не выдумывает критерий и не ставит «ПРОБЛЕМЫ» за отсутствие
   факта: при отсутствии эталона проверяет согласованность и инварианты.
4. **Эталоны живут в тематических GDD-доках** по теме (не в отдельном реестре) в
   едином формате **FAQ** — раздел «Эталоны (FAQ)» в профильном доке (напр.
   температура/смертность → `18a_population_death.md`):
   - `**Вопрос:**` — формулировка «как/где/когда/что будет…»;
   - `**Ответ (эталон создательа, ДАТА):**` — решение создательа дословно; ответа
     нет → `**Ответ:** эталон не задан (ДАТА) — открытый вопрос`.
   Счётчик открытых вопросов — `docs/gamedesign/faq_counter.md` (ровно одна
   цифра): вопрос без ответа добавлен в FAQ → +1; ответ внесён → −1. Считаются
   **все открытые вопросы эталонов, включая FAQ-разделы в идеях** (`ideas/`) до
   переноса в тематический GDD-док. В начале сессии агент читает счётчик и
   сообщает цифру; число > 10 → предложить сессию закрытия FAQ
   (см. `.opencode/agents/manager.md`).
   Уточнение границы (2026-09-20): счётчик считает только открытые вопросы
   эталонов физики/мира (калибровка, баланс); вопросы «делаем/не делаем» и
   кандидаты ГД-сущностей в счётчик НЕ вносятся — их дом роадмап §99.3 и идеи
   (решение создателя 2026-09-20).
5. **Изменение эталона — только с согласия самого создательа.** Никто не «улучшает»
   и не корректирует его; противоречивость/нереализуемость эталона выносится
   создательу на решение (дизайнер показывает конфликт и варианты, но не правит сам;
   баланс-тестер сообщает; менеджер передаёт).
