## Сырое пожелание (создатель, 2026-09-14)

> «Давай добавим в карточку поселения события. К примеру, если поселение
> вымерло, информацию о дате этого события будет хранить карточка»

## Уточнения и решения создателя (2026-09-14)

1. Пока **только вымирание** (других типов нет).
2. Запись появляется **автоматически** (не ручные).
3. Показывать: **дата + причина**.
4. Объём показа: **последние 3 записи** — достаточно.
5. **Это не события, а лог** (решение создателя): «вымерло» — результат, в
   который перешло состояние поселения, а не происшествие. Сущность —
   **лог поселения**: отдельная таблица записей (одно поселение — много
   записей), НЕ поля у поселения.
6. **Расширяемость** (решение создателя): записей/типов будет много и
   разнообразных; возможно, такие же журналы появятся у других объектов
   (звёзды, игроки, рынки) — но сейчас проектируем только лог поселения,
   общая система «событий вселенной» НЕ строится.
7. **Бэкфилл отменён** (решение создателя 2026-09-14): «Если не было события,
   то и записи о нем никакой нет. Вообще не надо старых обслуживать».
   Поселения, умершие до введения фичи, записей не получают вовсе (ни «дата
   неизвестна», ни причина «по текущим условиям»); запись пишется только при
   реальном фиксировании смерти с вычислимой датой.

## ТЗ (дизайн-срез готов, 2026-09-14 — см. `18a_population_death.md` §«Лог поселения»)

- В карточке поселения — блок «Лог»: последние 3 записи, формат строки —
  «Вымерло · <дата> · <причина>» — всегда с датой; при 0 записей — скрыт;
  сортировка по дате убыв.
- **Таблица `settlement_log`** (миграция `000024_create_settlement_log.sql`):
  `id` (uuid PK), `settlement_id` (uuid FK → settlements, ON DELETE CASCADE),
  `type` (text; первый `extinct`, список открыт), `occurred_at` (timestamptz
  **NOT NULL** — запись без даты не существует, бэкфилл отменён), `cause`
  (text; код причины), `created_at` (timestamptz). Отдельного `data JSONB` нет —
  добавится миграцией, когда появится второй тип с деталями. Готовая таблица
  `events` не используется (общая система событий отложена создателем).
- **Анти-дубль:** частичный уникальный индекс
  `uq_settlement_log_extinct (settlement_id) WHERE type = 'extinct'` + запись в
  той же транзакции синка (`FOR UPDATE`, Δt ≥ 30 мин) через
  `INSERT ... ON CONFLICT DO NOTHING`. Одна запись на вымирание, спама при
  просмотрах нет.
- Первая запись — «Вымерло», создаётся автоматически, когда пересчёт видит
  обвал (порог `N_dead` → разовый обвал) **и дата вычислима**
  (`population_exact > NDead` на чек-точке). Если чек-точка уже мёртвая
  (`population_exact ≤ NDead`) — запись не создаётся (штатно, без бэкфилла).
- **Дата** — момент пересечения порога по R-модели (`99.2.13`,
  `t_death = computed_at + ln(population_exact / NDead) / |ln(1 − r)|` сек,
  `r = ChangeComponents`; гвард `r ≥ 1` → `t_death = computed_at`), числа —
  вывод из уже принятой модели, новых констант нет.
- **Причина** — доминирующая рекурсивная компонента среды (жара / холод /
  гравитация / радиация, `DeathCause`) по вкладу; при равенстве — температура →
  гравитация → радиоактивность (решение создателя 2026-09-14).
- **Бэкфилл — отменён** (решение создателя 2026-09-14): умершие до введения
  фичи записей не получают вовсе; «дата неизвестна» не существует нигде.
- Ленивая модель сохраняется: пересчёт в памяти БД не трогает, запись идёт
  только транзакцией синка; клиентская экстраполяция запись не рисует.

## Критерии готовности (черновик, уточнить)

- Открыл карточку мёртвого поселения — видишь «Вымерло · <дата> · <причина>»,
  одна запись, без дублей при повторных открытиях.
- Живое поселение — блок пуст/скрыт.
- Поселения, умершие **до** введения фичи, записей не имеют вовсе (блок
  скрыт, «дата неизвестна» нигде не фигурирует).
- Новый тип записи добавляется без изменения таблицы поселений (структура
  лога это позволяет).
- UI: блок выглядит органично в стиле карточки — проверка создателем на
  живой карточке на гейте разработки.
- DoD по `AGENTS.md` §2; тест на определение момента/причины смерти,
  анти-дубль, «мёртвая чек-точка → запись не создаётся».
