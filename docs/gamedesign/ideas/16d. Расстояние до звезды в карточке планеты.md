## Факты из кода (менеджер, проверено 2026-09-16)

- **Готовое поле уже есть в данных планеты:** генератор пишет
  `"orbit_radius_au"` в JSON `data` всех планет — `internal/generator/planet/
  planet_data_generate.go` (стр. 318, 456, 586), `planet_data_gas.go` (стр. 117),
  `circumbinary.go` (стр. 292, 391 — там `3×sep`, не формула). Хранится в БД и
  приходит на фронт в JSON планеты как есть (PlanetData.Data raw).
- `orbitRadiusByIndex(index) = 0.4 × 1.7^index` (`physics.go`) — лишь часть
  случаев (S-орбиты); для P-орбит двойных систем радиус другой. Поэтому брать
  надо готовое поле `orbit_radius_au`, а не пересчитывать формулу.
- В UI (`web/static/js/modal/`) орбиты рисуются визуально по `orbit_index`
  (layout.js), числовое расстояние до звезды не показывается нигде.
- Вывод: показ — чисто фронтовая правка, миграция БД и изменение API не нужны.

## ТЗ (готово, ответы создателя 2026-09-14)

1. **Место показа** (решение создателя «выбери подходящее» → менеджер/разработчик):

   планеты в модалке системы (рядом с температурой/гравитацией/радиоактивностью).

   крупные орбиты (десятки/сотни а.е.) — тоже до 1 знака после запятой
   (например «12.3 а.е.»), без научной записи.
3. **Источник** (решение создателя, актуализировано менеджером 2026-09-16):
   **готовое поле `orbit_radius_au` из `data` планеты** (генератор уже пишет его
   для всех типов, включая P-орбиты двойных систем). Формулу на клиенте НЕ
   повторяем — единый источник правды. Поле отсутствует (старые данные) → «—».
   Отдельная миграция БД / изменение API не вводятся.

## Критерии готовности

- В блоке физических данных карточки планеты видно «Расстояние до звезды: N а.е.».
- N берётся из `planet.orbit_radius_au` (поле data), округлено до 1 знака, без
  научной записи (например «0.7 а.е.», «12.3 а.е.»). Нет поля → «—».
- DoD по `AGENTS.md` §2 (если правка затронет Go; ожидается чисто фронтовая).
