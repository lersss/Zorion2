# 98b — Поле дополнительных тегов с фронта в арт-студии (эксперименты)

## Пожелание (создатель, 2026-09-18)

«Можем добавить возможность свои теги в генератор вносить с фронта? какое-то поле для экспериментов чтобы было».

## ТЗ (менеджер, технические решения)

1. **UI арт-студии** (`cmd/art-studio/web/index.html`, embed): поле «Дополнительные теги» (одно общее для генерации — работает и для вариаций, и для кандидатов эталона). Передаётся в запросы генерации.
2. **API:** query-параметр `tags` в `/genvar` и `/genref` (опционально, пустой = как сейчас).
3. **Вставка в промпт:** `BuildPrompt` и `BuildPromptWide` (все ветки: не-антропо и морфные) — дополнительные теги вставляются в **конец** промпта, перед финальным «masterpiece, game avatar, no text, no watermark» (высокий вес в SDXL). Теги не сохраняются отдельно — попадают в `meta.json` в составе промпта (видно, с чем генерилось).
4. **Не ломает:** без `tags` поведение ровно как сейчас (98a: appearance/blocked/фильтрация не меняются).
5. **Тесты:** передача tags в промпт (все ветки BuildPromptWide + BuildPrompt), пустой tags — без изменений, хендлеры парсят tags.

## Дополнение (создатель, 2026-09-18): панель контроля полного промпта

«Мне нужен контроль. Можешь вместо "дополнительные теги" вывести всю строку запроса по выбранному семейству + расе + морфу + персонажу?»

**Решение (менеджер):** панель «Итоговый промпт» в UI арт-студии (поле тегов остаётся):
- Показывает ПОЛНУЮ строку промпта для текущего выбора: fam + race + morph (вкладка «Эталон») + personage + доп. теги — до генерации.
- Хендлер `GET /prompt?fam=&race=&morph=&personage=&tags=&seed=` → строит промпт (BuildPrompt для вариаций, BuildPromptWide для кандидатов с морфом) и возвращает JSON {prompt, race_id, race_name}. Без запуска генерации.
- UI: readonly-панель под выбором, обновляется при изменении параметров и по кнопке «Обновить пример» (случайный seed — показывает разброс вариантов).

## Дополнение 2 (создатель, 2026-09-18): хирургическая правка итогового промпта

«Да. Я должен мочь хирургически менять итоговый промпт, который уходит на генератор».

**Решение (менеджер):**
- Поле «Итоговый промпт» становится **редактируемым** (textarea/contenteditable).
- **Авто-режим** (по умолчанию): поле не тронуто — автообновляется при смене параметров; генерация идёт как раньше (BuildPrompt/BuildPromptWide на каждый i, разнообразие промптов).
- **Override-режим:** пользователь внёс ручную правку (поле отличается от авто-значения) — флаг override, подсветка, кнопка «↺ Вернуть авто». Генерация (вариации и кандидаты) использует **именно ручную строку** для всех N промптов (разброс картинок — за счёт seed у SDXL). В meta.json сохраняется ручной промпт.
- Передача: `/genvar` и `/genref` принимают опциональный `prompt_override`; передаётся ТОЛЬКО в override-режиме (в авто — не передаётся, чтобы не фиксировать один случайный промпт).
- Кнопка «Обновить пример» в override-режиме НЕ перезаписывает ручной текст.
