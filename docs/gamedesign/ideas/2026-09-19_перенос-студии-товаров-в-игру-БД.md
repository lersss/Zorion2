## 0. Пожелание создателя (2026-09-19)

> «Как работает удаление и бан?» → разбор (ответил). Далее:
>
> «Я могу как-то добавить товар в категорию "ресурс"?» → разбор: ресурсы — отдельный
> каталог на сервере, read-only в студии. Далее:
>
> «Давай так: 1. ресурсы больше не read-only, 2. У ресурсов может быть разный Tier,
> 3. их так же можно добавлять, удалять, банить и тд — никаких привелегий.»
>
> Уточнения (ответы на 4 вопроса скоупа):
> 1. Переносим ВСЮ студию, можно разбить на итерации и даже сессии.
> 2. Свой URL — шапка админки мешать будет.
> 3. Работаем с базой игры напрямую, а не с JSON.
> 4. Данные удаляем, кроме T0, которые есть в игре уже (ресурсы тира 0 из
>    Go-каталога internal/resource).

## 1. Решения (зафиксированы)

1. **Ресурс — «добываемый» товар, не производимый**: у ресурса НЕ может быть
   дочек (рецептов/слотов). Ресурс всегда лист дерева.
2. **Ресурсы без привилегий**: можно добавлять, удалять, банить, разбанивать,
   переименовывать, менять категорию и тир.
3. **Перенос студии в игровой сервер** (`cmd/server`): данные — в PostgreSQL
   (таблицы каталога), UI — на собственном URL (НЕ админка, без её шапки).
4. **state.json и текущие данные**: удаляем (не переносим), кроме ресурсов T0.
5. Разбиение на итерации/сессии — см. §5.

### Решения по вердикту критика (2026-09-19, создатель)

- **К1 (сидер)**: реальные вещества (`real.go`, 111) **переносим в игровой
  контент** — сидер БД = все 131 ресурс (слой 20 + витрина 111). Витрина
  «Реальные вещества» (94a) **переделывается: смотрит в контент (БД)**, а не в
  `real.go`. Эталон «витрина ≠ контент» (2026-09-18) пересмотрен создателем.
- **С1 (источник правды)**: **БД — источник правды** для каталога (ресурсы +
  товары). Go-каталог `internal/resource` перестаёт быть источником; читатели
  (94a витрина, проверки «все накормлены»/посредственность, forage, валидатор
  студии, будущий генератор полей) переходят на БД.
- **С3 (тир ресурса)**: развилка «тир назначаемый или вычисляемый» сохраняется
  (как у товаров: оверрайд ?? вычисленный; у ресурса вычисленный = 0, т.к.
  рецепта нет). Ресурсу можно **назначить тир** — для удобства разграничения
  «редких» и обычных ресурсов (презентация/сортировка; игровой эффект не
  заявлен).

## 2. Текущее состояние (факты, 2026-09-19)

- Студия — отдельный бинарь `cmd/goods-studio` (порт 8799, конфиг
  `config/goods/studio.json`, состояние `goods_data/state.json` вне git):
  394 товара / 13 категорий / 131 ресурс. UI — `cmd/goods-studio/web/index.html`
  (1556 строк, embed в бинарь).
- Серверные хендлеры: `handlers/state.go` (~1067 строк) — CRUD товаров/категорий/
  слотов/статусов/тир-оверрайдов, ИИ `ai/`, каталоги `catalog/` (импорт
  top-каталога `top_catalog.json` и деревьев Т8 `trees_t8.json`), валидаторы
  `validate/`, экспорт `export/`, граф `graph/` (тир = 1+max детей, ресурс = 0).
- Read-only ресурсов сейчас в 4 местах: PUT/DELETE товара (403), статус
  (ресурс — только banned/unban), тир (403), переименование (403).
- Игровой сервер: PostgreSQL + миграции `migrations/` (автоприменение при старте),
  JWT-роли `admin`/`skycomposer`, админка `web/static/js/admin/`. Таблиц каталога
  товаров/ресурсов в БД НЕТ (`planet_resources` — ресурсы планет, `goods_batches` —
  партии в экономике; каталог номенклатуры — ещё не в БД).
- Go-каталог ресурсов `internal/resource`: LayerCatalog() 20 + RealCatalog() 111 —
  используется студией (импорт на чтение) и сервером (94a, витрина «Реальные
  вещества»).

## 4. Вопросы к дизайну (решает @designer, выносит на гейт)

- **Таблицы**: `categories` (id, name), `goods` (id, name, category_id, kind,
  status, source, tier_override, banned_at, created_at, resource_ref?), слоты —
  отдельная таблица `slots` (good_id, pos, component_id, quantity, allow_resource)
  или JSONB-колонка в `goods` (рецепт). Учитывать проверку циклов (граф),
  нормализацию имён, `res:`-id ресурсов.
- **Сидер ресурсов**: первичное наполнение таблиц из `internal/resource`
  (одноразовая миграция/сид при первом старте; при обновлении Go-каталога —
  как обновлять?).
- **Роуты**: свой URL (например `/studio/goods` или `/goods-studio`), статика —
  в `web/` (не embed). Доступ: JWT `admin`/`skycomposer` (студия — инструмент
  наполнения контента, на проде открывать нельзя).
- **Судьба старой студии**: удаление `cmd/goods-studio` + `goods_data/` после
  переноса (отдельным шагом итерации).
- **Экспорт JSON**: нужен ли после переноса (данные уже в БД) или оставить
  как выгрузку для будущих систем?
- **ИИ-заполнение комплектующих** (`ai/`): переносится (opencode HTTP — клиент
  студии переиспользуется).
- **Импорт top-каталога / деревьев Т8**: переносится (кнопки в UI).

## 5. Предлагаемые итерации (разбиение, уточнится на гейте)

- **Итерация A — каркас на БД**: миграции (таблицы каталога: `categories`,
  `goods`, слоты; **сидер = все 131 ресурс** — слой 20 + витрина 111, из
  `internal/resource`), роуты `/studio/*` на игровом сервере (JWT admin/skycomposer,
  свой URL, без шапки админки), перенос серверной логики студии на SQL (CRUD
  товаров/категорий/слотов/статусов/тир-оверрайдов), **ресурсы — без привилегий**
  (создание/удаление/бан/тир-назначение; без рецептов), статика студии в `web/`.
- **Итерация B — UI студии**: подключение перенесённого `index.html` к новому
  API (граф/канвас, фокус-подграф, справочник с фильтрами — OR-семантика
  (используемые OR неиспользуемые OR забаненные) AND тиры, попап-деталь,
  drag&drop, «+ товар»/«+ ресурс»); **витрина «Реальные вещества» (94a) — переезд
  на чтение из БД**.
- **Итерация C — доводка**: ИИ «заполнить комплектующие», импорт top-каталога/
  деревьев Т8, экспорт (по решению гейта), удаление `cmd/goods-studio` +
  `goods_data/state.json`, перевод читателей Go-каталога (проверки 94a, forage,
  валидатор) на БД, обновление доков (ARCHITECTURE, PITFALLS, INDEX, impact map,
  GLOSSARY — «ресурс» остаётся «добываемым»; эталон «витрина ≠ контент»
  пересмотрен).

## 8. Вопрос на итерацию C (из вердикта критика по спеке A, 2026-09-19)

(пропуск ресурсов) ослабляет защиту «выгрузка без битых ссылок». Решение на C:
не-approved ресурсы (banned/excluded/draft) — выгружаются по факту ссылки или
только approved? От этого зависит корректность ослабления валидатора. В A не
блокер (экспорт — C).
