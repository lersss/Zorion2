## Уточнения (2026-09-20)

1. **Рядом с «Очистить галактику», не вместо.** Очистка (TRUNCATE) остаётся
   мгновенной; пакман — отдельная кнопка-джоб.
2. **Ест миры целиком** — звёзды вместе с планетами, поселениями, фракциями,
   локациями (как `clearUniverseTx`, но по траектории, порциями).
3. **Виден на игровой карте, и видят ВСЕ игроки** (не только админ): событие
   вселенной в реальном времени. Это главное отличие от простого прогресс-бара.
4. **Траектория — открытый дизайн-вопрос.** Создатель: «Не знаю, давай будем
   смотреть. Важен вау-эффект, как он будет достигаться пока не знаю».
   Ограничение создателя: ~100к миров за минуту.
5. **NPC-агенты съедаются вместе с миром** (решение создателя 2026-09-20,
   крупный блокер критика): агент в съеденном мире или летящий в него
   исчезает с карты. FK `npc_agents.current_world_id/from_world_id/target_world_id
   → worlds` — NO ACTION (000026): порционному DELETE нужен явный DELETE
   агентов по съеденным мирам.
6. **Знания игроков стираются вместе с планетами** (решение создателя
   2026-09-20, крупный блокер критика): «всё удалять. Это по сути вайп
   галактики (игроки остаются)». `player_planet_knowledge.planet_id → planets`
   — NO ACTION (000040): нужен DELETE знаний по съеденным планетам (или каскад).
7. **Первое приближение, потом подкрутка** (решение создателя 2026-09-20):
   сделать MVP с настраиваемой скоростью поедания (в конфиге/теле запроса),
   чтобы потом уменьшить. Вау-эффект — простой, но ощутимый; не раздувать.
8. **Регионы съедаются** (уточнение создателя 2026-09-20): полностью опустевшие
   регионы удаляются в конце джоба (`DELETE FROM regions WHERE world_count = 0`
   после пересчёта), частично съеденные — пересчитываются.
9. **Гейт дизайна 2026-09-20 — решения по §12 спеки** (все совпали с v1-дефолтами):
   игрок без мира (NULL + уведомление); полёт к съеденному прерывается;
   траектория — полярная спираль (змейка — режим `snake`); класс «События
   вселенной» — единичный инструмент в v1, каркас закладывается (решение
   менеджера, «на твоё усмотрение»); пустая галактика — ждём генерации админом.
   Спека: `docs/specs/2026-09-20-pacman-galaxy-wipe.md` (594 строки, 2 прогона
   критика: 0 крупных, 1 среднее закрыто, мелкие закрыты).

## Текущее состояние (что уже есть)

- **Джобы админки** (`internal/generator/status.go` + `admin_universe.go`):
  `StatusManager.TryStart/Progress/Done/Fail/Cancel`, поллинг
  `/admin/generate-status?job=…`, кнопки остановки, защита от конфликтов.
  Новый джоб `pacman` встраивается в этот механизм.
- **Очистка** (`clearUniverseTx`, `admin_universe.go:57`): TRUNCATE списка таблиц
  с временным снятием FK `users_current_world_id`. Для пакмана нужна **порционная**
  версия удаления (по миру/батчу), а не TRUNCATE.
- **Снапшот карты** (`internal/mapcache`): immutable `Snapshot`, замена через
  `atomic.Pointer`, `LoadAsync` после изменений. Пакман удаляет миры → пересборка
  снапшота (или точечное вычёркивание).
- **WebSocket** (`internal/handlers/websocket_hub.go`): `WebSocketHub.Broadcast`
  уже шлёт всем клиентам (используется уведомлениями NPC, `ws_notifier.go`).
  Клиент подключается к `/ws?token=…` (`web/static/js/map/npc_agents.js:104`).
  → позиция/события пакмана рассылаются Broadcast'ом всем игрокам.
- **Фронт карты**: Canvas + кластеры, рендер объектов (агенты, корабли игроков)
  — есть паттерны отрисовки живых объектов поверх карты.

## Открытые дизайн-вопросы (решает @designer, на гейт создателю)

1. **Траектория и честность полёта.** Честный «ближайший сосед» на 100к миров
   на каждый шаг — дорого (оценка в идее ниже). Варианты: змейка/спираль по
   координатам, жадная спираль от центра, батчи по близости, гибрид
   (визуальный полёт + фактическое пакетное удаление). Критерий: за минуту,
   вау-эффект, не убить БД.
2. **Вау-эффект.** Что видят игроки: огромный пакман (размер?), след,
   вспышка/поедание мира, счётчик «съедено», тосты/уведомления «внимание,
   галактику пожирают!». Создатель пока не знает — задача дизайнера предложить
   2–3 варианта.
3. **Взаимодействие с игроками/полётами.** Что если игрок летит в мир, который
   пакман ест? Мир исчезает под игроком — обработка (как при удалении мира,
   ср. 97a Restore: «битые миры отбрасываются»). Что если игрок на карте видит
   пакмана вплотную — можно ли попасть под «рот»?
4. **Масштаб**: пакман ест миры на всей карте или только «в поле зрения»?
   (Зачистка — всей карты, судя по «зачищать карту на 100к».)

## Оценка производительности (черновая, для дизайнера)

- 100к миров за ~60 с → ~1700 миров/с. Планет ~3 на мир → ~5к строк/с суммарно.
- DELETE по одному миру с каскадом (поселения/фракции/локации) — дорого
  (~десятые доли мс на мир в лучшем случае → 1700/с сомнительно, зависит от
  индексов и каскада). Реалистично: батчи `DELETE FROM worlds WHERE id IN (...)` +
  `DELETE FROM planets WHERE world_id IN (...)` + … по 100–500 миров, прогресс
  по батчам. Точную схему и замер — в дизайне/разработке.
- Траектория «ближайший сосед» на каждый мир: O(N²) ~ 10¹⁰ операций — не
  влезает в минуту. Нужен индекс/сетка (кластеры уже есть в mapcache) или
  заранее построенный маршрут.

## Решения живой приёмки (2026-09-20, все внесены в код/спеку)

1. **Визуал — классический Пакман**: жёлтый круг **34 px** (создатель: «меньше в
   3 раза» от 100), **без глаз и обводки** («классический пакман»), рот-сектор
   **из центра** (moveTo — иначе хорда «отрезанный край»), **открывается от
   ~11° до ~69°** (0.10+0.50·|sin|, 1.5 Гц — реальная «паку-паку»), пульсирующий
   нимб + след (заметность). Обводка/глаза были, убраны по просьбе.
2. **Скорость без нижней границы** («снизу не ограничивать — нормальный
   ивент»): `worlds_per_second` **float64, >0..10000** (0.01 — «кинорежим»).
   **Адаптивный батч = 1** при `wps < batch_size` — пакман ест **по одной
   звезде** («не для скорости, а для вайба»; центроид = сама звезда → частицы
   в ней). На больших скоростях — батчами (иначе 100к не успеть).
3. **Траектория — `nearest` (жадный ближайший сосед через сетку) как дефолт**
   («пусть он всё-таки как-то ближайшие кушает, иначе мечется по галактике»;
   спираль прыгала между кольцами). Сетка cell=2·span/√N, расширяющийся поиск
   по кольцам, детерминизм. spiral/snake — опции.
4. **Снапшот карты НЕ пересобирается на каждый батч** (rebuildSnapshot убран,
   LoadAsync в конце джоба): перезапросы области больше не «спойлерят»
   съеденные звёзды раньше пакмана («сами лопаются»).
5. **Звезда лопается, когда пакман до неё долетел** («не лопать, пока он до
   звезды не долетит»): клиент держит «долетающие» (pendingEaten) — видимы,
   пока пакман летит, лопаются в радиусе рта (dist < PACMAN_SCREEN_PX/scale)
   или по maxDelay=2×темп позиций+500 мс (быстрая скорость). Фильтр
   перезапроса вычитает eatenIds КРОМЕ pendingEatenIds.
6. **Непрерывный rAF-цикл при активном пакмане** (рот «замирал» ~3 фпс по
   событиям): ensurePacmanAnimLoop, паттерн NPC.
7. **Слежение «👾 Следить за Пакманом»** (кнопка в шапке карты, при активном
   событии): камера центрируется на пакмане каждый кадр, отключается на end.
8. **Кнопка «Остановить»** — появляется в админке при running (поллинг);
   отмена → canceled с отчётом «Съедено N из M». (Создатель сначала не видел —
   кеш HTML, Ctrl+F5.)
9. **Поздние подключения** (активация от любого события) — см. выше.
10. **Правки критика/ревьюера** внесены: RETURNING id, гварды, прото-планета,
    отмена полётов после COMMIT и т.д.
