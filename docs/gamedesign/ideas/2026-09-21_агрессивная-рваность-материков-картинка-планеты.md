## Анализ менеджера: источники линейности (проверено по коду)

1. **Круглые границы регионов.** `generateBiomeSurface` (`internal/generator/planet/planet_image_v2.go`): регион = сфера на шаре, попадание `dist3D(p,c) < r·(1+0.3·n)` — модуляция радиуса всего 30%, доменный варп в `elevationAt` — 12% (amount 0.3). Округлость берегов океанов/материков читается.
2. **Прямые стыки между биомами.** Остаток (зазоры между регионами) заливается **ближайшим регионом** (диаграмма Вороного → ровные рёбра между биомами). PITFALLS 2026-09-21: жёсткий «остаток → доминант» ломал бюджет ±30%, решение — ближайший; но ближайший даёт прямые грани.

## ТЗ на дизайн (что вернуть от gdesigner)

Дельта-спека к `docs/specs/2026-09-21-планета-форма-поверхности-блик-и-реальная-атмосфера.md` (живые ссылки — impact_map, PITFALLS, INDEX; не архивировать), раздел §4.1 «форма поверхности»:

- **Агрессивный доменный варп** координат на границе региона (сейчас 12% → целевые ~35–50%): береговая линия изломанная, заливы.
- **Сильная модуляция радиуса** региона (сейчас `r·(1+0.3·n)` → усилить + высокочастотная компонента, например вторая октава / ridged на границе): круг не читается.
- **Прямые стыки Вороного убрать**: остаток заливать не жёстко ближайшим, а смешанно по шуму (два ближайших региона + fbm-порог) либо увеличить перекрытие регионов (остатков меньше). Бюджет долей ±30% сохранить (PITFALLS: тест `TestSurfaceRegionAllocation`).
- Стиль А сохранить (мягкий реализм), детерминизм от seed — обязательно.
- Конкретные числа/формулы — на усмотрение дизайнера, но с проверяемыми критериями (см. ниже).

## Критерии приёмки (технические)

- Тесты не краснеют: `TestSurfaceNoCircles` (boundaryRaggedness > 0.2 — поднять порог, если форма стала заметно рванее), `TestSurfaceMasses`, `TestSurfaceRegionAllocation`, `TestPlanetImageDeterministic`, `TestPlanetImageVersionKey` (v4).
- **`ImageGenVersion` v3 → v4** (PITFALLS S1: любая визуальная правка → инкремент, иначе старые PNG из кэша).
- API `/api/planet-image` не меняется (режимы, параметры, кэш-ключи по структуре те же).
- Эталон Renyenmus: на 512px границы крупных масс изломаны (spread (max−min)/mean заметно > порога теста №3), круги и прямые стыки не читаются глазами.

## Итог реализации (что сделано на деле)

Направление из ТЗ скорректировано по ходу (дизайн-спека не писалась, разработчик пошёл сразу в код — менеджер счёл ТЗ идеи достаточным):

1. **Согласованный доменный варп** — искривление применяется и к точке пикселя, и к центрам регионов (центры варпятся один раз заранее). Сила ослаблена относительно черновика (amount 0.5/0.35), чтобы держать бюджет.
2. **Заливка — взвешенный Вороной** («ближайший регион» по `d/(r·mi)`), а не «два ближайших + fbm-порог» (тот приём бюджет ломал). Это и есть главный источник рваных (не прямых) стыков.
3. **Передняя полусфера** — регионы размещаются только на видимой половине (`z ∈ [0,1]`), раньше ~половина падала за лимб и биом с одним регионом давал 0%.
4. **Отбрасывание перекрытий** при размещении (допуск ×0.8) — мелкий регион больше не «проглатывается» крупным соседом.
5. Кламп лимба и джиттер радиуса подтянуты под бюджет.
6. `ImageGenVersion` v3 → **v4**.
