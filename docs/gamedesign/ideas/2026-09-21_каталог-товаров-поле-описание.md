## 1. Факты (сверка с кодом, 2026-09-21)

- **Таблица `goods`** (миграция `000045`): `id, name, name_norm, category_id,
  kind, status, source, tier_override, banned_at, created_at, props`.
  `props` JSONB — только для ресурсов (оси/семейство); у товаров NULL
  (`CHECK`). Поля `description` нет. Последняя миграция — `000056`, следующий
  свободный номер — **`000057`** (бронь у @manager, `docs/DB.md`).
- **Модель** `model.Good` (`types.go`): `ID/Name/Category/Kind/Source/Recipe/
  RecipeID/CreatedAt/Complexity/Volume/Weight`. Поля `Description` нет.
- **Репозиторий** (`goods_repository.go`): `loadGoods` — единый SELECT
  (`g.id, g.name, ..., g.volume, g.weight` + LEFT JOIN `recipes`), читается
  снимком; `CreateGood`, `UpdateGood` (name/category_id/volume/weight),
  `BulkCreateGoods` (парсит «имя | категория»), `ApplyProposals` (INSERT
  новых товаров от ИИ: только `name/name_norm/category_id/kind/source`).
- **Хендлеры** (`studio_handlers.go`): `GoodView` (id/name/category_id/kind/
  source/tier/tier_computed/recipe_id/complexity/bound_factories/recipe/
  volume/weight); PUT `/studio/api/goods/{id}` (тело `name/category_id/
  volume/weight`); POST `/studio/api/goods` (создание); POST
  `/studio/api/goods/bulk` (`lines`); fill-роуты (`fill`/`fill/apply`/
  `fill/cancel`) — асинхронные, предложения в in-memory `fillProposals`.
- **ИИ** (`internal/goodsstudio/ai/`): `Component{Name,Category,Reason}` —
  ответ ИИ на «заполнить комплектующие» (ровно по одному на пустой слот);
  `Proposal` (попап «Предложения ИИ»: slot/name/category/category_valid/
  reason/kind/link); `ProposalItem` (применение); `ApplyProposals` создаёт
  новые товары (kind=good). Описание в промпте/разборе/применении отсутствует.
  Клиент — HTTP к локальному opencode (`OPENCODE_URL/MODEL/TIMEOUT_S/
  MAX_RETRIES`), вызов блокирующий, в fill обёрнут в горутину.
- **UI** (`web/studio.html`): попап товара/ресурса — «объём · вес» (строка
  `dmeta`, ~1326), у товара — «Состав рецепта», «Доступен фабрикам»; попап
  «Предложения ИИ» с принять/пропустить; кнопки «+ товар»/«+ ресурс»;
  массовая подгрузка списком.
- **Тесты:** `studio_handlers_test.go` / `studio_producers_test.go` —
  sqlmock сверяет **дословный текст SELECT** `loadGoods`. Правка SELECT’а
  без обновления ожиданий ломает тесты (ловушка для @developer).

## 2. ТЗ (черновик для @designer)

Сквозная нитка: **БД → модель → репозиторий → API → ИИ → UI**. Поле проходит
по всем слоям; ниже — что где.

1. **БД:** миграция `000057` — `ALTER TABLE goods ADD COLUMN description TEXT
   NULL`. Одна колонка для обоих видов (`good`/`resource`); `props`
   (ресурсные оси) не трогаем; `CHECK` по `props` не затрагивается.
2. **Модель:** `model.Good.Description string` (`json:"description,omitempty"`).
3. **Репозиторий:**
   - `loadGoods` — добавить `g.description` в SELECT и Scan;
   - `CreateGood` — описание пустое (или принимать, см. п.6 создания);
   - `UpdateGood` — параметр `description *string` (nil = не трогать, как
     volume/weight); пустая строка = очистить;
   - `BulkCreateGoods` — третья колонка в строке «имя | категория | описание»
     (описание опционально: 2 колонки тоже валидны, описание пустое);
   - `ApplyProposals` — INSERT нового товара с описанием из предложения ИИ.
4. **API/представления:** `GoodView + description`; PUT `/studio/api/goods/{id}`
   — принять `description`; POST `/studio/api/goods` — принять `description`.
5. **ИИ — заполнение состава:** в ответе на «заполнить комплектующие» у
   составляющей появляется описание; `Component.Description`,
   `Proposal.Description` (показ в попапе), `ProposalItem.Description`
   (применение); промпт просит описание **только для новых** составляющих
   (`kind=new`); для `kind=link` (существующий товар) описание не меняется.
   Описание (как и имя) сохраняется в `goods.description` при создании
   нового товара в `ApplyProposals`.
6. **ИИ — при создании (вариант «в»):** ручное создание «+ товар»/«+ ресурс»
   должно получать предложение описания от ИИ. Развилки (см. §3): синхронный
   вызов сразу после создания или второй асинхронный прогон с попапом
   «принять/пропустить/отредактировать»; применяется и к ресурсам (у ресурса
   состава нет — только описание).
7. **UI:** многострочное поле в попапе товара/ресурса (textarea) с сохранением
   по изменению (как объём/вес) или по кнопке; показ описания в попапе
   «Предложения ИИ» как отдельного пункта «принять/пропустить»; поле описания
   в форме создания; подсказка о третьей колонке в массовой подгрузке.
8. **Тесты:** Go — юниты на разбор/применение (описание у `kind=new`,
   сохранение, bulk с 3 колонками, PUT description); обновить ожидания
   sqlmock SELECT. Клиентский флоу (попап, создание, ИИ-предложение) — e2e
   `/studio` (`tools/e2e`, если покроется) + ручной прогон @tester.
