## 2. Диагноз (менеджер, 2026-09-21)

### 2.1. Невидимые стены — баг, блокирует игру (шаг 1)

`SurfaceWorld.isSolid(x, y)` **выше** линии рельефа возвращает `true` для формаций
с `float: true` (висячие скалы, арки, гроты, скальные выходы, обсидиановые стены,
ледяные арки, грибные башни, плавучие камни):

```js
if (f.float) {
    const n = noise2(x * 0.01, y * 0.01, this.seed ^ 0xa5a5);
    if (n > 0.72 && y > th - 260) return true; // висячие скалы/арки
}
```

`getChunkCanvas` (отрисовка) рисует **только** породу ниже `terrainHeight` + пещеры
внутри неё. Всё, что выше рельефа, не рисуется вообще. Итог: физика видит твёрдый
объём, игрок в него упирается, на экране — пустое небо.

В биосфере («джунгли») одна из формаций — «скальные выходы» (`float: true`), отсюда
«если идти вправо» — упор в невидимую стену.

**Корень:** два разных ответа на вопрос «что здесь твёрдо» — физика и отрисовка
считают по разным правилам. Класс ошибки: «один факт — одно место».

### 2.2. Дёргание деревьев и дальнего плана — баг отрисовки (шаг 2)

**Декор (деревья/трава).** `drawDecor` идёт по **экранной** сетке шагом 4 px
(`for (let sx = 0; sx <= vw; sx += 4)`) и для каждой экранной точки спрашивает
колонку мира `Math.floor(left + sx)`, а рисует по экранной координате `x = sx`.
При дробном сдвиге камеры набор опрошенных колонок меняется: дерево попадает в
соседнюю клетку сетки или **выпадает из выборки** на этот кадр. Отсюда дёрганье на
несколько пикселей и мерцание (пропадает-появляется) на ходу.

**Дальний рельеф.** `drawFarRelief` берёт ту же `terrainHeight(wx * 1.4)` (мелкая
детализация с периодом ≈36 px) и опрашивает её шагом 12 px по экрану, при этом `wx`
непрерывно зависит от `camera.x`. Это наложение частот (≈3 отсчёта на волну):
силуэт не уезжает цельно, а каждый кадр меняет форму — гребни «дышат» и скачут.
Плюс дальний слой — сжатая копия ближнего, дублирует горы в другом масштабе.

### 2.3. Туман — заглушка, плохо выглядит (шаг 3)

`drawWeather` для `fog` рисует 3 прямоугольника высотой 60 px в координатах
**экрана** (`vh * (0.3 + i * 0.2)`), с покачиванием ±10 px. Не привязаны ни к земле,
ни к рельефу; резкие края; нет глубины. Тот же корень, что у 2.2 — экранные
координаты вместо мировых.

## 4. Шаг 1 — ТЗ @developer (невидимые стены)

**Цель:** что вижу — в то и упираюсь; игрок нигде не заперт.

1. **Одна функция-источник твёрдости.** Парящие камни рисуются тем же правилом,
   по которому `isSolid` считает их твёрдыми (не второй предикат-близнец).
   В `getChunkCanvas` добавить проход по полосе над рельефом
   (`y ∈ (th − 260, th)`, шаг 3 px, как у пещер) — красить породу там, где
   `isSolid(wx, wy)` истинно.
2. **Гарантированный проход под парящим камнем.** Сейчас камень может быть твёрдым
   вплоть до линии рельефа → стена до земли, непроходимая (прыжок ≈41 px при 1 g,
   рост игрока 28 px). Ввести минимальный зазор: камень твёрд только выше
   `th − зазор`, где зазор заведомо больше роста игрока. Стен «до земли» быть не
   должно — только парящие арки, под которыми проходишь.
3. **Не запираться на спавне и в щелях.** Проверить: спавн не внутри твёрдого;
   разрешение вертикальных коллизий не оставляет игрока зажатым.
4. **Границы чанка.** Проверить, что полоса парящих камней не выходит за верх
   канваса чанка (`CHUNK_TOP_MARGIN = 620`) — при высокой горе камень не должен
   обрезаться или пропадать.
5. **Хирургичность.** Туман и дёргание слоёв — НЕ в этом шаге (шаги 2–3).

**DoD:** `node --check` на изменённые JS; прогон `tools/e2e/surface-walk-check.js`
(ходьба/прыжок/HUD/возврат не сломаны); отдельная проверка проходимости в формации

## 7. Шаг B — направление по погоде (@uidesigner, 2026-09-21)

**Явлений шесть** (не семь — описка менеджера): штиль, туман, пыльная буря,
метель, кислотный дождь, полярное сияние.

**Общий принцип (вместо «полос на стекле»):**
1. **Дымка глубины** — у каждого явления свой «цвет воздуха»; им прокрашиваются
   слои тем сильнее, чем дальше слой: дальний силуэт 45–70 %, средний 30–40 %,
   ближний рельеф 8–15 %, весь кадр 8–25 %. Небо тоже уходит в оттенок.
2. **Частицы живут в мире** — засеяны по мировым колонкам с модульной обёрткой
   (как рельеф/декор), при движении камеры проносятся мимо; **3 пояса глубины**
   (дальний мелкий/медленный, средний, ближний крупный/смазанный), параллакс
   0.4 / 0.7 / 1.0.
3. **Общий ветер с порывами** — один вектор на явление, модулятор 0.6–1.5×,
   период 3–9 с; всё, что касается земли (позёмка, заносы, всплески, пары), —
   по `terrainHeight(x)`, не по экранному Y.

**Структурное следствие:** погоду надо рисовать **в 2–3 прохода между слоями
мира** (часть — между дальним силуэтом и рельефом), а не одним вызовом в конце
кадра (`surface_main.js` сейчас: один вызов `drawWeather` в конце).

**Три приоритетных (названы создателем):**

| Явление | Что видно | Ключевое (опознавательная деталь) |
|---|---|---|
| **Туман** | Молочная мгла, гуще вдали и у земли; дальний силуэт растворяется; клочья идут волнами; рваный верхний край; туман стелется в низинах | Слоистость + привязка к земле. Дымка: дальний 55–70 %, средний 30–40 %, ближний 8–15 %; клочья пар. 0.2–0.35 / 0.5–0.7 / 1.0; снос 5–14 px/с; порывы период 8–14 с; ядро alpha 0.18–0.30 |
| **Метель** | Белый поток летит **косо, вбок-вниз**; три пояса хлопьев; позёмка, вихри, заносы у камней и гребней; дальность падает до белой мглы | Косой лёт + позёмка + заносы. Дальний 120–200 точек 1–2 px пар. 0.4 (200–350 px/с); средний 70–110 шт 2–3 px пар. 0.7 (350–600, качание 8–15 px); ближний 20–40 шт 4–7 px пар. 1.0 (600–900, смаз в штрих 10–25 px); порывы 0.6–1.5× период 3–8 с; хлопья `rgba(245,250,255,0.55–0.90)`; мгла 20–45 % |
| **Кислотный дождь** | Наклонные струи; зелёно-жёлтая пелена; **у земли всплеск и поднимающийся дымок**, камни и лужи «дымят» | **Реакция земли** (всплеск + пар) — отличает от «просто дождя». Мгла 8–18 % на кадр + дальний 25–40 %; струи: 80–150 пар. 0.4 (500–700 px/с, наклон 10–20°), 60–90 пар. 1.0 (700–950), 10–25 ближних (длина 30–50 px); всплески у `terrainHeight`, жизнь 60–140 мс; пары 2–6 px вверх 15–40 px/с, жизнь 0.4–1.0 с |

**Остальные:** пыльная буря (бурый поток почти горизонтально, 3 пояса песчинок
250–1100 px/с, светило и небо гаснут в охру, «юбка» песка у земли); полярное
сияние (2–4 «шторы» из 30–80 вертикальных прядок, пар. 0.05–0.12, волна яркости
бежит снизу вверх 2–5 с, свечение аддитивное, небо чистое); штиль (базовая дымка
горизонта 8–12 % + 8–14 медленных пылинок 2–4 px/с; горизонт — самый резкий из
всех явлений, «эталон ясности»).

**Решения менеджера:** цвета явлений — производные от палитры биома (авторские
цвета — отдельный заход к @gdesigner); кроссфейд при смене 0.6–1.2 с, но при
админ-переключении целевое состояние полное **с первого кадра**.

**ТЗ на шаг B (черновик):** многопроходная отрисовка погоды в `surface_main.js` +
переписанный `drawWeather` по таблице выше; параметры — в `surface_config.js`;
`drawWeather` сейчас — заглушка (3 полосы / точки / штрихи в экранных
координатах), меняется целиком.

## 8. Дополнения создателя (2026-09-22) — связка погоды с физикой + вид прогулки

### 8.1. Погода ↔ атмосфера и температура (уточнение к шагу B)

Создатель: «можем это как-то связать с атмосферой и температурой?» — **да**,
и это правильнее текущего «погода только по категории биома» (сейчас на ледяном
мире возможна пыльная буря). Все нужные поля **уже в пакете высадки**
(`temperature`, `pressure_atm`, `toxic`, `radioactivity`, `liquid_medium`,
`life`) — связка делается **на клиенте, без правок сервера**; погода остаётся
визуальной (урон — отдельно, от `hazard`).

**Предлагаемая модель (уточнить у @designer):**
- **Давление задаёт, что вообще возможно.** Тонкая атмосфера/вакуум — осадков и
  туманов нет, только пыль и резкое небо. Комфорт (0.5–3 атм) — полный набор.
  Плотная — тяжёлые густые явления.
- **Температура задаёт наклон** (пороги — те же, что у комфорта скафандра
  −10…+40 °C): холоднее → метель/морозный туман/сияние; комфорт → дождь/туман/
  штиль; горячее → пыльная буря/марево/сухая дымка.
- **Токсичность** → кислотный дождь/смог вместо обычного дождя.
- **Радиация (высокая)** → полярное сияние. **Жидкость** → цвет осадков/дымки.
- **Биом** — модификатор вкуса (смещает вероятности внутри разрешённого физикой),
  не задаёт набор сам.
- Логическое следствие (подтвердить создателем): **почти без атмосферы осадков
  и туманов нет вообще** — только пыль и ясное небо.
- Админский ручной выбор любой погоды — остаётся (инструмент обхода).

### 8.2. Зум: «всё очень мелко»

Создатель: «сделай ближе zoom — всё очень мелко». Замер: игрок 28 px, крупные
формы рельефа ~230 px на экране 1080p — масштаб действительно мелкий. Нужен
**общий масштаб отрисовки** (zoom ~1.6–2×): мир и игрок крупнее, видимая область
меньше; физика не меняется (масштаб — только визуальный, через трансформ камеры;
не через `PPM`, т.к. `PPM` — метры→пиксели в физике, а рельеф задан в px).
Учесть: чанки рельефа кэшируются в 1:1 — при апскейле возможна мягкость; решает
@developer (рендер чанка в повышенном разрешении либо приемлемая лёгкая мягкость).
Точное значение зума — подберёт @developer/@uidesigner визуально.

### 8.3. Баг: по краям экрана деревья без земли

Создатель: «с краёв прорисовываются только деревья, не земля и не небо; надо
растягивать канвас на весь экран».

**Диагноз (менеджер):** рельеф рисуется **только ±`CHUNK_RADIUS`=3 чанка**
(~1792 px) вокруг камеры (`drawTerrain`, `surface_render.js`), а декор
(деревья/растения) перебирается **по всей ширине экрана** (`visibleDecor`).
На экране шире ~1792 px за пределами чанков земли нет, а деревья есть → висят в
пустоте. Канвас при этом растянут на весь экран (`position:fixed; inset:0`), т.е.
проблема не в размере канваса, а в **непокрытии рельефом широкого экрана**.
Правка: число рисуемых чанков — от ширины вьюпорта и зума (не константа 3);
опционально проверить `devicePixelRatio` для резкости. Хирургично, отдельно от
погоды.

### 8.4. Небо: тела системы — реальные текстуры и не навязчивые

Создатель: «звезда и планеты на фоне очень навязчивые; их текстуры бы брать из
реальных планет системы».

**Факт:** сейчас тела рисуются градиентными кружками из одного цвета
(`drawSky`, `surface_render.js`), потому что в пакете **нет id планет** —
только имя/тип/размер/цвет (`SurfaceSkyBody`, `surface_handlers.go`). Картинки
планет уже есть: `GET /api/planet-image?planet_id=<UUID>&size=small`
(`planet_image_handler.go`); т.к. игрок **в своей системе** — режим `full`
(настоящая текстура) доступен для всех планет системы.
**Правка:** добавить `planet_id` в тело неба (сервер, аддитивно) → клиент грузит
реальную текстуру и рисует её вместо кружка; спутники — фолбэк (плоский диск,
картинки у спутников нет). Заодно **приглушить**: мельче, тусклее, реже/разнести
по высоте, чтобы не были навязчивыми (формулировки/ракурс — @uidesigner).

подмножество** тел (не все), **разбросанных** по небу (и X, и Y), с разной

небо). Новых сущностей/таблиц нет → малая задача (@developer). Приоритет — после
погоды (та же зона неба/отрисовки) либо быстрым фиксом по «го».
