## 1. Факты (текущее состояние)

- **Ветка «Производители» в студии** (`web/studio.html`, `renderProdSprav`) —
  плоский список карточек справа; канвас в этой ветке пуст (рендер канваса —
  только ветка «Товары»). 9 типов производителей в каталоге (сид 8 + созданная
  создателем «Фабрика продовольствия»).
- **Категории:** 19 — 6 ресурсных (Минералы, Органика, Редкие, Топливо, Вода,
  Газы) + 13 товарных (продовольствие, топливо, конструкционные материалы,
  химикаты, полимеры, комплектующие, детали, медикаменты, товары быта,
  оборудование, оружие, броня, корабли и модули).
- **Модель каталога** (миграция 000048): `producer_types` (name, name_norm,
  kind goods/items/energy, category_id, race_family, output, input, params,
  status) — поля «базовый тип»/родителя НЕТ; `items` (типы предметов);
  `producer_items` (связи лаборатория → предмет).
- **Текущие лаборатории:** «Лаборатория исследовательская» (Чертёж +
  Сертификат анализа), «Лаборатория корабельных модулей» (Модуль корабля),
  «Лаборатория инструментов игрока» (Кирка).
- **Семейства рас** — в модели есть `race_family` (F1–F10 / NULL =
  универсальный), поле в попапе типа производителя («семейство рас»),
  фильтра по семейству в списке нет.
- Канвас товаров — образец: уровни-ряды, карточки, рёбра, клик = выбор,
  попап детали; референс для дерева построек.

## 2. Решения создателя (2026-09-21)

1. **Дерево — на канвасе** в ветке «Производители», как граф товаров
   (уровни, карточки, рёбра, попап детали по клику).
2. **Структура (4 уровня):**
   ```
   Строения
   ├── Производители товаров (kind=goods)
   │   ├── Поселение (тип)
   │   ├── Фабрика (тип)
   │   │   ├── Фабрика продовольствия   (подтип, категория продовольствие)
   │   │   ├── Фабрика топлива          (подтип, категория топливо)
   │   │   └── … по категориям товаров (АВТОМАТИКА)
   │   ├── Автофабрика (тип) — раскрытие по категориям: развилка дизайна
   │   └── Добывающая платформа (тип) — раскрытие по категориям ресурсов: развилка
   ├── Производители предметов (kind=items)
   │   └── Лаборатория (тип)
   │       ├── Лаборатория космических технологий  (подтип)
   │       ├── Лаборатория экипировки              (подтип)
   │       └── Исследовательская лаборатория       (подтип)
   ├── Производители энергии (kind=energy)
   │   └── Энергостанция (тип)
   └── Другие (задел; типы появятся позже)
   ```
3. **Признак родителя:** у записи подтипа — поле «базовый тип» (ссылка на
   родителя). «Да, всё верно» (создатель).
4. **Лаборатории — переименовать** в новые имена (создателю нравятся больше):
   - «Лаборатория корабельных модулей» → **Лаборатория космических технологий**
     (производит «Модуль корабля»);
   - «Лаборатория инструментов игрока» → **Лаборатория экипировки** (производит
     «Кирка»);
   - «Лаборатория исследовательская» → **Исследовательская лаборатория**
     (производит «Чертёж» + «Сертификат анализа»).
   Связи `producer_items` сохраняются по смыслу (маппинг выше — подтвердить на
   гейте).
5. **У Фабрики уровень по категориям товаров — автоматика:** раскрываются все
   категории товаров (13), даже если фабрика ещё не заведена (узел-приглашение
   «создать»); заведённая запись (напр. «Фабрика продовольствия») — существующий
   узел.
6. **Гейт разработки (2026-09-21, «поехали»):** спека принята к разработке.
   Требование создателя: **переименование типов/подтипов (лабораторий в т.ч.)
   доступно из студии в любой момент и НЕ ломает связи** (связи по id —
   producer_items/goods_slots, меняется только name/name_norm). Переименование в
   попапе — существующее (startProdRename/commitProdRename), сохранить для
   новых узлов дерева. Решение по видимости расы (звоночек С3) — по умолчанию
   **«своё + универсальное»**: раса R видит race_family IS NULL OR
   (race_family = family(R) AND race IS NULL) OR race = R (создатель не возразил,
   может поменять на приёме).
7. **Семейства и расы — ДВА уровня (уточнение создателя 2026-09-21):**
   - **Семейство** (F0–F10; в проекте 10 семейств био F0–F9 + F10 роботы, каталог
     `config/races.json`, док `22_races.md`) — верхний уровень расовости.
   - **Раса** (60 рас каталога: 50 био + 10 роботов) — нижний уровень: в одном
     семействе расы сильно различаются (F1: люди и океаниды-водные), у каждой
     свои цепочки производств и свои названия фабрик («Улей» у роя — раса
     sulfur_swarms и пр.).
   - В модели каталога сейчас только `race_family` (F1–F10 / NULL =
     универсальный). Нужен второй уровень — привязка к конкретной расе
     (например `race` TEXT NULL REFERENCES races, или расширение race_family до
     «семейство И раса»). Развилка для дизайна: как хранить (два поля
     race_family + race / одно поле с идентификатором расы / иерархия).
   - Дерево построек показывается для выбранного уровня расовости:
     универсальное (NULL) → семейство (F1–F10) → конкретная раса. Дизайн
     переключателя/фильтра — на @designer (варианты на гейт).
   - Расовая типизация: названия фабрик и цепочки — данные каталога
     (свои записи producer_types на расу/семейство), не код.

## 3. Развилки для дизайна (не блокеры, решает @designer + гейт)

1. **Автофабрика:** раскрывается ли по категориям товаров (как Фабрика)?
   По спеке — вид типа kind=goods; корзина роботов. Развилка.
2. **Добывающая платформа:** раскрывается ли по категориям ресурсов (Платформа
   минералов, Платформа органики…)? Сырьё = kind=resource, категории ресурсные.
3. **Узел «Строения» и классы «Производители товаров/предметов/энергии»:**
   фиксированные (не редактируются) — подтвердить.
4. **«Другие»** — показывать пустой веткой (задел) или скрыть до появления
   типов.
5. **Автоматика категорий:** узел-приглашение «создать» — что происходит по
   клику (создаётся запись producer_types с category_id и базовым типом?).
6. **Переименование лабораторий** — маппинг связей с предметами (см. §2 п.4),
   подтверждение на гейте; старые имена в сиде/БД → новые (миграция данных или
   UPDATE в студии).
7. **Хранение расовости двух уровней** (семейство + раса): два поля
   (race_family + race) / одно поле / иерархия — варианты на гейт. Источник
   списков: `config/races.json` (60 рас, семейства F1–F10) — как студия их
   получает (конфиг сервера / БД / API).
8. **Переключатель уровня расовости в дереве** — варианты UI на гейт.
