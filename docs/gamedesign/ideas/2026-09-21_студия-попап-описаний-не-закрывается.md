## 0. Пожелание создателя (2026-09-21, дословно)

> «у меня висит табличка "описания ИИ (1 из 1). крестик и отмена - не работают,
> при клике вне попапа он пропадает, но при обновлении снова появляется».

## 1. Факты (диагностика менеджера, 2026-09-21)

Замер сервера (`GET /studio/api/state`, учётка skycomposer):

- ИИ-джоб **не идёт**: `generating=false`, `desc_generating=false`;
- `desc_total=1`, `desc_done=1`, **`desc_proposals=1`** — висит неприменённый
  набор предложений на одну запись;
- описаний нет ни у одной записи каталога (134/134 пусто) — терять нечего.

Живой прогон в headless Chrome (`tools/e2e/tmp-desc-popup-probe.js`, временный):

| проба | результат |
|---|---|
| при загрузке | попап открыт (`display=flex`), предложений 1; `z-index` попапа 11 > оверлея 10 |
| клик по крестику | **закрывается** (`display=none`), оверлей снят |
| +4 с (один цикл авто-опроса 3 с) | **остаётся закрытым** |
| перезагрузка страницы (F5) | **открывается снова** |
| клик вне попапа | закрывается, в течение сессии не возвращается |
| «Отмена» при простое | попап остаётся, предложений по-прежнему 1, **отчёта/тоста нет**, JS-ошибок нет |

**Вывод:** крестик и клик вне работают; застревает не попап, а **набор
предложений**. Причина — сочетание двух решений:

1. авто-открытие попапа на любой непустой набор при загрузке страницы
   (`fetchState`, блок 460–473) — задумано спекой §9.4;
2. «Отмена» при простое **не очищает набор** (И7: «отмена сохраняет
   предложения»), а `cancel` без активного прогона вообще ничего не меняет → у
   пользователя нет выхода, кроме «Применить принятые» (внести описание).

Дополнительно зафиксировано: запуск нового прогона затирает прежний набор
предложений (за 26 минут до этого в состоянии было 105 предложений из 134 —
после одиночного прогона осталось 1 из 1). Данные не потеряны (описаний не было
ни у кого), но поведение стоит знать.

## 2. Что чиним

Набор предложений должен быть **разрываемым**: пользователь может отказаться от
набора целиком, и тогда попап закрывается и больше не всплывает.

## 3. Решение создателя (2026-09-21) — «Выбрасывать»

Вопрос менеджера: «что должна делать „Отмена“ — выбрасывать весь набор
предложений (попап уходит и больше не всплывает) или оставить как решено раньше
(отмена сохраняет предложения) и починить только навязчивое открытие?»
Ответ создателя: **«выбрасывать»** (принята рекомендация менеджера).

**Итоговое правило (§9.5 И7 уточняется):**

- **Прогон идёт** → «Отмена» = остановить прогон, **предложения сохраняются**
  (как было).
- **Прогон не идёт** → «Отмена» = **отказаться от набора**: предложения
  выбрасываются на сервере, попап закрывается и не открывается заново (набор
  пуст), пользователю — понятный отчёт.
- Авто-открытие попапа на непустой набор при загрузке страницы **остаётся**:
  пустого набора не будет, всплывать нечему.

## 4. Объём правки (ТЗ разработчику)

- **Сервер** (`internal/handlers/studio_handlers.go`): `POST
  /studio/api/descriptions/cancel` при **отсутствии** активного прогона —
  очистить набор предложений и связанные поля состояния (как это делает
  применение/новый прогон), вернуть признак отказа рядом с существующим
  признаком остановки (контракт сохранить: старое поле `cancelled` не ломать).
  При активном прогоне — как было: стоп + предложения целы. Мутации — под тем
  же флагом одного ИИ-джоба (И6).
- **Клиент** (`web/studio.html`, `cancelDesc`): закрыть попап и показать
  понятный отчёт («набор предложений отброшен» / «прогон остановлен,
  предложения сохранены») — сейчас при простое не происходит вообще ничего
  видимого, это и читается как «кнопка не работает».
- **Тесты (TDD):** cancel при простое → предложений нет, набор пуст; cancel при
  активном прогоне → прогон остановлен, предложения сохранены. Клиент —
  браузерным смоуком (шаги: открыть попап → «Отмена» → попап закрыт, предложений
  нет, после F5 не всплывает).
- **Не трогать:** зоны других задач в рабочем дереве (`web/static/js/surface/*`,
  `docs/specs/README.md`).
