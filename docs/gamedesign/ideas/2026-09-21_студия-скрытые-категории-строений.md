## 0. Пожелание создателя (2026-09-21)

> «Добавить возможность проставить флаг "скрытая" категории строения. По той же
> логике привязки к расам (у некоторых рас некоторые категории будут скрыты, а
> их функции возьмут на себя другие ветки) + галка "показать скрытые".»
> Уточнение: берём **после** задачи «Люди → F0» (решение создателя 2026-09-21).

## 1. Факты (сверка с кодом, 2026-09-21)

- **Видимость по расам** — `prodVisible(p)` (`web/studio.html`): уровень
  «универсальный / семейство / раса»; учитывает только `race_family`/`race`.
  Понятия «скрытая» (видимость по флагу) **нет**.
- **Категория у подтипа-завода** — записи `producer_types` с `parent_id NOT NULL`
  + `category_id` (инвариант «категория только у подтипов», спека дерева §1.2 п.4).
- **Автоматика категорий** — `prodAutoCategories(t)`: под Фабрикой/Автофабрикой —
  13 товарных категорий, под Платформой — 6 ресурсных; незаведённая категория —
  узел-приглашение «создать».
- У `producer_types` **нет** поля флага скрытия — понадобится новое поле (миграция).

## 2. Что значит «флаг скрытая» (модель, решения создателя 2026-09-21)

- У категории строения (подтипа-завода) — флаг «скрытая» + привязка к расам
  (семейство/раса), как у существующей расовости.
- **Решения создателя (2026-09-21):**
  1. **Скрытость перекрывает общее (вариант б):** скрытая запись на уровне
     расы/семейства прячет категорию именно у этой расы, даже если есть общий
     (универсальный) видимый завод — у остальных рас общий завод виден.
     Приоритет: более конкретный уровень побеждает (раса > семейство >
     универсальный); у расы своя видимая запись — категория показывается.
  2. **Узел-приглашение «создать» скрытой категории не предлагается** на
     уровне, где категория скрыта (иначе скрытие бессмысленно).
  3. **Объём сейчас — только студия/каталог:** видимость в дереве + галка
     «показать скрытые». Влияние на игру (релиз 2 фабрик) — отдельной задачей.
- **Логика:** для выбранного уровня расовости скрытая-для-этой-расы категория
  **не показывается** в дереве (её функции берут на себя другие ветки — возможны
  свои подтипы с своими именами/цепочками).
- **Галка «показать скрытые»** (в шапке ветки «Производители», рядом с
  переключателем расовости) — показывает скрытые узлы затемнёнными с пометкой
  (для администрирования каталога; деталь места/вида — @uidesigner).

## 2a. Переработка модели (решения создателя 2026-09-21, вторая волна)

После первой реализации выяснилось: скрытость на записи-заводе не решает
главный кейс — **скрыть пустой слот** (узел-приглашение категории без записи)
нельзя, не создав запись. Создатель: «да ну, каждый слот создавать чтоб
скрывать. Надо конфигурировать слоты в родительском модуле, а не просто
тянуть всё что видишь».

**Решения создателя (2026-09-21, вторая волна):**

1. **Слоты — конфигурация родителя.** У типа-родителя (Фабрика, Автофабрика,
   Добывающая платформа) настраиваемый список слотов-категорий; дерево
   показывает именно настроенные слоты, а не все 13/6 автоматом. **У каждой
   расы может быть свой конфиг родителя** (свои слоты на семейство/расу).
2. **Наследование.** Универсальная конфигурация слотов — база, видна на всех
   уровнях (как универсальные записи сейчас); семейные/расовые слоты — поверх
   (свои + скрытие поверх базы). «Проще удалить, чем добавить»: расы в основном
   скрывают (переопределяют) категории базы, добавление своих — вторично.
3. **Скрытость живёт на слоте родителя**, не на записи-заводе: флаг `hidden`
   на `producer_types` УБИРАЕТСЯ (одна ось). Скрытый слот прячет и карточку
   уже созданного завода, и слот (приглашение). **Галки «скрытая»
   расставляются из карточки родителя** (попап типа-родителя: список
   применимых слотов категорий с галкой «скрытая» на текущем уровне расовости).
4. Автоматика категорий (`prodAutoCategories` — «тянуть все категории») —
   заменяется конфигурацией слотов; стартовая база = сид слотов (Фабрика/
   Автофабрика — 13 товарных, Платформа — 6 ресурсных, универсальный уровень),
   поведение по умолчанию равно текущему.
5. Правило видимости «самая конкретная применимая запись решает», три состояния
   узла, галка «показать скрытые», затемнённые карточки — СОХРАНЯЮТСЯ,
   переносятся с записей на слоты.

## 3. Развилки (решения создателя 2026-09-21)

1. **Где живёт флаг:** новое поле `hidden` (BOOL) у `producer_types`. Скрытость +
   расовость — существующая привязка family/race записи. **Решение: вариант (б)**
   — скрытость перекрывает общее (см. §2 п.1).
2. **Скрытая — атрибут записи-подтипа** (`producer_types`), не самой категории
   (`categories`) — категории общие (19), скрытость расово-зависима. **Решение: да.**
3. **Галка «показать скрытые»** — в шапке ветки (рядом с переключателем
   расовости), скрытые узлы затемнённые с пометкой. **Решение: да** (деталь
   раскладки — @uidesigner).
4. **«Функции возьмут другие ветки»** — визуальное скрытие + правило узла:
   скрытая категория не показывается и её узел-приглашение «создать» не
   предлагается на уровне, где скрыта. **Решение: да** (п.2 ответа).
5. Скрытые категории в game-логике (релиз 2 фабрик) — скрытость влияет только
   на каталог/студию сейчас. **Решение: пока да** (п.3 ответа; влияние на игру —
   отдельной задачей).

## 4. Архитектурный фильтр (переработан под модель слотов)

**Новая таблица `producer_slots`** — конфигурация слотов родителя: реальное
отношение (родитель × категория × расовость × флаг скрытости), не «один
атрибут» (правило «сущность с двумя экземплярами — не сущность» здесь НЕ
нарушается: у каждого родителя много слотов, слоты — конфигурация, не лог).

- **Природа:** состояние/конфигурация (настроенный список слотов-категорий
  родителя), не происшествие.
- **Владелец:** у многих — каждый родитель (тип kind=goods с раскрытием) имеет
  свои слоты; расовость — существующие family/race.
- **Расширяемость:** любое число слотов, категорий, уровней расовости; вторая
  ось (напр. «слот скрыт/активен») ложится колонкой в ту же таблицу.

**Миграция:** > 000051 (свободный 000052): создание `producer_slots` +
data-миграция (сид слотов универсального уровня для Фабрики/Автофабрики/
Платформы из текущей автоматики). Колонка `hidden` у `producer_types` из
первой итерации — снимается (та же миграция: drop, т.к. фича не релизнута).
Затрагивает: студию (UI: дерево, карточка родителя с галками слотов, попап,
список), API (`studio_handlers.go` — state/POST/PUT слотов), репозиторий
(`producer_repository.go`), сид, impact map (`producer_types` + новая
`producer_slots`), `docs/DB.md`, спеки дерева/фабрик (дельта автоматики §2.2,
скрытости §2.4). Числа баланса нет.

## 7. Ретроспектива (бюджет итераций превышен 2026-09-21)

**Корень зависания:** фикс SQL-параметров (DELETE слота, 500 «could not determine
data type of parameter $3») проверялся не тем инструментом: разработчик
валидировал psql-PREPARE с типизированными параметрами и sqlmock-тестами, а 500
даёт кодирование untyped NULL именно драйвером lib/pq в предикате с
`IS NULL`/`IS NOT NULL`; ни psql, ни sqlmock типы параметров драйвера не
проверяют. Два подряд фикса (`interface{}`, затем `sql.NullString`) не
воспроизвели ошибку — критерий «проверено на живой БД» не покрыл реальный путь
(API через lib/pq).

**Предлагаемая дельта в `.opencode/agents/developer.md`:** «Правки, меняющие
SQL-параметры (NULL-типизация, предикаты IS NULL/IS NOT NULL, параметры через
Valuer), проверяются ЖИВЫМ вызовом API на поднятом сервере (curl/браузер), а не
только go test/sqlmock/psql-PREPARE: sqlmock не проверяет типы параметров, psql
не воспроизводит кодирование драйвера (lib/pq).»
