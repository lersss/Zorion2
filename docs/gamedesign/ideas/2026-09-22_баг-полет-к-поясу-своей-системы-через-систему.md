# Баг 🔴 — полёт к поясу «своей» системы предлагается «через систему» и падает

**Дата:** 2026-09-22
**Вектор:** Баги (полёт/модалка/пояса)
**Приоритет:** 🔴 — блокирует полёт к поясу в системе, где игрок уже находится
**Вектор/линия:** пояса этап 2 (показ/знание/полёт) + композитный маршрут 99.2.30

## Пожелание/баг создателя (дословно)

> «лететь через систему к поясу койпера в Krabaltar (58, 135) - already in this system»

## Что происходит

Кнопка у пояса в модалке показала **«🚀 Лететь · через систему»** (композитный маршрут,
`data-belt-composite-fly`), хотя игрок **уже в этой системе**. Клик → сервер вернул
**«Already in this world»** (400), полёт не стартовал.

## Разбор (факты по коду, приёмная 2026-09-22)

- Сервер (`internal/handlers/travel_handlers.go:364`) отдаёт `"Already in this world"`,
  если `req.WorldID == user.current_world_id` (цель = текущий мир).
- Клиент определяет «своя система» по `modalState.myPosition != null`:
  `panel.js` (`inOwnSystem = !!myPos`), `events.js`, `tabs.js`, `textures.js`.
- Сервер отдаёт `my_position` **только** если `current_world_id == worldID` **и**
  `travelMgr.GetFlight(userID) == nil` (`internal/handlers/planet_handler.go:118-119`).
  Во время межзвёздного полёта позиция `NULL`.
- **Итог:** есть состояния, когда игрок в системе (`current_world_id == worldID`), но
  `my_position` не приходит → клиент считает систему **чужой** → показывает композитную
  кнопку → сервер справедливо отвечает 400. То есть «своя система» определяется
  **косвенным признаком**, который ломается.

## Что нужно

- **Корень:** клиент не должен выводить «своя система» из наличия `my_position`.
  Нужен **явный признак** (например, флаг `in_own_system`/`is_own` в ответе планет
  системы, либо сравнение `worldId` с текущим миром игрока из `/me`), а кнопка пояса
  (и планет/спутников — та же логика) — по этому признаку.
- **Проверить:** не 400-ить, если игрок уже в системе и цель внутри неё — корректный
  ответ/деградация во **внутрисистемный** полёт (а не ошибка), как минимум — понятное
  сообщение.
- **Регресс-тест** на состояние «в системе, но `my_position` пуст» (напр. игрок в
  межзвёздном полёте / битая позиция).
