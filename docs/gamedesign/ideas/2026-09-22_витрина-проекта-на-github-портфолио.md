## 7. Найдено при работе: красная сборка в чистой копии (2026-09-22)

**Факт.** После пуша витрины CI на GitHub дал failure на шаге Build (`go build ./...`),
при этом локально сборка зелёная. Воспроизведено в чистой копии `origin/master`
(`git worktree add --detach <tmp> origin/master; go build -C <tmp> ./...`):

```
# zorion/internal/handlers
internal/handlers/admin_universe.go:631:38: undefined: repository.ResolveDefaultSettlementTypeID
```

**Причина.** Функция `ResolveDefaultSettlementTypeID` определена в
`internal/repository/economy_repository.go` — файле **незакоммиченной** работы
параллельной задачи «экономика поселения — итерация 4», а вызывается она из
**закоммиченного** `internal/handlers/admin_universe.go:631` (и ещё из
`admin_hypothesis.go:103`, `internal/generator/settlement/*`). Локально вызов
резолвится, потому что файл с функцией лежит в рабочем дереве; в CI и в свежем
клоне — нет. Ловушка не в моей зоне: чинить должен владелец той задачи.

**Дельта в `docs/PITFALLS.md`** (применять после снятия чужих незакоммиченных правок
в этом файле; адрес — владелец блока `ShipNegBackground`/`ShipNegRace`):

> `docs/PITFALLS.md`: + ловушка «Зелёная локальная сборка ≠ собирается чистая копия.
> Если вызов из закоммиченного файла ссылается на функцию/тип из **незакоммиченной**
> правки чужого пакета, `go build ./...` локально проходит, а CI и любой свежий клон
> падают (`undefined: repository.X`). Перед пушем проверять сборку в чистой копии:
> `git worktree add --detach <tmp> origin/master; go build -C <tmp> ./...`, после —
> `git worktree remove <tmp>`.»
