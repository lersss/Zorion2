### 2.3. ЧП4 — тесты на настоящей БД (design решён 2026-09-22)

Проверено фактами: пользователь БД `zorion` не имеет права создавать базы (`rolcreatedb=f`) и не суперпользователь; **но схему создавать может** (`CREATE SCHEMA`/`DROP SCHEMA CASCADE` — работает). В SQL-миграциях привязки к `public` нет — только в Go-коде `migrations.relationExists` (`to_regclass('public.' || $1)`).

**Решение:**
1. Правка `migrations/migrations.go`: `relationExists` → `SELECT to_regclass($1) IS NOT NULL` (без префикса `public.`). При дефолтном `search_path` (`"$user", public`) поведение эквивалентно; открывает запуск в отдельной схеме.
2. Новый пакет **`internal/integration`** (только тестовые файлы; вне `internal/repository`, чтобы чужая поломка соседнего теста не блокировала компиляцию).
3. Хелпер: URL из `TEST_DATABASE_URL`, иначе `DATABASE_URL`; нет URL / нет соединения → `t.Skip` (обычный `go test` остаётся зелёным). Создаёт схему `zorion_it_<rand>`, открывает соединение с `options=-csearch_path=...`, накатывает `migrations.Apply`, в конце `DROP SCHEMA ... CASCADE`.
4. Сценарии:
   - `миграции на пустой схеме` — Apply проходит, повторный Apply ничего не делает;
   - `жизненный цикл контракта с эскроу` — публикация (залог заперт, операция по счёту) → взятие → закрытие (залог освобождён); проверка балансов/статусов/лога;
   - `гонка взятия` — два параллельных взятия одного контракта → успех ровно у одного (атомарный flip);
   - `просрочка` — taken с истёкшим сроком → лог `failed`, залог возвращён автору.
5. Ограничение: на dev-схему `public` ничего не запускать; только scratch-схема. В CI тесты скипаются (нет БД) — это осознанно.
