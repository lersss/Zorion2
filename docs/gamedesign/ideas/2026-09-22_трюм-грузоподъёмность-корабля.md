# Трюм — грузоподъёмность корабля (фундамент под добычу и перевозки)

**Дата:** 2026-09-22
**Вектор:** Игрок (инвентарь/груз, корабль) · Новые механики (будущие потребители: перевозки, торговля)
**Статус:** ✅ реализовано 2026-09-22 (коммит `bdc76c7`), принято создателем. Трюм — врождённая ёмкость 20 т + грузовой модуль 80 т в универсальном слоте, содержимое (таблица `player_cargo`), жёсткий предел, «груз за борт», чтение + блок «Трюм» на дашборде; миграция `000068`. `@reviewer` — без блокеров (3 мелких внесены), `@tester` — 12/12 PASS.
**Предыстория:** трюм назван **предусловием** «куда идёт добытое» в идее добычи в поясе малых тел (`docs/gamedesign/ideas/2026-09-21_добыча-в-поясе-мини-игра.md`), с оговоркой «потребитель шире добычи — контракты, торговля, перевозка». Вынесен **отдельной задачей** решением создателя 2026-09-22 (сначала трюм, потом мини-игра пояса).

## Пожелание (дословно, создатель)

> «дизайн трюма»

## Решения создателя (2026-09-22, ответы на приёмке)

1. **Ёмкость: врождённая (небольшая) + универсальные слоты.** У корабля есть **врождённая** небольшая грузоподъёмность; сверх неё ёмкость набирают **грузовыми модулями в универсальные слоты**. Пока у корабля **один универсальный слот** («пусть пока 1 будет на корабле»).
2. **Пока ограничение по тоннажу (масса).** В будущем масса и объём — **разные ограничения** («думаю в будущем это точно будут разные штуки»); сейчас — только тонны. Данные уже заведены: у товаров/ресурсов в каталоге есть и **вес**, и **объём**.
3. **Объём задачи — необходимый минимум** (не тащить всю логистику сразу).
4. **Хранилище содержимого — отдельная таблица** (не поле внутри игрока).

## Ориентир: как в X4 (создатель просил посмотреть)

X4 Foundations: грузоподъёмность корабля — в **объёме (м³)**; у груза — «тип хранения» (Container / Solid / Liquid / Condensate), корабль везёт только свой тип; отдельно у корабля есть **масса (т)**. Вывод для Zorion: X4 разводит **объём** и **тип груза**; создатель хочет в будущем тоже развести **массу и объём**, **сейчас — только масса**. «Тип груза» (твёрдое/жидкое/…) — кандидат на будущее, в текущий минимум **не входит**.

## Архитектурный фильтр (предложение менеджера, подтверждено создателем)

- **Природа:** состояние (накопленный груз) — не событие и не лог.
- **Владелец:** один на игрока (один корабль = один трюм).
- **Расширяемость:** разных товаров/ресурсов много → **таблица записей** «игрок → товар → количество» (не JSONB-поле в игроке). Решение создателя №4.
- **Ёмкость:** врождённая — параметр **модели корабля**; модули — тип оборудования `cargo` с `params.capacity`, ставится в **универсальный** слот.
- Товары/ресурсы уже несут вес и объём в каталоге (`goods.weight` / `goods.volume`, миграция `000048`) — **новых полей у груза не надо**; сейчас используется только вес.

## Скоуп (необходимый минимум — предложение менеджера; уточняет дизайнер)

- Ёмкость трюма = врождённая ёмкость модели + сумма установленных грузовых модулей (в тоннах).
- Хранилище содержимого — отдельная таблица; чтение/запись через API (нужны потребителям).
- Показ в разделе «Корабль» дашборда: занято/всего, что лежит.
- **Не входит:** объём как второй лимит, типы груза, торговля/рынки, погрузка в порту, NPC-перевозчики, собственно добыча в поясе (следующий шаг линии).

## Открытые вопросы (на дизайн) — ✅ все закрыты (см. «Решения создателя на гейте дизайна» ниже)

- Базовая (врождённая) ёмкость, ёмкость модуля(ей), число уровней модулей и их связь с «стартовым 100» из исходного пожелания.
- Поведение при перегрузе: жёсткий запрет класть сверх ёмкости — или перегруз с наказанием.
- Единица: тонны; соглашение масштаба веса товара → тонны.
- Нужна ли «выгрузка» в минимуме, или только накопление + API для потребителей.
- Универсальный слот: вводим отдельный тип слота (принимает любые модули) или частный `cargo`-слот сейчас, а обобщение — позже.

## Решения создателя на гейте дизайна (2026-09-22)

1. **Ёмкость:** врождённая **20 т** + стартовый модуль **80 т** = **100 т** суммарно (подтверждено; «пусть так и будет»).
2. **Перегруз — жёсткий** (берём сколько влезет, остаток остаётся на источнике).
3. **Содержимое переживает очистку вселенной** + **новое в скоуп: механизм «груз за борт»** (игрок сбрасывает свой груз).
4. **Масштаб веса:** «1 единица = 1 тонна» сейчас; реальные веса товаров — отдельная калибровка позже.
5. **Эталон пересмотрен:** тех-характеристики корабля (грузоподъёмность) входят в скоуп — «приходим уже к далёкому будущему» (дельта в `21_ships.md`).
6. **Грузовой модуль — тестовый;** позже производится в лабораториях корабельного оборудования (до них ещё дойдём); сейчас просто выдаётся стартовым набором.
7. **Удаление ресурса из каталога уносит груз — риск принят;** главное — трюм (состояние игрока) вайп переживает.

## Зависимости

1. Модель корабля/оборудования (77a: `ship_models`, `equipment`, `users.equipment`) — расширяем (новый тип оборудования + слот).
2. Каталог товаров (`goods.weight`/`goods.volume`, 000048) — данные груза.
3. Контракты (требование-окно «трюм N т», `contract_requirements.threshold_text`) — будущий потребитель.
4. Добыча в поясе (этап 3 поясов, `2026-09-21_добыча-в-поясе-мини-игра.md`) — **первый потребитель**.
