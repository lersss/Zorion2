## Пожелание (создатель, 2026-09-23)

> «привязать их [корабли рас] к расам, агентов раскидать тоже по расам, старые
> корабли убрать из игры, и новые созданные агенты чтобы рассаживались на
> корабли своих рас»

Уточнения создателя (раунд, 2026-09-23):
1. **Корабль игрока — тоже по расе.** Пока что игрок = **человек** (раса `humans`).
2. **Агенту — своё поле расы.** «При генерации раскидывать рандомно».
3. **Хоумворлд агента = мир расы** — где эта раса живёт (кластер).
4. **Старые 21 корабль — всё пересоздаём**, игрокам проставить людей.
5. **Люди ×4 типа** — тип корабля человеку выдаётся **случайно**, как и остальным расам.

## ✅ Источник «мира расы» уже есть (найдено 2026-09-23, чужая работа в master)

Коммит `7966a78` «одна фракция на расу со столицей на её родной планете» даёт
**готовую связь раса → родная планета**:
- `factions.race_id` (миграция `000066`, уже в master) — одна фракция на расу;
- `factions.homeworld_id` — **родная планета расы** (её поселение с наибольшим
  населением; tiebreak — меньший `planet_id`, детерминированно;
  `internal/generator/faction/faction.go::GenerateFactions`);
- `buildings(building_type='capital', owner_type='faction', owner_id=faction)` —
  столица фракции на родной планете.

**Следствие для агентов:** хоумворлд агента = `factions.homeworld_id` его расы
(через `factions.race_id`). Новую связь/таблицу «мир расы» **не изобретать** —
брать из фракций (правило «что бывает — каталог, что стоит — buildings»,
COORDINATION.md). Открытый вопрос «если у расы несколько миров — какой брать»
снят: берём `factions.homeworld_id`.

**Агенты (`npc_agents`):** наблюдатели, `current_world_id`/`from`/`target` — миры; **расы и корабля у них нет**. Корабль агента на клиенте — `spriteForAgent(agent_id)` (FNV-1a % 21) по 21 старому спрайту (`web/static/js/map/ship_sprites.js`, `npc_agents.js`).

**Игрок (`users`):** `ship_icon` из того же реестра 21; выбор в профиле; `LegacyShipIconMap` (21 SVG→PNG), `DefaultShipIcon = crescent.png`; `ShipSprites` (24 = 21 легаси + 3 люди) — `internal/models/ship_sprites.go`.

**Раса в мире:** у `settlements.race_id` (000039, NULL = люди/динозавры), у `factions.race_id` (000066 — **чужая незакоммиченная работа!**). У `worlds`/`planets` прямой расы нет — раса мира читается через поселения/фракции (кластеры рас генерирует задача «расовые поселения», `config/race_settlement.json`).

**Легаси к выпилу:** `ShipSprites` (21 запись + 3 люди), `LegacyShipIconMap`, `DefaultShipIcon`, `spriteForAgent` (клиент), 21 PNG в `web/static/sprites/`, `ship_options` в `/me`.

## Суть (что делаем)

1. **Перенести расовые корабли в игру:** 129 PNG → `web/static/sprites/` (или отдельный каталог `web/static/sprites/races/`), реестр `ShipSprites` → расовый (по слагам + типы людей).
2. **`npc_agents.race_id`** (новая колонка) — раса агента; при генерации раскидывается **рандомно** по 60 расам.
3. **Хоумворлд агента** = мир, где его раса живёт (кластер расы). Связь: раса агента → кластер/поселения этой расы → мир `homeworld`.
4. **Игрок = человек**: `users.race_id = 'humans'` (бэкфилл/дефолт), корабль по расе (случайный тип из 4).
5. **Выпил 21 легаси:** реестр, маппинг, дефолт, `spriteForAgent`, PNG, `ship_options`; старые `ship_icon` в БД игроков — обработать (миграция на расовый корабль, не сломать).
6. **Рассадка агентов на корабли расы:** клиент рисует агента кораблём его расы (тип — случайно/по правилу), а не случайным из 21.
