## 2. B25 — исправлено

**Корень:** у «ребёнка» планет `player_planet_knowledge` FK заведён без
`ON DELETE CASCADE` (000040:30), в отличие от прочих детей планет. Знание об
удаляемой планете бессмысленно (`planet_id` новый при перегенерации) — должно
чиститься каскадом.

**Правка:** миграция `migrations/000073_planet_knowledge_cascade.sql` —
`DROP CONSTRAINT IF EXISTS` + `ADD CONSTRAINT ... FOREIGN KEY (planet_id)
REFERENCES planets(id) ON DELETE CASCADE`. Код путей удаления не менялся: каскад
закрывает все три пути. Явный `DELETE` пакмана и `TRUNCATE` (`clearUniverseTx`,
таблица уже в `truncateTables`) остаются как есть.

**Проверка (@tester, независимо, 2026-09-23):** в транзакции с `ROLLBACK` удаление
планеты со знанием проходит (`DELETE 1`, знание 0, ошибки FK нет); пересчёт мира —
`DELETE 8`, знание 0; контроль старого поведения воспроизводит исходную FK-ошибку;
тесты `TestClearPlanets`/`TestClearPlanetsOf`/`TestTruncateTables`/`Pacman` и
`go test -race -short` — зелёные. Журнал:
`docs/QA/checklists/2026-09-23_B25-каскад-знания-о-планете.md`.

**Живая проверка (после перезапуска dev-сервера, 2026-09-23):**
`player_planet_knowledge_planet_id_fkey` → `confdeltype='c'` (CASCADE);

## 3. B27 — исправлено

**Корень:** `RestoreIntra` (`internal/travel/intrasystem_manager.go`) в ветке «битая
цель» удалял строку полёта без `onArrival`, но `users.current_position` оставался

**Правка:** в `RestoreIntra` добавлен колбэк `resetPosition(userID, worldID)`,

**Проверка (@tester, независимо, 2026-09-23):** свой тест-сценарий (не тесты

## 3.3. B16 (пресеты генерации) — исправлено

**Корень:** генератор принудительно держит `ClusterSpacing ≥ 2×ClusterRadius`
(`poisson.go:95`), «мягкая» граница гнезда — до `1.25×ClusterRadius`
(`clusterEdgeAccept`). Значит зазор между скоплениями появляется только при
`spacing > 2.5×radius`; почти у всех пресетов (`generation.js`) было `spacing ≤ 2×radius`
⇒ гнёзда касались, поле сливалось в ровную россыпь.

**Правка:** в `web/static/js/admin/generation.js` (`UNIVERSE_PRESETS`) подняты
`clusterSpacing` и `mapSize` так, чтобы зазор `gap = max(spacing, 2·radius, minDist)
− 2.5·radius > 0` при `ratio ≥ 2.6`; `worlds`/`clusters`/`minDist`/`shape`/`outlierPercent`
не менялись. Запас `mapSize` — чтобы все центры скоплений помещались и звёзды
добирались (недобор = 0). Добавлен страж `web/frontend_generation_presets_test.go`
(читает `generation.js`, проверяет `gap > 0`, `ratio ≥ 2.6`).

**Проверка (@tester, независимо, итерация 2):** 280 прогонов (20 цель-наборов × 14
пресетов) — недобора нет, логов «Generated only …» ноль; регрессы `compact` seed=2 →
200/200, `swarm` seed=10 → 300/300; страж не тавтологичен (со старым `spacing` краснеет).
Журнал: `docs/QA/checklists/2026-09-23_B16-пресеты-генерации-кластеры.md`.

**Оговорка:** выбросы (`std = 3×ClusterRadius`) слегка «подсвечивают» зазоры —
контраст ≈50×, пустоты читаются, но абсолютной пустоты нет (поведение выбросов,
пресетами не лечится; отдельная задача вне скоупа). Галактики стали крупнее
(`mapSize` +~30–45 %), иначе скопления не разъехались бы.
