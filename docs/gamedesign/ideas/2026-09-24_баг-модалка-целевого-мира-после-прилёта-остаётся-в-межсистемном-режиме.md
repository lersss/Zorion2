**Приоритет:** баг (🔴 — ломает очевидное действие после прилёта)
**Вектор:** **Баги** (зона кода — фронт игрока, модалка системы: `web/static/js/modal/*`)

## Пожелание (создатель, 2026-09-24)

> Лечу с другого мира в целевой, в это время у меня открыта вкладка целевого мира.
> после прилёта, не закрывая модалки целевого мира, когда пытаюсь переместиться
> внутри, пишет «используйте внутрисистемный полёт», что-то такое

Уточнение создателя: полёт — **обычный межзвёздный к звезде** (не композитный
маршрут «через систему»); модалку целевого мира открыл **кликом по этой звезде на
карте уже во время полёта**.

---

## Воспроизведение

1. Игрок в мире A. На карте стартует межзвёздный полёт к звезде B.
2. Во время полёта кликает по звезде B на карте — открывается модалка системы B.
3. Ждёт прилёта, **не закрывая** модалку.
4. В модалке жмёт «🚀 Лететь» на планете/спутнике/компаньоне (или кнопку карточки).
5. Ответ сервера: `400 «Вы уже в этой системе — используйте внутрисистемный полёт»`.

---

## Диагноз (по коду, прослежено)

Модалка, открытая во время межзвёздного полёта, запоминает два признака, и оба
остаются устаревшими после прилёта:

- `modalState.inOwnSystem` — из ответа `/api/worlds/{id}/planets`
  (`in_own_system`): на момент открытия полёт ещё шёл, значит `false`;
- `modalState.interstellarFlight` — из `/me` (`me.flight`): активный полёт, значит
  `{...}` (не null).

Режим кнопки полёта задаёт `flightModeForSystem()` (`modal/state.js`):
`'intra'` только если `inOwnSystem && !interstellarFlight`, иначе `'composite'`.
Пока оба признака устаревшие — режим навсегда `'composite'`.

**Дырка 1 (главная для пути 1) — модалка не обновляется по прибытии межзвёздного
полёта.** Авто-обновление модалки в rAF-тике (`modal/index.js`, ~строка 707)
срабатывает только когда `myPosition.status === 'in_flight'` (внутрисистемный
сегмент). При межзвёздном полёте `my_position` = `null`, поэтому тик ничего не
обновляет. Карта своё прибытие распознаёт (`map/animation.js` → `loadUserData` →
`checkCompositeArrival`), но `checkCompositeArrival` в этом сценарии выходит
**раньше**: нет ни `pending_destination`, ни позиции `in_flight`, ни сессионного
маркера `compositeRoute` (обычный полёт к звезде — не композитный маршрут). Модалку
никто не трогает, она остаётся с устаревшими `inOwnSystem=false` и
`interstellarFlight != null`.

**Дырка 2 (проявится, если дырку 1 закрыть «в лоб»).** Даже когда модалка
обновляется (например, композитный путь: `checkCompositeArrival` → `refreshPlanets`),
`refreshPlanets()` перечитывает планеты и обновляет `inOwnSystem`/`myPosition`, но
**не сбрасывает `interstellarFlight`**. Тогда `flightModeForSystem()` всё равно
даёт `'composite'` — кнопка по-прежнему уходит в межсистемный запрос → тот же 400.

Итог: симптом у обоих путей один — после прилёта кнопка «Лететь» внутри системы
работает как межсистемная и получает 400.

Сервер, данные, баланс, API — ни при чём; правка только на клиенте модалки.

### Замеченная зацепка (для исполнителя, не требование)

Сервер по прибытии межзвёздного полёта одним UPDATE ставит
`current_world_id = B` и позицию «орбита звезды B» (`travel_handlers.go`,
`ArrivalHandler`, ИП-2). То есть свежий ответ `/api/worlds/{id}/planets` после
прилёта уже отдаёт `in_own_system = true` и `my_position = {status:'orbit',
object_type:'star'}`. А во время межзвёздного полёта позиция всегда `null` (С1:
старт `/travel` NULL-ит позицию). Значит признак «уже не в межзвёздном полёте»
выводится и из данных модалки — но только если её вообще перечитать (дырка 1).

---

## Предложение по фиксу (что должно быть на выходе)

**Зачем:** после прилёта игрок, не закрывая модалку целевого мира, сразу может
лететь внутри системы — кнопка «🚀 Лететь» должна стать внутрисистемной сама.

Что должно быть на выходе (способ — на усмотрение исполнителя):

1. Модалка, открытая во время межзвёздного полёта, **по прибытии обновляет своё
   состояние** — как минимум признак «в полёте» (`interstellarFlight`) и данные
   системы (`inOwnSystem`/`myPosition`). После этого `flightModeForSystem()` даёт
   `'intra'`, и «Лететь» уходит во внутрисистемный старт (`POST
   /api/intrasystem-flight`), а не в `/travel` с `destination`.
2. Работает **без закрытия модалки** и для обоих путей: обычный полёт к звезде
   (путь 1) и композитный маршрут (путь 2).
3. Кнопка «Обновить» в модалке тоже не должна оставлять устаревший режим полёта.

**Рамки:** только клиент (`web/static/js/modal/*`, `web/static/js/map/*`);
серверные контракты, схема БД, числа баланса не тронуты.

## Реализация (что сделано)

Механизм выбран создателем 2026-09-24: **событие прилёта карты** вместо
периодического сканирования — карта и так сама ловит прилёт межзвёздного полёта.

1. `web/static/js/map/data.js`, `checkCompositeArrival`: если модалка уже открыта
   на системе прибытия — `refreshPlanets()` (срабатывает и **без** признаков
   композитного маршрута; авто-открытие модалки по-прежнему только для
   композитного пути — простой полёт модалку сам не открывает).
2. `web/static/js/modal/index.js`, `refreshPlanets`: вызов
   `clearArrivedInterstellarFlight()` после обновления `inOwnSystem`/`myPosition`.
3. `web/static/js/modal/state.js`, `clearArrivedInterstellarFlight()`: снимает
   `interstellarFlight`/`interstellarFlightName`, когда сервер отдал
   `in_own_system` и позицию orbit/surface (не `null` — идёт межзвёздный сегмент;
   не `in_flight` — идёт внутрисистемный, в т.ч. композитный редирект).
4. Страховка для страницы без карты (админка; сценарий достижим —
   `web/static/js/admin/worlds.js` открывает модалку системы): **один**
   `setTimeout` на `start_time + duration`
   (`scheduleInterstellarArrivalFallback`), не скан; на карте не планируется;
   снимается в `resetState`.

Ежесекундного сравнения времени в цикле модалки нет (было в первой версии —
убрано по решению создателя).
