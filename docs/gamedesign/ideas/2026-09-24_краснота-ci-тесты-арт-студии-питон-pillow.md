## 1. Диагноз (две независимые Linux-причины)

CI-джоб `build · vet · gofmt · tests (race, short)` падал на шаге **Tests** (Build/Vet — зелёные; шаг Format — предупреждающий, не блокирует). Локально на Windows всё было зелено, поэтому краснота не замечалась.

**Как локализовано (лог CI закрыт авторизацией):**
- прогнан CI-эквивалент в **чистой копии на коммите CI** (`668a0bc`) — на Windows всё зелёное → в закоммиченном коде падений нет, дело в среде Linux;
- кросс-компиляция, `go vet` под Linux и сборка тест-бинарников под Linux — чистые (значит, не компиляция, а среда исполнения);
- сверено с составом образа ubuntu-latest: `Node.js 22`, `Python 3.12.3`, пакет `python-is-python3` (команда `python` есть), Pillow/numpy/scipy — нет.

### Причина №1 — Pillow у python (пакет `cmd/art-studio/generator`)

Пиксельные тесты силуэтов кораблей искали python функцией `findPython()`: сначала venv студии `C:\ComfyUI\venv\...`, иначе — **любой `python` из PATH без проверки зависимостей**. На ubuntu venv нет, команда `python` есть, Pillow нет → скрипт `tools/make_ship_silhouettes.py` падал на импорте → `t.Fatalf` → пакет красный. Локально первым кандидатом идёт venv с Pillow — потому зелено.

### Причина №2 (главная) — фейковый python был Windows-батником (три пакета art-studio)

Тесты подменяли python своим фейком, написанным как **командный файл Windows** (`.cmd`: `@echo off`, `copy`, `ping`, `exit /b`). Windows такой файл запускает, Linux — нет (не программа и не скрипт с shebang) → тест получал ошибку → пакет красный. Задеты: джоб кораблей (`generator`), конвейер выреза (`postproc`), обработчики (`handlers`). Причина давняя — CI красный с первого прогона.

## 2. Решение

**Причина №1 — вариант A (одобрен создателем):** правка только тест-кода — `findPython()` отбирает кандидата проверкой `python -c "import PIL"` (ровно нужное скрипту силуэтов), нет зависимости → `t.Skip` (паттерн `findStudioPython` из postproc). Осознанный компромисс: на CI эти проверки пропускаются, локально работают.

**Причина №2 — вариант 2 (одобрен создателем):** вместо «пропускать на Linux» — сделать фейки **рабочими на обеих ОС**. Выбран **паттерн helper-процесс**: роль python исполняет сам тест-бинарник (`os.Executable()`, fallback `filepath.Abs(os.Args[0])`), режим эмуляции — через env (`ART_STUDIO_FAKE_PYTHON` и др.), `TestMain` перехватывает повторный запуск, выполняет эмуляцию и завершает процесс до `m.Run()`. Один код эмуляции на обе ОС, без шелла; поведение фейков сохранено (дамп argv, отчёт кадра, orient-JSON, копия с ретраями, «зависание» для проверки таймаута), ассерты не ослаблены. Прод-код и `ci.yml` не тронуты.

Особенность конструкции: прод-код запускает python через `exec.Command` **без своего `Env`**, поэтому env из `t.Setenv` доходит до дочернего процесса — так ребёнок и узнаёт режим. Записано предупреждением в код и в список ловушек (если джоб-горутина переживёт конец теста, ребёнок без env отработает как полный прогон тестов — job-тесты обязаны дожидаться завершения джоба).
