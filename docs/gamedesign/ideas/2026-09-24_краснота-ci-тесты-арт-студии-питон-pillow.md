# 2026-09-24. Краснота CI: тесты арт-студии звали `python` без проверки Pillow

**Дата:** 2026-09-24
**Пожелание:** «build · vet · gofmt · tests — процесс завершился с кодом 1» — разобраться и починить CI.
**Приоритет:** P1 (шаг «Тесты» красный с самого создания CI — все 52 прогона подряд, включая чисто документационные коммиты).
**Статус:** ✅ закрыто (баг-фикс, вариант A).

## 1. Диагноз

CI-джоб `build · vet · gofmt · tests (race, short)` падал на шаге **Tests** (Build/Vet — зелёные; шаг Format — предупреждающий, не блокирует).

Причина — пакет `zorion/cmd/art-studio/generator` (пиксельные тесты силуэтов кораблей):

- тесты ищут python функцией `findPython()` (`cmd/art-studio/generator/ships_pixel_test.go`): сначала venv студии `C:\ComfyUI\venv\Scripts\python.exe`, иначе — **любой `python` из PATH без проверки зависимостей**;
- на ubuntu-latest venv нет, зато команда `python` есть (образ ставит пакет `python-is-python3`), а **Pillow/графической библиотеки нет** → скрипт `tools/make_ship_silhouettes.py` (импорт `from PIL import Image, ImageDraw`) падал на импорте → `renderShipSpec` вызывал `t.Fatalf` → пакет красный, шаг Tests = exit 1;
- локально (Windows) зелено, т.к. первым кандидатом идёт venv ComfyUI, где Pillow есть.

Соседний пакет `cmd/art-studio/postproc` устроен правильно: `findStudioPython()` проверяет зависимости (`import PIL, numpy, scipy`) и возвращает `""` → тест скипается. Недостающая проверка была только в пакете силуэтов.

**Как локализовано (без лога CI, доступ к нему закрыт):**
- прогнан CI-эквивалент в **чистой копии на коммите CI** (`668a0bc`) — на Windows всё зелёное; подтверждено, что в закоммиченном коде падений нет;
- кросс-компиляция и статические проверки под Linux — чистые; сборка тест-бинарников под Linux — чистая (значит, дело не в компиляции, а в среде исполнения);
- сопоставлено с составом образа ubuntu-latest: `Node.js 22`, `Python 3.12.3`, пакет `python-is-python3` (команда `python` есть), Pillow/numpy/scipy — нет.

## 2. Решение (вариант A, одобрен создателем 2026-09-24)

Правка **только тест-кода** (`cmd/art-studio/generator/ships_pixel_test.go`): `findPython()` отбирает кандидата проверкой `python -c "import PIL"` (ровно нужное скрипту силуэтов), нет зависимости — возвращает `""` → вызывающие тесты делают `t.Skip`. Паттерн — как `findStudioPython` в postproc. Прод-код и `ci.yml` не тронуты.

**Осознанный компромисс:** на CI пиксельные проверки силуэтов теперь **пропускаются** (в образе нет Pillow) — как и проверки выреза кораблей. Локально они продолжают работать.

**Возможное продолжение (вариант B, решение создателя — отдельно):** доустанавливать Pillow (и, при желании, numpy/scipy) в CI, чтобы пиксельные проверки гонялись и на сервере, а не пропускались.
