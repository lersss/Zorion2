## Проблема (факты)

- `docs/PITFALLS.md`: **1420 строк, ~142 КБ, ~35 000 токенов** — один файл.
- Файл **не** в автозагрузке (`opencode.json` → только `docs/AGENT_RULES.md`);
  читается «по требованию». Но при чтении агент тянет **весь** файл — ~35k токенов.
- Разделы (текущие): Введение; Общие; Go и многопоточность; БД и шелл; Фронт и UI;
  Прочее. Разделы-«помойки» («Прочее», «Фронт и UI») растут без чистки; устаревшее
  не убирается.
- Владелец файла — `@developer` (`docs/INDEX.md` §«Владельцы доков»).

## Предложение (что должно быть на выходе)

**Зачем:** агент, которому нужна одна ловушка, читает одну тему (~5–9k токенов),
а не 35k; список перестаёт расти бесконечно.

1. **Разбить по темам** на `docs/pitfalls/` (по факту разделов файла: раздела
   «Общие» не было, оказался «Дизайн и числа»):
   - `db-shell.md` — БД, миграции, shell/инструменты;
   - `go.md` — Go и конкурентность (гонки, `-race`, lock-паттерны);
   - `design.md` — дизайн и числа (событие vs лог, инварианты, K/°C);
   - `front-ui.md` — фронт, Canvas, UI, слои, модалки;
   - `misc.md` — прочее.
2. **`docs/PITFALLS.md` сделать тонким оглавлением:** введение, правила ведения, и
   по одной короткой строке на тему + ссылка на файл темы. Дёшево читать; при нужде
   агент идёт в конкретный файл темы.
3. **Чистка при переносе:** устаревшее/дубли/одноразовые записи → в
   `docs/pitfalls/_archive.md` (не читается по умолчанию); спорное — оставить в теме.
4. **Ссылки не должны сломаться.** Часть доков ссылается на ловушки **по номерам
   строк** (напр. `docs/QA/checklists/2026-09-17_70a-tooltip-star.md` — «строки
   314-323»). Такие ссылки при разбивке **перевести на «тема + заголовок/цитата»**,
   а не на строки. Проверить все упоминания `PITFALLS` по репозиторию.

**Границы:** только документы (`docs/PITFALLS.md`, новые `docs/pitfalls/*`); код,
БД, числа — не трогаются. Содержание ловушек не переписывается по смыслу, только
переносится/чистится от устаревшего.

**Зависимость:** делать **после** разбора бэклога незакоммиченных записей в
`docs/PITFALLS.md` (хвост 2) — иначе 9 чужих записей конфликтуют с переносом.
После переноса — закрыть/актуализировать хвосты 1/3/4/20/21/25 (они ждут именно
внесения в список ловушек).

**Судьба хвоста 25** (ловушка про модалку, открытую в межзвёздном полёте): по
разбору 2026-09-24 общий инвариант «"свою систему" не выводить из `my_position !=
null`» **уже записан** (PITFALLS, 2026-09-22, коммит `624771a`), а конкретика бага
живёт в коде комментарием. Рекомендация — хвост 25 **снять как дубль**, отдельную
запись не заводить.

## Этапы (гейт на каждый)

- **Этап 1 — перенос без потери содержания.** Разрезать `docs/PITFALLS.md` по
  разделам в `docs/pitfalls/{general,go,db-shell,front-ui,misc}.md` (раздел
  «Прочее» становится `misc.md` — не архивируем слепо, там есть действующие
  записи). `docs/PITFALLS.md` → тонкое оглавление (введение + правила + по строке
  на тему). Перевести ссылки на ловушки по номерам строк на «тема + заголовок»;
  grep-проверка всех упоминаний `PITFALLS` по репозиторию. Содержание не удаляем и
  не переписываем по смыслу — только перенос.
- **Этап 2 — чистка и закрытие хвостов.** Устаревшее/дубли → `docs/pitfalls/_archive.md`;
  внести ждущие ловушки (хвосты 1/3/4/20/21); снять хвост 25 как дубль; дельта в
  `docs/TAILS.md` на закрытие хвостов 1/3/4/20/21/25.

## Проверка

- Ни одного сломанного упоминания `docs/PITFALLS.md` (grep по репозиторию: ссылки
  на строки переведены, файлы `docs/pitfalls/*` существуют).
- Содержание не потеряно: каждая старая запись либо в теме, либо в `_archive.md`
  (сверить по заголовкам/маркерам).
- Оглавление в `docs/PITFALLS.md` соответствует реальным файлам тем.
- Размер каждого файла темы — разумный (ориентир ≤ ~500 строк); «помойки» не
  воспроизводятся.
