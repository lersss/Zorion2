4. **Остановка во время ИИ-прогона студии — вариант 1:** не давать останавливать, пока

## Пожелание создателя (дословно)

> «хочу кнопку запуска ИИ в студии локально»

Повод: в студии пакетный прогон «описания ИИ» упал с
`порция 1: ошибка ИИ: Post "http://127.0.0.1:3456/session": ... connection refused`.
Причина — локальный ИИ-помощник (`opencode serve`) не запущен; создатель хочет
поднимать его из студии, а не из терминала.

## Уточнения (ответы создателя, 2026-09-24)

1. Объём — **«полноценно»**: индикатор состояния (не запущен / запускается /
   работает) + кнопки «запустить» и «остановить».
2. Дополнительно — **«да, давай»**: поднимать помощника автоматически вместе с
   остальными локальными серверами (`start-all.cmd`); кнопка — как «поднять
   заново, если упал».

## Зачем (цель)

Создатель не хочет каждый раз открывать терминал и вспоминать команду запуска;
хочет из студии видеть, работает ли ИИ, и управлять им одной кнопкой. Сейчас
ИИ-кнопки студии («заполнить комплектующие», «описания ИИ») падают сырой сетевой
ошибкой, если помощник не поднят.

## Контекст (проверено менеджером 2026-09-24)

- ИИ-кнопки студии ходят в локальный `opencode serve` по `OPENCODE_URL`
  (дефолт `http://127.0.0.1:3456`), клиент — `internal/goodsstudio/ai`.
- На момент приёма: порт 3456 не слушается, процесса нет → «connection refused».
- CLI `opencode` в PATH нет; есть `node`/`npx` → рабочий запуск
  `npx -y opencode-ai serve --port 3456` (задокументирован в идее 99a).
- `start-all.cmd` (кодировка **cp866**) поднимает: Postgres 5432, Redis 6379,
  игровой сервер 8080, ComfyUI 8188, учёт агентов 8790, арт-студию 8798 —
  помощника там нет.
- Студия — часть `cmd/server` (`/studio`, `web/studio.html`), роуты
  `/studio/api/*` под `auth.AdminAuth` (admin/skycomposer), регистрация в
  `cmd/server/main.go` (~строки 570–611).

## ТЗ (что должно получиться)

1. **Ручки** (`/studio/api/ai/*`, роли admin/skycomposer):
   - **статус** — по факту доступности помощника (проба `OPENCODE_URL`), а не «мы
     его запускали»: работает / не запущен / запускается;
   - **запуск** — если уже доступен, честно «уже запущен», второго не плодить;
     иначе поднять процесс и дождаться готовности (первый запуск качает пакет —
     долго, статус «запускается»);
   - **остановка** — «полноценно»: гасить помощника, даже если он поднят
     `start-all.cmd` или вручную (порт 3456 → владелец → проверка, что это
     помощник → гашение); опознать не удалось — честная ошибка, чужое не гасим.
2. **UI студии** — строка состояния «ИИ: …» + кнопки «запустить»/«остановить»
   рядом с ИИ-кнопками; обновление без перезагрузки страницы; тексты человеческие,
   без сырой сетевой простыни.
3. **`start-all.cmd`** — запуск помощника (порт 3456) по образцу других сервисов:
   проверка порта → `start` → `wait_port` → строка в сводке; переключатель вкл/выкл
   (по образцу `COMFY`/`STUDIO`/`DASH`).
4. **Прод (Amvera)** — кнопка не ломается: помощника там нет, честное
   «недоступно».

## Развилки для дизайна (модель менеджера — дизайнеру подтвердить/поправить)

- **Владение процессом.** Помощник — отдельный процесс (своё окно, как ComfyUI),
  переживает рестарт игрового сервера; поэтому «остановка» ищет владельца порта, а
  не помнит «своего» ребёнка.
- **Порт занят чужим.** Если 3456 занят не помощником — статус «порт занят другим
  процессом», запуск не делаем.
- **Готовность.** «Запускается» → опрос порта до готовности с таймаутом; таймаут —
  честный отчёт (первый `npx` может качать долго).
