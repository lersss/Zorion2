## Пожелание создателя (дословно)

1. «Переименовал "поселение" в "колония" (категория построек). Теперь я хочу видеть
   отсортировано по количеству населения форпост - поселение - городок - город -
   мегаполис - метрополия - экуменополис»
2. «в студии в разделе "производители"»
3. «причем желательно чтобы они там самостоятельно формировались по максимуму населения»
4. «ну или по минимуму наверное точнее»
5. «Да, плюс отображать эти параметры в карточках»
6. (уточнение адреса) «а чего не сделал конфигурируемым внутри карточки? и на саму
   карточку можно было это не выносить» → «с карточек убрать. 2. Да.»
7. «Кстати, я вообще представлял, что будет явно указана связка, во что превращается
   колония на следующей стадии.»

**Зачем (цель):** создатель строит ладдеру ступеней поселения. В студии ступени должны
читаться как лестница (порядок — сам, по данным), а пороги — **настраиваться в карточке
постройки полями** (не сырым JSON), с явной связкой «во что превращается на следующей
ступени». На карточках дерева числа не нужны.

## Что сделано

Файл: `web/studio.html` (только клиент; Go/БД/сервер не тронуты — серверная ручка
`PUT /studio/api/producers/{id}` уже принимает типизированное `stage`).

1. **Порядок ступеней** «Колонии» в дереве «Производители» — по нижнему порогу
   населения (`params.stage.enter`) по возрастанию, сам из данных (`prodStageEnter`,
   сортировка в `prodSubtypeNoCatRecords`).
2. **Строка диапазона с карточек дерева убрана** (сортировка осталась).
3. **Блок «Стадия» в карточке постройки** (`stageBlock`) — по спеке
   `2026-09-23-стадии-поселения-и-скорость-производства` §11.1 п.3 / §11.2:
   - поля `[порог входа] → [порог выхода]` в людях, значения из `params.stage`;
   - у низшей ступени (`enter = 0`) — подпись «порог выхода не читается (пол)»;
   - `exit ≥ enter` — красная ошибка, сохранение блока не отправляется (сервер 422);
   - сохранение по изменению поля: `PUT {stage:{enter,exit}}` → `fetchState()`
     (пересчитывает порядок и связку);
   - **связка со следующей ступенью** (новое, дельта к §11.1): «следующая ступень:
     <имя> (при N чел.)» / «дальше ступеней нет» — по данным (`prodNextStage`);
   - блок — только у ступеней класса без слотов (тот же предикат, что у дерева).
4. Сырой JSON «служебные параметры» внизу карточки оставлен (аварийный путь).

**Рамки:** только студия. База/сервер не тронуты.
