## Симптом (живой прогон 2026-09-24)

`POST /studio/api/descriptions/fill` завершается `порция 1: мусор в ответе ИИ`,
предложений 0 — при этом помощник отвечает HTTP 200 с корректным JSON.

## Причина (доказано диагностикой, файлы сохранены в `%TEMP%\opencode`)

Модель `gonka/deepseek-ai/DeepSeek-V4-Flash-0731` отдаёт ответ одним `text`-part,
в котором сначала идёт **рассуждение на английском**, и в нём **цитируется шаблон
из промпта** `` `{"items":[{"name":"…","description":"…"}]}` `` (шаблон есть в
`prompt_desc.go:20`), а затем — настоящий JSON (байт 1905).

`extractJSON` (`internal/goodsstudio/ai/parse.go:29-51`) берёт подстроку **от
первого `{` до последнего `}`** → склеивает шаблон-цитату + прозу + реальный ответ
→ `json.Unmarshal` падает: `invalid character '`' after top-level value`
(offset 47). Отсюда «мусор в ответе ИИ».

Поле ответа при этом правильное (`items`/`name`/`description`) — гипотеза «чужая
структура» не подтвердилась.

**Второй факт:** `Client` (`client.go`) сессии не закрывает — `GET /session?limit=5000`
показал **1882 сессии** (копятся, не удаляются). Один `Ask` = одна новая сессия.

## ТЗ (что должно получиться)

1. **Разбор ответа находит ВАЛИДНЫЙ JSON, а не «первый-{…-последний-}».**
   Исправить `extractJSON` так, чтобы при наличии прозы/цитат шаблона брался
   корректный объект ответа (например, разбор с конца / выбор последнего
   валидного JSON-объекта / устойчивый скан). Критерий: ответ модели с
   рассуждением и цитатой шаблона разбирается в 1 item с верным описанием.
   Это чинит **оба** инструмента — описания и «заполнить комплектующие»
   (`ParseFillResponse` использует тот же `extractJSON`).
2. **Не сломать уже покрытые случаи:** валидный JSON, ```json-обёртка, проза
   вокруг голого JSON, проза без JSON (ошибка), пустые name/description
   отбрасываются — тесты `desc_test.go`/`prompt_fill_test.go` должны остаться
   зелёными.
3. **Сессии помощника закрываются.** После ответа сессия закрывается/убирается
   (по API помощника — DELETE/архивация), чтобы не копились. Критерий: после
   серии `Ask` число сессий не растёт линейно. Если помощник не даёт закрывать —
   честно зафиксировать в отчёте и предложить минимальный вариант (например,
   переиспользование одной сессии).
