## Пожелание (создатель, 2026-09-25)

В карточке поселения (вкладка «Поселения») рядом со стрелочкой изменения населения
показывать админам **суммарный R** — в процентах за секунду, с округлением до
тысячных, и в тултипе — **разбивку, из чего он состоит** (по компонентам).
Значения вида `6.0e-4` создателю непонятны — нужны проценты.

## Цель (зачем)

Создатель наблюдает за вымиранием форпоста на Meredsha и хочет **на глаз** видеть
скорость изменения и понимать, **чем она набрана** (голод/жажда/среда), не сверяясь
с сырым JSON и экспоненциальной записью. Это диагностическая витрина для админа.

## Решение по формату (согласовано в разговоре)

- **Кому:** `admin` и `skycomposer` (в клиенте — существующий `isAdmin()`).
- **Где:** `internal/models.Settlement` → `r_breakdown` (только админам, см. ниже).
- **Формат значения:** `доля/сек × 100`, `toFixed(3)`, десятичная запятая (ru-RU),
  знак сохраняем: **`+` — убыль, `−` — рост** (родной знак R движка:
  `p_{n+1} = p_n·(1−R)`). Ровно ноль — без знака (`0,000%/с`).
- **Inline** (рядом со стрелкой): модуль суммарного R, напр. `↓ 0,120%/с`
  (направление даёт стрелка, знак в число не тащим).
- **Тултип** (`title`): суммарный R со знаком + состав по компонентам.

Пример тултипа:

```
R суммарный = +0,120%/с (убыль)
Состав:
Голод: +0,060%/с
Жажда: +0,060%/с
Жара: 0,000%/с
Холод: 0,000%/с
Гравитация: 0,000%/с
Радиация: 0,000%/с
Естественная: 0,000%/с
(+ убыль, − рост)
```

## ТЗ (что сделать)

### 1. Сервер: разбивка R по компонентам

**Единая точка сборки — `internal/economy/settlement`.** R_total уже собирается
там (`EnvComponents` + вклад эффектов, `change_components.go`).

- Добавить чистую функцию разбивки средовых компонент, напр.
  `EnvBreakdown(input PlanetInput) []ComponentContribution` (небольшая структура
  с кодом и значением за секунду), покрывающую **обе модели**:
  - человеческая: `natural` (R_ест), `birth` (R_рожд), `heat`, `cold`, `gravity`
    (верхняя/нижняя ветка — одна ненулевая), `radiation`;
  - расовая (RaceID ≠ пусто/humans): `natural` = нетто расы
    (`reproduction·(1−k)·R_ест`), `heat`/`cold`/`gravity`/`radiation` — по
    active-кривым расы; при отсутствии записи расы — фолбэк на человеческую
    модель (как сейчас в `changeComponentsRace`).
- **Инвариант:** сумма значений `EnvBreakdown` **точно равна** `EnvComponents`.
  Достичь рефакторингом «наоборот»: `EnvComponents` суммирует `EnvBreakdown`
  (единый источник), а не дублирует формулы.
- Добавить разбивку вклада **эффектов** (по одному ряду на эффект), согласованную
  с `lastRate` (та же математика, что даёт `r_per_sec`): сумма рядов эффектов
  == `lastRate(needs)`. Имя ряда — человекочитаемое имя типа эффекта из каталога
  (`effect_types.name`: «Голод», «Жажда»).
- **Инвариант:** сумма всех рядов (среда + эффекты) **точно равна `r_per_sec`**
  поселения (та доля, что уходит в DTO).

### 2. Сервер: поле в DTO (только админам)

- `internal/models/economy.go`, `models.Settlement`: новое поле
  `RBreakdown []RComponent \`json:"r_breakdown,omitempty"\``, где
  `RComponent{Code string; Name string; Value float64}`.
- Заполнять в owner-проходе (`internal/repository/settlement_owner_pass.go`,
  `runOwnerPass`) рядом с `rPerSec`; имя — из уже загруженного каталога типов
  эффектов (как в `buildEffectModels`).
- **Витрина только админам** (как `r_per_sec`): обнулять в
  `internal/handlers/planet_visibility.go` в `playerSettlements` и
  `stripSnapshotSettlementSecrets` (там же, где `RPerSec = 0`). Игрок не должен
  получить `r_breakdown` ни в presence, ни в snapshot/scan/none.

### 3. Клиент: тултип в карточке поселения

- `web/static/js/modal/tabs.js`: `settlementTrendArrow(s)` — при `isAdmin()`
  добавить рядом со стрелкой процент (модуль) и `title` с составом из
  `s.r_breakdown`.
- Формат — по разделу «Решение по формату» выше (тысячные, запятая, знак).
- Подписи кодов: `natural` → «Естественная», `birth` → «Рождаемость»,
  `heat` → «Жара», `cold` → «Холод», `gravity` → «Гравитация»,
  `radiation` → «Радиация»; ряды эффектов — по `name` с сервера.
- Тултип многострочный (`&#10;` в `title`), значения экранировать.
- Коды/имена — на сервере; клиент не дублирует математику R.
- Правка клиента живая без перезапуска сервера (статика с диска, noCache).

### 4. Тесты

- Сервер: `EnvBreakdown` — сумма == `EnvComponents` (человек и раса, набор кодов,
  нулевые вклады присутствуют); owner-проход — `r_breakdown` непуст, сумма ==
  `r_per_sec` (в пределах эпсилона), ряды эффектов несут имя.
- Витрина: расширить существующие gварды (в тестах уже проверяется отсутствие
  `r_per_sec` у игрока/в снимке) — добавить `r_breakdown`.
- Клиент: прогон e2e-смоука карты под админ-учёткой + взгляд, что строка
  появляется только админам.
- DoD Go — `AGENTS.md` §2.
