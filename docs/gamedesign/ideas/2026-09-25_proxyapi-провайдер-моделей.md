## Что было (диагноз)

В личном конфиге opencode (`C:\Users\admin\.config\opencode\opencode.jsonc`, вне
репозитория) провайдер `proxyapi` **уже был**, но в нерабочем виде:

1. **адрес указывал на ветку только-OpenAI** — `https://api.proxyapi.ru/openai/v1`;
   в ней живут только модели с префиксом `gpt-*` (132 шт.), а перечисленные в
   конфиге `deepseek/...`, `z-ai/...`, `minimax/...`, `qwen/...` там отваливаются
   с «неверный запрос» (проверено живым запросом);
2. **ключ был старый** (`sk-xM5…`), не тот, что дал создатель.

## Что сделано

1. В записи провайдера `proxyapi` (личный конфиг, в git не попадает):
   - `baseURL`: `https://api.proxyapi.ru/openai/v1` → `https://api.proxyapi.ru/v1`
     (общая ветка — 623 модели, все перечисленные ниже в ней есть);
   - `apiKey`: `sk-xM5…` → новый ключ создателя (`sk-iTiu…HFV5BK`).
2. Список моделей оставлен как был (5): `deepseek/deepseek-v4.1-flash`,
   `deepseek/deepseek-v4-flash-0731`, `z-ai/glm-5.2`, `minimax/minimax-m3`,
   `qwen/qwen3.8-flash`.
3. **Модель по умолчанию не менялась** — остаётся `opencode-go/deepseek-v4.1-flash`
   (решение создателя на гейте). ProxyAPI — доступный выбор, не дефолт.

## Проверка (живые запросы, 2026-09-25)

- новый ключ валиден: OpenAI-ветка — 132 модели, `gpt-4o-mini` ответил «Ok!»;
- общая ветка `/v1` — 623 модели; `deepseek/deepseek-v4.1-flash` и `z-ai/glm-5.2`
  отвечают 200;
- общая ветка принимает **tools + stream** (проверено запросом с инструментом
  `get_weather`: модель вернула `tool_calls`) — значит, для агентов opencode годится;
- личный конфиг после правки разбирается как JSON; `baseURL`, ключ и 5 моделей —
  на месте.

**Не проверено живьём:** выбор модели ProxyAPI из интерфейса opencode — конфиг
читается один раз при старте, нужен новый запуск/перезапуск (проверяет создатель).

## Догон 2026-09-25 (живой прогон в приложении): «Model not supported»

**Симптом (создатель):** «Bad Request: `{"detail":"Model not supported"}` на дипсике… ни
одна модель не работает из вкладки opencode».

**Диагноз (факт):** приложение opencode **держало старую настройку в памяти**.

- В собственном состоянии приложения (Electron-хранилище
  `%APPDATA%\ai.opencode.desktop\opencode.global.dat`) записан адрес упавших
  запросов — `https://api.proxyapi.ru/openai/v1/chat/completions` (старая ветка), и
  текст ошибки `{"detail":"Model not supported"}`.
- Проверено вручную: старая ветка `/openai/v1` отвечает ровно так
  (`HTTP 400 {"detail":"Model not supported"}`) на `qwen/...`, `minimax/...`,
  `deepseek/...` — она обслуживает только модели `gpt-*`.
- **Причина:** приложение было запущено в 22:43, правка конфига — в 22:57;
  конфиг читается один раз при запуске, закрытие/смена вкладки не помогает.
- Кодировка **ни при чём**: файл конфига — UTF-8 без BOM, JSON валиден, русские
  названия целы (проверены сырые байты).

**Действие:** полный перезапуск приложения opencode (не вкладки) — после него запрос
пойдёт на `api.proxyapi.ru/v1`. Если адрес в состоянии приложения останется старым —
провайдера заводить через собственный интерфейс приложения (оно хранит копию
настроек отдельно).

**Урок (для будущих правок личного конфига):** после правки
`~/.config/opencode/opencode.jsonc` приложение opencode нужно **полностью
перезапускать**; иначе оно молча работает по старому конфигу.

## Настройка (для повторения)

- Провайдер — **только в личном конфиге**, не в `opencode.json` проекта (секрет не
  коммитим).
- Для моделей с префиксом (`deepseek/...`, `z-ai/...`) адрес — **общая ветка**
  `https://api.proxyapi.ru/v1`; ветка `/openai/v1` — только для `gpt-*`.
