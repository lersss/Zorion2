## Решения менеджера по развилкам (2026-09-25, «Делай»)

- **Что показываем:** витрину **всех кораблей, которые уже есть в игре** (игровой реестр), плюс
  срез **покрытия** — у каких рас корабля ещё нет и сколько вариантов у остальных.
- **Зачем:** витрина + рабочий сигнал «что осталось нарисовать». Клик по расе без корабля
  уводит в существующую вкладку «Корабли рас» с выбранной расой (новых генераторов не делаем).
- **Источник:** «есть в игре» = **реестр кораблей игры** (`internal/models/race_ship_sprites.go`)
  + картинки из игровой папки `web/static/sprites/`. НЕ пул студии (принятое в студии может
  опережать игру — это разные наборы).
- Витрина **только для чтения** (без приёмки/удаления/поворота): это обзор, а не рабочий пул.

## Зачем (цель)

Сейчас все вкладки студии показывают **то, что ещё генерируется** (кандидаты пула, референсы),
а не **то, что уже лежит в игре**. Чтобы оценить текущий набор кораблей игры целиком
(посмотреть/сравнить, поймать дубли и слабые картинки, увидеть пробелы по расам), нужно
сводить данные руками из реестра и папки. Витрина закрывает эту потребность одним экраном.

## Факты (текущее состояние)

- Арт-студия — отдельный бинарь `cmd/art-studio` (порт 8798), UI — один файл
  `cmd/art-studio/web/index.html` (~1616 строк / ~95 КБ), вкладки: Отбор · Эталон · Люди ·
  **Корабли рас** · Галерея.
- Вкладка «Корабли рас» показывает **кандидатов пула** (`ai_drafts/ships_pool`, эндпоинт
  `GET /ships/list`), с приёмкой/удалением/поворотом. Кораблей игры там нет.
- Реестр кораблей игры: `internal/models/race_ship_sprites.go` — **117 расовых записей**
  (`RaceShipSprites`: людской блок 12 первыми + 105 расовых) **+ отдельная `NeutralShip`**;
  у каждой: ID, человеческое имя, файл, слаг расы, пара показа `Angle`/`Flip`. Это источник
  правды в игре. У `Angle`/`Flip` в модели стоит `omitempty` — в JSON нулевые значения
  выпадают, значит для витрины нужна своя DTO-обёртка с обязательными полями.
- Картинки игрового набора — `web/static/sprites/` (проверено: все 117 файлов реестра +
  `neutral.png` на месте; PNG верхнего уровня ровно **118**, сирот нет; ещё есть подпапки
  `belt/` и `biomes/` — к кораблям не относятся).
- Покрытие: корабль есть у **57 рас** (людской блок + 56 нечеловеческих записей), каталог рас —
  **60 лор-файлов** (`docs/gamedesign/races/ships/*.md`). Без корабля: **cryo_sky, geysers,
  ice_plankton** (3 расы). 57 + 3 = 60.
- Имена рас: `config/races.json` уже читается студией (`raceNameBySlug`).
- Студия работает из корня репозитория (относительные пути вида `config/races.json`,
  `docs/gamedesign/races`), значит может и импортировать `zorion/internal/models`, и читать
  `web/static/sprites`.
- Статику игры студия не отдаёт — генератор фонов и оффсетов пула отдельные, поэтому картинки
  игрового набора нужен отдельный эндпоинт.

## ТЗ (что должно быть на выходе)

1. **Новая вкладка «В игре»** в арт-студии — витрина кораблей игрового реестра, сгруппированная
   по расам:
   - порядок групп: людской блок первым (как в реестре), дальше расы в порядке реестра;
     нейтральный корабль — отдельной группой «Нейтральный»;
   - в группе — карточки кораблей в порядке реестра; на карточке: картинка, человеческое имя
     (как в реестре), имя файла;
   - показ с учётом пары `(угол, зеркало)` из реестра — тем же способом, что уже применяется в
     студии для претендентов (CSS-трансформ, пиксели не трогаются);
   - у группы — счётчик вариантов.
2. **Срез покрытия:** расы каталога без корабля показываются отдельным блоком («Без корабля»)
   с числом и списком; клик по расе переключает на вкладку «Корабли рас» и выбирает эту расу
   (существующий путь генерации, новых ручек генерации не вводим).
3. **Данные — из игры:** витрина читает реестр `internal/models.RaceShipSprites` (импорт пакета)
   и картинки из игровой папки `web/static/sprites/`. Пул студии не используется.
4. **Новый эндпоинт:**
   - `GET /ships/ingame` → `[{file, id, name, race, race_name, angle, flip}]` — **состав витрины
     = `RaceShipSprites` + `NeutralShip`** (иначе нейтральной группы не будет). Это DTO-обёртка
     над `ShipSprite`: `angle`/`flip` отдаём **всегда** (не полагаемся на `omitempty`), плюс
     `race_name` из `config/races.json` (для нейтрального — пусто);
   - `GET /ships/ingame/img/<file>` → PNG из игровой папки (только `filepath.Base`, вне папки
     не отдаём).
5. **Список рас без корабля** считается на клиенте: `GET /ships/races` (те же 60 рас, что и во
   вкладке «Корабли рас» — **единственный источник базы покрытия**, чтобы витрина и вкладка
   генерации не разошлись) минус расы, встречающиеся в `/ships/ingame`. Новых эндпоинтов под
   это не нужно.
6. Витрина **только для чтения**: никаких приёмки/удаления/голосования; картинка открывается
   в новой вкладке по клику (как в пуле).
7. Правки файлов — **хирургические**: существующие вкладки/эндпоинты не трогаем, общие классы
   сетки (`grid`, `cell`, `orient`) переиспользуем.

### Путь картинок в конфиге (для тестов)

Папку игровых спрайтов не хардкодить в хендлере: своё поле сервера (в тестах — относительный
путь), дефолт `web/static/sprites`. ⚠️ Имя **не** `shipsDirPath` — оно уже занято каталогом
лора `docs/gamedesign/races/ships/` (`handlers/http.go`); берём другое, например
`gameSpritesDirPath`.
