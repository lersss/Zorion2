# 2026-09-25. Арт-студия: удаление кораблей из игры (вкладка «В игре»)

**Вектор:** Визуал (реестр/спрайты игры) · Игрок (иконка корабля игрока) — внутренний
инструмент студии; код — `@developer`.
**Приоритет:** обычный (инструмент создателя).
**Статус:** 🔄 реализация (дизайн пройден, спека `docs/specs/2026-09-25-арт-студия-удаление-кораблей-из-игры.md`; создатель дал «ок» на разработку 2026-09-25).

## Пожелание создателя (дословно)

«сделай в студии кораблей (в списке кораблей в игре) возможность удалять из игры корабли»

## Решения создателя (уточнения 2026-09-25, по номерам вопросов менеджера)

1. **Где** — арт-студия (`cmd/art-studio`), вкладка **«В игре»** (витрина игрового реестра
   кораблей). Отдельной «студии кораблей» в проекте нет.
2. **Что значит «удалить»** — вариант **(а) физически убрать**: удалить PNG из игровой папки
   и вычеркнуть запись из реестра игры. Создатель согласен, что фактически это **правка
   исходников игры и последующая пересборка сервера**; необратимо (страховка — git).
3. **Зачем** — **чистка дублей и слабых/ошибочно принятых картинок** (первый вариант).
4. **Судьба игроков** — **да**: если у игрока выбран удаляемый корабль, он **тихо подменяется
   на людской дефолт** (как уже работает резолвер для неизвестного корабля).
5. **Как** — **по одному** кораблю.
6. **Где хранить реестр (решение создателя 2026-09-25)** — **НЕ база данных и НЕ правка кода
   игры веб-инструментом**, а **вариант «данные»**: реестр кораблей игры переезжает из
   Go-констант в **статичный файл данных**, который коммитится вместе со спрайтами и
   читается игрой при старте (для эффекта удаления достаточно перезапуска сервера игры, без
   пересборки). Создатель: «ок» на проработку дизайнером именно этого варианта.

## Цель (зачем)

Дать создателю из витрины «В игре» убирать из игры неудачные/дублирующие корабли, чтобы в
игровом наборе оставались только хорошие картинки. Сейчас витрина **только для чтения** —
убрать корабль из игры можно лишь вручную правя исходники, тесты и файлы.

## Факты (текущее состояние, проверено)

- **Витрина «В игре»** — `cmd/art-studio/web/index.html` (`loadIngame`, `#gridIngame`), данные:
  `GET /ships/ingame` из `models.ShipOptions` (**компилированный** реестр
  `internal/models/race_ship_sprites.go`) + картинки `GET /ships/ingame/img/<file>` из игровой
  папки (`ships_handlers.go:250`, `http.go:163`; поле каталога — `gameSpritesDirPath`,
  `http.go:44`). Сейчас **только чтение** (идея `2026-09-25_арт-студия-витрина-кораблей-игры.md`,
  коммит `1d36cbc`).
- **Реестр игры** — Go-константы `internal/models/race_ship_sprites.go`:
  `RaceShipSprites` = **117 расовых** (12 людских + 105) + отдельный `NeutralShip`;
  `ShipOptions` = 118 (нейтральный последним). По замыслу — **статичен, коммитится с
  ассетами** (спека `2026-09-23-корабли-рас-раса-агентов-и-игрока.md` §6.2).
- **Тесты реестра жёстко зашиты** (`internal/models/race_ship_sprites_test.go`): ровно
  `117` записей (`:18`), людской блок 12 + 105 (`:42`), `ship_options` `118` (`:81`),
  пул humans `12` (`:101`), рас с кораблями `57` (`:114`). **Удаление любой записи ломает
  эти тесты**, пока их не сделать data-agnostic.
- **Источник приёмки** — `ai_drafts/final_accepted/ships/ships_meta.json` (124 записи) + PNG
  в той же папке. `tools/import_ship_sprites.ps1` копирует PNG в `web/static/sprites/`
  (сверка по **sha256**) и **печатает строки реестра вручную**, сам реестр **не переписывает**
  (шапка скрипта, `:6–7`, `:158`). ⚠️ **Ловушка:** если удалить только PNG+запись реестра, но
  оставить запись в `ships_meta.json`, следующий прогон импорта **вернёт корабль**.
- **Тихая подмена игрокам уже есть:** `/me` и админ-профиль отдают `ship_icon` через
  `models.ResolveShipIcon` (неизвестный/легаси → `DefaultHumanShip`, `auth_handlers.go:312`,
  `admin_users.go:356`); чужие игроки на карте — там же (`players_positions.go`). Значит
  удалённый корабль игрока подменится на людской без доп. кода. DB-значение `users.ship_icon`
  останется указывать на удалённый файл — на чтении это скрыто резолвером.
- **Нельзя удалять фолбэки:** `DefaultHumanShip = "race_humans_starship.png"` =
  `RaceShipSprites[0]` (DEFAULT `users.ship_icon`, миграция 000074; `:137–140`) и
  `NeutralShip` (фолбэк для расы без пула, §6.4). Удаление любого из них ломает игру.
- **Студия работает из корня репозитория** (относительные пути `config/races.json`,
  `web/static/sprites`) — может читать и писать игровые пути.
- **UI вшит в бинарь студии** (`//go:embed web/index.html`) — после правки страницы нужна
  пересборка и перезапуск студии (ловушка `docs/pitfalls/misc.md`).

## Открытые дизайн-вопросы (для `@designer`)

1. **Чем правит студия.** Вариант A — точечно править Go-исходник `race_ship_sprites.go`
   (удаление строки) + удалять PNG. Вариант B — вынести реестр игры в **встроенный JSON-данные**
   (embed, тоже статичен и коммитится), чтобы удаление было чистой правкой данных, а не кода.
   Выбрать с оценкой хирургичности и рисков (серия перезаписей одного файла → сторож зацикливания).
2. **Тесты реестра** — сделать data-agnostic (длины считать из реестра, людской блок — из
   реестра; «117/118/57/12» из тестов убрать), иначе удаление их ломает.
3. **Полная очистка, чтобы корабль не вернулся** — удалять ли запись из `ships_meta.json`
   и PNG из `final_accepted`? Иначе `import_ship_sprites.ps1` восстановит корабль.
4. **Отражение удаления в UI без пересборки** — `/ships/ingame` читает **компилированный**
   реестр: после правки исходника студия отдаст старые данные до пересборки. Решить: парсить
   исходник/данные при запросе, либо перезапуск, либо иное.
5. **Что если удаляем последний корабль расы** — раса возвращается в блок «Без корабля»
   (ожидаемо, отдельного кода не нужно — уточнить).
6. **Подтверждение/защита** — подтверждение удаления; запрет на нейтральный и людской дефолт;
   сообщение, что эффект в игре — **после пересборки сервера игры**.

## ТЗ (предварительное — уточняется дизайном)

1. В витрине «В игре» у карточки корабля — действие **«Удалить»** (по одному), с
   подтверждением; после успеха карточка исчезает, пересчитываются счётчик группы и общий
   счётчик, при необходимости раса уходит в «Без корабля».
2. Удаление **физическое**: запись реестра игры + PNG в игровой папке (+ запись меты, см.
   дизайн-вопрос 3). Возврат — только через git.
3. **Защита:** нейтральный корабль и людской дефолт (`race_humans_starship.png`) удалить нельзя.
4. **Игрокам** с удалённым кораблём — тихая подмена на людской дефолт (уже есть, доп. кода
   под это не требуется; при необходимости подтвердить тестом).
5. Правки файлов — **хирургические**, существующие вкладки/эндпоинты не трогаем; UI удаления —
   по образцу существующего удаления кандидатов в пуле (вкладка «Корабли рас»).

## Критика идеи (прогон `@critic`, 2026-09-25)

**Вердикт: «ЕСТЬ 11 — крупных 0, средних 5, мелких 6».** Крупных нет; механика не нарушает
«Двенадцать инвариантов», но есть средние, требующие решения создателя/дельт.

**Средние (вынесены создателю на гейте как звоночки):**
- **C1 — смена канона.** Реестр по канону только растёт в конец и правится вручную
  (спека §6.1 п.6/§9 И7; `import_ship_sprites.ps1` печатает строки вручную, реестр не
  переписывает). Идея вводит обратную операцию и автозапись студией — нужна дельта спеки
  и шапки скрипта; решение развилки A/B — за дизайном.
- **C2 — рассинхрон фолбэков игрок/агент.** При удалении последнего корабля расы X агент X
  рисуется `neutral.png` (`RandomShipForRace`), а игрок X с удалённым файлом — людским
  (`ResolveShipIcon`), при этом `PUT /me/ship-icon` не даёт выбрать нейтральный (раса `""`),
  а селектор расы пуст. Дизайн-вопрос 5 («доп. кода не нужно») неверен — сценарий надо назвать.
- **C3 — сдвиг вида агентов.** `spriteForAgent`/`pickVariant` при отсутствии слота берёт
  наименьший суффикс пула; удаление `_0<w>` сдвигает вид уже нарисованных агентов
  (И7 «вид уже нарисованных не сдвигается» покрывал только рост). Нужен тест деградации пула.
- **C4 — окно рассинхрона.** PNG исчезает сразу, реестр — только после пересборки;
  `/static/` отдаётся с диска `noCache`, клиент на 404 рисует примитив. В окне игрок/агент
  показываются примитивом, а не «тихой подменой» — порядок надо назвать в дизайне.
- **C5 — вариант B ломает импортёр.** `import_ship_sprites.ps1` ищет в реестре буквально
  `File: "<name>"` и путь `internal/models/race_ship_sprites.go`; при переезде реестра в JSON
  скрипт перестанет находить вставленные строки — при варианте B обязательна правка скрипта.

**Мелкие (правятся в ТЗ идеи/дизайна):** M1 — `TestShipsIngame` (`ships_handlers_test.go:1232`)
жёстко ждёт `race_humans_starship_02`; M2 — жёсткие числа 117/118 в доках
(`ARCHITECTURE.md:134–135`, JS `ship_sprites.js:9,240`); M3 — старая идея витрины и note
