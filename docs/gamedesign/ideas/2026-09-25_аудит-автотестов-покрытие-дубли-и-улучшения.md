## Находки

### Н1. Покрытие по трём пакетам вообще не измеряется (техническая ловушка)

`go test -cover` **падает на сборке** трёх пакетов: `cmd/art-studio/generator`,
`cmd/art-studio/handlers`, `internal/economy/settlement`. Причина — UTF-8 BOM в начале
**нет-тестовых** `.go`-файлов (`human_job.go`, `http.go`, `race_balancer.go`): инструмент
покрытия его не переваривает («invalid BOM in the middle of the file», позиция 1:1).
Обычные `go build`/`go test` без `-cover` проходят — поэтому ловушка незаметна.

- BOM только в `*_test.go` замеру **не мешает** (проверено: `galaxy`, `planet`,
  `repository`, `cmd/art-studio/config`, `postproc` — покрытие снято нормально).
- Всего BOM-файлов в репо — 15; из них нет-тестовых — 5 (в т.ч. `ships_handlers.go`,
  `ships_rebuild.go`, `race_job.go`, `ref_job.go` — их пакеты тоже в зоне риска).
- Следствие: `internal/economy/settlement` (170 тестов, 3303 строки) — **крупная зона
  «население/экономика» без замера**.

### Н2. Копипасты в тестах нет — но есть три дубля «по смыслу»

- **Таблица светимостей звёзд проверяется дважды.** `internal/generator/planet/physics.go:105`
  — тонкая обёртка `luminosityBySpectral` → `astro.LuminosityBySpectral`; тест обёртки
  (`physics_test.go:80`) и тест оригинала (`internal/astro/luminosity_test.go:13`)
  проверяют одну и ту же таблицу. Тест обёртки не ловит ничего нового.
- **Одинаковые имена на разных слоях (не дубль, но путает при разборе падений):**
  `TestRadarRadius` — `internal/handlers/visibility_test.go:61` и
  `internal/ship/catalog_test.go:32`; `TestGenerateSettlementsInvalidModel` —
  `internal/generator/settlement/generator_test.go` и
  `internal/handlers/admin_settlements_test.go`.
- Идентичные тела (MD5 нормализованного кода) — единственная группа:
  `TestMain` в `cmd/art-studio/{generator,handlers,postproc}/fake_python_*_test.go`
  (6 строк, отличаются только текстом). Это норма: три обвязки под три папки.

### Н3. Фронтенд-тесты лучше, чем выглядели сначала (проверено, ошибка исправлена)

Первый заход показал «фронтенд проверяется чтением текста». **Неверно.** Из 28 тестов
пакета `web`: **20 реально исполняют JS-модули в Node** и сверяют **значения**
(`frontend_money_test.go` — форматирование баланса, знак суммы, календарь, пустое
состояние, защита от `NaN`), 1 читает файл, 7 — **контрактные по тексту**
(`frontend_studio_{code_label,eat_goods,export,graph_recipe_id,stage,subtype,unit_scale}_test.go`:
ищут подстроки в теле функций `web/studio.html`).

Node **есть** (v24.20.0), Python **есть** (3.12.1), БД и Redis подняты — прогон
29.09.2026: `web` — 28 RUN, **0 SKIP**. То есть тесты действительно идут.

Риск: `t.Skip` срабатывает молча при отсутствии node/python/БД. На машине без node
28 фронтенд-тестов дадут «зелено» без единой проверки (и `-cover` покажет
`[no statements]` — заметить нельзя). Правило-страховка уже есть в
`docs/pitfalls/go.md` (тест с внешней зависимостью обязан её проверять) — пробел в том,
что «нет node» = skip, а не громкий отказ.

### Н4. Слабых тестов нет (проверено, первоначальная оценка снята)

Промежуточный подсчёт дал «93 теста с единственной проверкой, что ошибки нет». После
перепроверки: **у всех есть описанные ожидания обращений к БД (мок) либо запрос/ответ
через тестовый HTTP-сервер — они и являются проверкой**. Реально пустых — **0**.
Тесты-«дымовые» (`*NoPanic`, `*Smoke*`) тоже полезны: это стражи устойчивости, а не шум.

### Н5. Долгие тесты правильно спрятаны

Тяжёлые статистические тесты гейтятся `testing.Short()`:
`TestHotJupiterFromMigration` — 101,9 с, `TestOverflowRateByPlanetCount` — 55,6 с
(оба `internal/generator/planet`). Быстрый цикл их не тянет — сделано грамотно,
трогать не нужно. Общий пакет `planet` — 341,8 с, `galaxy` — 70,1 с (уже вынесены
из `-race`-цикла в `AGENTS.md` §2).

## ТЗ (что должно быть на выходе) — по приоритету

1. **Убрать BOM из нет-тестовых `.go`-файлов** (5 файлов; минимум 3 блокирующих замер).
   Правка безрисковая, ничего не меняет в поведении. Отдача: покрытие трёх пакетов,
   включая крупную зону «население/экономика».
   *Замер после правки: `go test -cover ./internal/economy/settlement/ ./cmd/art-studio/generator/ ./cmd/art-studio/handlers/` — три пакета собираются и дают проценты.*
2. **Зафиксировать ловушку Н1 в `docs/pitfalls/go.md`**: BOM в нет-тестовом `.go`
   валит `go test -cover` («invalid BOM in the middle of the file», 1:1), обычная
   сборка при этом проходит — ловушка незаметна; в тестовых файлах BOM не мешает.
   Рядом с существующей записью про PowerShell/кириллицу (`db-shell.md`).
3. **Громкий отказ вместо тихого пропуска для node/python-тестов** (Н3): при
   отсутствии зависимости тест должен **падать** в полном режиме и пропускаться только
   в коротком (`-short`), иначе зелёный прогон врёт. Образец — как гейтятся тяжёлые
   статистические тесты (Н5).
4. **7 контрактных текстовых тестов студии перевести на исполнение в Node** (Н3) —
   как уже сделано для 20 остальных. Сейчас они ломаются от рефакторинга и не замечают
   изменения поведения.
5. **Один дымовой тест старта сервера** (`cmd/server` — 0%): приложение поднимается,
   отвечает на `/health`. Дёшево и закрывает полностью непокрытый вход системы.
6. **Бенчмарки на горячее** (сейчас 0 бенчмарков): генерация галактики, генерация
   планет, сборка карты из снапшота. Цель — ловить просадки производительности, а не
   «улучшить цифру покрытия».
7. **Подтянуть покрытие слабых зон до обозначенной планки**: `internal/models` (49%),
   `internal/handlers` (67,5%), `internal/repository` (67,5%), `aiserve` (64%). Планку
   назначает создатель; предлагаю не «вообще», а точечно — по тем файлам, где были баги.
8. **Мелочи-чистки:** снять дубль-тест обёртки светимости (Н2); развести одинаковые
   имена тестов (Н2); убрать `tools/e2e/tmp-*` и черновики `qa-e3-snow*` (Н6).
