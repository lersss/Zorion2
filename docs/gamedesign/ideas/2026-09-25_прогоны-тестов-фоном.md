## 1. Что решили

Уровни прогонов остаются два, термины не меняются («быстрый цикл» — блокирующий, «тяжёлый генераторный прогон» — второй уровень):

1. **Тяжёлый генераторный прогон — не блокирующий.** Его выполняет фоновая проверка CI на push (джоб «генераторы»). Локально — по желанию, гейт его не ждёт.
2. **Тестер не повторяет полный набор Go-тестов** — он уже пройден разработчиком и повторяется фоновой проверкой CI. Тестер гоняет Go-тесты точечно, под конкретное сомнение, а основное время отдаёт живым сценариям (сервер, БД, браузер) и краевым входам.

**Блокирующим остаётся:** `go build ./...` + `go vet ./...` + быстрый цикл с детектором гонок по пакетам, кроме генератора.

## 2. Замеры (2026-09-25, Windows, gcc WinLibs в PATH)

| Прогон | Время |
|---|---|
| `go build ./...` / `go vet ./...` | 1,6 с / 0,9 с |
| быстрый цикл (`-race -short`, 38 пакетов), начисто | 75 с |
| тот же цикл из кеша (код не менялся) | 1,8 с |
| тяжёлый генераторный прогон (планеты + галактика, без `-race`) | 281 с (планеты ~280 с, галактика ~40 с) |

Побочная находка: в инструкциях тяжёлый прогон был описан как «~1 минута» — реально ~5 минут, устарело в 5 раз.
