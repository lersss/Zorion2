## 0. Цель и зачем

- Студия — **один файл 5120 строк**, из которых ~4620 строк — единый блок кода внутри
  страницы. По проектному правилу «файл длиннее 200–300 строк — делить» превышение ~15×.

## 1. Жёсткие рамки (почему так, а не иначе)

1. **Классические скрипты, НЕ ES-модули.** Разметка дёргает функции прямо из атрибутов
   (`onchange=`/`onclick=`), т.к. функции и состояние — глобальные. Перевод в `import/export`
   снесёт глобальность → интерфейс отвалится. Выносим как обычные `<script src="...">` **без**
   `type="module"`, подключая их **до** инлайнового скрипта (чтобы объявления существовали
   раньше, чем инлайновая часть их использует).
2. **Поведение и строки — дословно.** Переносим текст функции как есть. Никаких переименований,
   «чисток», смены порядка строк внутри блока.
3. **Один блок — один чекпоинт** со своим гейтом и браузерным смоуком студии.
4. **Контрактные тесты не переписываем по одному.** Все `web/frontend_studio_*.go` читают файл
   через **единственный** помощник `studioHTML()` в `frontend_studio_subtype_test.go`. Учим его
   читать и вынесенные файлы — тогда 6 тест-файлов остаются нетронутыми.
5. **Сторож зацикливания.** Большой файл правим **одной сводной записью**, не серией мелких
   правок (иначе сессия рубится). На один большой файл — не более двух батчей.
6. **Игровой код вне зоны.** Правки только в `web/studio.html`, `web/static/js/studio/*` и
   тест-помощнике.
