## 0. Цель и зачем

- Студия — **один файл 5120 строк**, из которых ~4620 строк — единый блок кода внутри
  страницы. По проектному правилу «файл длиннее 200–300 строк — делить» превышение ~15×.
- **Цена сегодня:** любая правка студии — правка гигантского файла; обзор диффа теряется,
  легко зацепить соседний блок, параллельные линии конфликтуют на одном файле.
- **Цель:** разнести код студии на связные блоки-файлы. **Поведение не меняется** — это чистый
  перенос строк, без переименований и «улучшений» по пути.

## 1. Жёсткие рамки (почему так, а не иначе)

1. **Классические скрипты, НЕ ES-модули.** Разметка дёргает функции прямо из атрибутов
   (`onchange=`/`onclick=`), т.к. функции и состояние — глобальные. Перевод в `import/export`
   снесёт глобальность → интерфейс отвалится. Выносим как обычные `<script src="...">` **без**
   `type="module"`, подключая их **до** инлайнового скрипта (чтобы объявления существовали
   раньше, чем инлайновая часть их использует).
2. **Поведение и строки — дословно.** Переносим текст функции как есть. Никаких переименований,
   «чисток», смены порядка строк внутри блока.
3. **Один блок — один чекпоинт** со своим гейтом и браузерным смоуком студии.
4. **Контрактные тесты не переписываем по одному.** Все `web/frontend_studio_*.go` читают файл
   через **единственный** помощник `studioHTML()` в `frontend_studio_subtype_test.go`. Учим его
   читать и вынесенные файлы — тогда 6 тест-файлов остаются нетронутыми.
5. **Сторож зацикливания.** Большой файл правим **одной сводной записью**, не серией мелких
   правок (иначе сессия рубится). На один большой файл — не более двух батчей.
6. **Игровой код вне зоны.** Правки только в `web/studio.html`, `web/static/js/studio/*` и
   тест-помощнике.

### ЧК1 — пилот (детали)

- **Что выносим:** строки 2143–2278: `exportContent`, `refreshImportStatus`, `importContent`,
  `openImportPopup`, `closeImportPopup`, `applyImportContent`, `sumCounts`, `importDiff`.
- **Куда:** новый `web/static/js/studio/content_transfer.js`, классический скрипт; подключение

  (строка 492).
- **Что проверяет пилот:** (а) перенос строк не ломает поведение; (б) контрактные тесты находят
  функции через обновлённый помощник; (в) кнопки «экспорт контента»/«импорт контента» работают
  (проводка в инлайновой части ссылается на функции — они глобальные из нового файла).
- **Правка тест-помощника:** `studioHTML()` начинает читать `web/studio.html` **и** тела
  вынесенных классических скриптов студии, в порядке подключения. Тогда `jsFuncBody` и
  `strings.Contains` продолжат работать без правок отдельных тест-файлов.
- **Почему именно этот блок:** он самодостаточен, невелик и **покрыт** контрактными тестами
  (`frontend_studio_export_test.go`, `frontend_studio_import_test.go`) — значит докажет механизм.
