## Уточнения (создатель, 2026-09-25)

1. **Фракция — пока имя расы.** В игре на каждую расу заведена одна фракция, и её
   имя совпадает с именем расы. Дополнительные детали (тип фракции) не нужны.
2. **Имя картинки корабля — ролям `admin` и `skycomposer`.** Показывать имя файла
   спрайта. Обычным игрокам — не показывать.

## Факты разведки

- Тултип агента при наведении — `showNPCTooltip` (`web/static/js/map/npc_agents.js`):
  сейчас показывает имя, статус, текущий мир, целевой мир.
- В позиции агента (`GET /api/npc/positions`) уже едет `race_id` (слаг, напр.
  `humans`), но человекочитаемого имени расы там нет.
- Прямой привязки «агент → фракция» в данных нет (`npc_agents.owner_faction_id` нигде
  не заполняется). Но фракция в игре — одна на расу, и её имя берётся из каталога рас
  (`races.ByID(raceID).Name`, см. `internal/generator/faction/faction.go`), т.е. это и
  есть имя расы. Новых таблиц/миграций не нужно.
- Корабль агента подбирается на клиенте `spriteForAgent(race_id, id)` → `{file, color}`
  (уже импортирован в `npc_agents.js`); имя файла доступно без серверных правок.
- Роль игрока на карте — `state.userRole` (`web/static/js/map/config.js`); проверка
  админ-ролей уже используется в `data.js`/`map_render.js`.

- В полезную нагрузку позиций агента добавить человекочитаемое **имя расы**

  строка.
- Заполнение — в хендлере позиций (`internal/handlers/npc_positions.go`) поверх снимка
  менеджера; в пакет `internal/npc` каталог рас не тянуть. Тесты позиций/видимости
  адаптировать под новое поле.

### Клиент

- В тултипе агента (`showNPCTooltip`, `web/static/js/map/npc_agents.js`) добавить
  строку **«Фракция: <имя расы>»** (пусто → «—»). Видна **всем** игрокам.
- Для ролей **`admin`/`skycomposer`** дополнительно добавить строку с **именем файла
  спрайта** корабля агента (напр. «Корабль: `race_humans_starship_02`»; расширение
  `.png` не показывать — решение создателя 2026-09-25 при приёмке). Обычным игрокам
  строку не показывать.

### DoD

## Инцидент при коммите (важно)

Параллельный процесс в момент коммита кода восстановил в индексе свой набор правок
(снятие git-заморозки), и коммит `286e74c` «подхватил» их: `.opencode/context.md`,
`CHANGELOG.md`, `docs/TAILS.md` и идею `2026-09-25_очистка-галактики-ложная-ошибка-пакман-ест`.
Данные не потеряны, но коммит смешанный. Корень: коммит берёт общий индекс, куда
пишут все агенты. Обход: коммитить `git commit -- <явные пути>`, тогда чужие
staged-файлы в коммит не попадают.

## Ретроспектива (правка применена)

- **Корень:** коммит из общего индекса при нескольких параллельных агентах —
  чужие `git add` попадают в чужой коммит (смешение задач, горячие доки в коммит
  кода).
- **Дельта в `.opencode/agents/manager.md`:** «Коммить явными путями **через
  pathspec**: `git commit -- <файлы>` (не `git add` + `git commit`); коммит берёт
  только указанные пути, чужие staged-файлы параллельных агентов в него не попадают.»
- **Ретроспектива: правка `.opencode/agents/manager.md` — применена 2026-09-25,
  коммит `a9ff997`** (отдельным явным «да» создателя).
