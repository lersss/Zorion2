## Принципы батчинга (согласовано с создателем)

- **Один инстанс = одна зона/файл.** Правки в одном месте — один разработчик,
  контекст переиспользуется.
- **Разные зоны — разные свежие инстансы.**
- **Крупные монолиты — всегда отдельный инстанс** (по одному), заранее дробим на
  подэтапы.
- **Пакет мелких = один разработчик → один прогон тестера → один гейт** («быстрый путь»).
- В ТЗ — только файлы и номера хвостов этого пакета, реестр не пересказывать.

**Хвост №87.** В шапке игрока строка «Статус полёта» печатала внутренние коды миров

**Исправлено:** сервер в ответе профиля аддитивно отдаёт названия обоих концов полёта

уже прочитанного «текущего мира» — лишнего запроса нет.
**Тесты:** серверные (названия концов + сохранность кодов; мир удалён) и клиентский
(функция вырезается из страницы и исполняется в Node; красный→зелёный).
**Ревью ревьюера:** ЧИСТО (инварианты многопользовательского режима не затронуты,
