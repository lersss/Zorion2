## Контекст

Всплыло при тестировании фикса #21a (разлогин). Параллельная правка (ролевая модель, спека 99.2.14) добавила функцию `bootstrapSkycomposer` во второй файл пакета `cmd/server/bootstrap.go`. Сборка/запуск **по явному файлу** компилирует только его — функция не видна.

## Воспроизведение (подтверждено менеджером 2026-09-14)

- `go build cmd/server/main.go` → ошибка `cmd\server\main.go:78:2: undefined: bootstrapSkycomposer` (падает)
- `go run cmd/server/main.go` → та же ошибка (это команда из run.ps1!)
- `go build ./...` → ok
- `go build ./cmd/server` → ok (так собирает Dockerfile)

## Где сломано

- `AGENTS.md` §2: `go build -o zorion-server.exe cmd/server/main.go` — команда сборки бинаря.
- `run.ps1:19`: `go run cmd/server/main.go` — команда запуска dev-сервера.

Тестер подтвердил: Dockerfile (сборка каталогом) работает.

## Причина

Go компилирует пакет целиком; сборка/запуск по отдельному файлу (`go build file.go`) — это «command-line-arguments», без остальных файлов пакета. Поэтому любой код, размещённый в `cmd/server/bootstrap.go`, ломает команды по явному файлу. Раньше (до появления bootstrap.go) `main.go` был единственным файлом в пакете — команды работали.

## Предлагаемое исправление (когда дозреет)

Заменить в:
1. `AGENTS.md` §2: `go build ./cmd/server` (или `go build -o zorion-server.exe ./cmd/server`).
2. `run.ps1`: `go run ./cmd/server`.

Либо переименовать пакет/перенести bootstrap в main.go (не рекомендую — файл уже большой, AGENTS.md §4.8: файл >200–300 строк делить).

## Критерий готовности

`go build cmd/server/main.go` → собирается без ошибок; либо команды в AGENTS.md/run.ps1 заменены на каталог-вариант и работают. (Выбор — по создателю.)
