# 22a. Баг: кнопка «Найти меня» не работает, когда текущий мир не задан

**Создано:** 2026-09-15
**Статус:** Новый
**Приоритет:** баг (🟡 — некритичный, чиним в этой же сессии; эталон создателя
задан ответами на уточнения, чисел баланса нет)

---

## Сырое пожелание (создатель, 2026-09-15)

> «Кнопка "найти меня" не работает потому, что текущий мир не задается. Надо
> попробовать починить автоустановку мира после любой генерации, и на всякий
> случай, если мир не задан, пусть кнопка "найти меня" хотя бы устанавливает
> вьюпорт карты на ближайшую планету»

## Уточнения (создатель, 2026-09-15)

1. «После любой генерации» = **генерация звёзд** (вселенной) **и генерация
   близнецов** (прогон гипотез).
2. Автоустановка мира — **только для роли `skycomposer`**.
3. Какой мир назначать: **лучше ближе к центру** галактики, но «можно
   сэкономить» — без сложного поиска.
4. Фоллбэк кнопки: «ближайшая планета» = **ближайшая звезда** (на карте миры/
   звёзды; у планет координат на карте нет).

## Диагностика (менеджер, факты из кода)

- **Кнопка:** `centerBtn` → `centerOnAgent()` (`web/static/js/map/navigation.js`).
  При пустом `state.currentWorldId` (строки 37–40) — `console.warn` и выход,
  кнопка «молчит». При полёте — центрирует по пути, ветка не зависит от мира.
- **Причина пустого мира:** `clearUniverseTx` (`internal/handlers/admin_universe.go:58`)
  делает `UPDATE users SET current_world_id = NULL WHERE current_world_id IS NOT NULL` —
  мир слетает у **всех** пользователей при генерации вселенной и при каждом
  прогоне гипотез (`runHypothesisJob` вызывает ту же функцию,
  `admin_hypothesis.go:119`). После генерации мир никому не назначается.
- При регистрации/входе мир тоже не назначается (ставится только по прибытии
  полёта, `travel_handlers.go`).
- Роли: `player` / `admin` / `skycomposer` (`internal/models/user.go:10-12`).

## ТЗ

**1. Автоустановка мира после генерации (бэк).**
После успешной генерации вселенной (`GenerateUniverse`, `admin_universe.go`) и
после успешного прогона близнецов (`runHypothesisJob`, `admin_hypothesis.go`)
пользователям с ролью `skycomposer`, у которых `current_world_id` пуст,
назначить текущий мир:
- выбираемый мир — из сгенерированных, желательно ближе к центру галактики;
  «можно сэкономить»: дешёвый запрос (например, ближайший к (0,0) по
  координатам), без точного поиска центра;
- если миров в БД нет — ничего не назначать;
- у пользователей с уже заданным миром его **не трогать** (условие `IS NULL`).
- Техместо — на усмотрение @developer: один общий хелпер для обоих путей,
  желательно в той же транзакции (до commit), семантика «мир вернулся после
  генерации» атомарна.

**2. Фоллбэк кнопки «Найти меня» (фронт).**
В `centerOnAgent()` (`web/static/js/map/navigation.js`):
- если `currentWorldId` не задан **или** мир не найден в кэше — центрировать
  вьюпорт на **ближайшей к центру экрана звезде** из уже загруженных
  (`state.worlds` / `state.clusters`);
- если загруженных звёзд нет вовсе — на выбор @developer: ничего не делать или
  понятный тост (на гейте показать создателю);
- поведение при полёте (п.1 текущего кода) не меняется.

## Критерии готовности

- После генерации вселенной у `skycomposer` без мира в БД появляется
  `current_world_id` (ближайшая к центру звезда); у остальных ролей — как было;
  у `skycomposer` с уже заданным миром — не меняется.
- После прогона близнецов — то же.
- Кнопка «Найти меня» при пустом мире центрирует карту на ближайшей звезде;
  при заданном мире — работает как раньше (мир + полёт).
- DoD по `AGENTS.md` §2 (Go затронут: `go build` / `go vet` / `go test ./...`;
  фронт: `node --check`).
