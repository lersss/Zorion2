**Статус:** Готово (2026-09-15)
**Приоритет:** фича

## Сырое пожелание (создатель, 2026-09-15)

> «Нужно сделать генератор агентов. Наверное, им нужно свой генератор имён
> (имя-фамилия), англоязычных. В админке, просто указанием количества. Хочу
> протестировать на большой галактике как они себя ведут в количестве 10-50-100к»

## Контекст (факты из кода/спек)

- NPC-агенты уже реализованы (идея `20a`, спека `docs/specs/_archive/20a.1-npc-agents-v1.md`):
  таблица `npc_agents`, планировщик `internal/npc/manager.go`, позиции in-memory,
  вкладка «NPC» в админке (`web/static/js/admin/npc.js`,
  `internal/handlers/admin_npc.go`). Архитектура рассчитана на сотни тысяч агентов.
- У агента уже есть поле `name` (вводится вручную при одиночном создании).
  Отдельного генератора имён нет. Массовой генерации нет — только по одному.
- Генераторы имён живут в `internal/names/` (звёзды, планеты, фракции, товары,
  спутники; слоговый подход уже используется для планет).
- Новых сущностей/таблиц НЕ требуется: пишем в существующую `npc_agents`.

## Решения создателя (2026-09-15)

| Параметр | Решение |
|----------|---------|
| Имена | **(б)** Слоговый генератор «звучит как английское», имя-фамилия; гарантированная уникальность до больших чисел (100к+) |
| Режим | **«Добавить N»** — ввёл число, создалось ровно столько новых (не «заполнить до N») |
| Стартовые миры | **Случайные по всей галактике** (видно поведение на большой карте) |
| Лимит count | **Без лимита** (валидация только count ≥ 1; защита от ошибок — на фронте) |
| Список агентов в админке | **Постраничный** (пагинация) — при 100к полный список каждые 10 с тяжёлый |
| «Найти агента» | **Кнопка поиска агента на карте** — найти агента (по имени/id) и показать на карте (центрирование) |
| Пуши | **Общая галка на всех агентов** (глобальный рубильник уведомлений), **по умолчанию выключена** — при 100к флуд недопустим |
| Метрики | **Включить в фичу** — инструмент замеров поведения (время генерации пачки, очередь на тик, лаги планировщика) |

## ТЗ кнопки «удалить всех агентов» (для @developer)

- Эндпоинт: массовое удаление всех `npc_agents` (согласовать с паттерном `/admin/clear`),
  атомарно, эффективно (один DELETE без WHERE; не 100к одиночных).
- Фронт: кнопка во вкладке «NPC» рядом с генерацией, **confirm** («Удалить ВСЕХ агентов (N)?
  Необратимо»), показ количества удалённых.
- Согласованность: 409 если идёт джоб генерации; очистить in-memory позиции (PositionCache),
  сбросить `last_bulk` в метриках.
- Тесты (sqlmock) + DoD.

## ТЗ (черновик для @designer)

1. **Генератор имён агентов** в `internal/names/` (новый файл, напр. `agent.go`):
   слоговый, имя + фамилия, англоязычное звучание, уникальность «имя-фамилия»
   гарантирована до больших чисел (комбинаторное пространство ≫ 100к).
2. **Массовая генерация**: кнопка + поле количества во вкладке «NPC» админки;
   создаёт N агентов со сгенерированными именами, стартовый мир — случайный по
   галактике, статус `idle` (подхватывает планировщик). Эффективность: для 100к —
   batch/COPY, а не 100к одиночных INSERT.
3. **Метрики поведения**: минимальный инструмент замеров — время генерации пачки
   (отклик в админке), очередь на тик / лаги планировщика, видимость в админке.
   Объём — по разумному минимуму, без городилов.
4. Границы: не трогать механику полёта/наблюдения (20a), не менять API-контракт
   `/api/npc/positions`, не трогать числа баланса полёта.

## Критерии готовности (черновик)

- 100к агентов генерируются за приемлемое время (без минутных блокировок админки),
  имена уникальны, агенты разлетаются по галактике.
- Метрики показывают: время генерации, очередь/лаги тика.
- DoD: `go build ./...`, `go vet ./...`, `go test ./...` зелёные.

## Итог (2026-09-15)

Спека `docs/specs/_archive/26a.1-bulk-npc-generation.md` (доработана по правкам создателя).
Реализовано и проверено тестером (2 прогона, «можно сдавать»), одобрено создателем:

- Генератор имён `internal/names/agent.go`: слоговый «Имя Фамилия», ~7 млн пар,
  уникальность между пачками (seed из БД), fallback `Agent-XXXX` недостижим.
- `POST /admin/npc/generate {count}`: фоновый джоб, COPY-вставка одной транзакцией
  (10к за ~0,2 с), без верхнего лимита (count ≥ 1), 202/400/409, стартовые миры
  случайные по галактике (O(1) через `worldGrid.allIDs`), статус `idle`.
- Пагинация `GET /admin/npc?limit&cursor`: keyset `(created_at,id)` DESC, свежие
  сверху; миграция `000029_npc_indexes.sql`.
- Поиск на карте `GET /api/npc/search?q&limit`: UUID → точный, иначе ILIKE;
  позиции из снапшота; поле на карте, центрирование, подсветка, мини-список.
- Пуши: глобальный рубильник `notify_enabled_global` (дефолт off, после рестарта
  off), гейт «рубильник И per-agent» в единственной точке; дефолт новых агентов
  `notify_enabled=false`.
- Метрики `GET /admin/npc/metrics`: живой COUNT `overdue_arrivals`, in-memory
  `last_tick_ms`/`full_batches`/`last_bulk`.
- Кнопка «удалить всех агентов»: `POST /admin/npc/clear` → `{"deleted": N}`,
  409 при идущем джобе, очистка PositionCache сразу (без призраков), сброс
  `last_bulk`; confirm с числом на фронте.
- Доработки создателя: имена агентов на карте убраны полностью; тултип по
  rollover вместо клика (клик проходит к звезде).
- DoD зелёный (build/vet/test), dev-сервер перезапущен, БД почищена тестером.
- 🟢 хвосты: wildcard `%`/`_` в поиске не экранируется (приемлемо, на потом);
  `AGENTS.md` §1/§5 устарели (админка на JWT-ролях) — дельта диспетчеру;
