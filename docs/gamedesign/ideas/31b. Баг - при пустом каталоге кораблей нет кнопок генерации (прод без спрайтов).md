# 31b. Баг: при пустом каталоге кораблей нет кнопок генерации (прод без спрайтов)

## Диагностика (менеджер, факты)

- **Спрайты кораблей не файлы.** Клиент собирает их из каталога деталей
  `ship_parts` (БД), получаемого по `GET /api/ship-parts` (`ship_render.js`,
  спека 99.2.15). Каталог наполняется ТОЛЬКО ручной генерацией из админки
  (вкладка «Корабли», «теневой генератор» — `admin_ship_parts.go`); сида в
  миграциях нет (`000027` создаёт пустую таблицу).
- **Локаль (БД `127.0.0.1:5432/zorion`):** каталог наполнен — **69 деталей,
  5 категорий** (hull 10, nose 20, wings 10, engine 9, tail 20) → спрайты видны.
- **Прод (Amvera `zorion-game-skycomposer.amvera.io`):** сервер свежий
  (`GET /api/ship-parts` → 401 — маршрут 24a есть; статика отдаёт вкладку
  «Корабли»), но каталог в прод-БД, судя по симптомам, пуст (генерацию в
  админке прода никто не проходил).
- **Следствия пустого каталога на проде:** (1) агенты на карте = фолбэк-ромбы
  вместо кораблей (И4, «спрайтов не видно»); (2) вкладка «Корабли» показывает
  только hint «Каталог пуст…» — **кнопки ``＋1``/``＋10`` не отрисованы** из-за
  раннего `return` в `renderCategories()` (`web/static/js/admin/ships.js`,
  стр. 243–245): категории с кнопками генерируются только из непустого
  каталога → «категорий деталей нет», «нет раздела генерации деталей» —
  тупик: начать генерацию из UI с пустого места нельзя.
  На локалке каталог наполнен, поэтому кнопки видны.
- **Способ проверки бага:** `ships.js` `renderCategories()`:
  `if (state.parts.length === 0) { root.innerHTML = hint; return; }` — ранний
  выход до рисования категорий.

## ТЗ

Одна правка в `web/static/js/admin/ships.js`, функция `renderCategories()`:
при пустом каталоге НЕ выходить рано — рисовать категории
(`state.layerOrder`: Корпус/Нос/Крылья/Двигатели/Хвост) с кнопками
`＋1`/`＋10`/`↻ Перегенерировать` и счётчиком «0 форм» всегда; hint «Каталог
пуст…» оставить подсказкой над списком категорий. Поведение при непустом
каталоге не менять. Больше ничего не трогать (хирургически).

## Критерии готовности

- При пустом каталоге вкладка «Корабли» рисует 5 категорий, у каждой — поля
  «0 форм» и кнопки `＋1`, `＋10`, `↻ Перегенерировать`.
- При непустом каталоге отрисовка идентична прежней (90 diff-строк не
  затронуты).
- Go/сервер не менялись; JS-синтаксис зелёный (`node --check`).
- Остальные вкладки админки не затронуты.

## Реализация (2026-09-15)

`web/static/js/admin/ships.js`, `renderCategories()`: убран ранний `return`
при `state.parts.length === 0`; hint «Каталог пуст. Сгенерируйте первые
детали кнопками «＋10» ниже.» выводится над списком категорий; категории из
`layerOrder` рисуются всегда (пустая категория — «0 форм» + кнопки).

## Вердикт @tester (2026-09-15)

**ПРОЙДЕНО.** `node --check` зелёный; песочницы Node (пустой и непустой каталог,
фейковый DOM): пустой → hint ПОВЕРХ + 5 блоков категорий с «0 форм» и кнопками
`＋1`/`＋10`/`↻ Перегенерировать`; непустой → рендер идентичен прежнему. Живые
API: `GET /api/ship-parts` → 200 (parts 69, palette 12, layerOrder 5),
`GET /admin/ship-parts` → 200 (все 6 ключей, совпадают с ожиданиями `ships.js`).
Краевой случай: «↻ Перегенерировать» на пустой категории — серверный хендлер
безопасен. Блокеров нет. Оговорки: (1) в `ships.js` ещё 2 косметические правки
масштаба ≈34px→≈9px — работа идеи 30b, не часть этого фикса; (2) пустой каталог
вживую не проверялся (живой прогон, пишущий в БД, запрещён на параллельной
работе — AGENTS §23), проверено логикой; (3) UX в браузере — финальный взгляд
создателя (F5 на вкладке «Корабли»). Предложен регрессионный кейс B-ADM-6.

## Операционный шаг на проде (для создателя)

После деплоя фикса: админка прода → «🚀 Корабли» → `＋10` на каждой из 5
категорий → спрайты агентов на карте появятся без рестарта (каталог
перезагружается сам). Минимум 10 форм на категорию (спека 99.2.15).
