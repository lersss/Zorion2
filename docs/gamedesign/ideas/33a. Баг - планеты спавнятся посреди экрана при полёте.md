# 33a. Баг — планеты «спавнятся» посреди экрана при полёте

**Создано:** 2026-09-15
**Статус:** Выполнено (2026-09-15, менеджер — баг, быстрый путь). Ожидает одобрения создателя + коммит по «го».
**Приоритет:** баг (визуальный, 🟡)

---

## Суть

При старте полёта всё прогружено, планеты на месте. В процессе движения и
по прибытию игрок часто «прибывает в пустое место», и планета появляется
прямо под кораблём (в центре экрана). Ощущение — «спавн» объектов на глазах.

## Механизм (из кода, 2026-09-15)

1. **Прибытие** (`web/static/js/map/animation.js:18-24`): при `elapsed >= flyDuration`
   вызывается `loadUserData(true)` → **`centerOnAgent()`** (центрирует камеру на
   пункте назначения по СТАРЫМ кластерам) → затем `loadClusters()`. Камера встаёт
   на пустую зону, и только потом приходят кластеры цели — планеты «материализуются»
   под кораблём. Нужен порядок: сначала данные, потом центр.

2. **Движение** (`web/static/js/map/data.js:59-74` `maybeReloadClusters`): запрос
   идёт на **текущий** вьюпорт с ограничением: интервал 600 мс + порог 25% края.
   Корабль в полёте движется по миру (scale ≥ 1.0), камера следует за ним; пока
   запрос летит (сеть ~100-300 мс + задержка 600 мс), камера уезжает дальше →
   перед носом корабля полоса не запрошенной местности. Звёзды появляются с лагом
   и в т.ч. в центре экрана (под кораблём). B17 закрыл лишь факт подгрузки
   во время полёта, но не опережение.

## Правка (ТЗ для @developer)

Только фронт, хендлеры/API/БД не трогать. Хирургично, без рефакторинга.

1. `web/static/js/map/animation.js` — ветка прибытия: сначала
   `loadUserData(true)` и `loadClusters()` зоны прибытия, **потом** `centerOnAgent()`.
   Камера остаётся на последней полётной позиции (она ~у цели), пока грузятся
   данные — не давать кадр пустоты с отцентрованной камерой.

2. `web/static/js/map/data.js` — `maybeReloadClusters` в полёте: запрашивать
   вьюпорт, **смещённый вперёд по курсу** (направление `flyFrom → flyTo`),
   с запасом ~1.5 с полёта (скорость = дистанция/flyDuration), чтобы следующая
   зона была загружена до прилёта, а не «под носом». Вне полёта — поведение
   без изменений.

3. Никаких новых сущностей/таблиц/запросов к API. Тот же `/api/worlds/filter`.

**Ограничения:** не ломать hand-панораму/зум (поведение вне полёта прежнее);
не плодить запросы сверх гарда 600 мс; стиль соседних строк.

## Реализация (developer, 2026-09-15, 2 итерации)

1. `web/static/js/map/animation.js` (строки ~18-26) — ветка прибытия:
   `loadUserData(true)` → `loadClusters()` → `centerOnAgent()` (было: центр ПЕРЕД
   загрузкой, кадр пустоты). Камера на последней полётной позиции (~у цели)
   грузит зону прибытия и центрируется по загруженному миру.

2. `web/static/js/map/data.js`:
   - `loadClusters(boundsOverride = null)` — опциональные границы; дефолт —
     текущий вьюпорт, поведение прежнее для всех вызовов без аргументов
     (`main.js`, `search.js`, `animation.js`, `scheduleReload`, `loadData`).
   - `getFlightBounds()` (строки ~190-208) — ОБЪЕДИНЕНИЕ текущего вьюпорта и
     смещённого вперёд по курсу на `speed*1.5` (union по min/max): экран не
     пустеет, полоса впереди грузится до прилёта. `dist=0` защищён (`|| 1`),
     вне полёта — чистый вьюпорт.
   - `maybeReloadClusters()` — сравнение границ и сам запрос по одной
     расширенной зоне: `loadClusters(getFlightBounds())`. Гард 600 мс и порог
     25% не тронуты; частота запросов даже ниже прежней (порог вырос).
   _Замечание менеджера на 1-й итерации:_ `maybeReloadClusters` сравнивал по
   смещённым границам, но зовул `loadClusters()` без аргументов — грузилась
   зона ПОД кораблём, а не впереди. Исправлено на union-границы в запрос.

## Проверка

- `node --check` на обоих файлах — ок (менеджер + разработчик).
- Go: правок нет, `go build/vet/test ./...` зелёные (прогнал developer, бонус).
- **Тестер (2026-09-15): вердикт ОК.** Статически: порядок прибытия верен,
  полётная зона — union, B17 не сломан, лишних запросов нет. API на расширенную
  зону отвечает 200 (41 кластер против 12 обычных), статика с noCache.
  Оговорка: визуальные кадры в браузере тестер прогнать не может — проверка
  создателем.
- Найденное (не блокеры, предсуществующее): (1) гонка `loadingData` на кадре
  прибытия — если полётный fetch ещё идёт, `loadClusters` на прибытии ставит
  `pendingReload` и центр встанет на +180 мс (последняя полётная зона покрывает
  цель — практически безвредно); (2) `lastFlightReloadAt` не сбрасывается между
  полётами — новый полёт в пределах 600 мс пропустит первую подгрузку.

  на месте сразу, без кадра пустоты и «спавна» в центре; после прибытия
  панорама/зум работают без рывков.
