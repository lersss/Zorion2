# 44a. Процесс — коммит-ответственность команд, горячие доки только дельтами

**Создано:** 2026-09-15
**Статус:** процесс (ждёт внесения через @dispatcher по «го»)
**Приоритет:** процессный

---

## Суть

Текущее правило «Git ведёт только один агент» (AGENTS.md §4.10, §4.21:
@dispatcher — единственный git-владелец) создаёт **дыру**: команды сдают
задачи по гейтам, но их правки не коммитятся — всё накапливается в рабочей
копие, пока @dispatcher «не разгребёт» (часами). Доклад создателя
(2026-09-15): «несколько команд вносят правки, потом диспетчер несколько
часов это разгребает. Нужен механизм, в котором команды закрывают свои
задачи».

## Решение создателя (2026-09-15)

1. **Коммит-ответственность на команды** — команда (менеджер/разработчик)
   сама коммитит **свой код** в свою зону файлов. Коммит — явными путями
   (`git add <свои файлы>`, без `git add -A`, AGENTS.md §4.7), после
   подтверждения гейта создателем.
2. **Горячие доки — только дельтами на @dispatcher.** Их команды не правят
   напрямую и не коммитят: единый источник истины, один писатель
   (AGENTS.md §4.22). Дельты сдаются в момент сдачи задачи — это не
   «висящая работа», диспетчер применяет механически в паузу.
3. Раздача задач по **разным зонам файлов** (создатель старается давать
   командам разные части кода) → конфликтов в коде почти нет, те что есть —
   на мерже у @dispatcher.

## Принципиальное различие (зафиксировано)

- **Код** — зоны команд: каждая команда коммитит своё сама.
- **Горячие доки** (`STATUS.md`, `docs/INDEX.md`, `99_roadmap.md`,
  `faq_counter.md`, `CHANGELOG.md`, `AGENTS.md`, `.opencode/CONTEXT.md`) —
  общая зона, один писатель @dispatcher, команды сдают дельтами.
- @dispatcher остаётся **владельцем мержа и горячих доков** (создатель
  вызывает его «@dispatcher, разнеси дельты»), но перестаёт быть
  единственным, кто коммитит код.

## Кто что коммитит (схема по этапам, решение создателя 2026-09-15)

Команда коммитит свои артефакты **по гейтам**, а не одной кучей в конце:

| Этап | Что создано | Кто коммитит | Когда |
|---|---|---|---|
| Дизайн-гейт | спека (+ идея) | **менеджер** | после «го» создателя на дизайне |
| Разработка-гейт | код + тесты | **developer** | после «го» создателя на разработке |
| Сдача | идея (статус, дельты) | **менеджер** | после финального «го» |
| Горячие доки | дельты | **только @dispatcher** | в паузу |

Принципы:
- **Менеджер коммитит артефакты своей команды** (идеи, спеки — он их
  автор/владелец), **developer коммитит код** своей зоны.
- Ограничение: менеджер коммитит **только файлы своей команды** (идея,
  спека) и никогда — горячие доки, чужой код, чужие зоны. Тот же принцип
  «своя зона — свой коммит».
- Спеки/идеи — артефакты команды (у каждой свой файл), **не** горячие доки:
  через диспетчера дельтами не гонятся (это вернуло бы узкое место).
- Коммит **не заменяет гейт**: следует за явным «го» создателя. Менеджер
  включает коммит в предложение на гейте («по "го" закоммичу пачку и сдам
  дельты») — одно «го» покрывает приёмку и коммит (AGENTS.md §4.2). Хочет
  посмотреть дольше — «пока не коммить», коммит висит до отдельного «го».

## Что НЕ меняется

- Горячие доки по-прежнему пишет только @dispatcher (менеджер не порождает
  его, не коммитит доки, не мержит).
- Гейты менеджеров остаются: после этапа — ждём «ок/го» создателя; коммит
  следует за «го», не обходит его.
- `git add -A` запрещён всегда (AGENTS.md §4.7).
- Пуш — по-прежнему только через @dispatcher / с разрешения создателя.
- Дизайнер/тестер/графдизайнер/баланс-тестер не коммитят (их артефакты
  коммитит менеджер/developer по схеме выше).
