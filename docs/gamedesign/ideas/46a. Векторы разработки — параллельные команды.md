## 0. Откуда взято (не из роадмапа — из кода)

Векторы выделены по **графу зависимостей Go-пакетов и общим точкам правок**, а не по роадмапу. Факты:

- Подсистемы уже разнесены по пакетам и почти не импортируют друг друга:
  - `internal/generator/galaxy` + `internal/astro` → только `models`/`names`/`astro`
  - `internal/npc/*` → только `mapcache`/`models` (самодостаточен)
  - `internal/generator/ship` + `ship_*` → только `models`/`names`
  - `internal/generator/planet` + `audit/planet` → связаны с `settlement` и `resource`
  - `internal/economy/settlement` + `settlement`-генератор + `planet_repo`/`economy_repo`/`galaxy_population`
- **Горячие точки (пересекутся все вектора, неизбежно):**
  1. `internal/models/*` — каждая фича расширяет модели (файлы уже разнесены: `npc_agent.go`, `ship_visual.go`, `economy.go`, `planet.go` — отдельные).
  2. `internal/repository/*` — тоже разнесён по файлам.
  3. `migrations/` — **общая нумерация**, последняя `000032`. Реальные конфликты, если два вектора добавляют миграцию в одном релизе.
  4. `cmd/server/main.go` — регистрация всех маршрутов + инициализация всех менеджеров.
  5. `web/static/js/admin/{tabs.js, main.js, admin.html}` — регистрация вкладок админки.
  6. Стык `planet ↔ settlement`: `planet_data_generate.go`, `descriptions_tags.go`, `properties.go` импортируют settlement — Вектор A и B могут тут столкнуться.
- Каркас игровой петли в коде есть, но это каркас, не механика:
  - Контракты: `Assignment` (open/taken/completed), `GetContracts/TakeContract/CompleteTestContract`; **нет эскроу, поставок, возврата, охраны**.
  - Полёт: `TravelManager` реальный (старт/отмена/прибытие, `onArrival`); дальше — пусто.
  - Добыча / сдача / «мир изменился»: **нет** — нет инвентаря/груза игрока, нет денег (только дизайн `14_money.md`), нет реакции мира.

- **R3:** «Мир изменился» — сдача контракта влияет на поселение (рост/товар), территория реагирует; карточка поселения показывает эффект.
- **R4:** 99.2.8 Автозаводы и присутствие (автозавод как постройка, присутствие как контракт) — по спеке.
- **R5:** 99.2.7 полная модель контракта: охрана, поставки, возврат, операции (по спеке) + 99.2.9 Сеть ретрансляторов (до 1.0, отдельная подсистема в том же векторе).

## 3. Правила развязки на горячих точках

1. **Миграции — бронь номеров через @manager.** Последняя `000032`. Вектор, которому нужна таблица/колонка, берёт номер в `COORDINATION.md` до начала работы. Два вектора одну миграцию в одном релизе не добавляют.
2. **`cmd/server/main.go` — только свои блок-секции.** Каждый вектор добавляет маршруты + инициализацию своего менеджера отдельным блоком; общую часть не трогает.
3. **Вкладки админки — один JS-файл на фичу** (паттерн AGENTS.md §4.23), в `tabs.js`/`admin.html`/`main.js` — точечные вставки (импорт + кнопка + pane), «добавил в конец, не переписал».
4. **Стык `planet ↔ settlement` (A vs B)** — назначаем владельца общего файла на релиз; второй вектор в этот релиз туда не лезет. (Буфер-интерфейс — отдельный рефакторинг, не сейчас.)
5. **Общие модели/репо** — каждый вектор трогает только свои файлы; нужна правка чужого — через дельту/меня, не напрямую.
