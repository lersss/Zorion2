## Диагностика (менеджер, факты)

- Ошибка в ночном логе сервера (03:37:29) и в логе PostgreSQL:
  `ERROR: column "type" does not exist at character 66` +
  `STATEMENT: SELECT ... title, description, type, reward, ... FROM assignments WHERE world_id = $1 AND status = 'open'`.
- Схема `assignments` (проверено в БД): колонок **`type` и `reward` НЕТ**.
  Есть: id, world_id, author_type, author_id, title, description, expires_at,
  status, effects, created_at, updated_at.
- Миграция `000010_assignments_type_reward.up.sql` (ALTER TABLE ... ADD COLUMN
  IF NOT EXISTS type/reward) **числится применённой** в schema_migrations
  (applied_at 2026-09-11 14:07:03), но колонки в БД отсутствуют — кто-то удалил
  их вручную позже (комментарий в миграции прямо предупреждает: «IF NOT EXISTS —
  если раньше уже применялась через DBeaver»).
- Код (`internal/repository/assignment_repository.go`) запрашивает `type`/`reward`
  в трёх местах: `Create` (INSERT), `GetByID` (SELECT), `GetByWorldWithFilters`
  (SELECT + фильтры). Падают все.
- Побочно: сервер ранее был поднят на пустой базе (ошибка менеджера с каталогом
  PostgreSQL) — это объясняло «слетевший пароль», но не этот баг.

## ТЗ

1. **Миграция** `migrations/000035_restore_assignments_type_reward.sql`
   (по образцу 000010, идемпотентно):
   ```sql
   ALTER TABLE assignments
       ADD COLUMN IF NOT EXISTS type text NOT NULL DEFAULT 'unknown',
       ADD COLUMN IF NOT EXISTS reward integer NOT NULL DEFAULT 0;
   ```
2. Код менять НЕ нужно — он уже ожидает эти колонки (Type/Reward в
   `models.Assignment`).
3. Применить миграцию, проверить: `\d assignments` показывает type/reward;
   `GetByWorld` перестаёт падать (проверка через открытие мира или SQL-запрос).
