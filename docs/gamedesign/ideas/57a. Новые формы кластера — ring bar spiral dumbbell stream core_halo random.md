## ТЗ

### Формы (7 новых значений Shape)

> **Итерация параметров (решение создателя 2026-09-16):** «чтобы читалось, но не
> бросалось в глаза». Изначальные параметры (ringR 0.65–0.7R, толщина 0.15R и др.)
> давали формы, которые на карте читались слабо (кольцо выглядело «пятном с
> дыркой»). Параметры скорректированы на умеренно выразительные (ниже).

1. **ring** — кольцо: средний радиус ≈ 0.75–0.8×radius, толщина (std) ≈ 0.10×radius,
   центр пустой. r = ringR + gaussian(ringThickness), angle = uniform.
2. **bar** — перемычка: вытянута вдоль случайной оси (угол поворота роллится на
   кластер), std вдоль оси = 0.85×radius, поперёк = 0.12×radius. Генерация в
   локальных координатах → поворот на угол.
3. **spiral** — спиральный рукав (один): r(θ) = radius × (θ/θ_max), θ ∈ [0, 2.5π],
   ширина рукава (std по нормали к спирали) ≈ 0.07×radius, случайный поворот
   кластера.
4. **dumbbell** — две доли: два гауссовых очага на ±0.65×radius от центра вдоль
   случайной оси, std каждого ≈ 0.25×radius, точки делятся ~50/50.
5. **stream** — цепочка/поток: 2–4 очага вдоль плавной дуги от центра, std очага
   ≈ 0.18×radius, шаг очагов ≈ 0.45×radius, случайный изгиб и поворот.
6. **core_halo** — ядро + гало: 75% точек — ядро (std = 0.18×radius), 25% — гало
   (std = 0.55×radius), оба вокруг центра.
7. **random** — режим, не форма: для каждого кластера случайно выбирается одна
   из остальных 8 форм (blob, circle, ring, bar, spiral, dumbbell, stream,
   core_halo). Выбор — через g.rng в момент генерации кластера (детерминизм по seed).

### Инварианты всех форм (как у существующих)

- Соблюдение minDist — отбор отбрасыванием (`isPointValid` / `spatialGrid`).
- `clusterEdgeAccept(cx, cy, x, y, radius)` — точки в пределах 1.25×radius от
  центра кластера.
- `galaxyEdgeAccept(x, y)`.
- Детерминизм по seed (общий `g.rng` генератора).
- Не ломать blob/circle и существующие пресеты.

### Добивка — генерация остатка в форме кластера (решение создателя 2026-09-16)

Проблема: добивка кластерных точек (`generateWorldsPoisson`, poisson.go ~160–198)
генерирует недобранные точки **гауссом вокруг центра региона** (std = радиус),
независимо от формы. Для не-blob форм с плотным minDist (например, spiral) рукав
физически не вмещает все точки → остаток заливается гауссом и размазывает форму
(end-to-end спираль читается лишь у ~15% точек). Итерация параметров (ширина рукава
0.1R→0.07R) усугубила (57%→40% точек в рукаве).

Решение (создатель: «форма должна читаться при изучении, но не бросаться в глаза
сама по себе»): **добивка генерирует точки в той же форме кластера**, к которому
они приписываются.

- Вынести выбор формы из `clusterPoints` (сейчас при random выбирается внутри) в
  `generateWorldsPoisson`: для каждого кластерного центра заранее определить форму
  (random → `g.rng` из 8 форм) и запомнить её (массив по индексу центра). `clusterPoints`
  принимает форму параметром.
- Выделить генератор «случайной точки формы» (без проверок) из каждой `clusterPoints*`
  и переиспользовать его и в `clusterPoints*`, и в добивке.
- Добивка: для региона генерировать кандидата **в форме региона**, проверять
  `clusterEdgeAccept` + `galaxyEdgeAccept` + глобальный `grid.HasNear` (minDist).
- Умеренность: добивка продолжает форму естественно (не раздувает, не создаёт
  резких колец/линий) — форма читается при изучении на зуме, но не бросается сама
  по себе. Детерминизм по seed сохраняется. Инварианты (1.25R, minDist) — прежние.
