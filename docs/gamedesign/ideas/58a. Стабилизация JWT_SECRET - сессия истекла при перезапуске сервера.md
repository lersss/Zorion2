# 58a. Стабилизация JWT_SECRET — «сессия истекла» при перезапуске сервера

**Статус:** Готово (2026-09-16). Гейт создателя: «го» на план.

## Сырое пожелание (создатель, 2026-09-16)

> «какой срок сессии? слишком часто вижу "сессия истекла, зайдите заново"»
> «часто — это несколько раз в час. Возможно связано с перезапуском сервера»
> «Я вообще руками не запускаю сервер, это делают агенты»

## Диагноз (менеджер, факты из кода и логов)

1. **Срок сессии — 24 часа** (TTL JWT, `internal/auth/jwt.go:89`). Других сроков нет.
2. **По логам `server_stderr.log` (15.09):** истечений по сроку — **0** (`expired: 0`);
   «сессия истекла» = 4 × `token signature is invalid`. То есть все сбои — токен,
   подписанный **другим секретом**, чем у работающего сервера.
3. **Локальные источники секрета стабильны:** `.env` и `run.ps1` содержат
   одинаковый секрет (сравнены по SHA-256), оба не менялись с 10.09. `godotenv.Load()`
   вызывается ДО `config.Load()` (`cmd/server/main.go:41-49`) — рестарт сам по себе
   секрет не меняет (фикс старого бага 21a, `docs/PITFALLS.md`).
4. **Причина «плавания»:** сервер запускают агенты по `AGENTS.md` §1, где стоит
   плейсхолдер `$env:JWT_SECRET = "минимум-32-символа"` (18 символов — **невалиден**,
   сервер с ним не стартует). Агент подставляет своё значение — у каждого запуска
   своё. Заданный вручную env **перекрывает `.env`** (godotenv не перетирает уже
   заданные переменные). Каждый перезапуск с новым секретом мгновенно убивает все
   живые токены → «Сессия истекла — войдите снова» у всех залогиненных.
5. **Доказательство из лога:** 15.09 в 15:16:02 сервер стартовал, и ровно в эту
   секунду пришли 4 запроса со старым токеном — все `signature is invalid`; через
   2 секунды клиент перелогинился и дальше весь день токен жил без сбоев. Один
   перезапуск с чужим секретом = смерть всех сессий.

## ТЗ (утверждено создателем, «го» 2026-09-16)

1. **Правило запуска:** сервер — только через `run.ps1`, либо `go run` **без
   ручного `JWT_SECRET`** (тогда подхватывается стабильный секрет из `.env`).
2. **`AGENTS.md` §1** — заменить плейсхолдер на правило «JWT_SECRET вручную не
   задавать» (дельта → `@dispatcher`).
3. **`docs/DEPLOY.md` §2 Шаг 1** — убрать ручной пример `JWT_SECRET` (дельта →
   `@developer`, владелец документа).
4. **`.env.example`** — `JWT_SECRET` длиной 29 символов (< 32, по шаблону сервер
   не стартует) → валидный плейсхолдер ≥ 32 (делает менеджер, мелкая правка).
5. **TTL не меняем** — он не виноват (0 истечений по сроку).

## Реализация (2026-09-16, менеджер — быстрый путь; код не трогается)

1. **Менеджер:** `.env.example` — `JWT_SECRET=обязательный-минимум-32-байта` (29
   симв.) → `JWT_SECRET=замени-на-свой-секрет-не-короче-32-символов` (43 симв.,
   валиден ≥ 32).
2. **`@developer`:** `docs/DEPLOY.md` §2 «Шаг 1 — Задать переменные» — убрать
   строку `$env:JWT_SECRET = "минимум-32-символа-ключ-для-теста"` (провоцирует
   копипаст своего секрета), добавить примечание про `.env`/`run.ps1`.
