# 62a. Ретроспектива — агенты учатся на ошибках

**Создано:** 2026-09-16
**Статус:** процесс (ждёт внесения через @dispatcher по «го»)
**Приоритет:** процессный

---

## Суть

Пожелание создателя: научить агентов учиться на ошибках. Если проблема
вызывает слишком много итераций — агент сам находит причину, по которой
«подвисает» на задаче, и на гейте предлагает исправить это в промтах/рабочих
инструкциях.

Раньше при превышении бюджета итераций мы просто «выносили создателю», не
фиксируя, **почему** зависли, и не превращая причину в правку инструкций.

## Решение создателя (2026-09-16)

1. **Ретроспектива — автоматически при первом превышении бюджета итераций**
   (не ждать повторного сбоя: событий мало, один провал уже дорогой; шум
   фильтрует создатель на гейте).
2. **Область правок — только коммуникация и контекст** (неполные данные,
   неоднозначное ТЗ, отсутствующие критерии). Процессные правки (критерии
   гейта, DoD, порядок шагов) ретроспектива не предлагает — их инициирует
   только создатель.
3. **Правка инструкций не покрывается «ок» на гейте.** На гейте два
   раздельных решения: обычное закрытие задачи + отдельный максимально
   заметный блок с правкой инструкций (жирным, капсом, разделителями),
   который спрашивается **отдельным вопросом** штатным механизмом Opencode
   (один вопрос за раз) — чтобы создатель не мог «случайно» окнуть изменения
   вместе с гейтом.
4. Разовый сбой → создатель отклоняет правку; ретроспектива собирает данные,
   применять не обязана.

## Механизм (внесено в `.opencode/agents/manager.md`)

- Превысил бюджет (3) на этапе → **перед** выходом к создателю ретроспектива
  в файл идеи (раздел «Ретроспектива»): корень зависания (одна строка) +
  предлагаемая дельта (дословная формулировка, в конкретную инструкцию).
- Подача на гейте: закрытие задачи — обычный гейт; правка инструкций —
  отдельный заметный блок с вопросом «применить правку инструкций — да/нет?»,
  ждём явного ответа отдельно от гейта.
- Правило в «ПРАВИЛА»: общее «ок» на гейте никогда не считается согласием на
  правку инструкций.

## Что НЕ меняется

- Гейты, бюджет итераций, DoD — как были.
- «Ок» на гейте покрывает только закрытие задачи; правка инструкций — только
  отдельным явным «да».
- Процессные правки по-прежнему инициирует только создатель.
- Горячие доки — только дельтами на @dispatcher.

## Применённая правка (2026-09-17, зацикливание @tester)

**Корень зависания:** тестер зациклился ВНУТРИ одного пункта ТЗ (повторял один

был сменой итераций; открытое ТЗ с 3+ сценариями без критерия остановки.

**Дельта применена по явному «да» создателя (2026-09-17):**
1. `.opencode/agents/tester.md` (Лимиты): «Жёсткий чек-лист: при 3+ пунктах
   проверки выполняй каждый РОВНО ОДИН раз, не повторяй уже сделанные
   проверки (один grep на пункт). Заметил, что повторяешь один и тот же
   шаг/вывод — немедленно СТОП и доложи менеджеру: "зациклился на пункте X".»
2. `.opencode/agents/manager.md` (шаг 7 «Тест»): «ТЗ тестеру для прогонов с
   3+ сценариями — жёсткий чек-лист: каждый пункт один раз, фиксированный
   формат ответа (по слову/строке на пункт), явный критерий остановки.
   Открытое ТЗ "проверь по-всякому" для больших прогонов не давать.»

Оба файла инструкций правит менеджер по «да» создателя (не горячие доки —
коммит артефактов команды на сдаче).
