## Пожелание (создатель, 2026-09-17)

> «В перелёте если через некоторое время меняешь маршрут на мир, из которого
> вылетел, тебя мгновенно туда телепортирует.»

**Уточнение (создатель, 2026-09-17):** ожидаемое поведение — **разворот**: выбор
мира отправления во время полёта работает как обычная смена курса — корабль
разворачивается из текущей точки маршрута P и летит обратно с честной
длительностью (мин 3 сек). Мгновенно никто никуда не переносится.

## Диагноз (менеджер, факты из кода)

- `internal/handlers/travel_handlers.go:143–156` — особая ветка «возврат в мир
  отправления во время полёта»: `flight != nil && req.WorldID == fromWorldID`
  → `travelManager.CancelFlight(userID)` + 202 `{"status":"cancelled"}`.
  Полёт просто отменяется → игрок мгновенно «остаётся» в мире отправления A
  (current_world не менялся) — это и есть телепорт.
- Ветка добавлена фичей 61a (2026-09-16) как фикс «нельзя вернуться» (раньше
  выбор мира отправления в полёте давал 400 «Already in this world»).
  Решение «отмена полёта» — слишком резкое: возврат мгновенный, без честного
  времени, в отличие от любой другой цели (редирект из точки P).
- Любая другая цель в полёте уже работает как редирект: точка P =
  `redirectStartPoint(flight.StartX, flight.StartY, oldTo, elapsed, duration)`,
  длительность `dist(P, цель) × 0.3 сек` (мин 3). Мир отправления — единственное
  исключение, и исключение выглядит как телепорт.
- Фронт: `web/static/js/map/flight.js:107–114` — ветка `data.status === 'cancelled'`
  (скрыть панель, `isFlying = false`, «Текущий мир: A») — после фикса не нужна.

## ТЗ

**1. Сервер (`internal/handlers/travel_handlers.go`):**
- Убрать ветку «возврат = отмена» (строки 143–156) целиком: выбор мира отправления
  при активном полёте должен идти обычным путём редиректа (точка P → цель,
  `duration = dist(P, цель) × 0.3`, мин 3 сек).
- Проверка `fromWorldID == req.WorldID` («Already in this world», 400) остаётся
  только для случая БЕЗ полёта (порядок: сначала ветка редиректа/идемпотентности,
  потом 400).
- ВАЖНО: при редиректе на мир отправления `From == To == A` в ответе — проверить,
  что серверный путь это переживает без сюрпризов (onArrival обновит current_world
  на A — то же самое, что было; ничего не ломается).

**2. Фронт (`web/static/js/map/flight.js`):**
- Убрать ветку `data.status === 'cancelled'` (107–114) — редирект на мир
  отправления вернёт обычный TravelResponse.
- Проверить сценарий `from == to == A`: `ensureWorld(data.from)` и
  `ensureWorld(data.to)` вернут один мир; панель/шапка покажут «В полёте: A → A».
  Косметика — решить аккуратно (не ломать рендер); это мелочь, без гейта.

**3. Тесты (`internal/handlers/travel_handlers_test.go`):**
- Обновить тест возврата (сейчас: 202 cancelled, строки ~317–341): теперь ожидается
  редирект — полёт заменён, `to == A`, стартовая точка = P (прогресс учтён),
  `duration` честный.
- Регрессия: без полёта выбор своего мира → 400 «Already in this world» сохраняется.

## Критерии готовности

- В полёте A→B выбор A → корабль разворачивается из текущей точки P, летит обратно
  в A, время = `dist(P, A) × 0.3 сек` (мин 3), без телепорта.
- Полёт без смены цели, редирект на другую звезду, идемпотентность (та же цель),
  каскадный редирект — поведение 61a не изменилось.
- Без полёта выбор своего мира → 400 «Already in this world» (регрессия).
- DoD по `AGENTS.md` §2 (`go build`/`go vet`/`go test ./...`; фронт `node --check`).
