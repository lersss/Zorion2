# 72a. Недобор миров при генерации — MapSize не помогает (ёмкость кластеров)

**Создано:** 2026-09-17
**Статус:** ✅ Готово (сдано 2026-09-17). Пройдено: диагностика (менеджер, прогоны на 4 seed) → уточнение (создатель: minDist=200, «дело в размере кластера») → решение (minDist+50 в пресетах + компенсация) → гейт → разработка (@developer, generation.js) → DoD → тест (@tester, ОК). Коммиты: `ba99a0e` (правка пресетов).
**Вектор:** Генерация / Баги
**Приоритет:** высокий (🔴 текущий релиз)

## Пожелание создателя

При генерации вселенной (100000 миров, 200 кластеров, mapSize 120000, радиус
кластера 2500, расстояние между кластерами 5000, 20% выбросы, форма «случайная»)
админка пишет: «⚠️ Готово, но НЕДОБОР! Миров создано: 81287 из 100000».
Увеличение MapSize не меняет результат — недобор остаётся.

**Уточнение (создатель, 2026-09-17):** minDist в форме = 200. Гипотеза создателя:
«дело не в MapSize, а в размере кластера» — подтверждена.

## Диагноз (менеджер, прогон генератора 2026-09-17)

Проблема НЕ в MapSize и НЕ в лимитах попыток. Причина — **физическая ёмкость
территории кластера**.

- 200 кластеров × по 400 миров (100000 × 80% / 200) — на каждый кластер ложится
  400 миров.
- Территория кластера = круг радиусом 1.25 × clusterRadius (3125 при радиусе
  2500). При minDist D туда влезает ~(2.5×radius/D)² миров: при D=150 — ~1736
  (влезает), при D=200 — ~976 (впритык), при D=250+ — меньше 400 (не влезает).
- Форма «случайная» усугубляет: ~половина кластеров получает узкие формы
  (ring/bar/spiral/stream), ёмкость которых в разы меньше blob/circle — они
  физически не вмещают 400 точек при minDist ≥ ~190–200.
- **MapSize не влияет**: территория кластера задаётся clusterRadius, а не
  размером карты. Добивка (16 млн попыток) не помогает — некуда класть.

Прогон на текущем коде (HEAD), пресет создателя (minDist=200, seed 42/7):

| параметр | миров создано |
|---|---|
| как есть (cR=2500, md=200) | ~81287 |
| md=150 | 100000 / 100000 |
| cR=3000, md=200 | 100000 / 100000 |
| cR=3500, md=200 | 100000 / 100000 |
| cR=2500, clusters=300, md=200 | 100000 / 100000 |
| cR=2500, clusters=400, md=200 | 100000 / 100000 |

Дополнительно: при md=210 — 76135–76361; md=250 — 54746; md=300 — 49709;
md=350 — 42321. При cR=1500 (md=150) — 61463; cR=1750 — 74796; cR=2000 — 89496;
cR=2200+ (md=150) — полный добор. Воспроизводится на всех версиях кода (HEAD,
5f02fe5^, a80493e, 3620915) — это не регрессия, а свойство алгоритма.

## Варианты решения (на выбор создателя)

**Решение создателя (2026-09-17):** увеличить minDist (расстояние между
звёздами) на ~50 во всех пресетах как самостоятельное пожелание +
компенсировать, чтобы недобора не было.

## Подобранная компенсация (менеджер, прогон на 3–4 seed)

Проверка «minDist+50 без компенсации»: недобор в 8 из 14 пресетов (compact,
swarm, constellation, crossroads, archipelago, agglomeration, metropolis,
outskirts). Компенсация — радиус кластера ×1.1–1.2 (или mapSize для dense),
проверена на seed 42/7/123/999 — полный добор во всех прогонах:

| пресет | minDist | компенсация |
|---|---|---|
| dense | 120→170 | mapSize 40000→45000 |
| sparse | 150→200 | — |
| compact | 100→150 | clusterRadius 1600→1920 |
| prototype | 100→150 | — |
| swarm | 120→170 | clusterRadius 620→744 |
| frontier | 180→230 | — |
| constellation | 100→150 | clusterRadius 650→780 |
| crossroads | 110→160 | clusterRadius 1470→1764 |
| archipelago | 130→180 | clusterRadius 3950→4740 |
| outback | 160→210 | — |
| agglomeration | 110→160 | clusterRadius 1540→1848 |
| fararm | 150→200 | — |
| metropolis | 115→165 | clusterRadius 1580→1738 |
| outskirts | 140→190 | clusterRadius 3760→4136 |

Примечания:
- без компенсации minDist+50 ломает 8/14 пресетов (недобор до 92%);
- dense дополнительно: при mapSize 40000 случайная упаковка даёт лишь
  ~151 кластер из 200 (spacing 5000) — при md=170 не хватает; mapSize 45000
  стабилизирует (176–182 кластера, worlds полные);
- кластеры ×1.2 (вместо радиуса) — не хватает плотным пресетам, отклонено;
- компенсация радиусом неявно поднимает spacing до 2×radius — кластеры чуть
  дальше друг от друга, но worlds полные.

## Открытый вопрос

Дефолт поля minDist в форме генерации (сейчас 150) — тоже поднять до 200,
или изменения только внутри пресетов?

**Решение (2026-09-17):** дефолт формы НЕ менялся (создатель подтвердил только
пресеты; ручной ввод с minDist 200 без компенсации снова даст недобор — при
желании поднять дефолт, компенсацию для ручного ввода решать отдельно).
