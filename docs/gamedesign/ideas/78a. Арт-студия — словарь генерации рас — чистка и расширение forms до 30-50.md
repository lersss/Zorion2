## Пожелание создателя (2026-09-17)

> «Дальше: нужно посмотреть на описание рас (есть в отдельной папке) и УДАЛИТЬ из
> генератора картинок слова, которые прямо совсем не подходят по контексту
> (напр. "ложка" расе-роботу) и ДОБАВИТЬ пачку слов, которые могут помочь в
> генерации, исходя из описания расы. Нужно широко раскрыть расу, 30-50 слов
> добавить в словарь для генерации»

## Решения создателя (уточнение 2026-09-17)

1. **Куда класть слова: вариант «а»** — расширяем `forms` каждой расы до 30–50
   коротких описаний (генератор уже берёт из этого списка случайно → «широкое
   раскрытие» без нового поля и без правки кода промпта). Инвариант теста
   «forms 2–4» → «≥ 2» правит @developer на этапе разработки.
2. **Масштаб:** брать только **значимые, отличительные черты** расы (по
   контексту), а не всё описание; отбор — по контексту против описания.
3. **Формат:** **сначала протестировать, что формат будет работать** — пилот на
   2–3 расах (новый словарь → реальная генерация в студии), после подтверждения —
   масштабирование на все 60 рас.
4. **Вариант «б» (механика кандидатов):** кандидаты эталона берут форму из
   словаря **той расы, чьи материалы/свечение выпали** (вместо общего
   абстрактного словаря форм) — правка `BuildPromptWide` (зона @developer).
   Диагноз менеджера 2026-09-17: текущие кандидаты «одинаковые» НЕ из-за сидов
   (проверено: сиды разные, файлы свежие, рандом рас работает), а из-за
   шаблона: «абстрактный объект на тёмном фоне» + материалы семейства → SDXL
   рисует одинаковые глыбы; расовая идентичность в эталоны не попадает.
5. **Критерий разброса:** новая генерация должна давать **новые картинки** —
   повторный `/genref` даёт визуально другой набор кандидатов (случайная раса +
   случайная форма из её 30–50 + материал/свечение/сцена + сид). Фиксированного
   пула быть не должно; формы рас должны быть **визуально различимыми** (не 40
   вариаций одной глыбы).

## Что проверено менеджером (факты на 2026-09-17)

- **Словарь расы** = списки `forms` (2–4 коротких описания-фразы), `materials`
  (2–3), `glows` (2–3) у каждой расы в `config/art/families.json`. Генератор
  (`BuildPrompt`) берёт по одному случайному элементу из каждого на промпт.
- **Отдельного словаря слов нет**; «ложки» (`spoon`) нет ни в `config/art/*`,
  ни в `tools/*.py` — пример создателя условный, понимается как «аудит +
  чистка явно нелепого».
- **Описания рас**: `docs/gamedesign/races/`, 60 файлов (по одному на расу:
  внешность, природа, характер, быт) — источник слов для расширения.
- Формат текущих `forms` — короткие английские фразы-описания формы
  (напр. «a tall archival tower of memory banks»).

## ТЗ (что должно получиться)

### Часть 0 — пилот формата (зона @designer + проверка создателя)

- Выбрать **2–3 показательные расы** (например: одна робо-раса F10, одна
  органическая F2, одна «газовая/энергетическая» F7/F9).
- Для каждой: аудит текущих `forms` (+ явные несоответствия `materials`/`glows`)
  и расширение `forms` до ~30–50 коротких фраз — **только значимые отличительные
  черты** (внешность/характер/среда/техника), отбор по контексту описания.
- **Проверка формата:** прогнать генерацию в студии (эталоны/вариации) — работает
  ли новый формат в реальных промптах; подтверждение создателя/художника.
- После подтверждения — масштабирование на все 60 рас (Часть 1).

### Часть 1 — контент (зона @designer)

Для **каждой из 60 рас** (9 семейств F2–F10) в `config/art/families.json`:

1. **Аудит и чистка:** просмотреть текущие `forms` (+ на явные несоответствия
   `materials`/`glows`) против описания расы (`docs/gamedesign/races/<slug>.md`
   + `basis` из `config/races.json`); убрать фразы/слова, которые прямо не
   подходят контексту расы (заменить на подходящие).
2. **Расширение `forms` до 30–50** коротких фраз — **только значимые,
   отличительные черты** (не всё описание): внешность, характер, среда,
   техника/материалы, «как выглядит существо/объект». Отбор по контексту против
   описания расы. Цель — «широко раскрыть расу»: генератор должен уметь показать
   разные грани. Формат — английские фразы в стиле текущих `forms` (короткое
   описание формы), подтверждённый пилотом.
3. **Materials/glows не расширять** (остаются 2–3), но заменить явно нелепые,
   найденные в аудите.

Правила по семействам:
- Расы F2–F9 — по `docs/gamedesign/races/*.md` + 99.2.21 §5.
- Роботы F10 (51–60) — по `docs/gamedesign/races/*.md` (архивариусы…эхо чужих)
  + слой `robotic` (99.2.24 §3); «живой кремний» не использовать (монополия F6),
  био-органики нет (машины).
- Не пересобирать `beast_forms`/`anthro_clothes`/`anthro_neg` семейств (эталон
  76a) — только `forms` рас и точечная чистка materials/glows.

### Часть 2 — код и тесты (зона @developer, после гейта дизайна)

- `cmd/art-studio/config/load_test.go`: инвариант `forms` 2–4 → **≥ 2** (верхнюю
  границу убрать или поднять до ~60 для страховки от дублей); `materials`/`glows`
  2–3 не менять.
- Проверить, что генератор (`BuildPrompt`/`BuildPromptWide`) корректно работает
  со списками `forms` длиной 30–50 (код не зависит от длины — только рандомный
  выбор; правок промпта не ожидается).

### Границы

- Новые поля в конфиг НЕ добавляем (вариант «а»); код промпта не меняем.
- `config/races.json`, игровой сервер, `docs/gamedesign/races/*.md` — не трогаем
  (описания — только источник).
- F4/F5 `beast_forms`/`anthro_clothes` — эталон, не трогать.
- Чисел баланса нет → сверка с @balancetester не требуется.
