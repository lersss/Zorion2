## Замысел (сырая заметка → уточнится дизайном)

**Дашборд игрока** — отдельная страница личной зоны: профиль (ник, корабль,
мир), статистика (миры посещены, полёты, «открыто X из Y» по разделам
энциклопедии) + **Энциклопедия** с разделами. Сейчас у игрока нет личной
страницы: `/me` (данные, корабль, полёт) + модалка системы. Дашборд —
фундамент под будущее (77a знание, снаряжение, рынок).

**Энциклопедия — разделы (заготовки):**
1. **Расы** — открытые игроком расы: имя, класс (био/робот), окна (°C/атм),
   атрибуты, лор из `22_races.md`; скрытые — силуэт «—». Не-регрессия решения
   2026-09-16 (не ярлыки; детали — через отчёты/действия).
2. **Звёзды** — переиспользовать справочник спектральных классов (41a,
   `getSpectralInfo`): класс, температура, цвет, срок жизни.
3. **Планеты** — типы, атмосферы, физика (данные карточки планеты → общий
   справочник).
4. **Ресурсы/сырьё** — заготовка: реестр пуст, наполнится при 99.2.5.
5. **Корабли/оборудование** — заготовка: реестр пуст, наполнится после 77a.
6. **Лор-термины/существа** — заготовка: бестиарий (76a.1) + словарь терминов.

**Открытие (в):** базовое (названия/классы/справочные числа) видно сразу;
детали (лор-абзацы, конкретные поселения/расы встреченные) — по действию
(посещение планеты, скан, отчёт). Границы для каждого раздела — решает дизайн
с гейтом создателя.

## Связь с 77a (важно для дизайна)

77a вводит «личное знание» `player_planet_knowledge` (миграция 000040
забронирована за 77a, спека в дизайне, не в коде). Энциклопедия НЕ забирает
миграцию у 77a: проектировать так, чтобы знание 77a стало источником
«открытий» позже, а сейчас открытие — по доступным действиям (текущие ручки:
список планет мира, карточка планеты, поселения). Дублирования «открытий» с
будущей таблицей 77a избежать: либо пока без таблицы (локализованные данные),
либо договориться с 77a об общей модели открытий (решит дизайн, отметит).
