# 89a. Аналитик-оптимизатор промтов и структуры

**Создано:** 2026-09-18
**Статус:** Готово (создатель принял, 2026-09-18)
**Приоритет:** процесс (инструменты)

---

## Сырое пожелание (создатель, 2026-09-18)

> «Мне нужно регулярно оптимизировать код и промты. Напишешь классный промт для
> такой роли?»

## Уточнение (создатель, 2026-09-18)

- Фокус — **промты** (код не трогает).
- Роль — **аналитик**: смотрит на структуру проекта + промты и подсказывает, как
  ускорить работу.
- Промты должны **покрывать** структуру проекта (агент знает о важных доках/зонах/
  файлах/правилах) и **ограничивать** (агент не лезет в чужое, не переспрашивает,
  не крутит итерации).

## Принятые дефолты (менеджер, создатель не возразил)

1. **Полномочия:** аналитик только предлагает дословные дельты; сам ничего не правит,
   не коммитит. Правка инструкций — только отдельным явным «да» создателя (правило 62a).
2. **Режим запуска:** регулярно — встроенный шаг в паузу (раз в N закрытых задач /
   перед большим релизом) + по запросу создателя, когда чувствуется «тупят агенты».
   Отдельный агент в `.opencode/agents/`, вызывается через @manager.
3. **Критерий успеха:** меньше итераций на задачу, меньше переспрашиваний, меньше
   превышений бюджета, короче цикл дизайн→код→тест. Находка = конкретное место +
   дословная дельта, а не «стало бы лучше».

## ТЗ (реализовано)

Агент `optimizer` (`.opencode/agents/optimizer.md`):
- Читает: все промты `.opencode/agents/*.md`, `AGENTS.md`, `docs/INDEX.md`,
  `.opencode/CONTEXT.md`, дерево репозитория, `git log` по промтам, процессные идеи
  (44a, 62a, 46a, 83a).
- Пять осей анализа: покрытие, ограничение, скорость, актуальность, дублирование/раздутость.
- Выход — отчёт: сводка + максимум 5–7 находок (файл → место → что происходит →
  последствие → дословная дельта), только по фактам, без шума и без отмены
  утверждённых решений создателя.
- Правила: только отчёт, 1 прогон = 1 отчёт, не читает лишнего.
