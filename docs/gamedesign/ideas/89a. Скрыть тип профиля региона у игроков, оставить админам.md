## Пожелание (создатель, 2026-09-17)

«надо убрать у игроков тип кластера под названием региона на карте (не трогать
админов и суперадмина)».

## Диагноз

На малом зуме карты регионы галактики (ячейки Вороного) рисуются с названием,
а под названием — **вторая строка: тип профиля региона** (мелкий приглушённый
жёлтый, напр. `young`, `industrial`). Это отладочный вывод фичи 59a (профиль
региона влияет на генерацию), явно промаркирован «отладочно, в финале убрать»:
- клиент: `map_render.js:626-631` (коммент «Отладочно (59a)… В финале убрать —
  профиль не публикуется как ярлык, спека §11.7 / GDD §2.6.1»);
- сервер: `region_handler.go:19-22` (DTO `Profile`, тот же коммент).

В отличие от 87a (раса — убрана всем, потому что не нужна никому), профиль —
**инструмент создателя**: админам/суперадмину оставить, игрокам убрать. Аналог
паттерна FPS-счётчика (28a): роли-гвард на клиенте.

## Реализация (менеджер, мелочь)

Один клиентский файл, `web/static/js/map/map_render.js` (~5 строк смысла):

1. Константа `REGION_PROFILE_ROLES = ['admin', 'skycomposer']` (рядом с секцией
   «Регионы», стр. ~552-555).
2. В `drawRegionLabels` гейт единственной отрисовки профиля:
   `const hasProfile = !!lb.profile && REGION_PROFILE_ROLES.includes(state.userRole);`
   (стр. ~645). Ширины/высоты подписи уже считаются через `hasProfile` — для
   игроков подпись автоматически компактнее (только название).
3. Комментарии обновлены.

Не тронуто: сервер, `/api/regions` (профиль по-прежнему в DTO — отображение
режет клиент), статус-бар «Регион: X» (это имя региона, не тип), модалки, 87a.

Паттерн повторяет FPS_ROLES (`map_render.js:932`): `state.userRole` приходит из
`/me` (`data.js:346`), дефолт `''` → `includes('')` = false → до загрузки /me
профиль скрыт (безопасно).
