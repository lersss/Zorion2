## Пожелание (слова создателя, 2026-09-19)

> «Нужно в принципе логику переделать приложения.»
> «Нужно иметь возможность прямо указать тир в карточке товара, дать возможность сменить тир.»
> «Иметь возможность подгрузить справочник (сделать карточки из названий по списку).»
> «Логику просмотра всего дерева оставь, пусть включается отдельной галкой.»

## Требования (решения создателя, 2026-09-19)

### 1. Канвас: режим «вокруг выбранного» (по умолчанию)
- Виден **только выбранный товар + прямые родители + прямые дети** (1 уровень, не вся цепочка).
- **Ресурсы, попавшие в подграф, видны всегда**; чекбокс «показать ресурсы» — **убрать**.
- Выбор товара: **клик по родителю/ребёнку на канвасе** (подграф перестраивается вокруг него)
  или **клик по товару в справочнике**.
- Когда ничего не выбрано — канвас пуст с подсказкой (кликните товар в справочнике).

### 2. Режим «всё дерево» (полный граф)
- Отдельная **галка** включает старую логику полного графа (ряды по тиру).

### 3. Тир: вычисленный + ручной оверрайд
- В карточке товара — **оба**: вычисленный (1 + max(тиры составляющих)) и **ручное поле тира**.
- Тир **не указан** → вычисляется (текущее поведение). Тир **прямо указан** → **оверрайд**,
  идёт в экспорт (complexity). Создатель: «Давай оба. Я хочу гибкость и контроль»;
  «если T не указан, он вычисляется, если прямо указан — оверрайд».
- **Полная свобода оверрайда** (решение создателя 2026-09-19, ответ на звоночек критика):
  ручной тир можно ставить ЛЮБОЕ значение, в т.ч. ниже вычисленного. Ограничений нет,
  «Нужна полная свобода». (Предупреждение о расхождении с вычисленным — на усмотрение UI,
  не блокер.)

### 4. Справочник (бывшая «палитра», переименовать)
- **Поиск по имени** — распространить на товары (у ресурсов уже есть).
- **Галки-фильтры** (по умолчанию **всё выключено**): «используемые» / «неиспользуемые»
  (комбинируются, гибкость: «показать все неиспользуемые ресурсы», «все используемые товары»)
  и «T0» (ресурсы, тир 0).
- **Кнопка «+ товар»** — добавить новый товар в справочник (поштучно).
- **Подгрузка списка**: текстовая область, каждая строка **«название | категория»**
  (категория по имени из категорий студии) → карточки-черновики.
- **Drag&drop из справочника в слот** — перенос товара в слот рецепта (существующая
  логика слотов: слоты живут в правой панели, `dropOnSlot`; карточка дочки на канвасе
  = слот родителя, пустой слот = плейсхолдер). Справочник становится источником
  drag&drop как сейчас палитра ресурсов (draggable-карточки → слоты). **Логику слотов
  НЕ переделывать** (создатель 2026-09-19: «логика слотов на канвасе сейчас правильная,
  ничего не прошу сверх того, что сейчас есть по слотам» — слоты-приёмники под
  карточками НЕ возвращать, критик был неправ, что их «нет»).

### 5. Количество в рецепте — УЖЕ РЕАЛИЗОВАНО, не трогаем
- Количество составляющей в слоте (input в правой панели, PUT quantity, экспорт
  quantity, импорт quantity из файлов) — сделано в 99a.2, работает.
- Создатель 2026-09-19 (после проверки): «я ничего не прошу сверх того, что сейчас
  есть по слотам» — **на канвас количество НЕ добавляем** (на канвасе слоты не
  рисуются, карточка дочки = слот). Требование «нужно количество в рецепте»
  закрыто существующим полем в слоте правой панели.

### 6. Деталь товара — в попап (решение создателя 2026-09-19)
- Всё, что сейчас в правой панели **над справочником** (`#detail`: имя/переименование,
  категория, слоты с количеством и галкой allow_resource, кнопки «+ слот»/«заполнить
  комплектующие»/статусы/«добавить родителя»/«удалить», «Используется в:», поле тира
  99a.3) — **вынести в попап** (модальное окно), открывается **при клике на товар**
  (на канвасе или в справочнике), не показывается постоянно.
- **Справа останется только справочник и его фильтры** (+ «+ товар» и подгрузка
  списка; забаненные — по умолчанию отдельной переключаемой панелью/галка в
  справочнике, решает @uidesigner, вариант в гейт).

## Факты (сверка с кодом, 2026-09-19)

- **Канвас сейчас** (`web/index.html`, 1057 строк): рисует ВСЕ товары рядами по глубине
  (depthOf, не тир — решение создателя 2026-09-19); `selected` — выделение рамкой;
  обратные рёбра («Используется в») только при чекбоксе `reverseEdges`; ресурсы скрыты
  чекбоксом `showResources`. Слоты на канвасе НЕ рисуются отдельными приёмниками:
  заполненный слот = карточка дочки + линия, пустой слот = пунктирный плейсхолдер в ряду
  ниже (решение создателя 2026-09-19 «только линии связующие»); клик по карточке = выбор;
  drag&drop идёт в слоты ПРАВОЙ панели (`dropOnSlot`, `slotDragOver`) — НЕ на канвас.
- **Количество в слотах реализовано (99a.2):** `Slot.Quantity` (дефолт 1, нормализация при
  загрузке), PUT `/api/goods/{id}/slots/{n}` `{quantity}` (только количество), UI в правой
  панели (input number), экспорт `quantity`, импорт деревьев читает quantity из файла.
- **Палитра справа** (`renderPalette`): ресурсы с поиском; неиспользуемые (входящая
  степень 0, не забаненные, не ресурсы); забаненные (отдельная панель). Справочника
  как списка всех товаров с фильтрами нет. «Используемость» = вхождение в чей-то рецепт
  (`used[good_id]`).
- **Тир** — вычисляемый (`tierOf`: 1 + max детей, ресурс = 0). Ручного поля нет.
- **Подгрузка списка названий** — нет (есть импорт top-каталога кнопкой «Импорт», 99a.2).
- **Модель** (`model/types.go`): `Good{id,name,category,status,kind,source,recipe,created_at,resource_ref}`.
  Поля ручного тира нет — понадобится (например `tier_override *int`).
- **Экспорт** (`export/export.go`): `complexity = тир` — при оверрайде должен идти ручной тир.
- **Студия запущена** (порт 8799), state.json живой (108 товаров, 99a.2 живой прогон).
- Код и артефакты студии **не закоммичены** (в рабочем дереве; 99a «не коммитить как готовое»).
  В дереве также чужие незакоммиченные правки — стейджить только свои пути.

## Вердикт критика (прогон 2026-09-19, до дизайна)

**11 находок (мелких 6, средних 4, крупных 1).** Разбор:

**Крупное №1 (слоты на канвасе) — СНЯТО создателем:** критик посчитал, что требования
«drag&drop из справочника в слот» и «количество» опираются на несуществующие слоты-
приёмники на канвасе (якобы убраны Пакетом 2). Создатель: «Логика слотов на канвасе
сейчас правильная, мы вчера доработали её. Я ничего не прошу сверх того, что сейчас
есть по слотам». Факт кода подтверждён: слоты = карточка дочки + линия (заполненный),
плейсхолдер (пустой); drag&drop и количество — в слотах правой панели, работают.
В ТЗ внесено: логику слотов НЕ трогаем (см. §4/§5).

**Средние — решения создателя:**
- №2 (тир-оверрайд против «тир = 1+max детей») — **полная свобода** оверрайда,
  любые значения (см. §3). Расхождение с вычисленным — предупреждение в UI, не блокер.
- №3 (ресурсы в полном дереве) — создатель: «по умолчанию всё выключено, там разберусь».
  Решение дизайна: в подграфе ресурсы видны всегда (требование §1); в режиме «всё
  дерево» — по умолчанию скрыты (как сейчас), чекбокс «показать ресурсы» остаётся
  только для режима «всё дерево» (создатель уточнит на гейте).
- №4 (раскладка по глубине, не по тиру) — учтено: режим «всё дерево» = текущая
  раскладка по глубине (depthOf), а не «ряды по тиру». Факты исправлены.
- №5 (галку «T0» трактовать по виду, не по тиру) — решение: галка «T0» показывает
  ресурсы (kind=resource); товары с пустым рецептом (тоже тир 0) — по умолчанию
  в справочнике видны (это рабочие черновики), их не прячем.

**Мелкие (6) — правятся в спеке:** №6 «используемость» = вхождение в чей-то рецепт
(уже так в коде, `used[good_id]`), забаненные скрыты из справочника (отдельная панель
остаётся); №7 подгрузка списка: ненайденная категория → ошибка строки с указанием
номера, дубликат имени → пропуск с предупреждением; №8 кнопка «+ товар» в справочнике
дублирует addbar — оставить обе (addbar в шапке, справочник — в панели), поведение
одинаковое (имя + категория); №9 снятие оверрайда тира: поле можно очистить → снова
вычисляется; №10 промпт ИИ «заполнить комплектующие» получает вычисленный тир
(оверрайд не влияет на генерацию — только на отображение/экспорт); №11 «палитра» →
«справочник» — термин в спеке 99a.1 §10.4 и 99a.1-ui §4.3 синхронизировать при сдаче,
кандидат в GLOSSARY.
