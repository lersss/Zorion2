## Диагноз (подтверждён создателем: T=773 K — ручная правка 500 °C в UI гипотез)

Планета **Falumzia** (прогон `greenbelt`, группа «сад», ТЗ подтверждено):
T = 773 K, g = 1, радиоактивность 20, вода 70%, растительная жизнь.
В `settlements` — поселение с population = population_exact = **100 000 000**.

**Формулы работают правильно** (калибровка 99.2.12): 773 − 350 = 423 ≥
HardZeroHot=350 → жёсткий ноль → `TotalLambda = +Inf` → `Population = 0`,
`Uninhabitable = true`. Планета **необитаема принципиально**.

Проблема не в формулах, а в их применении — три дыры:

1. **Гипотезный джоб создаёт поселения на необитаемых планетах.**
   `runHypothesisJob` (`admin_hypothesis.go:158-176`) инсертит поселение с полным
   населением после проверки только `Chance`; пригодность планеты
   (`settlement.Uninhabitable`) не проверяется вовсе. В БД лежит «ложь» 100 млн.
   Тот же вопрос для обычного генератора поселений с расширенной моделью
   (`internal/generator/settlement/generator.go` — фильтрует по правилам модели,
   в которых можно задать temperature выше жёсткого нуля).

2. **Витрина показывает устаревшее/несуществующее население без пересчёта.**
   - Снапшот карты: `HasHabitable = EXISTS(SELECT 1 FROM settlements …)`
     (`mapcache/snapshot.go:135`) — планета «обитаемая» на карте по факту
     наличия записи, даже если население 0.
   - Админ-статистика `habitable_count`, `avg_population`
     (`admin_stats.go`, `loadSettlementPopulation`) и вкладка «Поселения» читают
     `settlements.population` напрямую → 100 млн.
   - Честен только путь карточки: `attachSettlements` пересчитывает в памяти
     (население 0), в БД запись продвигается лишь по «событию» (Δt ≥ 30 мин).

3. **Запись в БД после «события» не удаляется** — вымершее поселение
   (population = 0) остаётся строкой в `settlements`, поэтому карта вечно
   показывает планету обитаемой («вымерло позже» — тот же симптом, что и
   «создано мёртвым», только через время).

Побочно: пресет гипотез `forges`/«Жара» (`hypothesisPresets.js`, axisValue 500 °C)
написан до жёсткого нуля — «население живёт только поставкой» теперь неверно:
773 K = мгновенный ноль.

## Ход (2026-09-14): первопричина жалобы найдена и устранена

Жалоба «в карточке планеты население не умирает» объяснена **не формулами, а
старым бинарём**: zorion-server.exe собран 13.09 23:41, калибровка (f166437,
14.09 01:44) в него не вошла, сервер не перезапускали (нарушение AGENTS.md
§4.13). Старая линейная форма с капом на 1 для 773 K давала λ=0.01/ч —
население почти не менялось.

Перезапущен 14.09 ~02:49 на свежем бинаре; `/health` OK. Предпросмотр
`/admin/mortality-preview` для Falumzia: severity(temperature)=4.47,
lambda=100 (+Inf зажат), **uninhabitable=true**, проекция 0 на всех точках.
В карточке население теперь 0 (в БД запишется по «событию» Δt ≥ 30 мин).

**Остаются открытыми (вторичные дыры):** генерация поселений на Uninhabitable
и витрина Habitable по EXISTS. Скоуп на них создатель не выбирал (2026-09-14).

**Решение создателя (2026-09-14):** по генерации — **не чинить**. Гипотезный джоб
должен создавать поселения на необитаемых планетах: иначе не проверить, что
поселения уничтожаются.

**Решение создателя по витрине (2026-09-14):** фильтры/витрину **сейчас не
трогаем** — нужны админу в текущем виде. Но переделка признана необходимой:
фильтры **ломают инвариант об информации** (актуальное состояние против факта
наличия записи); формулировку инварианта уточнить при составлении ТЗ на
переделку. → Перенесено в бэклог (переделка фильтров), черновик ТЗ выше.

**Статус идеи:** Отложено (причина жалобы устранена перезапуском; остальное — в
бэклог по решению создателя).

## Что не менять

Формулы смертности (`mortality.go`) и ленивый пересчёт карточки — работают,
это модель «правда на сервере, синк по событию» по решению создателя.

## Критерии готовности (черновик, уточнить)

- На планетах за жёстким нулём (`Uninhabitable`) поселения не создаются
  ни одним путём (гипотезный джоб, обычный генератор).
- Карта (`HasHabitable`) и админ-статистика показывают планеты поселениями
  только при актуальном населении > 0 (ленивый пересчёт по формуле), либо
  принято другое решение по витрине.
- Falumzia не отображается обитаемой нигде, кроме (при необходимости)
  истории эксперимента.

## Маршрут

Баг → этап разработки (минимальный скоуп: генерация не создаёт поселения на
Uninhabitable; витрины считают живость по формуле). Скоуп уточняется у создателя
(2026-09-14): только генерация или генерация + витрины.
