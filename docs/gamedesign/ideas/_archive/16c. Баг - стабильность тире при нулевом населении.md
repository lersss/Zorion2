## Сырое пожелание (создатель, 2026-09-14)

> «У поселения с 0 населением стабильность должна быть тире»

## Диагностика (менеджер, факт из кода)

- Отображение: `web/static/js/modal/tabs.js:389` —
  `s.stability != null ? s.stability + '%' : '—'` — тире показывается **только**
  когда `stability == null`.
- Модель: `internal/models/economy.go` — `Stability int \`json:"stability"\`` —
  поле всегда число, `null` не бывает (БД `stability` NOT NULL, дефолт в
  генераторе — см. `internal/generator/settlement/generator.go` `buildSettlement`
  и тест `economy_repository_recompute_test.go` — `Stability: 60`).
- Итог: у вымершего поселения (population = 0) карточка показывает «Стабильность:
  60%» вместо «—» — это баг отображения, чисел баланса не касается.

## ТЗ (черновик — техрешение за @developer)

- В карточке поселения, где население = 0, вместо процента стабильности
  показывается тире («—»), как уже предусмотрено в `tabs.js` для `null`.
- Место правки и способ (фронт: условие на `population == 0`; бэк: вернуть
  `stability: null`) — на выбор разработчика, но фронтовое решение ближе к
  сути (поле `stability` в модели/БД не nullable; семантика отображения).
- Других мест отображения стабильности в web не найдено (grep по `stability` в
  `web/` — только `tabs.js:389`).

## Критерии готовности

- Открыл карточку поселения с населением 0 — «Стабильность: —» (тире).
- Живое поселение — как раньше, «Стабильность: N%».
- DoD по `AGENTS.md` §2 (если правка затронет Go).

## Реализация (2026-09-14)

`web/static/js/modal/tabs.js:389` — одна строка, фронт:

```js
<div>Стабильность: <strong>${populationAt(s, Date.now()) === 0 ? '—' : (s.stability != null ? s.stability + '%' : '—')}</strong></div>
```

Тире — когда отображаемое население = 0 (та же функция/момент времени, что и в
строке населения `tabs.js:388`, рассинхрона нет). Go не затронут, рестарт не
нужен. Вердикт `@tester`: **ПРОЙДЕНО** (node --check по 37 JS, реальный рендер
всех веток, живой сервер; чек-лист `docs/QA_CHECKLIST.md` обновлён).

## Известные нюансы (решение создателя 2026-09-14 — не чинить, суперминор)

1. **Транзиентный разрыв:** `repaintPopulationNumbers` (`extrapolate.js:50–68`)
   обновляет числа населения каждую секунду, но не строку стабильности (у
   `<strong>` нет id). Если поселение доживает до 0 на глазах — население
   покажет «0», а стабильность останется «N%» до следующего синка.
   Самовосстанавливается при `refreshPlanets`. Если когда-нибудь чинить: дать
   id и обновлять в repaint.
2. **Посторонние правки в `tabs.js`** (реворк `settlementTrendArrow`, блок «Лог»
   `settlementLogRows`) — вклад параллельного агента (фича 16a), вне этой
   заявки; в дифф коммита этой заявки не включать.
