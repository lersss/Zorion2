## Решения гейта (2026-09-19, слова создателя)

1. **Крупное №1 — вариант А:** «Постройки не включаем». Ретрансляторы,
   лаборатории, атмосферные экстракторы, реакторы, станции, склады — НЕ позиции
   каталога. Вместо них — топовые **составляющие для них** (сложные комплектующие,
   детали, оборудование).
2. **№2 (реализованное оборудование):** «Нет» — конкретные реализованные модули
   (радар/сканер/двигатель 91a) в каталог НЕ дублируем. Категория «Корабли и
   модули» остаётся (решение С-1) — новые корабли/модули включаем.
3. **№3 (эскиз составляющих):** «Эскиз будет затираться при импорте (сделает
   другая команда)» — эскиз черновой, машинного контракта нет; студия (после
   доработки другой командой) построит граф сама. Формат эскиза свободный.
4. **ТЗ дизайнеру (слова создателя):** «Что надо при создании графа: понимать,
   что сложные ресурсы (с высоким параметром на одной из осей) могут быть
   составляющими для хай-тир товаров. Можно это учесть при генерации». —
   В эскизах хай-тир товаров допускаем составляющими сложные ресурсы из
   существующих каталогов (layer 20 / real 111, высокое значение по одной оси:
   твёрдость, T_melt, проводимость, радиоактивность > 60 и т.п.).
5. **№4 (распределение спроса):** принято без возражений — ~70% непрерывные
   потребители (поселения, содержание, стройка), ~30% всплесковые
   (мегапроекты, кризисы, война).
6. **№5 (способ ввода):** принято — ручной ввод в студию, импорт не обещаем.
7. «Давай сделаем и посмотрим что получится» — старт дизайна.
8. **Метка спроса** (решение создателя): на каждую позицию — метка
   «постоянный» (continuous) / «всплесковый» (spike), чтобы распределение ~70/30
   было видно и проверяемо.
9. **Верхний тир = Т8** (решение создателя 2026-09-19): шкала тиров каталога до
   8; не каждая верхушка обязана быть Т8 — разные топовые товары разной глубины
   (6–8). Это также вклад в развилку тира студии 99a (Пакет 3), код студии
   НЕ трогаем.
10. **Полное разворачивание до ресурсного слоя** (решение создателя): каталог из
    «затравки с эскизами» превращается в полный граф производства — каждый
    промежуточный товар (тиры 2–7) описан и связан, листья — ресурсы тира 0.
    Промежуточные товары — полноценные позиции (имя + категория + «почему» +
    свои составляющие).
11. **Ресурсы — составляющие любого тира** (решение создателя 2026-09-19):
    ресурс (тир 0) может входить в товар любого тира напрямую (не только Т1);
    согласуется с моделью студии (тир товара = 1 + max(тиры составляющих)).
12. **Листья — только существующие ресурсы** каталогов (слой 20 `layer.go` +
    витрина 111 `real.go`); чего в каталогах нет — помечаем «нет в каталоге»
    (формирует список «каких ресурсов не хватает» — цель студии 99a).
13. **Черновой вариант** (решение создателя): «давай просто черново сделаем и
    посмотрим что получилось» — приоритет полноте и связности цепочек, а не
    полировке текстов.
14. **Не привязываться к тиру в цепочках** (решение создателя 2026-09-19):
    «деталь Т5 может быть составляющим Т8, не привязывайтесь к тиру» — шаг по
    тирам произвольный (составляющая тира ниже, но не обязательно ровно тир−1);
    тир в студии вычисляется сам (1 + max тиров составляющих), рёбра только
    вверх. При составлении цепочек — осмысленность, а не «ровно на тир ниже».
15. **Переориентация: «просто сделай красивую модель потребления и
    производства»** (создатель 2026-09-19, отменил полное разворачивание сотен
    узлов): полный граф до ресурсного слоя НЕ разворачиваем. Каталог 100
    верхушек остаётся затравкой; главный артефакт — **модель потребления и
    производства**: кто что потребляет, что и как производится, как категории
    связаны в цепочки. Раздел «Модель» ниже.
16. **Итоговое ТЗ — «20 Т8» (создатель 2026-09-19):** «Ресурсы должны быть
    редкостью в рецептах топового тира. Давай упростим задачу: сделаем 20 Т8,
    которые состоят в среднем из двух комплектующих тира ниже + чистый ресурс
    (чем ниже тир, тем менее ценный будет ресурс)».
    - 20 товаров верхнего тира Т8.
    - Рецепт каждого: **~2 комплектующих Т7 (производимые товары) + 1 чистый
      ресурс** (редкий/ценный из каталогов: уран, плутоний, гелий-3, дейтерий,
      вольфрам, титан-сплав, YBCO, GaAs…).
    - **Ресурсы — редкость в рецептах топового тира** (один, не пачка).
    - Правило ценности: **чем ниже тир, тем менее ценный ресурс** (Т8 — редкие
      и ценные; низкие тиры — простые: вода, железо, глина).
    - Каталог 100 верхушек остаётся как широкий список кандидатов/сырьё;
      ядро — 20 Т8 (из него или поверх него).
17. **Финальное ТЗ — полные деревья, пилот 5 Т8 (создатель 2026-09-19):**
    «надо сделать полное разворачивание вниз. каждый Т8 будет состоять из двух
    Т7 + ресурс (редкий, с большими значениями по одной из осей), в свою очередь
    эти Т7 будут каждый состоять из двух Т6 + ресурс и так далее — до Т1. Давай
    серьёзно подойдём к вопросу» + «Не обязательно уникальные... ресурсов у нас
    пока всего 111, могут быть пересечения. Давай сделаем 5 Т8 для начала, но с
    полными деревьями».
    - **Структура:** ТN = 2×Т(N−1) + 1 ресурс, рекурсивно до Т1.
    - **Т1** = производимый товар из простых ресурсов (2–3 шт., тир 0).
    - **Ресурсы:** верхние тиры — редкие, с большими значениями по одной из осей
      (уран, плутоний, гелий-3, вольфрам, YBCO, GaAs…); чем ниже тир — тем
      проще ресурс (вода, железо, глина). Только из каталогов (layer 20 /
      real 111).
    - **Общие узлы допустимы** (сеть, пересечения; один Т7 на несколько Т8).
    - **Пилот: 5 Т8 с полными деревьями** → гейт создателя → масштабирование
      до 20 Т8.
    - Развернуть: «серьёзно подойти» — полнота и связность, осмысленные имена
      на каждом уровне, реальные ресурсы.

## Видоизменение ТЗ (создатель, 2026-09-19): 2 Т8 с полными деревьями

> Создатель: «Давай сделаем 2 Т8 товаров, полностью ветки, из чего они состоят
> (2 комплектующих тиром ниже + ресурс редкостью T), но условие: можно
> переиспользовать уже имеющиеся названия комплектующих, просто добавлять их
> тир. Например, радиодетали могут быть Т7, Т6, Т5.»

**Выбор пары (создатель):** «Реакторное топливо "Гелиос"» (топливо, мегапроекты)
+ «Микропроцессор "Кремний-9"» (комплектующие, непрерывный спрос) — ядро
энергоснабжения и мозг техники.

**Структура дерева (рекурсивно до Т1):**
- Т8 = 2×Т7 + 1 ресурс (редкий, редкость Т8).
- ТN (N = 2..8) = 2×Т(N−1) + 1 ресурс; редкость ресурса соответствует тиру.
- Т1 = производимый товар из 2–3 простых ресурсов (тир 0: вода, железо, глина…).
- Ресурсы — только из каталогов (слой 20 `layer.go` / витрина 111 `real.go`).

**Редкость ресурса (уточнение создателя 2026-09-19):** редкий ресурс (Т8) — это
ресурс с топовыми значениями по осям (10 осей + T, модель осей 94a); **чем
больше топовых значений по осям, тем реже ресурс**. Чем ниже тир — тем проще
ресурс (вода, железо, глина: 1–2 обычных значения).

**Переиспользование имён:** одно имя комплектующего может стоять на разных
тирах («Радиодетали» Т5, Т6, Т7 — тир добавляется к имени). Тир товара
вычисляется сам (1 + max тиров составляющих), рёбра только вверх.
**Уточнение (создатель):** комплектующие — **обобщающие имена**, не обязательно
конкретные: «Антенны», «Горючее», «Микропроцессоры», «Радиодетали» и т.п.
(конкретика остаётся за верхушками Т8 и ресурсами).
**Уточнение 2 (создатель, переработка имён):** имена товаров-узлов —
**однословные, короткие** («стекло», а не «стекло техническое»); уточняющие
прилагательные/вторые слова убираем, если они не несут смысла. Ресурсы из
каталогов (layer.go / real.go) — их имена фиксированные, не переименовываются.
**Уточнение 2а (создатель):** если второе слово — **не прилагательное**
(«Ячейки памяти»), оно часто несёт уточняющий смысл — **оставляем**: «Ячейки»
само по себе непонятно и многозначно. Убираем только прилагательные-пустышки.
**Уточнение 2б (создатель):** **избегать сложных специфических терминов**
(«шлики», «подложки», «катанка») — слова уровня ребёнка 10 лет: «Шестерёнки»,
«Краска», «Рычаги». Меньше физического смысла, но в это можно играть.
**Уточнение 3 (создатель):** **не бояться переиспользовать готовые товары в
более высоких рецептах** — сложность тира набираем **количеством** простых
деталей в рецепте: например, рецепт Т7 = 8×Т5-товар + ресурс (готовый товар
низшего тира кладём большим числом штук), а не только «2×Т6 + ресурс».
Структура «2 комплектующих тира ниже + ресурс» — не догма: количество
ингредиентов может расти, чтобы увеличить сложность/тир.
**Грань упрощения (создатель, 2026-09-19):** упрощаем **язык**, но не
**анатомию товара**. Можно: сложное слово → простое с тем же смыслом («спечённая
керамика» → «фарфор»). Нельзя: подменять составляющие изделия абстракциями и
условиями работы («Ядра + Ток = микропроцессор» — как «двигатель = поршни +
бензин»; «Ток»/«Питание» — это энергия, а энергия — не товар §11.1.2). Состав
Т7/Т8 должен быть правдоподобным: реальные части изделия (кристаллы, платы,
контакты, корпуса, сборки, стержни), а не абстракции.
**Правило «товар = предмет» (создатель, 2026-09-19):** имя товара-узла должно
иметь **главную коннотацию предмета**, а не абстракции/процесса/фигуры/явления.
«Линии» — геометрическая фигура, не товар; «Схемы» — чертёж; «Дорожки» —
тропинка; «Стыки» — место соединения; «Канавки» — бороздка; «Площадки» —
детская/стройплощадка; «Покрытия»/«Пропитка»/«Изоляция» — процессы;
«Слои»/«Слоёные» — геометрия/еда. При переименовании **переиспользовать уже
существующие товары** деревьев, где подходит по смыслу (решение создателя:
«можно переиспользовать в рецепте то, что уже есть и подходит по смыслу»).
**Решения по чистке имён (создатель, 2026-09-19):** чиним все 10 «не-товаров»:
Линии (Т5 К-9), Дорожки (Т6 К-9), Схемы (Т4 К-9), Стыки (Т4 Г), Канавки (Т4 К-9),
Площадки (Т4 К-9), Покрытия (база), Пропитка (база), Изоляция (Т3/Т4), Слои
(Т4 К-9), Слоёные (Т1 база). Пограничные сырьё (Месиво, Основа, Жидкости, Газ,
Пыль) — оставляем. Новый инстанс @designer (2026-09-19).

**Общие узлы между двумя деревьями** допустимы (пересечения, сеть; решение №17).

**Готовый каталог 100** (ниже) остаётся как пул имён и сырьё для веток; два
дерева строятся из него/поверх него. Модель потребления (§ниже) — контекст
спроса.

**Формат результата:** как раньше — JSON в `goods_data/` (рабочая копия, вне
git) + текстовые схемы деревьев в доке (стиль «Модель» §3 ниже).

## Модель потребления и производства (черновик, 2026-09-19)

> Собрана @manager из разведки механик + каталога 100 верхушек. «Красивая» —
> значит связная: каждый товар стоит на пересечении «кто потребляет» и «из чего
> производится». Эскизно; полировка — позже.

### 1. Потребление — кто ест товары

| Потребитель | Характер | Категории товаров |
|---|---|---|
| **Поселения** | непрерывный, объёмный, узкий | продовольствие, медикаменты, товары быта, топливо, химикаты |
| **Содержание построек** | непрерывный, средний | топливо, комплектующие, детали, полимеры |
| **Стройка и ремонт** | импульсный, средний | конструкционные материалы, оборудование, детали |
| **Мегапроекты** | разовый, огромный | корабли и модули, оборудование, конструкционные, экзотика |
| **Война** | импульсный | оружие, броня, химикаты, топливо |
| **Кризисы** | всплеск по типу | медикаменты (эпидемия), топливо (холод), оружие/броня (вторжение) |

Правило: **основная масса товаров кормится от трёх непрерывных** (поселения,
содержание, стройка) — мегапроекты и война дают всплески, на них одну экономику
не построить (§5.2.1). В каталоге: 69 непрерывных / 31 всплесковый (~70/30).

### 2. Производство — как товары делаются

- **Завод** — постройка, производит один товар; работает, если тир поселения ≥
  сложности рецепта (§11.1.1).
- **Автозавод (робот)** — постройка, ест энергию + комплектующие + детали;
  потоково требует **сложные детали** (деталь сложности ≥ N, §13.9.6).
- **Ресурсы** — тир 0, листья всех цепочек (слой 20 + витрина 111).
- **Тир товара** = 1 + max(тиры составляющих); шаг по тирам произвольный
  (деталь Т5 в составе Т8 — норма), рёбра только вверх.

### 3. Связность — категория → верхушка → промежуточные товары → ресурсы

> Исправление (создатель 2026-09-19): «до 8 тира должно быть достаточно
> производимых товаров» — цепочка Т8 собирается из производимых товаров
> (комплектующие, детали, узлы), а не из одних ресурсов. Примеры ниже — полные
> цепочки: (т) — производимый товар (будущая позиция каталога/студии),
> (р) — ресурс из каталогов (слой 20 / витрина 111). Тиры эскизные, шаг
> произвольный (п.14).

```
Корабельный реактор «Сердце» (Модули кораблей, Т8, мегапроекты)
  ├ Реакторные стержни (т, комплектующие, Т5) ← Уран-оксид UO₂ (р) + Графит (р)
  ├ Корпус-оболочка (т, детали, Т4)            ← Титан-сплав Ti-6Al-4V (р) + Вольфрам W (р)
  ├ Контур охлаждения (т, оборудование, Т4)    ← Свинец Pb (р) + Вода H₂O (р)
  └ Регулирующая электроника (т, комплектующие, Т6) ← Кремний Si (р) + Медь Cu (р) + GaAs (р)

Сложная деталь «Нейрон» (детали, Т6, автозаводы)
  ├ Микросхема-контроллер (т, комплектующие, Т4) ← Кремний Si (р) + Медь Cu (р) + Золото Au (р)
  ├ Прецизионный привод (т, детали, Т3)          ← Титан-сплав Ti-6Al-4V (р) + Литий Li (р)
  └ Силовая плата (т, комплектующие, Т3)         ← Медь Cu (р) + Бериллий Be (р)

Радиоизотопный генератор «Вечный огонь» (комплектующие, Т7, непрерывный)
  ├ Термоэлектрический модуль (т, комплектующие, Т5) ← Плутоний Pu (р) + Кремний Si (р)
  ├ Радиационная оболочка (т, детали, Т4)            ← Вольфрам W (р) + Свинец Pb (р)
  └ Силовой интерфейс (т, комплектующие, Т3)         ← Медь Cu (р) + Кремний Si (р)

Оборудование экстремальных сред «Панцирь-Э» (оборудование, Т6, капитальный барьер)
  ├ Термостойкий корпус (т, детали, Т4)        ← Титан-сплав Ti-6Al-4V (р) + Асбест (р)
  ├ Герметичный интерфейс (т, полимеры, Т3)    ← Полиэтилен (р) + Смолы (р)
  └ Датчиковая сеть (т, комплектующие, Т5)     ← Кремний Si (р) + Медь Cu (р) + Аргон Ar (р)

Вакцина-матрица «Иммун-7» (медикаменты, Т5, эпидемии)
  ├ Антиген-матрица (т, химикаты, Т3)        ← Белки (р) + Сахароза (р)
  ├ Стабилизирующая среда (т, химикаты, Т2)  ← Глицерин (р) + Вода H₂O (р)
  └ Реактив-консервант (т, химикаты, Т2)     ← Хлор Cl₂ (р) + Этанол (р)
```

**Это и есть «модель производства»:** верхушка Т8 — вершина, вниз — слои
производимых товаров (комплектующие/детали/узлы/подсистемы, тиры 2–7), в
основании — ресурсы тира 0. Один и тот же промежуточный товар (например,
«Контур охлаждения» или «Термостойкий корпус») может входить в несколько
верхушек — тогда цепочки пересекаются, экономика становится **сетью, а не
пучками**.

### 4. Что модель даёт (зачем мы это делаем)

- **Спрос ясен:** каждая категория привязана к потребителю — не «висящие»
  товары.
- **Глубина цепочек:** верхушка Т8 → производимые товары (комплектующие,
  детали, узлы, тиры 2–7) → ресурсы тира 0. Промежуточные товары — общие узлы
  сети (одна деталь на несколько верхушек).
- **Список «каких ресурсов нет»:** листья из каталогов; чего не хватило —
  помечаем (это вход для студии 99a и будущего генератора ресурсов).
- **Затравка для студии:** 100 верхушек с эскизами — точки входа в граф, тиры
  посчитает студия сама (шаг по тирам не важен, п.14). Промежуточные товары
  дополняются при вводе в студию (сеть строится там) — либо заранее в каталог,
  если создатель захочет (см. гейт).
