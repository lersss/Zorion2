## Диагностика (менеджер, факты)

- **Роль skycomposer проставлена** (БД, `users`): `skycomposer | skycomposer`.
  Гипотеза про роли **не подтвердилась**. Вкладка «Корабли» на сервере под
  `AdminAuth` (`admin` + `skycomposer`, `internal/auth/admin_auth.go`) — по ролям
  не ограничена; видимость вкладки не зависит от роли.
- **Данные есть**: таблица `ship_parts` содержит 49 деталей (hull 10, nose 10,
  wings 10, engine 9, tail 10). Сервер подключён к той же БД (`.env`:
  `127.0.0.1:5432/zorion`), `/health` и `/status` — 200.
- **Корень бага — HTML-структура `web/admin.html`:** вкладка «Корабли»
  (`<div id="tab-ships" class="tab-pane">`, стр. 448) **вложена внутрь** вкладки
  «Пользователи» (`<div id="tab-users" class="tab-pane">`, стр. 402): между
  `userProfileCard` (стр. 446) и комментарием «Вкладка: Корабли» (стр. 447)
  **нет закрывающего `</div>`** для `tab-users`. Баланс div по файлу: 127
  открыто / 126 закрыто — ровно один незакрытый.
- **Механика:** `.tab-pane { display:none }`, `.tab-pane.active { display:block }`
  (`admin.css:685-690`). При клике на «Корабли» `tab-ships` получает `.active`,
  но родитель `tab-users` остаётся `display:none` → контент вкладки невидим.
  JS работает без ошибок (запрос `/admin/ship-parts` проходит, рендер
  выполняется) — контент просто скрыт родителем. Отсюда «пустая вкладка» и
  «ошибок в JS нет».
- **Откуда взялось:** коммит `7fa19ce` (вкладка «Корабли») вставил блок после
  `userProfileCard`, не закрыв `tab-users`.

## ТЗ

строки с `userProfileCard`, перед комментарием «Вкладка: Корабли». Больше
ничего не менять (хирургически). Проверка: баланс div 127/127; визуально
вкладка «Корабли» рендерит каталог (49 деталей, 5 категорий).
