## Сырое пожелание (создатель, 2026-09-15)

> «Внешний вид двойных систем (графика) ничем не отличается от одинарных»

## Факт из кода (менеджер, диагностика)

Двойные/кратные генерируются (5%/2%, см. спеку 99.2.4 §4.1), но **нигде в
графике не используются**:

- **Карта галактики** — `web/static/js/map/map_render.js`:
  - `drawSingleStar` (строки 208–269) и `drawCluster` (271–296) рисуют **один
    круг** на систему; цвет — `getStarShade(спектр, температура, star_type)`
    (`map/utils.js:29`). Поле `system_type` при отрисовке **не читается вовсе**.
  - Данные уже приходят: `data.js:120,307` — `system_type: w.system_type || 'single'`.
- **Модалка системы** — `web/static/js/modal/modal_render.js`, СЛОЙ 2 (строки
  40–48): рисуется **одна** звезда (`ctx.arc(cx, cy, finalStarRadius, ...)`).
  Компаньон не отрисовывается: для wide (S-тип) — просто одна звезда; для
  close (P-тип, планеты обращаются вокруг пары) — нарисована одна звезда при
  физически правильной картине из двух — визуально неправильно.
- Текстовая индикация уже есть: в панели модалки бейджи «двойная широкая
  (S-тип)» / «двойная тесная (P-тип)» (`modal/utils.js:104–105`), метка типа
  системы (`modal/index.js:249`, `systemTypeLabel`). Визуально — на карте и в
  модалке система неотличима от одиночной.

Поле `system_type` (`single`/`binary`/`multiple`) и `stellar_mods`
(`binary_type` wide/close, `companion` спектр) доступны во фронте — данных
для отрисовки достаточно, нужна только графика.

## Вопрос по визуалу (решён создателем 2026-09-15)

> «везде, где рисуется» — и на карте, и в модалке.

Утверждён эскиз: на карте — маленькие точки-компаньоны (приглушённый цвет
главной), в модалке — реальный компаньон по `binary_type` (close — две звезды
в центре, wide — компаньон на малой орбите), цвет по спектру компаньона.

## ТЗ (утверждено создателем 2026-09-15, «везде, где рисуется»)

Правки только frontend (JS). Go не трогаем, API не меняем, рестарт не нужен
(статика с диска, noCache).

### Карта (`web/static/js/map/map_render.js`, `drawSingleStar`, cnt==1)

После основной звезды и до оверлеев (focus/current/hover) — точки-компаньоны
по `c.systype` (в `drawCluster` НЕ рисуем — агрегат):

- `binary`: одна точка, угол 45°, расстояние `max(3px, radius*1.5)`,
  радиус `radius*0.45`, `fillStyle = color` (тот же `getStarShade` главной),
  `ctx.globalAlpha = 0.6`, без обводки.
- `multiple`: две точки при 30° и 150°.
- `globalAlpha` вернуть в 1 после отрисовки.
- `drawCluster` — без изменений.

### Модалка (`modal_render.js` + `state.js` + `index.js`)

- `state.js`: добавить в `modalState` поля `systemType: 'single'`,
  `binaryType: ''`, `companionColor: ''`.
- `index.js` в `renderModal` (после строк ~335–340):
  `modalState.systemType = (data && data.system_type) || 'single'`;
  из `(data && data.stellar_mods) || {}` — `binaryType = mods.binary_type || ''`,
  `companionColor = getStarColor(mods.companion, 'star')` (getStarColor уже
  импортирован в index.js; `mods.companion` — спектр-буква O..Y).
- `modal_render.js` СЛОЙ 2 (после основной звезды):
  - `close` (P-тип): компаньон вплотную справа: `x = cx + finalStarRadius*0.8`,
    `y = cy`, радиус `finalStarRadius*0.5`, цвет `companionColor`,
    `globalAlpha = 0.7` (вернуть 1). Орбиты планет — вокруг `cx,cy`
    (барицентр), уже так; физика верна для P-типа.
  - `wide` (S-тип): компаньон на медленной орбите: угол `timeMs * 0.0002`,
    дистанция `max(12, finalStarRadius*1.8)`, радиус `finalStarRadius*0.45`,
    цвет `companionColor`, alpha 0.7. Планеты вокруг `cx,cy` — физика верна
    для S-типа.
  - `multiple`: как wide, вторая точка на +60° от первой.
  - `systemType === 'single'` / отсутствие binaryType — ничего нового не рисуем.

### Критерии готовности

- На карте: у одиночных систем (cnt==1) с `systype=binary` рядом видна малая
  точка-компаньон; у `multiple` — две; у single — без изменений. Кластеры
  (cnt≥5) — без изменений.
- В модалке: close — две звезды в центре, планеты вокруг пары; wide —
  компаньон на малой орбите вокруг главной; single — как раньше.
- DoD: `node --check` всех затронутых JS-файлов — 0 ошибок. Go не затронут,
  рестарт не нужен (noCache).
