# 39a. Баг: сумма весов типов систем не считается (Cannot read properties of null)

**Создано:** 2026-09-15
**Статус:** Готово (2026-09-15). Подтверждение создателя: «ок». Вердикт @tester: ПРОЙДЕНО.
**Приоритет:** баг (🟡 — некритичный, блок весов в админке не ломает генерацию)

---

## Сырое пожелание (создатель, 2026-09-15)

> «Cannot read properties of null (reading 'value') в генерации звезд. Там же
> смотрю на веса типов систем/объектов, там сумма --»

## Диагностика (менеджер, факты)

- Ошибка JavaScript в админке, блок «⚖️ Веса типов систем/объектов»: сумма
  остаётся `—` (дефолт `Сумма: —`), в консоли `Cannot read properties of null
  (reading 'value')`.
- **Корень:** `recalcGenWeights()` в `web/static/js/admin/generation.js` (стр.
  719) читает `.value` у элементов `sw<cls>` (стр. 723) и `st<key>` (стр. 738)
  **без null-проверки**. Если хоть один элемент отсутствует — исключение
  выбрасывается до обновления `systemTypeWeightsSum` (стр. 747) → сумма
  остаётся дефолтной `—`, а в консоль падает ошибка.
- Соседние чтения в той же функции (`sw<cls>_pct`, `spectralWeightsSum`,
  `systemTypeWeightsSum`) уже защищены `if (el)` — стиль файла, в двух местах
  его не придерживаются.
- На текущей отдаваемой сервером странице (`GET /admin` → 200) все элементы
  весов на месте (`stSingle..stExotic`, `swO..swY` — проверено по HTTP-ответу).
  Значит, у создателя страница рассинхронизирована с кодом (кеш браузера,
  старая версия admin.html до добавления части весов). Код при этом
  незащищён: любой рассинхрон HTML/JS ломает блок.
- Тот же класс риска в `saveGenConfig()` (стр. 803, 807, 811, 816, 817) —
  незащищённые `.value`; срабатывает при клике «Сохранить конфиг». В ТЗ не
  входит (симптом не репортирован), отмечено как рекомендация.

## ТЗ

Одна правка в `web/static/js/admin/generation.js`, только в `recalcGenWeights()`:
добавить null-проверку перед чтением `.value` в обоих циклах (спектральные,
стр. 723; типы систем, стр. 738) — по образцу соседних `if (el)`. Отсутствующий
элемент = вес 0, функция не падает, сумма считается по найденным. Больше ничего
не менять (хирургически). Go/HTML не трогаем.

## Критерии готовности

- `recalcGenWeights()` не падает при отсутствии любого из элементов весов
  (симуляция: вызов с несуществующим id → сумма по существующим).
- При всех существующих элементах поведение не меняется (сумма считается
  как раньше).
- `node --check web/static/js/admin/generation.js` — зелёный.
- Go не менялся → DoD `go build/vet/test` не требуется.

## Реализация (2026-09-15)

`web/static/js/admin/generation.js`, `recalcGenWeights()`: в обоих циклах
чтения весов элемент берётся через `document.getElementById(...)` с проверкой
`if (el)`; при отсутствии — вес 0.

## Вердикт @tester (2026-09-15)

**ПРОЙДЕНО.** `node --check` — зелёный; HTTP-отдача `generation.js` (200,
no-cache) содержит паттерн `const v = el ? (parseFloat(el.value) || 0) : 0;`
ровно 2 раза (оба цикла). Smoke в Node с заглушкой `document` (отсутствуют
`swY` и `stExotic`): NO CRASH, веса отсутствующих = 0, спектральная сумма 30.0
(10+20), системная 80.0 (50+30), проценты корректны (33.3%, 62.5%). Хирургичность
подтверждена: остальные `.value`-чтения (`saveGenConfig`, `regeneratePlanets`)
не тронуты. Go не менялся — DoD не требовался. Замечание: в `saveGenConfig`
остались незащищённые `.value` — та же ловушка при будущем ленивом рендере,
вне объёма фикса.
