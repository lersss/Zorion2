# 61a. Смена конечной точки полёта в пути + честная длительность полёта

**Создано:** 2026-09-16
**Статус:** ✅ Готово (2026-09-16, подтверждено создателем «ок» на коммит)
**Приоритет:** фича (UX, путешествия)

## Сырое пожелание (создатель, 2026-09-16)

> «Дай возможность админу менять конечную точку полета. Сейчас невозможно. И роли skycomposer тоже»

**Уточнение (создатель, 2026-09-16):**
- Это НЕ про админские ручки для чужих полётов: сам админ (и skycomposer) **как игрок**
  в полёте выбирает другую звезду — система не должна отвечать «уже в полёте»,
  а принять новую конечную точку (полёт перенаправляется).
- Разрешено **всем игрокам**, не только admin/skycomposer («хорошо, всем игрокам»).
- «Заодно давай сделаем его честным, не ускорять из-за превышения лимита времени полёта» —
  **убрать потолок 20 сек** (решение создателя 2026-09-16; заменяет решение 2026-09-14
  о капе 20 из идеи 16f). Минимум 3 сек сохраняется (он не ускоряет, а защищает
  от телепортов между близкими звёздами — решение менеджера, не трогаем).

**Редирект из текущей точки (решение создателя 2026-09-16):**
- При смене цели корабль продолжает из **текущей точки маршрута** P, а НЕ отскакивает
  к стартовой звезде (визуальный баг заметил создатель).
- P вычисляет **сервер** по прогрессу старого полёта: `progress = elapsed/duration`,
  `P = lerp(fromCoord, toCoord, progress)` — клиент точку НЕ передаёт (защита от абьюза).
- Новый полёт: стартовая точка P → новая цель; длительность `dist(P, цель) × 0.3 сек`
  (мин 3, без потолка); стартует с `now()`.
- Модель полёта получает **стартовые координаты** (`start_x`/`start_y`), отличные от
  координат мира отправления; при обычном старте = координаты FromWorld.
- Панель полёта по-прежнему показывает миры (From = исходный мир отправления).

**UI полёта в шапке карты (решение создателя 2026-09-16):**
- Блокировка действий/информации мира отправления в полёте — **НЕ входит в текущий
  релиз** (решение создателя: «это неважно в текущем релизе»; проверку `IsInFlight`
  для контрактов не добавляем, модель `current_world` не трогаем).
- Тост-уведомления полёта («Полёт начат», «Курс изменён», «Полёт отменён») **убираем**;
  их информация переносится в шапку карты вместо надписи «Текущий мир»:
  - в полёте: шапка показывает **«В полёте: From → To»**;
  - по прибытии/отмене: возвращается **«Текущий мир: X»**.
- Панель «🚀 Перелёт» (#flight-panel) и статус-бар «🚀 В полёте... осталось N сек»
  остаются. Тост-ошибки (notifyError) остаются.
- Вариант Б (сдвиг `start_time` на линию from→newTo) отклонён: корабль «перескакивал»
  на линию нового курса на той же доле пути — нечестно для сильно другого направления.

## Диагностика (менеджер, факты из кода)

- **Сервер:** `StartTravel` (`internal/handlers/travel_handlers.go:122–125`) —
  блок: `if h.travelManager.IsInFlight(userID) { http.Error(w, "Already in flight", 400) }`.
- `travel.Manager.StartFlight` (`internal/travel/manager.go`) **уже умеет заменять**
  активный полёт: закрывает старый `CancelChan` и стартует новый с новым `StartTime`.
  Горутина старого полёта при пробуждении не удаляет чужой полёт (сравнение указателей),
  `onArrival` старого не вызывается → редирект не требует новых методов менеджера.
- Проверка `fromWorldID == req.WorldID` («Already in this world») остаётся: при редиректе
  `from` — мир отправления, менять нельзя.
- **Фронт:** `startFlight()` (`web/static/js/map/flight.js:72–75`) — guard
  `if (state.isFlying) { notifyError('Уже в полёте'); return false; }`. Все вызовы
  (карта, модалка системы) идут через эту функцию — один фикс.
- `state.userRole` уже есть в памяти фронта (`web/static/js/map/data.js:296`, из `/me`) —
  но по решению создателя разрешаем всем, роль для guard'а не нужна.
- **Формула:** `calcTravelDuration` (`travel_handlers.go:46–58`): `dist × 0.3 сек`,
  мин 3 сек, потолок 20 сек (кап от 16f). Потолок срезает зависимость от расстояния
  для dist > 66.
- **`/me`** отдаёт актуальный полёт после редиректа автоматически (StartFlight заменил) —
  восстановление после рефреша (идея 42a) работает без изменений.

## ТЗ

**1. Сервер (`internal/travel/manager.go`, `internal/handlers/travel_handlers.go`, `internal/handlers/auth_handlers.go`):**
- `travel.Manager`: `TravelInfo` получает стартовые координаты `StartX/StartY float64`
  (точка старта текущего сегмента; при обычном старте = координаты FromWorld,
  при редиректе = текущая точка P). `StartFlight` — принимает `startX/startY`
  (или отдельный метод); обновить все вызовы (StartTravel, тесты).
- `StartTravel`: убрать блокировку `IsInFlight` — всем игрокам разрешён повторный `/travel`
  в полёте.
  - Проверка `from == to` («Already in this world») сохраняется.
  - Идемпотентность: запрошенная цель == текущей цели → вернуть текущий полёт без сброса
    (202).
  - Редирект (новая цель): сервер считает `progress = elapsed/duration` старого полёта
    (зажат 0..1), `P = lerp(старый fromCoord, старый toCoord, progress)`; новый полёт
    стартует из P → новая цель, длительность `dist(P, цель) × 0.3 сек` (мин 3, без
    потолка), `start_time = now()`.
- `TravelResponse` — добавить `start_x`/`start_y` (стартовая точка) и `start_time`
  (UnixMilli) — фронт берёт их из ответа.
- `GetMe` (`/me`, идея 42a): в поле `flight` добавить `start_x`/`start_y` — для
  восстановления полёта после рефреша.
- **Редирект-точка P для КАСКАДНЫХ редиректов берётся от `flight.StartX/StartY`**
  (фактической точки старта предыдущего сегмента), НЕ от `fromWorld.CoordX/Y`.
  Найденный баг (создатель, 2026-09-16): при частых редиректах стартовая точка
  предыдущего полёта считалась от МИРА ОТПРАВЛЕНИЯ A, хотя полёт мог стартовать
  из точки P → корабль «перескакивал» на линию A→нов.цель, при малом прогрессе это
  выглядело как сброс к планете вылета. Фикс: `redirectStartPoint` для предыдущего
  сегмента вызывается с `(flight.StartX, flight.StartY, oldTo.CoordX, oldTo.CoordY)`.
  Фолбэк при удалённом oldTo (перегенерация) — старт из `flight.Start` (текущая
  позиция), не из fromWorld.
- **Возврат в мир отправления во время полёта** (баг создателя 2026-09-16): выбор
  `fromWorldID` (= `user.CurrentWorldID`, мир отправления, меняется только по прибытии)
  во время полёта раньше отвечал 400 «Already in this world» — игрок не мог вернуться.
  Фикс: при активном полёте выбор мира отправления = **отмена полёта** (новый метод
  `travel.Manager.CancelFlight(userID)`), ответ 202 `{"status":"cancelled", ...}`,
  `current_world` не меняется (он и есть мир отправления). Без полёта — прежний 400
  «Already in this world» остаётся.
- `calcTravelDuration`: убрать ветку потолка `> 20*time.Second`, минимум 3 сек остаётся.
- TDD: тесты `internal/handlers/travel_handlers_test.go`:
  - редирект в полёте: второй `/travel` с новой целью → полёт заменён, стартовые координаты
    = точке P (progress учтён), новая `to`, новый `duration`;
  - **каскадный редирект**: два редиректа подряд — стартовая точка второго берётся от
    `flight.StartX/StartY` (точки P первого), а не от fromWorld;
  - idempotent: та же цель → полёт не перезапущен (стартовые координаты/start_time не
    изменились);
  - обычный старт: стартовые координаты = координатам FromWorld;
  - честная длительность: dist > 66 → duration > 20 сек;
  - регрессия: «Already in this world» на месте.

**2. Фронт (`web/static/js/map/`):**
- `config.js`: `state.flyStartX/flyStartY` (стартовая точка сегмента).
- `flight.js`: убрать guard `state.isFlying`; при успехе `state.flyStartX/Y =
  data.start_x/start_y`, `state.flyStartTime = data.start_time` (НЕ `Date.now()`);
  тост «Курс изменён: X → Y» если игрок уже был в полёте.
- `map_render.js` `drawFlight`: стартовая точка `(flyStartX, flyStartY)` вместо
  координат `flyFrom` (lerp от стартовой точки к `flyTo`).
- `navigation.js` `centerOnAgent`: lerp от `(flyStartX, flyStartY)` к `flyTo`.
- `data.js` `getFlightBounds`: скорость/полоса впереди — от стартовой точки к `flyTo`;
  восстановление 42a: `state.flyStartX/Y = user.flight.start_x/start_y`.

## Критерии готовности

- В полёте выбор другой звезды → полёт перенаправлен: корабль продолжает из ТЕКУЩЕЙ
  точки маршрута (не отскакивает к стартовой звезде), летит к новой цели, панель
  показывает новую цель, тост «Курс изменён».
- В полёте выбор той же звезды → ничего не сброшено, полёт продолжается.
- Длительность полёта — `dist(старт.точка, цель) × 0.3 сек`, минимум 3 сек, без потолка.
- Полёт без смены цели — поведение не изменилось.
- DoD по `AGENTS.md` §2 (`go build`/`go vet`/`go test ./...`; фронт: `node --check`).
