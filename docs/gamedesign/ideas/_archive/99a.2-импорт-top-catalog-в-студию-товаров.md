## Уточнения диалога (решения создателя, 2026-09-19)

1. **Триггер — кнопка в UI студии** (эндпоинт; файл по умолчанию
   `goods_data/top_catalog.json`), не автоимпорт при старте.
2. **Статус импортированных топ-товаров — сразу «согласовано» (approved)**
   (поедут в экспорт; возможность исключить остаётся).
3. **`why_top` — выкидываем** (в модель студии описание не добавляем).
4. **Замена — полная** (не merge): каталог заменяет существующие товары студии.
   **Ресурсы (129, read-only) НЕ трогаем** (создатель: «ресурсы не нужно трогать») —
   остаются базой графа. Ручные черновики входят в «заменять всё» (сносятся).
5. **Файл `top_catalog.json` не модифицировать** — импорт только читает.
6. **Отображение:** после импорта — посмотреть глазами, как каталог ляжет в
   студию; из-за переиспользования компонентов отображение связок может
   пострадать; чем жертвовать — решим после просмотра (варианты: рёбра не
   рисовать / как есть / выборочно).
7. **Количество в слотах (решение создателя 2026-09-19):** «будем оба сценария
   пробовать. Пока давай количественно просто выражать — на Т2 должно быть
   необходимо меньше резины, чем на Т5». Слот получает **количество** (единиц
   составляющей): различие «резина в Т2 vs резина в Т5» выражается количеством
   в рецепте, а не отдельными сущностями. Это **санкционирует итерацию
   количества** из спеки 99a.1 §6.4/§10.13 («1 слот = 1 единица; поле количества —
   будущая итерация корзины качества» → вводим сейчас): модель `Slot.quantity`
   (дефолт 1, старые слоты без миграции — zero value), UI (показ/ввод количества
   у слота), экспорт (`quantity` в формате §11 уже есть — заполняется реальным).
8. **Оба сценария переиспользования — пробуем вживую** (решение создателя
   2026-09-19): (а) одинаковое имя = один узел (штатный резолв §6.3) — работает
   как есть; (б) разведение по тирам — выражаем количеством (п.7) и/или именами
   с тиром, смотрим на живом каталоге и решаем.

## Факты (сверка с проектом, собрал @manager 2026-09-19)

- **Формат `top_catalog.json`:** `{schema_version:1, catalog:"top-goods",
  generated_at, summary{total:100, per_category, demand{continuous:69, spike:31}},
  goods:[{id:"tg_0001"…, name, category, why_top, constituents:[{name, type:
  "resource"|"good"}]}]}`.
- **100 товаров**, у каждого 2–4 составляющие, все заполнены; **дубликатов имён
  нет** (проверено). Категории каталога (13) **совпадают с категориями студии
  по имени 1:1** (включая c13 «Модули кораблей»).
- **Составляющие: только name+type, id нет ни у одной из 304.**
  - `resource`: **все (100%) находятся по имени** среди ресурсов студии
    (слой 20 + витрина 111; 0 ненайденных — проверено по state.json).
  - `good`: **ровно 8 уникальных внешних компонентов** (ароматический комплекс,
    витаминный комплекс, жировой концентрат, катализатор, минеральный премикс,
    присадочный комплекс, Питательная паста, Синтезированный белок). Два из них
    **уже есть в студии** как черновики («Питательная паста», «Синтезированный
    белок») — резолв по имени даст ссылку на них (§6.3). Шесть — новые.
  - **Внутренних ссылок на топ-товары нет (0)** — топ-товары не ссылаются друг
    на друга, только на ресурсы и 8 внешних компонентов.
- **Резолв по имени** — штатный механизм студии (спека 99a.1 §6.3: нормализация,
  совпадение = ссылка на существующий узел, не дубль).
- **Модель студии:** `Good{id, name, category, status, kind, source, recipe[]Slot,
  created_at, resource_ref}`; слот = `{good_id, reason, allow_resource}`; 1 слот =
  1 единица. Статусы: draft/approved/excluded/banned/resource.
- **API студии** (`cmd/goods-studio/handlers/http.go`): есть `/api/state`,
  `/api/resources`, `/api/categories`, `/api/goods`, `/api/export`, `/api/validate`;
  **импорта НЕТ** — новый эндпоинт + кнопка в UI (`web/index.html`).
- **Игровой сервер не трогается** (инвариант 99a.1 §14.2); студия — отдельный
  бинарь (порт 8799).
- `goods_data/` **вне git** (`.gitignore`); `top_catalog.json` не в git.
- Клиентский флоу студии → прогон e2e-смоука `tools/e2e/goods-studio-check.js`
  (правило тестера, решение создателя 2026-09-18).

## Развилки для @designer

1. **Парсер** — новый пакет/файл в `cmd/goods-studio/catalog/` (рядом с
   `import.go` ресурсов): чтение top_catalog.json, маппинг на модель.
2. **Замена состояния** — как именно: каталог → товары (approved) + 6 новых
   компонентов + 8 ссылок на внешние good; ресурсы остаются; черновики сносятся;
   категории — по имени (новые из каталога — создать).
3. **Статус 6 новых внешних компонентов** — предложение: `draft` (их состав
   неизвестен — пустые рецепты; approved с пустым рецептом даст валидатор
   «неполные цепочки»). Топ-товары — approved.
4. **Эндпоинт** — `POST /api/import` (путь файла опционально, дефолт
   `goods_data/top_catalog.json`); ответ — новое состояние + отчёт (что
   импортировано, что снесено, что создано новым, предупреждения).
5. **Кнопка «Импорт» в UI** — рядом с «Экспорт»; подтверждение (замена полная!);
   тост-отчёт.
6. **Отображение связок** — решение после просмотра; в первой итерации импорт
   + рендер как есть (граф уже рисует переиспользуемые узлы одним экземпляром).
7. **Количество (п.7 решений):** `Slot.quantity` (int, дефолт 1) — модель,
   UI (показ + ввод у слота), экспорт (quantity уже в формате §11), импорт
   (в каталоге количеств нет → все слоты = 1; инструмент количества нужен для
   ручной правки и будущего формата каталога). Попутно: дельта в спеку 99a.1
   (§6.4, §10.13, §10.3 — инвариант «1 слот = 1 единица» меняется).

## Заполнение внешних компонентов (2026-09-19, живой прогон)

После импорта вживую валидатор дал ожидаемые 16 предупреждений (спека 99a.2 §9):
8× «Каких ресурсов нет» + 8× «Ссылка на не-согласованного» (внешние компоненты —
draft с пустыми рецептами). Создатель: **«заполни»**.

**Решение:** каждому из 8 внешних компонентов заполнен рецепт из существующих
ресурсов каталогов (слой 20 + витрина 111, read-only) и статус → **approved**
(через API студии: POST slots → PUT slots/{n} → POST status). Состав:

| Компонент (ext:*) | Рецепт (ресурсы каталога) |
|---|---|
| ароматический комплекс | органика-ресурс, Сахароза, Этанол |
| витаминный комплекс | органика-ресурс, Белки, Сахароза |
| жировой концентрат | Жиры/масла, Глицерин, морская биомасса |
| минеральный премикс | Соль NaCl, Кальций, Калий, Магний |
| присадочный комплекс | Этанол, Толуол, Бензол |
| Питательная паста | Белки, Крахмал, Жиры/масла, Вода |
| Синтезированный белок | Белки, органика-ресурс, Вода |
| катализатор | Кобальт, Никель, Медь |

**Итог:** 108 товаров (100 `tg_*` + 8 `ext:*`), все approved, **предупреждений
валидатора: 0**; экспорт чистый (complexity компонентов = 1). Данные — только в
`goods_data/state.json` (вне git), код студии не менялся. Примечание: состав
компонентов — контент-решение (эскизное, при пересборке графа в студии
пересматривается), не эталон.
