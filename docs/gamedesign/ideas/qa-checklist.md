## Проблема

У проекта есть автотесты (43 файла `*_test.go`) и журнал ручных проверок `docs/QA.md`,
но нет формальных тест-кейсов: `@tester` каждый раз импровизирует сценарии по рискам
AGENTS.md §0. Кроме того, `docs/QA.md` растёт как журнал (append-блоки) — дублирует
git-историю и раздувается.

## Решение

### 1. Файл `docs/QA_CHECKLIST.md` — реестр «проблема → время последней проверки»

Файл НЕ растёт: при каждом прогоне перезаписывается только дата в колонке
«Последняя проверка». Структура:

- **Уровень Ядро (гонится всегда, 7 кейсов):**
  - A1 — сервер стартует, `/health` отвечает;
  - A2 — регистрация → логин → `/me` с JWT;
  - A3 — генерация мира через админку → мир и планеты есть;
  - A4 — карта открывается, система открывается в модалке;
  - A5 — полёт туда-обратно между системами не падает;
  - A6 — конкурентные риски §0: одновременные запросы/ws не роняют процесс;
  - A7 — аудит не падает на сгенерированном мире.
- **Уровень Зоны (таргетированно, 2–5 кейсов каждая)** — карта зон по пакетам
  (AGENTS.md §3): auth, генерация (галактика/планеты/фракции), экономика/поселения,
  полёты, карта/фронт, админка, аудит. Кейсы — сквозные/ручные сценарии, НЕ
  дублирующие автотесты (в чек-лист идёт только то, что Go-тесты не покрывают:
  сквозное, конкурентность, UI).

Правило прогона: дифф задачи → **Ядро всегда + только зона(ы), которых коснулись
правки**.

### 2. Судьба `docs/QA.md`

Журнал отчётов больше не ведём: `docs/QA.md` → заглушка-указатель на
`QA_CHECKLIST.md` (история прогонов остаётся в git).

### 3. Судьба найденных багов

Баг при прогоне → (а) новая запись «проблема → время последней проверки» как
регрессионный кейс своей зоны в чек-лист; (б) задача на исправление через @manager.

### 4. Актуализация (кто / когда / критерии)

- **@tester, каждый прогон:** нашёл сценарий вне чек-листа или устаревший кейс →
  строка «Предложение в чек-лист: …» в отчёте прогона.
- **@manager:** собирает предложения, согласует, применяет. При маршрутизации:
  дифф затронул пакет без зоны в чек-листе → зона добавляется сразу.
- **Перевод в Ядро:** только по решению игрока, критерий — «поломка = нельзя
  играть / краш / потеря прогресса». Правки Ядра — гейт с игроком; добавление
  кейса в зону — упрощённо (тестировщик + менеджер).
- **Источник кейсов зон:** в основном из найденных багов (регрессионные).
- Удаление из Ядра — событие, тоже по решению игрока.

### 5. Правки конфигов агентов

- `.opencode/agents/tester.md`: формат работы — обновлять даты в `QA_CHECKLIST.md`
  вместо append в `docs/QA.md`; в отчёт прогона добавлять строку «Предложение в
  чек-лист» при находке незакрытого сценария.
- AGENTS.md §4.14 (упоминание `docs/QA.md`) — проверить и обновить ссылку на
  новый формат.

## Критерии готовности

1. `docs/QA_CHECKLIST.md` создан: Ядро (7 кейсов A1–A7) + Зоны с кейсами.
2. `docs/QA.md` — указатель на чек-лист, без растущих блоков.
3. `tester.md` обновлён (перезапись дат, не append).
4. Упоминания QA-формата в AGENTS.md актуальны.
5. Регламент актуализации зафиксирован в чек-листе (секция «Актуализация»).
