## Симптом

`go test ./...` падает в `internal/handlers`:
`TestRegisterAssignsSpawnWorld` / `TestRegisterNoWorlds` / `TestRegisterFallbackClosestWorld` —
ошибка «JWT-секрет уже инициализирован». Тест зелёный в изоляции, падает только
когда до него в том же процессе другой тест уже вызвал инициализацию.

## Причина

`auth.InitJWTSecret` — глобал процесса (инициализируется один раз), вызывается из
двух тестовых файлов пакета (`auth_handlers_test.go` и `admin_users_test.go`).
Какой тест запустится первым — тот и «выигрывает», остальные падают. Порядок
тестов в пакете не гарантирован → флейк.

## Что нужно при починке (черновик)

1. Вариант A: вынести инициализацию в `TestMain` пакета `handlers` (один раз для
   всего пакета).
2. Вариант B: сделать инициализацию «идемпотентной» — повторный вызов с тем же
   секретом не падает (например, `sync.Once`-подобный хелпер в тестах).
3. DoD: `go test ./internal/handlers/` ×N стабильно зелёный, `go test ./...`
   зелёный.
