# Ловушки: Прочее

- **Строка нужды витрины поселения живёт ВНУТРИ блока `settlement.arithmetic`
  (спека 2026-09-24-потребление-по-товарам §10.2/§10.3, И3).** Поля нужды
  (`need`/`effect`/`covered_share`/`deficit_share`) и `norm` — на элементах
  `models.SettlementPositionArithmetic`, а не отдельным полем `Settlement`.
  Причина: очистка видимости (`playerSettlements` при выключенной настройке,
  `stripSnapshotSettlementSecrets` в снимке) обнуляет блок `arithmetic` целиком —
  отдельное top-level поле она НЕ покрывает (утечка игроку/снимку), а
  `planet_visibility.go` — чужая зона (belt-команда, мягкий локейт). Выносишь
  нужду в своё поле — обязан добавить его в ту же очистку.

- **`object_type='belt'` — перечислители (спека поясов этап 2 §5.4, 2026-09-22).**
  Значение добавлено в `object_type` внутрисистемного полёта. Точки, где значение
  перечисляется поимённо и обязано знать `belt`: `objectRadiusAU`, `targetInSystem`,
  `positionObjectValid`, `normalizeMyPosition`, `arrivalTargetValid`,
  `StartIntraFlight` (`intrasystem_handlers.go`), `resolveIntraStatus`
  (`players_positions.go`), `destinationInSystem`/`validateTravelDestination`/
  `autostartIntra` (`travel_handlers.go`), `switch objType` в Restore
  (`cmd/server/main.go`). Пропуск любой → пояс молча уходит в фолбэк «орбита звезды»
  или 400. Функции принимают `belts []models.Belt` рядом с `planets` — источник
  поясов обязателен в каждой точке.

- **Порядок удаления агента и возврата залога (контракты, B2, 2026-09-22).** При
  появлении агента-автора сперва вернуть залог его контрактов, затем удалять
  агента — иначе резолв плательщика не найдёт удалённого агента и уронит батч
  (пакман/очистка вселенной). Счёт агента (`accounts owner_type='agent'`) тоже
  чистить — FK нет, остаётся сиротой.

- **blocked_by текстурных тегов кораблей (ship_dict.json) — substring-матчинг
  коллизит с чужими токенами: «ice» в «pumice».** `blockedByMatch`
  (`cmd/art-studio/generator/ship_prompt.go`) исключает тег, если любой токен
  его `blocked_by` — подстрока любого токена `blocked` расы. Токен «ice» у
  холодных тегов («dense frost texture» и др.) ловил «pumice» (пемза) в blocked
  аммиачников — теги ошибочно исключались у расы, которая их НЕ блокирует
  (проверено 2026-09-20, диагноз визуального аудита ammonia). Правило: токен
  `blocked_by` проверять на коллизии со ВСЕМИ blocked-токенами рас, которые
  тег должен получать; при коллизии — брать токен без коллизии (у ледяных
  тегов — `["frost", "snow"]` вместо «ice»: все 26 рас, блокирующих «ice»,
  блокируют и «frost»). Аналогичная коллизия в парсере модулей: «бледный»
  содержит «лед» (б-л-е-д) — холодный стем корпуса «лед» давал ложный
  cold_hull; стемы «лёд»/«ледян» покрывают реальные слова без коллизии.

- **Go-структура с nil-слайсом сериализуется в JSON как `null`, а Python-скрипт
  силуэтов падает на `spec.get('modules', [])`.** `SilhouetteSpecJSON`
  (`cmd/art-studio/generator/ship_prompt.go`) маршалит `SilhouetteSpec.Modules`
  (nil, если в ТЗ нет секции «модули:») в `"modules": null` — скрипт
  `tools/make_ship_silhouettes.py` получал `None` из `.get('modules', [])`
  (ключ есть, значение null) и падал `TypeError: 'NoneType' object is not
  iterable` (проверено 2026-09-20 на пиксельных тестах форм без модулей).
  Правило: Python-чтение опциональных полей spec — `spec.get('modules') or []`
  (и `has_cockpit` — тот же паттерн), не `.get(key, [])`.

- **opencode serve: контракт HTTP-API (студия товаров 99a.1 §7.5, белое пятно
  спеки — решено на разработке).** Локальный opencode (`opencode serve`, порт
  по умолчанию 4096; конфиг — env `OPENCODE_URL/MODEL/TIMEOUT_S/MAX_RETRIES`
  (файл `config/goods/studio.json` удалён, iterC 2026-09-20)) отдаёт
  OpenAPI-спеку на `/doc`. Рабочий путь «заполнить комплектующие»:
  `POST {url}/session` → `{id}`; `POST {url}/session/{id}/message` с телом
  `{model, parts:[{type:"text", text: prompt}]}` → `{info, parts[]}` — текст
  ответа собирается из `parts` с `type=="text"`. Модель передаётся явно в теле
  (решение создателя: «модель должна быть явно указана»). 5xx/сетевые ошибки —
  retryable (`max_retries`), 4xx/парсинг — нет. Реализация:
  `internal/goodsstudio/ai/client.go` (перенос iterC 2026-09-20).
  **`default_agent` из `opencode.json` ломает fill:** проект задаёт
  `"default_agent": "manager"` — сессия без явного агента отвечает приветствием
  менеджера (7 векторов), а не JSON-составом: fill падает «invalid character
  looking for beginning of value». Фикс: в теле message передавать
  `"agent": ""` (пустая строка = сырая модель, проверено живым прогоном
  2026-09-19). Модель (deepseek-v4-flash) при этом иногда возвращает не-JSON —
  ретрай fill лечит (транзиентно).

- **Go-каталог `internal/resource` (layer.go/real.go) — больше НЕ источник
  каталога после сида (С1, спека переноса-студии-товаров-iterA §5).** Сидер
  (`internal/goodsstudio/seed.go`) читает его один раз при первом старте
  (маркер `goods_catalog_seed` в `generation_config`); после сида источник
  правды — БД (`categories`/`goods`/`goods_slots`). Правки студии (имя/
  категория/тир/статус/бан) Go-каталогом НЕ перезаписываются; удалённый
  ресурс не возвращается. «Обновить каталог из Go» — отдельное ручное
  действие (вне A). Новые ресурсы создаются в студии (кнопка «+ ресурс»),
  а не правкой layer.go/real.go.

- **`config/descriptions/README.md` содержит чужой текст** — описывает формат
  `config/anomalies/`. Не ориентируйся на него.

- **`.env` есть в истории git** (добавлен `5253b8c`, удалён `44e3cfc`).
  Содержит дев-креды, включая `admin123`.

- **Go не читал `.env` автоматически → `JWT_SECRET` «плавал» между рестартами**
  (баг 21a). До фикса сервер читал `JWT_SECRET` только из `os.Getenv`
  (`internal/config/config.go:48`); при ручном запуске бинаря `zorion-server.exe`
  секрет задавался «на глаз» — при каждом рестарте он мог отличаться, все
  выданные ранее токены умирали (401), фронт чистил localStorage и разлогинивал.
  Исправлено: в начале `main()` (`cmd/server/main.go`) вызывается
  `godotenv.Load()` ДО `config.Load()` — `JWT_SECRET`/`DATABASE_URL`/`REDIS_URL`
  берутся из `.env` единообразно. Поведение: уже заданные переменные окружения
  имеют приоритет (godotenv их не перетирает); отсутствие `.env` — только
  лог-предупреждение, не fatal (прод задаёт env иначе: Docker/Amvera).
  Соглашение: запускать сервер **из корня репо** (godotenv читает `.env` из
  рабочего каталога), либо задать `JWT_SECRET` в env явно.

- **Генерация спрайтов кораблей: модель режет корпус у края кадра.** На сырых
  txt2img-кадрах 1024 корабль уходит за край (проверено 2026-09-21: 28 из 44
  кадров касаются края в пределах 8 px — «половина не весь корабль влезает»);
  никакая постобработка это не восстановит. Правило: автопроверка кадра
  (`ship_frame_check` в `tools/spike_ship_sprite_cut.py`) — корабль не ближе
  `margin=8 px` к краю И (для 3/4-вида) вытянутость силуэта `λ1/λ2 ≥ 1.3`
  (фронтальный симметричный вид даёт ≈1.0); негодный кадр → следующий seed
  (детерминированный перебор, ≤ 6 попыток), в промпт — `entire spaceship fully
  visible...` и негатив `cropped, cut off, out of frame...`.

- **Корабли рас: выравнивание главной оси (PCA) ≠ определение носа.**
  `profile_orientation` (`tools/spike_ship_sprite_cut.py`, 2026-09-21) поворачивает
  силуэт по главной оси (PCA) — артефакты перестают быть «диагональными» — но
  направление нос/корма по силуэту различается ненадёжно: «двигательный» признак
  (яркое насыщенное свечение) путает голубое стекло кабины с соплами, а
  taper-профиль на 3/4-виде даёт ложные срабатывания. Правило: авто-ориентация —
  черновая; финальную сторону задаёт человек кнопками
  `/ships/act?what=rot90|rot180|flipH` (вкладка «Корабли рас»); при приёмке
  сверяй по тёплым соплам (оранжевое свечение `R>G>B` — они у кормы, значит
  нос с другой стороны). Тот же признак полезен при отладке: `warm`-масса
  слева/справа на финальном спрайте однозначно показывает сторону кормы.

- **Вырез кораблей: порог `edge` выбирается по фону кадра; фон рецепта —
  снова ЧЁРНЫЙ (2026-09-22).** Промпт фона (`ShipBackground`,
  `cmd/art-studio/generator/ship_prompt.go`) — «pure flat black background».
  Возврат с magenta-хромакея: magenta-фон заливал пунцовым САМ корабль (прогон
  126 кандидатов — 60 с пунцовым оттенком, 28 сильных; в сырых кадрах ComfyUI
  фон и корпус оба пунцовые), тогда как принятые ранее корабли на чёрном фоне
  пунцового оттенка не имеют (cast ≤ 0). Причина прежнего ухода с чёрного
  («фон режет тёмный корпус насквозь») закрыта не фоном, а методом: `--method
  edge` (flood от рамки + барьер по Собелю от размытой кромки) держит тёмный
  корпус. **Порог tol зависит от фона кадра:** чёрно-фоновые `--tol 40 --edge 20`,
  magenta-фоновые `--tol 100 --edge 20` (у magenta фон-градиент шире:
  «магента-ность» `m = min(R,B)−G` падает с ~158 до ~38, при tol=40 остаются следы
  градиента; на чёрном фоне tol ≥ 80 выедает тёмный корпус — доля съеденного при
  tol=100: Алмазные 0.21, Дисковые 0.31, Силикатные рои 0.34). Авто-детект фона —
  `postproc.ShipCutTol`/`isMagentaFrame` (студия, по пикселям рамки: 75-й квантиль
  `m` ≥ 40 → magenta; порт `is_magenta_bg`) и `is_magenta_bg` в
  `tools/ship_recut_pool.py` (там же `--tol`/`--tol-magenta`). **Остаточный фон
  не-чёрного/не-magenta цвета** у части рас (Дисковые — коричневый «горизонт»,
  Прибрежные — бирюзовое пятно, Серные рои — жёлтый) не убирается ни `edge`, ни
  `chroma` — это дефект генерации (нужен одноцветный фон), а не выреза. Хромакей
  по magenta (`--method chroma`) как рецепт НЕ используется (SDXL даёт градиент,
  а не ровную заливку); `hyst` и `chroma` оставлены в скрипте для сравнения/отката.
  Проверка — `tools/test_ship_sprite_cut.py` (синтетика + `is_magenta_bg`),
  Go-тест порога — `TestShipCutTol`/`TestMagentaNess` в
  `cmd/art-studio/postproc/ship_cut_tol_test.go`; сравнение методов —
  `tools/ship_cut_compare.py`; перерезка пула без перегона —
  `tools/ship_recut_pool.py` (сопоставление `sNN.png` ↔ сырой кадр ComfyUI по
  seed из `meta.json`; проверено бит-в-бит).

- **Расо-зависимый негатив фона кораблей: магента теперь запрещается (хромакей

- **Роль для UI-гейта — из токена, а не из БД.** Клиентский гейт (роль из `/me`) и серверные ручки должны читать **один источник** — роль из JWT. Иначе смена роли после выдачи токена даёт рассинхрон: панель впускает, а ручки отвечают 403 (тост «Не удалось загрузить поля: HTTP 403» и ошибки почти на каждой вкладке админки). Решение: `/me` (и поле `role` пакета поверхности) отдают роль из токена, фолбэк — БД; гейт выбора биома тоже по токену. Идея `docs/gamedesign/ideas/2026-09-23_403-в-админке-роль-из-токена-а-не-из-базы.md`.

- **Фича, импортирующая модуль из параллельной незакоммиченной задачи, не должна
  коммититься раньше него (2026-09-23).** `web/static/js/dashboard/money.js`
  импортирует `../game_date.js` — модуль параллельной задачи «календарь/присутствие».
  Пока календарь не был закоммичен, наш коммит раньше него уронил бы граф модулей
  на `/` и `/map`: импорт не разрешается → `money.js` не загружается (страница
  «жива», но блок денег мёртв). Правило: фича с импортом из чужой незакоммиченной
  правки ждёт её коммита либо коммитится вместе с ней одним релизом; порядок —
  сначала модуль-зависимость, потом потребитель.

- **Общий файл уносит чужие незакоммиченные куски в чужой коммит (2026-09-22).**
  Если правишь файл, помеченный в `docs/COORDINATION.md` соседом, коммить только
  свои hunk'и (`git commit -- <пути>` + проверка `git diff --cached`) — иначе
  незавершённая задача соседа уезжает в чужой коммит и ломает сборку в чистой
  копии. Случай: коммит «фракции» `7966a78` унёс кусок итерации 4 «экономика
  поселения» → `undefined: repository.ResolveDefaultSettlementTypeID` на сборке
  Amvera. Локально зелено (в дереве функция лежала) — поэтому проверять сборку
  именно в чистой копии `origin/master`, а не только у себя.

- **В хранилище сессий opencode под ролью `user` лежат служебные сообщения —
  считать «сообщения человека» по `role=user` нельзя (2026-09-24).** opencode
  прячет под ролью `user` служебные сообщения сжатия памяти (несколько на сессию),
  поэтому замер «активность от сообщения человека до сообщения человека» по
  `role=user` даёт мусор. Для метрик сессии (используется в `tools/agent-dash`)
  брать все сообщения сессии по времени, а не только `role=user`; активное время —
  от первого действия до последнего с обрезкой пауз.

- **Порядок валидаций `enter` в добыче пояса: трюм проверяется ДО ленивой
  инициализации запаса (лёд в поясе, 2026-09-24).** В `belt_mining_handlers.go`
  `enter` сперва отклоняет вход при полном трюме и только затем выполняет ленивую
  инициализацию запаса (`iron_remaining`/`ice_remaining`) — порядок **сознательно
  сохранён** из базовой спеки (не «чинить»). Полный трюм — отказ без записи в БД;
  смена порядка заставила бы вход с полным трюмом писать инициализацию впустую.

- **Экспорт/импорт контента: `items.unlocks` в БД хранит id, в снимке — метку/ключ;
  прочие JSONB-привязки каталога — имена (спека
  `2026-09-24-каталог-экспорт-импорт-контента-на-прод` §4/§5 п.6, И2/И3, канон
  итерации 4).** Схема (`000048`) описывает `items.unlocks` как
  `[{producer_type_id, category_id}]` — числовые id локальной базы, они не
  переносимы между средами. Поэтому снимок несёт `unlocks` **по метке/натуральному
  ключу**: `[{"producer": "<code p_NNNN>", "category": {"kind", "name"}}]`;
  экспорт резолвит id → метку/ключ (`translateUnlocks`,
  `internal/handlers/studio_content.go`), импорт — обратно в id-форму БД. Элемент,
  который не резолвится (id нет в снимке / чужая метка), — **отказ** снимка, не
  молчаливый пропуск; id в файл не попадает никогда. Формат БД в v1 **не меняется**
  (id-форма остаётся, трансляция — на границе export/import). Прочие JSONB-привязки
  ссылаются на **имена**: `producer_types.output`/`input` — на товары/предметы
  (`{"items":["Модуль корабля"]}`, `{"consumables":["механика"]}`),
  `params.effects` — на эффекты (`name_norm`, `000070`); их резолв идёт по
  имени/метке (осознанно).

- **Арт-студия: UI вшит в бинарь (`//go:embed web/index.html`,
  `cmd/art-studio/main.go`).** После правки `cmd/art-studio/web/index.html` нужна
  пересборка (`go build -o zorion-art-studio.exe ./cmd/art-studio`) и перезапуск
  студии, иначе браузер отдаёт старую страницу. Комментарий-предупреждение уже
  стоит в коде рядом с директивой.

- **Арт-студия правит ДАННЫЕ, а не код: реестр кораблей игры —
  `config/ships_registry.json`, читается игрой при старте.** Удаление корабля в
  студии вступает в силу в игре **ПОСЛЕ перезапуска сервера игры**. Файл писать
  **UTF-8 БЕЗ BOM** (PowerShell 5.1 иначе добавит BOM и Go его не разберёт).

- **Параллельные сессии: `git add` и `git commit` не атомарны — коммить
  `git commit --only -m "<msg>" -- <явные пути>` (2026-09-25, Э5.1).** Между
  чужим `git add` и завершением pre-commit-хука (он медленный: `go vet` +
  автосверка impact map) в индекс попадают файлы другой сессии, и обычный
  `git commit` без путей захватывает их целиком (в реальном случае — 28 чужих
  файлов ускорителя/полёта). Спасает `--only`/`git commit <пути>`: коммитит
  **только** перечисленное, чужие staged-файлы остаются в индексе. Откат ошибочного
  коммита: `git reset --soft HEAD~1` + `git reset` (mixed) и пересборка; пуш при
  этом не делать.
