## 0. Резюме (одним абзацем)

Процедурный генератор картинки планеты переводится с косметической текстуры по `visualType`
на **честную картинку из биомов** (поверхность: пятна по {form, share} с шум-границами, цвет по
контракту «биом → цвет») **и атмосферы** (дымка, лимб, свечение, облачный покров). Эндпоинт
`/api/planet-image` становится **авторизованным** (JWT обязателен) и принимает `planet_id`:
сервер сам решает режим картинки — **честная** (своя система / знание о планете / админ) или
**заглушка** (чужая система без знания; нейтральный силуэт, ничего не раскрывает). Заслонение
поверхности облачным покровом — **производная от видимых клиенту параметров** (тип, газовый
гигант, температура, вода, обитаемость, жизнь): атмосферные числа в генератор не входят —
инвариант 77a И1 соблюдён структурно. Один генератор на все типоразмеры: малая текстура
(канвас 256 → 20–40 px на канвасе орбит) и большая «вид с орбиты» (512 px, в карточке планеты
при `orbit {planet}` по 99.2.27). Кэш: in-memory по (планета, режим, размер) + диск-кэш PNG для
большой; 2–3 варианта на планету, нагрузка от числа уникальных планет (С3 гейта 1). Иконки
биомов (пачка 1, 23 шт) встраиваются в модалку рядом с составом (М1).

## 1. Цель и рамки

### 1.1. Цель

1. **Честная поверхность из биомов:** 100% кусков поверхности планеты ({form, share}, 99.2.28)
   → текстура (цвет/вид из параметров биома по контракту «биом → цвет», С2 гейта 1).
2. **Честная атмосфера по параметрам:** дымка, толщина лимба, свечение, облачный покров —
   вместо косметического «ободка» по флагу (текущий `applyPostProcessing`).
3. **Заслонение:** плотная атмосфера скрывает поверхность (облачный покров/дымка, биомы не
   видны) — решение создателя гейта 2 «честное заслонение».
4. **Заглушка для чужих систем** (гейт видимости 77a решён): планета и игрок в разных
   системах без знания → нейтральная картинка, не раскрывающая вид планеты; знание снимает
   заглушку (С3); админы видят всё (гейт 2).
5. **Большая картинка «вид с орбиты»** в модалке при `orbit {planet}` (99.2.27), 256–512 px.
6. **Иконки биомов** (пачка 1, 23 шт) в модалке рядом с составом (М1).

### 1.2. Рамки (что НЕ делаем)

- **Высадка** на поверхность — отдельная задача (вектор «Игрок»/«Поселения», после визуала).
- **Спутники на канвасе** — не рисуются (99.2.27 §5.8, v1); картинки спутников в v1 не нужны
  (фолбэк-контракт зафиксирован, §7).
- **Анимация** (вращение облаков, фазы) — косметика, вне скоупа; картинка статична.
- **Смена состояния биомов** (создатель: «сейчас пока не надо ничего менять») — вне скоупа.
- **Бэкфилл** старых миров — запрещён (99.2.28); старые миры — фолбэк (§7).
- **Миграции БД** — нет: кэш большой картинки — файлы на диске, не таблицы.
- **Прегенерация картинок в БД** — отклонено (С3 гейта 1: на лету с кэшем).
- **Второй генератор** для большой картинки — отклонено: один универсальный генератор на все
  размеры (решение создателя гейта 2).

## 2. Разворот подходов (история итераций)

### 2.1. Источник картинки

| Вариант | Как | Итог |
|---|---|---|
| **A. Серверная генерация на лету + кэш по seed (принято)** | как сейчас `/api/planet-image`, кэш in-memory по seed; большая — диск-кэш PNG | принято (С3 гейта 1): нагрузка от числа уникальных планет, не юзеров; ~1000 пользователей |
| B. Отдельный генератор большой картинки | второй конвейер, свои входы/кэш | отклонено: два источника истины, два кэша; один генератор на оба размера (гейт 2) |
| C. Прегенерация при генерации планеты | PNG в БД/диске при создании планеты | отклонено: бэкфилл старых миров невозможен, правки каталога биомов не отразятся (дрейф приемлем — С2), лишнее хранилище |

### 2.2. Заслонение: входы

| Вариант | Как | Итог |
|---|---|---|
| **A. Производная от видимых данных (принято)** | cloudCover = f(type, is_gas_giant, temperature, water_percent, habitable, life) — всё видимо игроку; атмосферные числа в генератор не входят | принято: И1 структурно (нет скрытого входа → нет утечки); калибровка под режимы 99.2.20 делает заслонение «честным» в типичных случаях (атмосфера каскада генерится из тех же параметров) |
| B. Реальная атмосфера (контракт @gdesigner полностью) | состав → цвет дымки, давление → лимб, τ_IR → glow, cloudFraction → облака | отклонено для player: `atmosphere_data` скрыта (77a strip) — скрытый вход в картинку; допустимо только как решение создателя (С1 «заслонение свободно») — вынесено в открытые вопросы §12.1 |
| C. Гибрид: реальная атмосфера с клампом к видимой | реальная, но ступень заслонения не выше ожидаемой из видимых данных | отклонено: сложно специфицировать и тестировать «кламп ±1 ступень» |

### 2.3. Заглушка

| Вариант | Как | Итог |
|---|---|---|
| **A. Нейтральный силуэт (принято)** | диск-силуэт с детерминированной по seed лёгкой полосатостью и тенью; без данных планеты | принято: не раскрывает тип/поверхность/атмосферу; детерминизм по seed — одинаковые планеты выглядят одинаково |
| B. «Туман»/пикселизация честной картинки | честная картинка, размытая | отклонено: пикселизация всё равно раскрывает цвет/структуру (тип угадывается) |
| C. Не рисовать планету | пустое место на орбите | отклонено: канвас «дырявый», хуже читается |

### 2.4. Алгоритм «share → пятна»

| Вариант | Как | Итог |
|---|---|---|
| **A. Посев пятен от крупных к мелким + шум-границы (принято, задано)** | сортировка по доле; крупные сеются первыми, мелкие втискиваются; границы пятен деформированы fbm | принято: органичные пятна, детерминизм по seed, доли приближённые (картинка — вид, не отчёт) |
| B. Voronoi-разбиение по центрам | клетки с весами долей | отклонено: резкие «клетчатые» границы, не стиль А |
| C. Симплекс-шум по долям (попиксельный выбор) | каждый пиксель — взвешенный выбор по шуму | отклонено: мелкая рябь без пятен, «шумный» вид |

## 3. Входы генератора и контракт API

### 3.1. Входы генератора (формальные)

**Честная картинка** (все роли — один генератор, одна функция):

| Вход | Источник | Примечание |
|---|---|---|
| `planet_id` (UUID) | запрос | идентификация; seed = детерминированный 64-бит хэш id (М3 закрыт: коллизии 32-бит хэша клиента уходят) |
| `biomes` [{form, share}] | `planets.data.biomes` | поверхность; старые миры без ключа → фолбэк §7 |
| `type` | планета (виден) | палитра, заслонение |
| `is_gas_giant` | планета (виден) | заслонение = 1.0 |
| `temperature` (K) | планета (виден) | заслонение, палитра |
| `water_percent` | планета (виден) | заслонение |
| `habitable`, `life` | планета (видны) | заслонение |
| `has_rings` | планета (виден) | кольца (существующая фича) |
| `size` (small/big) | запрос | типоразмер |

**Атмосферные числа (`composition`, `pressure_atm`, `tau_ir`, `cloudFraction`, `scale_height_km`)
в генератор НЕ входят** — для любой роли. Это решение И1 (77a): `atmosphere_data` скрыта для
player; картинка не может раскрыть то, чего нет на входе. Визуал атмосферы строится из
производной `cloudCover` + палитры по типу (§4.4) — адаптация контракта @gdesigner (см. §12.1).

**Заглушка:** только `planet_id` (seed) + `size`. Никаких данных планеты.

### 3.2. Контракт API

`GET /api/planet-image` — **становится авторизованным** (решение С2 гейта 2; 401 без JWT).

| Параметр | Тип | Обязателен | Значение |
|---|---|---|---|
| `planet_id` | UUID | да | id планеты (вместо seed/starType/climateId) |
| `radius` | int | нет | px; default 40; ≤ 40 — малая (канвас 256), ≥ 128 — большая (канвас 512); промежуточные — канвас 256 |
| `size` | string | нет | `small` \| `big` — явный выбор типоразмера (удобнее клиенту); если задан, `radius` игнорируется: small → 40, big → 512 |

- Заголовок: `Authorization: Bearer <JWT>`.
- Ответ: `Content-Type: image/png`, тело — PNG.
- Ошибки: 401 (нет/битый JWT), 404 (планета не найдена), 500 (генерация/кэш).
- Старый публичный контракт (seed/starType/climateId) **удаляется** — единственный потребитель
  `web/static/js/modal/textures.js` обновляется в этой же фиче (проверено: других вызовов нет).

**Серверная логика режима** (порядок):
1. Роль из JWT (`roleFromContext`): `admin`/`skycomposer` → честная всегда (И7).
2. `user.CurrentWorldID == planet.WorldID` → честная («своя система», гейт 2).
3. `KnowledgeRepository.GetKnowledge(userID, planetID) != nil` → честная (С3: скан при прошлом
   визите / купленный отчёт; **любая запись, включая протухшую** — знание о планете есть).
4. Иначе → заглушка.

### 3.3. Режимы картинки (таблица)

| Роль | Система | Знание | Режим |
|---|---|---|---|
| player | своя (`current_world_id == world_id`) | — | честная |
| player | чужая | есть (скан/отчёт) | честная |
| player | чужая | нет | **заглушка** |
| player | вне системы (межзвёздный полёт) | есть | честная |
| player | вне системы | нет | **заглушка** |
| admin / skycomposer | любая | — | честная |

### 3.4. Заслонение: входы и пороги (зафиксировано)

**Входы заслонения — только видимые клиенту:** `type`, `is_gas_giant`, `temperature`,
`water_percent`, `habitable`, `life`. Облачность — **производная** (решение §2.2-A):

```
cloudCover(planet):
  if is_gas_giant:                      return 1.00   // гигант: полосы, «поверхность» = полосы
  if temperature >= 350:                return 0.85   // жаркий: плотная дымка (калибровка Венера-режим, 99.2.20)
  if habitable:                         return 0.45   // обитаемый: умеренные облака
  if 250 <= temperature < 350:
      if water_percent >= 30:           return 0.40   // умеренный с водой: облака (Земля-режим)
      return 0.20                                       // умеренный сухой: лёгкая дымка
  return 0.10                            // холодный: тонкая дымка (калибровка Марс-режим)
  // life: +0.1, кламп <= 0.6 (жизненный проход — влажность, 99.2.20 §3.6)
```

**Ступени заслонения** (грубая шкала — картинка не несёт точных значений, С1):

| cloudCover | Ступень | Поверхность |
|---|---|---|
| ≥ 0.7 | полное заслонение | не видна (облачный покров; у гиганта — полосы) |
| 0.35–0.7 | частичное | видна местами (пятна облаков ~доля cloudCover) |
| < 0.35 | дымка | видна, лёгкий лимб |

Калибровка: атмосфера каскада (99.2.20) генерится из тех же параметров (режим по T₁, вода по
зоне, жизнь → O₂), поэтому производная повторяет реальную облачность в типичных случаях —
«честное заслонение» гейта 2 выполняется без скрытых входов. Исключения (tuned-миры 99.2.22 с
аномальным составом) дают визуальный дрейф — приемлемо (С2 гейта 1: «вращается планета»).

## 4. Процедурный генератор

Один генератор, стиль А «Орбитальная съёмка» (мягкий реализм, референс
`ai_drafts/planet_concepts/A_orbital.png` — по духу, не буквально). Слои (снизу вверх):

### 4.1. Слои

1. **Поверхность из биомов** — пятна по {form, share} (§4.3), цвет по контракту «биом → цвет»
   (§4.2). Для старых миров/гигантов — фолбэк (§7).
2. **Рельеф/текстура** — fbm-шум поверх пятен (лёгкая модуляция яркости), ridged-шум для
   «гористых» категорий (литосфера/вулканизм) — мягкий реализм без фототекстур.
3. **Яркость по альбедо** — средняя яркость пятна = f(albedo биома): albedo 0.1 → темнее,
   0.9 → светлее (альбедо есть в `BiomeDef`, 99.2.28).
4. **Атмосферный слой** (§4.4): дымка (палитра по типу), лимб (толщина по cloudCover), свечение
   (по типу), облака (по cloudCover).
5. **Заслонение** (§3.4): ступень ≥ 0.7 — облачный покров вместо поверхности; 0.35–0.7 —
   пятна облаков поверх; < 0.35 — только дымка.
6. **Постобработка** (существующий `applyPostProcessing`): тень, блик, мягкий терминатор —
   сохраняется, атмосферный «ободок» по флагу заменяется слоем 4.
7. **Кольца** (существующий `drawRings`) — для гигантов по seed; в заглушке колец нет.

### 4.2. Контракт «биом → цвет» (гибрид, С2 гейта 1)

```
biomeColor(biome, planet):
  if biome.color != "" → parse hex (переопределение из каталога, приоритет)
  base = categoryBase[biome.category]        // палитра категорий
  сдвиги:
    albedo → яркость (0–1: 0.1 → тёмный край, 0.9 → светлый край)
    liquid_medium → оттенок: вода → синева, метан → бирюза, аммиак → розоватость, co2 → желтизна
    temperature планеты → тепло/холод: T ≥ 350 → теплее, T < 250 → холоднее
  return base + сдвиги
```

**Палитра категорий** (база; примеры — от @gdesigner, 2026-09-20):

| Категория | База (hex) | Характер |
|---|---|---|
| литосфера | `#8a7a6a` → `#b8a88a` | серо-коричневые |
| вода | `#2a5a8a` → `#4a9eff` | синие |
| биосфера | `#2a6a3a` → `#7ac47a` | зелёные |
| вулканизм | `#3a2a2a` → `#c0392b` | красно-чёрные |
| крио | `#d0e8f2` → `#f0f8ff` | бело-голубые |
| экзотика | `#7a4a9a` → `#c86ae0` | неоново-пурпурные |

**Примеры (8 биомов):** горы `#8b7355`, пески_пустыни `#d4a373`, кратеры `#4a4a4a`,
океаны `#3498db`, луга_степи `#a3c644`, леса `#27ae60`, ледники `#d0e8f2`,
лавовые_поля `#e74c3c` (совпадают с существующими `FORM_COLORS` в `tabs.js` — согласованность).

**Опциональное поле `color` в `biome_catalog.json`:** `"color": "#aabbcc"` — переопределяет базу.
Редактируется **только в админке** (вкладка «Основное», редактор биома — `biomeCatalog.js`):
поле hex-цвета (color picker или text input) + валидация `#RRGGBB`; ручной правкой файла не
пользуемся (решение создателя: «руками ничего не правим, сразу делаем как будет»). Правка
каталога меняет вид существующих планет — дрейф приемлем (С2 гейта 1). Поле необязательное:
отсутствует у всех 57 биомов сейчас — база + сдвиги работают без него. Валидация — инвариант 17
(`Validate()` в `biome_catalog.go`, вызывается и из PATCH /admin/biome-catalog): `color` —
необязательный валидный hex `#RRGGBB` (при наличии); битый hex → ошибка (422 в PATCH).
**Неизвестный id биома** (правка каталога после генерации мира) → фолбэк-цвет по категории из
`type_tags`/имени, иначе нейтральный `#8a7a6a` (не падать).

### 4.3. Алгоритм «share → пятна» (детерминированный)

```
blobs(seed, biomes, canvasSize):
  K = max(8, canvasSize / 16)          // масштаб пятен: 256 → 16, 512 → 32
  sorted = biomes по share убыванию
  rng = rand.New(seed XOR hash(form))  // детерминированный RNG на биом
  пятна = []
  for biome in sorted:                 // крупные сеются первыми
    k_i = max(1, round(share_i / 100 * K))
    for j in 0..k_i:
      центр = случайная точка в диске (rng)
      радиус = R_base * sqrt(share_i/100) * (0.5 + rng * 0.5)
      пятна.append({центр, радиус, biome})
  растеризация: для каждого пикселя диска:
    для пятен в порядке добавления:   // крупные раньше — занимают свои площади
      если пиксель внутри пятна (граница искажена fbm: dist < радиус * (1 + 0.3 * fbm(p, seed)))
        и пиксель ещё не назначен → назначить биом
    остаток (незанятые пиксели) → доминирующий биом (max share)
```

- Детерминизм: RNG от (seed планеты, id биома) — одинаковый вход → одинаковое разбиение.
- Доли приближённые (пятна не дают точных процентов) — картинка «вид, не отчёт» (С1/С4);
  точные проценты — только скан (77a).
- fbm — существующий `noise.go` (`newValueNoise`).
- Минимальный биом (share ≥ 1%) всегда получает ≥ 1 пятно — все биомы состава видны.

### 4.4. Атмосферный слой (адаптация контракта @gdesigner)

Контракт @gdesigner (2026-09-20): цвет дымки из состава газов Σ тинтов×%, толщина лимба по
давлению/высоте, glowBoost по τ_IR, облака по cloudFraction. **Адаптация под входы §3.1**
(атмосферные числа не входят, И1): те же визуальные элементы, входы — `cloudCover` + палитра
по типу:

| Элемент | Вход | Правило |
|---|---|---|
| цвет дымки | `type` + `temperature` | палитра типов: гигант `#d8c8a8`, жаркий/вулканический `#e8c878`, умеренный с водой/жизнью `#7ab8e8`, холодный/ледяной `#c8dce8`, пустынный `#d8c8a8`, экзотика `#b8a0d8` |

### 4.5. Заглушка (нейтральный вид)

## 5. Размеры и кэш

### 5.1. Типоразмеры

| Типоразмер | Запрос | Канвас | Использование |
|---|---|---|---|
| малая | `size=small` (radius ≤ 40) | 256 | канвас орбит модалки, 20–40 px (как сейчас) |
| большая | `size=big` (radius ≥ 128) | 512 | «вид с орбиты» в карточке планеты, 256–512 px (CSS-масштаб) |

Один генератор на оба размера (гейт 2); масштаб пятен K зависит от канваса (§4.3).

### 5.2. Кэш

**Кэш-ключ** (М4: 2–3 варианта на планету, НЕ системы×планеты):

```
key = hash64(planet_id) + "|" + mode + "|" + size
mode ∈ {honest, stub}; size ∈ {small, big}
```

Роль в ключ **не входит** (решение §2.2-A: один генератор, одна картинка для всех ролей в
одном режиме; админ = honest, игрок со знанием = honest — картинки идентичны). Знание/позиция
в ключ не входят — они определяют режим, режим уже в ключе. Смена знания (скан) меняет режим →
новый ключ; старый (stub) вытесняется FIFO.

**In-memory кэш** (существующий `PlanetGenerator.cache`, maxCacheSize 1000, FIFO): малая и
большая (после генерации); ключ — §5.2.

**Диск-кэш большой** (С3 гейта 1): PNG 512 в `{PLANET_IMAGE_CACHE_DIR}/{sha256(planet_id|mode)}.png`.
Путь — env `PLANET_IMAGE_CACHE_DIR`, дефолт `data/planet_images` (локально; прецедент
`BALANCER_PRESETS_FILE` — env с дефолтом, DEPLOY.md §1). Каталог создаётся при старте
(MkdirAll); на проде задаётся в место с правом записи (`data/` может быть read-only, DEPLOY.md §1).
Лимит **1000 файлов** (≈ 100–300 МБ при 100–300 КБ/PNG), вытеснение LRU по mtime (при
превышении — удалить самые старые); отсутствие файла → генерация + запись; битая запись
(частичный файл) → перегенерация. Малая на диск не пишется (in-memory достаточно).

**Производительность (~1000 юзеров):** нагрузка от числа уникальных планет (кэш по seed), не
от юзеров (С3 гейта 1): малая — один расчёт на (планета, режим), большая — один расчёт на
(планета, режим) + диск. Нагрузочный тест `/api/planet-image` — кандидат (С3; STATUS §3 п.1).

### 10.2. Природа сущности (архитектурный фильтр)

1. **Природа** — производный артефакт/сервис (картинка генерится на лету), не событие и не

   режим в кэш-ключе, не персональные копии.
3. **Расширяемость** — типоразмеры/режимы в одном генераторе; второй тип «картинки»
   (например, карта поверхности для высадки) — отдельный генератор, не в эту схему.

### 12.2. Большая картинка: только при orbit {planet} vs всегда в карточке

**Моё решение:** только при `orbit {planet}` (буквально по создателю: «если мы на неё
прилетели») или админ (§6.2). Альтернатива: всегда в карточке планеты своей системы (честная)
— проще, но «вид с орбиты» без прилёта обесценивает прилёт. **Жду подтверждения.**

### 12.3. Протухшее знание снимает заглушку?

**Моё решение:** да — любая запись `player_planet_knowledge` (fresh или stale) → честная
(С3: «скан при прошлом визите» — знание есть, даже устаревшее). Альтернатива: только fresh
(≤ 7 дней, 77a §8.2) — строже, но игрок, сканировавший планету 10 дней назад, снова видит
заглушку. **Жду подтверждения.**

### 12.4. Старый публичный эндпоинт

**Моё решение:** заменяется (клиент — единственный потребитель, обновляется в фиче).
Альтернатива: оставить публичный для совместимости — не нужно (внешних потребителей нет).
