## 0. Резюме (одним абзацем)

Три доработки процедурной картинки планеты (стиль А, мягкий реализм) по решениям создателя 2026-09-20:
**(1) форма поверхности** — замена пятен-кругов `blobs()` на «поле высот + регионы» (контракт @gdesigner A): низкочастотный fbm даёт 2–5 крупных масс (континенты/океаны), внутри — регионы биомов по зонам высот, мелкие биомы — вкрапления; доли {form, share} сохраняются (бюджет ±30%, все биомы share ≥ 1% видимы), круги не читаются;
**(2) блик** — единый световой вектор L от seed (контракт B): терминатор/спекл/кольца от одного L, спекл приглушён в 3–5 раз и разнообразен по типам, кольца освещены (день/ночь, тень планеты); заглушка блика не даёт (контракт D, находка M4);
**(3) реальная атмосфера** (решение создателя «б», контракт C) — **отдельная ось режима картинки `full` + отдельный кэш-ключ** (находка K1): состав → цвет дымки, давление → лимб, τ_IR → свечение, cloudFraction → облака. Реальную атмосферу показывают только режимы физического присутствия (своя система/орбита) и админ; режим «знание» (`honest`) остаётся на производной атмосфере — знание атмосферу не содержит (`PlanetKnowledgeView` = `surface_*`/`settlements_count`), И1 для канала знания сохранён структурно. Кэш получает **версию генератора** (находка S1): in-memory ключ и диск-путь с `imageGenVersion`, старые файлы вычищаются при старте.

## 1. Цель и рамки

### 1.1. Цель

1. **Форма поверхности без читаемых кругов** (идея §2.1): доли биомов {form, share} определяют вид (честность к данным), форма — хаотичная («поле высот + регионы», контракт A).
2. **Естественный блик** (идея §2.2): единый световой вектор L от seed, спекл приглушён и разнообразен по типам, кольца освещены согласованно (S3), сильно отвлекающий блик убран.
3. **Реальная атмосфера** (решение создателя «б»): картинка режима `full` показывает реальную атмосферу (состав → цвет дымки, давление → лимб, τ_IR → свечение, cloudFraction → облака) — без утечки через общий кэш (K1: отдельная ось режима + отдельный ключ).
4. **Заглушка без блика и свечения** (контракт D, M4): мягкий терминатор от L(seed), спекл-блик и свечение отсутствуют.
5. **Версия генератора в кэше** (S1): визуальная правка доезжает до закэшированных планет.

### 1.2. Рамки (что НЕ делаем)

- **Иконки биомов** — не зависят от формы поверхности (находка M2): отдельный хвост @artist пачками, вне этой спеки.
- **Реальная фаза по орбите** (положение звезды/наблюдателя → терминатор) — v1 свет от seed (решено гейтом 2026-09-21, §12.1); кандидат ГД-сущности §10.3, в числа не входит.
- **Анимация** (вращение облаков, фазы) — вне скоупа; картинка статична.
- **Миграции БД** — нет: кэш — файлы, новая сущность БД не вводится (§10.2).
- **Бэкфилл старых миров** — запрещён (99.2.28); старые миры — фолбэк (§7).
- **Смена состояния биомов / формулы 99.2.20 / механика 99.2.28** — не меняются (картинка — read-only потребитель).
- **Мелкий баг админки** (biomeCatalog.js read-only) — снят @critic (M1: уже `disabled`), из скоупа убрано.

### 2.1. Форма поверхности

| Вариант | Как | Итог |
|---|---|---|
| **A. ## 3. Входы генератора и контракт API

### 3.1. Входы генератора (формальные)

**Честная картинка — теперь два режима с разным набором входов:**

**Режим `honest` (знание/скан о чужой планете)** — как прошлая спека §3.1 (только видимые клиенту):

| Вход | Источник | Примечание |
|---|---|---|
| `planet_id` (UUID) | запрос | seed = FNV-1a 64 от id |
| `biomes` [{form, share}] | `planets.data.biomes` | поверхность; старые миры без ключа → фолбэк §7 |
| `type` | планета (виден) | палитра, заслонение |
| `is_gas_giant` | планета (виден) | заслонение = 1.0 |
| `temperature` (K) | планета (виден) | заслонение, палитра |
| `water_percent` | планета (виден) | заслонение |
| `habitable`, `life` | планета (видны) | заслонение |
| `has_rings` | планета (виден) | кольца |
| `size` (small/big) | запрос | типоразмер |

**Режим `full` (присутствие/админ)** — добавляются атмосферные поля (контракт C):

| Вход | Источник | Примечание |
|---|---|---|
| `composition` map газ→% | `p.AtmosphereData["composition"]` | цвет дымки: Σ(тинт×%)/100; проценты (сумма 100); перед `classifyAtmosphere` — нормализация /100 (C2, §4.3) |
| `pressure_atm` | `p.AtmosphereData["pressure_atm"]` | лимб, дымка, облака |
| `tau_ir` | `p.AtmosphereData["tau_ir"]` | свечение |
| `scale_height_km` | `p.AtmosphereData["scale_height_km"]` | поправка лимба (SH/8)^0.5 |

Ключи JSON — из `atmosphereDataToJSON` (`planet_data_generate.go`): `composition`/`pressure_atm`/`tau_ir`/`scale_height_km`. `cloudFraction` в данных НЕ хранится — вычисляется внутри генератора существующими функциями того же пакета: `fc = cloudFraction(classifyAtmosphere(comp, P), P)` (`atmosphere.go`). Старые миры без `atmosphere_data` → фолбэк §7 (производная, как `honest`).

**Заглушка (`stub`):** только `planet_id` (seed) + `size`. Никаких данных планеты.

### 3.2. Контракт API

`GET /api/planet-image?planet_id=<UUID>&size=small|big` (или `radius`) — **не меняется**: JWT обязателен, ответ PNG, ошибки 401/404/500 (прошлая спека §3.2). Меняется только серверная логика режима (§3.3). Клиентский кэш `textures.js` — мелкая дельта §6.1.

### 3.3. Режимы картинки: ось `stub / honest / full` (K1)

**Ось режима — три значения, не два** (прошлая спека знала `honest`/`stub`):

| Режим | Что показывает | Атмосфера | Входы |
|---|---|---|---|
| `stub` | нейтральный силуэт (контракт D) | нет (ни реальной, ни производной) | seed + size |
| `honest` | честная поверхность (биомы) + производная атмосфера (§4.4 прошлой спеки) | производная (палитра по типу + cloudCover из видимых) | видимые параметры |
| `full` | честная поверхность + **реальная атмосфера** (контракт C) | реальная (состав/давление/τ_IR/cloudFraction) | видимые + `atmosphere_data` |

**Серверная логика режима** (`resolveMode`, порядок):
1. Роль `admin`/`skycomposer` → `full` (И7: видят всё).
2. `user.CurrentWorldID == planet.WorldID` → `full` (решение гейта 2026-09-21, §12.5-A): **вся своя система** показывает реальную атмосферу — присутствие в системе легитимизирует вид состава (инвариант 5 «присутствие даёт данные свежее любой инфраструктуры»).
3. `KnowledgeRepository.GetKnowledge(userID, planetID) != nil` → `honest` (знание атмосферу НЕ содержит — `PlanetKnowledgeView` = `surface_*`/`settlements_count`; производная атмосфера не раскрывает скрытое).
4. Иначе → `stub`.

**Таблица видимости:**

| Роль | Система | Знание | Режим | Атмосфера |
|---|---|---|---|---|
| player | своя (`current_world_id == world_id`) | — | **full** | реальная |
| player | чужая | есть (скан/отчёт) | **honest** | производная |
| player | чужая | нет | **stub** | нет |
| player | вне системы (межзвёздный полёт) | есть | **honest** | производная |
| player | вне системы | нет | **stub** | нет |
| admin / skycomposer | любая | — | **full** | реальная |

**Ответ на вопрос K1 (решён создателем 2026-09-21, §12.2/§12.5):** реальную атмосферу показывают только режимы физического присутствия — **вся своя система** (`full`, §12.5-A) и админ; знание/скан/отчёт — **упрощённая производная** атмосфера (`honest`); заглушка — ничего. Знание реальную атмосферу НЕ даёт — знание её не содержит (`PlanetKnowledgeView` = `surface_*`/`settlements_count`), а картинка `honest` строится из производной (скрытый вход отсутствует структурно). Это сохраняет рынок отчётов об атмосфере (77a §6.2: «если сканер даёт недра/атмосферу бесплатно, отчёты обесцениваются»).

### 3.4. Заслонение

- **`honest`:** как прошлая спека §3.4 — `cloudCover` из видимых параметров (не меняется).
- **`full`:** реальная облачность `fc = cloudFraction(classifyAtmosphere(comp, P), P)`; ступени те же (§3.4 прошлой спеки): `fc ≥ 0.7` полное заслонение, `0.35–0.7` частичное, `< 0.35` дымка. Калибровка: Земля (азотно-кислородная, P=1) → 0.30 → дымка (поверхность видна); Венера (парниковая) → 0.90 → полное; Марс (P < 0.1 → f_c = 0) → дымка; Юпитер (водородно-гелиевая) → 0.30 → полосы + дымка.
- **`stub`:** заслонения нет (силуэт).

## 4. Процедурный генератор

Слои (снизу вверх), стиль А «Орбитальная съёмка»:

1. **Поверхность из биомов** — «поле высот + регионы» (§4.1, контракт A); цвет по контракту «биом → цвет» (§4.2 прошлой спеки — без изменений). Старые миры/гиганты — фолбэк §7.
2. **Рельеф/текстура** — fbm поверх пятен + ridged для «гористых» категорий (без изменений, прошлая спека §4.1).
3. **Яркость по альбедо** — без изменений.
4. **Атмосферный слой** — `honest`: производная (§4.4 прошлой спеки); `full`: реальная (§4.3, контракт C).
5. **Заслонение** — §3.4.
6. **Постобработка** — тень/терминатор/спекл от **L(seed)** (§4.2, контракт B); `stub` — мягкий терминатор без спекла и свечения (контракт D).
7. **Кольца** — освещены от L (§4.2, S3); в `stub` колец нет.

### 4.1. Форма поверхности: «поле высот + регионы» (контракт A)

Замена `blobs()` (`planet_image_v2.go` §«share → пятна»). Псевдокод:

```
surfaceRegions(seed, biomes, canvasSize):
  # RNG размещения — детерминированный от seed
  rng = rand.New(rand.NewSource(seed ^ 0xA7A7))
  sorted = biomes по share убыванию

  # 1. Поле высот E(p): fbm 3 октавы, ~1.3 цикла на диаметр, сэмплинг на сфере
  #    (spherePoint), доменный варп noise.warp(amount=0.3) — сдвиг ≈15% размера
  #    фичи (≈6% диаметра), в пределах контракта «10–15% размера фичи»;
  #    береговая линия хаотичная (тест №3 «нет кругов» зелёный на этом
  #    значении; итерация 4 — значение зафиксировано по реализации).
  #    Даёт 2–5 крупных масс (континентов/океанов, 30–60% радиуса).
  # 2. Зоны высот (для РАЗМЕЩЕНИЯ центров): низ E < 0.35 | середина 0.35–0.65 |
  #    верх E > 0.65; полюса |z| > 0.6 (z — компонента точки сферы).
  # 3. Категория → зона размещения: вода → низ; крио → верх + полюса;
  #    вулканизм → верх; биосфера/литосфера/экзотика → середина.
  #    Зона — МЯГКИЙ БАЙАС размещения (итерация 4, принято @reviewer): точка
  #    в зоне принимается всегда, вне зоны — с вероятностью 0.35 (регионы не
  #    кластеризуются в узких зонах); ≤ 32 попыток, затем любая точка диска
  #    («перелив», контракт A). Площадь биома зоной НЕ ограничена (решение C1,
  #    вариант «б»: бюджет важнее зоны — иначе вода-доминантная планета
  #    «заперта» в низкой зоне, заданной порогами E, а не долей).
  # 4. Регионы биома i:
  #    n_i = clamp(round(share_i/5), 1, 6)          # share ≥ 5%: 1–6 регионов
  #    share < 5%: n_i = 4 + rng.Intn(3)            # 4–6 вкраплений
  #    r_i = R · sqrt(share_i/100 / n_i) · (0.9 + 0.2·rng)   # R — радиус диска
  #    центр c_i — случайная точка сферы в зоне размещения (крио: |z| > 0.5)
  # 5. Растеризация пикселя (dx, dy):
  #    p = spherePoint(dx, dy, R, 1.3)
  #    первый регион в порядке убывания share, где
  #    dist3D(p, c_i) < r_i·(1 + 0.3·n)   # n = fbm — мягкие границы 2–3 px @512
  #    → биом региона. Зона пикселя НЕ ограничивает назначение: бюджет
  #    безусловный, зона влияет только на то, ГДЕ лежат регионы (вода — в
  #    низинах, крио — у полюсов), а не СКОЛЬКО их площади.
  #    остаток (зазоры между регионами) → БЛИЖАЙШИЙ регион (по 3D-расстоянию
  #    до центра): зазоры распределяются пропорционально долям (клетка
  #    Вороного ∝ r² ∝ share) — бюджет безусловный. «Доминирующий биом»
  #    отклонён (итерация 4): доминант получал бы share + остаток (~20–40%),
  #    бюджет ±30% не выполнялся ни на одном из 8 проверенных seed.
```

**Честность долей (S2, C1, ловушка PITFALLS «Дизайн и числа»):** площадь пикселей биома i на слое поверхности (до атмосферы/постобработки) `count_i` — **безусловный бюджет, зоны его не ограничивают** (зона — только байас размещения, §4.1 шаг 3/5):
- `share_i ≥ 5%`: `count_i / diskPixels ∈ [share_i×0.7, share_i×1.3]` (бюджет ±30%, С1/С4 — «вид, не отчёт»);
- `share_i 1–5%`: `count_i / diskPixels ≥ share_i×0.7` (нижняя граница — видимость), верх — перелив вкраплений (мелкий биом не может быть меньше видимого минимума).

Формула n_i/r_i даёт площадь ≈ share_i·(0.81–1.21) до наложения регионов; растеризация в порядке share (крупные первыми) даёт крупным биомам выигрыш пересечений, мелким — потери; **зазоры (остаток) заполняются ближайшим регионом** — распределяются пропорционально долям (клетка Вороного ∝ r² ∝ share), доминант не получает share + остаток (иначе бюджет ±30% не выполняется — проверено на 8 seed, итерация 4). Бюджет ±30% для типичных составов — контракт, n_i/r_i — отправная точка (разработчик вправе подстроить под тест №2, не меняя бюджет).

**Все биомы share ≥ 1% видимы:** n_i ≥ 4 вкрапления для мелких, ≥ 1 регион для крупных — пиксели цвета каждого биома присутствуют (тест №2).

**Детерминизм:** все RNG от seed; одинаковый вход → одинаковое разбиение (кэш-ключ корректен).

### 4.2. Свет: единый L(seed), спекл по типам, кольца (контракт B)

**Световой вектор** (замена фиксированного `(-0.5, -0.4, 0.2)` в `applyPostProcessing`):

```
lightVector(seed):
  rng = rand.New(rand.NewSource(seed ^ 0x11CE))
  az = 2π · rng.Float64()
  el = (20° + 40°·rng.Float64()) в радианах        # 20–60° над плоскостью
  return (cos(el)·cos(az), cos(el)·sin(az), sin(el))
```

Терминатор/тень/спекл/кольца — от одного L (детерминизм, разнообразие по seed).

**Спекл (приглушён в 3–5 раз, было 0.8 → ≤ 0.25), цвет — не чистый белый, естественные светлые тона по типам:**

| Тип (`postVisualType`) | pow | сила (rng в диапазоне) | цвет |
|---|---|---|---|
| gas (гигант) | 8 | 0.10–0.18 | цвет дымки гиганта |
| ice (лёд) | 30–40 | 0.15–0.25 | `#f0f8ff` (голубоватый) |
| earth (вода) | 20 | 0.12–0.20 | `#fff8e0` (тёплый) |
| rocky (пустыня/камень) | 12 | 0.05–0.10 | `#f8f0e0` (песчаный) |
| lava | 16 | 0.08–0.15 | `#ffb060` (оранжевый) |

Формула: `specIntensity = pow(max(0, 2·diffuse·normDz − nz), pow_i) · strength_i · 2`, кламп `specIntensity ≤ 0.25`.

**Контракт постобработки (M3, разделение честная/заглушка):** существующий `applyPostProcessing(img, size, visualType, hasAtmosphere, rng)` (фиксированный свет `(-0.5,-0.4,0.2)`, без подавления спекла) заменяется на:

```
applyPostProcessing(img, size, fx PostFX, rng)
  PostFX {
    L          // световой вектор от seed (lightVector)
    shadowStrength
    specular   *Specular   // nil = спекла нет (заглушка); {pow, strength, color}
    atmGlint   *Glint      // nil = ореола нет; {glowStrength, haze} — только full
  }
```

- `honest`/`full`: `L` от seed; `shadowStrength` по типу (ice 0.4, остальные 0.6 — как сейчас); `specular` по таблице выше; `atmGlint` — только `full` (P ≥ 0.1), `honest` — nil.
- `stub`: `L` от seed; `shadowStrength` 0.4; `specular` = nil; `atmGlint` = nil (контракт D).
- Параметр `hasAtmosphere` (атмосферный «ободок» старой постобработки) убирается — атмосферный слой генератора заменяет его (прошлая спека §4.1 п.6; сейчас в `honest` всегда вызывается с `false`).

**Атмосферная составляющая (только `full`):** `atmGlint = glowStrength · (0.5 + 0.5·diffuse) · edgeFactor`, кламп ≤ 0.2, цвет = цвет дымки (ореол на дневном лимбе). Поправка по давлению: `P < 0.1` (тонкая атмосфера) → спекл отсутствует (сила 0); `P ≥ 1` (плотная) → широкий ореол цветом дымки (pow 4–6, сила ≤ 0.2) вместо точечного спекла. В `honest` (нет P) — таблица по типу.

**Кольца (S3, `drawRings`):** геометрия/базовый цвет — как сейчас (tilt/rotation/alpha от rng); добавляется освещение от L:
- яркость пикселя кольца: `dayFactor = 0.5 + 0.5·dot(normalize(L_r), normalize(d_r))`, где L_r — проекция L на плоскость кольца, d_r — направление пикселя от центра в плоскости кольца; `brightness = lerp(0.35–0.5, 0.8–1.0, dayFactor)` (ночь 0.35–0.5, день 0.8–1.0);
- тень планеты: пиксели кольца в цилиндре тени (проекция диска планеты на плоскость кольца вдоль L) → `brightness × 0.25–0.35`;
- лёгкий тинт дымкой 10–20% (в `full` — реальный haze, в `honest` — палитра по типу).

### 4.3. Реальная атмосфера (контракт C, режим `full`)

**Разделение зафиксировано (решение гейта 2026-09-21, §12.2):** реальная атмосфера — только режим `full` (присутствие/админ); режим `honest` (знание) реальную атмосферу НЕ использует — производная (§4.5); `stub` — ничего. Двух трактовок нет.

```
realAtmosphere(compPct, P, tau, SH) → (haze, hazeAlpha, limbPx, limbAlpha, glowStrength, glowColor, fc):
  SH = SH > 0 ? SH : 8                          # фолбэк
  # Единицы (C2): compPct — проценты (сумма 100, compositionToPct).
  # Цвет дымки работает с процентами: Σ(тинт[газ]·compPct[газ])/100.
  # classifyAtmosphere/cloudFraction ожидают ДОЛИ 0–1 (внутри pct := comp[k]*100):
  compFrac = compPct / 100                      # нормализация перед вызовом
  # Цвет дымки: Σ(тинт[газ]×share[газ])/100, затем осветление 35% к белому
  hazeRGB = Σ(тинт[газ] · compPct[газ]) / 100   # неизвестный газ → #cccccc
  haze = lerp(hazeRGB, белый, 0.35)
  hazeAlpha = clamp(0.05 + 0.20·log10(1+P), 0.03, 0.45)
  # Лимб (канвас 512; на 256 — масштаб ×size/512)
  limbPx = clamp(1 + 2.5·log10(1+P), 1, 12) · (SH/8)^0.5
  limbAlpha = clamp(0.12 + 0.22·log10(1+P), 0.08, 0.65)
  # Свечение
  glowStrength = clamp(tau/4, 0, 1)
  glowWidth = limbPx · (1 + glowStrength)
  glowAlpha = 0.25 · glowStrength               # цвет = haze (было жёстко #ffc878 у вулканических)
  # Облака
  fc = cloudFraction(classifyAtmosphere(compFrac, P), P)   # существующая функция atmosphere.go
  # ступени заслонения §3.4; цвет облаков = haze осветлённый 30%
```

**Детерминизм суммирования (M4):** `Σ(тинт·comp)` выполняется по **фиксированному упорядоченному списку газов** (порядок таблицы тинтов ниже); неизвестные газы — в конце по сортированному списку ключей. Итерация `map` в Go рандомизирована, float-сложение неассоциативно — суммирование по map дало бы недетерминированный PNG (тест №1).

**Тинты газов (контракт C):** H₂ `#c8ccd8`, He `#d8dce4`, N₂ `#b8c8dc`, O₂ `#a8c0e8`, CO₂ `#e0c898`, CH₄ `#a8ccd8`, H₂O `#c0d8e8`, SO₂ `#e8d0a8`, NH₃ `#d0c0e0`, H₂S `#e0d8b0`, N₂O `#b8d0e0`, Ar `#d8d8d8`, прочие `#cccccc`.

**Калибровка (тест №7):**

| Планета | comp / P / τ / SH | haze | limbPx | limbAlpha | glow | fc |
|---|---|---|---|---|---|---|
| Земля | N₂ 78, O₂ 21 / 1 / 0.9 / 8 | ≈ `#cfdaea` | ~1.75 px | ~0.19 | 0.225 | 0.30 |
| Венера | CO₂ 96 / 92 / 100 / 15.9 | ≈ `#e0d2b8` | ~8 px | ~0.55* | 1.0 | 0.90 |
| Марс | CO₂ 95 / 0.006 / 0.05 / 11 | желтизна α~0.05 | 1 px | 0.12 | ~0 | 0 |
| Юпитер | H₂ 90, He 10 / 1 / 0.5 / 27 | ≈ `#d7dae2` | ~2.3 px | ~0.19 | 0.125 | 0.30 |

* Контракт называет Венеру 0.65; формула при P=92 даёт ~0.55 (коэффициент 0.22) — расхождение ~0.1, визуально незначимо; тест калибрует по формуле (0.55±0.03). Формула — исполняемое правило, таблица — ориентир.

**Гиганты (`full`):** пятна не добавляем, «поверхность» = полосы (`generateGas`), тонированные дымкой (haze); лимб/свечение по P/τ — как у всех. `fc` гиганта (0.30) на полосы не накладывается (полосы — уже «поверхность»).

### 5.1. Типоразмеры

### 5.2. Кэш: версия генератора + ось режима (K1, S1)

**Кэш-ключ:**

```
imageGenVersion = "v3"        // константа; инкремент при ЛЮБОЙ визуальной правке
                              // генератора (форма/свет/атмосфера/заглушка) — S1
key = hash64(planet_id) + "|" + mode + "|" + size + "|" + imageGenVersion
mode ∈ {stub, honest, full}; size ∈ {small, big}
```

- Роль/знание/позиция в ключ не входят — они определяют режим, режим уже в ключе (как было).
- **Версия в ключе (S1):** визуальная правка генератора → инкремент константы → старые in-memory записи не хитятся (FIFO вытеснит), старые PNG на диске не читаются.
- Смена знания (скан) меняет режим `stub → honest` → новый ключ; прилёт в систему `honest → full` → новый ключ.

**Диск-кэш большой:** `{PLANET_IMAGE_CACHE_DIR}/{imageGenVersion}_{sha256(planet_id|mode)}.png` (префикс версии — явная сегрегация поколений). **Стартовый клин (S1, M1):** `InitPlanetImageCacheDir` при старте удаляет файлы, чьё имя **не начинается с текущего префикса `{imageGenVersion}_`** — включая **легаси-файлы без префикса** (старый путь писал `{sha256}.png`), иначе легаси остаются в LRU-лимите 1000 и вытесняют новые; лимит 1000 файлов LRU по mtime — без изменений; битый файл → перегенерация — без изменений.

**Производительность:** без изменений (нагрузка от числа уникальных планет; вариантов на планету теперь до 3 режимов × 2 размера = 6, но реально: своя система = full, чужая = stub|honest — типично 2–3 варианта, как и было).

### 8.3. Критерии приёмки (создатель)

1. Просмотр картинок: форма поверхности хаотичная (круги не читаются), доли биомов читаются, стиль А; планеты различаются по блику (положение/интенсивность), блик не отвлекает.
2. Реальная атмосфера: Земля/Венера/Марс/Юпитер по контракту C (дымка/лимб/свечение/облака); заглушка нейтральна, без блика.
3. Кольца освещены согласованно с бликом (день/ночь, тень планеты на кольце).
4. Режимы: своя система — реальная атмосфера; знание — производная; чужая без знания — заглушка; админ — всё. Старые миры/гиганты не падают.

## 9. Инварианты

- **Детерминизм:** одинаковый (планета, режим, размер, версия) → одинаковый PNG (кэш-ключ корректен; версия в ключе — S1).
- **Не-регрессия:** старые миры и газовые гиганты не падают (§7); формулы 99.2.20 и механика 99.2.28 не меняются (картинка — read-only потребитель); контракт «биом → цвет» и производная атмосфера `honest` без изменений.
- **77a И7:** админ и skycomposer видят всё → `full` всегда (§3.3).
- **77a И8:** знание с датой; картинка не обновляет знание; заглушка снимается по НАЛИЧИЮ записи знания (не по свежести) — без изменений.
- **77a И1 — снятие для атмосферы в `full` (правило создателя 2026-09-20):** картинка `full` (присутствие/админ) раскрывает состав атмосферы с орбиты — осознанный обход 77a §6.2, дельта в 77a обязательна (§13). Режим `honest` (знание) И1 сохраняет структурно: входы — только видимые параметры, атмосферные числа не входят (§3.1); заглушка не раскрывает тип/поверхность/атмосферу.
- **Честность долей (S2, C1):** каждый биом share ≥ 1% видим; бюджет площади **безусловный** — зоны высот не ограничивают площадь биома (зона — мягкий байас размещения, §4.1), **остаток (зазоры) → ближайший регион** (не доминирующий биом — иначе доминант получает share + остаток и бюджет ломается, итерация 4), `count/diskPixels ∈ [share×0.7, share×1.3]` для share ≥ 5%, нижняя граница для 1–5% (§4.1) — ловушка PITFALLS «Дизайн и числа» закрыта явным бюджетом и тестом №2.
- **Кэш-версия (S1):** любая визуальная правка генератора → инкремент `imageGenVersion`; старые файлы вычищаются при старте.

### 10.2. Природа сущности (архитектурный фильтр)

1. **Природа** — производный артефакт/сервис (картинка генерится на лету), не событие и не лог: картинка не «происходит» и не «состояние» — это кэшируемый результат функции. Новая сущность **не вводится**: меняется существующий `planet_image` (генератор + хендлер + кэш); входы (биомы, атмосфера, знание) — существующие сущности.
2. **Владелец** — нет (общий кэш на всех); режим персональный (знание/присутствие), но картинка общая — режим в кэш-ключе, не персональные копии.
3. **Расширяемость** — три режима (stub/honest/full) в одном генераторе; версия генератора — константа, не сущность; второй тип «картинки» (карта поверхности для высадки) — отдельный генератор, не в эту схему.
