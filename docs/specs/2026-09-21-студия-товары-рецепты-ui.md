## 2. Ключевые решения раскладки (рекомендация)

1. **Новая группа в шапке** `#segGoodsScope` (класс `.tool-seg`) в ряду
   `head-tools` (строка 182–193), **первой** — левее `#segGraph`. Содержимое:
   метка «Фабрика» + `#goodsFactorySel`; метка «Семейство» + `#goodsFamilySel`.
   *Почему:* оба селекта задают «что вообще показывает ветка» (граф + видимость
   товаров) — это скоп ветки, а не подрежим графа. Ряд `head-tools` уже
   `flex-wrap: wrap` (CSS 9) и `#headbar` имеет `margin-right:320px` (CSS 8) —
   переносится без обрезки. Видимость — вместе с `#segGraph` (только «Товары»),
   через `applyBranchUI` (2704–2723).
2. **`#goodsFactorySel`** — главный скоп ветки: «Все товары (обзор)» (дефолт) +
   конкретные фабрики (`§3`). Ширина `max-width:280px`.
3. **`#goodsFamilySel`** — фильтр семейства рас (`§4`). Ширина `max-width:170px`.
4. **Граф фабрики — всегда целиком** (лес замыкания вниз): в режиме фабрики
   фокус-режим и галка «всё дерево» не применяются (`§5`).
5. **Попап:** «Состав рецепта» (переименование), «Сложность» вместо
   тир-оверрайда, новая секция «Доступен фабрикам:» (`§6`).
6. **Привязка** — перетаскиванием карточки на канвас + секция привязок в попапе
   (`§7`). Это **новое** поведение канваса (см. §11 D1).
7. **Критерий создателя — время конфигурирования** (решение гейта UI, идея §8).
   Элемент интерфейса хорош, если **экономит клики на массовом вводе контента**:
   перетаскивание вместо «попап → селект → кнопка», копирование набора вместо
   ручного набора рецептов, обновление без перезагрузки, сохранение скролла
   списка. Обратная сторона — тишина на успехе там, где подтверждение мешает
   темпу (§7.3.4). По этому критерию проверяются все правки этой спеки.

**Альтернатива (одной строкой, не рекомендую).** `#goodsFamilySel` — не в шапке,
а в шапке справочника рядом с `#spravCat` (224). Дешевле по разметке, но
разрывает пару «фабрика+семейство» и вводит в заблуждение: фильтр семейства
меняет **и граф**, а не только список справочника. Цена: два места управления
скопом ветки.

**Включено в объём** (решение менеджера, идея §9): два дешёвых по критерию п.7
улучшения, ранее предлагавшиеся сверх объёма, теперь часть ТЗ — счётчик «в наборе
{N}» в `#modeBadge` (§5.2) и пункт «привязать к „{фабрика}“» в контекстном меню
справочника (§7.6); критерии — §9 п.17–18.

## 3. Селектор фабрики `#goodsFactorySel`

**Было:** нет. **Станет:** `<select id="goodsFactorySel">` в `#segGoodsScope`.

**Список (источник — `state.producer_types`):**

- Первый пункт всегда: `<option value="">Все товары (обзор)</option>` (дефолт,
  решение §11.8 спеки; вне `optgroup`).
- Далее — **конкретные фабрики**: `parent_id != null` **и** `kind === "goods"`
  **и** `category_id != null`, чья категория — товарная (найти категорию в
  `state.categories` по `category_id`, оставить только `kind === "good"`).
  Фабрики с **ресурсной** категорией в список не попадают (рецепт невозможен,
  §4.1 спеки) — не пометкой, а фильтром.
- Группировка: `<optgroup label="{parent_name}">` (родительский тип). Порядок
  групп — по порядку появления родителя в `state.producer_types`; внутри группы —
  по `category_name`, затем по ступени: универсальная → семейство → раса.
- Подпись пункта: **`{category_name} · {levelLabel}`**, где `levelLabel`:
  - `race` задан → `Раса: {raceName(race)} ({familyLabelById(race_family)})`;
  - `race_family` задан, `race` нет → `familyLabelById(race_family)` (напр.
    «F4 Крио-аммиачные»);
  - оба пусты → `универсальная`.
  - `hidden === true` → суффикс ` · скрыта` (скрытые фабрики держат рецепты —
    их надо видеть в инструменте).
- Нет ни одной конкретной фабрики → `#goodsFactorySel` `disabled` с
  `title="Конкретных фабрик нет — создайте в разделе «Производители»"`.

**Поведение:** смена значения — только клиент (сервер не запрашивается),
мгновенно пересчёт графа/маркеров/«+ товар»; сразу в localStorage
`gs_goodsFactory` (`§8`). При пересборке списка (авто-refresh) значение
сохраняется (как `#catFilter`, 2493).

## 4. Фильтр по семейству `#goodsFamilySel`

**Было:** нет. **Станет:** `<select id="goodsFamilySel">` в `#segGoodsScope`.

- Пункты: «Все семейства» (`value=""`, дефолт) + по `racesData.families` в
  порядке сервера (`F0`…`F9`, `robotic`) подписями `familyLabelById(f.id)` —
  ровно «F0 Люди» … «F10 Роботы» (1840).
- До загрузки `racesData` — только «Все семейства».
- Смена — клиент-only, localStorage `gs_goodsFamily`.

**Правило (канон «самая конкретная побеждает», спека рецептов §4.3; правило —
источник @designer, здесь только видимый эффект).** При уровне = семейство `Fk`:

1. Для каждой категории берём **применяемые записи-фабрики** уровня `Fk`:
   `race_family IS NULL` **или** (`race_family === Fk` **и** `race` пуст).
2. Нет применяемых записей → категория **не показывается** (ни в справочнике,
   ни в графе).
3. Самая конкретная применяемая запись-фабрика `hidden` **или** самый конкретный
   применяемый слот (`state.producer_slots`) `hidden` → категория **исключена**
   (обе оси, как канон §5.3–§5.4 спеки лестницы).
4. Иначе уровень получает **все** применяемые записи самой конкретной ступени:
   есть семейные → только они; иначе все универсальные. Универсальная «в
   довесок» к своей **не** добавляется.
5. Показываются товары, чей рецепт привязан к полученной фабрике:
   `bound_factories` товара ∩ полученные фабрики ≠ ∅ (или через
   `state.producer_recipes`).

**Где действует:** AND c селектором фабрики и с существующими фильтрами
(категория/поиск/пилюли тиров/галки используемости). Влияет и на список
справочника, и на граф (в §4.3 спеки — «ни товары, ни граф»).

**Клиент-эффекты:** выбранное семейство не изменилось серверным опросом; при
изменении — `renderAll`; если ранее выбранный товар пропал из видимых —
`selected = null`; если пропал из справочника — он исчезает (выбор сброшен);
попап-детали, если открыт, остаётся (деталь — валидный объект).

## 5. Граф выбранной фабрики

### 5.1. Режим «Все товары (обзор)» — как сейчас

`#goodsFactorySel = ""`: всё как сегодня (`visibleGoods` 457–466,
`fullTreeMode`/`focusSubset`). Единственная добавка — маркер «не привязан» в
справочнике (`§6.4`), чтобы находить «ничей» товар (дельта спеки фабрик §4.3).

### 5.2. Режим фабрики

- **`factoryMode()`** = ветка «Товары» **и** выбрана конкретная фабрика.
- **Граф = замыкание вниз** от выходов её рецептов: корни — товары из
  `state.producer_recipes` с `producer_type_id === выбранной`; далее рекурсивно
  компоненты `recipe` (ресурсы — листья). Полное замыкание (решение §11.7).
- **Граф всегда целиком** (лес; может быть **несвязным** — несколько деревьев,
  §4.2 спеки): в `factoryMode` `fullTreeMode()` возвращает `true`
  (единая правка 438 → все вызовы раскладки/хитТеста/центрирования 606–607,
  743, 848–856, 891, 2632 автоматически берут полное множество). Галка
  «всё дерево» (`#fullTree`) в режиме фабрики **скрыта** (`display:none` у её
  `label` через `applyModeUI` 2643–2651); фокус-оверлей
  (`#focusEmptyOverlay`) не показывается (`factoryMode` — «всё дерево»).
- `#modeBadge` (156) в режиме фабрики: `фабрика: {имя} · всё дерево · в наборе
  {N}`, где `N` — число привязок выбранной фабрики (`state.producer_recipes` с
  `producer_type_id === выбранной`). Счётчик — видимый прогресс набора, не
  заглядывая в справочник (критерий §2 п.7); пересчитывается вместе с
  `applyModeUI` (2650). В обзоре (`#goodsFactorySel = ""`) — как сейчас
  («всё дерево» / «фокус: вокруг выбранного»).
- Фильтры `#catFilter`/`#search`/`#showResources`/`#reverseEdges`/`#btnTop`
  продолжают действовать на множество фабрики (узкое место — `visibleGoods()`
  становится `factoryMode`-зависимым). `computeLayout`/`hitTest`/`centerOn`/
  `centerTop` менять не нужно — они идут через `visibleGoods()`.

### 5.3. Маркер «производится другой фабрикой»

- На карточке компонента (не корня!) в режиме фабрики: если у компонента
  `bound_factories` **непуст и не содержит** выбранную фабрику → бейдж
  **«др. фабрика»** на канвасе (второй бейдж рядом с «тир N», 664–674), фон
  `#357`, тултип `showTip` (717–729) второй строкой — «производится другой
  фабрикой».
- Если `bound_factories` содержит выбранную фабрику → бейджа нет (свой набор).
- Если `bound_factories` пуст («ничей») → бейджа на канвасе нет: решением гейта
  UI (2026-09-21, п.1 §12) отдельного маркера «ничей» на канвасе **не вводим**;
  носитель — бейдж «не привязан» в справочнике (§6.5).

### 5.4. Пустые компоненты и несвязность

- Пустые компоненты — существующие пунктирные плейсхолдеры (503–513,
  679–699) без изменений, рисуются для товаров множества фабрики.

### 7.3. Перетаскивание карточки из справочника на канвас (привязка)

> ⚠️ В коде **сейчас** канвас не принимает drop (1019–1021: «drag&drop на канвасе
> не используется»). Это **новая** функциональность (D1), включена в объём
> решением гейта UI 2026-09-21 (идея §8: «мне бы очень хотелось просто
> драгндропать… сокращение времени to be done критично»).

**Источник — только карточка справочника** `.card[draggable="true"]` (1455–1460,
`dragStart` 2483 → `dataTransfer "text/plain" = good id`). Других источников
перетаскивания нет: узлы дерева построек (ветка «Производители») не `draggable`.

#### 7.3.1. Активация: когда канвас реагирует

| Ветка / состояние | `dragover` | `drop` |
|---|---|---|
| «Товары» + `factoryMode()` (выбрана конкретная фабрика) | `ev.preventDefault()` + `dropEffect="copy"` + `#canvasWrap.dnd-over` | **привязка** (§7.3.2) |
| «Товары» + «Все товары (обзор)» (`#goodsFactorySel = ""`) | `ev.preventDefault()` (чтобы drop сработал), **без** `dnd-over`, `dropEffect="none"` | тост-подсказка «Выберите фабрику в шапке — перетаскивание привяжет рецепт к ней»; запроса нет |
| «Производители» (дерево построек) | **нет** `preventDefault` — drop инертен (без подсветки, без тоста, без запроса) | — |
| «Предметы» (канвас скрыт, `applyBranchUI` 2710) | — | — |
| `loading` / `#right.disabled` (2627) | справочник `pointer-events:none` — перетащить нечего | — |

`factoryMode()` — из §5.2. В режиме фабрики канвас может быть накрыт оверлеями
(`#factoryEmptyOverlay`, §7.1 п.2; `#noResultsOverlay`) — это **дети**
`#canvasWrap` (264–274), события `dragover`/`drop` всплывают к обработчику
`#canvasWrap`, поэтому drop работает и поверх оверлея; подсказка
`#factoryEmptyOverlay` прямо предлагает перетащить товар. Попапы
(`#detailPopup`/`#detailOverlay`, `#catPopup`) — **не** дети `#canvasWrap` (в
`#main`): при открытом попапе канвас накрыт подложкой и drop-привязка недоступна;
drop в **слоты** попапа продолжает работать штатно (`slotDragOver`/`dropOnSlot`,
1078/1086/1298) — цели не конфликтуют.

#### 7.3.2. Что происходит при drop (порядок пречеков)

```
goodId = dataTransfer.getData("text/plain")   // как dragStart 2483
if (!factoryMode())         → тост «Выберите фабрику в шапке …» (§7.3.1); стоп
g = state.goods.find(id)                      // товара нет (удалён) → тост; стоп
if (g.kind === "resource")  → тост «ресурс нельзя привязать как рецепт»; стоп
if (g.category_id !== фабрика.category_id)
    → тост «товар другой категории — фабрика производит только «{category_name}»»; стоп
if (bindingInFlight.has(g.recipe_id) || уже в bound_factories фабрики)
    → тост «уже в наборе фабрики»; стоп
POST /studio/api/producers/{factory}/recipes {recipe_id: g.recipe_id}   // §5 спеки
    → ok:  fetchState() — без тоста (визуальная обратная связь, §7.3.4)
    → 4xx: api() (1154–1158) показывает серверное сообщение тостом (страховка)
```

- **Куда брошено — неважно** (привязка — свойство фабрики, а не слота): бросок
  на пустое место канваса, на карточку компонента, на карточку выхода, на ребро
  или на оверлей — **одно и то же действие**. Целиться не нужно: рецепт
  привязывается выбранной фабрике целиком. Состав рецепта drop **не меняет**.
- *Почему без исключений для карточек:* попасть по нужному узлу при
  конфигурировании десятков товаров — лишние промахи и клики, а эффект
  одинаковый (критерий «минимум кликов», §2 п.7).
- **Ресурсы:** `draggable="true"` у карточек ресурсов **сохраняем** — тот же drag
  используется для перетаскивания ресурса **в слот** состава рецепта (ресурс —
  легальный компонент, §2.5 спеки рецептов). Поэтому ресурс не запрещаем
  атрибутом, а отсекаем пречеком по `kind` на канвасе (тост выше). Снять
  `draggable` у ресурсов глобально **нельзя** — сломается drag в слоты попапа.
- **Повтор** (товар уже привязан): тост «уже в наборе фабрики»; серверный 409 —
  страховка (гонка/вторая вкладка). Пречек идёт по `bound_factories` товара, а
  в окне между двумя быстрыми drop'ами — по `bindingInFlight` (Set `recipe_id`
  на время запроса), чтобы не отправить два POST.
- **Чужая категория:** 400 сервера в норме недостижим (пречек в UI, §7.5) —
  страховка тостом.

#### 7.3.3. Подсветка, курсор, служебные состояния `dragover`/`dragleave`/`drop`

- **Стиль подсветки** (новый класс, в тон `.slot.drop-target`, CSS 83):
  `#canvasWrap.dnd-over { border-color:#8cf; box-shadow: inset 0 0 0 2px #8cf }`.
  Рамка канваса 1px (`#canvasWrap`, CSS 36) — `box-shadow` раскладку не сдвигает.
- **Курсор** задаётся нативным `dropEffect`: активный режим — `"copy"`, обзор без
  фабрики — `"none"` (курсор «нельзя»). Отдельный CSS-курсор не нужен.
- **`dragover`** — на `#canvasWrap`: `ev.preventDefault()` (иначе браузер не
  разрешит drop), выставляется `dropEffect`, добавляется `.dnd-over`.
- **`dragenter`/`dragleave` — счётчик глубины.** `#canvasWrap` содержит детей
  (`canvas#graph`, `#tip`, оверлеи, `#modeBadge`, `#panelToggle`): при движении
  между ними `dragleave`/`dragenter` сыплются постоянно. Правило: `dragenter` →
  `dndDepth++`; `dragleave` → `dndDepth--`; при `dndDepth === 0` снять
  `.dnd-over`. Так подсветка не мигает и корректно гаснет при уходе курсора за
  пределы окна (`relatedTarget` там `null` — отдельная проверка не нужна).
- **`drop`** — снимает `.dnd-over`, обнуляет счётчик, затем выполняет §7.3.2.
- **Отмена без drop** (Esc во время переноса, drop вне цели, drop в другую
  программу): `dragend` приходит на исходную карточку — **делегированный**
  `document.addEventListener("dragend", resetDnd)` снимает подсветку/счётчик
  (карточки справочника перерисовываются, поэтому обработчик не на самой
  карточке). Запроса при отмене нет.
- **Конфликты с навигацией канваса** (требование задачи):
  - **панорамирование**: pan стартует только по `mousedown` **на канвасе** (753,
    781) — из карточки справочника он не возникает; дополнительно на время drag
    вешаем флаг `dndActive`, и в начале `canvas.mousedown` (753) и
    `canvas.wheel` (814) делаем `if (dndActive) return;` — так **зум колесом во
    время перетаскивания не сработает**;
  - `mousemove` (783) при `dndActive` не трогаем: он активен только при
    `panning`, который в drag не выставляется; тултип карточки канваса в drag не
    мешает (браузер подавляет hover при переносе).

#### 7.3.4. Экономия времени конфигурирования (критерий создателя, §2 п.7)

- **Несколько товаров подряд, без переоткрытия попапа.** После drop попап
  **не** открывается, `selected` **не** меняется, канвас **не** центрируется,
  `zoom/pan` сохраняются — можно сразу тащить следующий товар. N привязок = N
  перетаскиваний (вместо N циклов «открыть попап → найти фабрику в селекте →
  „+ привязать“ → закрыть»).
- **Обновление без перезагрузки.** После успешного POST — `fetchState()` →
  `renderAll()`: новый рецепт появляется в графе фабрики, карточка справочника
  получает бейдж **«в наборе»** (§6.5), маркеры/счётчики пересчитываются.
  Авто-refresh (399–409) догонит изменения из другой вкладки.
- **Скролл справочника не сбрасывается** (`renderSprav` уже сохраняет
  `scrollTop`, 1461) — работа продолжается с того же места списка.
- **Успех — без тоста.** `showReport` (425–431) — механизм ошибок/отчётов
  (`#report`, 8 с); успех подтверждается визуально (узел в графе + бейдж «в
  наборе»), чтобы при массовом вводе тост не заслонял экран и не сбивал темп.
  Ошибки — как обычно, тостом (§7.5).
- **Тупик без drag-цели:** при `#right.disabled` (загрузка) и вне ветки «Товары»
  карточки не тянутся — путь «попап → секция „Доступен фабрикам“» (§6.4) остаётся
  доступной альтернативой (в т.ч. для клавиатуры — HTML5 drag недоступен).

### 7.5. Конфликты 400/409 — что видит пользователь

- **Тост** — штатный механизм `api()` (1154–1158): любое серверное сообщение
  (`{error}`) уже показывается через `showReport`. Новых модалок не вводим.
- **Предотвращение вместо тоста** там, где причина детерминирована: селект
  привязки — только своя категория (§6.4); `#spravNewCat` заблокирован
  категорией фабрики (§7.2); drag — пречек категории/повтора (§7.3);
  смена категории товара с привязками — селект заблокирован (§6.1).
- **409 смены категории фабрики** при привязанных рецептах — происходит в ветке

### 7.6. Контекстное меню карточки справочника — «привязать к „{фабрика}“»

> Решение менеджера (идея §9): включено в объём — путь привязки без
> перетаскивания для тех, кто предпочитает клики; новых роутов/механик нет.

- **Где:** `showSpravCtxMenu` (934) — сейчас ровно один пункт «удалить» (938–940).
  При `factoryMode()` (§5.2) в меню добавляется **ровно один** пункт
  `привязать к „{имя фабрики}“` (`{имя}` — подпись выбранной фабрики из
  `#goodsFactorySel`, §3), **первым**, существующий «удалить» остаётся ниже и не
  меняется.
- **Пречеки — те же, что у drop (§7.3.2, единый источник правды):**

  | Состояние карточки | Пункт меню |
  |---|---|
  | нет выбранной фабрики (обзор) | **не показывается** |
  | `g.kind === "resource"` | показывается; клик → тот же тост, что §7.3.2: «ресурс нельзя привязать как рецепт» |
  | `g.category_id !== фабрика.category_id` | показывается; клик → пречек-тост «товар другой категории — фабрика производит только „{category_name}“» (та же формулировка, что серверный 400) |
  | товар уже в `bound_factories` фабрики | **не показывается** (повтор не предлагаем) |
  | иначе (товар фабрики, не привязан) | активен |

- **Клик** → тот же путь, что drop §7.3.2:
  `POST /studio/api/producers/{factory}/recipes {recipe_id: g.recipe_id}`
  (`g.recipe_id` пуст → тост «рецепт не создан»); успех — `fetchState()` **без**
  тоста (визуальная обратная связь: узел в графе + бейдж «в наборе», §6.5, и
  счётчик `N` в `#modeBadge`, §5.2); 4xx — тост `api()` (1154–1158). Защита от
  двойного клика — `bindingInFlight` (§7.3.2).
- **Инвариант меню:** расширяется **ровно одним** пунктом; скрытие/порядок
  «удалить» и прочие контекстные меню студии не трогаются (§10).
- Ресурсы/обзор и ветка «Предметы» — меню выглядит как сейчас (один пункт
  «удалить»).

## 9. Критерии проверки (что увидит создатель)

1. В шапке «Товары» появились «Фабрика» и «Семейство»; в разделе
   «Производители»/«Предметы» их нет.
2. Выбор фабрики → граф показывает только её рецепты (замыкание вниз); возможны
   несколько отдельных деревьев.

   «производится другой фабрикой»); свой компонент — без бейджа.
4. Попап товара: секция «Состав рецепта», поле «сложность рецепта», секция
   «Доступен фабрикам:».

6. «− отвязать» убирает привязку; «+ привязать» (свой селект) привязывает;
   повторно — привязка не предлагается; чужой категории — не предлагается.

    фабрика в сохранённом ключе не ломает экран (сброс в обзор).

13. Тир-бейдж на графе и фильтр тиров работают как раньше (тир производный).
14. Перетаскивание без выбранной фабрики даёт тост-подсказку (без подсветки);

17. При выбранной фабрике `#modeBadge` показывает «фабрика: {имя} · всё дерево ·
    в наборе {N}»; после привязки/отвязки (drag, попап, меню) `N` меняется без
    перезагрузки; в обзоре бейдж — как раньше.
18. Контекстное меню карточки справочника при выбранной фабрике содержит пункт
    «привязать к „{имя}“» (и по-прежнему «удалить»); пункт привязывает тем же
    роутом/тостами, что drag; в обзоре, у ресурса и у уже привязанного товара —

## 13. Кнопка «скопировать набор рецептов» (ветка «Производители»)

**Основание:** решение гейта UI 2026-09-21 (идея §8) — митигация развилки
§11.11 спеки рецептов («расовая/семейная фабрика без рецептов обнуляет
категорию у уровня»); §4.3/§11.11 спеки. Серверный роут — канон §5 спеки
рецептов: `POST /studio/api/producers/{id}/recipes/copy-universal` (тело пустое;
ответ `200 {"added": N, "skipped": M}`; идемпотентно, `ON CONFLICT DO NOTHING`;
пустой источник — тоже 200 с нулями, не ошибка; **400** — цель не конкретная
фабрика / нет категории / категория не товарная; живёт в префиксном хендлере
`ProducerByID`, отдельной строки роута не требует). **D7 (§11) — устранён.**

**Смысл:** у **конкретной** фабрики `kind=goods` одной кнопкой набрать её набор
из набора **универсальных** конкретных фабрик той же категории (обычно «Фабрика
X» → «F0 Люди X»). Новой механики нет: копируются существующие привязки
`producer_recipes` существующим серверным роутом, дубликаты сервер пропускает.

### 13.1. Где живёт (два входа — оба дешёвые, делаем оба)

1. **Попап существующей фабрики** (`renderProdPopup` 1515; блок для
   `p.kind==="goods" && p.parent_id` — рядом со строкой категории 1533–1537).
2. **Диалог создания подтипа** (`openProdCreatePopup` 2203–2224 → `doProdCreate`
   2225–2237) — «при создании подтипа-фабрики предлагать кнопку» (§11.11 спеки).

*Почему оба:* вход (2) срабатывает в момент обнуления (создание расовой
фабрики) — это то, что названо в §11.11; вход (1) лечит уже существующую пустую
расовую/семейную фабрику (типовой случай после миграции/правок) и стоит одной
строки разметки. (2) без (1) оставлял бы «забыл на создании — правь вручную»;
(1) без (2) не митигировал бы обнуление в момент создания.

### 13.2. Вход 1 — попап фабрики

Разметка (внутри блока `kind=goods && parent_id`, после строки категории):

```
<div class="dmeta">набор рецептов: {N} ·
  <button class="gen" id="btnCopyRecipes" title="…">скопировать набор
  универсальной фабрики</button>
</div>
<div class="hint">источник: «{имена универсальных фабрик}» · будет добавлено
  {K} (уже есть {M})</div>
```

- `N` — число привязок фабрики; источник и `K`/`M` считаются **на клиенте** из
  `state.producer_recipes` + `state.producer_types` (нового эндпоинта не надо):
  `источники` = конкретные `kind=goods` фабрики той же `category_id` с
  `race_family IS NULL && race IS NULL`, **кроме самой фабрики**;
  `K = |рецепты источников \ рецепты фабрики|`, `M = |пересечение|`.
- Селект источника **не вводим**: универсальных фабрик категории обычно 1–2,
  копируем из всех сразу (спека рецептов §5: «копирует привязки из универсальных
  конкретных фабрик той же категории»).

**Состояния кнопки:**

| Условие | Кнопка | Текст/подсказка |
|---|---|---|
| универсальных источников (кроме себя) нет | `disabled` | `title="нет универсальной фабрики этой категории — копировать не из чего"` |
| источники есть, но `K = 0` (у них нет рецептов **или** всё уже в наборе) | `disabled` | `title="копировать нечего: {у источников нет рецептов \| все рецепты уже в наборе}"` |
| `K > 0` | активна | клик → подтверждение (§13.3) |
| запрос в полёте | `disabled` | защита от двойного клика |

### 13.3. Подтверждение и результат

- **Подтверждение** — существующая модалка `openModal` (1309): «Скопировать
  набор рецептов в «{имя фабрики}»? Будет добавлено **{K}** рецептов (уже в
  наборе: {M}). Источник: «{имена универсальных фабрик}»». Кнопки:
  «Скопировать» (`.gen`, primary) / «Отмена» (`closeModal`). Считанный `K`
  показываем **до** действия — объём понятен заранее.
- **Запрос:** `POST /studio/api/producers/{id}/recipes/copy-universal` (тело
  пустое), где `{id}` — id целевой фабрики (попап §13.2 / только что созданной
  §13.5). Ответ `200 {"added": N, "skipped": M}`.
- **Успех:** `showReport(["добавлено {added}, пропущено {skipped}"])` → сразу
  `fetchState()` (не ждать авто-refresh).
- **Пусто на сервере** (`added = 0`, гонка: источник опустел между рендером и
  запросом): тост «копировать нечего».
- **Ошибка 4xx:** через `api()` (тост, §7.5).

### 13.4. Реактивность после копирования

- Ветка «Товары»: `renderAll` при переключении (2683–2702) уже возьмёт новое

- Авто-refresh (399–409): `state.producer_recipes` — источник бейджей

  JSON-сравнение (уже указано в §7.4).

### 13.5. Вход 2 — диалог создания подтипа

В модалке `openProdCreatePopup` (2211–2220), под строкой «Имя», добавляется
чекбокс (только `kind=goods` — узлы-приглашения создаются лишь для товарных
категорий, `buildProdTree` 2000–2025):

```
<label><input type="checkbox" id="prodCreateCopy"> скопировать набор рецептов
  универсальной фабрики категории «{cat.name}» ({K} рецептов)</label>
```

- `K` — тот же клиентский расчёт (§13.2) по универсальным фабрикам категории.
- Источников/рецептов нет (`K = 0`) → чекбокс **не показываем вовсе** (модалка не
  должна обещать пустое действие); условие проверяется в `openProdCreatePopup`
  до разметки.
- `doProdCreate` (2225): после успешного `POST /producers` и **получения id
  новой фабрики** — если чекбокс стоял, вызвать тот же обработчик копирования
  для `{id}` новой фабрики, затем `fetchState()`. Порядок обязателен: копировать
  можно только в **существующую** фабрику.
- Ошибка создания → копирования нет (как сейчас). Ошибка копирования → фабрика
  создана, тост об ошибке (частичный успех честно виден).

### 13.6. Что в ветке «Производители» НЕ трогается (точная дельта §10)
