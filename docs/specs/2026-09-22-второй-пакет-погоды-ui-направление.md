## 2. Единый стиль подписей (правило)

1. **Имя = то, что видит игрок**, не внутренний механизм. Названия веществ (CO₂/CH₄/NH₃) в HUD не выводим — это flavor мира, а не ярлык явления (исключение — если создатель решит иначе, §12).
2. **Одна форма:** именительный падеж, первая буква заглавная, 1–3 слова, без точки, без латиницы, без скобок.
3. **Вариант уточняет базовое имя, но не lengthens без нужды.** Отдельное короткое имя получает только тот вариант, который игрок читает **как другое явление** (напр. `Смог`, `Ливень`, `Град`). Иначе остаётся базовое.
4. **`id` — контракт, не подпись.** `WEATHER_IDS`/`dataset.weather` не переименовываются; меняется только отображаемый текст.
5. **Температура — только °C** (решение создателя 2026-09-18). Кельвинов в UI нет нигде. В подписях погоды температуры нет вовсе.

## 4. Баг «Кислотный дождь» на нетоксичном дожде (починка)

**Факт:** явление `кислотный дождь` — **одно** явление с вариантами (пакет 1 §4.6): `toxic = true` → кислотный; `toxic = false` → обычный. Приоритет вариантов (пакет 2 §4.6): `радиоактивный` → `инверсионный` → `кислотный` (`toxic`) → **`обычный`** (fallback). Значит не-токсичный дождь — **нормальный случай**, а «кислотный» — частный.

**Было:**
- HUD: `state.weather.id` → «кислотный дождь» (строчными, всегда), вариант не виден;
- сутитиль: игрок на живой планете читает «кислотный дождь» там, где дождь обычный.

**Станет:** `weatherLabel(run)` (§5.3 спеки, клиентский хелпер) возвращает имя по **базовому `label` + карте вариантов**; дождь строится так:

| Вариант | **Подпись** |
|---|---|
| `обычный` (fallback) | **Дождь** |
| `кислотный` (`toxic`) | **Кислотный дождь** |
| `радиоактивный` | **Радиоактивный дождь** |
| `инверсионный` | **Ливень** |

**Почему база = «Дождь», а не «Кислотный дождь»** (отличие от literal-примера §5.3 спеки — формулировки делегированы @uidesigner): `обычный` — это fallback, т.е. **самый частый** случай; базовая подпись обязана быть нейтральной и безопасной при отсутствии данных о варианте (state без `variant`, старый пакет). При базе «Кислотный дождь» любой сбой резолва варианта возвращал бы баг. Если менеджер/создатель хочет строго по примеру спеки (§5.3), меняется **одна строка**: `label: 'Кислотный дождь'` + override `обычный → «Дождь»`; риск бага выше — **рекомендую базу «Дождь»**.

## 5. Подписи вариантов (карта `variantLabels`)

Механизм: `weatherLabel(run) = variantLabels[run.variant] ?? WEATHER_VISUALS[run.id].label`. Вариант без записи в карте → базовое имя. Данные — рядом с `label` в `surface_config.js` (`WEATHER_VISUALS[*].variantLabels`).

| Явление (base) | Вариант | **Подпись** | Почему отдельно |
|---|---|---|---|
| Туман | `серный`/`кислотный` (`toxic`) | **Смог** | читается как другое явление, зелёно-жёлтый |
| Туман | `плотный CO₂` | **Густой туман** | плотная белесая пелена |
| Туман | `морозный` (`cold`) | **Морозный туман** | оттенок/иглы |
| Туман | `марево` (`hot`) | **Марево** | тонкая дымка у горизонта |
| Туман | `аммиачно-метановый` | **Мутный туман** | зеленовато-бурые клубы, отдельного ярлыка не заслуживает, но «мутный» честнее |
| Пыльная буря | `стеклянно-кристаллическая` | **Стеклянная буря** | блеск осколков вместо песка |
| Гроза | `токсичная` | **Кислотная гроза** | зелёные разряды, связка с «Кислотный дождь» |
| Гроза | `сухая` | **Сухая гроза** | только разряды, без осадков |
| Ледяной град | `град` | **Град** | крупные твёрдые ядра |
| Ледяной град | `крупа`/`базовая крупа`/`углекислая крупа`/`метановая крупа` | **Ледяная крупа** | мелкие гранулы; вещество игроку не видно |
| Пепельный дождь | `сухой` (fallback) | **Пепелопад** | без жидкости «дождь» — неточность |
| Пепельный дождь | `криовулканический` | **Пепелопад** | то же, вещество не видно |
| Свечение | `светящийся туман` | **Светящийся туман** | — |
| Свечение | `светящийся ливень` | **Светящийся ливень** | — |
| Свечение | `биоаэрозоль` | **Светящиеся споры** | вместо техн. «биоаэрозоль» |
| Полярное сияние | `магнитная буря` | **Магнитная буря** | шире/ниже, многоцветные полосы |
| `штиль`, `метель`, `ледяные иглы` | все | **базовое имя** | варианты визуально близки; ярлык не нужен |

**Не даём отдельных подписей:** `ледяные иглы` (все варианты — «Ледяные иглы»: вещество игроку не видно, «иней» = те же кристаллы), `туман.базовый`, `пыльная буря.базовая`, `гроза.ливневая`, `сияние.базовое`, `дождь.обычный` (уже = базовое «Дождь»).

**Заголовки (tooltip) админ-чипов:** остаются поясняющими, не обязательны; достаточно `title` = базовая подпись, у вариантов в HUD тултипов нет.

## 6. Чипы и индикаторы фаз суток

Фазы (пакет 2 §6.1): **`рассвет`, `день`, `закат`, `ночь`**. «Сумерки» — собирательное для `рассвет`/`закат`; отдельной пятой фазы нет.

### 6.1. Админ-чипы (обязательно, §6.5 спеки)

**Новый элемент** — вторая строка `#hud-env-admin` во `.hud-center`, под `#hud-weather-admin`, тем же стилем чипов (`WEATHER_CHIP_CSS`/`paintWeatherChip` — переиспользуем, не дублируем).

- подпись группы: «сутки (админ)» (строчными, как «погода (админ)»);
- кнопки: «авто», **«Рассвет»**, **«День»**, **«Закат»**, **«Ночь»**;
- `dataset.env` = `''` / `рассвет` / `день` / `закат` / `ночь` (id контракта);
- `title` у кнопок: «авто» — «Сутки идут сами, как у игрока»; фазы — «Зафиксировать фазу до конца прогулки»;
- активная — подсветка жёлтым (как погода); при ручном выборе — **полный вид фазы с первого кадра**, держится до конца прогулки; «авто» возвращает цикл (по аналогии с погодой, пакет 2 §6.5);
- у **игрока строки нет вообще** (функция не вызывается) — как у погодных чипов.

### 6.2. Индикатор фазы у игрока — 3 варианта (ВЫБОР СОЗДАТЕЛЯ)

Что уже даёт цикл: небо, светило, свет, звёзды (пакет 2 §6.3). Вопрос — добавлять ли **явный** индикатор.

| Вар. | Что видит игрок | Цена | Минус |
|---|---|---|---|
| **A. Без индикатора** | фаза читается по небу/свету; брифинг объяснил один раз | 0 элементов | на широком разбросе биомов/явлений игрок может не заметить смену |
| **B (рекомендую). Тихая подпись в `.hud-center`** | перед подписью погоды — слово фазы: `Ночь · Полярное сияние`; днём — `День · Штиль` | одно `#hud-env`, контраст ниже остального HUD (не спорит с погодой) | ещё один элемент |
| **C. B + тост на смену** | при переходе — `notify('Светает…')` / `«Солнце садится»` / `«Ночь опустилась»` | ловим границу фазы, один вызов `notify` | тост раз в 1–3 мин может наскучить |

**Рекомендация:** **B** — фаза рядом с погодой, обычным текстом, приглушённым цветом; без глифов и без цифр часов. Смена фазы сама подсвечивает её через небо. Если создатель захочет «событийности» — **C** добавляется одной строкой, но это уже решение вкуса (§12).

**Формат B:** `#hud-env` — `<span>` перед `#hud-weather`; при `env` и известной фазе: `Рассвет` / `День` / `Закат` / `Ночь`; при отсутствии данных — пусто (элемент скрыт, см. §7). У админа текст фазы **без** суффикса «вручную/авто» (режим виден по подсветке чипа) — не дублируем.

1. **`surface_config.js` — `WEATHER_VISUALS`.** Было: `label` у 6 явлений; `кислотный дождь.label = 'Кислотный дождь'`. → Станет: `label` по §3 (у `кислотный дождь` — «Дождь»), у 5 новых — свои `label`; добавить `variantLabels` по §5. **Почему:** подпись — данные, а не строка в логике кадра.

3. **`surface_main.js` — строка HUD.** Было: `state.weather.id` (§строка 138). → Станет: `weatherLabel(state.weather)` + существующий суффикс ` · авто/вручную` (только админ). **Почему:** игрок видит человеческое имя, а не `id`.
4. **`surface_ui.js` — чипы явлений.** Было: `btn.textContent = it.label` где `it.label = id`. → Станет: текст = `WEATHER_VISUALS[id].label` (§3), `dataset.weather` = `id` (не менять). **Почему:** чипы — те же человеческие имена, контракт id цел.
5. **`surface_ui.js`/`surface.html`/`surface_main.js` — индикатор фазы (если создатель выберет B/C, §6.2).** Было: нет. → Станет: `#hud-env` (один `<span>` перед `#hud-weather`); обновление из `updateHUD`/соседней функции; текст по §6.2/§7; при отсутствии env — скрыт. **Почему:** явная, но тихая фаза рядом с погодой.
6. **`surface_ui.js` — админ-чипы фаз.** Было: нет. → Станет: `showEnvToggle(onPick)` по образцу `showWeatherToggle`: строка `#hud-env-admin` + «сутки (админ)» + «авто»/4 фазы; `setEnvToggleActive(id)`; вызов — только у `admin`/`skycomposer` и только если env доступен. **Почему:** инструмент обхода (пакет §6.5).
7. **`surface_ui.js` — брифинг.** Было: нет строки о сутках. → Станет: абзац §8 (2 строки или 1 — по решению создателя), приглушённым цветом, только при доступном env. **Почему:** игрок узнаёт про короткие сутки до старта, а не удивляется.

**Реактивность (что происходит при действии):**
- клик админ-чипа явления/фазы — мгновенное применение (без кроссфейда для ручного, как у погоды), подсветка активного, «авто» возвращает цикл;
- смена фазы в цикле — меняется только текст `#hud-env` (и небо/свет — зона отрисовки); никаких модалок/блокировок;
- игрок — HUD неинтерактивен (кроме «Вызвать корабль»), фаза только читается.

**Критерий проверки (как создатель увидит результат):**
1. На нетоксичной обитаемой планете HUD показывает **«Дождь»**, на токсичной — **«Кислотный дождь»** (баг закрыт).
2. Все 11 явлений (админ-чипы) дают человеческие подписи по §3; варианты — по §5 (напр. `toxic` туман → «Смог», `инверсионный` дождь → «Ливень»).
3. У админа — две линейки чипов («погода (админ)», «сутки (админ)»), обе переключаются и подсвечиваются; у игрока чипов нет.
4. Фаза читается: у игрока — по §6.2-выбору (или по небу), у админа — по чипам; ночной вид/сияние совпадают с выбранной фазой (визуальная часть — приёмка @gdesigner).
5. Брифинг содержит строку(и) о сутках; при отключённом env строка отсутствует, ошибок нет.
6. Неизвестный `id` в HUD → показан как есть; отсутствие `variant`/`sky` → без падения.

## 10. Что НЕ трогать (инварианты)

- **Логику выбора погоды** (`pickWeatherRun`, гейты/веса, анти-повтор, цикловой PRNG) и **отрисовку** 11 явлений/слоя среды — не трогаем.
- **Контракт `id`:** `WEATHER_IDS`, `dataset.weather`, `data-weather` — не переименовывать; «11 явлений» = 11 `id` без новых.
- **Поведение админки по погоде:** ручной выбор полон с первого кадра и держится до конца; «авто» = цикл 2–4 мин; суффикс ` · авто/вручную` сохранён.
- **Остальной HUD:** HP, оси `#hud-axes`, `#hud-biome`, `#hud-distance`, «Вызвать корабль» — не меняем.
- **Брифинг (существующие строки):** биом/доля/описание/планета/гравитация/°C/оси/приговор скафандра/жизнь — не меняем; добавляем **только** абзац §8.
- **Экраны смерти/паузы/прелоадера/ошибки высадки** — не трогаем.
- **Стиль (палитра, шрифты, глифы, анимации)** — зона @gdesigner; не выдумываем. Чипы фаз берут существующий стиль чипов погоды.
- **Механику/баланс/урон/HP/сервер/пакет/БД** — не трогаем (погода и среда визуальны).
- **Температура — только °C**; кельвинов в UI нет.
- **Основную спеку дизайнера не правим**; роадмап/идеи — не трогаем.
