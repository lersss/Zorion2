## 0. Резюме (одним абзацем)

Погода прогулки перестаёт быть «одним явлением из списка по категории биома,
нарисованным в экранных координатах». Теперь (а) **явление выбирается из физики
планеты**: давление задаёт, что вообще возможно, температура — наклон, токсичность —
вариант осадков и тумана, радиация — сияние, `liquid_medium` — цвет, биом — мягкое
смещение внутри физически разрешённого; (б) **явление рисуется в мировых координатах**
(частицы засеяны по мировым колонкам с модульной обёрткой, три пояса параллакса
0.4/0.7/1.0, приземные эффекты — по `terrainHeight`, не по экранному Y); (в) **дымка
глубины** прокрашивает слои мира (дальний силуэт сильнее, ближний слабее) — вместо
«полос на стекле»; (г) погода рисуется **тремя проходами между слоями мира**, а не
одним вызовом в конце кадра. Все входы уже в пакете прогулки (§7.1) — **сервер не
трогается**, новых таблиц/сущностей/миграций нет, урон от среды не затрагивается.

## 1. Цель, скоуп, границы

**Цель:** убрать «полосы на стекле» и получить читаемые живые явления; связать явление
с планетой так, чтобы на ледяном мире не шла пыльная буря, а на почти безвоздушном —
дождь. Носитель эмоции — вид (идея §1, спека прогулки §9).

**В скоупе:**
1. Модель выбора явления из осей планеты (жёсткая допустимость + мягкие веса) — §4.
2. Визуальная спецификация 6 явлений (общая механика §5.1 + по явлению §5.2–5.7).
3. Структурная правка порядка отрисовки: три прохода погоды между слоями мира — §6.
4. Параметры в `surface_config.js` — §7.
5. Сохранение админского ручного выбора и авто-цикла 2–4 мин — §8.

**НЕ в скоупе (не трогать):**
- зум/масштаб отрисовки, края экрана/число чанков, текстуры тел неба — параллельная
  правка @developer (идея §8.2–8.4);
- урон от среды, события опасности, HP — существующая логика (спека прогулки §8);
- сервер: `land`/`leave`, пакет прогулки, БД, миграции — не меняются;
- звук погоды (в прогулке звука нет; появление — отдельная задача);
- «дождь» как седьмое явление (см. §4.6 — осадки остаются одним явлением с вариантами).

## 2. Термины (кандидаты в GLOSSARY)

- **Явление погоды** — одно из шести состояний атмосферы прогулки: `штиль`, `туман`,
  `пыльная буря`, `метель`, `кислотный дождь`, `полярное сияние`. В один момент времени
  в прогулке ровно одно явление (§7.2 спеки прогулки).
- **Вариант явления** — визуальная модификация явления от осей планеты (напр. туман:
  обычный / морозный / смог / марево; осадки: обычные / кислотные). Вариант не меняет
  набор явлений и не является отдельным явлением.
- **Пояс частиц** — группа частиц явления с общим параллаксом и общей мировой шириной
  тайла (дальний 0.4, средний 0.7, ближний 1.0). Частицы засеяны по мировым колонкам
  и повторяются с периодом тайла (§5.1 п.2).
- **Дымка глубины** — полупрозрачная заливка «цвета воздуха» явления поверх слоя мира;
  доля (alpha) тем больше, чем дальше слой (§5.1 п.1).
- **Окно выбора** — 2–4 мин (существующее), в конце которого явление перебрасывается
  заново (§8).

## 3. Разворот подходов (пространство решений модели выбора)

Требовалось: из осей планеты получить явление, детерминированно, читаемо, расширяемо
на будущие явления. Перебраны 4 класса:

| Класс | Суть | Цена | Итог |
|---|---|---|---|
| **A. Таблица весов + взвешенный жребий** | жёсткие гейты допустимости + множители весов от осей, нормировка, жребий локальным PRNG | нужны авторские числа (эталон не задан); редкость настраивается одним числом | **принят** |
| B. Дерево решений (if/else по приоритету) | «первое сработавшее» правило | жёстко: редкие явления либо всегда, либо никогда; добавление оси ломает порядок; нет плавных вероятностей | отклонён |
| C. Непрерывное поле по осям (явление = ближайший полюс) | явление из расстояния в пространстве осей | непредсказуемо для автора, тяжело объяснить игроку и трудно отлаживать визуально | отклонён |
| D. Каталог расписаний на класс планеты | предвычисленные наборы явлений | второй реестр контента рядом с пакетом (дублирование), не масштабируется на новые явления | отклонён |

Принят **A**: он единственный даёт и «что физически невозможно — не появится»
(жёсткие гейты, требование создателя §8.1), и «редко, но бывает» (мягкие веса),
и одну точку расширения — новая строка в таблицах §4.

## 4. Модель выбора явления из физики планеты

### 4.1. Входы (всё — из пакета прогулки §7.1, сервер не трогаем)

| Поле | Роль в модели |
|---|---|
| `pressure_atm` | жёсткий гейт «что возможно» + плотность |
| `temperature` (K) | мягкий наклон (3 полосы) |
| `toxic` | вариант осадков/тумана + мягкий множитель |
| `radioactivity` (0–100) | мягкий множитель сияния — **сила** |
| `radioactive` (bool) | **гейт сияния** — готовая метка генератора `Radioactivity > 50` (`core.go:220`); своей константы порога не заводим |
| `liquid_medium` | мягкий множитель осадков (§4.3); **цвет не задаёт** — `biome_color` уже содержит сдвиг (§5.1 п.4) |
| `biome_category` (6 значений) | мягкое смещение вероятностей **внутри** разрешённого |
| `biome_color` | **единственный** источник цвета явлений: уже содержит сдвиги по `liquid_medium` и температуре (`SurfaceBiomeColorHex`, `surface_handlers.go:354`) — второй сдвиг не применять (§5.1 п.4) |
| `suit.temp_comfort_k`, `suit.pressure_comfort_atm` | **пороги полос** (единственный источник; своих констант не заводим) |
| `seed` | детерминизм жребия |
| `life`, `gravity` | **на погоду не влияют** (названо явно: `life` работает на декор, `gravity` — на физику игрока) |

**Пороги — из пакета, не из головы.** Полосы давления = `suit.pressure_comfort_atm`
(0.5–3.0 атм), полосы температуры = `suit.temp_comfort_k` (263–313 K). Правка вилок
скафандра в одном месте автоматически переносит пороги погоды — «один факт — одно место».

**Чего в пакете нет (влияние исключено, анти-ловушка «описываем то, чего нет»):**
влажность, облачность (`cloudCover`), роза ветров, альбедо поверхности. Этих полей в
пакете прогулки нет — модель **не зависит от них**. Ветер в §5 — визуальная константа
явления, а не измеренная величина планеты.

### 4.2. Жёсткие гейты: что вообще возможно

| Давление | Условие | Разрешённые явления |
|---|---|---|
| тонкая/вакуум | `p < 0.5` атм | `штиль`, `пыльная буря`. `Полярное сияние` **запрещено** (решение создателя 2026-09-22 №2: в вакууме светить нечему) |
| комфорт | `0.5 ≤ p ≤ 3.0` атм | `штиль`, `туман`, `пыльная буря`, `метель`, `кислотный дождь`; `полярное сияние` — **только при `radioactive = true`** (высокая радиация, решение создателя №2) |
| плотная | `p > 3.0` атм | `штиль`, `туман`, `пыльная буря`, `метель`, `кислотный дождь`. `Полярное сияние` **запрещено** (решение создателя 2026-09-22 №3: сияние живёт в разреженных верхних слоях) |

**Гейт сияния — один, в этой таблице** (отдельной таблицы или константы нет, §4.5).

Смысл (решение создателя §8.1): «почти без атмосферы осадков и туманов нет вообще —
только пыль и резкое небо»; плотная атмосфера даёт тяжёлые густые явления.

### 4.3. Мягкие множители: веса внутри разрешённого

Итог: `W(явл) = base × M_temp × M_rad × M_tox × M_liq × M_biome`.
`base`: сияние `0.15` (редкое), остальные пять `1.0`.

*Числа ниже — **калибровка, не эталон мира** (решение создателя 2026-09-22 №1):
приняты как есть, подстраиваются визуально после первой приёмки, в счётчик эталонов не
вносятся.*

**Температура** (полосы от `suit.temp_comfort_k`; `cold` < 263 K, `comfort` 263–313 K,
`hot` > 313 K):

| Явление | cold | comfort | hot |
|---|---|---|---|
| штиль | 0.6 | 1.2 | 0.5 |
| туман | 1.2 (морозный) | 1.0 | 0.8 (марево) |
| пыльная буря | 0.3 | 0.6 | 2.0 |
| метель | 2.0 | 0.05 | 0.0 |
| кислотный дождь | 0.0 | 1.6 | 0.7 |
| полярное сияние | 1.6 | 0.6 | 0.3 |

**Токсичность** (`toxic = true`): `туман` ×1.3 (смог), `кислотный дождь` ×1.2,
остальные ×1.0. Токсичность **переключает вариант** осадков и тумана (§5.6, §5.3).

**Радиация** (только сияние): `M_rad = clamp(1 + radioactivity / 25, 1, 5)` — задаёт
**силу** сияния. Допустимость сияния решает булева метка `pkg.radioactive` в гейте
§4.2 (порог генератора `Radioactivity > 50`, `core.go:220`); собственной константы
`thinRadGate` спекa не вводит.

**Жидкость** (`liquid_medium`): пусто/«нет» → `кислотный дождь` ×0.2, иначе ×1.0.
Множитель применяется **только к осадкам** (туман от типа жидкости не зависит —
непроверяемое правило снято, примеры §4.7 согласованы). Цвет не меняет (§5.1 п.4).

**Биом** (мягкое смещение, набор не задаёт):

| Явление | литосфера | вода | биосфера | вулканизм | крио | экзотика |
|---|---|---|---|---|---|---|
| штиль | 1.2 | 0.9 | 1.0 | 0.8 | 1.1 | 1.0 |
| туман | 0.8 | 1.4 | 1.3 | 1.2 | 1.2 | 1.1 |
| пыльная буря | 1.4 | 0.4 | 0.5 | 1.5 | 0.6 | 1.0 |
| метель | 0.6 | 0.5 | 0.7 | 0.4 | 1.6 | 0.8 |
| кислотный дождь | 0.7 | 1.3 | 1.4 | 0.6 | 0.8 | 0.9 |
| полярное сияние | 1.0 | 0.9 | 0.9 | 0.8 | 1.2 | 1.5 |

### 4.4. Жребий и детерминизм

1. Собрать разрешённые явления (§4.2), посчитать `W` (§4.3).
2. Нормировать по сумме; если `Σ W = 0` — `штиль` (недостижимо: вес штиля всегда > 0,
   он разрешён во всех полосах и не обнуляется ни одной осью).
3. Выбрать взвешенным жребием на **цикловом PRNG**:
   `mulberry32((seed ^ 0x5eed ^ Math.imul(cycle, 0x9e3779b1)) >>> 0)`.
   `cycle` — номер окна выбора (0, 1, 2…), счётчик прогулки. **Не** общий поток
   (`Math.random` запрещён, спека прогулки §12 п.10) и **не** накопленный rng: один и
   тот же `(seed, cycle)` даёт одно и то же явление — воспроизводимо в отладке.
4. **Анти-повтор:** если разрешено ≥2 явлений и выпало то же, что в предыдущем окне —
   жребий повторяется среди разрешённых **без** прошлого явления. При одном разрешённом
   явлении правило не действует (перебрасывать не из чего).
5. Границы полос — включительные (`p == 0.5` → комфорт; `T == 263` → комфорт), как окна
   потребления (`PITFALLS` «Дизайн и числа»).

### 4.5. Сияние: гейт и множитель

Гейт сияния — **один**, в таблице §4.2: `0.5 ≤ p ≤ 3.0` атм **и** `radioactive = true`.
Тонкая/вакуумная и плотная атмосферы сияние исключают (решения создателя 2026-09-22
№2–3). Отдельной таблицы или константы порога нет; величина радиации работает
**множителем силы**, а не допустимости (§4.3). Это снимает прежнее противоречие
§4.2 ↔ §4.5 по порогам давления.

### 4.6. Осадки: одно явление, два варианта

Осадки — **одно** явление `кислотный дождь` (id не переименовываем: он зашит в
админских чипах и `WEATHER`). Вариант определяет `toxic`:
- `toxic = true` — **кислотный** (зелёно-жёлтая пелена, реакция земли, §5.6);
- `toxic = false` — **обычный** (цвет от `liquid_medium`), подпись в HUD «Дождь».

Седьмое явление («дождь») не вводится: механика одна, различие — оттенок и подпись
(«один факт — одно место», не плодим сущность ради одного варианта). Подпись в HUD —
@uidesigner (§12).

## 5. Визуальная спецификация явлений

### 5.1. Общие правила (для всех шести)

1. **Дымка глубины.** Цвет воздуха явления (`airColor`) заливается поверх слоёв:
   дальний силуэт, средний (основной рельеф + декор), ближний (передний пояс).
   Доли — в таблице явления (§5.2–5.7); общий ориентир §7 идеи: дальний 45–70 %,
   средний 30–40 %, ближний 8–15 %, кадр 8–25 %. Заливка — `rgba(airColor, α)`;
   небо тоже уходит в `airColor` (отдельная заливка в дальнем проходе).
   `airColor = shade(biome_color, k)` со сдвигом от `liquid_medium` (п.4).
2. **Частицы в мировых колонках с модульной обёрткой.** Для пояса `b` заданы: тайл `S_b`
   (мировая ширина повторения, px), число частиц `N_b`, параллакс `p_b`.
   Частица `i`: `u_i = hash1(i, seed ^ salt_b) · S_b`, размер и фаза — от того же хеша.
   **Хеш — одна точка детерминизма:** `hash1` **экспортируется** из `surface_world.js`
   (добавить `export`; хеш там уже есть), второй хеш-механизм в модуле погоды не
   заводится (иначе два хеша дадут разные миры при одном seed). Экранная координата:
   `base = u_i − camera.x · p_b + windX(t)`; `sx = mod(base, S_b)`; частица рисуется в
   копиях `sx + k·S_b` для всех `k`, попадающих в кадр. **Никакого перебора экранного
   шага** — частица не «перескакивает» между кадрами (корень бага §2.2 идеи).
3. **Три пояса параллакса.** 0.4 — дальний (мелкий/медленный/много), 0.7 — средний,
   1.0 — ближний (крупный/быстрый/смазанный). Числа поясов — в таблице каждого явления.
4. **Цвет.** База — **только** финальный `biome_color` из пакета. Сдвиг по
   `liquid_medium` и температуре **уже выполнен сервером** (`SurfaceBiomeColorHex`,
   `surface_handlers.go:354`; `biomeColor`, `planet_image_v2.go:232–263`) — повторный
   сдвиг в клиенте запрещён (второй источник истины → дрейф, ловушка «один факт — одно
   место»). Явление строит оттенок из этой базы (`shade`, `rgba`) и добавляет
   собственный тинт (белый у метели, охра у пыли и т.п.). Авторские цвета явлений —
   отдельный заход к @gdesigner.
5. **Ветер с порывами.** Один вектор на явление (направление задаёт цикловой PRNG:
   влево/вправо). Снос `windX(t)` = базовая скорость × модулятор
   `g(t) = lo + (hi − lo) · (0.5 + 0.5·sin(2πt / P + φ))`, где `[lo, hi]` — **диапазон
   явления** (штиль `[0.8, 1.2]`, остальные `[0.6, 1.5]`; задан в таблице явления),
   период `P` — тоже из таблицы (3–14 с). Наклон оси потока (дождь/снег/пыль) — там же.
6. **Привязка к земле.** Всё, что касается земли (позёмка, заносы, всплески, пары,
   «юбка» песка, клочья в низинах), считается по `world.terrainHeight(wx)` и переводится
   в экран через `− camera.y + vh/2`. **Экранный Y для приземных эффектов запрещён**
   (корень §2.3 идеи — заглушка течёт по экрану).
7. **Пелена кадра** — заливка `rgba(airColor, α_frame)` поверх всего (кроме HUD) в
   переднем проходе; для сияния = 0 (небо чистое).

## 6. Структурная правка: три прохода вместо одного вызова

### 6.1. Было

`surface_main.js`: `drawSky → drawFarRelief → drawTerrain → drawDecor → drawCreatures →
drawPlayer → drawWeather` (один вызов в конце кадра). Отсюда «погода поверх всего» и
невозможность дымки по слоям.

### 6.2. Стало (порядок вызовов кадра)

```
drawSky(...)
drawWeatherBack(ctx, world, camera, vw, vh, w)     // проход 1
drawFarRelief(...)
drawWeatherMid(ctx, world, camera, vw, vh, w)      // проход 2
drawTerrain(...)
drawDecor(...)
drawCreatures(...)
drawPlayer(...)
drawWeatherFront(ctx, world, camera, vw, vh, w)    // проход 3
// HUD — как сейчас (DOM, ui.updateHUD)
```

### 6.3. Что в каком проходе

| Проход | Содержимое |
|---|---|
| `drawWeatherBack` (после неба, до дальнего силуэта) | шторы сияния (аддитивно; пар. 0.05–0.12 — **глубже** силуэта 0.35); тинт неба в `airColor` |
| `drawWeatherMid` (после дальнего силуэта, до рельефа) | дымка дальнего силуэта (`Air. дальний`); **дальний пояс (0.4) и средний пояс (0.7)** частиц |
| `drawWeatherFront` (после игрока) | дымка основного рельефа/декора (`Air. средний`); ближний пояс частиц (1.0); приземные эффекты (позёмка/заносы/юбка/всплески/пары) по `terrainHeight`; пелена кадра (`Air. кадр`) |

**Порядок глубины соблюдён** (правка по @critic): сияние (0.05–0.12) глубже дальнего
силуэта (0.35) → проход 1; оба ближних пояса частиц **0.4 и 0.7 ближе силуэта** →
проход 2 **после** него (прежде пояс 0.4 ошибочно ставился до силуэта, то есть под ним).

Порядок внутри переднего прохода обязателен: **сначала** дымка слоёв и пелена кадра,
**потом** ближний пояс и приземные эффекты — иначе крупные ближние частицы гасятся
пеленой и глубина пропадает.

### 6.4. Функции

- `surface_render.js`: **удалить** `drawWeather` (заглушка) и добавить три функции
  `drawWeatherBack/Mid/Front(ctx, world, camera, vw, vh, w)`, где `w` — состояние погоды
  (§7.2). Общая часть (расчёт позиций поясов, ветер, цвет воздуха) — внутренние хелперы
  файла, чтобы три прохода не дублировали формулы.
- `surface_main.js`: убрать вызов `drawWeather`; вставить три вызова (§6.2).
- **Хирургичность:** функции `drawSky`, `drawFarRelief`, `drawTerrain`, `drawDecor`,
  `drawCreatures`, `drawPlayer` не меняются. Зум/края/текстуры неба — чужая правка
  (идея §8.5): если @developer тронет трансформ камеры или число чанков, погодные
  проходы не должны требовать переделки — они зависят только от `camera` и `world`.

### 6.5. Зависимость от зума и `devicePixelRatio` (параллельная правка)

На клиенте прогулки параллельно появились **зум ~1.8×** и трансформ холста по
`devicePixelRatio` (идея §8.2). Погода этому **не противоречит**, но обязана соблюдать:

- все координаты частиц, дымки и приземных эффектов — **мировые** (`camera`,
  `terrainHeight`); перевод в экран — тем же трансформом, что у слоёв мира
  (`drawTerrain`/`drawFarRelief`). Погода **не применяет** ни зум, ни DPR повторно
  (иначе двойной масштаб);
- числовые размеры/скорости §5 даны в **мировых px при зуме 1×**; при зуме ~1.8× они
  визуально растут вместе с миром — это ожидаемо. Если после приёмки частицы кажутся
  крупными/быстрыми, подстройка идёт **внутри диапазонов §5**, без структурных правок;
- тайлы поясов `S_b` — в мировых px, поэтому при смене зума обёртка не рвётся (тайл и
  позиция частицы масштабируются согласованно).

## 7. Параметры (`surface_config.js`)

### 7.1. Правила выбора

`WEATHER_BY_CATEGORY` **удаляется** (биом больше не задаёт набор). Вместо него:

```js
export const WEATHER_IDS = ['штиль','туман','пыльная буря','метель','кислотный дождь','полярное сияние'];

export const WEATHER_RULES = {
  base: { /* §4.3 base */ },
  byTemp: { cold: {...}, comfort: {...}, hot: {...} },     // §4.3
  byToxic: { 'туман': 1.3, 'кислотный дождь': 1.2 },        // §4.3
  byLiquidAbsent: { 'кислотный дождь': 0.2 },               // §4.3 (только осадки)
  byBiome: { 'литосфера': {...}, 'вода': {...}, 'биосфера': {...},
             'вулканизм': {...}, 'крио': {...}, 'экзотика': {...} }, // §4.3
  aurora: { radDivisor: 25, radMax: 5 },                    // §4.3/§4.5 — сила; допустимость — pkg.radioactive
  repeatGuard: true,                                        // §4.4 п.4
  crossfadeMs: [600, 1200],                                 // §8
};
```

Пороги полос — **не здесь**: читаются из `pkg.suit` при старте прогулки (§4.1).

### 7.2. Визуал явлений

```js
export const WEATHER_VISUALS = {
  'туман': {
    label: 'Туман',
    air:    { base: 1.6, blend: ['sky', 0.5], far: [0.55, 0.70], mid: [0.30, 0.40],
              near: [0.08, 0.15], frame: [0.08, 0.25] },       // §5.3
    belts:  [ { parallax: 0.4, tile: 1400, count: [10, 16], size: [120, 320], h: [30, 70],
                alpha: [0.10, 0.20], drift: [5, 10] },
              { parallax: 0.7, tile: 1800, /* ... */ },
              { parallax: 1.0, tile: 2200, /* ... */ } ],
    wind:   { base: [5, 14], gust: { period: [8, 14], range: [0.6, 1.5] } },
    ground: { mode: 'valley', offsetPx: [-10, 20] },
    variants: { cold: {...}, hot: {...}, toxic: {...} },
  },
  /* 'штиль', 'пыльная буря', 'метель', 'кислотный дождь', 'полярное сияние' — по §5 */
};
```

Диапазоны `[min, max]` разрешаются **цикловым PRNG** один раз на окно (не на кадр) —
явление не «дышит» числом частиц покадрово.

### 7.3. Состояние в `surface_main.js`

```js
state.weather = { id, variant, params, t0, until, crossFrom, crossT };
```

`params` — развёрнутые из `WEATHER_VISUALS[id]` диапазоны (тайлы, частицы, ветер).
`crossFrom/crossT` — кроссфейд (§8).

## 9. Ограничения и «чего не делать»

1. **Только клиент.** Сервер, пакет прогулки, `land`/`leave`, БД — не меняются.
2. **Новых таблиц, сущностей, миграций НЕТ.** Погода — представление, не состояние:
   ничего не хранится, при рефреше явление перебрасывается (как и сейчас).
3. **Погода визуальна.** Урон — существующая отдельная логика (спека прогулки §8),
   не затрагивается. Явление не влияет на HP, события, ходьбу, столкновения.
4. **Не трогать:** зум/масштаб, края экрана/число чанков, текстуры тел неба (идея
   §8.2–8.4), `drawSky`/`drawTerrain`/`drawDecor`/`drawPlayer`/`drawCreatures`.
5. **Не перебирать экранный шаг частиц** (корень бага §2.2 идеи) — только мировые
   колонки с модульной обёрткой (§5.1 п.2).
6. **Не вводить седьмое явление** ради варианта осадков (§4.6).
7. **Не заводить собственные константы порогов** температуры/давления — только `suit`
   из пакета (§4.1).
8. **Не использовать `Math.random`** — только цикловой `mulberry32` (§4.4).
9. **Не применять зум/`devicePixelRatio` повторно** — погода идёт тем же трансформом, что
   слои мира (§6.5); собственных масштабов она не вводит.
