**своего** экрана (под ними нет другого контекста).

## 1. Модель слоёв: единый реестр полос

Один модуль-владелец `z-index` для попапов — **`web/static/js/ui/layers.js`**.
`z-index` больше **не пишется в разметке/файлах попапов**: его выдаёт реестр.

**Полосы (bands).** Понятная роль вместо числа. Внутри полосы порядок — по
порядку открытия (шаг 10), поэтому попапы одного типа корректно ложатся друг на
друга.

| Полоса | База | Роль | Кто в ней |
|---|---|---|---|
| `modal` | **1000** | диалоговый слой | модалка системы, диалоги/попапы форм, карточки-попапы (студии — позже) |
| `menu` | **1100** | транзиентные меню/подсказки | контекстные меню (карта, модалка, студия), тултипы (звезда, координаты, NPC), дропдаун поиска NPC |
| `banner` | **1200** | глобальные баннеры/пиллы | баннер пакмана, «Галактика пуста», offline-пилл (позже) |
| `alert` | **2000** | **ошибка/предупреждение/подтверждение поверх всего** | `openAlert`/`openConfirm` (новое) |
| `system` | **9000** | критические полноэкранные | вход в админку/студию, «сессия истекла» (позже) |
| `toast` | **10000** | уведомления | тосты (`ui/toast.js`) |

**Инварианты модели:**
- `alert` (2000) **выше любого легаси-попапа** (легаси ≤ 1300) — ошибка поверх
  модалки работает **даже до перевода** модалки/меню на реестр.
- `toast` (10000) остаётся **самым верхним** и **не участвует** в Esc/клик-вне/фокусе
  (уведомление, а не диалог) — поведение тостов не меняется. Крестик тоста
  (`.toast-close`) — **собственный**: реестр клики внутри тоста не перехватывает
  (тост не диалог, «закрыть» не должно становиться «клик вне»).
- **Маршрутизируемые и пассивные слои.** `modal`/`menu`/`alert`/`system` —
  **маршрутизируемые** (участвуют в Esc/клик-вне/ловушке фокуса). `toast`,
  `banner` и **тултипы** (звезда/координаты/NPC) — **пассивные** (`passive:true`):
  получают `z` из полосы, но **не участвуют** в маршрутизации — иначе видимый тост
  (10000) «съедал» бы Esc у модалки под ним (F2). Пассивные закрываются своим
  жизненным циклом, но **через `handle.close()`** (не `.remove()`).
- `system`-оверлеи (вход в админку/студию) живут **в своих документах** —
  кросс-страничных пересечений нет: карта, админка и студии — разные страницы,
  на каждой свой реестр.
- Хром страницы (`map.css` 10–60, шапки/зум/панели) — **не попап**: реестр его не
  трогает, значения остаются.
- Страничные оверлеи belt/surface (`#error`/`#pause`/`#loading`) — **не попапы**:
  это состояния **своей** страницы, под ними нет другого контекста. Остаются как
  есть; реестр их не касается.

**Кто верхний.** Реестр держит массив открытых слоёв (`stack`). Верхний — последний
открытый. `z` слоя = база его полосы + `10 · (число уже открытых слоёв этой полосы)`.
Упорядочивание между полосами задано таблицей, внутри полосы — открытием.

## 2. Контракт (API модуля `ui/layers.js`)

> Имена и сигнатуры — предложение @uidesigner; точная реализация — зона
> @developer. Смысл контракта обязателен.

```js
// Открыть слой. el — уже смонтированный в DOM корень попапа.
openLayer(el, {
  level,            // 'modal' | 'menu' | 'banner' | 'alert' | 'system' | 'toast'
  closeOnEsc = (level !== 'toast' && level !== 'banner'),
  closeOnOutside = (level === 'menu' || level === 'modal'),
  trapFocus = (level === 'modal' || level === 'alert' || level === 'system'),
  passive = (level === 'toast' || level === 'banner'),  // вне маршрутизации (§1)
  lockScroll = false,
  onClose,          // вызвать ОДИН раз при любом закрытии (чистка попапа)
}) -> handle        // { el, level, close(result), result }

handle.close(result)        // закрыть этот слой (результат доступен в onClose)
closeTop(reason)            // закрыть только верхний (Esc/клик вне)
closeToLayer(handle|level, {inclusive=false})  // «закрыть всё до уровня/слоя»
closeAll(level?)            // всё (или всю полосу) — навигация/разлогин
hasOpen() / topLayer()      // состояние стека

// Готовые диалоги поверх контекста (полоса alert):
openAlert({ title, text, actions = [{id:'ok', label:'Понятно', primary:true}] })
  -> Promise<actionId>      // возврат результата выбора
openConfirm({ title, text, confirmLabel='ОК', cancelLabel='Отмена' })
  -> Promise<boolean>
```

**Правила контракта:**
- **Владелец закрытия — реестр.** Попап **не вешает** собственный Esc/outside —
  иначе двойное закрытие (см. риск §8.1). Попап даёт реестру `onClose` со своей
  уборкой (снять DOM, остановить таймеры/rAF, вернуть колбэк).
- **Возврат результата** — через `handle.close(result)` и `onClose(result)`
  (диалоги `openAlert`/`openConfirm` возвращают Promise).
- **Отписка** — `close()` идемпотентен; `onClose` вызывается ровно один раз даже
  при `closeAll`.
- **Уровень выдаёт реестр**, попап его не считает (передаёт только `level`).
- **Пассивные слои вне маршрутизации (F2).** `passive:true` (тост/баннер/тултипы)
  не берут Esc/клик-вне/`Tab`; `topLayer()` возвращает верхний
  **маршрутизируемый** слой. `closeAll()` по умолчанию закрывает **только
  маршрутизируемые** — видимые тосты/баннеры не гасятся; пассивные снимаются
  своим циклом или явным `handle.close()`.

## 3. Поведение

### 3.1. Esc и клик вне — только верхний
- **Маршрутизация — только через реестр.** Единые слушатели (`keydown` Esc и
  `pointerdown`, capture) в реестре решают исход по верхнему **маршрутизируемому**
  слою (пассивные — тост/баннер/тултипы — **пропускаются**, §1). Локальные
  обработчики нижележащих слоёв **на время верхнего не активны**: `closeOnOutside`
  нижнего не срабатывает, пока над ним есть слой. При переводе попапа его локальные
  Esc/outside-слушатели **снимаются** (ТЗ §6.2) — иначе «Esc убил модалку под меню»
  и двойное закрытие вернутся.
- `Escape` → `closeTop('esc')`, **если** у верхнего `closeOnEsc`. Нижележащие не
  трогаются. Событие гасим, чтобы старые/чужие слушатели не сработали повторно.
- Клик/`pointerdown` вне корня верхнего слоя → `closeTop('outside')`, если
  `closeOnOutside`. Клик **внутри** верхнего слоя не закрывает ничего.
- Если `closeOnOutside=false` (алерт, тост, баннер) — клик вне **не** закрывает
  (алерт требует явного выбора).
- Открытие нового слоя **не** закрывает нижележащие (стек).

### 3.2. Фокус и доступность
- При открытии: сохраняем `document.activeElement`; фокус уходит в слой
  (`[autofocus]` → первый фокусируемый → сам корень с `tabindex="-1"`).
- **Ловушка фокуса** (`trapFocus`): `Tab`/`Shift+Tab` обрабатывает **верхний
  маршрутизируемый** слой, циклично внутри него; ловушки нижележащих **спят**, пока
  есть слой выше. Корень помечается `role="dialog"`, `aria-modal="true"` (меню —
  `role="menu"`), `aria-label` = заголовок/роль.
- При закрытии: фокус возвращается на элемент, открывший слой (или на
  нижележащий слой), если он ещё в DOM.

### 3.3. Блокировка прокрутки фона
- Пока открыт ≥1 слой с `lockScroll` — `document.documentElement.style.overflow='hidden'`
  (ref-count); при закрытии последнего — вернуть как было.
- Дефолт `lockScroll=false`: модалка системы прокрутку карты не блокирует
  (карта за ней и так фиксирована). Включаем адресно там, где фон прокручивается.

### 3.4. Навигация и разлогин
- Навигация в проекте — полная перезагрузка страницы: стек и DOM попапов
  умирают сами. **Дефект возможен только с `lockScroll`** — снимаем его на
  `pagehide` (и в `closeAll`) как страховку.
- Уход на `/login-page` (`handleUnauthorized` в `modal/index.js`) — перед
  `location.href` вызвать `closeAll()` (косметика; страница всё равно
  перезагрузится). **`belt_*` здесь ни при чём:** у belt-страниц нет реестра и
  своего `handleUnauthorized` (401 обрабатывает `belt_main.js` инлайн-редиректом) —
  этап 1 не подключает реестр к belt/surface (F9).

### 3.5. Звук
- Не меняется: тосты звучат как раньше (`playToast`); закрытия молчат.
- **Решение (менеджер, 2026-09-23):** алерт ошибки **играет `ui_error`** — только
  там, где звук активирован (`activateSound` — карта). В админке/студиях звук
  молчит (как и весь интерфейс этих страниц).

## 4. Случай «ошибка поверх модалки» — фикс бага пояса

### 4.1. Как сейчас (диагноз)
Клик «⛏ Добывать» (`modal/events.js` `showBeltMenu`) делает
`window.location.href = '/belt.html?belt=<id>'`. Страница `belt.html` в `boot()`
шлёт `POST /api/belt/mine/enter`; сервер отказывает `400 «Трюм полон»`
(`belt_mining_handlers.go:424`, осн. §6.2); `belt_main.js` показывает
**полноэкранный** `#error` (UI §5.3). Итог: карта и модалка уехали вместе со
страницей — контекст потерян.

### 4.2. Как должно быть — «пред-проверка без мутации» (рекомендую)

**Почему не вызов `enter` из модалки.** `POST /api/belt/mine/enter` **не
read-only**: успешный вызов пишет `users.current_position = mining` и (лениво)
инициализирует `system_belts.iron_remaining` (осн. §6.2 п.2, осн. §6.3). Пречек,
который «просто спрашивает сервер», оставлял бы игрока **в поясе**, если он
передумал: маркер уезжает к поясу, игрок бесплатно видит состав (обход гейта
знания), F5 даёт «висящую» сессию `mining`, двое могут «войти» одновременно.
Значит пречек обязан быть **read-only — без вызова `enter`**.

**Данных на карте достаточно** (всё уже есть):
- `modalState.myPosition` — стоит ли игрок **в этом поясе** (`orbit`/`mining`);
- `modalState.belts[]` — `remaining_level` (`полный`/`истощается`/`выработан`) и
  `belt_class`, уже отфильтрованные **гейтом знания** (осн. §6.4/§8.4);
- `GET /api/cargo` — свободное место в трюме (`limits.mass.used/total`).

Поток по клику пункта «⛏ Добывать» (`showBeltMenu`):
1. Меню закрываем; строим вердикт **локально по данным выше** — без запросов
   `enter` и без смены состояния игрока.
2. **Вердикт «можно»** → прямой переход
   `window.location.href = '/belt.html?belt=<id>'` (как сейчас).
3. **Вердикт «нельзя»** → показываем **`openAlert` полосы `alert`** (2000,
   **выше модалки 1000 и меню 1100**). Модалка **остаётся открытой**, игрок — на
   карте; `belt.html` в этом случае не открывается вовсе.
4. **`status='mining'`** (пункт «⛏ Продолжить добычу») → **прямая навигация без
   пречека**, **кроме случая «пояс выработан»**: «выработан» **важнее** `mining`
   (как в UI §2.2 и коде, где пункт дизейблится при выработанном независимо от
   позиции) — тогда алерт/`disabled`, а не навигация (F4).

**Матрица вердикта (тексты — как у сервера, UI §5.3/§7):**

| Условие (локально) | Заголовок/тело алерта | Кнопки |
|---|---|---|
| не в этом поясе (`myPosition` ≠ этот пояс `orbit`/`mining`) | «Сначала долетите до пояса» / «Подлетите к поясу и попробуйте снова.» | «Понятно» |
| `remaining_level == 'выработан'` (при знании) | «Пояс выработан» / «Добывать здесь больше нечего.» | «Понятно» |
| запаса нет данных (поле пусто — старый/неинициализированный мир, осн. §8.4) | «Нет данных о запасе пояса» / «Заход в пояс невозможен.» | «Понятно» |
| свободный трюм `0` (из `GET /api/cargo`) | «Трюм полон» / «Нет свободного места в трюме — добывать некуда. **Выгрузите груз на дашборде** (раздел «Корабль», блок «Трюм») и возвращайтесь.» | «Понятно» |
| иначе | — сразу `belt.html` (без алерта) | — |

**Один вердикт — один алерт.** Приоритет сверху вниз (первое совпавшее): не в
поясе → выработан → нет данных → полон трюм. Часть причин уже отсекается
`disabled`-состоянием пункта (UI §2.2: полёт, «не в поясе», выработан) — там клик
не проходит вовсе; локальный алерт — **для активного пункта**, прежде всего
**«Трюм полон»** (и «нет данных», если пункт оставлен активным). Пункт меню при
**известной** причине можно **заранее пометить `disabled`** с `title` (как UI §2.2)
— опционально; алерт остаётся обязательным финальным ответом по клику. Сеть при
запросе `/api/cargo` недоступна — вердикт «трюм» пропускаем (не блокируем игрока
из-за сети), остальные проверки работают.

**«Понятно»** → закрывается **только алерт**; модалка, камера и выбранная
планета/вкладка на месте. Кнопки «Открыть трюм» **в v1 нет** (решение менеджера,
2026-09-23): она сама уводит с карты — против цели. Куда разгрузиться, объясняет
текст алерта.

### 4.3. Что осталось на belt.html — три пути захода

| Путь захода | Кто показывает отказ |
|---|---|
| из модалки, вердикт «нельзя» | **модалка** — `openAlert` поверх неё (§4.2) |
| из модалки, вердикт «можно» | навигация; если отказ всё же случится (гонка) — его покажет `belt.html` своим экраном |
| **прямой вход** `/belt.html?belt=…` (закладка / F5 / ручной URL) | **`belt.html`** — полноэкранный `#error` (UI §5.3). Корректный третий путь: под ним нет модалки, терять нечего |

**Честно про дублирование валидации.** Локальный вердикт (§4.2) **дублирует**
серверную проверку `enter` — **осознанный компромисс**: взамен мы не трогаем
состояние игрока скрытым вызовом `enter` и не уводим его с карты. Источник правды
остаётся за сервером (он валидирует при фактическом заходе, осн. §6.2); клиент
лишь **не даёт уйти в тупик** по уже известным причинам.

Ветка **«Пояс не найден»** (`belt_mining_handlers.go:338/393/397/522`) гейтится
**только сервером** (в `BeltView` такого поля нет) — локально не воспроизводится
и остаётся на стороне `belt.html` (полноэкранный экран ошибки). Строку **«вне зоны
видимости»** `enter` **не отдаёт** — она из других ручек (`world_handlers.go:114`,
`planet_handler.go:105`), в матрицу §4.2 не входит (F6). Это тот же третий путь
таблицы.

**Ленивая инициализация.** `iron_remaining` у пояса инициализируется **лениво** —
на первом `enter` (осн. §6.3), поэтому до первого захода `remaining_level` может
отсутствовать: тогда показываем «нет данных», а не «выработан» (осн. §8.4).

**belt.html не меняется:** механизм отказа страницы остаётся как есть (UI §5.3);
меняется только **что** модалка делает с известной заранее причиной.

**То же применимо к «Высадиться» → `/surface.html`** (та же навигация-отказ,
`surface_main.js`: ошибка → редирект на `/map`). В **этой** спеке **не делаем** —
отдельная дельта после v1 (решение менеджера, §10 О3).

## 7. Критерий проверки (как создатель увидит результат)

1. **Баг пояса — фикс.** Трюм полон, игрок на карте, открыта модалка системы →
   ПКМ по поясу → «⛏ Добывать»: игрок **остаётся на карте**, модалка открыта, а
   **поверх неё** — попап «Трюм полон»; «Понятно» закрывает только попап.
   При этом **состояние игрока не изменилось**: позиция/маркер не «уехали» к
   поясу, `mining` не выставлен, состав пояса не раскрылся (пречек был read-only).
2. **Esc — только верхний.** Модалка + алерт: первый `Esc` закрывает **алерт**,
   модалка остаётся (та же планета/вкладка/камера); второй `Esc` — модалку.
3. **Клик вне — только верхний.** То же: клик по затемнению алерта (если он
   закрываем) / по пустому месту закрывает **верхний**, нижележащее цело.
4. **Вложенный попап не убивает нижний.** Открыть контекстное меню поверх
   модалки, затем ошибку поверх меню: закрытие по одному — по порядку
   (ошибка → меню → модалка), состояние модалки сохраняется всё время.
5. **Не сломано старое.** Меню карты/модалки, тултип координат, поиск NPC, тосты
   (верх-право, не гаснут по Esc), баннер пакмана и «Галактика пуста» — как
   раньше; дропдаун поиска сущностей `#entity-search-results` выходит **над**
   модалкой; **видимый тост не мешает** `Esc` закрыть модалку под ним и сам при
   этом не гаснет (F2); прямой вход на `/belt.html` (F5) по-прежнему даёт
   полноэкранный экран ошибки.
6. **Фокус/прокрутка.** После закрытия попапа фокус возвращается туда, где был;
   `Tab` не уводит из открытого диалога; фон под ним не прокручивается (если
   `lockScroll` включён).

## 8. Риски регрессий и что НЕ трогаем

1. **Двойное закрытие (главный риск).** Пока у модалки/меню остаются свои Esc/
   outside-слушатели, реестр закроет **два** слоя за одно нажатие. Требование:
   при переводе попапа его локальные слушатели **удаляются** (ТЗ §6.2).
2. **Клик вне vs. drag/pan.** Модалка и карта перетаскиваются `mousedown`.
   Outside-закрытие обязано игнорировать события **внутри** корня верхнего слоя и
   не закрывать слой, открытый тем же жестом (проверять по `stack` после события).
3. **Уборка `closeModal`.** Если слой просто снять из DOM, не вызвов `onClose`,
   останутся `rAF`-цикл, `setInterval` опроса игроков, чужой `setRedrawCallback`.
   **Не менять** тело `closeModal()` (только вызывать его из `onClose`).
4. **Прокрутка.** Включать `lockScroll` точечно: блокировка на модалке системы
   ломала бы ожидание «карта под ней живёт». Дефолт — `false`.
5. **Пакман, агенты, тултипы — семантика сохраняется.** У баннера/оверлея
   пакмана и тултипов (звезда/NPC) **не появляются** Esc/клик-вне/трейп: только
   смена источника `z-index`. **Тултип координат** сохраняет **свой** цикл
   (мин. 3 с + скрытие по ЛКМ, `closeOnEsc:false`) — поведение **подтверждено как
   есть** (F8), на реестр переводится только `z`.
