## 1. Зачем

Первая витрина локального рынка: у игрока появляется место, где кредиты превращаются в игровое имущество (модули корабля), а экономика получает **печь** — точку, где деньги сгорают (покупка без встречного зачисления). Каркас «витрина с разделами» (решение создателя) закладывает форму для будущих разделов рынка (товары, отчёты, ресурсы) — сейчас реализуется только раздел «Модули».

Текущее состояние: модули корабля выдаются только стартовой комплектацией (`radar_1`/`scanner_1`/`engine_1`/`cargo_1`), интерфейса покупки/установки нет. Магазин даёт первый канал приобретения и **заменяющий установщик** (покупка ставит модуль в слот; свободная установка/снятие — вне скоупа, см. §16).

## 2. Решения создателя (2026-09-24, из идеи — не менять)

1. **Каркас будущей торговли** — «витрина с разделами»; сейчас только раздел «Модули».
2. **Базовые модули** `cargo_1`/`engine_1`/`radar_1`/`scanner_1` — **бесконечный запас** «для теста экономики». Продвинутые — только через лабораторное производство (канал 3b.6.3 спеки фабрик), задел вне v1. Инвариант «NPC — пол, а не потолок» (`11_markets.md` §11.2.2): рынок торгует тем, что есть у всех, и не превосходит производство.
3. **Место** — модалка планеты (паттерн: доска контрактов, покупка отчётов).
4. **Наличие поселения на планете = есть рынок**; видимость — по ветке данных вкладки «Поселения».
5. **Покупка = трейд-ин**: старый модуль в слоте выкупается за **50 % полной цены** и **засчитывается в оплату**; пустой слот — без выкупа; инвентаря игрока НЕТ; «дребезг купи-продай невыгоден (потеря 50 %) — печь кредитов».
6. **Покупка только при присутствии на орбите планеты** (серверно-авторитетно, инвариант 8); прецедент — `can_buy_report` из орбитной спеки; «контракт — единственный рычаг удалённого действия».

## 3. Скоуп

**Входит:**
- Справочник предложений `market_offers` (раздел «Модули»; 4 строки базовых модулей, бесконечный запас).
- Витрина планеты: `GET /api/planets/{planetID}/market`.
- Покупка: `POST /api/planets/{planetID}/market/buy` (серверно-авторитетно: присутствие, живое поселение, слот, списание, установка, журнал).
- Трейд-ин: выкуп старого модуля слота за 50 % полной цены, зачёт в оплату.
- Вкладка «Магазин» в карточке планеты (видимость — по данным вкладки «Поселения»).
- Дельта чтения модулей: модуль работает по типу из любого слота (в т.ч. `universal*`).

**Не входит** (см. §16): продвинутые модули, per-планетный ассортимент/цены, свободная установка/снятие, инвентарь игрока, рынок отчётов, топливо, селектор корабля.

Цена — свойство рынка, не модуля: `equipment` — справочник предметов (77a), рынки будущего будут менять цены без смены предмета. Будущие разделы витрины (товары/отчёты) не влезут в `equipment` (там `goods`/иное). (в) отклонено для v1: каталог общий, локальность выражается **гейтами знания и присутствия**, не ассортиментом |

Иначе покупка `radar_1`/`scanner_1`/`engine_1` — фикция (платишь за неработающее). (в) противоречит замыслу универсального слота (трюм §20.2) |

(б) создаёт деньги из ниоткуда — эмиссия в обход замкнутой системы (`14_money.md` §14.1); зачёт не даёт игроку денег, только снижает цену — печь работает, эмиссии нет |

## 5. Данные: `market_offers` (миграция `000081`)

Справочник предложений витрины. Природа — **справочник-каталог** (не событие, не лог): статичные строки «что продаётся и за сколько». Владелец — **все игроки** (общий каталог; локальность — гейты знания и присутствия, §7). Расширяемость: `kind` — **открытый список** разделов (паттерн `money_operations.kind`, денежная спека §3.2); схема переживает второй тип (`good`/`report`) без изменения.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `bigserial` PK | ключ предложения (паттерн `categories`/`goods`, `000045`) |
| `kind` | `text` NOT NULL CHECK (`kind = 'module'`) | раздел витрины. **Открытый список** (позже `good`, `report`…) — CHECK сужается до текущего типа, расширение — отдельной миграцией |
| `item_id` | `text` NOT NULL | что продаётся: для `kind='module'` — `equipment.id` (`cargo_1`…). Полиморфная ссылка без FK (паттерн `accounts.owner_id`, денежная спека §3.1); валидация — на сервере (`EquipmentByID`) |
| `price` | `bigint` NOT NULL CHECK (`price >= 0`) | цена в кредитах (целое — деньги не дробим, денежная спека §3.1) |
| `params` | `jsonb` NULL | задел (скидки, ограничения) — в v1 не используется |
| `created_at` | `timestamptz` NOT NULL DEFAULT `now()` | |

**Сид (в миграции):** 4 строки, `kind='module'`, `item_id` = существующие записи `equipment` (миграции `000040`/`000043`/`000068`):

| `item_id` | `name` (из `equipment`) | `type` | `params` | `price` (гипотеза, см. §11) |
|---|---|---|---|---|
| `cargo_1` | Грузовой модуль-1 | `cargo` | `{"capacity": 30}` | 3 000 |
| `engine_1` | Двигатель-1 | `engine` | `{"speed_factor": 0.3}` | 3 000 |
| `radar_1` | Радар-1 | `radar` | `{"radius": 800}` | 3 000 |
| `scanner_1` | Сканер-1 | `scanner` | `{"depth":"surface","settlements":true}` | 3 000 |

**Бесконечный запас** — отсутствие учёта остатков: предложение всегда в наличии (решение создателя). Строка `market_offers` — не склад, а цена+предмет; «кончился» = строка удалена админом (в v1 — не удаляется).

**Идемпотентность сида:** `INSERT ... ON CONFLICT (id) DO NOTHING` (сид — справочник, повторный прогон не дублирует).

**Инвариант каталога:** для `kind='module'` `item_id` обязан существовать в `equipment` (проверка при сиде и на чтении — `EquipmentByID`; отсутствие → строка пропускается с логом, не 500).

## 6. Миграция `000081`

Номер свободен (последняя занятая — `000080`). Самостоятельная, чужих ручек не трогает.

```sql
-- 000081: магазин модулей — справочник предложений витрины (спека
-- 2026-09-24-магазин-модулей-локальный-рынок §5). Раздел «Модули»:
-- 4 базовых модуля, бесконечный запас. kind — открытый список разделов
-- (позже good/report), CHECK сужен до текущего типа.
CREATE TABLE market_offers (
    id         BIGSERIAL PRIMARY KEY,
    kind       TEXT NOT NULL CHECK (kind = 'module'),
    item_id    TEXT NOT NULL,
    price      BIGINT NOT NULL CHECK (price >= 0),
    params     JSONB NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

INSERT INTO market_offers (kind, item_id, price) VALUES
    ('module', 'cargo_1',   3000),
    ('module', 'engine_1',  3000),
    ('module', 'radar_1',   3000),
    ('module', 'scanner_1', 3000);
```

## 7. API

### 7.1. `GET /api/planets/{planetID}/market` — витрина планеты

Роль: `player` (JWT). Админ/skycomposer — не нужен (видят всё и так; флаг `can_trade` для них `false`).

**Ответ `200`:**

```json
{
  "offers": [
    {"id": 1, "kind": "module",
     "item": {"id": "cargo_1", "type": "cargo", "name": "Грузовой модуль-1", "params": {"capacity": 30}},
     "price": 3000}
  ],
  "can_trade": false
}
```

- `offers` — все строки `market_offers` (сейчас 4; `item` — развёрнутый модуль из каталога `equipment`; каталог клиенту уже отдаётся в `/me.ship_catalog` — здесь дубль **осознанный**: витрина должна быть самостоятельной, без зависимости от даты загрузки `/me`).
- `can_trade` (bool, default `false`) — **гейт покупки**: `true` ⟺ игрок **присутствует** на орбите **этой** планеты (прецедент — `can_buy_report`, орбитная спека §5.2; отличие: там карточка ≠ планета присутствия, здесь карточка = планета присутствия). Присутствие на спутнике — по родительской планете (орбитная спека §5.5). Статус `surface` — **не** даёт `can_trade` (решение создателя: «присутствие на орбите»; возврат на орбиту — `POST /api/surface/leave`).

**Гейт знанием (И-С1 орбитной спеки, инвариант 5 — свежесть только за присутствие):** роут гейтится **тем же режимом знания, что и вкладка** (§10) — витрина не раскрывает бит «есть живое поселение СЕЙЧАС»:

- режим `none` (записи знания нет) — **`404` «Нет данных»** (как прочие скрытые детали планеты; `offers`/`can_trade` не отдаются);
- знание есть (`presence`/`snapshot`/`scan`, приоритет орбитной спеки §5.1), но `settlements_count == 0` — **`200` с `offers: []`** (рынка нет — по знанию, не по живости сейчас);
- знание есть и `settlements_count > 0` — **`200` с каталогом**; живость поселения **сейчас** здесь не проверяется и не раскрывается (она — гейт покупки, §7.2 п.2), `can_trade` — только при `presence`.
- **Планета не найдена** — `404`.

**Серверная проверка присутствия** — по `users.current_position` (инвариант 8; позиция игрока — серверно-авторитетная, спеки 99.2.27/высадка). Флаг вычисляется на чтении, ничего не пишется.

### 7.2. `POST /api/planets/{planetID}/market/buy` — покупка

Тело: `{"offer_id": 1, "slot": "universal2"}`.

`slot` ∈ `universal` | `universal2` | `universal3` (конвенция трюма §20.2; нумерация 1-based по позиции). Валидация: ключ существует и его номер ≤ `ship_models.slots.universal` модели игрока (для `starter` — 3).

**Алгоритм (сервер, одна транзакция):**

0. **Сериализация**: `SELECT ... FROM users WHERE id = $1 FOR UPDATE` — блокировка строки игрока (единственная точка сериализации покупок). Параллельные покупки в один слот выстраиваются в очередь; каждая следующая видит слот **после** предыдущей установки и корректно считает трейд-ин — выкуп старого не теряется.
1. **Гейт присутствия**: игрок на орбите планеты (`can_trade`, §7.1). Нет → `403` «Покупка доступна только с орбиты планеты».
2. **Живое поселение**: `SELECT 1 FROM settlements WHERE planet_id = $1 AND population_exact > 0 LIMIT 1`. Нет → `409` «Рынок закрыт» (поселение вымерло между открытием витрины и покупкой). Живость — **только здесь**, на покупке; на чтении (§7.1) не раскрывается.
3. **Предложение**: `market_offers` по `offer_id`; для `kind='module'` — `EquipmentByID(item_id)` (модуль обязан существовать). Нет → `404` «Предложение не найдено».
4. **Слот**: валиден (§7.2); текущее содержимое — `users.equipment.slot` (отсутствие ключа = пусто).
5. **Сумма**: `tradein = floor(price_старого / 2)`, где `price_старого` — цена модуля, стоящего в слоте, **из `market_offers`** (по его `item_id`); модуля нет в `market_offers` → `tradein = 0`. Итог: `amount = max(0, price_нового − tradein)`. **Выкуп не даёт денег сверх цены** («засчитывается в оплату» — не отдельное зачисление, §2 п.5).
6. **Списание** (инвариант 1, паттерн «прочая трата» денежной спеки §3.3):
   ```sql
   UPDATE accounts
      SET balance = balance - $amount,
          withdrawable = LEAST(withdrawable, balance - $amount)
    WHERE owner_type = 'player' AND owner_id = $1 AND balance >= $amount
   ```
   `RowsAffected == 0` → `409` «Недостаточно средств» (проверка и списание — одним оператором, атомарно).
7. **Установка**: `UPDATE users SET equipment = jsonb_set(COALESCE(equipment, '{}'), $slot, to_jsonb($item_id)) WHERE id = $1`.
8. **Журнал**: `money_operations` — `kind='purchase'`, `delta = −amount`, `balance_after` (расширение открытого списка kind, денежная спека §3.2; `contract_id` — NULL).
9. **Ответ**: `200 {"ok": true, "amount": 3000, "tradein": 1500, "slot": "universal2", "item_id": "radar_1"}`.

**Отказы:** `400` (невалидный `slot`/тело), `403` (не на орбите), `404` (планета/предложение), `409` (рынок закрыт / недостаточно средств).

**Гонки:** блокировка строки игрока (п.0) сериализует покупки одного игрока — вторая покупка в тот же слот ждёт первую и считает трейд-ин по уже обновлённому слоту. Идемпотентности нет **намеренно**: повторная покупка того же модуля в тот же слот — новый трейд-ин (−50 % за цикл, печь).

## 8. Деньги: печь кредитов

- **Покупка — «прочая трата»** (денежная спека §3.3): `balance −amount`, `withdrawable = min(withdrawable, balance_after)` — метка «заработанное» сгорает при трате. Правило уже зафиксировано в денежной спеке — здесь только применение.
- **Деньги никому не зачисляются**: у поселений нет счёта (канон `14_money.md` §14.3.0 — кошелёк поселения — лимит, не счёт; денежная спека §3.1). Сумма покупки **сгорает** — рынок NPC, «торговец скупает → деньги сгорают (печь)» (`13_tiers.md` стр. 376). Эмиссии нет: выкуп — зачёт в оплату (§7.2 п.5), а не зачисление.
- **Дребезг невыгоден**: купил за 3 000 → заменил (выкуп 1 500) → итог −1 500 за замену (−15 % капитала за цикл); каждый цикл −50 %. Это и есть печь.
- **Журнал**: `kind='purchase'` — новый вид движения в открытом списке `money_operations` (денежная спека §3.2). Игрок видит свою историю (`GET /me/money`), чужие — никогда (§3.2, `14_money.md` §14.4).

## 9. Дельта чтения модулей: эффект из любого слота

Сегодня `RadarRadius`/`HasScanner`/`HasEngine` (`internal/ship/radar.go`, `catalog.go`) читают **только** легаси-ключи `radar`/`scanner`/`engine`. Модуль, купленный в `universal*`, не давал бы эффекта — покупка стала бы фикцией (развилка §4).

**Дельта к 77a §4.2 / 91a §7.3 (зафиксировать в этих доках):**

- **`RadarRadius(equipment)`**: ищет радар по **всем** значениям `equipment` (любой слот); радиус — **максимум** из установленных радаров (несколько радаров не суммируются — радиус свойство корабля). Без радара — минимум 200 px (существующий фолбэк).
- **`HasScanner(equipment)`**: наличие валидного сканера в любом слоте.
- **`HasEngine(equipment)`**: наличие валидного двигателя в любом слоте (полёт без двигателя запрещён — 91a §6.1, сохраняется).
- **`CargoCapacityMass`** — уже итерирует все значения (§8.3 трюма) — правок не требует; `cargo` из `universal*` уже даёт ёмкость.

**Скорость двигателя (`EngineSpeed`) — контракт v1 (не обещаем больше, чем реализуемо):** в v1 чтение **не меняется** — `EngineSpeed` берёт скорость из установленного в легаси-слоте `engine`; двигатель в `universal*` даёт **право полёта** (`HasEngine` — любой слот, 91a §6.1), но скорость не изменяет. **Задел vNext:** «скорость — из любого установленного двигателя» (правило выбора — максимум/произвольный — на этап продвинутых двигателей, когда появится не один двигатель).

Смысл: **модуль работает по типу, независимо от слота**; легаси-слоты — стартовые позиции комплектации, `universal*` — позиции приобретений. Один модуль одного типа — один эффект (радар не стекается); `cargo` — суммируется (существующее поведение, трюм §8.3).

## 10. UI: вкладка «Магазин» в карточке планеты

Формат модалки — открытое решение создателя («модалка → карточка», STATUS §Открытые решения) — **жёстко не зашивается**; ниже поведение, не пиксели.

- **Видимость — по ветке данных вкладки «Поселения»** (решение создателя): вкладка появляется, когда у игрока есть знание о поселениях планеты — `presence`/`snapshot`/`scan` с `settlements_count > 0` (режимы орбитной спеки §5.1). `none` или `settlements_count == 0` — вкладки нет. **Одна ветка видимости с роутом** (§7.1): вкладка не показывается там, где `GET /market` вернул бы 404.
- **Содержимое** (лениво, `GET /api/planets/{id}/market` при открытии):
  - Заголовок раздела «Модули» (каркас «витрина с разделами» — раздел один).
  - Карточка предложения: имя модуля, тип, параметры (радиус 800 px / ёмкость +30 т / скорость 0.3 сек/px / глубина — поверхность), **цена в Cr** (числа с сервера, «один факт — одно место»).
  - **Выбор слота**: 3 ячейки (занят/пуст) — из `/me` (`ship_model.slots` + `equipment` + `ship_catalog`; паттерн раздела «Корабль», трюм §20.4). Занятая ячейка показывает модуль и выкуп: «выкуп старого: −1 500 Cr»; пустая — «без выкупа».
  - **Итоговая цена** пересчитывается при выборе слота (`price − tradein`).
  - Кнопка «Купить» → `POST /buy`; ошибки — тостом/подписью (403 «только с орбиты», 409 «недостаточно средств» и т.д.); успех — обновление ячейки слота.
  - **Лок кнопки на время запроса** (защита от двойного клика): после нажатия кнопка неактивна до ответа сервера; ответ приходит после блокировки строки (§7.2 п.0) — вторая попытка клиента не создаёт второй покупки по устаревшему состоянию.
- **Гейт**: при `can_trade == false` кнопка покупки неактивна, подпись «Магазин доступен только с орбиты планеты» (паттерн: управление покупки отчёта — только по `can_buy_report`, орбитная спека §5.3). Витрину (offers) при этом видно — смотреть можно, покупать нельзя.
- **`offers: []`** — «На планете нет рынка» (поселений нет по знанию — `settlements_count == 0`); 404 «Нет данных» — режим `none`, вкладка не показана вовсе.
- Баланс в витрине **не дублируется**: игрок видит счёт в шапке дашборда/карты (`money_ui`); «один факт — одно место».

## 12. Инварианты

- **И-М1 (сервер — источник истины).** Покупка проверяет и выполняет всё на сервере (присутствие, поселение, слот, счёт); клиентская отрисовка цены/выкупа — косметика (77a И1, орбитная спека И-С2).
- **И-М2 (гейт присутствия).** `can_trade` и покупка — только с орбиты планеты (инвариант 8 GD_PROMPT); удалённой покупки нет («контракт — единственный рычаг удалённого действия»).
- **И-М3 (печь, нет эмиссии).** Покупка не зачисляет деньги никому; выкуп — зачёт в оплату, не зачисление; итог `max(0, …)` — выкуп не даёт денег сверх цены.
- **И-М4 (списание атомарно).** Проверка и списание — одним `UPDATE` с условием `balance >= $amount` (инвариант 1, AGENTS.md §0); `withdrawable` пересчитывается тем же оператором (денежная спека §3.3).
- **И-М5 (модуль работает по типу из любого слота).** `RadarRadius`/`HasScanner`/`HasEngine` читают все значения `equipment`; радар не суммируется (максимум).
- **И-М6 (отсутствие ключа = пустой слот).** Пустые слоты — форма модели (`ship_models.slots`), не данные игрока (трюм §20.3); покупка в пустой слот пишет ключ, выкупа нет.
- **И-М7 (NPC — пол, не потолок).** Витрина не продаёт продвинутые модули (только 4 базовых); продвинутые — лабораторное производство (3b.6.3), задел вне v1.

## 13. Тесты

**Сервер (Go):**
- `GET market`: 4 offers с развёрнутым `item`; `can_trade` — true при орбите планеты, false вне её / на поверхности / для админа; **гейт знанием**: режим `none` → 404 (без `offers`/`can_trade`), знание есть и `settlements_count == 0` → 200 `offers: []`, знание есть и `settlements_count > 0` → 200 с каталогом (живость сейчас не проверяется и не раскрывается); 404 для несуществующей планеты.
- `POST buy` (успех): списание `amount = price − tradein`, установка в слот (`jsonb_set`), запись `money_operations` `kind='purchase'` с `balance_after`; пустой слот — полная цена; занятый — `floor(price/2)` зачёт; слот с модулем вне `market_offers` — выкуп 0.
- `POST buy` (отказы): 403 вне орбиты; 409 без живого поселения; 404 неверный `offer_id`; 400 невалидный слот (в т.ч. номер > `slots.universal`); 409 недостаточно средств (списание не прошло — `RowsAffected == 0`); `withdrawable` урезается (`min(withdrawable, balance_after)`).
- `RadarRadius`/`HasScanner`/`HasEngine`: модуль в `universal2` работает; два радара — максимум; без радара — 200 px (существующий фолбэк). **`EngineSpeed`**: двигатель в `universal*` даёт право полёта (`HasEngine`), скорость — из легаси-слота `engine` (чтение не меняется).
- Гонка: две параллельные покупки в один слот — блокировка строки игрока (§7.2 п.0) сериализует; вторая покупка видит **обновлённый слот** и считает выкуп старого корректно (не теряет трейд-ин).

**UI:** e2e-смоук вкладки «Магазин» (паттерн е2е карточки планеты): видимость по знанию о поселениях, карточки 4 модулей, выбор слота с пересчётом выкупа, кнопка неактивна при `can_trade == false`, успешная покупка обновляет ячейку.

## 16. Что не входит (границы)

- **Продвинутые модули** (`radar_2` и т.п.) — только лабораторное производство (3b.6.3 фабрик), задел вне v1; витрина продаёт 4 базовых (И-М7).
- **Per-планетный ассортимент/цены** — каталог общий; локальность — гейты знания и присутствия (развилка §4). Задел: `market_offers.planet_id`/привязка, если создатель захочет «разные планеты — разный рынок».
- **Свободная установка/снятие модулей** (интерфейс установки) — вне скоупа; магазин даёт только **заменяющий установщик** (покупка = установка в выбранный слот). Переставить купленный модуль между слотами без покупки нельзя (трюм §20.2: «когда появится интерфейс установки — ключи не меняются»).
- **Замена модулей в легаси-слотах** (`radar`/`scanner`/`engine`) — покупка ставит только в `universal*`; легаси-слоты — стартовая комплектация (77a §3.3).
- **Инвентарь игрока** — нет (решение создателя): модуль либо в слоте, либо ничего; выкупленный модуль исчезает (засчитан в оплату).
- **Рынок отчётов** (`can_buy_report`) — отдельная задача (`10_exploration.md` §10.3.4); эта спека его не проектирует.
- **Спутники** — поселений на спутниках нет (`settlements.planet_id` — только строки `planets`), поэтому **витрин на спутниках не бывает** (гейт знанием §7.1: `settlements_count` спутника = 0 → 200 `offers: []`; вкладка не показывается). **Задел:** если в будущем поселения на спутниках появятся — их рынки будут **browse-only** (`can_trade` — только для родительской планеты, орбитная спека §5.5).
- **Топливо, селектор корабля, вторая валюта, счёт поселению** — не вводятся (канон `14_money.md` §14.5.1; денежная спека §10).
