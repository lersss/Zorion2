## 2. Направления блока (чем различаются и во что обходятся)

### Направление A — «Полоса с порогом» (строка) — **рекомендую**

Каждая ячейка — строка: иконка + имя + справа состояние; под строкой — горизонтальная полоса `amount / cap` во всю ширину и мелкая мета «доля N%».

- **Чем отличается:** максимально близко к текущему языку (полосы `renderResources`, строки `settlementArithmeticHtml`); данные сканируются без наведения.
- **Цена:** ничего сверх токенов; тянет 5–8 ячеек без раскрывашек (у поселения сейчас реально 2 нужды + компоненты веток).

```
ВНУТРЕННЕЕ ХРАНИЛИЩЕ · занято 34% (340 / 1000)
● жизнь (голод/жажда)   ● производство (вход)
──────────────────────────────────────────────────────────
🖼  Очищенная вода   ◆жажда              388 / 400   не хватает 388
    [████░░░░░░░░░░░░░░░░░░]   заполнено 3% · доля 40%
🖼  Пища             ◆голод              240 / 300   полно?
    [███████████████░░░░░░░]   заполнено 80% · доля 30%
🖼  Вода неочищенная                      0 / 300     пусто
    [░░░░░░░░░░░░░░░░░░░░░░]  заполнено 0% · доля 30%
```

### Направление B — «Полка ячеек» (плитки)

Ряд компактных квадратных ячеек (как полка/стеллаж): иконка + **вертикальное** заполнение снизу вверх + линия порога. Числа — в тултипе по наведению.

- **Чем отличается:** буквально «ячейки хранилища», самая «красивая» подача, компактно.
- **Цена:** числа не видны без наведения (для «нехватки» это минус); длинные имена не помещаются; при >12 ячейках лента требует скролла/раскрывашки; читаемость 20 px иконок внутри плитки 40–48 px — риск каши.

### Направление C — «Гибрид»

Сверху лента-полка (B) как «картинка производства», под ней строки (A) с числами. Максимум «красиво + полезно».

- **Цена:** дублирование одних и тех же ячеек в двух видах (шум, «один факт — одно место»); кандидат на ЧК2г, когда `@uidesigner` возьмётся за разгрузку.

**Рекомендация:** старт — **A** (дёшево, в языке, сразу полезно). B/C — после гейта создателя, если хочется «полочного» вида.

## 3. Раскладка рекомендованного блока (A)

**Где:** в `branches.js → settlementCardHtml`, **отдельным блоком** после строки «Стадия» и блока «Арифметика», перед «Ветки». (Точный порядок — финально `@uidesigner`/ЧК2г; здесь предложение.)

**Структура (сверху вниз):**

1. **Шапка** (стиль заголовков секций): `ВНУТРЕННЕЕ ХРАНИЛИЩЕ · занято 34% (340 / 1000)`.
   Проценты — `amount_sum / size`. `size = 0` (легаси/не задано) → `порог не задан`, полос нет.
2. **Легенда вида нужды — один раз на блок** (не в каждой строке, чтобы не шуметь):
   `● жизнь (голод/жажда) · ● производство (вход)` — цветные точки.
3. **Ячейки** — строки, сортировка по срочности: сначала `population` с дефицитом, затем `production` с дефицитом, затем полные; внутри — по величине дефицита.

**Строка ячейки (поля и их смысл):**

| Элемент | Что показывает | Токен/вид |
|---|---|---|
| Иконка | товар (по `code`) или фолбэк-эмодзи | 20 px, `vertical-align:middle`, `margin-right:4px` |
| Имя | `position` | `#ddd` |
| Чип нужды | **только** у `population` — `◆ голод` / `◆ жажда` | чип стилем `structureChipHtml`, цвет жизни |
| Числа | `amount / cap` | `#ccc` / `#888` справа |
| Состояние | `полно` / `не хватает N` / `пусто` | цвет состояния (см. §4) |
| Полоса | `amount / cap` во всю ширину | трек `#2a2a4a`, заливка по виду нужды, высота 8 px, радиус 4 px |
| Мета под полосой | `заполнено N% · доля M%` | `#888`, `0.8rem` |

**Инварианты строки:** `0 ≤ amount`, `deficit = max(0, cap − amount)`, `fill% = amount/cap` (при `cap=0` строка без полосы и со «порог не задан»); переполнение (`amount > cap`) — заливка 100 %, состояние `полно` (без «перелива» визуально, чтобы не плодить четвёртый цвет).

### 3.1. Состояния (три, без новых сущностей)

| Состояние | Условие | Как выглядит |
|---|---|---|
| **Полно** | `deficit == 0` | состояние `✓ полно` зелёным `#4ade80`; заливка семантическая, у правого края тонкая зелёная кромка |
| **Недобор** | `0 < amount < cap` | состояние `не хватает N`; цвет текста по виду нужды |
| **Пусто** | `amount == 0` | состояние `пусто`; заливки нет, трек слегка тонирован; цвет по виду нужды (для `production` — приглушённый: простой, а не катастрофа) |

### 3.2. Как различить «нужду населения» и «нужду производства» без шума

- **Цвет (основной канал):** жизнь — тёплый янтарь, производство — холодная сталь (см. §4).
- **Чип** с подписью — **только у жизни** (`голод`/`жажда`); у производства чипа нет — его «нетревожность» и есть сигнал. Легенда сверху объясняет разницу один раз.
- Никаких вторых эмодзи/иконок рядом с именем — имя и так с иконкой товара.

### 3.3. Как уживается с перегруженным интерфейсом

- Блок **не плодит новых видов** — это тот же «заголовок секции + карточки + полосы», что уже в модалке.
- Строк мало по природе (нужды = эффекты (2) ∪ компоненты веток); сверх этого — ничего не рисуем.
- Сортировка по срочности прячет «полные» вниз.
- Полная разгрузка (раскрывашки, скрытие второстепенного, тултипы) — **ЧК2г** (`@uidesigner`), здесь не проектируется (граница механики §13).
- **Не дублировать:** сейчас `branches.js` рисует «Выход · остаток (осадок)» из буферов ветки. После ЧК2а буферы уходят в ячейки — остаток ветки в блоке хранилища и так виден; строку «остаток» в блоке ветки следует **убрать** (иначе один факт в двух местах). Это правка UI веток — отметить `@designer`/`@developer` при реализации.

## 5. Иконки товаров и сырья

### 5.1. Ключ ассета — `goods.code`

- Файл: `web/static/sprites/goods/<code>.png`, например `g_0018.png` (железо fe), `g_0131.png` (пища).
- Почему `code`, а не `name_norm`: имена кириллические, с пробелами и `/`; `code` — 6 символов `g_NNNN`, уникален, без NULL, стабилен при переносе между базами.
- URL на клиенте: `/static/sprites/goods/${encodeURIComponent(code)}.png`.
- **Требование к серверу (аддитивно, не моя зона):** в DTO ячейки (§8 механики) нужен `code` (или резолв по `good_id` через разовый реестр). Рекомендую **добавить `code` в ячейку** — одно поле, без нового эндпоинта. Это правка `@designer`/`@developer`, отмечаю как необходимое для иконок.

### 5.2. Формат, размер, стиль

| Параметр | Значение | Почему |

### 5.3. Фолбэк «нет иконки» (обязателен)

Цепочка, как у биомов (`data-biome-fallback`):
1. `<img src="/static/sprites/goods/<code>.png">` с `onerror`;
2. файла нет → **эмодзи категории** по `category_id` (карта на клиенте; для 6 категорий сырья — из `09_resources.md` §9.1.3: 🪨🌿⭐🔥💧💨; для категорий товаров без эмодзи — нейтральный `📦`);
3. категория неизвестна → `•`.

Пустой ячейки/дырки в UI быть не должно **никогда**. Хардкод списка id не нужен — фолбэк по ошибке загрузки.

## 8. Открытые вопросы на гейт создателя

1. **Направление блока:** A «Полоса с порогом» (рекомендую) / B «Полка ячеек» / C «Гибрид»? B и C дороже и рискованнее по читаемости.
2. **Стиль иконок:** «объект-значок» (рекомендую) — или ближе к биомам «мини-сцена»? Мини-сцена на 20 px в плотной строке рискует в кашу.
3. **Холст иконок:** 48×48 (паритет с биомами) — или 64×64 с заделом под крупные карточки (рынок/энциклопедия)?
4. **Объём первой пачки:** 31 иконка текущей цепочки сразу — или сначала 6 категорийных + пища/вода (8 шт) как разминка?
5. **`code` в DTO ячейки** — подтвердить аддитивное поле (иначе иконки требуют отдельного реестра).
6. **Заказ иконок:** запускать `@artist` пачкой 1 после гейта — или ждать выбранного направления (B/C меняют размер плитки, не размер иконки, но могут изменить плотность показа).
