## 1. Компоновка экрана (рекомендованная — «Навигационный планшет»)

**Направление A (рекомендую): полноэкранное поле + верхняя паспорт-полоса +
нижняя панель действий.** Портрет, mobile-first (ВК Mini Apps, осн. §6.7).

```
┌─ safe-area top ────────────────────────────────┐
│ [🛰 дальний] [G→M] [одиночная] [+5 400°C → +3 100°C] ⏷   ← паспорт (сворачивается)
│                                        [← На карту]     ← выход (тач-цель)
│              «Не хватает 2 маяков»                     ← статус-строка (центр)
│                                                        │
│        ┌──────────────────────────────────┐            │
│        │                                  │            │
│        │   ПОЛЕ [0,1]² (canvas, кодом)    │            │
│        │   СТАРТ ⚓ ──путь── ✦ ФИНИШ      │            │
│        │   маяки ● ● ●   ложные ○          │            │
│        │   зоны потери времени ≈           │            │
│        │                                  │            │
│        └──────────────────────────────────┘            │
│   [Маяки 2/4]   [≈ короче эталона]                     │ ← строка обратной связи
│   ┌──────────────┐  ┌───────────────────────┐          │
│   │ ↶ Точка назад │  │      Проложить         │          │ ← крупные кнопки
│   └──────────────┘  └───────────────────────┘          │
│              [ Заново ]                                │
└─ safe-area bottom ─────────────────────────────┘
```

**Элементы (сверху вниз):**

1. **Паспорт-полоса «характер маршрута»** (осн. §6.7). Компактная строка-чипы в
   верх-лево, **сворачивается** по тапу (по умолчанию свёрнута — не мешать полю):
   - **дальность** — качественно: «близкий / средний / дальний» (без чисел и без
     ETA: перевод `dist` в минуты запрещён решением 14, осн. §6.4);
   - **класс звёзд концов** — `G → K` + тип системы («одиночная/двойная/кратная»);
   - **температура концов — только °C** (перевод из K; решение 2026-09-18,
     осн. §5.1/§6.7): «+5 400 °C → +3 100 °C»;
   - **число/тип препятствий** из `field`: «Маяки 4 · Ложные 3 · Зоны 2»;
   - пояс системы назначения — **только если есть** (`visible=true`), чипом
     «Пояс в системе».
2. **Выход «← На карту»** — верх-право, крупная тач-цель (≥44 px). Доступна
   **всегда**, в любом состоянии (уход до отправки бесплатен, осн. §6.2).
3. **Статус-строка** (верх-центр, под паспортом) — единственная динамическая
   строка подсказки: «Ведите путь от СТАРТА к звёзде-ФИНИШУ», «Не хватает
   N маяков», «Путь не доходит до ФИНИШа», «Путь готов» (формулировки — §7).
4. **Поле** — полноэкранный `<canvas id="route-canvas">` под HUD. Координаты
   `[0,1]²` рисуются в **квадратную область 1:1**, отцентрованную в свободном
   месте (letterbox), фон-звёздное поле заполняет весь экран. Квадрат 1:1 —
   **сознательно** (не растягиваем нормализованное поле: искажение геометрии
   ломает восприятие «короче/дороже»; серверная оценка не зависит от вёрстки).
5. **Строка обратной связи** (над кнопками) — «Маяки 2/4» (счёт, task) и
   **грубый индикатор качества пути** (осн. §6.7): шкала-градусник без чисел,
   со словами «короче эталона / как эталон / длиннее эталона». **Никаких
   ETA/секунд/`q`/`bonus` до отправки** (решение 14).
6. **Панель действий** (низ, safe-area bottom): крупные кнопки
   **«↶ Точка назад»** и **«Проложить»** (primary, широкая) в ряд; **«Заново»**
   под ними (secondary, на всю ширину). Все три — тач-цели ≥44–52 px.

**Альтернативы (коротко).**
- **B — «кокпит снизу»**: паспорт и обратная связь — нижней карточкой над
  кнопками. Минус: нижняя треть — зона рисования пальцем, карточка перекрывает
  поле и путь; цена — отход от образца `belt.css`.
- **C — «минимализм»**: только поле + кнопки; паспорт по тапу из чипа. Минус:
  «характер маршрута» (обязательный по осн. §6.7) спрятан; хуже для обучаемости.

Ниже полностью спроектировано **A**; при выборе B/C переносятся только позиции
блоков, данные/состояния (§2–§4) не меняются.

**Гонка «состояние изменилось, пока открывал».** Кнопка «Ускорить» активна лишь
при `available=true`; между тапом и `offer` возможна смена сегмента (разворот 61a,
прибытие, чужая вкладка). Тогда `offer` → `409 {available:false, reason,…}`:
страница показывает оверлей-причину (§2) и **не даёт играть**, «На карту» ведёт
обратно. Поле/паспорт (`field`/`passport`) при `409` **не отдаются** (осн. §3.4) —
рисовать нечего, поэтому оверлей, а не «пустое поле».

## 3. Реактивность и ввод

### 3.1. Модель ввода — полилиния «точками» (тап/протяжка)

Оба ввода равнозначны (осн. §6.2): `Pointer Events`
(`pointerdown/pointermove/pointerup`), `touch-action:none` на канвасе.

- **Начало.** Первая точка обязана попасть в **радиус захвата СТАРТА**. Попала —
  первая вершина **притягивается ровно к СТАРТУ** (снимаем дрожание пальца и
  гарантируем серверно-валидный старт). Не попала — точка не ставится, статус
  «Начните путь от СТАРТА».
- **Продолжение.** Каждый тап/отпускание добавляет **вершину**. Пока палец на
  экране, от последней вершины к пальцу тянется **«свободная» линия** (бледная);
  зафиксированные сегменты — **ярче** (осн. §6.7).
- **Конец.** Последняя вершина в радиусе ФИНИША **притягивается к ФИНИШУ**.
- **Отмена точки.** «↶ Точка назад» убирает последнюю вершину (бесплатно,
  осн. §6.2). «Заново» очищает путь целиком (бесплатно).
- **Ограничения** (осн. §6.6): потолок числа точек; минимальный шаг; координаты
  `[0,1]`. Превышение — мягко: лишние точки не добавляются + тост «Слишком много
  точек пути». Точка вне `[0,1]²` клипуется к квадрату поля.

### 3.2. Рисование (что происходит на каждом шаге)

- **«Голова» пути** — маркер вершины под пальцем + «свободная» линия.
- **Захват маяка.** Как только зафиксированный или свободный сегмент входит в
  радиус маяка, маяк **вспыхивает** (быстрая пульсация), счётчик «Маяки k/N»
  растёт, статус-строка обновляется.
- **Ложный сигнал.** Визуально отличим от маяка (осн. §6.1/§6.7); заход в его
  радиус **ничего не даёт** и не «вспыхивает» — при захвате показываем короткий
  тост «Это ложный сигнал». Никакого штрафа (осн. §6.3).
- **Зона потери времени.** Сегмент внутри зоны **подсвечивается** (иной тон/край);
  всплывает качественный чип «дороже» у зоны. Точный множитель в UI **не
  выводим** — чтобы не давать численного оракула (осн. §6.4/§6.6).
- **Свободная линия** предупреждающе меняет тон над зоной (игрок видит, что
  проведённый здесь путь дороже), оставаясь без чисел.

### 3.3. Подсказка «не хватает N маяков»

Считаем по факту: `N = всего обязательных − захвачено`. Статус-строка показывает
первую невыполненную причину в порядке: (1) нет СТАРТА → (2) «Не хватает N
маяков» → (3) «Путь не доходит до ФИНИШа» → (4) «Путь готов». Знаменатель `N`
берём из `field.nodes` (тип `beacon`).

### 3.4. Активация «Проложить»

Кнопка активна **только** при одновременном: (1) путь начинается в СТАРТЕ,
(2) заканчивается в ФИНИШЕ, (3) захвачены **все** обязательные маяки,
(4) остаток ≥ `min_remaining_boost_s` (осн. §6.2 п.4, §3.4). Иначе — disabled +
объяснение. **Финальное слово — сервер** (осн. §6.6).

### 3.5. Грубая обратная связь «лучше/хуже эталона»

Клиент считает **приблизительную** оценку по серверным правилам (осн. §5.3/§6.6)
и показывает **только полосу без чисел** и слово:
«короче эталона» / «примерно как эталон» / «длиннее эталона» (решение 14, осн.
§6.4/§6.7). **Запрещено до отправки:** ETA, секунды, `q`, `bonus`, точная
`L_eff`. Полоса перерисовывается на каждое изменение пути (throttle по кадру —
без «дёрганья»).

### 3.6. Успех (после `POST /boost`)

1. **Импульс «ускорения»**: яркий световой фронт пробегает вдоль
   зафиксированного пути СТАРТ → ФИНИШ, путь «сжимается»/ускоряется, вспышка на
   ФИНИШе (осн. §6.7). Анимация кодовая, ~0.8–1.2 с.
2. **Оверлей-результат** (карточка поверх поля, поле остаётся видно):
   - заголовок **«Ускорение принято»**;
   - **качественный класс** из `quality` (пороги — **UI-слова, не механика**):
     `≥0.9` «Идеальный маршрут», `0.7–0.9` «Отличный маршрут», `0.5–0.7`
     «Хороший маршрут», `<0.5` «Маршрут проложен»;
   - **«Скорость перелёта +X %»** из `bonus` (после отправки число **разрешено**
     — решение 14 ограничивает только **до** отправки);
   - **новый прогресс**: полоса перелёта (короче) + «Осталось ~X» (можно как
     прогресс без точной секунды; число — из `remaining_s`);
   - кнопка **«Вернуться на карту»** (primary).
3. **Идемпотентность:** повторный тап после успеха игнорируется (`submitting`).

### 3.7. Бесплатные действия

Пока путь не отправлен: «Заново», «↶ Точка назад», «На карту», любое число
перерисовок — **бесплатны**, откат не тратится (осн. §6.2, О8). Откат тратится
**только** за успешно применённый полный маршрут.

### 3.8. Звук

Переиспользуем `web/static/js/ui/sound.js` (после `activateSound()`, как
`belt_main.js` §354): постановка точки, захват маяка (`ui_select`), пересечение
зоны (`ui_error`-тон, тише), успех (`ui_success`). Конкретный набор — пожелание
`@gdesigner`; в v1 достаточно существующих.

## 4. Навигация

- **Вход — только из панели полёта** при `available=true` (осн. §4.4): кнопка
  «Ускорить» открывает `web/route.html` **без параметров** (сервер выводит
  `offer` из текущего полёта; как `/belt.html?belt=…` — образец входа, но здесь
  параметр не нужен, т.к. полёт у игрока один). Прямой заход без полёта →
  `offer` = `no_flight` → оверлей-причина.
- **Выход — «← На карту» / «Вернуться на карту»**: `window.location.href='/map'`
  (образец `belt_main.js` `returnToMap`). Метку `sessionStorage` (как
  `beltReturn`) **не ставим** — попап системы не нужен.
- **Ожидаемый эффект после возврата** (зона разработчика, осн. §4.4): карта при
  загрузке заново читает `/me`, панель полёта показывает **новый**
  `start_time`/`duration` — **полоса короче**, а кнопка «Ускорить» — в состоянии
  «Ускорение уже действует» (`active=true`) до прибытия/смены цели. Клиент
  страницы игры этого не делает; описано как ожидаемое следствие.
- **Гонка** (§2): состояние изменилось, пока открывался → `offer` 409 →
  оверлей-причина + возврат. Старый `offer` после разворота сервер отвергнет
  (`fingerprint`, осн. §4.2) → тост «Маршрут изменился» + возврат.
- **Прибытие во время партии**: по истечении остатка (локальный таймер) —
  «Проложить» гаснет (§3.4); при явном submit сервер вернёт `too_short`/`no_flight`
  → оверлей-причина.
- **Смена цели/разворот во время партии**: сервер отвергнет submit
  (`fingerprint`) → тост + возврат на карту (ускорение сбрасывается, осн. §6.8).

## 5. Мобильные требования

- **Портрет, полноэкранный canvas** (`position:fixed; inset:0`), DPR-`resize()`
  как в `belt_main.js` (§53–59).
- **Safe-area**: `viewport-fit=cover` в `<meta viewport>`; отступы HUD/панели
  действий через `env(safe-area-inset-*)` (верх/низ/лево/право) — кнопки и
  паспорт не режутся «вырезом»/жестами.
- **Крупные тач-цели** ≥44–52 px: «Проложить», «Заново», «↶ Точка назад»,
  «На карту», чипы паспорта. `touch-action: manipulation` на кнопках (без
  двойного тап-зума), `user-select:none`.
- **Без hover**: активные состояния — `:active`/`:focus-visible`; никакая
  информация не доступна **только** по наведению (осн. §4.4).
- **Рисование тачем и мышью равнозначно** (Pointer Events), `touch-action:none`
  на канвасе — палец не скроллит страницу.
- **Поле 1:1** letterbox внутри свободной области; фон заполняет весь экран.
- **Производительность:** поле рисуется **кодом** (осн. §6.7); спрайты только
  для звезды/корабля/атмосферы/фактур маяков и зон; `preloadSprites()` до первого
  кадра (образец `belt_main.js`), фолбэк на кодовые фигуры при ошибке загрузки.
- **Паспорт-полоса свёрнута по умолчанию** — на узких экранах не съедает поле.

### 6.6. Критерий проверки (как создатель увидит результат)

1. **Мобильный флоу (390×844):** `/map` → начать межзвёздный перелёт → в
   `#flight-panel` кнопка «Ускорить» → `/route.html` открывается на весь экран;
   паспорт и поле в кадре, кнопки не под вырезом.
2. **Рисование:** путь ведётся тапом/протяжкой; маяки вспыхивают при захвате;
   «↶ Точка назад» и «Заново» работают и **не** тратят откат.
3. **Гейт «Проложить»:** активна только при СТАРТ+ФИНИШ+все маяки+остатке;
   иначе — объяснение в статус-строке.
4. **Нет утечки прогноза:** до отправки **нигде** нет секунд результата, `q`,
   `bonus`, ETA (проверить визуально).
5. **Успех:** после «Проложить» — импульс вдоль пути + результат; возврат на
   карту; полоса перелёта **короче**, кнопка «Ускорить» → «Ускорение уже
   действует».
6. **Состояния:** отдельно воспроизвести `already_active` (повтор в том же
   сегменте), `too_short` (короткий перелёт), `cooldown` (таймер), `no_flight`
   (прямой заход), гонку (разворот между тапом и `offer`).
7. **e2e-смоук** `tools/e2e/route-check.js` проходит (сценарий осн. §9, пп. 1–8).

### 6.7. Что не трогать (инварианты)

- **Карта, модалка системы, панель полёта** — как есть, кроме добавления кнопки
  «Ускорить» и её строки состояния. Таймер/полоса/`updateFlightPanel` логику
  **не менять**; интерполяцию и `Restore` не трогать.
- **Механику и числа не меняем:** `q`, `bonus`, `newRem`, пороги
  `min_remaining_offer_s`/`min_remaining_boost_s`, откат — на сервере; клиент
  **не считает награду** и не влияет на неё (осн. §5.3/§6.6).
- **Скрытые данные не показываем:** паспорт — только открытые данные; масса,
  возраст, регион — нет; пояс — только `visible=true` (осн. §5.1/§5.2).
- **Температура — только °C** (никаких K в UI; осн. §5.1/§6.7, решение 2026-09-18).
- **Никакого точного ETA/секунд/`q`/`bonus` до отправки** (решение 14); после —
  можно.
- **Течения (`current`) — вне v1** (осн. §6.1, О4): не рисуем, не упоминаем как
  доступное.
- **Одно активное ускорение на сегмент** (решение 18/И-9): UI не предлагает
  «ускорить ещё раз» на том же сегменте; повтор — только после смены цели.
- **Страницы `belt`/`surface`** и их JS/CSS — не трогаем.

### 1. Направление внешнего вида

Общее для всех: mobile-first, портрет, поле 1:1, код рисует поле/путь/узлы/зоны —
во всех направлениях это остаётся; различаются палитра, глубина, характер анимации и
роль спрайтов.

> **Решение создателя 2026-09-25:** выбрано **направление A**; палитра **разрешена**
> (выходим из «нуля новых цветов»), задача — «максимум красоты» в мобильном бюджете;
> спрайты набираются **пулами** со случайным выбором на запуск (наигрыш, §3.7).
> B/C оставлены ниже как история решения.

#### Направление A — «Навигационный планшет» (выбрано, доводим до максимума красоты)

Инструмент курса, а не аркада: глубокая тьма, тонкие светящиеся линии, точная сетка,
сдержанный неон; спрайты дают «настоящую» звезду, маяк, ЧД и туманность. **Красота
набирается светом и глубиной** (туманность, blend, bloom, параллакс), а не пестротой
игрового слоя — читаемость пути/узлов/опасности сохраняется (§3.1, правила читаемости).

- **Палитра:** база — существующие константы (фон/панели/текст/primary, §3.1);
  **добавлены атмосферные тона** — туманность (роза/пурпур/бирюза/индиго/фиолет),
  ореол ЧД, мягкое свечение гало. Новые тона живут **только** в фоне/туманности/свечении
  и не занимают зарезервированные цвета интерактива (путь, захват, опасность, успех).
- **Типографика:** `'Segoe UI', Roboto, system-ui` (как есть). Заголовок панели `1.3rem/600`,
  тело `0.95rem`, чипы `0.75rem`, подписи `0.8rem`; все числа — `font-variant-numeric:
  tabular-nums` (как `#flightTime`); метки чипов — верхний регистр с `letter-spacing:0.04em`.
  Новых шрифтов нет.
- **Глубина/свет:** 5 слоёв — (0) база + виньетка; (1) дальняя туманность (аддитивно,
  параллакс 0.1); (2) звёздное поле (0.15–0.2); (3) ближняя пыль/туманность (0.4);
  (4) поле 1.0 (узлы/зоны/путь) + HUD. **Источник света — звезда-ФИНИШ:** rim-light на
  корабле и маяках, свечение аддитивно, bloom — двойной отрисовкой (без convolution);
  у ЧД — тёмный ореол (свет «отсутствует», §3.3).
- **Анимация:** характер «прибор + дыхание космоса»: дрейф туманности 60–120 с, дыхание
  короны звезды, пульс маяка, вспышка захвата, нерегулярное мигание ложного, вращение
  зоны, световой фронт успеха (§3.4). Всё — трансформации/alpha, без шейдеров по кадру.
- **Ассеты:** **пулы** (звезда, ЧД, маяк, ложный сигнал, фактура зоны, фоновая
  туманность), спрайты **нейтральные** (luminance/grayscale), цвет/температура
  накладываются кодом (§3.7, §4).
- **Цена:** пулов немного (3–5 на тип, §3.7); часть кандидатов уже сгенерирована
  (тестовая пачка, §0); на мобилке дёшево — прелоад только выбранных вариантов,
  без тяжёлых эффектов (§3.6).

#### Направление B — «Живой космос» (киношный фотореализм)

Богатая туманность, объёмная звезда с короной, линзовые блики, сильный свет,
дрейф туманностей; «кадр из фильма».

- **Палитра:** база та же, но туманности — насыщеннее и фотореалистичнее, чем в A
  (в A новые тона уже разрешены, §3.1); B отличается не фактом новых цветов, а
  фотореалистичным рендером и плотностью слоёв.
- **Типографика:** как A, но кегли крупнее (тело `1rem`).
- **Глубина/свет:** 5–6 слоёв, туманности-спрайты, блики, сильный rim; HUD тонет на фоне.
- **Анимация:** богатая — дрейф облаков, вспышки, мерцание.
- **Ассеты:** 10–15 PNG (звезда с короной, 3–4 туманности, пыль, подсветка корабля,
  варианты зон), фотореалистичный рендер.
- **Цена:** самый дорогой по ассетам и ручной приёмке; тяжелее на слабых мобилках; риск
  конфликта с плоской картой; новые цвета. **Задел на будущий «премиум»-вид**, не v1.

#### Направление C — «Тактический чертёж» (монохром, ноль спрайтов)

Плоский сине-циановый план: сетка, скан-линии, всё кодом.

- **Палитра:** `#05070f` + `#38bdf8`/`#60a5fa` монохром, сетка.
- **Типографика:** моноширинный шрифт для цифр (новый шрифт — исключение).
- **Глубина/свет:** плоская, без спрайтов и тумана.
- **Анимация:** резкая, «прицельная» (сканы, штриховка).
- **Ассеты:** **0**.
- **Цена:** дёшево и стильно, но **не даёт «клёвых спрайтов»** — прямо не выполняет
  требование §5.1 и уходит от фотореалистичного корабля в кадре.

### 2. Решение (зафиксировано создателем)

**Направление A — «Навигационный планшет» + «максимум красоты» + пулы с наигрышем.**

Почему A: (1) совпадает с компоновкой `@uidesigner` («Навигационный планшет», §1) и
формулировкой §6.7 осн. спеки («читается как навигационный планшет»); (2) даёт спрайты
там, где они реально поднимают уровень, и оставляет кодом то, что дешевле кодом;
(3) переиспользует обкатанный конвейер `belt` (прелоад, фолбэк, параллакс). **Что
изменилось против итерации 1:** палитра **расширена** (снято «ноль новых цветов»),
добавлены **фоновая туманность** и **ЧД**, ассеты — **пулы** со случайным выбором
варианта на запуск («наигрыш»). B/C — история решения; B (киношный фотореализм) остаётся
заделом, отдельным решением.

### 3. Полный стиль (по выбранному направлению A, «максимум красоты»)

#### 3.1. Палитра

**Новое — атмосферные тона (только фон, туманность, свечение/ореол; правила ниже):**

| Роль | Значение | Где применяется |
|---|---|---|
| Туманность — эмиссия (роза) | `#e879a9` | тинт `nebula_bg` |
| Туманность — эмиссия (пурпур) | `#c026d3` | акцентное ядро туманности |
| Туманность — ионизация (бирюза) | `#22d3ee` | нити/кромки туманности |
| Туманность — глубина (индиго) | `#6366f1` | дальний слой |
| Туманность — фиолет | `#8b5cf6` | связка с `map.starColors.default` |
| Ореол ЧД (void halo) | `#3b0764` | тёмно-фиолетовое гало вокруг диска |
| Мягкое свечение (гало) | `#fff7ed` | тёплое гало звезды |
| Холодный ореол объектов | `#7dd3fc` | rim/свечение холодных объектов |

**Правила читаемости (новые тона не ломают игру):**

1. **Зарезервированные цвета интерактива неизменны** и не используются фоном/туманностью
   в полную силу: путь `#60a5fa`, захват `#fde047`/`#fde68a`, опасность/ложный `#ef4444`,
   успех `#4ade80`. Туманность этих тонов не берёт.
2. **Туманность — всегда полупрозрачный аддитивный слой** (alpha ≤0.35, `lighter`),
   тусклее игрового слоя; ни один кадр туманности не должен «пересвечивать» путь.
3. **Тест на читаемость (обязательный, §6):** кадр в градациях серого / при сниженной
   насыщенности — путь, узлы и опасность различимы; снимок не превращается в «кашу».
4. **Опасность отличается не только тоном,** но и формой/поведением: клубящаяся фактура,
   искажённая кромка, подсветка сегмента, чип «дороже» — работает и при слабом
   цветовосприятии.
5. **Цвет звезды по-прежнему из `map.starColors`** (один факт — одно место); новые тона
   звезду не перекрашивают.

#### 3.2. Типографика

Семейство — существующее `'Segoe UI', Roboto, system-ui, sans-serif`. Кегли: заголовок
панели `1.3rem` (как `.panel h2`), тело `0.95rem`, чипы `0.75rem`, подписи `0.8rem`.
Все счётчики/таймеры — `font-variant-numeric: tabular-nums`. Метки чипов — верхний
регистр, `letter-spacing:0.04em`. В спрайтах **текста нет** (температура и числа —
только HTML-текстом, °C).

#### 3.3. Глубина и свет

**Пять слоёв** (снизу вверх): (0) фон `#05070f` + виньетка `radial rgba(0,0,0,0.45)`;
(1) **дальняя туманность** — `nebula_bg`, аддитивно, alpha ≤0.35, параллакс 0.1;
(2) звёздное поле — код (tile + параллакс 0.15–0.2, как `belt`) + редкие «яркие» звёзды
с крестовым бликом; (3) **ближняя пыль/туманность** — второй `nebula_bg` (0.4) или
кодовая пыль; (4) поле 1.0 (узлы/зоны/путь) + HUD. Свет один — от звезды-ФИНИШ: rim-light
на корабле и маяках в её сторону (радиальный градиент в экранном пространстве, как rim в
`belt`), свечение аддитивно; bloom — **двойной отрисовкой** (alpha ~0.25, scale 1.4),
без полноэкранного размытия. У **ЧД** источник света инвертирован: тёмное ядро-пустота и
яркий диск, тёмно-фиолетовый ореол `#3b0764` — объекты вокруг неё **не** подсвечиваются.
Виньетка и лёгкая десатурация периферии дают «экран прибора». Сколько туманностей можно
держать одновременно — §3.6.

#### 3.4. Анимация (характер)

«Прибор + дыхание космоса»; всё — дешёвые трансформации/alpha, без шейдеров по кадру:

- **Туманность:** медленный дрейф/дыхание **60–120 с** (сдвиг transform ±2–3 %), без
  мерцания; вторая туманность движется с иной фазой (даёт глубину).
- **Звезда-ФИНИШ:** дыхание короны **3.5–4.5 с** (±8 %).
- **Маяк:** пульс-кольцо **1.6 с**; захват — вспышка **180 мс** + кольцо-разлёт **400 мс**.
- **Ложный сигнал:** **нерегулярное** приглушённое мигание **~1.2 с** (рваный ритм —
  визуальный признак «сломано»).
- **Опасная зона:** медленное вращение фактуры **20–30 с/об**.
- **ЧД:** медленное «дыхание» яркости диска **5–7 с**, без вспышек.
- **Путь:** фиксированные сегменты ярче свободной линии (см. §3.1); успех — один пробег
  светового фронта **0.8–1.2 с** + вспышка на ФИНИШе.
- **`prefers-reduced-motion: reduce`:** туманность и короны статичны, пульсов нет,
  успех — кроссфейд без разлёта.

#### 3.5. Что кодом, а что спрайтом

Спрайты — **по пулам** (§3.7); конкретный вариант выбирается случайно на запуск.
Спрайт **не несёт игровой истины**: радиус, стоимость, награда — только код.

| Элемент сцены | Код | Спрайт (пул) |
|---|---|---|
| Фон: звёздное поле, пыль, параллакс, виньетка, крестовые блики | **да** (по образцу `belt`) | — |
| Фон-глубина: туманности | позиция/масштаб/тинт/дрейф/alpha | `nebula_bg_01…03` |
| Поле 1:1: рамка, сетка/хайрлайны, letterbox | **да** | — |
| Радиусы захвата, кольца, пульсы, вспышки | **да** | — |
| Путь: фиксированные/свободные сегменты, «голова» | **да** | — |
| Узлы: ядро маяка / ложного сигнала | позиционирование, пульс, захват | `beacon_01…04` / `false_signal_01…04` |
| Зона потери времени: граница, искажение края, подсветка сегмента | **да** | фактура `hazard_cloud_01…03` внутри |
| ФИНИШ: ядро/лучи звезды | оттенок+температура (`map.starColors`), размер, glow | `star_core_01…05` (нейтральный luminance) |
| ФИНИШ-ЧД: диск/тьма | размер, ореол, дыхание яркости; **без яркого тинта** | `black_hole_01…03` |
| СТАРТ: корабль игрока | позиция, поворот, fallback-фигура | **переиспользуется** реестр корабля (`ship_sprites.js`) |

#### 3.6. Мобильный бюджет «максимума красоты»

Цель — красиво **и** без просадок на среднем телефоне (портрет 390×844). Что делаем и
что сознательно оставляем за бортом:

| Делаем (дёшево) | Не делаем (дорого) |
|---|---|
| ≤2 туманности на кадр, каждая ≤1024², статичные quads + дешёвый transform-дрейф | полноэкранный convolution-bloom / gaussian blur, DOF, motion-blur |
| bloom = двойная отрисовка (alpha 0.25, scale 1.4) | пост-обработка через framebuffer/shaders по кадру |
| аддитивный blend туманностей `globalCompositeOperation='lighter'` | многослойная объёмная дымка (5+ слоёв туманностей) |
| предзагрузка **только выбранных вариантов** (≤6 PNG) до первого кадра | предзагрузка всего пула (22 PNG) — лишняя память/время |
| DPR ≤2; canvas-размер = CSS-px × DPR, с потолком | текстуры 2048/4096, per-pixel шум/турбулентность |
| редкие «яркие» звёзды с бликом (линии кодом) | динамические линзовые блики и световые лучи от каждого источника |
| пулы 3–5 вариантов (конечная генерация) | десятки вариантов на тип (долгая генерация, необозримый наигрыш) |

Ориентир (не механика): стабильные кадры на бюджетном Android; при первых признаках
просадки — первым убираем вторую туманность и крестовые блики, красоту звезды/маяка
не трогаем.

#### 3.7. Пулы вариантов и режим наигрыша

**Зачем.** Создатель хочет «наигрыш»: при каждом запуске страница берёт **случайный**
вариант спрайта из пула, чтобы за несколько прогонов сравнить и выбрать лучший. Это
**режим отбора**, не прод: после выбора создателя выбор **замораживается** — по одному
значению на тип, и случайность в прод не идёт.

**Пулы (тип → число → чем различаются):**

| Тип | Вариантов | Чем различаются (кратко) |
|---|---|---|
| `star_core` (ядро звезды-ФИНИШ) | **5** | рисунок дифракционных лучей: 4 длинных тонких; 6 коротких + плотная корона; 8 лучей-звёздочка; 2 широких луча + мягкое гало; мягкая «туманная» без резких лучей. Все — белый luminance |
| `black_hole` (ФИНИШ-ЧД) | **3** | кольцо анфас + сильное линзирование (основа — S07); наклонный эллипс-диск + дуга; диск с узким джетом |
| `beacon` (обязательный маяк) | **4** | силуэт: тарелка + маячный огонь (B05); мачтовый прожектор; ферменная станция; кубический модуль с антеннами |
| `false_signal` (ложный) | **4** | характер поломки: надкушенная/треснувшая тарелка (F03); согнутая мачта с погасшим огнём; расколотый модуль без панели; обломок с искрящим повреждением |
| `hazard_cloud` (фактура опасной зоны) | **3** | характер тумана: клубящиеся вихри; диагональные пылевые полосы; волокнистые нити/спираль-вихрь |
| `nebula_bg` (фоновая туманность) | **3** | форма/масса: широкое облако; завеса-вуаль; нити/щупальца. Grayscale-alpha, тинт кодом из §3.1 |

**Обоснование размера пулов.** 3–5 на тип: (1) наигрыш обозрим — за 2–3 прогона
создатель видит всех кандидатов типа; (2) генерация конечна — одна пачка на тип (часть
уже есть, §0); (3) 22 PNG суммарно не бьют по памяти, т.к. прелоадится только выбранное.
Меньше 3 — «нет выбора»; больше 5 — долгая генерация и размытый наигрыш.

**Взаимозаменяемость (обязательна):** все варианты одного типа имеют **одинаковый
размер холста, один и тот же якорь** (объект центрирован), **прозрачный фон**, одинаковую
визуальную массу (вписан по длинной стороне, запас ≥6 % от края) и **не рисуют** кольца
захвата/радиусы (их рисует код по игровому радиусу). Случайная подмена варианта не
меняет композицию и не требует разной вёрстки.

**Заморозка (позже).** Когда создатель выберет победителя, в конфиге ассетов остаётся
**одно значение на тип** (индекс/имя файла); выбор-случайность отключается, страница
всегда берёт этот вариант. Детерминизм **игрового поля** (от seed) к пулам отношения
не имеет и не меняется (§7).

**Требования к подложке, якорю и масштабу (все ассеты; взаимозаменяемость §3.7):**

- RGBA PNG, **прозрачный фон**; объект **центрирован**, вписан по длинной стороне, запас

### 5. Интеграция (что увидеть в коде; структура — `@developer`)

- **Выбор варианта из пула — до прелоада:** на старте страницы для каждого типа берётся
  **случайный** вариант, затем прелоадятся **только выбранные** PNG (≤6) до первого кадра
  (образец `belt_render.js` `preloadSprites`); при ошибке загрузки любого — **фолбэк-фигура
  кодом**, сцена не падает (инвариант §5 спеки).
- **Случайность — только косметика:** выбор варианта спрайта; позиции/звёздное поле/пыль
  по-прежнему от seed (`belt`-приём). Поле игры от выбора спрайта не зависит.
- Цвет звезды — `getStarColor(spectral_class, star_type)`; температурный оттенок —
  `getStarShade(spectral_class, temperature, star_type)` из `map/utils.js` (не дублировать
  формулу); `black_hole` → пул `black_hole_*` без яркого тинта (тёмный ореол); прочая
  экзотика (`neutron`/`white_dwarf`/`protostar`) — пул `star_core_*` с тинтом/размером
  по типу.
- `beacon_*`/`false_signal_*` — спрайт-ядро + **код**: пульс/кольцо, счётчик захвата;
  радиус кольца = игровому радиусу захвата.
- `hazard_cloud_*` — фактура тинтуется холодным тоном, маскируется по границе зоны,
  медленно вращается; подсветка сегмента внутри — код.
- `nebula_bg_*` — 1–2 слоя аддитивно, alpha ≤0.35, тинт из палитры §3.1, дрейф
  transform-ом; вторая туманность — опция бюджета (§3.6).
- СТАРТ — `recolorShipSprite(ship_icon, ship_color)` + `shipDrawTransform`.
- **Новые тона — только из §3.1** и только слой фона/туманности/свечения; сетка/виньетка —
  alpha существующих; зарезервированные цвета интерактива не подменяются.
- **Заморозка:** после выбора создателя конфиг ассетов хранит **одно значение на тип**;
  код выбора должен уметь оба режима (случайный на запуск / фиксированный).

### 6. Критерий проверки (как создатель увидит результат)

1. **Мобильный вид (390×844):** `/route.html` на весь экран; фон читается «прибором»
   (глубина туманности/звёзд/пыли, виньетка); поле 1:1 в кадре, HUD не перекрывает спрайты.
2. **Режим наигрыша:** при **перезагрузке** страницы несколько раз подряд видны **разные**
   варианты спрайтов из пулов (§3.7) — но композиция, размеры, якоря и игровое поле
   **идентичны** (подмена не сдвигает вёрстку).
3. **Звезда-ФИНИШ:** для G, K, M, O, B и др. цвет совпадает со звездой той же системы
   **на карте** (общий `map.starColors`); при разной температуре внутри класса заметен
   сдвиг светимости; **звезда остаётся нейтральным luminance-спрайтом** (красится кодом).
4. **ЧД:** тёмное ядро с ярким диском/кольцом и тёмным ореолом, **не** «яркая звезда».
5. **СТАРТ:** виден спрайт корабля игрока (его форма/цвет); при отсутствии PNG —
   кодовая фигура, `pageerror` нет.
6. **Маяки:** «живые» (пульс), при захвате — вспышка и рост счётчика; **ложный сигнал
   явно отличим** (приглушён, иная форма/рваное мигание) под **любой** туманностью и не
   вспыхивает как маяк.
7. **Зона потери времени:** читается туманностью с мягким краем; сегмент внутри подсвечен;
   **никаких чисел-множителей** (решение 14).
8. **Читаемость:** на кадре с любой туманностью путь/узлы/опасность различимы; тест
   «в градациях серого» (§3.1, правило 3) проходит — сцена не «сливается в кашу».
9. **Путь:** фиксированные сегменты ярче свободной линии, «голова» видна; успех —
   импульс вдоль пути + вспышка на ФИНИШе.
10. **Прелоад:** выбранные ассеты готовы к первому кадру (нет подмены примитивов на глазах);
    при удалении любого PNG сцена работает на фолбэке.
11. **Производительность (§3.6):** на среднем телефоне нет просадок; память/число
    декодированных текстур в рамках бюджета (≤2 туманности, только выбранные варианты).
12. **`prefers-reduced-motion`:** непрерывных пульсаций и дрейфа нет.
13. **Заморозка (после решения создателя):** с фиксированным значением на тип страница
    при каждом запуске показывает один и тот же вариант.

### 7. Что не трогать (инварианты)

- **Палитры и страницы `belt`/`surface`/карты — как есть.** `route.css` — новый файл;
  в `map.css` меняется **только** кнопка «Ускорить» (§6.2 этой спеки). Новые атмосферные
  тона (§3.1) применяются **только** в фоне/туманности/свечении route; зарезервированные
  цвета интерактива не подменяются. Цвет звезды — из `map.starColors`.
- **Случайный выбор спрайта при каждом запуске — сознательный режим наигрыша**
  (решение создателя 2026-09-25), не прод. Он **замораживается** после выбора создателя:
  одно значение на тип, случайность в прод не идёт. Случайность касается **только**
  косметики (какой вариант пула нарисовать).
- **Детерминизм игрового поля (от seed) не трогаем:** поле/узлы/зоны — чистая функция
  seed (осн. §6.1); выбор спрайта на неё не влияет и не меняет `q`/награду.
- **Взаимозаменяемость пулов:** все варианты типа — один холст/один якорь/прозрачный фон/
  одинаковая визуальная масса; никакая вёрстка не зависит от варианта; кольца захвата/
  радиусы в PNG не рисуются (их рисует код).
- **Поле, узлы, зоны, путь, захват — код.** Спрайты **не несут игровую истину**
  (радиус/стоимость/награду); нет «визуального радиуса», расходящегося с логическим.
- **Спрайты нейтральны:** звезда/ЧД/туманность/фактура — grayscale; цвет/температура/тинт —
  только код.
- **Скрытые данные не рисуем:** масса/возраст звезды, регион — нет; пояс — только
  `visible=true` (осн. §5.1/§5.2).
- **Температура — только °C** (решение 2026-09-18), только текстом HUD; в спрайтах
  текста нет, оттенок — производная от температуры.
- **До отправки нет ETA/секунд/`q`/`bonus`** (решение 14); после — можно.
- **Течения (`current`) — вне v1**: не рисуем и не упоминаем как доступное.
- **Спрайт не выходит за канвас и не перекрывает HUD/тач-цели**; порядок слоёв
  фон → поле → путь → эффекты → HUD сохраняется.
- **Реестр корабля не дублируем:** СТАРТ — тот же спрайт, что в полёте/поясе.
- **Мобильный бюджет (§3.6) — граница красоты:** полноэкранных пост-эффектов, >2
  туманностей и текстур >1024 нет.
