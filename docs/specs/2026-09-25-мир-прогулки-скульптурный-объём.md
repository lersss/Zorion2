## 0. Одним абзацем

Сейчас земля — это `y = f(x)`: силуэт есть, объёма нет; настоящие арки, нависания, гроты и свод `пещерного_мира_с_потолком` невозможны (стоит заглушка — полоса `float`). Э5 переводит землю на **двумерное поле твёрдости** `solidAt(x,y)`, которое **одновременно** читают физика (коллизия игрока) и растеризатор чанка — это и есть гарантия «нет невидимых стен». Новые формы (`overhang`, `crack2d`, `void`, `crater`) выражаются в **существующей грамматике** рецепта вида (`BiomeDef.view`), валидируются сервером нефатально и включаются на **уже сданных** биомах-целях (`горы`, `каменные_пустоши`, `пещерный_мир_с_потолком`, `лавовые_поля`/`магмовый_океан`, `кратеры`). Свод строится **не вычитанием** (`void`), а **несущей аддитивной формой сверх поверхности** (плита-свод/арка), под которой `void` вырезает полость (§2.2). Якоря разведены: корабль/фауна/спавн читают **пол** `floorY`, погода — **верх** `skyTop` (§5 п.12). Э5 идёт тремя чекпоинтами, у каждого свой гейт.

## 1. Разворот подходов: как реализовать 2D-поле

Пять **разных классов**: A — столбцы-интервалы (run-length); B — плотное поле чанка; C — 1D-база + локальные 2D-наросты; D — SDF-скульптура (CSG над базой); E — поле плотности/твёрдости. Полное описание, таблица сравнения и разбор «почему не B / не E» — **приложение §A.1**.

**Принято: C как модель + A как контракт запроса/растеризации + D как реализация локальных форм.** Единая функция `solidAt(x,y)` (контракт), внутри — 1D-база и локальные 2D-операторы; растр и физика читают **одну** функцию; `columnSpans(x)` (класс A) — **гипотеза** производительности (§2.4). B не берём (память/перф: +3…12 МБ на мир), E отклонён (форма перестаёт быть рецептом).

## 2. Архитектура поля: один источник твёрдости

### 2.1. Контракт (главное)

```
solidAt(x, y) -> bool      // ЕДИНСТВЕННЫЙ источник твёрдости
skyTop(x)     -> y         // «поверхность неба»: min y, где solidAt(x,y)=true
floorY(x)     -> y         // «пол/опора»: верх твёрдого, СВЯЗАННОГО с базой (земля)
```

- **Физика:** `Player.solidAt(px,py)` вызывает `world.solidAt(px,py)`. Второй реализации коллизии нет.
- **Растр:** `getChunkCanvas` закрашивает **твёрдое тело** `{solidAt(x,y)=true}` с запасом ±1 px — допуск на дискретизацию, не разрешение расхождения.
- **Инвариант «что твёрдо — то видно» (по твёрдому телу).** Твёрдая точка обязана быть нарисована; нарисованное **твёрдое тело** не пропускает игрока. Инвариант §6 п.4 рецептов («растр — **надмножество** твёрдой области») **сохраняется**: растр может нести **косметику сверх** твёрдого тела.
- **Пещерная маска — часть твёрдого тела, не косметика (S1-bis).** `isCave` (2D-шум) **вычитает** твёрдое из `solidAt`; маска — проявление этого вычитания. Растр обязан быть **консервативен**: **не рисовать воздух там, где `solidAt=true`**; грубый блок 3×3 допустим только если весь блок — воздух (иначе блок «закрывает» твёрдую точку = «невидимая стена»); **на границе пещеры — выборка шагом 1 px** (как для форм, §2.3). Исключение маски из равенства запрещено — именно оно раньше разрешало под-покраску твёрдого.
- **Косметика — вне равенства (суженный перечень).** Исключены не-твёрдые слои: `viewOnly`-рябь (`viewHeight`), светлая кромка, снеговая полоса, глубинный градиент (рисуется **и внутри** канваса чанка — `source-atop` в `getChunkCanvas`, **и** отдельным экранным проходом `drawDepthGradient`; градиент лишь **тонирует** нарисованное, на равенство по твёрдому телу не влияет). Пещерная маска сюда **не входит**.
- **Декор и фильтр размещения (`where`/склон) остаются на `terrainHeight` — принятое косметическое ограничение (M11).** Под валом `crater`/несущей плитой декор может оказаться **скрыт в материале** — косметика, не дефект твёрдости. Перевод на `floorY` — кандидат-хвост (отдельный гейт: риск регрессии ЧК0–ЧК5).
- **`skyTop` / `floorY` / `surfaceY` (разведены).** `surfaceY(x)` — верх **отрисовки** (мин. физического и видового профиля, с косметикой). `skyTop(x)` — верх твёрдого поля (погода/осадки). `floorY(x)` — **опора** для корабля/фауны/спавна: верх твёрдого, **связанного с базой** (в терминах интервалов — верх интервала, содержащего базу; висящие плита-свод `arch=1` и полоса `float` в пол **не входят**; вскрывшие базу `void` опускают (`crack2d` — косметика, не опускает, §3.2); вал `crater`, связанный с землёй, поднимает). Для обычной колонки `floorY=terrainHeight` (корка первых 8 px твёрдая — `isCave` её не режет). Не взаимозаменяемы: якоря — §5 п.12.

Текущий `isSolid` — алиас `solidAt`; **раскладка растра меняется**: главный проход «залить твёрдые интервалы `solidAt`», а не «от `surfaceY` вниз» (§2.3).

### 2.2. Внутренняя раскладка

```
solidAt(x,y) = baseSolid(x,y) ⊕ forms(x,y)
```

- `baseSolid` — текущее поведение: `y ≥ terrainHeight(x)` без пещер; полоса `float` (`FLOAT_SPAN`/`FLOAT_GAP`).
- `forms` — операторы `relief2d` (Э5.2/Э5.3): **аддитивные (несущие)** — `overhang` (в т.ч. плита-свод `arch=1`), **вал `crater`**; **вычитающие** — `void`, **впадина `crater`**; **косметический (`viewOnly`)** — `crack2d` (в `solidAt` не входит, §3.2/§5 п.1). Порядок: аддитивные → вычитающие.
- **`crater` — одна запись, два знака (M9).** `{prim:"crater"}` даёт кольцо целиком: **вал** (аддитив, материал **над** поверхностью) + **впадина** (вычитающая). В бюджет вверх (§5 п.6) входит только вал `rim`.
- **Свод — только через несущую аддитивную форму.** Над `terrainHeight` — воздух, вычитать нечего. Над поверхностью ставится **несущая плита-свод** (`overhang arch=1`), а `void` вырезает полость **под ней** — плита есть **кровля** полости, а не «полость внутри плиты» (§3.2). `void` без несущей формы = пустота.
- **Пещеры** (`isCave`, 2D-шум) остаются отдельным слагаемым базы.
- В Э5.1 `forms` пуст — поле равно текущему миру 1:1.

### 2.3. Растр: как укладывается в существующий чанк

- **`CHUNK = 256`, `CHUNK_HEIGHT = 1700`, `CHUNK_TOP_MARGIN = 1200`** — не меняются (в спеке рецептов §6 п.8 устаревшее `700` — **дрейф**, дельта §B.2.2). Растр `(CHUNK+1)×CHUNK_HEIGHT` (нахлёст +1 колонка), `topY = baseY − CHUNK_TOP_MARGIN`; **низ** = `baseY + CHUNK_HEIGHT − CHUNK_TOP_MARGIN` = `baseY + 500` (§5 п.6). **`SS ≤ 2`** — не меняется; формы — в том же канвасе.
- **Главный проход:** залить твёрдые интервалы `columnSpans(x)` (быстрый путь) либо скан `solidAt` по y (медленный путь для задетых формой столбцов). Косметика — поверх, как сейчас.
- **Пещерная маска — консервативна.** Шаг 3 px — **только для полностью воздушных блоков**; **граница пещеры и задетые 2D-формой столбцы — шаг 1 px** (точное согласие по твёрдому телу). Столбцы без форм и без границы пещеры сохраняют шаг 3 px (нулевая регрессия ЧК0–ЧК5).
- **Аддитивные формы сверх поверхности** (плиты/своды, нависания) обязаны попадать в растр: столбцы под ними — «задетые» (шаг 1 px), иначе свод не нарисован (класс «невидимые стены»).
- **Полоса `float`** (Э5.1) — тот же скан `solidAt` (`fillFloatRun`), частный случай `forms`/`baseSolid`. **Порядок кадра** без изменений.

### 2.4. Цена и структура, снижающая стоимость (гипотеза к проверке)

**Честно:** наивный скан `solidAt` по `(CHUNK+1)·CHUNK_HEIGHT ≈ 437 000` точкам на чанк — **неприемлемо**. Предлагаемая структура: `columnSpans(x)` — аналитические интервалы; для столбцов **без форм** O(1), для задетых формой — O(длина фичи), а не O(`CHUNK_HEIGHT`). **Пометка: это гипотеза, а не факт** — Э5.1 обязан **замерить** (baseline до/после) и уложиться в бюджет (§5 п.7). Запасной ход: **кэш интервалов `columnSpans` на чанк**. Вариант «понижение `SS` до 1» **снят как невыполнимый** — `SS` задаёт размер всего канваса чанка.

### 2.5. Ключ чанк-кэша и память

- **Ключ не меняется** (индекс чанка): рецепт — **константа мира**, резолвится в `land` и фиксирован на сессию (инвариант §6 п.8 рецептов). **Сброс кэша** — по смене `SS` **и** по идентичности рецепта (`_viewKey` = `view_version` + хеш `relief`).
- **Память:** канвас чанка ≈7 МБ при `SS=2`; при `CHUNK_RADIUS=3` — ≈49 МБ. 2D-формы **не добавляют** плотного хранилища (класс C/A). **Вытеснение `_chunkCache`** (хвост: кэш не чистится) становится **обязательным** в Э5.1 (§5 п.8).

## 3. Данные рецепта: 2D-формы в существующей грамматике

### 3.1. Где живут формы

Новый ключ **`view.relief.forms[]`** — список `{prim, …params, where?}`, где `prim` обязан иметь `kind = "relief2d"`. Реестр `view_primitives` **уже несёт** `overhang`/`void`/`crack2d`/`floatband`; **`crater` отсутствует**.

**Стадия `crater` (решение создателя 2026-09-25, разведено):** **регистрация** `crater` → `kind="relief2d"` в **обеих** копиях справочника (`config/biome_catalog.json` + `internal/generator/planet/biome_catalog_seed.json`), счёт `relief2d` `4 → 5`, и **правка теста `32 → 33`** — **в Э5.2**; **применение** `crater` на биоме `кратеры` — **в Э5.3** (§3.4). Без регистрации рецепт `кратеры` уйдёт в фолбэк.

- **Правка теста — в ту же порцию (M6), Э5.2.** Жёсткие тесты реестра (`internal/generator/planet/biome_view_test.go`) требуют `require.Len(t, kinds, 32)`: с `crater` — **33** → обновить **оба** места (`TestBiomeViewPrimitivesRegistry` и ЧК5-проверку) на `33`; «4 поздних 2D» → «**5 поздних 2D**» (и «ЧК5: 32 примитива» → «33»). Регистрация без правки теста = красный тест.
- **Счёт в спеке рецептов** (§2.2/§3.5 — «4 поздних 2D») — дельта владельцу (§B.2.2).

**Правило слияния (ловушка):** `forms` — **список**, а список по §2.3 рецептов **перекрывается дельтой целиком** (как `horizon`). Если `forms` есть и в пресете семейства, и в дельте биома, дельта **затирает** пресетный список. Поэтому **на Э5 формы задаём только в дельтах биомов**, пресеты не трогаем.

### 3.2. Параметры примитивов (дизайн-предложение, px)

Числа — **гипотеза**; отношения/углы из §32.1 (§A.2). `[lo,hi]` разворачивается детерминированно от `seed`.

**`overhang`** — нависание/арка/козырёк/шляпа худу; **аддитивный (несущий)**: `perRegion [1,3]`; `w` (полуширина) `[40,160]`; `h` (**толщина плиты**) `[20,60]`; `reach` (вынос) `[30,120]`; **`arch` — категориальный флаг, фиксированное значение (M10):** `1` — замкнутая арка/**плита-свод**, `0` (или ключ отсутствует) — консоль/козырёк; **диапазоном `[0,1]` не задаётся** (свод требует строго `1`); `opening` (просвет под сводом) `[50,160]`; `taper` `[0,1]`; `dir ±1`; `where`.

**Вертикальное размещение плиты (S2-bis; знак исправлен в Э5.2).** В мире `y` растёт вниз, «выше» = меньше `y`; висящая плита-свод **висит над поверхностью**, а не уходит в породу (§2.1/§2.2/§5 п.12). Формула ниже — обязательная.
- **`arch=1`** (замкнутая арка / **плита-свод**): **низ (подошва) плиты** = `terrainHeight(x) − opening`; **верх плиты** = `terrainHeight(x) − opening − h`. `opening` — просвет между землёй и подошвой плиты. В **бюджет вверх** (§5 п.6) входит **`opening + h`**, а не только `h`/`reach` — иначе проверка пропустит свод за верх растра («невидимая стена»).
- **`arch=0`** (консоль/козырёк/шляпа худу): плита **крепится к рельефу** в опорной колонке `x₀` — её подошва = `terrainHeight(x₀)`; вынос `reach` идёт в сторону `dir`; под вынесенной частью — воздух (просвет = `terrainHeight(x₀) − terrainHeight(x)`), `taper` утоньшает плиту к свободному краю. Для **шляпы худу** опорной колонкой служит вершина 1D-`spike`: на колонке ножки `terrainHeight(x₀)` уже включает `spike`, поэтому шляпа садится на вершину **без нового якорного параметра**.
- **Просвет `opening` гарантирован диапазоном** `[50,160]` > роста игрока (28): при `opening` ниже порога рецепт применяется, админу — warning-сетка безопасности (§3.3), не ошибка.

**`void`** — каверна/грот/лавовая трубка/полость свода; **вычитающий**: `perRegion [1,2]`; `w [60,220]`; `h [50,400]`; `depth` (в породу) `[40,200]`; `shape` (`grotto`/`tube`/`dome`); `open` bool; `where`.
- **Полость свода — `dome` ПОД плитой, не внутри неё (S2-ter).** Плита (`h [20,60]`) — **кровля** полости; «вырезать полость внутри плиты» невыполнимо (полость `h [100,400]` > толщины плиты). Полость **вырезается из базы вверх до нижней грани плиты**, её **высота `h` отсчитывается от дна** (дно — на `depth` ниже поверхности, потолок — низ плиты). `void.h` (высота полости) и `overhang.h` (толщина плиты) — **разные величины**.
- **Диапазоны по формам — единый источник (здесь; §A.2 ссылается):** `grotto` — `w 60–220`, `h 50–180`; `tube` — `w 60–180`, `h 60–180`; `dome` — `w 120–220`, `h 100–400` (в сборочном своде `h` не свободна: `h = depth + opening` — верхняя оценка вилки; свободная `h` — для отдельно стоящих гротов).

**`crack2d`** — сквозная трещина; на Э5.2 — **косметическая (`viewOnly`)**: `perRegion [1,4]`; `w` (визуальная ширина у поверхности) `[6,40]`; `depth [80,400]`; `taper` (сужение вглубь — клин шире вверху) `[0,1]`; `tilt` (наклон, °) `[0,30]`; `where`.
- **Косметический слой, физику не трогает (решение менеджера 2026-09-25, по итогам @tester).** В растр рисуется **затемнение-клин** (та же геометрия `w`/`depth`/`taper`/`tilt`), но `solidAt`/`floorY`/`skyTop`/`columnSpans` он **не меняет** — это слой косметики (вне равенства по твёрдому телу, §2.1/§5 п.1). **Почему не вычитающая:** вычитающая сквозная трещина на реальном рельефе превращается в **воронку/наклонную ловушку** и **запирает игрока** (High от @tester: seed 1, старт x=892.5 — провал, макушка на 87 px ниже поверхности, выхода нет) — нарушение **жёсткого** инварианта §5.1 п.5 («нет новых застреваний»); кламп ширины не спасает. В 2D-виде сбоку тёмная косметическая расселина и «настоящая» трещина **визуально неотличимы**, но косметика физически безопасна. **Широкие разломы/провалы — `void`/`crater` (Э5.3), не `crack2d`.**

**`crater`** — кольцевой кратер/кальдера; **одна запись даёт вал и впадину (M9)**: `perRegion [0,1]`; `d [200,900]`; `depth` (≈ `d/5`) `[40,180]`; `rim` (вал, аддитив — в бюджет вверх) `[10,40]`; `wallDeg` (крутизна стенки, °) `[30,40]`; `talus` (осыпь) `[0,1]`; `where`.
**`crater` ↔ `carve`:** 1D `carve` — вырез **в профиле** (воронка/русло/каньон линейно вдоль `x`); `crater` — **2D-кольцо** с **выступающим валом** (материал над поверхностью), углами `wallDeg` и осыпью `talus`, допускает асимметрию/разрыв вала. **Когда что берём:** русло/каньон/одиночная воронка вдоль профиля — `carve` (1D, дешевле, уже есть); кольцевой вал/кальдера — `crater` (2D, Э5.3). Одну форму обоими **не дублируем**. Числа — гипотеза, уточняются на витрине Э5.3.

**`floatband`** — легаси-полоса `float` (`span 260`, `gap 48`); в Э5.1 остаётся скаляром `relief.float`, перевод в форму — отдельным шагом (не входит).

### 3.3. Валидация (серверная, нефатальная)

Расширение `validateView` (`biome_view.go`, §2.8 рецептов):
- **Ошибка** (рецепт не применяется, биом в фолбэк): `relief.forms[i].prim` отсутствует в `view_primitives` или `kind ≠ relief2d`; диапазон `[lo,hi]` пуст/перевёрнут; **выход за бюджет вертикали** (§5 п.6) с учётом форм.
- **Предупреждение** (рецепт применяется): `opening`/`gap` ≤ `PLAYER_H` (28) + запас. **Согласование (M8):** дизайн-диапазон `opening [50,160]` гарантирует `opening > PLAYER_H` **самим диапазоном** — на заводских рецептах warning недостижим и **не является проверкой обязательства**. «Обязан» снимается: просвет объявляется **гарантированным диапазоном**, warning — **сетка безопасности** для правок админа ниже порога (и для `gap`). Жёсткой проверкой не делается. `opening` относится к `arch=1`; у `arch=0` параметра `opening` нет — просвет под выносом производен от рельефа (§3.2), warning по нему не ставится.
- `declaredReliefTop` расширяется вверх **суммой по аддитивным несущим** формам: **`overhang`** — `arch=1` → **`opening + h`**, `arch=0` → **`h`** (верх плиты-козырька = `terrainHeight(x₀) − h`, подошва = `terrainHeight(x₀)`, §3.2); **`crater`** → `rim`. Сумма — **единая методология** с 1D-слоями (`rise` = `115·ridge + 40·(1−0.7·flatten) + Σ layerUpAmp`), консервативно. **`relief.scale` к формам НЕ применяется** (формы — абсолютные px; `scale` множит только 1D-базу и слои). **Вычитающие (`void`) и косметический (`crack2d`) вверх не поднимают**.
- **Бюджет вертикали — с двух сторон.** Верх: `topSolid(x) ≥ baseY − CHUNK_TOP_MARGIN + 24`. **Факт кода (M7, уточнено 2026-09-25):** Э5.1 (коммит `5a4a505`) **уже ввёл** `viewTopSafety = 24` и применяет его в серверной проверке (`declaredReliefTop ≥ baseY − CHUNK_TOP_MARGIN + viewTopSafety`); Э5.2 добавляет к проверке **амплитуды форм (суммой)**. Низ: `bottomSolid(x) ≤ baseY + CHUNK_HEIGHT − CHUNK_TOP_MARGIN − 24` = `baseY + 476`; зеркалится `declaredReliefBottom` (на будущее), проверяется T-budget.

### 3.4. Какие биомы получают формы и на каком чекпоинте

| ЧК | Биомы (точные `id`) | Формы | Пресеты |
|---|---|---|---|
| **Э5.1** | — (новых форм нет) | — | не трогаем |
| **Э5.2** | `горы` (арки, нависания, грибные башни), `каменные_пустоши` (нависания, тёмные разломы-косметика) | `overhang` (**`arch=1` — природные арки**; `arch=0` — нависания/козырьки/шляпы худу), `crack2d` (косметика) | не трогаем (формы — в дельтах биомов) |
| **Э5.3** | `пещерный_мир_с_потолком` (настоящий свод), `лавовые_поля`/`магмовый_океан` (лавовые трубки), `кратеры` (кольцевые кратеры/кальдеры) | `overhang arch=1` (плита-свод — на `пещерном_мире_с_потолком`) + `void dome` (полость **под** плитой), `void tube`, `crater` | не трогаем |

**Свод `пещерного_мира_с_потолком` собирается из посылок.** Витрина Э5.3 = (1) несущая **плита-свод** `overhang arch=1` над поверхностью (низ = `terrainHeight − opening`, верх = `terrainHeight − opening − h`, §3.2; в бюджет §5 п.6); (2) `void shape=dome` **под плитой** — полость/проход (плита — кровля, высота от дна); (3) `open` — вход. Без (1) форма (2) даёт пустоту. Контраст с прежней заглушкой-полосой `float`. **Плита-свод — только Э5.3;** на Э5.2 тот же `overhang arch=1` даёт **природные арки** на `горах` (§3.5).

**Замена заглушки `float` (Э5.3) — явно.** Пресет `экзотика` несёт `relief.float: true`; чтобы свод **заменил** полосу парящей породы, на Э5.3 в **дельте биома** `пещерный_мир_с_потолком` задаётся **`relief.float: false`** (пресет не трогаем). Иначе полоса `float` останется рядом со сводом, и «замены» не произойдёт.

**`crater` — стадия разведена (решение создателя 2026-09-25).** **Регистрация** `crater` в `view_primitives` (обе копии, счёт `4 → 5`) и правка теста `32 → 33` — **Э5.2** (§3.1); **применение** `crater` на биоме `кратеры` (запись в дельте биома) — **Э5.3**.

**Грибные башни** — композиция `spike` (ножка, 1D) + `overhang` (шляпа, `arch=0`, `taper`) — новых примитивов не требует.

**Правка уже введённого пресета** (`forms` в `горные`/`скальные пустоши`/`лавовые`) — **отдельный гейт** (§5 п.3 рецептов). Рекомендация: на Э5 пресеты **не трогать** — только дельты биомов.

**Изменение вида уже сданных биомов** вне целевого списка **не допускается**; `горы`/`каменные_пустоши`/`пещерный_мир_с_потолком`/`лавовые_поля`/`магмовый_океан`/`кратеры` — **явно целевые** (решение §32.2), их изменение и есть суть чекпоинта.

### 3.5. Конкретные `forms`-дельты Э5.2 (готовы к вставке)

> **Пометка по объёму (2026-09-25):** файл > 40 КБ — при следующей правке **одна полная запись файла** (не серия мелких `edit`). §3.5 оставлен в основной спеке: JSON нужен `@developer` 1:1.

**Куда.** В **дельты биомов** `горы` и `каменные_пустоши` — ключ `BiomeDef.view.relief.forms`, **в обеих копиях** справочника (`config/biome_catalog.json` + `internal/generator/planet/biome_catalog_seed.json`, §2.7 рецептов). **Пресеты `view_families` (`горные`, `скальные пустоши`) не трогаем**: `forms` — список, дельта затирает пресетный список целиком (§3.1). Остальные ключи `relief` (`layers`, `scale`, `float`, `ridge`…) в дельте не задаются — наследуются из пресета (слияние карт по ключам, `mergeViewMaps`).

**Числа — гипотеза Э5.2**, не эталон; диапазоны — §3.2. `[lo,hi]` разворачивается детерминированно от `seed` (§5 п.2).

**`горы`** — арки/плиты (`arch=1`), нависания/козырьки (`arch=0`), грибные башни (широкая шляпа `arch=0` на ножке 1D-`spike` из семейства):

```jsonc
"relief": {
  "forms": [
    // природные арки: замкнутая арка над землёй, гарантированный просвет opening
    { "prim": "overhang", "arch": 1, "perRegion": 2, "w": [80, 150], "h": [26, 50], "opening": [80, 150], "taper": [0.35, 0.65], "dir": 1 },
    // нависания/козырьки: консоль, крепится к рельефу, вынос reach, утоньшение taper
    { "prim": "overhang", "arch": 0, "perRegion": 2, "w": [50, 120], "h": [22, 46], "reach": [40, 110], "taper": [0.4, 0.75], "dir": -1 },
    // грибные башни: широкая шляпа (ножка — spike семейства), taper к краю
    { "prim": "overhang", "arch": 0, "perRegion": 1, "w": [90, 160], "h": [20, 40], "reach": [50, 120], "taper": [0.5, 0.8], "dir": 1 }
  ]
}
```

**`каменные_пустоши`** — нависания (`arch=0`) и тёмные разломы (`crack2d`, косметика):

```jsonc
"relief": {
  "forms": [
    // нависания-козырьки: консоль на рельефе
    { "prim": "overhang", "arch": 0, "perRegion": 2, "w": [50, 130], "h": [20, 44], "reach": [40, 110], "taper": [0.35, 0.7], "dir": 1 },
    // косметический тёмный разлом (viewOnly): клин шире вверху, наклон tilt — физику не трогает
    { "prim": "crack2d", "perRegion": 3, "w": [10, 34], "depth": [100, 360], "taper": [0.4, 0.8], "tilt": [4, 24] }
  ]
}
```

**Геометрия и правила (сводятся к §3.2).**
- **`arch=1` (природные арки `горы`).** Подошва плиты = `terrainHeight(x) − opening` (плита **висит** над землёй, §3.2); просвет `opening` гарантирован диапазоном `[50,160]` > роста игрока (28) → проход есть. В бюджет вверх — `opening + h`. **`arch=1` имеет два применения, разведённых по чекпоинтам:** на Э5.2 — **природные арки** `горы`; на Э5.3 — **плита-свод** `пещерного_мира_с_потолком` (кровля полости `void dome`, §3.4). Механика одна, различают их биом-дельта и наличие/отсутствие `void` под плитой.
- **`arch=0` (нависания/козырьки/шляпы).** Плита крепится к рельефу в опорной колонке `x₀` (подошва = `terrainHeight(x₀)`), вынос `reach`, `taper` к свободному краю (§3.2). Просвета-параметра нет — он производен от рельефа под выносом; гарантий прохода по диапазону `opening` **не даёт** (это нависание, не проход).
- **Грибные башни — композиция** ножки (1D `spike`, уже в семействе `горные`, `perRegion [1,3]`, `h [120,260]`) и широкой шляпы (`overhang arch=0`, `w [90,160]`, `taper` к краю). Новых примитивов не требует.
  **Осознанное ограничение Э5.2 (решение создателя 2026-09-25).** В грамматике **нет якорного ключа** «шляпа ← конкретная ножка `spike`» (у декора есть `hang.from`, у `overhang` — нет). Принят **вариант (а):** совпадение шляпы `overhang arch=0` с вершиной 1D-`spike` — **вероятностное** (стилизованный вид); отдельного ключа-якоря `from` на Э5.2 **не вводим**. Шляпа садится на `terrainHeight(x₀)` **своей** опорной колонки; на колонке, где стоит `spike`, `terrainHeight` уже включает ножку, и башня читается, но совпадение шляпы с ножкой **геометрией не гарантировано**. **Кандидат-хвост (не в объёме Э5.2):** ключ-якорь `from` (шляпа ← ножка) либо отдельный примитив «гриб» — только по отдельному решению создателя.
- **`crack2d` — косметика (решение менеджера 2026-09-25, по итогам @tester).** На Э5.2 `crack2d` — **косметический (`viewOnly`) тёмный разлом**: та же геометрия (`w`/`depth`/`taper`/`tilt`), но `solidAt`/`floorY`/`skyTop`/`columnSpans` он **не меняет** (§3.2). Причина: вычитающая сквозная трещина на реальном рельефе **запирает игрока** (High @tester: seed 1, x=892.5 — провал, макушка на 87 px ниже поверхности; нарушение жёсткого §5.1 п.5). **Кламп физического просвета снят** — больше не нужен. `w` дельты (`[10,34]`) — **визуальный** размах. **Широкие разломы/провалы — отдельные формы `void`/`crater` (Э5.3), не `crack2d`.** Кандидат-хвост (Э5.3/далее): **глубокие вычитающие разломы** с механикой (провал/выбирание) — **только отдельным решением создателя**.
- **Бюджет/валидация.** `declaredReliefTop` = **сумма по аддитивным несущим** формам: `arch=1` → `opening + h` (в дельте `горы` — до `150 + 50 = 200` px), `arch=0` → `h` (§3.3); **`relief.scale` к формам не применяется** (абсолютные px). Точная граница — T-budget (§3.3/§5 п.6), не арифметика на глаз. Битый `forms` уводит **один** биом в фолбэк (§3.3).

## 5. Инварианты и режимы отказа

1. **«Что твёрдо — то видно» — по твёрдому телу.** Растр несёт всё твёрдое тело `solidAt` (±1 px) и **косметику сверх** него (§6 п.4 рецептов «растр — надмножество»). **Пещерная маска — часть твёрдого тела** (не косметика): растр **консервативен** — не рисует воздух там, где `solidAt=true`; граница пещеры — шаг 1 px (§2.1/§2.3). Дефекты: твёрдая точка не нарисована («невидимая стена»); пройти сквозь нарисованное твёрдое тело. Косметика вне равенства: `viewOnly`-рябь, светлая кромка, снеговая полоса, глубинный градиент, **`crack2d`-разлом (косметический слой Э5.2, §3.2)**.
2. **Детерминизм.** Только `hash1`/`hash2`/`mulberry32`; `Math.random` запрещён. Формы размещаются по регионам как `primSpike` (соседние регионы `base−1…base+1`). «Камень медленный» (§32.2) — формы **статичны**, обвалов/анимации нет.
3. **Физика игрока не меняется по числам.** `PPM=40`, `w=12`, `h=28`, `WALK/SPRINT/JUMP_SPEED`, клип гравитации 0.2–2.5 — как есть. Меняется **форма земли**, не законы движения.
4. **Коллизия с объёмом (алгоритм, не числа).** Текущая коллизия точечная; с нависаниями/сводами нужна **угловая выборка** бокса 12×28 (4 угла + центр) для горизонтали и вертикали — иначе игрок «проткнёт» тонкий свод или застрянет. Скорости/гравитация не меняются. **Обязательный подпункт Э5.1**, проверяется e2e-смоуком под аркой и в гроте.
5. **Порядок кадра не меняется** (§6 п.1 рецептов). Формы — часть `drawTerrain` (запечены в чанк), новых слоёв нет.
6. **Бюджет вертикали (расширение).** `topSolid(x) ≥ baseY − CHUNK_TOP_MARGIN + 24` и `bottomSolid(x) ≤ baseY + CHUNK_HEIGHT − CHUNK_TOP_MARGIN − 24` = **`baseY + 476`** — низ совпадает с геометрией растра (§2.3), а не `baseY + CHUNK_HEIGHT`. `declaredReliefTop` учитывает **сумму по аддитивным несущим** формам — `overhang` (`arch=1` → `opening + h`; `arch=0` → `h`) и `crater.rim`; **`relief.scale` к формам не применяется** (абсолютные px); **вычитающие** (`void`) и **косметический** (`crack2d`) вверх не поднимают. Точная граница — T-budget.
7. **Бюджет отрисовки.** Ориентир ~600 отрисовок/кадр (LOD/кап декора **в коде не реализованы** — хвост 58; здесь не чиним). Формы **не добавляют** покадровых отрисовок (запечены в канвас), но удорожают **генерацию** чанка — бюджет замеряется (§B.1), ориентир ≤2× baseline (гипотеза).
8. **Память чанка и вытеснение.** Плотного хранилища нет; канвас ≈7 МБ при `SS=2`. `_chunkCache` **обязан вытесняться** (хвост эпика).
9. **Рецепт — константа мира.** Ключ чанк-кэша не меняется; сброс по `SS` и `_viewKey` (§2.5).
10. **`biome_color`/палитра — серверные.** Формы не пересчитывают цвет; `planet_image` **не затрагивается** — 2D-формы не видны с орбиты, бамп `ImageGenVersion` **не нужен**.
11. **Вода не вводится раньше ЧК6.** Гроты/трубки — без жидкости.
12. **Якоря разведены (S4).** Корабль на высадке, точки фауны и **спавн игрока** читают **`floorY(x)`** («пол/опора»), а не `skyTop`/`surfaceY`/`terrainHeight`: под висящей плитой `skyTop` = потолок, а `terrainHeight` игнорирует формы. **Приземные эффекты погоды читают `skyTop(x)`** («поверхность неба»). Косметика (`surfaceY`, `viewOnly`-рябь) якорем **не** является. Единый список — §5.1.6, §9 Д.12, §B.2.

### 5.1. Как ловится риск «невидимые стены» (тесты)

1. **Юнит на поле:** сетка `(x,y)` (несколько seed × биомы-цели), сравнение **по твёрдому телу** `rasterPainted ⇄ solidAt`; столбцы с формами **и границы пещер** — шаг 1 px; **косметика исключена** (§2.1).
2. **Юнит на бюджет:** `topSolid`/`bottomSolid` в границах растра (`baseY − CHUNK_TOP_MARGIN + 24` … `baseY + 476`) для всех рецептов с формами (T-budget).
3. **e2e-смоук прогулки:** проход под аркой, вход в грот, прыжок в потолок — 0 `pageerror`, нет застреваний, нет «прохода сквозь камень».
4. **Регрессия:** замороженный кадр ЧК0–ЧК5 до/после вне целевых биомов — **неизменность твёрдого поля/силуэта** (`solidAt`/`terrainHeight`); **косметическая дельта на границе пещер** (консервативный растр, шаг 1 px) **допустима** — замеряется и предъявляется числом (сколько px, только ли кромка).
5. **Стресс узких мест (M6):** на существующих биомах угловая коллизия **не создаёт новых застреваний/стен** — прогон узких щелей, полосы `float`, кромок пещер.
6. **Юнит на якоря:** корабль/фауна/спавн читают `floorY` (под нависанием — пол, не потолок и не `terrainHeight`/`surfaceY`); погода — `skyTop`. Список — §5 п.12.
