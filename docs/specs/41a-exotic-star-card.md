## 1. Цель и скоуп

Карточка звезды экзотики (`star_type ≠ 'star'`) показывает **честные физические
значения** по всем полям (температура, цвет, радиус, светимость, возраст) вместо
прочерков — спека 99.2.4 §8 обещала это («T=0 у ЧД без аккреции отображается как
«тёмная», не «0 K»»), до кода не дошло: `renderStarCard()` для экзотики ставит
«—» по всей спектральной инфо (`panel.js` строки 155–159). Дополнительно: возраст
системы хранится в `worlds.age` (витрина + наследование `system_age` планет
экзотики) — сейчас планеты экзотики роллят возраст независимо
(`determineSystemAge("")`, 2–10 млрд).

**В скоупе:**

- Миграция `000033` (`worlds.age`, млрд лет, nullable) + модель + INSERT +
  репозиторий + API `/api/worlds/{id}/planets` (возраст в ответе).
- Генератор: возраст остатков (ЧД/НЗ/WD) 2–13 млрд в `fillExoticWorld`;
  наследование возраста планетами экзотики (`buildExoticPlanet` берёт возраст из
  `WorldInfo`), фолбэк старых миров — ролл 2–13 (было 2–10).
- UI карточки звезды: таблица значений по типу (§5), ветка «аккреция» для ЧД,
  оформление «тёмная» вместо «0 K».
- Числа — строго из принятой спеки 99.2.4 §5.1 (не меняются).

**НЕ в скоупе:**

- Обычные звёзды и «прочая экзотика» (сверхгиганты O–B–A, `star_type='star'` +
  фаза I): возраст им НЕ пишется, карточка продолжает использовать фронтовый
  справочник `getSpectralInfo` по спектральному классу (решение создателя —
  «обычные звёзды не трогаем»).
- `disk_temp_range`/`disk_notes` из 99.2.4 §5.4 (атрибуты диска в `stellar_mods`):
  не вводятся этой фичей — см. §6 вариант (в); диск показывается по статическому
  диапазону спеки.
- Снапшот карты (`mapcache`): возраст не добавляется — карта его не показывает,
  модалка тянет свежие данные из API. Цвета/размеры карты экзотики уже работают
  (§8 99.2.4, `getStarShade` ветвится по `star_type` — T=0 безопасна).
- Админка (вкладка «Миры», статистика): возраст не выводится (пометка на
  будущее), группировка `planetsByStarType` уже есть (§7 99.2.4).

## 2. Природа сущности «возраст системы» (развилки дизайна)

Разбор по правилам дизайна до показа:

1. **Природа — атрибут существующей сущности (мира).** Возраст — это состояние
   объекта (сколько времени прошло с коллапса/формирования), а не происшествие и
   не лог. Логом стала бы история «как менялся возраст» — её нет и не нужно.
   → **колонка `worlds.age`**, как `temperature`/`stellar_mass`, не таблица.
2. **Владелец — один мир = одно значение.** Возраст — характеристика мира, не
   набора объектов; расширяемость «много владельцев» не требуется (в отличие от
   лога поселения). Единственная связь «вниз» — планеты экзотики наследуют его в
   `planets.data.system_age` (уже существующее поле JSON планеты).
3. **Расширяемость типов:** число типов объектов, которым нужен возраст,
   фиксировано моделью 99.2.4 §2 (`star_type`: 4 экзотических). Второй тип в ту
   же колонку кладётся без миграции (это float). Колонка переживает и новые
   типы остатков, и (потенциально) заполнение для обычных звёзд — схема не
   зажимается. Отдельная «таблица возрастов» не нужна: записей много, а читается
   возраст только в карточке и генератором планет.

**Единицы:** млрд лет, `DOUBLE PRECISION` (как `stellar_mass`), nullable. Старые
миры — NULL (бэкфилл не делаем — решение создателя по бэкфиллу логов действует
по духу: «если не было значения — его нет»; возраст — витрина).

## 4. Генератор: возраст экзотики и наследование

### 4.1. `fillExoticWorld` (`internal/generator/galaxy/galaxy.go`, строка 431)

В конце ветки (после `w.StellarMods = mods` — единый блок):

```go
switch category {
case "black_hole", "neutron", "white_dwarf":
    age := 2 + g.rng.Float64()*11 // 2–13 млрд лет (решение создателя 2026-09-15)
    w.Age = &age
case "protostar":
    // гейт-вопрос §8: предложение — молодой диапазон 0.001–0.01 млрд (1–10 млн лет)
}
```

Примечания:

- «2–13» = галактический максимум (потолок Вселенной 13.8; ~13 млрд — честный
  галактический предел, вердикт @scientist). 10 млрд в старой логике — не
  физический максимум, а потолок генератора (фиксировано в идее 41a).
- Равномерный ролл, не лог-uniform: возраст — витринная величина, вердикт
  @scientist — на генерацию планет не влияет; усложнение не оправдано.
- `case "exotic"` (сверхгиганты) и обычные звёзды: возраст НЕ заполняем
  (фронтовый справочник по классу — «Короткий (до 10 млн лет)» у O и т.д.).

### 4.2. Наследование: `buildExoticPlanet` (`internal/generator/planet/exotic.go`, строка 106)

`WorldInfo` (`planet_data.go` строка 98) получает поле `Age *float64`.

`buildExoticPlanet`: вместо `"system_age": determineSystemAge("", g.rng)`:

```go
"system_age": exoticSystemAge(w.Age, g.rng),
```

где `exoticSystemAge(age *float64, rng) float64`: если `age != nil` — вернуть
`*age`; иначе фолбэк `2 + rng.Float64()*11` (старые миры без возраста; решение
создателя «вместо 2–10» — 2–13). `determineSystemAge` не трогаем (обычные звёзды
покрыты своими ветками, default-ветка остаётся для прочих вызовов).

Заполнение `WorldInfo.Age`: в `admin_universe.go` (GeneratePlanets, строка 369) и
`admin_regenerate_planets.go` (строка 74) — `Age: w.Age`.

Протозвезда: планеты не генерируются (99.2.4 §5.3 — диск вместо планет),
наследование для неё не задействовано; возраст нужен только витрине.

## 5. UI: карточка звезды

### 5.1. Таблица значений по типам (числа — из 99.2.4 §5.1, вердикт @scientist)

| Поле | ЧД без аккреции | ЧД + аккреция (диск) | Нейтронная | WD | Протозвезда |
|---|---|---|---|---|---|
| **Температура** | «нет фотосферы (не излучает)» — НЕ «0 K», НЕ «−273 °C» | «диск: 10⁵–10⁷ K» (сама ЧД не излучает) | из данных: `N K` (10⁵–10⁶ K) | из данных: `N K` (5000–30000 K) | из данных: `N K` (3000–4000 K) |
| **Цвет** | «чёрный (тень)» | «голубовато-белый (диск)» | «голубой/белый» | «белый/серебристый» | «красно-оранжевый» |
| **Радиус** | «горизонт событий ≈ N км» (2.95 × M/M☉) | «горизонт событий ≈ N км» (2.95 × M/M☉) | «≈10–15 км» | «≈0.01 R☉ (≈7000 км)» | «порядка R☉ и больше (сжимается)» |
| **Светимость** | «нет (не излучает)» | «диск: 10²–10³ L☉» | «0.01–1 L☉» | «10⁻²–10⁻⁴ L☉» | «1–10² L☉» |
| **Возраст** | из `worlds.age` | из `worlds.age` | из `worlds.age` | из `worlds.age` | «молодая: ≈N млн лет» (гейт §8) |

Температура из данных: нейтронная/WD/протозвезда уже получают честную T от
генератора (§5.1 99.2.4) — карточка просто перестаёт их скрывать. ЧД — всегда 0
в данных; ветка по модам решает показ (§6).

### 5.2. Форматирование и фолбэки

- **Температура экзотики из данных** — только «K» без «°C» (для 10⁵–10⁶ K
  цельсий не имеет смысла); разделители тысяч: `temp.toLocaleString('ru-RU') + ' K'`.
  У обычных звёзд формат не меняем (там °C привычен).
- **Радиус горизонта ЧД:** `≈ ` + `Math.round(2.95 * stellarMass)` + ` км`
  (км, без дробей — формулы Шварцшильда хватает на целые км; «≈» — честная
  метка округления). Масса NULL → «—» (без массы радиус не вычислить).
- **Возраст:** `age >= 0.1` → `${age.toFixed(1)} млрд лет`; `age < 0.1` →
  `${Math.round(age * 1000)} млн лет` («молодая»). `age == null` (старые миры) →
  «—». Обычные звёзды — как сейчас, `getSpectralInfo` не трогаем.
- **Фолбэки:** все поля экзотики — строка из таблицы §5.1, статическая или из
  данных; единственный «—» — радиус ЧД без массы и возраст без данных. Прочерков
  «данные есть, а поле пустое» не остаётся (критерий готовности идеи).

## 6. Температура микроквазара — разворот подходов (гейт-вопрос 1 менеджеру)

Сейчас ЧД с `subtype accretion` получает `worlds.temperature = 0` — баг против
витринных обещаний 99.2.4 §5.1 («диск 10⁵–10⁷»). Три РАЗНЫХ класса решения:

- **(а) Хранить T диска в `worlds.temperature`** (10⁵–10⁷ K, INT помещается).
  Цена: меняется семантика колонки — «температура объекта» у ЧД становится
  «температурой диска»; 0 остаётся маркером «тёмная» (семантика двух значений в
  одной колонке); любые будущие потребители `worlds.temperature` (агрегаты,
  витрины) увидят 10⁷ у ЧД без контекста; аудит/статистика сейчас колонку не
  читают, но проверка на будущее дороже. Текучка: карточке всё равно нужна
  ветка (надпись «диск», не «температура звезды»).
- **(б) T остаётся 0 в данных; UI ветвится по `stellar_mods`** (рекомендация).
  Карточка: ЧД без аккреции — «нет фотосферы (не излучает)», ЧД+аккреция —
  «диск: 10⁵–10⁷ K» (статический диапазон §5.1). Цена: ноль — колонка не
  меняет смысл, диск — уже атрибут модов (`disk_state=accretion`, бейдж
  «микроквазар» показывается). Плюс: 99.2.4 §5.4 **уже решила** хранить
  диск-атрибуты в `stellar_mods` (`disk_state`, плановые `disk_temp_range`/
  `disk_notes`) — вариант (б) согласован с принятой спекой, (а) ей противоречит.
- **(в) Роллить и хранить `disk_temp_range` в `stellar_mods`** (развитие (б) по
  плану §5.4: генератор кладёт `disk_temp_range: [10⁵, 10⁷]` в JSONB, UI читает
  его, фолбэк — статический диапазон). Цена: диску по физике положен **градиент**
  (внутренний край ~10⁷, внешний ~10⁵ — у диска нет одной температуры), поэтому
  ролл одного значения не честнее статического диапазона из §5.1; добавка
  работы в генератор и в моды без игровой пользы (витрина). Отложить до
  полноценной сущности «диск» (там — да).

**Рекомендация: (б).** Решение — гейт-вопрос менеджеру/создателю (§8.1).

## 7. Консистентность, аудит, статистика (гейт-вопрос 5)

- **Аудит (42 правила):** не ломаем. Правила — планетные, читают `planets.data`;
  `worlds.temperature`/`worlds.age` в правила не входят. Планеты ЧД получают T от
  ветки (30–80 K, §5.3 99.2.4), а не от мира — проверено: `generateExoticPlanet`
  задаёт T сама, `generatePlanet` общего пути температуры мира не принимает.
  Новые правила не нужны: инвариант «system_age планеты = age мира» — свойство
  генератора, не данных (View аудита не имеет join на world), машинная проверка
  избыточна.
- **Статистика админки:** `admin_stats_load.go` читает явный список колонок
  (COALESCE спектра, star_type, system_type) — `age` не ломает; группировка по
  `star_type` уже есть (§7 99.2.4). Агрегатов по температуре миров нет — при
  реализации перепроверить (быстрый grep по `aggregator.go`), но изменения не
  планируются.
- **Карта:** `getStarShade` ветвится по `starType` раньше температуры (строки
  30–32 `web/static/js/map/utils.js`) — T=0 у ЧД безопасна, не трогаем.
- **«ЧД как Солнце»** (fallback L=1.0) нигде не появляется (99.2.4 §5 правило
  №1) — наши правки общий путь не касаются.

### 8.2. Возраст протозвезды — уточнение решения «2–13»

Решение создателя «диапазон генератора 2–13 млрд лет» принято в контексте
остатков (ЧД Iffaegan; «потолок генератора»). Вердикт @scientist (создателем
одобрен) для протозвезды: **возраст тысячи–миллионы лет** — протозвезда по
определению молода (до-ГП фаза). Буквальное «13 млрд» у протозвезды — физический
абсурд, противоречащий самому духу фичи «честные значения».

- **Вариант А (рекомендация):** «2–13» применяется к остаткам (ЧД/НЗ/WD);
  протозвезда — молодой диапазон **0.001–0.01 млрд лет (1–10 млн лет)**,
  карточка: «молодая: ≈N млн лет». Это не отмена эталона, а раскрытие его
  скоупа: создатель решал про потолок остатков; протозвезда — не остаток.
- **Вариант Б:** «2–13» для всей экзотики включая протозвезду (буквально по
  решению). Цена: карточка покажет «13 млрд лет» у протозвезды — ложь против
  вердикта учёного, иронично именно в фиче «честные значения». Не рекомендую.
