## 1. Скоуп и что это за спека

Скоуп релиза (решение создателя, 94а аспект 1, вариант А): **каталог базового слоя + таблица потребления рас**. Механика потребления в этой итерации — только данные, поселения реально не потребляют («Пока так»). Выход: ГДД → спека → БД; данная спека — результат первых двух шагов (ГДД-уровень + спека).

**Почему новая спека, а не расширение `99.2.5-resource-model.md`:** `99.2.5` — спека блока (порядок работ, разделение ресурс/месторождение, схема таблиц). Настоящая спека — данные фичи внутри блока: таблица потребления, каталог, развод реестров, теневой товар T1. Разные уровни и разные читатели; правило «один блок — один файл» не нарушается (файл фичи именуется по номеру идеи, как `41a-exotic-star-card.md`, `80a-salt-races-rework.md`, `91a-ship-section-dashboard.md`).

**Границы (НЕ входит):** deposits, симуляция потребления, UI; старый генератор и `PlanetResource` не ломаются (новая модель рядом, 52а §0.5); роботы 51–60 (последняя очередь); проектирование T2 (развилка 1а/1б отложена); поля «дом+радиус», сводка богатства, фильтр карты; «до чего поселение дотягивается при добыче»; миграции БД (схема БД в этой итерации — только логическая, §10).

**Терминология (решения создателя, пронесена в эту спеку):** «потребляет» (не «корм/ест»); «потребительская корзина» = «корзина тира»; для T1 корзина — практически только ресурсы без переработки, только добычи; «ресурс» (не «вещество»); тиров МНОГО, потолка «тир 3» нет.

## 2. Два реестра окон и их развод

Подтверждено создателем (94а аспект 9): окна потребления рас и окна требований товаров — **два разных реестра**. Слой закрывает физиологию рас, но НЕ окна товаров (правило неполноты §9.2.7 — несущее, живо).

### 2.1. Реестр 1 — потребление рас (полный, слой его закрывает)

| Свойство | Значение |
|---|---|
| Владелец | Расы (50 биологических). Роботы 51–60 — отдельный слой `robotic`, не в этой итерации |
| Формат | Раса → потребности → окна по осям свойств (тот же язык, что у товаров §5.2.2) |
| Источник истины | `consumption` (13 осей) из `config/races.json` + лор рас (`22_races.md`) |
| Полнота | Каждая потребность каждой расы покрыта ≥ 1 ресурсом каталога (критерий «все накормлены», §8) |
| Природа сущности | **Данные-записи** (лог/результат-состояние), не событие. Владелец — у многих (у каждой расы свой набор) → схема записей с типами (раса → потребность), а не атрибуты расы: у расы 3–5 потребностей, и вторая потребность обязана влезть в ту же схему (расширяемость) |

### 2.2. Реестр 2 — требования товаров (дырявый, слой его НЕ закрывает)

| Свойство | Значение |
|---|---|
| Владелец | Товары §5.2.1 (13, список открыт) |
| Формат | Уже существует: §5.2.2 «профиль категории» (требования + предпочтения) |
| Дырявость | Намеренная (неполнота §9.2.7). Слой не должен закрывать эти окна на приемлемом качестве |
| Статус | Остаётся как есть; в этой итерации не трогается, кроме фиксации развода (§2.3) |

### 2.3. Развод

- **Разные владельцы** (расы vs товары), **разные цели** (физиология vs производство), **разные требования полноты** (полный vs дырявый).
- **Один язык** (окна по осям свойств) — это общий язык, а не общий реестр. Запись «окно потребления расы» и запись «окно требований товара» — разные записи в разных таблицах.
- **Слой проектируется ТОЛЬКО против реестра 1.** Реестр 2 используется как **негативное ограничение**: ни один ресурс каталога не должен закрывать товарное окно на приемлемом качестве (посредственность, §8).
- Продовольствие: товарное продовольствие в каталог НЕ входит (§9.2.2, `13_settlements.md` §13.5) — полом служит подножный корм. Потребление расы — это её ресурсы-«еда», но это НЕ товарное продовольствие номенклатуры.

## 3. Мост: consumption (13 химосей) → окна по осям свойств

Белое пятно из 94а («мост») — механизм перевода. Проектируется честно, в четыре шага.

### 3.1. Шаг 1: шаблоны хемотипов (13 строк, ручная работа из физической химии)

Каждая из 13 consumption-осей получает **шаблон** — канонический профиль ресурса-«еды» этого хемотипа: окно `T_melt`, окно `T_boil`, окна по 2–4 релевантным осям свойств (не по всем 10), уместные категории. Числа окон опираются на **эталон — физику** (реальные температуры плавления/кипения веществ-растворителей), расширенные до разумного допуска (±15–25 K: раса ест не чистый реагент, а смеси/растворы/льды). Источник чисел назван: физика; отклонение от точки вещества — осознанное расширение окна.

| Ось | Смысл (что ест раса) | T_melt, K | T_boil, K | Оси свойств (окна) | Категории |
|---|---|---|---|---|---|
| ВОД | жидкая вода, растворы | 250–280 | 350–400 | биосовместимость 60–100, токсичность 0–30 | 💧 |
| АММ | жидкий аммиак | 185–210 | 230–250 | химическая активность 30–60, токсичность 40–80 | 💧 |
| МЕТ | жидкий метан | 85–100 | 105–120 | горючесть 60–100, энергоёмкость 60–100 | 💧 |
| CO2 | CO₂-льды, сублимация | 190–200 | 185–195 | химическая активность 20–50 (сублимирующий, §5) | 💨 |
| СЕР | сера, сероводородные источники | 380–420 | 700–750 | химическая активность 30–60, токсичность 40–80 | 🪨 |
| РАС | расплавы солей (эвтектики) | 500–900 | 1500–2500 | токсичность 50–90, биосовместимость 0–30 | 🪨 |
| СКФ | сверхкритические флюиды | 280–295 | 305–320 | плотность 0–20, химическая активность 30–60 | 💨 |
| КРЕ | кремний, силикаты | 1600–1800 | 3000–4000 | твёрдость 60–100, плотность 40–70 | 🪨 |
| ОРГ | органика, биосфера | 250–350 | 400–600 | биосовместимость 60–100, эластичность 30–70 | 🌿 |
| ГРД | терморедоксные градиенты | — (любая в окне расы) | — | химическая активность 60–100, энергоёмкость 40–80 | 🔥 |
| ВГЕ | водород, атмосферы гигантов | 10–15 | 20–30 | плотность 0–10, горючесть 55–75, энергоёмкость 55–75 | 💨 |
| ПЫЛ | пыль, реголит | — | — | твёрдость 0–30, плотность 0–30, биосовместимость 0–40 | 🪨 |
| ИЗЛ | излучение (радиоактивные материалы) | — | — | радиоактивность 60–100, токсичность 40–80 | ⭐ |

Примечания к шаблонам:
- **ГРД, ПЫЛ, ИЗЛ** — не «вещества-растворители»: ГРД — источник энергии (редокс-потенциал), ПЫЛ — субстрат, ИЗЛ — излучение. Для них температурные окна не задаются (пища в любой фазе в окне обитания расы), а «еда» — это материал с нужным профилем (высокая химическая активность / низкая твёрдость и плотность / высокая радиоактивность).
- **T_melt/T_boil входят в окна потребления только как жёсткие интервалы** (требования), никогда как взвешенное предпочтение — то же правило, что для товаров (§9.1.2). Фаза пищи при температуре обитания расы критична.
- **Конвенция фазы:** для всех ресурсов T_melt < T_boil с зазором ≥ 5 K, кроме объявленных сублимирующими (T_boil ≤ T_melt, §4 уточнение 1). Для сверхкритических ресурсов T_melt/T_boil задаются вокруг критической точки (CO₂ ~304 K) с зазором; фаза при T > T_boil — газоподобная (сверхкритическая). Диапазоны шаблонов не должны соприкасаться вплотную (иначе реализация может дать melt ≥ boil).
- **ВГЕ-окно занижено намеренно (55–75 вместо 80–100):** расы едят водород-БОГАТЫЕ аэрозоли/смеси (H₂/He/CH₄/NH₃, `22_races.md` §3.7), а не чистый H₂. Чистый водород (горючесть/энергоёмкость ≥ 80) — ресурс полей и очищенное топливо, а не еда универсального слоя. Занижение держит неполноту §9.2.7 числами: ресурс не закрывает товар «Топливо» (порог ≥ 70, §5.2.3).

### 3.2. Шаг 2: вывод окон расы (механический, не ручной)

Для каждой расы из её `consumption`-вектора:
1. Каждая ось с весом > 0 наследует шаблон §3.1.
2. **Окно расы по каждой оси свойств = объединение окон шаблонов её потребляемых осей.** T_melt/T_boil — объединение интервалов шаблонов.
3. **Вес оси задаёт долю диеты, а не ширину окна.** Ширину задаёт шаблон; устойчивость расы (`resilience`) — мягкий множитель ширины (устойчивые едят чуть шире; величина балансная, дефолт ×1.0, диапазон 0.9–1.15 — предположение дизайнера, проверит @balancetester).
4. Потребность расы = **набор независимых окон** (по одному на ось потребления), а не одно окно. Раса ест смесь: вода-подобное (60 %), органика (30 %), CO₂-подобное (5 %), градиенты (5 %).

### 3.3. Шаг 3: корреляция с условиями обитания (инвариант)

Окно T_melt/T_boil пищи должно быть **совместно с температурным окном расы** (`conditions.temperature` из `config/races.json`): существует пересечение — пища хотя бы в части окна обитания находится в нужной фазе.

**Ограничение модели, названное явно:** правило фазы (§9.1.2) — только по T, без давления. Окна рас включают P (`conditions.pressure`), и реальная фаза при высоком P расходится с T-правилом (аммиак при высоком P остаётся жидким и при T > 240 K). Модель это не держит; игроку обещается ровно то, что держит модель (фаза по T), расхождение с P — известное ограничение, не баг.

Примеры (точные):
- **Аммиачники** (T 196–255 K) и аммиак-ресурс (T_melt 198, T_boil 240): пересечение [196, 240] ≠ ∅ — в нижней части окна пища жидкая; в верхней (240–255 K) по T-правилу — газ (по реальности при P — жидкость; ограничение модели выше).
- **Ледяные пастухи** (T 155–225 K) и CO₂-лёд (точечный профиль №4: T_melt 196, T_boil 189, сублимация): твёрдая фаза при T < 189 K — пересечение [155, 189] ≠ ∅; в opt-зоне 170–210 K пища твёрдая только до 189 K, выше — газ/сублимация (раса ест лёд там, где он есть, и газ — где нет; фаза по T без P).

Для рас с узким T-окном это жёстко связывает пищу с домом; для широких (роботы — вне скоупа) — слабее.

### 3.4. Шаг 4: генераторы-помощники (как помогают творческой ручной работе)

Потребности — творческая ручная работа из лора (94а белое пятно). Генераторы помогают четырьмя проверяемыми функциями, а не творчеством:

1. **Проверка полноты** — автоматическая сверка каталога с окнами всех 50 рас: «все накормлены» (критерий §8.1).
2. **Поиск дыр** — список непокрытых (раса, ось, вес): куда добавить ресурс или мостовой.
3. **Черновики профилей** — кандидаты-профили в окне шаблона для ручной доводки (дизайнер принимает/правит; финальные профили — фиксированные, предустановленные).
4. **Проверка посредственности** — каталог не закрывает товарные окна §5.2.2 (критерий §8.2).

## 4. Оси свойств: пересмотр под специфику рас

Окно возможностей до заморозки (94а аспект 13). Анализ: все 13 consumption-осей отображаются на 10 осей + T_melt/T_boil (ВОД→биосовместимость/токсичность/T; АММ→хим.активность/токсичность/T; МЕТ→горючесть/энергоёмкость/T; CO2→хим.активность/T; СЕР→хим.активность/токсичность/T; РАС→T_melt/токсичность; СКФ→T/плотность; КРЕ→твёрдость/T_melt; ОРГ→биосовместимость/эластичность; ГРД→хим.активность; ВГЕ→горючесть/энергоёмкость/плотность; ПЫЛ→твёрдость/плотность; ИЗЛ→радиоактивность). **Новые оси НЕ требуются.** Но специфика рас требует двух уточнений модели:

**Уточнение 1 — сублимация (предложение изменения инварианта §9.1.2).** Пища CO₂-едоков (ледяные пастухи, сублиматоры, крио-кораллы) — CO₂-лёд, который сублимирует: T_boil < T_melt (при 1 атм сублимация ~195 K, тройная точка 216.6 K). Инвариант «T_melt < T_boil по построению» для сублимирующих ресурсов не выполняется. **Предложение:** разрешить T_boil ≤ T_melt и расширить правило фазы (§9.1.2): T < min(T_melt, T_boil) → твёрдое; между → газ (сублимация, жидкой фазы нет); > max → газ. Это реальное изменение модели, вызванное спецификой рас — попадает в окно возможностей до заморозки. **Гейт-вопрос §11.1.**

**Уточнение 2 — пер-расовая семантика осей.** Для рас окна биосовместимости/токсичности/радиоактивности **смещены** относительно человеческих: аммиачники потребляют «токсичное» для людей, радиотолерантные — радиоактивное, кремниевые — «несъедобное». Ось — физический скаляр (0–100); «хорошее» направление задаёт окно расы, а не глобально «больше = лучше». Это не изменение состава осей, а фиксация семантики: **окно потребления расы — это её собственный диапазон пригодности на той же шкале.** **Гейт-вопрос §11.2.**

**Следствие:** T_melt/T_boil становятся несущими для потребления (фаза пищи), а не только для товарных профилей.

## 5. Каталог базового слоя (20 ресурсов, число плавает)

**Имена — НЕ финальные.** Рабочие заглушки («вода-ресурс» и т.п.). Финальные имена даёт @writer с @designer по ТЗ §9.1.4 (нейтральная фонетика, кир/лат, не принадлежащая ни одному кластеру регионов). ТЗ на имена — §9.

## 7. Теневой товар T1

Решение создателя (94а аспект 10): производство закрывает крайне ограниченное количество базовых товаров T1 теневым механизмом; раса потребляет своё, излишек/не-своё выставляет на продажу (вплоть до улучшений корабля игрока). Принцип контраста: аммиачники едят аммиак, из воды делают товар T1; люди пьют воду, из аммиака делают товар T1 (пример-принцип).

### 7.1. Состав (4 позиции, ограниченный набор)

| Товар T1 | Из чего (сырьё — не-свой ресурс каталога) | Качество |
|---|---|---|
| Топливо | энергоёмкий/горючий ресурс, который раса НЕ потребляет | низкое (осадок) |
| Химикаты | химически активный ресурс, который раса НЕ потребляет | низкое |
| Конструкционные материалы | твёрдый/плотный ресурс, который раса НЕ потребляет | низкое |
| Товары быта | любой не-свой ресурс (широкие окна) | низкое |

Кандидат на добавление (не входит в состав сейчас): полимеры (нужен эластичный ресурс) — отложено до обкатки.

### 7.2. Механизм (теневым, через осадок)

- Производство — **фоновое** (не завод, не наём): «у поселений есть автоматизированная добыча ресурсов с поверхности, и в целом оно может делать несложные товары "фоном"» (94а аспект 15).
- Переформулировка осадка §13.12.3 (решение создателя, аспект 16): **собственный грубый осадок = собственное фоновое производство минус фоновое потребление того, что произвели**.
- Раса производит те позиции T1, для которых на её планете есть не-свой ресурс каталога. Своего ресурса в товар не перерабатывает — потребляет напрямую.
- Качество — низкое (осадок): не проходит пороги контрактов (§13.12.3), продаётся объёмно; в прогресс тира не идёт (§13.9.2).
- **Качество T1 проверяемо после точечных профилей (§5.3):** сырьё каталога — посредственное (все «↑»-оси < 70), значит и товар T1 из него < 70 по качеству — осадок, контрактные пороги (§5.2.3) не проходят. Сверка по §8.2.
- Потребители: другие поселения (в т.ч. других рас), игрок (улучшения корабля — задел).

### 7.3. Связь с корзиной тира

Для T1 корзина тира = практически только ресурсы без переработки, только добычи (94а аспект 3) + простенький производимый товар для роста — теневым механизмом (94а аспект 1, 10). Товары номенклатуры §5.2.1 в корзину T1 не входят.

## 8. Критерии приёмки (для @balancetester, числа)

### 8.1. «Все накормлены» (полнота реестра 1)

Для каждой из 50 биологических рас и каждой consumption-оси с весом ≥ 10 существует ≥ 1 ресурс каталога, чей профиль попадает в окно расы по этой оси (окно из шаблона §3.1). Доли 5–9 — желательно покрытие мостовыми; доли < 5 — необязательны. **Проверяется автоматически** (генератор-помощник, функция 1).

**Конвенция включительности окон:** все окна (шаблонов §3.1 и потребления рас) — **включительные**: границы входят в интервал (значение 60 на границе [60,100] попадает в окно). Иначе генератор полноты даст ложные дыры на граничных значениях каталога: №16/18/19/20 хим 60 = нижняя граница ГРД [60,100]; №17 T_melt 350 = верхняя граница ОРГ [250,350]; №14 T_boil 400 = граница ВОД [350,400] и ОРГ [400,600].

### 8.2. Посредственность слоя (негативное ограничение по реестру 2)

Проверка — **по конъюнкции требований** (§5.2.2): ресурс закрывает товар, только если проходит ВСЕ его оси-требования. Критерий: ни один ресурс каталога не выполняет все оси-требования ни одного товара §5.2.2 на уровне ≥ 70 (порог качества §5.2.3). Операционно: все «↑»-оси товаров у всех ресурсов каталога < 70 (полные профили §5.3; мысленная проверка по 13 товарам — там же). Доля товарных профилей, не закрываемых каталогом, = 100 %.

**Товары быта — исключение из проверки, названное явно:** их окна настолько широки (§5.2.1 «широкие окна», кандидат на пересмотр), что каталог может частично в них попадать; быта не создают решений игрока (не несущий профиль), поэтому попадание не нарушает неполноту §9.2.7. Точные окна быта проверяются отдельно при их фиксации в §5.2.2.

**Окна-оси без «↑» (химикаты, медикаменты-токс и т.п.) — состояние зафиксировано:** реестр требований товаров §5.2.2 в этой итерации не трогается (граница скоупа), точные окна-интервалы (например «химикаты: химическая активность (окно)») в нём не зафиксированы. Проверка посредственности по окнам-осям **отложена до фиксации реестра**; по «↑»-осям (≥ 70) доказана числами (§5.3). Окно химикатов дизайнер не придумывает — это зона реестра товаров.

### 8.3. Неполнота товарных окон (реестр 2, живость §9.2.7)

Реестр требований товаров остаётся дырявым: в произвольной точке галактики часть товарных профилей требует привозного сырья. Каталог в эту проверку не вмешивается (только не ухудшает: §8.2).

### 8.4. Диапазоны осей

- Все 10 осей в [0, 100].
- T_melt, T_boil в [10, 6000] K (52а §2.2).
- T_melt < T_boil с зазором ≥ 5 K, **кроме сублимирующих ресурсов** (T_boil ≤ T_melt, §4 уточнение 1) и сверхкритических (T_melt/T_boil вокруг критической точки с зазором, конвенция §3.1).
- Сумма consumption-вектора каждой расы = 100 (инвариант данных `config/races.json`).

### 8.5. Корреляции температур (фаза пищи)

Для каждой расы: существует пересечение окна T_melt/T_boil её пищи (объединение шаблонов §3.2) с её температурным окном обитания (`conditions.temperature`) — пища хотя бы в части окна обитания в нужной фазе. **Модель фазы — только по T, без P** (§9.1.2); расхождение с реальностью при высоком P — известное ограничение модели, игроку обещается ровно то, что модель держит. Примеры-контроль (точные, с точечными профилями §5.3):

- **Аммиачники** (T 196–255 K) и аммиак-ресурс (T_melt 198, T_boil 240): пересечение [196, 240] ≠ ∅ — пища жидкая в нижней части окна; 240–255 K — по T-правилу газ (по реальности при P — жидкость; ограничение модели).
- **Ледяные пастухи** (T 155–225 K) и CO₂-лёд (точечный профиль №4: T_melt 196, T_boil 189, сублимация): твёрдая фаза при T < 189 K — пересечение [155, 189] ≠ ∅; opt-зона 170–210 K — твёрдая только до 189 K, выше газ/сублимация.

### 8.6. Категории vs поверхности

Категория каждого ресурса каталога совместима с формами поверхности/типами недр планет рас-потребителей (§9.2.6): иначе «везде, где категория уместна» для этой расы не работает, и поселение не находит еду на своей планете (вымирание — §11, но не из-за ошибки каталога).

**Осознанный риск, закрытый в скоупе:** ОРГ-доля углекислых (ОРГ 20) закрыта мостовым №17 «органические аэрозоли» (💨, атмосферная органика — аналог толинов), не требующим биосферных поверхностей 🌿. Общая проверка «категория ресурса реально присутствует на планетах расы» — на генерации поверхностей, вне этой спеки (граница скоупа); каталог обязан её пройти, критерий остаётся в §8.6.

## 9. ТЗ на имена базового слоя (для @writer + @designer)

Финальные имена ресурсов каталога даёт @writer с @designer (решение создателя, 94а аспект 8). Требования:

1. **Нейтральная фонетика** (§9.1.4): не принадлежит ни одному кластеру регионов; услышал региональное звучание — груз местный, нейтральное — фон.
2. **Два варианта**: кириллица и латиница (Атрокс / Atrox).
3. **Уникальность в пределах галактики**: одно имя — один ресурс.
4. **Смысловая нейтральность**: имя не должно прямо называть химию («аммиак», «вода»), но должно быть произносимым и различимым (20 имён, которые игрок запоминает с первого дня — общий словарь §9.2.2).
5. **Мнемоническая связка с хемотипом — опционально** (по желанию @writer): звуковой намёк на «холодное/горячее/лёгкое» допустим, но не обязателен.

## 11. Открытые вопросы (гейт создателя)

1. **Сублимация** (§4): разрешить T_boil ≤ T_melt для сублимирующих ресурсов (CO₂-лёд) с расширением правила фазы? Это изменение инварианта §9.1.2. Альтернатива: фиктивная жидкая фаза (T_melt = 194.7, T_boil = 216.6 — «жидкий CO2 при давлении») — дешевле, но менее честно.
2. **Пер-расовая семантика осей** (§4): подтвердить, что окна биосовместимости/токсичности/радиоактивности для рас — их собственные диапазоны пригодности на той же шкале (не глобально «больше = лучше»).
3. **Состав теневого товара T1** (§7.1): 4 позиции (топливо, химикаты, конструкционные материалы, товары быта) — подтвердить; полимеры — кандидат на добавление.
4. **Порог покрытия** (§8.1): доли consumption ≥ 10 обязательны к покрытию отдельным ресурсом; 5–9 — желательно; < 5 — необязательны. Подтвердить порог.
5. **Название таблицы** `substances` vs `resources` — не решено создателем (94а поправки); сама схема БД — следующий релиз, но имя зафиксировать на гейте.
6. **Шаблоны хемотипов** (§3.1): числа T_melt/T_boil — из физики (эталон); окна по осям свойств и точечные профили каталога (§5.3) — предположения дизайнера, проверены @balancetester (итерации 2–3); при сильном расхождении — вернусь с вариантами.
7. **Число ресурсов** (20): плавает в обе стороны (94а аспект 14); критерий — §8.1, а не фиксированное число. В итерации 3 сжато с 26 до 20: мёртвые по T мостовые удалены, добавлены живые градиентные (§5.2).
8. **Товары быта** (§8.2): точные окна быта не зафиксированы в §5.2.2 — проверка попадания каталога отложена до их фиксации (не несущий профиль, неполноту не нарушает).

## 12. ГД-сущность-кандидат (обязательное предложение)

**«Экзотические товары рас» (перекрёстная ценность).** Товар T1, произведённый расой из НЕ-своего ресурса, получает повышенную ценность на рынках рас, для которых этот ресурс СВОЙ (принцип контраста создателя, доведённый до механики): люди покупают «аммиачные товары» аммиачников дороже своих, аммиачники — «водные товары» людей. Создаёт межрасовую торговую нишу и мотив возить товары между мирами разных рас. Кандидат на решение создателя; в текущие числа не входит (анти-двойной учёт). Реализация — после T2/рынков.

## 13. Инварианты и гарантии (для красных тестов будущей разработки)

1. Все 10 осей ресурсов каталога в [0, 100]; T_melt/T_boil в [10, 6000] K; T_melt < T_boil с зазором ≥ 5 K, кроме сублимирующих (T_boil ≤ T_melt) и сверхкритических (крит. точка с зазором).
2. Каталог: ровно предустановленный набор (20), вид = universal, без дом/радиус.
3. «Все накормлены»: каждая раса покрыта по всем consumption-осям с весом ≥ 10 (§8.1).
4. Посредственность по конъюнкции: каждый ресурс каталога проваливает ≥ 1 ось-требование каждого товара §5.2.2 на уровне ≥ 70; все «↑»-оси товаров у каталога < 70 (§8.2, полные профили §5.3). Проверка по окнам-осям без «↑» (химикаты и т.п.) — отложена до фиксации реестра §5.2.2 (§8.2).
5. Корреляция температур: существует пересечение окна T_melt/T_boil пищи с окном обитания расы; модель фазы — только по T, без P (§8.5).
6. Категория ресурса совместима с поверхностями планет рас-потребителей (§8.6).
7. Сумма consumption каждой расы = 100.
8. Окна рас не хранятся — выводятся из шаблонов + consumption (один факт — одно место).
9. Живость мостовых: точечный профиль (включая T_melt/T_boil) попадает в окна адресатов; мёртвых по T записей нет (§5.2, §5.3).
10. Окна (шаблонов и потребления) — включительные: границы входят в интервал (§8.1); иначе граничные значения каталога (хим 60, T_melt 350, T_boil 400) дают ложные дыры.
