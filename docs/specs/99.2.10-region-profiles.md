5. **Связь с границей сада** (`17_decay.md` §17.2.2) — профиль как второй
   носитель изолинии рядом с ценой еды.

   (`11_contracts.md` §11.3.2).

**Связь с экзотическими типами звёзд** (§99.2.4). Физическая причина профиля —
это и есть экзотический тип. Реализовывать вместе.

**Чего не делать:**

- **Не публиковать профиль как ярлык.** Последствия скрыты, открываются
  наблюдением (`02_worlds.md` §2.6.1).
- **Не делать набор профилей нормой.** 1–2 на регион, чаще один. Комбинации —
  только как отдельные комбинированные классы, написанные руками.

## 7. Влияние на генерацию звёзд (59a)

Профиль **мягко сдвигает** вероятности генерации звёзд в регионе: спектральные
классы, типы систем, массы, металличность. Жёсткие правила («в регионе только X»)
запрещены. Мягкость — через **мультипликативные множители весов** (все типы
остаются возможны) и **ограниченные аддитивные сдвиги**.

**Ручки (ключи конфига, секция `star`):**

| Ручка | Тип | Диапазон (сильная) | Что делает |
|---|---|---|---|
| `spectral_mult` | множитель | 0.3–3.0 | Веса спектральных классов O–Y (`Weights.Spectral`, `galaxy.go`). Неупомянутый класс = 1.0. |
| `system_type_mult` | множитель | 0.3–3.0 | Веса типов систем `single/binary/multiple/black_hole/neutron/white_dwarf/protostar/exotic` (`Weights.SystemTypes`). |
| `mass_bias` | аддитив | −0.3…+0.3 | Смещение выбора массы **внутри** диапазона класса (`StellarMassRanges`): масса = `min + (max−min)·clamp(U(0,1)+bias, 0, 1)`. Физика диапазона не нарушается. |
| `metallicity_shift` | аддитив | −0.3…+0.3 | Сдвиг среднего `rollMetallicity` (`galaxy.go`): `N(0+shift, 0.3)`, clamp [−0.8, +0.5] сохраняется. |
| `variable_mult` | множитель | 0.3–2.0 | Вероятности переменности в `rollStarMods` (`mira`, `uv_ceti`, `cepheid`, `eclipsing`, `t_tauri`), каждая клампится к ≤ 1.0. |

**Инвариант нормировки.** `weightedPick` нормирует веса по сумме (`galaxy.go`),
поэтому сумма после сдвига не важна — важно, что **все веса > 0**. Валидация
конфига: `spectral_mult` / `system_type_mult` / `variable_mult` обязаны быть
строго положительными; иначе тип может исчезнуть — нарушение мягкости.

**Масштабирование интенсивностью.** Конфиг задаёт сдвиги для **сильной**
интенсивности (максимум). Эффективный сдвиг:

- слабая: ×0.3 · средняя: ×0.6 · сильная: ×1.0

Для мультипликативных ручек: `eff = 1 + (config − 1) × scale` (интерполяция от
нейтрального 1.0). Для аддитивных (`mass_bias`, `metallicity_shift`): `eff =
config × scale`. Клампы применяются после масштабирования. «Слабый квазарный
регион — почти нормальный» (`02_worlds.md` §2.6.1) достигается масштабом 0.3.

**Согласование с экзотикой (99.2.4).** Профиль не добавляет типы систем — он
только сдвигает веса существующих. «Квазар» — НЕ тип системы, а профиль региона:
квазарный регион повышает долю чёрных дыр/нейтронных (`black_hole` с аккрецией =
микроквазар, 10% в 99.2.4 §4.3). Физическая причина профиля — это и есть
экзотический тип (см. §5).

## 8. Влияние на генерацию планет (59a)

Каскад `99.2.20` **не модифицируется**: формулы физики (T⁴-энергобаланс,
аккреция, атмосфера, гейты воды/жизни) не трогаются. Профиль сдвигает **входы**
каскада и **композиционный шаблон** (веса полосы) — физика продолжает решать и
фильтровать (гейт жидкой воды подавляет «океаны» при 500 K независимо от сдвига).

**Ручки (ключи конфига, секция `planet`):**

| Ручка | Тип | Диапазон (сильная) | Что делает |
|---|---|---|---|
| `planet_count_mult` | множитель | 0.7–1.3 | Среднее число планет. **Добавляемый хук** (P3): сейчас `determinePlanetCount` берёт `mean` из `g.means.meanForClass(...)` без множителя; хук — `mean × mult` перед потолком 8. Диапазон 0–8 сохраняется. |
| `gas_giant_shift` | аддитив | −0.2…+0.2 | Доля газовых гигантов. **Добавляемый хук** (P4): `gasGiantChance` возвращает пер-классное значение (0.1–0.8) без сдвига; сдвиг ±0.2 с клампом [0.05, 0.95] применяется на местах вызова (`circumbinary`, `planet_data_generate`). Гиганты не исчезают и не доминируют. |
| `surface_bias` | множитель | 0.3–3.0 | Веса форм поверхности полосы (`baseSurface` из `config/planet_archetypes.json`) → доминирующая форма → ГД-тип планеты. **Ограничение (O4):** работает только внутри текущей температурной полосы — форма вне шаблона полосы — no-op; гейт жидкой воды фильтрует по физике. «Океаны» в регионе с горячими планетами bias не добавит. |
| `subterrain_bias` | множитель | 0.3–3.0 | Веса форм недр полосы (`baseSubterrain`) → категории ресурсов. То же ограничение полосы, что у `surface_bias`. |
| `resource_bias` | множитель | 0.3–3.0 | Вес категории при выборе ресурса. **Добавляемый механизм (P2):** сейчас `pickCategory` в `internal/resource` выбирает равномерно (`categories[rng.Intn(len(categories))]`) из набора, собранного из форм поверхности+недр с долей > 5%; весового выбора нет. Хук — весовой выбор категории (вес = bias) или применение bias на этапе сбора категорий. Bias **не добавляет** категорию: если `water` не попала в набор (например, горячая полоса без ледников/вод), она не появится — только взвешивает существующие. |

Металличность (ручка `metallicity_shift` из §7) тоже влияет на планеты через
существующую физику: `accretionMass` масштабируется `10^(0.5·[Fe/H])` (99.2.20
§3.3) — богатый металлами регион даёт массивнее планеты → лучше удержание
атмосферы → больше пригодных кандидатов. Это осознанный косвенный эффект, не
отдельная ручка.

**Развилка механизма сдвига типов планет** (рассмотрено, см. §12): принят сдвиг
входов + композиционного шаблона (вариант А); пост-классификация (вариант В)
отклонена — противоречит «физика первым слоем, косметика вторым» (99.2.20).

## 9. Стартовый каталог классов

Один файл на класс в `config/region_profiles/` (паттерн `config/anomalies/`).
Схема записи:

```json
{
  "id": "quasar",
  "name": "Квазарный",
  "weight": 0.5,
  "cause": "physical",
  "crises": ["бури", "помехи связи", "радиация"],
  "boons": ["редкие элементы", "аномальные вещества"],
  "star": {
    "spectral_mult": {"O": 2.5, "B": 1.5, "A": 1.2, "K": 0.8, "M": 0.6},
    "system_type_mult": {"black_hole": 3.0, "neutron": 2.0, "exotic": 1.5, "binary": 1.2, "single": 0.9},
    "mass_bias": 0.2,
    "metallicity_shift": 0.1,
    "variable_mult": 1.5
  },
  "planet": {
    "planet_count_mult": 0.8,
    "gas_giant_shift": -0.1,
    "surface_bias": {"кратеры": 1.3, "лавовые_поля": 1.2},
    "subterrain_bias": {"радиоактивные_зоны": 1.5, "рудные_жилы": 1.2},
    "resource_bias": {"rare": 2.0, "mineral": 1.3, "fuel": 0.8, "organic": 0.5}
  }
}
```

`weight` — вес класса при ролле профиля региона (дефолт 1.0; редкие классы —
вес < 1). `cause`: `physical` (видна на карте) / `content` (скрыта, §2.6.1).
Неупомянутые ключи множителей = 1.0 (нейтрально).

**Принцип:** контентные профили **без астрономического следа** (пиратский,
хищный, плодородный, заброшенный) **не трогают генерацию звёзд** — их причина не
астрономическая; сдвигают только планеты/ресурсы/кризисы. Физические — сдвигают и
звёзды, и планеты. Исключение — **мёртвый**: причина контентная (древняя
катастрофа), но она оставляет астрономический след (остатки WD/NS, старая
популяция), поэтому сдвигает звёзды; сам профиль скрыт, виден только след.

списка — no-op (ключ не совпадёт с шаблоном полосы, эффект нулевой); валидация
конфига отклоняет неизвестные имена.

Список открыт: новый класс — один файл в каталоге, не правка кода. Комбинированные
классы («1–2 профиля» из GDD) — отдельные записи, написанные руками (например,
`quasar_toxic`), со своими множителями.

**Различитель «мёртвый vs старый» (O1).** По генерации звёзд классы почти
неразличимы (M/L/T/Y↑, O/B↓, WD/NS/BH↑, металличность↓) — это осознанно:
различие несёт **контентная часть** (кризисы/блага, след катастрофы у мёртвого:
радиоактивные_зоны, кратеры, артефакты; у старого — бедные месторождения без
благ), а не генерация. Генерация у обоих — «старая популяция», контент разводит
классы. Не усиливать различия в звёздах — это сломает физическую правдоподобность
обоих.

**Числа — предположение дизайнера, эталон не задан (2026-09-16).** Точные
величины сдвигов проверяет `@balancetester` на гейте 1 идеи 59a (распределения
в регионе с профилем vs без; все типы присутствуют).

## 10. Привязка профиля к региону при генерации

Профиль задаётся в `buildRegions` (`galaxy.go`), до генерации миров, в той же
транзакции, что и `worlds`. **Порядок роллов** (все через `g.rng`, тот же seed —
детерминизм по seed сохраняется):

1. **Класс:** взвешенный выбор по `weight` из каталога. ~75% регионов получают
   профиль, ~25% — фоновые (без профиля). Доля фоновых — развилка, см. §12.
2. **Интенсивность:** равномерно {слабая, средняя, сильная} (1/3).
3. Запись в регион: `regions.profile` (ключ класса), `regions.profile_intensity`.

**Семантика «выводится из генерации» (уточняет п.2 «Порядок работ»).** Профиль
задаётся **до** генерации миров и сам формирует свою причину: генерация региона
сдвигается к причине (квазарный регион реально содержит больше ЧД/нейтронных).
Это обращение старого правила «физическая причина выводится из генерации»:
консистентность региона с причиной становится эмерджентной, а не постфактумной.
Альтернатива (постфактум: сгенерировать миры, затем вывести профиль из состава)
противоречит требованию создателя «профиль влияет на генерацию» (курица и яйцо) —
отклонена, см. §12.

**Миры региона** генерируются со сдвинутыми весами: в `generateWorldsPoisson`
каждая точка знает свой регион (`pointRegion[i]`), `generateWorld` применяет
профиль региона точки. Для случайной генерации (без кластеров) регионов нет —
профиля нет.

**Планеты (отдельный джоб `GeneratePlanets`).** Профиль региона применяется при
генерации планет: для каждого мира регион определяется по ближайшему центру
(та же `nearestRegionIndex`, что в генерации звёзд — присвоение консистентно).
Координаты регионов после генерации не меняются (механики нет) — пересчёт
детерминирован. **Без изменения схемы** (не добавляем `worlds.region_id`).
Колонка `worlds.region_id` — запасной вариант, если регионы станут редактируемыми
(развилка, см. §12).

## 11. Инварианты и аудит

1. **Все типы возможны.** Все множители весов строго > 0 (валидация конфига).
   `weightedPick` нормирует по сумме — тип не исчезает.
2. **Масса в диапазоне класса.** `mass_bias` не выводит массу за `[min, max]`
   класса (кламп к 0..1 внутри диапазона).
3. **Металличность в [−0.8, +0.5].** Кламп `rollMetallicity` сохраняется; сдвиг
   меняет только среднее распределения.
4. **Число планет 0–8.** Mean-модель с потолком 8 не нарушается.
5. **Газовые гиганты 5–95%.** `gas_giant_shift` клампит шанс в [0.05, 0.95].
6. **Каскад не модифицируется.** Формулы физики 99.2.20 не трогаются; сдвигаются
   только входы и веса композиционного шаблона. Гейты воды/жизни фильтруют
   по физике независимо от сдвига.
7. **Профиль — не ярлык** (§2.6.1). Последствия скрыты; игрок видит причину
   (население звёзд, состав планет) и выводит следствия сам. Эффекты генерации —
   наблюдаемые следствия, сам профиль не публикуется.
8. **Контентные профили без астрономического следа не трогают звёзды.** Причина
   не астрономическая — множители звёзд нейтральны. Исключение — мёртвый (след
   древней катастрофы: WD/NS, старая популяция), см. §9.
9. **Квазар = профиль, не тип системы** (99.2.4, решение 2026-09-15). Профиль не
   добавляет типы систем, только сдвигает веса существующих.
10. **Аудит `@balancetester`** (гейт 1 идеи 59a): распределения в регионе с
    профилем vs без; все типы присутствуют; сдвиг не перекашивает границу
    сада/фронтира (профиль — второй носитель изолинии, §17.2.2).

## 12. Развилки и история итераций

**Рассмотрено и отклонено:**

- **Постфактум-вывод профиля из состава региона** (сгенерировать миры, затем
  вывести профиль). Противоречит «профиль влияет на генерацию» — курица и яйцо.
  Принято: профиль задаётся до генерации и сам формирует причину.
- **Пост-классификация планет по профилю** (пересборка ГД-типов после каскада).
  Противоречит «физика первым слоем, косметика вторым» (99.2.20). Принято: сдвиг
  входов + композиционного шаблона, физика решает.
- **Только входы каскада** (металличность + число планет + шанс гиганта, без
  `surface_bias`/`subterrain_bias`). Эффект на «доли типов» слабый и неуправляемый
  (нельзя сделать «плодородный» регион с большей долей землеподобных). Принят
  вариант А: + композиционный шаблон (веса полосы — вход, не физика).
- **Отдельная сущность «фишка кластера».** Отклонена создателем (2026-09-16):
  фишка = профиль региона, расширенный влиянием на генерацию.

**Открытые развилки (ждут решения создателя):**

1. **Доля фоновых регионов.** Рекомендация: ~25% регионов без профиля (фишка ≠
   норма, сохраняется базовый фон галактики). Альтернатива: 100% регионов с
   профилем (строгое чтение «1–2 на регион» из GDD), тогда «почти нормальный»
   даёт слабая интенсивность.
2. **Интенсивность-масштаб.** Принят: конфиг = сильная, масштаб 0.3/0.6/1.0.
   Альтернатива: конфиг = средняя, масштаб 0.5/1.0/1.5. Оба дают «слабая ≈ почти
   нормальный»; принят первый (округлые числа).
3. **Привязка планет к региону.** Принят: ближайший центр по координатам, без
   изменения схемы. Альтернатива: колонка `worlds.region_id` (лишняя миграция,
   нужна только если регионы станут редактируемыми).
4. **Величины сдвигов** — предположение дизайнера, эталон не задан (2026-09-16);
   проверка `@balancetester`, при необходимости правка чисел в конфиге (не в коде).
