## 1. Проблема

Модель изменения населения (`internal/economy/settlement`) — только про убыль: единственная
положительная (убывающая) компонента `R_ест = 1/СПЖ` с СПЖ = 50 лет как константа, рост
невозможен, возрастной потолок 120 лет — «выключатель», обнуляющий население по возрасту
поселения независимо от знака r (ломает рост).
Задача (идея 29a): добавить **естественную рождаемость** и вывести две балансные ручки
**в админку** — СПЖ и коэффициент рождаемости k.

**Решения создателя 2026-09-15 (финальные, не пересматриваются):**

1. Две ручки в админке («Основное»): **СПЖ** (дефолт 50 лет) и **коэффициент рождаемости k**
   (дефолт 2). Формула:
   ```
   R_ест  = 1/СПЖ                 (смертность, база; рампа [15,30] °C как есть)
   R_рожд = −k × R_ест            (рождаемость = k × смертность, знак минус)
   нетто  = (1 − k)/СПЖ
   ```
   k=1 → равновесие (нетто 0); k=2 → медленный рост (нетто −1/СПЖ = −2%/год при СПЖ 50);
   k=0 → чистая убыль.
2. СПЖ и k — **переменные, не константы** — чтобы потом без миграции пересадить в профиль
   расы (`ToleranceProfile`); сейчас — две глобальные ручки.
3. Потолок 120 лет — **убрать совсем** («Не, убрать совсем. Ненужная штука», создатель
   2026-09-15): возраст поселения ни на что не влияет; **третьей ручки не будет** — остаются
   две (СПЖ, k). Смысл потолка («исходные поселенцы умрут за 120 лет, новых нет») с
   рождаемостью исчез.
4. Будущие механики (война, эпидемия, переток, сквоттинг) — **отдельными членами**
   `ChangeComponents`, в рождаемость НЕ встраиваются.

**Эталон для чисел (референс @scientist, 2026-09-15, идея 29a):** Земля — рождаемость ≈ 17‰,
смертность ≈ 8‰ → отношение ≈ 2.1–2.2 : 1 (растущий мир, +0.9%/год). Дефолт k=2 = почти точное
земное среднее. Мой дизайн попадает в вилку: дефолт k=2 даёт в комфорте нетто −6.34·10⁻¹⁰/сек
(рост +2%/год, удвоение ~35 лет) — сходится с земным порядком «растущий мир». Расхождений нет.

## 2. Модель

### 2.1. Куда встраивать рождаемость — разворот подходов

**A. Отдельная компонента `BirthComponent(T) = −k·NaturalComponent(T)`** — **принято.**
Добавляется в `ChangeComponents` рядом с `NaturalComponent`:

```go
func BirthComponent(tempK float64) float64 {
    return -BirthRateCoefficient() * NaturalComponent(tempK)
}

func ChangeComponents(input PlanetInput) float64 {
    return NaturalComponent(input.TemperatureK) +
        BirthComponent(input.TemperatureK) +
        HeatTemperatureChangeRate(input.TemperatureK) +
        ColdChangeRate(input.TemperatureK) +
        GravityChangeRate(input.GravityG) +
        RadiationChangeRate(input.CoreRadioactivity)
}
```

**Почему A, а не B/C:**

- **Зеркалит решение создателя п.4**: рождаемость — первая будущая «положительная» механика,
  и она приходит отдельным членом, как придут война/эпидемия. Формула в коде читается как
  формула в 18a: `R_total = R_ест + R_рожд + R_жара + ...`.
- **Будущий профиль расы** (`ToleranceProfile`): пара «СПЖ, k» пересаживается двумя
  независимыми параметрами; каждая компонента станет методом профиля. В варианте B (один член)
  пересадка сводит формулу к `(1−k)/СПЖ` — тоже возможно, но теряется явная пара
  компонент-источников, а `NaturalComponent` перестаёт существовать как «смертность».
- **`DeathCause`** (18a: естественная компонента в сравнение вкладов не входит — она не
  «причина») — при A рождаемость симметрично исключена из причин: код `DeathCause` **не
  меняется вовсе** (`BirthComponent` туда не добавляется). При B пришлось бы вручную вычитать
  рождаемость из «natural», чтобы не получить ложную причину.
- **Модульность тестов** (99.2.13 `TestTotalRSum`): декомпозиция «каждый фактор добавляет
  свою компоненту» сохраняется в исходном виде.

**Цена A:** двойной вызов `NaturalComponent(T)` в `ChangeComponents` (внутри
`BirthComponent`) — две чистые функции за пересчёт, пренебрежимо против `math.Pow` в
`Population`.

**B. Один член `(1−k)·NaturalComponent(T)`** — отклонён: рождаемость слита со смертностью
в один член (против п.4 решений по духу), `NaturalComponent` теряет смысл «естественная
смертность», `DeathCause` требует отдельной оговорки. Выигрыш — один вызов функции — не стоит.

**C. Вшить k внутрь `NaturalComponent`** — отклонён: семантика `R_ест = 1/СПЖ` (эталонная
смертность) разрушается, «убыль» и «рост» неразличимы в коде, профиль расы потребует
разделения обратно.

### 2.2. Формулы и зоны температуры

```
R_total = NaturalComponent(T) + BirthComponent(T)
          + R_жара(T) + R_холод(T) + R_гравитация(g) + R_радиация(rad) + (будущие)
        = (1 − k)·R_ест(T) + R_жара(T) + R_холод(T) + R_гравитация(g) + R_радиация(rad)
R_ест(T) = NaturalComponent(T)   — рампа [15, 30) °C, как есть (99.2.12)
R_рожд(T) = BirthComponent(T) = −k·R_ест(T)   — та же рампа, знак минус
```

Поведение по зонам (рампа **сохраняется** — решение создателя «просто делай формулу
смертности со знаком минус ×2»):

| Зона T, °C | R_ест | R_рожд | Нетто естественной пары | Прочие компоненты |
|---|---|---|---|---|
| **< 15** | 0 | 0 | 0 | R_холод (T < 288.15 K — работает уже ниже 15 °C) |
| **[15, 30)** | NCR·(T−15)/15 | −k·NCR·(T−15)/15 | **(1−k)·NCR·(T−15)/15** | 0 |
| **≥ 30** | NCR (полная) | −k·NCR (полная) | **(1−k)·NCR** | R_жара (0 при T ≤ 30 °C, растёт выше) |

Ниже 15 °C нет ни смертности-рампы, ни рождаемости — там холод (решение создателя).
В жаре (T > 30 °C) рождаемость остаётся **полной** (рампа рождаемости = рампа смертности;
отдельную температурную воронку рождаемости не вводим — её не заказывали, GD_PROMPT
«никакой гибкости, которой не просили»; при 70 °C жара всё равно доминирует: убыль
~5.30·10⁻⁹/сек при k=2 — R_жара(70) ≈ 5.94e-9 минус NCR 0.63e-9).

### 2.3. Числа при дефолтах (СПЖ 50 лет, k=2)

- Комфорт (≥30 °C, без прочих угроз): `R_total = (1−2)·NCR = −6.34·10⁻¹⁰/сек` → **рост
  +2%/год**, удвоение `ln2/0.02 ≈ 34.7 года` (режим «растущей колонии»; эталон — идея 29a,
  числа @scientist).
- k=1: `нетто = 0` — равновесие по численности (живёт бесконечно: убыли нет, потолка нет, §4).
- k=0: `нетто = +NCR` — чистая убыль, поведение как до фичи.
- k>2: быстрее; k<1: убыль. Верх/низ диапазона — §3.3.

### 2.4. Что НЕ меняется в модели

- Рекурсия `pₙ₊₁ = pₙ·(1−R_total)^Δt_сек` — уже поддерживает r < 0 (`1−r > 1`,
  `Population`, mortality.go) — **правок нет**.
- Гвард r ≥ 1 (мгновенная гибель) — без правок; рождаемость лишь уменьшает r.
- `DeathCause` — без правок (§2.1).
- `Uninhabitable` — без правок: r < 0 → false (растущая планета витринно обитаема).
- `DeathMomentSeconds(p0, r)`: r ≤ 0 → +Inf — уже так; рост = «не вымирают».
- `MaxLifespanSeconds` (120 лет) — **удаляется полностью** (решение создателя 2026-09-15):
  возраст не влияет ни на пересчёт, ни на дату смерти (§4).
- Будущие механики — отдельными членами гирлянды (п.4 решений): в `ChangeComponents`,
  не в `BirthComponent`.

## 3. Настройки (СПЖ и k)

### 3.1. Природа сущности (развилки дизайнера)

- **Природа:** настройки — не событие и не лог, это **конфигурация процесса** (атрибут
  модели), как прецеденты `NDead`/`MinPersistInterval` (package-level var в `settlement`) и
  NPC settings. Таблицу/миграцию **не вводим** (решение идеи 29a, развилка 2).
- **Владелец:** глобальные, одни на сервер (две ручки на всё население; расы — будущее,
  §3.4).
- **Расширяемость:** параметров уже два (СПЖ, k) — структура, а не две константы;
  второй «тип настроек» (профиль расы) пересаживается на те же переменные без миграции
  (п.2 решений). Хранить в БД не на что — сброс на дефолты при рестарте.

### 3.2. Структура и API — `internal/economy/settlement/settings.go` (новый файл)

По образцу `internal/npc/settings.go` (RWMutex, геттеры/сеттеры, дефолты):

```go
package settlement

// populationSettings — настройки рождаемости/СПЖ из админки (спека 99.2.16).
// In-memory: дефолты при рестарте (прецедент — internal/npc/settings.go).
// Конкурентность: ChangeComponents читает на каждом вызове (RLock), админка
// пишет редко (Lock) — RWMutex.
type populationSettings struct {
	mu                   sync.RWMutex
	lifeExpectancyYears  float64 // СПЖ, лет, дефолт 50
	birthRateCoefficient float64 // k, дефолт 2
}

var popSettings = populationSettings{
	lifeExpectancyYears:  50,
	birthRateCoefficient: 2,
}

// LifeExpectancySeconds — средняя продолжительность жизни, сек
// (заменяет константу LifeExpectancySeconds, §3.5).
func LifeExpectancySeconds() float64 {
	popSettings.mu.RLock()
	defer popSettings.mu.RUnlock()
	return popSettings.lifeExpectancyYears * 365.25 * 24 * 3600
}

// SetLifeExpectancyYears — СПЖ из админки, годы. Валидация: 1..500 (см. §3.3).
func SetLifeExpectancyYears(y float64) error { ... }

// BirthRateCoefficient — коэффициент рождаемости k (дефолт 2).
func BirthRateCoefficient() float64 { ... }

// SetBirthRateCoefficient — k из админки. Валидация: 0..10 (§3.3).
func SetBirthRateCoefficient(k float64) error { ... }

// NaturalChangeRate — естественная компонента изменения за 1 секунду:
// 1/СПЖ (заменяет константу NaturalChangeRate, §3.5).
func NaturalChangeRate() float64 { return 1.0 / LifeExpectancySeconds() }

// ResetPopulationSettings — дефолты (тесты; «сброс» при желании в админке не делаем).
func ResetPopulationSettings() { ... }
```

### 3.3. Валидация (диапазоны — предложение на утверждение создателя, §9.1)

| Ручка | Диапазон | Обоснование |
|---|---|---|
| СПЖ, лет | **1..500** (float, шаг 1 в UI) | < 1 года — поселение гаснет за месяцы даже в комфорте (R_ест > 6.3·10⁻⁸/сек), бессмысленно; > 500 лет — убыль почти нулевая при любом k ≤ 10, для калибровки ручки хватает. Границы включены |
| k | **0..10** (float, шаг 0.1 в UI) | k=0 — «чистая убыль» (решение создателя); отрицательный k = отрицательная рождаемость = вторая смертность — запрещён; k=10 — запас для отладки (нетто −18%/год = рост +18%/год при СПЖ 50: удвоение ~3.9 года). Границы включены |

Ошибка валидации → PATCH отвечает 400 с текстом (прецедент `npc_settings.go`), текущие
значения не меняются. Значения за пределами диапазона не «клампятся», а отклоняются:
кламп делает ошибки админа невидимыми.

### 3.4. Профиль расы — не входит в числа (анти-двойной учёт)

`ToleranceProfile` — будущая сущность (18a, открытый вопрос 4): у рас может быть своя
СПЖ/k. Сейчас в игре её нет → в текущие числа/калибровку **не включается**; пересадка
подготовлена (переменные вместо констант, п.2 решений). Пометка для будущего: при введении
профиля рождаемость/смертность пересчитываются через профиль расы поселения — иначе
применится второй раз (двойной учёт).

### 3.5. Замена констант на переменные

`internal/economy/settlement/change_components.go`:
- Константа `LifeExpectancySeconds` → геттер `LifeExpectancySeconds()` (значение из настроек,
  §3.2). Имя константы исчезает как константа.
- Константа `NaturalChangeRate` → функция `NaturalChangeRate()` = `1/LifeExpectancySeconds()`.
- Комментарий шапки файла: список компонент дополняется `BirthComponent`.
- Все вхождения в коде и тестах: `NaturalChangeRate` → `NaturalChangeRate()`,
  `LifeExpectancySeconds` — только в тестах/коде как константа заменяется на геттер.

### 3.6. Эндпоинты — GET/PATCH `/admin/settlement-settings`

Новый файл `internal/handlers/admin_settlement_settings.go` по образцу `npc_settings.go`
(диспетчер по методу, JSON, 400 на невалидное). Авторизация — `auth.AdminAuth` (роут в
`cmd/server/main.go` рядом с `/admin/mortality-preview`).

```
GET  /admin/settlement-settings  → 200
PATCH /admin/settlement-settings  → 200 | 400 | 405
```

Тело PATCH — опциональные поля, хотя бы одно (прецедент npc_settings):

```json
{ "life_expectancy_years": 50, "birth_rate_coefficient": 2 }
```

Ответ (GET и PATCH) — текущие значения + производные для UI (единое место расчёта на
сервере, фронт не дублирует формулу):

```json
{
  "life_expectancy_years": 50,
  "birth_rate_coefficient": 2,
  "natural_change_rate_per_sec": 6.34e-10,
  "netto_per_year_percent": -2.0
}
```

`netto_per_year_percent = (1 − k)/СПЖ_лет × 100` — знак минус = **рост** (согласованно с
`r_per_sec`: r < 0 → рост). Для показа: «нетто-темп: +2%/год (рост)» — фронт меняет знак
для человекочитаемости.

### 3.7. Применение на лету — проверено

`NaturalComponent` и `BirthComponent` — чисто читают переменные через геттеры
(`NaturalChangeRate()`, `BirthRateCoefficient()`) на **каждый вызов**; рампа не кэширует
значения; `ChangeComponents` ничего не замораживает. Правка ручки в админке действует на
следующий же пересчёт любого поселения (ленивый пересчёт читает текущие значения — никаких
«старых» чек-точек с зашитой константой нет: формула пересчёта — чистая функция от
чек-точки и **текущих** настроек). Рестарт сервера → дефолты (in-memory).

## 4. Возрастной потолок 120 лет — удалён

`MaxLifespanSeconds` (120 лет) **удаляется из баланса полностью** (решение создателя
2026-09-15: «Не, убрать совсем. Ненужная штука»). С рождаемостью исходный смысл потолка
(«исходные поселенцы умрут за 120 лет, новых нет») исчез: популяция восполняется, возраст
поселения больше ни о чём не говорит. **Третьей ручки не будет** — остаются две (СПЖ, k);
возраст не влияет ни на пересчёт, ни на дату «Вымерло». Константа `MaxLifespanSeconds`
и связанный с ней код удаляются.

### 4.1. Правка `Recompute` (`recompute.go`)

Сейчас: проверка возраста независимо от знака r (`age ≥ MaxLifespan → 0`). Стало — проверку
возраста **убрать целиком**:

```go
deltaSeconds := now.Sub(since).Seconds()
if deltaSeconds <= 0 {
    return populationExact
}
r := ChangeComponents(input)
next := Population(populationExact, r, deltaSeconds)
if next < NDead {
    return 0
}
return next
```

Остаются: гвард Δt ≤ 0, рекурсия `Population` (рост r < 0 поддержан — `(1−r) > 1`), обвал
`next < NDead → 0` (18_needs). Возраст поселения в пересчёте **не участвует** (параметр
`createdAt` больше не читается — сигнатуру можно оставить для совместимости или убрать,
решение разработчика).

### 4.2. Правка `DeathTime` (`death.go`)

Убрать `ceiling = createdAt + MaxLifespanSeconds` из логики целиком. Остаются ветки:

```go
func DeathTime(populationExact float64, r float64, computedAt time.Time, createdAt time.Time) (time.Time, bool) {
    if populationExact <= NDead {
        return time.Time{}, false // чек-точка уже мёртвая: дата невычислима (бэкфилл отменён)
    }
    if r >= 1 {
        return computedAt, true // гвард мгновенной гибели (без NaN в ln(1−r))
    }
    if r <= 0 {
        return time.Time{}, false // рост (r<0) и равновесие (r=0): не вымирают (99.2.16)
    }
    tSec := math.Log(populationExact/NDead) / math.Abs(math.Log(1-r))
    // Дата через Unix-секунды (решение создателя 2026-09-15): time.Duration ограничен
    // ~292.5 года (max int64 нс), а медленная убыль даёт даты за тысячу лет. int64-секунд
    // хватает на ~292 млрд лет — лимит недостижим; запись «Вымерло» есть у ВСЕХ вымерших.
    unix := computedAt.Unix() + int64(tSec)
    return time.Unix(unix, 0), true
}
```

- `0 < r < 1` → формула `ln(pop/NDead)/|ln(1−r)|` **без** среза сверху потолком.
- **Лимит `time.Duration` снят (решение создателя 2026-09-15):** дата через Unix-секунды
  `computedAt.Unix() + int64(tSec)` → `time.Unix(unix, 0)`. `int64` секунд хватает на
  ~292 млрд лет — недостижимо для любых реалистичных убылей (макс. сценарий: СПЖ 500 лет,
  k=0, pop 10¹² → t ≈ 3.6·10¹¹ сек ≈ 11.5 тыс. лет). Запись «Вымерло» создаётся у **всех**
  вымерших, включая медленную убыль без среды (k=0, pop 10⁹ → ~800 лет).
- Причина лога — `natural` («Естественная убыль»: смертность > рождаемость в комфорте).
  Причины «от старости» (потолочной, «все умерли к 120 годам») **больше не существует** —
  потолок убран (создатель: «Просто причины "от старости" больше не будет :)"»).
- **База Unix — `computedAt`** (момент пересчёта: `tSec` отсчитывается от него). Создатель
  в решении назвал `createdAt.Unix()` — но это сдвинуло бы дату на возраст поселения
  («честная дата» нарушается); «или эквивалент без `time.Duration`» — использован
  `computedAt.Unix()`. Подтверждение — §9, п.2.
- Сигнатура: `createdAt` остаётся (решение создателя: «нужен для Unix-базы»); фактическое
  использование — см. развилку базы выше. Согласовать с вызовами в репозитории
  (`recompute.go`); `computedAt` нужен для ветки `r ≥ 1` и Unix-базы.
- Технический предел БД: `timestamp` в Postgres 15 — до 294 276 г. н. э.; реалистичные
  сценарии (≤ ~11.5 тыс. лет) в пределах — запись корректно сохраняется.

### 4.3. Краевые случаи (потолка нет)

| Случай | Поведение |
|---|---|
| **r < 0 (нетто-рост)** | `ok=false`, запись «Вымерло» не создаётся; поселение живёт бесконечно (потолка нет) |
| **r = 0 (равновесие, k=1; или 288 K где рампа+холод дают 0)** | `ok=false`, живёт бесконечно (раньше вымирало в 120 лет по потолку — теперь нет) |
| **0 < r < 1 (любая длительность убыли)** | Дата по формуле через Unix-секунды `computedAt.Unix() + int64(tSec)` (лимит ~292 млрд лет недостижим); запись «Вымерло» создаётся с честной датой, причина `natural` («Естественная убыль») — в т.ч. медленная убыль без среды (k=0, pop 10⁹ → ~800 лет) |
| **r ≥ 1 (мгновенная гибель)** | `ok=false` для чек-точки ≤ NDead; иначе `computedAt` — гвард без NaN |
| **Возраст поселения (created_at) любой** | **Не влияет ни на что** — потолка нет (убывающее от среды поселение вымирает по формуле NDead, не по возрасту) |
| **Uninhabitable** | Без правок: r < 0 → false (витрина не считает растущую планету «необитаемой») |
| **Предпросмотр `/admin/mortality-preview`** | Без правок: `DeathMomentSeconds(r ≤ 0)` = +Inf → `t_death_hours` скрыт (`admin_mortality.go:59-64`); `Projection` считает рост той же формулой — уже работает |
| **Лог «Вымерло» при росте** | Запись не создаётся — уже так (транзакция синка пишет только при `(time, ok)` из `DeathTime`; при r ≤ 0 ok=false) |

## 12. Что не делаем (режим отказа и границы)

- **16e** (UI-инструмент балансировки всех компонент) — в бэклоге, НЕ входит (идея 29a,
  развилка 5). Делаем ровно две ручки.
- Таблицу/миграцию настроек **не вводим** (in-memory; рестарт → дефолты) — прецедент NPC
  и `NDead`; БД-настройки появятся, когда появятся расы с профилями (тогда же — пересадка).
- Отдельную температурную воронку рождаемости (>30 °C, <15 °C) **не вводим** — рампа
  рождаемости = рампа смертности (решение создателя).
- `DeathCause`, `Uninhabitable`, `Projection`, предпросмотр, стрелка тренда — **без правок**
  (кроме комментария о «росте нет»).
- Потолок 120 лет **удалён полностью** — третьей ручки нет, возраст ни на что не влияет
  (решение создателя 2026-09-15, п.3); `MaxLifespanSeconds` и проверки возраста из кода убраны.
- Запись «Вымерло» — у **всех** вымерших, включая медленную убыль без среды (дата через
  Unix-секунды, лимит `time.Duration` снят — решение создателя 2026-09-15); не создаётся
  только при росте/равновесии (r ≤ 0). Причина «от старости» не существует; причина
  `natural` («Естественная убыль») остаётся.
- Режим отказа фичи: ручка СПЖ → 500 лет + k=10 = нетто −18%/год (рост +18%/год) при почти
  нулевой смертности — население растёт без возрастных ограничений — «райская планета» как
  вводимое наблюдаемое поведение; это штатно (админка — отладка), единственный предел роста —
  верхний потолок экономики (13.8), при необходимости сузить диапазоны (§9.1).
