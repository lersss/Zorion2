## 1. Цель и скоуп

Переписать генератор планет вокруг **физического каскада**: физика вычисляется
первым слоем (звезда → орбита → планета → ядро → энергобаланс → атмосфера →
флаг жидкой воды → поверхность → вода/жизнь/классификация), косметика
(композиция, описания, ярлыки) — вторым, и **не может противоречить физике**.

Планета становится **составным объектом** из четырёх частей: `атмосфера`
(новый объект), `поверхность` (существующая композиция 16 форм, сумма 100%),
`недра` (существующая композиция 17 типов, сумма 100%), `ядро` (существующий
объект). Атмосфера перестаёт быть текстовым полем: состав газов в % (сумма
100%), давление у поверхности, толщина (масштабная высота), оптическая толщина
в ИК. Тип атмосферы («азотно-кислородная», «парниковая»…) — **производный
ярлык**, вычисляется из состава и давления, хранится в строковом поле для
совместимости.

Флаг жидкой воды `liquid_water_possible: true/false` — бинарная **заготовка
для будущего генератора поверхностей**: вычисляется фазовой проверкой воды при
(T, P). Производные (T, P, точка замерзания, точка кипения, вода%) лежат в
данных рядом; градация «местами/стабильно/обильно» вычисляется потом, флаг не
меняется.

**В скоупе:** каскад для обычных звёзд O–Y (S- и P-планеты), атмосфера-объект
(включая гигантов), T⁴-энергобаланс, флаг жидкой воды, плотность от состава +
сжатия, масса по аккреции для каменистых/ледяных, судьба архетипов (полосы по
температуре), исправление светимостей O/B, обнуление вклада ядра для зрелых
планет, металличность как вход, материализация недостающих полей
(орбитальный период, давление, escape-скорость, эксцентриситет, приливный
захват), 2 новых правила аудита, обновление реестра полей.

**НЕ в скоупе** (границы — §12): генератор поверхностей (флаг — заготовка),
вращение/наклон/день-ночь, сезонные эффекты эксцентриситета, циркуляция
атмосферы, N-body, мини-нептуны (8–15.9 M⊕), новые компоненты R-модели
поселений, экзотические звёзды (ЧД/НЗ/WD/протозвезда — ветка не меняется),
механизм близнецов (клонирование без каскада), бэкфилл старых планет.

## 2. Каскад: слои и порядок

Порядок вычислений (для каждой планеты обычной звезды; P-планеты — тот же
каскад с L_total и r_P):

1. **Звезда:** светимость L (таблица по классу, исправлена — §3.1), T_eff
   (из мира), масса M★ (из мира, фолбэк по классу), возраст (из мира, фолбэк
   роллом), металличность [Fe/H] (новый ролл, фолбэк 0).
2. **Орбита:** радиус r (масштаб по светимости `0.4 × 1.7^index × √L` для S —
   §3.2; `3 × companion_sep_au` для P), период P_orb (Кеплер III),
   эксцентриситет (ролл 0.03–0.3, в v1 на T не влияет), приливный захват
   (флаг при P_orb < 10 сут; срабатывает у M-звёзд).
3. **Планета:** масса по аккреции (каменистые/ледяные — §3.3; гиганты —
   утверждённое логнормальное 99.2.15), объёмный состав (породы/железо/лёд по
   зоне снеговой линии) → плотность ρ (состав + сжатие) → радиус R = (M/ρ)^(1/3)
   → гравитация g = M/R².
4. **Ядро:** тип/доля/активность/радиоактивность (существующая генерация),
   внутренний поток F_int (Вт/м²): радиогенный (экспоненциальное затухание,
   для зрелых < 0.1 K) + аккреционный (молодые) + Кельвина–Гельмгольца
   (гиганты).
5. **T⁴-энергобаланс** (§3.5): T⁴ = (F★(1−A) + F_int + F_tidal) / (4σ) ·
   (1 + ¾τ_IR). Две итерации: T₀ без атмосферы → T₁ с номинальным парником
   (режим атмосферы по T₁) → атмосфера → T_final с τ_IR и облачным альбедо.
   Без цикла фиксированной точки (документировано).
6. **Атмосфера** (§3.6): состав газов (%), масса атмосферы (бюджет летучих по
   зоне + секвестрация по режиму + удержание по escape + стриппинг по T_eff) →
   давление P у поверхности → τ_IR → парник. Ярлык типа — производный.
7. **Флаг жидкой воды** (§3.7): фазовая проверка при (T_final, P).
8. **Поверхность** (§3.8): композиция генерируется **с учётом флага** —
   флаг false → водные и биосферные формы поверхности исключаются.
9. **Недра / вода% / жизнь / классификация** (§3.9): вода% по гидросфере
   (гейтится флагом), жизнь (требует жидкой воды или подлёдного океана),
   классификация (существующий `ClassifyGameDesignType`, входы от каскада).
   Жизненный проход: при жизни состав атмосферы пересчитывается (O₂, CO₂ ↓),
   τ_IR и T_final обновляются.

Инвариант каскада: **косметика не может противоречить физике**. Композиция
поверхности, гидросфера, биосфера, жизнь, классификация — функции от
(T_final, P, флага), не наоборот.

## 3. Формулы и константы по слоям

### 3.1. Слой 1 — звезда

**Светимость по спектральному классу** (исправлена; источник поломки — аудит
@Scientist: «O/B занижены на 1–3 порядка»). Единый источник —
`internal/astro/luminosity.go` (таблица читается и galaxy для сортировки пары,
и planet для температуры):

| Класс | Было (L☉) | Стало (L☉) | Обоснование |
|---|---|---|---|
| O | 1000 | **5·10⁴** | реальные O5 V ≈ 10⁴–10⁶; средняя точка логарифмического диапазона |
| B | 100 | **10³** | B0–B5 ≈ 10²–10⁴; средняя точка |
| A | 10 | **20** | A0–A5 ≈ 10–50 |
| F | 2 | **3** | F0–F5 ≈ 2–6 |
| G | 1 | 1 | Солнце |
| K | 0.1 | **0.25** | K0–K5 ≈ 0.15–0.4 |
| M | 0.01 | 0.01 | M0–M5 ≈ 0.06–0.005 |
| L | 0.001 | 0.001 | без изменений |
| T | 0.0001 | 0.0001 | без изменений |
| Y | 0.00001 | 0.00001 | без изменений |

Неизвестный/пустой класс — fallback 1.0 (сохранено, закреплено тестами).
Следствия: сортировка пары «главная = ярче» (99.2.18) сохраняет относительный
порядок (таблица монотонна); L входит в T P-планет (L_total, 99.2.18), в
снеговую линию (r_ice = 2.7·√L) и карточку звезды; для S-планет при масштабе
орбит √L (§3.2) инсоляция одинакова для всех классов — «выжженность» планет
O/B достигается XUV-стриппингом атмосфер и сухой внутренней зоной (§3.6, §8),
а не нагревом.

**Металличность [Fe/H]** — новый ролл в `galaxy.go` (для всех обычных звёзд):
`[Fe/H] = clamp(N(0, 0.3), −0.8, +0.5)` (солнечная окрестность), пишется в
`StellarMods.Metallicity`. Старые миры (nil) — фолбэк 0 (солнечная). Влияние на
каскад: масштаб массы аккреции (§3.3).

**Масса звезды M★** — из `worlds.stellar_mass` (29a). Старые миры (nil) —
фолбэк серединой диапазона класса (`DefaultStellarMassRanges`, galaxy.go).
Используется в Кеплере III (§3.2) и приливном захвате.

**T_eff** — из `worlds.temperature` (есть). Используется для XUV-стриппинга
атмосфер (§3.6).

**Возраст** — из `worlds.age` (41a) через `WorldInfo.Age`; старые миры (nil) —
фолбэк `determineSystemAge` (существующий ролл по классу). Пишется в
`system_age` и `core.age`.

### 3.2. Слой 2 — орбита

- **Радиус r — масштаб по светимости** (новое; обоснование — баланс-проверка
  В2 и аудит «приливный захват критичен у M-звёзд»):

```
r_i = 0.4 × 1.7^i × √L      а.е.   (S-планеты; i = 1..n)
r_P = 3 × companion_sep_au  а.е.   (P-планеты, 99.2.18 — без масштаба)
```

  Масштаб √L — физическая обитаемая зона (r_hab ∝ √L): каждая звезда получает
  свои орбиты, инсоляция орбиты i одинакова для всех классов
  (F★ = 1361·L/r² = 1361·L/(0.4624·L) = 2943 Вт/м² на орбите 1; 1018.5 на
  орбите 2 (r = 0.4·1.7² = 1.156 → r² = 1.3363 → 1361/1.3363); 354 на орбите 3).
  Следствия:
  - **G-звёзды (√1 = 1): орбиты не меняются** — нулевая регрессия для
    распространённого случая; анализ стабильности 99.2.18 для G в силе;
  - **M-звёзды:** орбита 1 = 0.068 а.е. (обитаемая зона M достижима) — планеты
    тесные; приливный захват (порог P < 10 сут) срабатывает при M★ ≥ 0.42 M☉
    (см. ниже);
  - **O/B-звёзды:** орбиты на 100+ а.е. (их честная обитаемая зона); планеты
    стерилизованы XUV-стриппингом и сухой внутренней зоной (§3.6, §8) — цель
    аудита «планет у O/B нет» достигается стриппингом, не нагревом;
  - **L/T/Y (коричневые карлики):** орбиты 0.002–0.02 а.е. — честная тесная
    зона коричневых карликов;
  - **Известные упрощения:** внешние орбиты горячих звёзд (O: до ~6200 а.е.)
    могут выходить за стабильную зону широких двойных (0.33×a, 99.2.18 §4.2) —
    редкий случай, не моделируется; триггер гигантов «орбита ≥ 3» у M-звёзд даёт
    «горячие юпитеры» на ~0.2 а.е. — редко, физически допустимо;
  - `orbit_radius_au` в planet.data — новые значения для новых планет (старые
    сохраняют старые; фолбэк §7).
- **Период** (Кеплер III, материализуется): `P_orb = √(r³ / M★)` лет.
  Диапазон генератора ≈ [0.0007, 127 000] лет (Y-звезда орбита 1 → 0.0007;
  O-звезда орбита 8: r = 0.4·1.7⁸·√L = 27.9·223.6 ≈ 6240 а.е. → P =
  √(6240³/15…60) = 64 000–127 000; см. §6.4 рамки). M-звезда, орбита 1
  (0.068 а.е., M★ = 0.1–0.6): P_orb = √(0.000314/0.1…0.6) = 0.023–0.056 года =
  **8–21 суток**.
- **Эксцентриситет** (материализуется): ролл `e = 0.03 + rng × 0.27`
  (0.03–0.3, лёгкий нижний предел — круговые орбиты редки). В v1 на
  температуру **не влияет** (средняя орбита), хранится как данные.
- **Приливный захват** (материализуется как флаг): `tidal_lock = P_orb < 10 сут`
  (≈ 0.0274 года). Порог по массе звезды: `M★ > r³/P²` — для орбиты 1 M-звезды
  (0.068 а.е.): M★ > 3.14·10⁻⁴/7.5·10⁻⁴ = **0.42 M☉** (не 0.25): при M★ = 0.42 →
  P = 10 сут; при M★ = 0.25 → P = 12.9 сут (захвата нет); при M★ = 0.1 →
  P = 20.5 сут (нет). Захват срабатывает у ранних M (M★ ≥ 0.42, ~половина
  диапазона 0.1–0.6). **Обитаемая орбита 2 M-звезды (0.116 а.е., P = 14–19 сут)
  под порог не попадает** — флаг false; реальное приливное замыкание поздних
  M-звёзд идёт быстрее порога P < 10 сут — известное упрощение (граница §12).
  Эффект на T в v1 не применяется (граница §12).

### 3.3. Слой 3 — планета: масса, состав, плотность, радиус, гравитация

**Масса по аккреции** (требование 99.2.11; заменяет рулетку `MassMin + rng ×
(MassMax − MassMin)`):

```
M_core = r^1.5 × 10^(0.5 × [Fe/H]) × ζ
ζ ~ logN(0, 0.4)   (логарифмически-нормальный разброс, пересэмплингом)
M = clamp(M_core, 0.1, 8.0)   M⊕
```

Калибровка: при r = 1 а.е., [Fe/H] = 0, ζ = 1 → M = 1 M⊕ (Земля). С масштабом
√L (§3.2) орбиты всех звёзд лежат на общей шкале: орбита 1 = 0.68·√L → 0.56·ζ
(0.2–1.4 M⊕); орбита 2 = 1.16·√L → 1.25·ζ (0.5–3 M⊕); орбита 3 = 1.96·√L →
2.75·ζ (1–7 M⊕). Верхний кламп 8 M⊕ — граница реестра и граница «суперземля»
(§3.4 03_planets.md). Нижний кламп 0.1 M⊕ — граница реестра. Металличность:
богатые металлом звёзды дают более массивные ядра (×10^(0.5·[Fe/H]):
[Fe/H] = +0.5 → ×1.78; −0.5 → ×0.56).

**Газовые гиганты:** масса — утверждённое логнормальное [15.9, 4131] M⊕
(99.2.15 §3.2, создатель 2026-09-15) — **не заменяется аккрецией** (эталон
создателя; аккреция решает только вопрос «каменистая или гигант» через
существующий триггер: орбита ≥ 3 + `gasGiantChance(класс)` — не меняется).
Радиус — кривая `GasGiantRadius(M)` с насыщением (99.2.15 §3.3, **не
ломается**); ρ = M/R³, g = M/R² (производные, не меняются).

**Объёмный состав** (новый вход плотности; источник поломки — аудит
«плотность от формы поверхности»):

Зона по снеговой линии `r_ice = 2.7 × √L` а.е. (аудит):

| Зона | Доля пород (0.49 ρ⊕) | Доля железа (2.0 ρ⊕) | Доля льда (0.17 ρ⊕) |
|---|---|---|---|
| Внутренняя (r < 0.7·r_ice) | 0.40–0.75 | 0.15–0.50 | 0–0.10 |
| Переходная (0.7–1.5·r_ice) | 0.50–0.70 | 0.10–0.20 | 0.10–0.30 |
| Внешняя (r > 1.5·r_ice) | 0.30–0.50 | 0.05–0.15 | 0.40–0.60 |

Доли нормализуются к 1. Доля железа до 0.50 во внутренней зоне — железо-богатые
миры (Меркурий-режим, редкий хвост); типичная внутренняя зона — 0.15–0.35.
Плотность:

```
ρ_mix = w_rock × 0.49 + w_iron × 2.0 + w_ice × 0.17     (ρ⊕, единицы Земли)
ρ = ρ_mix × (1 + 0.04 × log10(M))                        (гравитационное сжатие)
```

Проверка (единый путь формулы): Земля (w_rock 0.68, w_iron 0.32, w_ice 0) →
0.68×0.49 + 0.32×2.0 = 0.97 ρ⊕ (сжатие при M=1 → ×1.0) ✓; внутренняя типичная
(0.7/0.25/0.05) → 0.85 ρ⊕; металлическая (0.4/0.5/0.1) → 0.4×0.49 + 0.5×2.0 +
0.1×0.17 = 1.21 ρ⊕ (сжатие при M=5 → ×1.03 → 1.25); ледяная (0.4/0.1/0.5) →
0.4×0.49 + 0.1×2.0 + 0.5×0.17 = 0.48 ρ⊕.
Диапазоны честной плотности по таблице зон: ледяные 0.34–0.5, каменистые
0.5–1.25, металлические (железо-богатый хвост) 1.0–1.25, океанические 0.7–1.0
(каменистый объём + водная оболочка). Минимум: внешняя зона (0.3/0.05/0.65) →
0.36 ρ⊕ (сжатие при M=0.1 → 0.34); максимум: внутренняя (0.4/0.5/0.1) → 1.21
(сжатие при M=8 → 1.25). Реестр [0.077, 2.95] покрывает (§6.4). Таблица §3.4
в 03_planets.md обновляется дельтой (старые диапазоны «от поверхности» —
0.9–1.3 и т.п. — заменяются на 0.34–1.25).

**Радиус и гравитация** (инварианты не меняются):

```
R = (M / ρ)^(1/3)        R⊕
g = M / R²               g (земных)
```

Аудит `mass_size_density` (R = cbrt(M/ρ)) проходит по построению.

### 3.4. Слой 4 — ядро

Существующая генерация (`GenerateCore`): тип по массе, доля 5–60%, активность
0–100, радиоактивность 0–100, возраст = возраст системы — **сохраняется**
(потребители: реестр `core.radioactivity`, R-модель радиации 18a/99.2.13,
аудит, описания).

**Внутренний тепловой поток F_int (Вт/м²)** — новый; источник поломки — аудит
«вклад ядра до 372 K — завышение ~3 порядка»:

```
F_int = F_radiogenic + F_accretion + F_KH

F_radiogenic = 0.2 × (radioactivity/100) × 2^(−age_Gyr/2.5)   Вт/м²
               (экспоненциальное затухание с периодом 2.5 млрд лет —
                смесь U/Th/K; Земля: 0.2 × 2^(−4.6/2.5) = 0.056 Вт/м² —
                реальный радиогенный поток ~0.05–0.1 Вт/м² ✓;
                зрелые: при age = 5 → 0.05 Вт/м², при age ≥ 7 → ≤ 0.03 Вт/м² —
                вклад в T < 0.1 K, «обнуление для зрелых» достигнуто по эффекту)
F_accretion = 1000 × max(0, 1 − age_Gyr/0.5) × (M/1)^0.5            Вт/м²
               (только молодые, age < 0.5 млрд лет; остывание аккреции)
F_KH = 13 × (M/317.8)^2.5 × max(0.1, (1/age_Gyr)^0.5)               Вт/м²
               (только газовые гиганты: сжатие Кельвина–Гельмгольца;
                калибровка: Юпитер 13 Вт/м²)
```

Проверка вклада в T: зрелая каменистая планета (F_int ≈ 0.06 Вт/м²) против
F★(1−A) ≈ 100–1000 Вт/м² — вклад в T⁴ < 0.1 K (обнуление для зрелых — цель
аудита). Молодая планета (age 0.1 млрд лет, F_accretion ≈ 800 Вт/м² при M=1) —
вклад существенен (T₀ +~25 K). Гигант 13 MJ при age 0.1:
F_KH = 13 × 13^2.5 × max(0.1, √10) = 13 × 609.3 × 3.16 ≈ **25 000 Вт/м²** →
T_int = (25000/2.268·10⁻⁷)^0.25 ≈ **577 K** (вклад ~460 K относительно
холодного гиганта ~120 K — горячий молодой гигант, физично).

`core.radioactivity` (0–100) **остаётся** игровым показателем радиационной
опасности (R-модель, реестр, аудит, описания — не ломаем); F_radiogenic
выводится из него калиброванной формулой (мост «очки → Вт/м²»,
документировано как приближение).

### 3.5. Слой 5 — T⁴-энергобаланс

Формула (решение создателя 2026-09-16; отбрасывает старую модель: множитель
парника 1.0–2.5 + сложение кельвинов + вклад ядра до 372 K):

```
T⁴ = (F★(1 − A) + F_int + F_tidal) / (4σ) × (1 + ¾τ_IR)
T = clamp(T, 20, 2500)   K   (аудит-гейты TempAbsoluteMin/Max, сохраняются)
```

- **F★** = 1361 × L / r² Вт/м² (L в L☉, r в а.е.; 1361 — солнечная постоянная
  на 1 а.е.).
- **σ** = 5.67·10⁻⁸ Вт/м²·K⁴ (Стефан–Больцман).
- **A** — бондовое альбедо: `A = A_surface × (1 − f_c) + 0.7 × f_c`,
  где A_surface — существующее альбедо по доминирующей форме поверхности
  (`albedoByForm`), f_c — облачная доля по ярлыку атмосферы (таблица ниже),
  0.7 — альбедо облаков. Кламп A ∈ [0.03, 0.85].

| Ярлык атмосферы | f_c |
|---|---|
| разреженная / нет | 0 |
| азотная | 0.15 |
| азотно-кислородная | 0.30 |
| облачная / туманная | 0.45 |
| углекислая / плотная | 0.60 |
| парниковая | 0.90 |
| ядовитая | 0.40 |
| метановая | 0.35 |
| водородно-гелиевая / водородная / гелиевая | 0.30 |

  Проверка (единый путь формулы): Земля (океаны 0.06, f_c = 0.30) →
  A = 0.06×0.70 + 0.7×0.30 = 0.252 (реальная 0.30 ✓); Юпитер (f_c = 0.30) →
  A = 0.15×0.70 + 0.7×0.30 = 0.315 (реальная 0.34 ✓); Венера (f_c = 0.90) →
  A = 0.12×0.10 + 0.7×0.90 = 0.642 (реальная 0.75 — порядок верен).
- **F_int** — §3.4. **F_tidal** — только спутники гигантов: `F_tidal =
  2 / orbitIndex³` Вт/м² (замена старого «400/orbitIndex³ K»; Ио-подобный
  порядок).
- **τ_IR** — оптическая толщина атмосферы в ИК (§3.6).
- **Архетип-клампы отменены** (требование 99.2.11): `ArchetypeMin/Max` больше
  не ограничивают T. Остаются только абсолютные [20, 2500].

**Порядок вычисления (две итерации, без цикла фиксированной точки):**
1. T₀: τ_IR = 0, A = A_surface (без облаков; по предварительной поверхности
   полосы — как в текущем коде `GenerateSurfaceComposition` с T = 0, вода = 0),
   F_int по §3.4.
2. T₁ = T₀ × (1 + ¾·τ_nom)^0.25, τ_nom = 1.0 — предварительный парник
   номинальной атмосферы; **по T₁ выбирается режим атмосферы** (§3.6):
   T₁ < 273 → холодный; 273–373 → умеренный; > 373 → горячий. Порог горячего
   режима 373 K = точка кипения воды при 1 атм: T₁ > 373 → вода не
   конденсируется → океанов нет → секвестрации нет → CO₂-режим (физическое
   обоснование, баланс-проверка В2 п.3.4).
3. Атмосфера от режима (§3.6): состав, f_atm, P, τ_IR.
4. T_final: τ_IR и A с облаками из атмосферы.
5. Жизненный проход (§3.9): при жизни состав пересчитывается (O₂, CO₂ ↓),
   τ_IR и T_final обновляются (сдвиг ≤ 10 K — флаг не пересчитывается,
   документировано).

### 3.6. Слой 6 — атмосфера (объект)

**Генерация состава и массы** (каменистые/ледяные; режим выбран по T₁, §3.5):

1. **Бюджет летучих** по зоне снеговой линии (f_vol — доля массы планеты):
   - внутренняя: log-uniform [10⁻⁴, 10⁻³] (Земля-орбита 2 здесь;
     окно обитаемости — нижние ~55–60% диапазона, см. п.6);
   - переходная: log-uniform [10⁻⁴, 10⁻²];
   - внешняя: log-uniform [10⁻², 0.3] (ледяные миры).
2. **Доля летучих в атмосфере** (секвестрация по режиму):
   - **горячий** (T₁ > 373): секвестрации нет (океанов/карбонатов нет) →
     `f_atm = f_vol` (Венера-режим);
   - **умеренный** (273–373): вода в океанах, CO₂ в карбонатах →
     `f_atm = f_vol × 0.006` (постоянные газы CO₂/N₂) + влажность
     `f_h2o = f_perm × w_H2O/(1 − w_H2O)` (калибровка Земля → ~1 атм);
   - **холодный** (T₁ < 273): вода выморожена, CO₂ частично →
     `f_atm = f_vol × 0.006` (калибровка Марс).
3. **Удержание и стриппинг**:
   - escape: `f_esc = 0.05` при v_esc < 6 км/с, иначе 1 (калибровка Марс);
   - XUV-стриппинг у горячих звёзд (аудит «планет у O/B почти нет»):
     `f_strip = 1` при T_eff < 8000 K; `0.1` при 8000–15000 K; `0.01` при
     T_eff > 15000 K;
   - `f_atm ×= f_esc × f_strip`.
4. **Масса атмосферы**: `M_atm = f_atm × M_planet` (кг; M_planet = M ×
   5.97·10²⁴ кг).
5. **Давление у поверхности** (гидростатика; требование «из состава + массы +
   гравитации → давление»):

```
P_surf = (M_atm / 5.15·10¹⁸) × g_⊕ / R_⊕²     атм
```

   где 5.15·10¹⁸ кг — масса атмосферы Земли, g_⊕ — гравитация в земных g,
   R_⊕ — радиус в земных R. Проверка: Земля (f_vol = 1.5·10⁻⁴, умеренный →
   f_atm = 1.5·10⁻⁴×0.00603 = 9.05·10⁻⁷ → M_atm = 5.4·10¹⁸ кг, g = 1, R = 1)
   → **1.05 атм** ✓; Венера (f_vol = 10⁻⁴, горячий → f_atm = 10⁻⁴, M = 0.815,
   R = 0.967, g = 0.871) → M_atm = 4.87·10²⁰ кг → **P = 94.5 × 0.93 ≈ 88 атм**
   (реальная 92 ✓; при M = 1, R = 1 → 94 атм); Марс (f_vol = 10⁻⁴, холодный →
   f_atm = 6·10⁻⁷, M = 0.1, R = 0.464, g = 0.464) → P = 0.15 атм, ×f_esc = 0.05
   → **0.0075 атм** (реальная 0.006 ✓).
   Кламп: P_surf ≤ 1000 атм (граница реестра; сверхплотные «мини-нептуны» в
   v1 не генерируются — граница §12).
6. **Состав газов** (массовые доли, нормализация к 100%; ключи: `N2, O2, CO2,
   H2, He, CH4, H2O, SO2, NH3, Ar`):
   - **холодный:** CO₂ 0.90–0.95, N₂ 0.03–0.08, H₂O 0 (выморожена),
     CH₄ 0–0.05 (внешняя зона);
- **умеренный без жизни:** CO₂ 0.30–0.70, N₂ 0.25–0.65,
      H₂O = 0.010 × water_share (0.0005–0.009; Земля water_share 0.7 → 0.007),
      CH₄ 0.001–0.01;
   - **умеренный с жизнью** (жизненный проход §3.5 п.5): N₂ 0.75–0.80,
      O₂ 0.15–0.22, CO₂ 0.001–0.01 (фотосинтез), H₂O 0.010 × water_share,
      Ar 0.01;
   - **горячий:** CO₂ 0.85–0.97, N₂ 0.03–0.10, H₂O 0.0001 (истощена —
      фотолиз + утечка водорода; реальная Венера 0.00002), SO₂ 0.001–0.01
      (вулканическая);
   - **гиганты:** H₂ 0.85–0.95, He 0.05–0.15 (первичная), следы CH₄/NH₃.
   water_share — доля воды в бюджете летучих (доставка воды стохастична,
   особенно во внутреннюю зону — Земля получила воду, Венера/Меркурий нет):
   внутренняя зона 0.05–0.9 (log-uniform, доставка), переходная 0.5–0.8,
   внешняя 0.7–0.9.
7. **Оптическая толщина в ИК** (честный парник; источник поломки — аудит
   «множитель 1.0–2.5»):

```
τ_IR = P_surf × (w_H2O × 200 + w_CO2 × 1.0 + w_CH4 × 1.2 + w_N2O × 3.0)
```

   где w — массовые доли (0–1), P_surf в атм. Веса калиброваны по единому
   пути формулы (§3.5) на Землю (H₂O) и Венеру-аналог (CO₂) — см. «Проверка
   калибровок» ниже. Для Земли вклад CO₂ пренебрежим (τ_Earth ≈ 200·w_H2O);
   для Венеры доминирует CO₂.
8. **Масштабная высота** (размер/толщина атмосферы):

```
H = 8.5 × (T_final/288) × (29/μ) × (1/g_⊕)     км
μ = Σ w_i × μ_i   (N₂ 28, O₂ 32, CO₂ 44, H₂O 18, H₂ 2, He 4, CH₄ 16, ...)
```

   Проверка: Земля → 8.5 км ✓; Венера-аналог (T = 747, μ = 43.5, g = 0.9) →
   16.4 км (реальная ~15.9 ✓); Юпитер (T = 118, μ = 2.3, g = 2.53) → ~17 км
   (реальная ~27 — порядок верен).
9. **Ярлык типа** (производный, пишется в строковое поле `atmosphere`):
   классификатор по составу и давлению (порядок проверок):
   - H₂+He > 90%: H₂ > He → «водородно-гелиевая», He > H₂ → «гелиевая»,
     H₂ > 90% → «водородная»;
   - CO₂ > 80%: P > 5 атм → «парниковая», иначе «углекислая»;
   - CH₄ > 50%: «метановая»;
   - O₂ > 15% и N₂ > 50%: «азотно-кислородная»;
   - N₂ > 70%: «азотная»;
   - SO₂ + NH₃ + H₂S значимы (> 5%): «ядовитая»;
   - H₂O > 5%: P > 1 атм → «облачная», иначе «туманная»;
   - P < 0.1 атм: «разреженная»;
   - P > 5 атм (не CO₂): «плотная»;
   - fallback: «азотная».
   Все 14 существующих ярлыков покрыты; потребители ярлыка (пресеты,
   аудит, описания, UI, реестр) работают без изменений.

**Проверка калибровок (единый путь формулы §3.5, без подгонки под ответ):**

- **Земля-режим** (G, орбита 2 = 1.156·√L а.е., L = 1, M = 1, ρ = 1,
  water_share = 0.7 — доставка воды во внутреннюю зону, f_vol = 1.5·10⁻⁴,
  жизнь): F★ = 1018.5 Вт/м²; T₀ = (1018.5×0.94/2.268·10⁻⁷)^0.25 = 254.9 K;
  T₁ = 254.9×1.1505 = 293.3 → умеренный; f_atm = 9.05·10⁻⁷ → P = 1.05 атм;
  состав (жизнь): N₂ 0.78, O₂ 0.21, CO₂ 0.004, H₂O 0.007, Ar 0.01 →
  τ = 200×0.00694 + 1.0×0.00396 = 1.39+0.004 = 1.39; A = 0.252 →
  T_final = (1018.5×0.748/2.268·10⁻⁷)^0.25 × (1+¾×1.39)^0.25 = 240.3 × 1.197 =
  **287.2 K** (реальная 288 ✓); флаг true (273 < 287.2 < 374.5) ✓.
- **Венера-аналог игрового лэддера** (G, орбита 1 = 0.68 а.е., лавовая
  поверхность A_surface = 0.10, f_vol = 10⁻⁴, M = 0.815, R = 0.967, g = 0.871):
  F★ = 2943 Вт/м²; T₀ = (2943×0.90/2.268·10⁻⁷)^0.25 = 328.9 K;
  T₁ = 378.4 > 373 → горячий; f_atm = 10⁻⁴ → P = 88 атм; состав: CO₂ 0.96,
  N₂ 0.035, H₂O 0.0001, SO₂ 0.004 → τ = 88×(1.0×0.96 + 200×0.0001 + 3×0.004) =
  88×0.992 = 87.3; A = 0.642 → T_final = (2943×0.358/2.268·10⁻⁷)^0.25 ×
  (1+¾×87.3)^0.25 = 261.3 × 2.857 = **746.5 K** (цель — реальная Венера
  737 K, 1%); флаг false (T > T_кип(88) = 508) ✓. Примечание: типичная
  орбита 1 (пески, A = 0.35) даёт T₁ ≈ 349 < 373 → умеренный режим →
  жаркая пустыня T_final ≈ 340–365 K; горячие CO₂-миры — лавовые орбиты 1
  и молодые планеты (F_accretion, §3.4).
- **Марс-режим** (G, орбита 3 = 1.96·√L а.е., M = 0.1, ρ = 1.0, f_vol = 10⁻⁴):
  F★ = 354 Вт/м²; T₀ = (354×0.85/2.268·10⁻⁷)^0.25 = 190.9 K; T₁ = 219.6 →
  холодный; f_atm = 6·10⁻⁷ → P = 0.15 атм, ×f_esc = 0.05 → 0.0075 атм; состав:
  CO₂ 0.93, N₂ 0.05 → τ ≈ 0.007; T_final = **190.9 K** (реальная 210 — 9%);
  флаг false (T < 273; P = 0.0075 ≥ 0.006 — решает температура) ✓.

**Гиганты:** атмосфера-объект тоже создаётся: состав H₂/He, P_surf = 1 атм
(условный уровень «поверхности» — 1 бар), τ_IR ≈ 0.05–0.1 (слабое поглощение
H₂/He), H по формуле (μ ≈ 2.3). Температура — T⁴ с F_KH (§3.4): Юпитер
(F★(1−A) = 34.5 Вт/м², F_KH при age 4.6 = 13×0.466 = 6.06 Вт/м²; «13 Вт/м²» —
калибровка при age = 1) → T = (40.6/2.268·10⁻⁷)^0.25 × 1.018 ≈ **117.7 K**
(реальный ~124 — 5%). Старая формула гигантов `tEq × greenhouse + 30`
отбрасывается (чинит известную особенность 99.2.15 §8.6 «гигант 13 MJ может
получить T до 20 K»).

### 3.7. Слой 7 — флаг жидкой воды

```
liquid_water_possible = (P_surf ≥ 0.006 атм)  ∧  (T_freeze < T_final < T_boil)

T_freeze = 273 K                                (зависимостью от P пренебрегаем)
T_boil = 373 + 30.2 × ln(P_surf)  K             (Клаузиус–Клапейрон, 0.006–100 атм)
```

Проверки аудита @Scientist (числа — из калибровок §3.6):
- **Марс-режим** (T_final ≈ 191 K, P ≈ 0.0075 атм): P ≥ 0.006, но T < 273 →
  флаг false ✓ (вода не живёт — лёд/сублимация);
- **Венера-аналог** (T_final ≈ 747 K, P ≈ 88 атм): T_boil = 373 + 30.2×ln(88) ≈
  508 K, 747 > 508 → вода кипит → флаг false ✓ (жидкой воды нет);
- **Земля-режим** (T_final ≈ 287.2 K, P ≈ 1.05 атм): 273 < 287.2 < 374.5 →
  флаг true ✓;
- **Горячий парник (T = 400, P = 92) — иллюстрация формулы, не состояние
  модели:** флаг true (400 < T_кип(92) = 510) — вода жидкая при высоком
  давлении физически возможна; модель такое состояние не воспроизводит
  (умеренный режим с высоким f_vol даёт убегающий парник T 700+, горячий
  режим истощает H₂O) — зафиксировано как граница §12.

Флаг — **бинарный, хранимый** (`liquid_water_possible: true/false` в
planet.data). Производные (T, P, T_замерзания, T_кипения, вода%) — данные
рядом; градация «местами/стабильно/обильно» — будущая функция от них, флаг не
меняется.

### 3.8. Слой 8 — поверхность (с учётом флага)

`GenerateSurfaceComposition` (существующий механизм: базовые веса полосы →
температурные модификаторы → водные модификаторы → биосферные ниши → рандом
±20% → матрица совместимости → нормализация) получает **флаг**:

- флаг true: водные формы (океаны, озёра_реки) и биосферные формы (луга_степи,
  леса, джунгли, болота, коралловые_рифы) разрешены (существующее поведение);
- флаг false: **водные и биосферные формы поверхности исключаются из базовых
  весов до нормализации** (океаны, озёра_реки, болота, коралловые_рифы — явное
  требование задачи; луга/леса/джунгли — следствие: поверхностная биосфера
  требует жидкой воды). Остаются литосферные/вулканические/ледяные формы.

Реализация: новый модификатор `applyLiquidWaterGate(c, flag)` — при flag false
обнуляет 9 форм (5 биосферных + 4 водных) в копии базовых весов, вызывается
до температурных модификаторов.

### 3.9. Слой 9 — недра, вода%, жизнь, классификация

- **Недра** — существующая генерация (`GenerateSubterrainComposition`), входы
  от каскада (T_final, вода%, поверхность). Без изменений механики.
- **Гидросфера** (производный ярлык): выбор из `allowed_hydrospheres` полосы,
  отфильтрованных флагом:
  - флаг true: «океаны», «озёра», «сухая»;
  - флаг false: «ледяной покров», «подлёдная», «сухая», «кислотная».
- **Вода%** — существующие полосы `generateWater` по гидросфере и T
  (океаны/озёра только при флаге true; ледяной покров/подлёдная при T < 273 —
  флаг не требуется). Подлёдный океан (Европа-режим) возможен при флаге false.
- **Жизнь** (исправление ложных кандидатов):

```
life = (liquid_water_possible ∨ hydrosphere = "подлёдная")
       ∧ water_percent > 10 ∧ 200 < T_final < 400
       ∧ биосфера ≠ "стерильная" ∧ rng < life_chance(полосы)
```

  Марс-режим (T в диапазоне, флаг false, не подлёдная) → жизни нет ✓.
- **Пригодность под поселение** — `settlement.Suitable(water, temp,
  atmosphere_ярлык, life, isGasGiant, radioactive)` — без изменений.
- **Классификация** — `ClassifyGameDesignType` (существующий механизм,
  порядок проверок от специфичных к общим, fallback «скалистая (базовая)») —
  входы от каскада. Типы «океаническая»/«радиоактивная» возникают из физики
  (§5, решение по подветкам).

## 4. Структура данных `planet.data`

Миграций SQL нет — всё в существующем JSONB `planets.data` (паттерн «открытый
пакет», 99.2.4 §2).

### 4.1. Новые поля

| Поле | Тип | Семантика |
|---|---|---|
| `atmosphere_data` | объект | атмосфера-объект: `composition` (газ → массовая доля %, сумма 100), `pressure_atm`, `mass_earth_atm`, `tau_ir`, `scale_height_km`, `mean_molecular_weight` |
| `liquid_water_possible` | bool | флаг жидкой воды (§3.7) |
| `orbital_period` | float (лет) | Кеплер III (§3.2) |
| `eccentricity` | float | 0.03–0.3 (§3.2) |
| `escape_velocity` | float (км/с) | `11.2 × √(M/R)` |
| `tidal_lock` | bool | P_orb < 10 сут (§3.2) |

Существующее строковое поле `atmosphere` **сохраняется** как производный ярлык
(§3.6 п.9) — все потребители (пресеты поселений, аудит, описания, UI, реестр)
работают без изменений. Ярлык пишется генератором из объекта (один факт —
одно место: источник — `atmosphere_data.composition` + `pressure_atm`).

### 4.2. Изменённые поля

| Поле | Было | Стало |
|---|---|---|
| `temperature` | архетип-клампы + множитель парника + вклад ядра | T⁴-энергобаланс (§3.5), только абсолютные [20, 2500] |
| `density` | от доминирующей формы поверхности | от объёмного состава + сжатия (§3.3) |
| `mass` | рулетка архетипа | аккреция (§3.3); гиганты — без изменений |
| `core` | activity/radioactivity 0–100 | те же + внутренний поток F_int (Вт/м²) — новое поле `heat_flux_w_m2` в объекте `core` |
| `archetype` | рулетка по весам класса | производный ярлык полосы по T (§5) |
| `system_age` | ролл по классу | из `worlds.age` (фолбэк роллом) |

### 4.3. «Планета из объектов» — концептуальная модель, плоское хранение

Четыре части планеты (атмосфера, поверхность, недра, ядро) существуют в
planet.data как объекты (`atmosphere_data`, `surface_composition`,
`subterrain_composition`, `core`) на плоском уровне. Вложение под один родитель
(`planet.parts = {...}`) **не делается**: сломало бы всех потребителей плоских
ключей (пресеты, аудит, реестр, близнецы, UI, models.Planet) без игрового
выигрыша. Концептуальная модель фиксируется в 03_planets.md §3.11 дельтой.

### 4.4. models.Planet (API-whitelist)

Новые поля добавляются в `internal/models/planet.go` + `populatePlanetFromJSON`
(правило PITFALLS «новый ключ в planets.data → поле в models.Planet»):
`AtmosphereData map[string]interface{}`, `LiquidWaterPossible bool`,
`OrbitalPeriod float64`, `Eccentricity float64`, `EscapeVelocity float64`,
`TidalLock bool`. Поле `Atmosphere` (string) остаётся (ярлык).

## 5. Судьба архетипов (разворот подходов)

**Проблема:** сейчас архетип (5 категорий) выбирается рулеткой по весам класса
и задаёт массу, T-клампы, воду, жизнь — «хвост виляет собакой» (99.2.11).
Каскад требует физику первой.

**Варианты:**
1. **Полосы по температуре** (выбран): 5 архетипов `config/planet_archetypes.json`
   остаются файлом и структурой (обратная совместимость загрузки), но роли
   полей переопределяются: `base_surface`/`base_subterrain` — базовые веса
   композиции полосы; `allowed_hydrospheres/atmospheres/biospheres` — списки
   выбора (гейтятся флагом); `water_chance`/`life_chance` — косметические
   вероятности (гейтятся физикой); `temperature_min/max`, `mass_min/max`,
   `weight` — **не используются** (физика решает; рулетка отменена).
   Выбор полосы по T_final: T ≥ 500 → «экстремальный»; 350 ≤ T < 500 →
   «жаркий»; 250 ≤ T < 350 → «умеренный»; T < 250 → «холодный». «Изменчивый»
   из генерации выводится (остаётся в конфиге и реестре как допустимое
   значение, больше не выдаётся). **Семантика ярлыка:** полоса = диапазон
   T_final (композиционный шаблон), **не утверждение об обитаемости** —
   замёрзший мир (T_final = 240, флаг false) получает полосу «холодный»,
   водные/биосферные формы гейтятся флагом независимо от полосы. `archetype`
   в planet.data — производный ярлык полосы. Цена: конфиг частично «мёртв»
   (weight/temp/mass поля не читаются) — документируется в конфиге
   комментарием.
2. **Удалить архетипы, захардкодить полосы** — теряется администрируемость
   конфига, ломается загрузка/тесты/fallback-архетип. Отклонено.
3. **Оставить рулетку, физика подстраивается** — противоречит каскаду
   («косметика не может противоречить физике»). Отклонено.

**Гиганты/океанические/радиоактивные подветки** (разворот подходов):
1. **Растворить в каскаде** (выбран): ветки `generateOceanicPlanet` и
   `generateRadioactivePlanet` удаляются из `generatePlanet`; типы возникают из
   физики — «океаническая» при гидросфере «океаны» (флаг true) и воде > 60
   (существующее правило классификации); «радиоактивная» при
   `radioactive = core.radioactivity > 50` (существующий порог `IsRadioactive`),
   флаг `radioactive: true` пишется от ядра. Цена: меняется частота этих типов
   (смоук-тест подтверждает разумное распределение; описания/реестр/аудит
   типов не зависят от частоты). Цена альтернативы ниже.
2. **Оставить ветки, гейтить флагом** — «океаническая» только при флаге true;
   «радиоактивная» остаётся случайной. Меньше изменений, но «радиоактивная»
   остаётся косметическим исключением (не выводится из физики), а две ветки
   дублируют каскад. Отклонено в пользу (1) — каскад един для всех путей.

## 6. Совместимость

### 6.1. Пресеты поселений (не ломаем)

`settlement.Suitable` читает ярлык `atmosphere` (string) — сохраняется как
производный (§4.1). `ForbiddenAtmospheres` («ядовитая») работает: классификатор
§3.6 п.9 выдаёт «ядовитая» для SO₂/NH₃/H₂S-атмосфер. Вода/температура — от
каскада. Реестр полей (`fields.go`) пополняется (§6.4) — существующие поля и
рамки не меняются (кроме уточнения единиц/диапазонов там, где меняется
генератор: density/gravity рамки остаются валидными — проверено §3.3).

### 6.2. Аудит планет (42 активных + 1 отключённое — не ломаем)

Все существующие правила читают поля, которые сохраняются (`temperature`,
`surface_composition`, `core`, ярлык `atmosphere`). Проверено:
- `checkMassSizeDensity` (R = cbrt(M/ρ)) — проходит по построению (§3.3);
- `checkOceansInHeat` (океаны при T > 400) — при флаге false океаны не
  генерируются, правило почти не срабатывает (это нормально);
- `checkGreenhouseInCold` (парниковая при T < 250) — ярлык «парниковая»
  требует P > 5 атм и CO₂ > 80%; честная CO₂-атмосфера при T < 250 возможна
  (толстая, парниковая) — правило может давать Medium-флаги на физически
  корректных планетах. Известная особенность, пороги не меняются (зона
  баланса, не этой фичи).

**Новые правила (2, аддитивные):**
- `atmosphere_sum_not_100` (High): сумма `atmosphere_data.composition` ≠ 100
  (с допуском 0.5). Пропускает планеты без `atmosphere_data` (старые).
- `liquid_water_mismatch` (High): `liquid_water_possible = true`, но
  T_final ∉ (273, T_boil(P)) или P < 0.006 — инвариант флага. Пропускает
  планеты без флага (старые).

### 6.3. Описания (11 типов, ~700 текстов — не ломаем)

Механизм `descriptions_*.go` не меняется: `DescriptionContext.Atmosphere`
получает производный ярлык; теги (`addAtmosphereTags`, `inhabited`) работают от
ярлыка и пресета. Пороги тегов (cold/temperate/hot, density, mass) — от новых
входов каскада, семантика сохраняется. Правок библиотеки не требуется.

### 6.4. Реестр полей (`internal/generator/settlement/fields.go`)

Добавляются (рамки = границы генератора, инвариант «рамки == границы»,

### 6.5. Гиганты (99.2.15 — не ломаем)

Кривая M→R, распределение масс, ρ = M/R³, g = M/R² — **без изменений**
(эталоны создателя 2026-09-15). Меняется только: температура (T⁴ + F_KH,
§3.6) и добавление `atmosphere_data` (H₂/He, P = 1 атм). Тесты 99.2.15
(честность гиганта, рамки, пресеты) остаются зелёными; тест температуры
гиганта (если есть) обновляется на T⁴-ожидание (Юпитер ≈ 122 K).

### 6.6. Двойные системы (99.2.18 — не ломаем)

`orbit_center`/`orbit_radius_au`/`circumbinary` — сохраняются. P-планеты идут
через тот же каскад с L_total = L₁ + L₂ и r_P = 3a (инсоляция от суммы
светимостей — сохраняется). Полосы `circumbinaryBandForTemp` заменяются
единым каскадом (полоса по T — как у S-планет). Числа планет (mean 0.2 /
×0.9 / ×0.9) — не меняются. Справочные температуры P-планет из 99.2.18 §5.1
становятся историческими (рассчитаны на старую таблицу светимостей и старую
модель T) — новые значения даёт каскад.

### 6.7. Близнецы (гипотезы)

Механизм клонирования (clone + overrides) — без изменений («никакого каскада:
поля копируются побайтово», twin.go). Новые поля (atmosphere_data, флаг)
входят в шаблон как данные; оверрайд температуры без пересчёта флага может
дать рассинхрон — приемлемо для инструмента проверки гипотез (не
физическая симуляция), документируется. Валидация рамок (validateFieldRanges)
автоматически покрывает новые числовые поля реестра.

### 6.8. UI модалки

`tabs.js` показывает ярлык `planet.atmosphere` — работает без изменений.
Добавляется строка давления при наличии `atmosphere_data.pressure_atm`
(«Давление: N атм») — минимальная правка; при отсутствии (старые планеты) —
строка не выводится. Остальной UI не меняется.

### 6.9. Прототип поселения (`GeneratePrototypePlanet`)

Гарантия «землеподобная, пригодная, с жизнью» сохраняется: прототип — тестовый
инструмент, ему разрешено форсировать физику (документировано): полоса
«умеренный», T = 288 K, флаг = true, вода = 80%, жизнь = true (явные
оверрайды после каскада). Без форсирования прототип на орбите 1 у G-звезды дал
бы T_final ≈ 365 K (влажный режим; вне [200, 350] пресета) — контракт
инструмента ломается.

## 10. Кандидат ГД-сущности (Вопрос → Ответ)

Каждое задание приносит +1 кандидата; в текущие числа **не входит**
(анти-двойной учёт):

- **«Атмосферные ресурсы» (добыча газов):** атмосфера-объект (состав,
  давление, масштабная высота) позволяет сделать газы ресурсной категорией —
  плотные атмосферы дают месторождения H₂, He, CH₄, CO₂, O₂, N₂ (связано с
  бэклогом §99.3.3 «Атмосферные ресурсы — какие газы, с какой скоростью?»).
  Ответ: кандидат на будущую сущность; если принят — отдельная фича
  (ресурсная модель 99.2.5 + генератор), в числа 45a не входит.

## 11. Открытые вопросы / гейт-вопросы создателю

Каждый вопрос — с предложением по умолчанию (решение принято в спеке,
создатель может переопределить):

1. **Подветки океанических/радиоактивных планет** — растворить в каскаде
   (типы возникают из физики; рекомендовано) или оставить ветки с гейтом по
   флагу? Цена растворения: меняется частота этих типов (смоук-тест
   подтверждает).
2. **Ключ атмосферы** — сохранить строку `atmosphere` (ярлык) + добавить
   объект `atmosphere_data` (рекомендовано, ноль поломок) или сделать
   `atmosphere` объектом, ярлык перенести в `atmosphere_type` (чище, но
   правит всех потребителей)?
3. **Температура гигантов** — перевести на T⁴ + F_KH (рекомендовано; чинит
   известную особенность 99.2.15 §8.6 «гигант 13 MJ может иметь T до 20 K»)
   или оставить старую формулу?
4. **Металличность** — ролл [Fe/H] в galaxy.go (рекомендовано) или пропустить
   (солнечная 0)?
5. **Следствие каскада: обитаемая доля планет падает** (~40–45% → **~6%**,
   оценка 5–8% по согласованным числам §3.5–3.7: пригодны орбита 2 каждой
   звезды при f_vol в окне 1.1·10⁻⁴–4·10⁻⁴ (внутренняя зона) и water_share
   > 0.42 (доставка воды) + P-планеты тесных G-подобных пар). Это прямое
   следствие «физика вычисляется, а не подгоняется». **Развилка замысла:**
   принять ~6% (честная физика) или поднять ручками доставки воды/влажности
   (0.010 → 0.015·water_share, доставка 0.05–0.95) до ~10% — решение
   создателя. Точное число — смоук-тест.
6. **Венера-аналоги и горячие миры** (решение п.3.4 принято в спеке):
   порог горячего режима 373 K + κ_CO2 = 1.0 → Венера-аналоги достижимы
   (лавовые орбиты 1, молодые планеты, T ≈ 747 K); типичная орбита 1
   (пески) — жаркая пустыня 340–365 K. Подтвердить или задать иное видение
   (например, полный отказ от горячих CO₂-миров — тогда калибровка
   «Венера-аналог» становится гипотетической).
7. **Кандидат ГД-сущности** «Атмосферные ресурсы» (§10) — принять как
   кандидата?

## 12. Что НЕ делаем в этой фиче (границы)

- **Генератор поверхностей** (ландшафты, климат, градация «местами/стабильно/
  обильно») — флаг `liquid_water_possible` — заготовка под него; сама
  генерация — будущая фича.
- **Вращение, наклон оси, день/ночь, сезонность** — `rotation/day_length`,
  `axial_tilt` не материализуются (остаются «в модели нет» §3.11).
- **Эксцентриситет на T** — хранится, на температуру не влияет (средняя
  орбита).
- **Приливный захват на T** — флаг хранится, эффект (одна сторона к звезде)
  не моделируется.
- **Циркуляция атмосферы, климатические зоны, облачная динамика** — нет.
- **Паровая атмосфера / убегающий парник** (состояние «T ≈ 400 K при
  P ≈ 90 атм, жидкая вода под давлением») — не воспроизводится моделью:
  горячий режим истощает H₂O (0.0001), умеренный с высоким f_vol даёт
  T 700+ (T > T_кип) — флаг в этом состоянии остаётся false; фазовая
  проверка формулы корректна (иллюстрация §3.7), состояние — граница.
- **Цикл фиксированной точки** (T ↔ атмосфера) — одна итерация.
- **Мини-нептуны** (8–15.9 M⊕) — кламп P ≤ 1000 атм и массы ≤ 8 M⊕;
  заполнение промежутка — отдельная фича.
- **Новые компоненты R-модели поселений** (атмосфера/вода как факторы
  смертности) — 45a меняет входы (T, g, радиация — от каскада), но не
  добавляет компоненты; 18a §«Область (v1)» актуализируется дельтой
  (редизайн пришёл, компоненты R — будущее).
- **Экзотические звёзды** (ЧД/НЗ/WD/протозвезда) — ветка `generateExoticPlanet`
  не меняется (мёртвые тела, T 25–150 K, атмосферы нет).
- **Близнецы** — механизм без изменений (клонирование, не каскад).
- **Аудит-пороги существующих правил** — не меняются (зона баланса).
- **Автоматический бэкфилл/миграция старых планет** — нет (§7).
- **Изменение чисел планет** (mean), весов систем, `gasGiantChance` — нет.
  Лэддер орбит **меняется** (масштаб √L, §3.2) — это слой «орбита» каскада;
  G-звёзды без регрессии (√1 = 1).
