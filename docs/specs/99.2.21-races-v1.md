## 1. Цель и скоуп

Спроектировать сущность «раса» и наполнить её 50 расами, существование которых не
зависит от воды, исходя из физики каскада 99.2.20. Расы — полноценная новая
сущность (своя биология, свои поселения, свои условия пригодности), НЕ расширение
биосферы-ярлыка (`planet.data.biosphere` остаётся, расы вне неё). Люди — среди 50
(водная основа); в будущем игрок сможет играть не только за людей.

**В скоупе:** структура карточки расы (поля + шкалы), 50 рас (имена, основы,
физические условия, асимметричные окна, атрибуты, каркас корма), семейства
задним числом (критерий + применение к 50), кластерная привязка (концепция),
правило подселения на выбросах, сосуществование двух рас раздельными поселениями.

**НЕ в скоупе (границы — §14):** код/миграции/конфиги; голос/личность/тексты
общения; корабли/визуал/приоритеты агентов; механика отношений; числа баланса
(прогон @balancetester после этой спеки; здесь — только шкалы и диапазоны);
правка пригодности людей «вода из H+O» (отдельная задача); мягкость/жёсткость
подкручивания генератора (параметр конфигуратора, решается позже).

## 2. Сущность «раса» — природа, владелец, расширяемость

Разбор по правилу «сущность с двумя экземплярами — не сущность» (GD_PROMPT):

1. **Природа.** Раса — **справочная сущность-каталог** (статический список 50
   записей, как архетипы планет `config/planet_archetypes.json`), НЕ событие и НЕ
   лог. Её проявление в мире — **поселения** (динамические сущности, существующая
   таблица `settlements` + новое поле `race_id`). Раса не «вымирает» как сущность:
   «вымерло» — запись лога поселения (`settlement_log`, существующий механизм
   18a), раса остаётся в других поселениях и в каталоге.
2. **Владелец.** Одна раса → много поселений (1:N). Расширяемость закладывается
   сразу: `settlements.race_id` (nullable; NULL = легаси/люди). На одной планете —
   несколько поселений разных рас (существующее правило §13.2.1 «на одной планете
   может быть несколько поселений» + `race_id` различает их).
3. **Расширяемость.** 50 типов сразу — каталог с типами (список записей), НЕ
   атрибуты планеты. 51-я раса = новая запись каталога, схема не меняется. Схема
   переживает второй тип — да, переживает 50-й. Хранение: `config/races.json`
   (каталог, как архетипы) + `settlements.race_id` (строковый ключ, nullable;
   NULL = легаси/люди). Альтернатива — таблица `races` в БД — закрыта (решение
   создателя 2026-09-16, §12.3).

**Анти-ловушка «сущность вне игры»:** сущность «конфигуратор подкручивания
генератора» (потребитель карточек рас, §7) в игре отсутствует — на текущие числа
(карточки рас, семейства) **не влияет** (это будущий механизм генерации, не вход
карточки); двойного учёта нет. Сущность «подножный корм рас» — каркас (§4),
конкретные данные при 99.2.5; в числа карточек не входит.

## 3. Карточка расы — поля и шкалы

Карточка заполняется только тем, что нужно для существования поселений (данные,
не нарратив). Решение белых пятен 56a:

- **Окно задаётся по каждому условию отдельно** (не одно общее). Обоснование:
  биохимия привязана к физическим осям независимо (раса может быть гибкой по
  температуре и жёсткой по давлению); одно общее окно не выразит «терпит холод
  сильнее жары». Пригодность планеты = конъюнкция окон по всем осям.
- **Асимметрия — в числах окон**, не отдельным полем: у каждой оси два диапазона —
  `opt` (оптимум, полный комфорт) и `surv` (выживание, живёт хуже). Выпирание —
  производное: `surv` шире в одну сторону от `opt`. Направление выпирания
  (`bulge`) — производное поле для правила подселения (§7.3).
- **Минимальный обязательный набор полей:** `temperature`, `pressure`,
  `atmosphere` (нужна/яд), `radiation`. Опциональные (полный диапазон =
  «не влияет»): `heat_flux`, `gravity`, `liquid_water` (только для водных).

### 3.1. Структура карточки

```
race_card = {
  id: string, name: string, basis: string,          // основа существования
  conditions: {
    temperature: { opt: [lo,hi], surv: [lo,hi] },   // K, диапазон каскада [20, 2500]
    pressure:    { opt: [lo,hi], surv: [lo,hi] },   // атм, диапазон [0, 1000]
    atmosphere:  { need: {газ: min%}, poison: {газ: max%} },  // ключи каскада §3.6
    radiation:   { opt: [lo,hi], surv: [lo,hi] },   // core.radioactivity 0–100
    heat_flux:   { opt: [lo,hi], surv: [lo,hi] },   // Вт/м² (опционально; «не важно» = [0, ∞))
    gravity:     { opt: [lo,hi], surv: [lo,hi] },   // g, земных (опционально)
    liquid_water: true | false | nil                // требуется / исключена / не важно
  },
  attributes: {                                     // 0–100, 50 = человек; размножение — множитель
    aggression: 0–100,   // агрессивность (экспансия/конфликт)
    curiosity:  0–100,   // любопытство (исследовательский дух)
    reproduction: ×,     // скорость размножения при удовлетворении условий, × человек (лог-шкала)
    intelligence: 0–100, // интеллект
    diplomacy: 0–100,    // дипломатичность
    resilience: 0–100    // устойчивость: градиент деградации вне оптимума (50 = человек)
  },
  consumption: { ВОД, АММ, МЕТ, CO2, СЕР, РАС, СКФ, КРЕ, ОРГ, ГРД, ВГЕ, ПЫЛ, ИЗЛ },
                   // композиция потребления, сумма = 100 (см. §4)
  forage: { source: string, works_where: string, basic_resources: [string] },
  home: { star_classes: [string], planet_niche: string },   // кластер-дом (§7)
  bulge: "cold" | "hot" | "highP" | "lowP" | "none"         // производное выпирание окна
}
```

### 3.2. Шкалы атрибутов

| Атрибут | Шкала | Смысл |
|---|---|---|
| Агрессивность | 0–100 (50 = человек) | 0 = охранители/домоседы, 100 = экспансионисты |
| Любопытство | 0–100 (50 = человек) | 0 = сидят дома, 100 = исследователи |
| Размножение | множитель × человек (лог-шкала) | 1 = человек; фактический диапазон 4·10⁻⁶–200 (см. §5, §6) |
| Интеллект | 0–100 (50 = человек) | 50 = человек; < 20 — коллективный/растительный разум (абстракция, §10) |
| Дипломатичность | 0–100 (50 = человек) | готовность к союзам/торгу |
| Устойчивость | 0–100 (50 = человек) | насколько медленно деградирует популяция вне оптимума (градиент, не порог) |

**Решение по «характеру (агрессивные/исследователи)» из 56a:** разложено на две
ортогональные оси (агрессивность + любопытство). Обоснование: полюса не
противоположны — раса может быть агрессивной и домоседной (серные «преисподние»)
или мирной и любопытной (экзотика). Одна ось заставила бы их ложно
коррелировать. Принято создателем 2026-09-16 (§12.1).

**Решение по «ещё что-то» из 56a:** добавлена ось `resilience` (устойчивость).
Обоснование: окно задаёт *где* живёт, устойчивость — *как быстро* деградирует
вне оптимума; это нужный вход для R-модели поселений рас (градиент вместо
порога, согласуется с эталоном «порог-переключатель запрещён»). Принято
создателем 2026-09-16 (§12.2).

**Статус набора атрибутов — драфт, открытый** (решение создателя 2026-09-16,
§12.1–12.2): две оси характера и `resilience` остаются, но набор **не закрыт** —
новые оси атрибутов добавляются по мере надобности. Схема переживает новые оси
**без миграции**: новые поля входят в `attributes` каталога `config/races.json`
(§2.3), схема БД (`settlements.race_id`) не меняется.

## 4. Потребление и корм (каркас)

**Потребление** — композиция 13 осей (сумма = 100), «что раса ест/потребляет из
среды». Это числовой носитель «базового потребления», по которому считаются
семейства (§6). Оси:

| Код | Ось | Кому |
|---|---|---|
| ВОД | вода (жидкая) | водные |
| АММ | аммиак (NH₃) | крио-аммиачные |
| МЕТ | метан (CH₄) | крио-метановые |
| CO2 | CO₂ (атмосфера/льды) | CO₂-семейство, крио-пастухи |
| СЕР | сероводород/сера (H₂S, S) | серные |
| РАС | расплавы (соли и низкоплавкие металлы: эвтектики, олово/свинец/цинк) | терморедокс |
| СКФ | сверхкритические флюиды (CO₂/SO₂) | терморедокс, вихревые |
| КРЕ | кремний/силикаты | кремниевые |
| ОРГ | органика/биосфера | водные, углекислые |
| ГРД | энергия градиента (терморедокс/хемосинтез) | серные, терморедокс, глубинники |
| ВГЕ | водород/гелий (атмосферы гигантов) | небесные, крио-небесные |
| ПЫЛ | пыль/лёд | ледяной планктон |
| ИЗЛ | энергия излучения/магнитосферы | экзотика-фантастика (пометка) |

**Важно (не сливать при имплементации):** 13 осей потребления (§4) — **биохимическая
основа питания расы** («что раса ест из среды»), числовой носитель семейств (§6).
Это НЕ 13 товаров экономической номенклатуры `05_economy.md` §5.2.1 (перевыведена
в 13 товаров, `13_settlements.md` §13.3) — экономические товары потребления
поселений. Совпало только число «13»; множества разные. При реализации
`forage.basic_resources` (99.2.5, универсальный слой `09_resources.md` §9.2.2)
оси §4 **не отображаются 1:1** на товары номенклатуры — это два независимых слоя.

**Корм (каркас, данные позже при 99.2.5):** у каждой расы три поля —
`forage.source` (что ест), `forage.works_where` (где корм работает — для рас это
свои окна выживания: «подножный корм расы работает там, где выполнены её окна»,
аналог §13.3.2 для людей), `forage.basic_resources` (категории ресурсов из
универсального слоя/полей, конкретные вещества — при 99.2.5). Правило §13.3
(«незанятое кормится само») переносится на расы без изменений: незанятое
население расы живёт на своём корме, занятое — работает по найму (механика найма
рас — будущее, не этой сессии).

## 6. Семейства задним числом — критерий, алгоритм, результат

**Критерий близости базового потребления** (решение белого пятна 56a):

- Вектор потребления расы — композиция 13 осей (§4), сумма = 100.
- Расстояние между расами — **евклидово** на композициях (нормировка не нужна:
  сумма уже 100, шкалы соизмеримы).
- Алгоритм — **двухфазная процедура**:
  - **Этап 1 — ядро:** агломеративная кластеризация (average linkage) по 47
    расам ядра (все расы, кроме мостовых 10/43/48): на каждом шаге
    объединяются два кластера с минимальным средним попарным расстоянием;
    остановка при пороге **τ = 45** (все межкластерные средние расстояния > 45).
    Результат — 9 семейств-основ без мостовых рас.
  - **Этап 2 — мосты:** каждая мостовая раса прибивается к семейству-основе с
    минимальным средним расстоянием до её членов: 43 Приливные → F4 (23.8),
    48 Крио-небесные → F2 (32.5), 10 Сублиматоры → F8 (39.0). 49 Маргулы —
    не мостовая: после переработки 80a (РАС55-доминанта, СКФ 0) кластеризуется
    в ядро F5 (ближайший член ≈ 24.5).

Обоснование порога: при τ = 45 естественные основы (вода/аммиак/метан/сера/
терморедокс/кремний/водород/CO₂/излучение) разделяются, а мостовые расы
(Приливные 43, Крио-небесные 48, Сублиматоры 10) прибиваются к
ближайшей основе по среднему расстоянию. Порог — настраиваемый параметр: если
создатель захочет иное число семейств, меняется τ, не критерий.

## 7. Кластерная привязка (концепция, не код)

### 7.1. Кластер = раса-дом (homeworld)

Кластер (ячейка Вороного, ~500 систем) получает **доминирующую расу** — её
homeworld. У каждой расы в карточке есть `home`: типы звёзд + планетная ниша
(§5, колонки «Основа»/условия). Примеры: Люди — G/K, умеренная зона; Аммиачники —
K/M, холодная зона с NH₃-обогащением; Серные — молодые вулканические миры;
Небесные — гиганты.

### 7.2. Подкручивание генератора — конфигуратор

Подкрутка выносится в **конфигуратор** (решение создателя 56a; мягкость/жёсткость
— параметр, решается позже). Набор параметров (предложение):

| Параметр | Что делает | Диапазон |
|---|---|---|
| Веса спектральных классов | какие звёзды чаще в кластере (G/K для людей, M/L/T для метановых, O/B — нет) | веса 0–1, сумма 1 |
| Сдвиг орбитального лэддера | смещение T-диапазона планет (холоднее/горячее) | сдвиг в долях орбиты |
| Обогащение состава атмосферы | добавка газов под расу-дом: NH₃/CH₄ холодным, H₂S/SO₂ вулканическим, H₂/He гигантам | добавка % к составу |
| Веса типов планет | доля гигантов (небесные), ледяных спутников (приливные), лавовых (терморедокс) | веса 0–1 |
| Мягкость/жёсткость | 0 = генератор как есть (раса живёт там, где повезло), 1 = жёсткая гарантия условий дома | 0–1 (решается позже) |

**Важная сверка с каскадом 99.2.20:** в составе атмосфер каскада **нет H₂S**, а
NH₃/CH₄ в холодном режиме — следы (0–5%). Поэтому подкрутка состава — не
косметика, а условие существования серных и метановых рас: без обогащения их
окна «нужна H₂S ≥ 1%» / «CH₄ ≥ 5%» не выполняются нигде. Это усиливает роль
конфигуратора (55a: «В кластере с большим шансом генерируются звёзды, подходящие
для жизни расы»).

### 7.3. Подселение на выбросах — широкие пограничные зоны

Правило (решение создателя 56a, вариант 2):

- В **широкой пограничной зоне** кластера Y (полоса смешения, а не тонкая кромка)
  может расселиться раса A из ближайшего соседнего кластера X.
- Условие: планеты зоны попадают в `surv`-окно A **по всем осям** (конъюнкция
  §3). Асимметрия окна объясняет, куда A реально подселится: выброс идёт в ту
   сторону, куда у A окно **выпирает** (`bulge`). Пример: Люди (bulge в
   холод) подселяются на холодный край соседнего кластера; Терморедокс (bulge в
   жару) — на горячий.
- Подселение — отдельные поселения расы A в зоне Y (не смена доминанты Y).
- Проверка совместимости биохимий — §8.

### 7.4. Сосуществование двух рас на планете

Две расы на одной планете = **две сущности-поселения** (решение 56a, вариант А):
два ряда `settlements` с разными `race_id`, у каждого своя биология, свой корм,
своя скорость размножения. Существующее правило §13.2.1 («на одной планете может
быть несколько поселений») покрывает механику без изменений.

**Совместимость биохимий** (кто может сосуществовать):

| Пара | Совместимость | Причина |
|---|---|---|
| Вода + аммиак | **нет** | NH₃ + H₂O реагируют (scientist) |
| Вода + сера | **нет** | O₂ — яд для серных; H₂S — яд для водных |
| Вода + метан | нет (редко) | H₂O вымораживает/отравляет метановую среду |
| Сера + терморедокс | да (часто) | перекрытие окон T 450–600, общие SO₂/CO₂, разные корма |
| Сера + кремний | да (редко) | разные T-ниши, общие H₂S/CO₂ при высоком P |
| Люди + небесные | **нет** | O₂ — яд для небесных, но need для людей → взаимный яд по правилу вывода §7.4; плюс разные типы планет (поверхность vs атмосфера гиганта) |
| Люди + углекислые | нет | O₂ > 5% — яд для углекислых |

Полная матрица 50×50 не прописывается (решение создателя: отношения не
вычисляются правилами) — совместимость **выводится** из карточек: две расы
сосуществуют, если их окна пересекаются по всем осям И ничья «яд»-атмосфера не
является требованием другой. Это естественное следствие данных, не отдельное
поле.

## 16. Инварианты и проверки

1. **Композиция потребления = 100** у каждой из 50 рас (проверка таблицы §5).
2. **Окна:** `opt ⊆ surv` по каждой оси; `surv` в пределах диапазонов каскада
   (T [20, 2500], P [0, 1000], rad [0, 100]). **Исключение (осознанное):** расы,
   явно помеченные «оф-модельная/вне каскада» (раса 40 Водородные, P-окно «1000+»;
   жидкий H₂ требует глубин, вне диапазона [0, 1000]) — их окна выходят за диапазон
   каскада намеренно (фантастика/флавор); в каскаде для них нет планет, и это
   зафиксировано в §10 (дыра не маскируется).
3. **Семейства:** повторное применение двухфазной процедуры §6 (этап 1:
   average linkage τ = 45 по 47 расам ядра без мостовых 10/43/48; этап 2:
   прибивка мостовых рас к ближайшей основе по среднему расстоянию) к таблице §5
   даёт те же 9 семейств (детерминированность; проверяемо вручную по векторам).
4. **Пригодность планеты** = конъюнкция `surv`-окон по всем осям + атмосфера
   (need/poison) + `liquid_water` (если задан).
5. **Сосуществование** выводится из карточек (пересечение окон + отсутствие
   взаимных ядов), не хранится отдельно.
6. **Не-регрессия:** расы вне биосферы (55a п.3) — `planet.data.biosphere` не
   меняется; `settlement.Suitable` людей не трогается (кроме будущей H+O-правки).
7. **Кандидат ГД-сущности** (§11) в числа спеки не входит (анти-двойной учёт).
