## 1. Цель

Новая карточка расы в энциклопедии — **«игровое восприятие»**: игрок видит расу как живое существо, а не как набор чисел. Карточка получает:

- **лор без терминов** (2–4 абзаца художественного текста, без игровых терминов и числовых оценок);
- **«Вид»** (словарь §4, 11 значений);
- **атрибуты-слова** (6 слов вместо цифр/баров; цифра игроку **не показывается**);
- **«Размер особи»** + **«Размер стаи/роя»** (у коллективных рас);
- **«Ниша»** ярлыком (словарь §5, 12 значений);
- **«Дом»** словами;
- **«Сосуществование»** (остаётся).

**Границы цели (решения создателя, гейт 2026-09-18):**

- **Только игровой слой.** Механики, баланс, генератор, R-кривые не затрагиваются.
- **`config/races.json` НЕ трогаем** (эталон чисел, вариант А) — слова атрибутов **дериваты** чисел, числа остаются источником истины.
- **Старые поля `config/race_lore.json` сохраняем** (`id`, `family`, `character`, `how_live`, `why`, `coexistence`, `origin` у роботов) — не переименовываем, не удаляем.
- **API-контракт аддитивен** (идея 86a): новые поля добавляются к ответу энциклопедии, старые поля ответа не меняются.
- Миграций/БД/Redis **не добавляем** — новые поля — атрибуты существующей записи лора (природа сущности, §3.1).

**Реконструкция:** тела файлов исходного устройства отсутствуют; эта спека восстановлена по манифесту (структура, решения создателя, эталоны) и локальному контексту. **Полные таблицы слов и границ (§4–§6) и списки (§5, §6.5) — реконструкция дизайнера на этом устройстве**, соблюдающая все зафиксированные решения создателя; места, где реконструкция не подтверждена манифестом, помечены «на подтверждение создателя» (§12).

## 2. Карточка (что видит игрок)

Открытая карточка встреченной расы (силуэт «—» до встречи — 86a §5.1.2, не меняется). Порядок блоков:

1. **Имя + бейдж семейства** (F1–F9 / «Роботы») — без изменений.
2. **Основа** (`basis`) — без изменений.
3. **Ключевые окна** (T в °C, P в атм, g, радиация, атмосфера) — без изменений (86a §5.1.2).
4. **Атрибуты-слова** — 6 строк: подпись оси + слово из `attributes_words` (порядок `ATTRIBUTE_LABELS`: агрессия, любопытство, размножение, интеллект, дипломатия, устойчивость). **Числовые значения атрибутов и бары игроку не показываются** (замена `attributeBars`). Примечание: слова шкал размножения («в десятки раз быстрее») содержат словесные сравнения темпа — это осознанный слой §6.2 (эталон №2): в них нет цифр, только слова.
5. **Блок «Вид · Ниша · Размер (+ Рой/стая)»** — `kind · niche · size_individual`; если `size_group` не null (коллективная раса), добавляется `· size_group`.
6. **«Дом»** — `home_words` словами; при отсутствии — фолбэк на коды `home.star_classes + home.planet_niche` (как сейчас).
7. **«Корм»** (`forage.source`) — без изменений.
8. **Слой роботов** (`robotic`: энергия/сброс тепла/сырьё) — без изменений.
9. **Лор-блок** — новый `lore` абзацами (заменяет в UI `character`/`how_live`/`why`); **«Сосуществование»** (`coexistence`) и **«Происхождение»** (`origin`, роботы) остаются.

**Правило лора:** текст без игровых терминов (нет «окон выживания», «атрибутов», «R-кривых», «хемотипов», «потребления») и без числовых оценок («в десятки раз быстрее» — слово шкалы атрибутов, в лоре не используется; эталон №2, §7).

### 6.2. Лог-шкала размножения

`m` = множитель × человек (`reproduction` в `races.json`). Граница **строгая**: `m < limit`; **последний шаг {0, слово} — рабочий фолбэк** для `m >= 100` (B2: «в сотни раз быстрее»). Решения создателя: **0.1 ≤ m < 1 «в разы медленнее»**, **1 ≤ m < 2 «как человек»** (согласовано с rep=0.5 у deep_dwellers/magnetophages):

| m | Слово |
|---|---|
| m < 0.0001 | в сотни тысяч раз медленнее |
| 0.0001 ≤ m < 0.001 | в тысячи раз медленнее |
| 0.001 ≤ m < 0.01 | в сотни раз медленнее |
| 0.01 ≤ m < 0.1 | в десятки раз медленнее |
| 0.1 ≤ m < 1 | в разы медленнее |
| 1 ≤ m < 2 | как человек |
| 2 ≤ m < 10 | в разы быстрее |
| 10 ≤ m < 100 | в десятки раз быстрее |
| m ≥ 100 | в сотни раз быстрее *(фолбэк {0, слово})* |

Покрытие всех 60 значений `races.json` проверено (0.000004…200, 9 ступеней, ни одного пропуска).

### 6.3. Примечание о границах

- Линейные шкалы: `v <= limit` (включительно, верхняя граница входит в ступень).
- Лог-шкала: `m < limit` (строго), последний шаг — фолбэк `{0, слово}` (любое `m >= 100` → «в сотни раз быстрее»).
- Монотонность: рост числа → не-убывающее слово (проверяется тестом границ, §9.2).

- `TestScaleBoundaries` — линейные шкалы: значения на границах (0/20/21/44/45/56/57/68/69/100 и т.д.) дают ожидаемые слова; монотонность.
