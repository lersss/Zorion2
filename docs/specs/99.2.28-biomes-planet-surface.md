## 1. Цель и скоуп

Перевести поверхность и недра планеты из «текстовых значений с долями» в **объекты модели**, добавить **биомы как последний слой каскада** и сделать **перечень «что бывает» редактируемым справочником в админке** (решения создателя 2026-09-20, идея §2):

1. **Биомы — объекты.** Поверхность = контейнер биомов («куски»), сумма долей 100%. Каждый биом — объект `{form, share}`.
2. **Недра — тоже объекты** (тот же паттерн). Спутники — вне скоупа.
3. **Доли биомов считает физика** (свойства планеты), а не справочник. Таблица климатов (`config/planet_archetypes.json`) **не удаляется** — остаётся перечнем возможных биомов и границ «что где в принципе бывает».
4. **Справочник «что бывает» — расширяется и становится редактируемым из админки** (вкладка «Основное»): биомы поверхности, типы недр, типы планет, полосы климатов, матрица несовместимости (решение п.15). Справочник — данные (конфиг-файл), не жёсткие константы кода.
5. **Биомы — не землеподобные, под разнообразие рас** (решение п.16): кристаллические рощи, метановые моря, серные поля, радиационные ковры, струнные рощи и прочая экзотика рождаются. Стартовый набор 57 биомов — из материала @scientist/@writer (§5.4; полные таблицы — приложение).
6. **Вулканы — не отдельная сущность, частный случай генератора** (решение п.17): вулканические поля — один из биомов справочника. «Вулканический индекс» V — техническая промежуточная величина (§7). Отдельное аудит-правило под вулканы **не делаем**.
7. **Пороги типов планет (`classify.go`) — убираются из кода** (решение п.18): тип планеты — производный ярлык, вычисляемый **правилами в справочнике типов** (теги биомов + предикаты + пороги — данные; код — интерпретатор без чисел, §11).
8. **Леса/луга — с условием нетоксичной атмосферы** (решение п.19): земные биосферные формы требуют life + жидкую воду + нетоксичную атмосферу; на токсичных мирах — особые биомы («леса-экстремофилы»: кислотные дебри, хемосинтетические сады, серные поля), §6.
9. **Вулканизм — «один корень»:** вулканы в биомах и магмакамеры в недрах — от внутреннего тепла (ядро + радиоактивность). Лава — вулканизм, отфильтрованный температурой. Костыль «лава → магмакамеры» **убирается**.
10. **Формат данных — аддитивность:** биомы/недра-объекты отдельными полями; прежний сводный состав (`surface_composition` / `subterrain_composition`) **сохраняется**, но вычисляется из объектов автоматически. Миграция БД не нужна. Старые миры без биомов — фолбэк «нет данных» (не падать).
11. **Классификация типов** идёт после биомов (читает финальную поверхность — производный состав из биомов).

**В скоупе:** модель объектов биома/недр; справочник биомов (сущность, поля, хранение, стартовый набор); админка-редактор справочника (данные/потребность — §22, UI — @uidesigner); физика долей биомов и недр (категория-формулы + гейты условий справочника); правила типов планет в справочнике; вулканизм «один корень» (V — техническая величина); роли трёх «поверхностей» (слой 5 / слой 8 / биомы); аддитивный формат данных + whitelist API; перенос surface_bias на новую базу; судьба аудит-правил; газовые гиганты (явно без биомов); конфиг-дельта (справочник + полосы); прототип поселения (оверрайды через каскад — находка @critic №1).

**НЕ в скоупе** (границы — §19): формулы физики 99.2.20 (эталон), ядро (45а п.1), спутники, визуализация (отдельная идея), высадка, смена состояния биомов (создатель: «сейчас пока не надо ничего менять»), экзотические планеты, бэкфилл старых планет, миграции БД, вертикальное пространственное разделение биомов (облачные плавучие острова — отложено, §5.4).

## 2. Термины (кандидаты в GLOSSARY)

- **Биом** — экземпляр формы поверхности на планете: объект `{form, share}`, где `form` — id биома из справочника (§5), `share` — доля поверхности в %. Поверхность планеты = контейнер биомов, сумма долей = 100%. В v1 на планете не более одного биома одной формы (пространственная раскладка «кусков» — будущая визуализация, схема списком расширяема).
- **Справочник биомов** — редактируемый каталог определений «что бывает»: биомы поверхности, типы недр, правила типов планет, полосы климатов, матрица несовместимости, параметры токсичности. Живёт в конфиг-файле `config/biome_catalog.json` (сид — константы `composition_forms.go`), читается генератором и админкой (§5).
- **Форма поверхности** — термин сохраняется за константой-сидом (16 существующих имён); после ввода справочника «форма» = запись справочника. «Биом» — объект-экземпляр на конкретной планете.
- **Недра-объект** (зона недр) — экземпляр типа недр на планете: объект `{type, share}`, `type` — id типа недр из справочника.
- **Тег типа** — метка биома, ведущая в тип планеты (вулканический/биосферный/водный/ледяной/пустынный/стеклянный/металлический/каменный). Биом может нести несколько тегов. Сумма долей биомов с тегом — вход правил типов (§11).
- **Токсичная атмосфера** — признак атмосферы, вычисляемый от состава по порогам на каждый токсичный газ (SO₂ > 0.1%, H₂S > 0.1%, Cl₂ > 0.1%, NH₃ > 1%, CO > 1%, CH₄ > 1%, H₂SO₄-аэрозоль > 0.1% — любой превышен → токсичная; числа — предположение, калибровка; CH₄-порог 1%, не 5% — генерация даёт CH₄ строго <5%). Земные биосферные формы требуют «нетоксичную» (§6). Гейты биомов по атмосфере работают на **признаках по составу** (no_toxic/toxic/acidic/methane/nitrogen/co2/oxygen_free/dense — приложение §0), а не на ярлыках классификатора (ярлыки недостижимы генератором — находка @critic №2).
- **Вулканический индекс V** — техническая промежуточная величина 0–1, общий корень вулканизма поверхности и недр (§7). Не хранится в данных (производный от ядра), не является сущностью.

## 3. Модель объекта «биом» и «недра»

### 3.1. Биом (минимальный набор)

```json
{ "form": "кристальные_рощи", "share": 23.5 }
```

Минимально достаточный набор на этот релиз — **два поля** (`form` = id из справочника, `share`). Обоснование:

| Применение (создатель, идея §4.5) | Когда нужно | Какие поля добавит |
|---|---|---|
| Картинка (цвет/вид/рельеф) | задача «визуализация атмосферы и поверхности» (следующая) | `color`/`terrain` — производны от определения биома в справочнике (категория, описание); отдельные поля не требуются |
| Высадка (опасность/ресурсы/проходимость/пригодность) | будущая фича высадки | `hazard`, `passability`, `resources` |
| Изменения состояния (здоровье/освоен/загрязнён) | создатель: «сейчас пока не надо ничего менять» | `state` |

Правило: **новое поле биома — аддитивно** (JSONB, миграции нет), добавляется той фичей, которая его потребляет. Не закладываем спекулятивные поля сейчас (GD_PROMPT «сначала простота»).

### 3.2. Недра-объект (зона недр)

```json
{ "type": "рудные_жилы", "share": 12.0 }
```

Тот же паттерн. Поля состояния недр (выработка, затопление) — будущие фичи, аддитивно.

### 3.3. Природа сущности (архитектурный фильтр)

1. **Биомы планеты** — лог/результат-состояние (генераторный результат, как `surface_composition` сейчас), НЕ событие. Хранится в `planets.data` (JSONB), не в отдельной таблице — потребители читают снимок.
2. **Справочник биомов** — каталог определений (контент), НЕ лог и НЕ событие. Один глобальный экземпляр на игру, читается всеми генераторами и админкой. Живёт в конфиг-файле (развилка хранения — §5.2, гейт-вопрос А).
3. **Владелец** — одна планета → один набор биомов (1:1). Расширяемость на спутники — заложена схемой (список), но спутники вне скоупа.
4. **Расширяемость** — много типов (справочник — открытый класс: биомы/недра/типы планет пополняются контентом); схема списка переживает «несколько кусков одной формы» без изменения формата.

## 4. Порядок слоёв каскада — роли трёх «поверхностей»

Целевой порядок (решение создателя, идея §5):

`звезда → орбита → планета (состав) → ядро → T⁴ → атмосфера → флаг жидкой воды → поверхность (предв., слой 5, для альбедо) → недра (объекты, слой 9) → биомы (финальная поверхность объектами, новый слой 10)`

| Слой | Роль | Хранится в planet.data | Потребители |
|---|---|---|---|
| **5** (предв.) | Альбедо-прокси для T₀ — вход T⁴ (§3.5 99.2.20). Механизм **не меняется** (веса полосы × surface_bias, `GenerateSurfaceComposition` с T=0, вода=0) | нет (транзит) | T⁴-энергобаланс (эталон) |
| **8** (draft) | **Пробная поверхность** для мягких связей недр: физические веса биомов **без джиттера**, нормализованные (§6.3) | нет (транзит) | `applySurfaceToSubterrainLinks` (мягкие связи недр, кроме костыля лава→магмакамеры) |
| **10** (биомы) | **Финальная поверхность объектами** — полный конвейер: физические веса + surface_bias + гейты условий справочника + джиттер ±20% + матрица совместимости + нормализация (+ примитивные 3.5%) | да (`biomes`) | `surface_composition` (производный), `surface_dominant`, классификация (правила справочника типов), описания, ресурсы, аудит, модалка, API |

**Ключевые следствия:**

- **Слой 8 перестаёт быть финальной поверхностью** — транзитный draft-пробник (физические веса без джиттера, без потребления энтропии RNG — детерминизм по seed сохраняется).
- **Недра генерируются после draft и до биомов** — порядок «недра после поверхности» сохранён (5 мягких связей не теряются, требование @critic). Мягкие связи читают draft, а не финальные биомы — расхождение с финалом только на джиттер/матрицу, приемлемо для мягких множителей.
- **Классификация идёт после биомов** — вызывается в `planet_data_generate.go` после `runCascade`, читает `res.Surface` = производный состав из биомов; тип вычисляется правилами справочника (§11).
- **Гейт флага, матрица несовместимости, рандом ±20%** — остаются на своих шагах: гейт флага встроен в физические веса (§6.2), матрица/джиттер — в конвейере слоя 10.

## 5. Справочник биомов (новое, решение создателя п.15)

### 5.1. Что это

Справочник — редактируемый каталог определений «что бывает»: **биомы поверхности, типы недр, правила типов планет, матрица несовместимости, параметры** (пороги токсичности/кислотности). Заменяет жёсткие константы `composition_forms.go` (16 форм + 17 типов недр) и пороги `classify.go` как источник «что существует». Константы остаются **сидом имён** (обратная совместимость старых миров); полный каталог 57 биомов — сид справочника (встроенный дефолт, источник определений 41 нового биома — материал @scientist/@writer, приложение §1).

**Разведение файлов (находка @critic «полосы в справочнике vs planet_archetypes»):**

- `config/biome_catalog.json` — биомы (включая `bands` — полосы, где биом возможен), типы недр, правила типов планет, матрица, параметры. Пишется админкой (§22).
- `config/planet_archetypes.json` — полосы климатов: `base_surface`/`base_subterrain` **только как веса** для альбедо-прокси слоя 5 и предварительных недр ядра (механизм 99.2.20 не меняется), allowed-списки гидросфер/атмосфер/биосфер. Пишется админкой (§22). **Whitelist биомов в полосах НЕ хранится** — он в `bands` биома (§6.2).

### 5.2. Где живёт (развилка хранения; предложение по умолчанию — вариант А)

**Вариант А (рекомендую): конфиг-файл `config/biome_catalog.json` + in-memory store + админка пишет файл атомарно (tmp + rename).**

- Паттерн уже есть: `race_balancer.json` (tmp+rename, битый JSON → лог, hot-reload через store), пресеты балансировщика (99.2.17 §5), `composition_compatibility.go` (LoadCompatibilityMatrix + RWMutex-кэш).
- Плюсы: контент-каталог в git — рецензируемость диффом и восстановление; правки переживают рестарт; hot-reload атомарной заменой store (как `SetCurve`).
- Цена/риски: лок на запись (сериализация через серверный хендлер); файл в рабочем дереве — правки админки попадают в git (решить на деплое, как race_balancer.json); валидация при загрузке (битый JSON → лог + сид, сервер не падает).

**Вариант Б: БД** (таблица `biome_definitions` + миграция + сидер при первом старте, как `goods_catalog_seed` студии товаров). Плюсы: многопользовательская админка безопаснее, история правок. Цена/риски: миграция, CRUD, API; каталог определений — статичный контент, который хочется видеть в git; для контент-каталогов проект использует файлы (races.json, planet_archetypes.json, families.json).

**Решение по умолчанию: вариант А** — консистентно с существующими контент-каталогами. Гейт-вопрос А.

### 5.3. Поля определения биома (что редактируется руками vs производное)

**Редактируется руками (контент):**

| Поле | Тип | Семантика |
|---|---|---|
| `id` | строка | уникальный ключ (например «кристальные_рощи»); на него ссылаются планеты, производный состав, аудит, ресурсы. **Не редактируется после создания** (переименование = миграция данных планет) |
| `name`, `category`, `description` | строка | отображаемое имя; категория (литосфера/вода/биосфера/вулканизм/крио/экзотика — группировка UI, ресурсный маппинг, матрица); художественный образ (из @writer) — для будущей энциклопедии/визуализации |
| `t_range`, `p_range`, `water_range`, `composition_min`, `gravity_range` | K, атм, %, {iron,ice,rock}, g | диапазоны, где биом в принципе возможен (гейты, §6.2) |
| `needs_light` | bool | биосферный фотосинтез требует света (хемосады/светящиеся чащи — false) |
| `liquid_medium` | enum | вода / метан / аммиак / co2 / нет — определяет фазу и несовместимости (разные жидкие среды на одной поверхности запрещены, инвариант 13) |
| `atmosphere_ok` | [string] | список **признаков по составу** (приложение §0): no_toxic / toxic / acidic / methane / nitrogen / co2 / oxygen_free / dense; все должны выполняться (AND); пусто = «любая». Ярлыки классификатора НЕ используются (недостижимы генератором — находка @critic №2) |
| `bands` | [string] | полосы, где биом возможен (э/ж/у/х) — **whitelist из справочника** (находка @critic №1); проверяется против полосы по T_final в шаге 3 §6.2 |
| `volcanism` | enum | не зависит / требует V>0 / требует V и T≥500 (лава) |
| `requires_radiation`, `requires_tidal_lock`, `requires_life`, `requires_liquid_water` | bool | радиационные — **источник флага: среда поверхности, P_surf < 0.5 атм** (тонкая атмосфера/магнитосфера → радиолиз), НЕ радиоактивность ядра (ядро вне скоупа); терминаторные (`tidal_lock`); биосферный (строгий гейт); водный биосферный |

- Доли биомов на конкретной планете (§6) — физика, не справочник (решение п.6).
- Совместимость пар — автоматическая от `liquid_medium` (попарно несовместимы вода/метан/аммиак/co2) + ручные пары матрицы (§5.6).
- Тип планеты — правила справочника типов от тегов и долей (§11).
- Визуальные параметры (цвет/вид) — будущая визуализация, производны от категории/имени.

- **Гейты «что физически невозможно» учтены:** вода и метан/аммиак/CO₂ несовместимы на одной поверхности (жидкость-гейт, авто-матрица §5.6); метановые миры — бескислородные; H₂SO₄ на горячей поверхности не моделируется; фотосинтез без света запрещён (`needs_light = false` у хемосадов/светящихся чащ/радиационных ковров); высота «деревьев» на высоких g ниже.
- **Гейт биосферы:** все биосферные формы — `requires_life`; земные — жидкая вода + `no_toxic` (решение п.19, закрывает @critic №2). Экстремофилы (кислотные дебри — `toxic` + tuned, хемосады — геотерма, радиационные ковры — радиация) — жизнь без нетоксичной атмосферы/света.
- **Флаги радиации/приливного захвата заполнены:** `requires_radiation` (источник — P_surf < 0.5 атм) — радиационные_пустоши, радиационные_ковры; `requires_tidal_lock` — терминаторная_зона.
- **Bands ↔ вилки сверены** (находка @critic №11): у каждого биома bands пересекаются с t_range (мёртвые полосы убраны); песчаные биомы расширены в жаркий пояс (пески 280–500, соляные/танцующие/грозовая 250–400) — жаркий пояс не обеднён песчаным контентом, пустынный тип достижим в жарком (правило — на тег «пустынный», приложение §3).
- **Минеральные «леса»** — НЕ биосфера (жизнь не требуется) — рождаются на стерильных мирах (решение п.16).
- **Отложено (вертикальная/аномальная модель):** облачные плавучие острова, сад нулевого тяготения (кандидат ГД-сущности, §18), море «которое дышит» (объединено с термальными террасами).

### 5.5. Типы недр (17 существующих, условия в справочнике)

Существующие 17 типов недр остаются как есть (сид имён); в справочник добавляются условия появления (T/вода/V/состав/life), `bands` и `weight_base` — полная таблица в приложении §2. Новые типы недр в этот релиз не вводятся (открытый класс). Примеры: магматические_камеры — V>0; подземные_льды — T<273 и вода>0; угольные_пласты — life; соляные_купола — океаны>0 в draft (bands ж/у — мягкая связь «океаны→соль» жива, находка @critic №1).

### 5.6. Матрица несовместимости

- **Автоматическая часть (от физики):** пары с разными `liquid_medium` из {вода, метан, аммиак, co2} — несовместимы на одной поверхности (вода×метан, вода×аммиак, вода×co2, метан×аммиак, метан×co2, аммиак×co2 — находка @balancetester П3); лава/магмовый океан несовместимы с водными/крио-водными.
- **Ручная часть:** существующая матрица `compatibility_defaults.json` (паттерн `composition_compatibility.go`) — редактируется в админке (пары биомов).

## 6. Физика долей биомов

### 6.1. Входы (все доступны к слою 10: ядро — слой 4, T_final/атмосфера/флаг — слои 5–7, недра — слой 9)

`T_final` (K), `P_surf` (атм), флаг жидкой воды `flag`, `water%` (0–100), `F_int` (Вт/м², `core.heat_flux_w_m2`), `core.Activity` (0–100), `core.Radioactivity` (0–100), объёмный состав планеты (доли rock/iron/ice), `gravity` (g), `life` (bool), `biosphere` (ярлык), состав атмосферы (для признаков токсичности/атмосферы), `tidal_lock` (bool), полоса по T_final (`bandForTemp`), `bands` биома (whitelist из справочника), `surface_bias` (профиль региона).

### 6.2. Вес биома = база × категория-формула × гейты условий справочника

**Общая формула (ядро дизайна; числа — предположение дизайнера, эталон не задан — калибровка @balancetester):**

```
w(form) = weight_base(form) × f_category(form, планета) × Π g_condition(условие, планета)
```

- `weight_base` — из справочника (насколько биом вообще распространён).
- `f_category` — одна из формул по категории (код, ~6 формул):
  - **литосфера:** `1.0`; горы — страховка: `0.55 + 0.45·clamp(gravity/1.5, 0, 1)` (рельеф от гравитации, всегда > 0);
  - **вода:** `flag ? (w/100)^k : 0`, k = 2 для океанов, 1 для озёр/мелководий;
  - **биосфера:** земные — `life && flag && !toxic ? 1 : 0` × температурный комфорт `smooth(T, 250, 330)`; экстремофилы/хемосады — `life ? 1 : 0` (без нетоксичной);
  - **вулканизм:** `V` (вулканические поля при любой T — Ио) или `V·smooth(T, 500, 700)` (лава — только горячо);
  - **крио:** `(1 − smooth(T, lo, hi))·(вода или ice)` — ледники/мёрзлые газы/азотная тундра;
  - **экзотика:** специфические условия (радиация, tidal_lock, гравитация, состав) — по записи справочника.
- `g_condition` — гладкий гейт (smoothstep 0→1 на границах диапазона) по каждому условию справочника: T, P, вода, состав, g, жидкость, атмосфера, вулканизм, радиация, tidal_lock, life, свет. Условие вне диапазона → вес = 0.

**Признак токсичности атмосферы** (решение п.19; согласовано с генерацией — находки @critic №3/@balancetester): `toxic` — любой токсичный газ выше порога (SO₂ > 0.1%, H₂S > 0.1%, Cl₂ > 0.1%, NH₃ > 1%, CO > 1%, CH₄ > 1%, H₂SO₄-аэрозоль > 0.1%; числа в справочнике — предположение, калибровка). **CH₄-порог 1% (не 5%)** — генерация даёт CH₄ строго <5%, порог «>5%» не срабатывал бы никогда. Считается от `atmosphere_data.composition`. Достижимость `toxic`: жаркие серные миры (SO₂ ≈ 1%) — токсичны; холодные метановые (CH₄ 1–5%, внешняя зона) — токсичны/бескислородны; **умеренные токсичные миры (H₂S/SO₂/NH₃-обогащение) — только tuned-подкрутка 99.2.22** (на фоне не возникают — явная зависимость экстремофилов умеренных T от подкрутки). Прочие атмосферные гейты биомов — признаки по составу (приложение §0), все достижимы генератором.

**Порядок применения (слой 10):**

1. Веса по формуле (детерминированно, без RNG).
2. `surface_bias` (профиль региона): `w_i ×= bias_i` для форм из bias (форма вне bands полосы — no-op, ограничение O4 сохраняется, §12).
3. **Whitelist-гейт полосы (bands):** полоса выбирается по T_final (`bandForTemp`); биом возможен, только если его полоса в `bands` биома (справочник). **Источник whitelist — `bands` биома, а не ключи `base_surface` полосы** (находка @critic №1: по ключам полос не рождались бы 38 из 57 биомов; решение п.16 выполняется на сиде — приложение §1). `base_surface` полосы — только веса альбедо-прокси слоя 5.
4. Джиттер ±20% (существующий `applyRandomJitter`).
5. Матрица совместимости (существующий `resolveConflicts` + авто-часть от жидкости, §5.6).
6. Нормализация к 100%, отсев нулевых (`Normalize().NonZero()`).
7. **Страховка «минимум 1 биом»:** пустой результат → `fallbackComposition(base)` (существующий механизм) — гарантия ≥ 1 биома (закрывает @critic №5).
8. Примитивные планеты (~3.5%): `simplifyComposition` на состав биомов (и недр) — как сейчас.

### 6.3. Draft слоя 8 (пробник для мягких связей недр)

Те же шаги 1–3 (веса + bias + whitelist), нормализация, **без джиттера и матрицы** (шаги 4–5 пропущены), без потребления энтропии RNG. Результат — транзитная карта форма→доля, вход мягких связей недр.

## 7. Вулканизм — «один корень» (техническая величина, не сущность)

**Решение создателя (идея §2 п.10, п.17):** вулканы — не отдельная сущность, а биомы справочника; и вулканы в биомах, и магмакамеры в недрах — от **внутреннего тепла планеты** (ядро + радиоактивность). Лава — тот же вулканизм, отфильтрованный температурой.

**Вулканический индекс V — техническая промежуточная величина** (не тема спеки, не сущность, не хранится в данных):

```
V = clamp(0.4·(Activity/100) + 0.6·clamp(F_int/50, 0, 1), 0, 1)
```

Калибровка: Земля (Activity 70, F_int 0.056) → V ≈ 0.28 (вулканы есть, лавы нет — T<500); молодая горячая (Activity 80, F_int 800) → V ≈ 0.92; мёртвая холодная (Activity 10, F_int 0.02) → V ≈ 0.04; Ио-режим (холодная молодая) → V высокий, лава = 0 (T<500).

Реализация:

- **Поверхность:** вулканические_поля = `weight_base·V` при любой T (Ио); лавовые_поля = `weight_base·V·smooth(T,500,700)` — только где T ≥ ~500 K; магмовый_океан — `weight_base·V·smooth(T,1200,1500)`; серные_поля — `weight_base·V` при любой T (Ио-тип, гейт кислотной атмосферы снят — находка @critic №6); криовулканические поля — `weight_base·V` при T 90–200 (водно-аммиачная слизь).
- **Недра:** магматические_камеры = `weight_base·V` (§8) — тот же индекс V, общий корень.
- **Убирается костыль** `applySurfaceToSubterrainLinks` (блок «лава+вулканы > 25 → магмакамеры ×1.4»): он дублировал общий корень и давал двойной счёт лавы. Остальные 4 мягкие связи (океаны→нефть/соль/осадок, леса+болота→уголь/нефть, ледники→подземные льды/кристаллы, кратеры→руды/редкоземельные) **сохраняются** (идея §4.8).
- **Аудит-правило под вулканы — НЕ делаем** (решение создателя п.17): отдельное `volcanism_without_heat` из v1 **снимается**. Согласованность биомов с физикой проверяется общими правилами (§14): лава только при T≥500 (по построению), вулканические биомы только при V>0 (по построению), сумма = 100.

## 8. Физика долей недр

Тот же паттерн, что §6. Входы: те же + draft поверхности (мягкие связи). Вес типа недр = `weight_base` (справочник) × категория-формула × гейты условий (T/вода/V/состав/life). Категории недр: породы (база), вулканические (V), осадочные (flag/P), биогенные (life), водные (flag/вода), ледяные (T/вода), рудные (iron/V), радиоактивные (Radioactivity), карстовые (вода/V). Стартовый сид условий и bands — приложение §2.

Порядок: веса → `subterrain_bias` (профиль региона, новая база §12) → **whitelist-гейт полосы по `bands` типа недр** (как у биомов, §6.2; находка @critic №2 — по ключам `base_subterrain` мертвы соляные_купола/редкоземельные/газовые_карманы/пещерные_системы) → мягкие связи от draft (§7, кроме костыля) → джиттер → матрица → нормализация → примитивные 3.5%. `determineCoreActivity`/`determineCoreRadioactivity` (ядро, слой 4) читают недра **предварительной полосы** (`base_subterrain` — только веса для ядра) — сохраняется как есть (ядро вне скоупа; влияние конфиг-дельты на ядро — честно, §15).

### 9.5. Газовые гиганты

Поверхности/недр не имеют (99.2.15/99.2.20) → **биомов и зон недр нет** (пустые массивы/отсутствие ключа). Зафиксировать явно: `runCascadeGiant` не заполняет `biomes`/`subterrain`; модалка и API не падают.

## 11. Классификация типов планет — правила в справочнике (решение п.18)

**Проблема (решение создателя):** «Должны физикой биомы генериться, а не тем, что мы жёстко в код прописали». Жёсткие константы-пороги `classify.go` (15/20/25%, presence/volcanic/desert/biosphere) — кандидаты на перенос в справочник.

**Развилка (разворот подходов, §24):**
- (а) **Тип = производный ярлык от тегов биомов**: каждый биом знает теги; тип = доминирующий тег. Просто, но теряет тонкие правила (землеподобная требует settleable+life+горы+вода — не сводится к тегу).
- (б) **Пороги в конфиге, логика как сейчас**: числа уезжают из кода, но порядок проверок остаётся кодом.
- (в) **Правила в справочнике типов** (рекомендую): список правил (предикаты + пороги + порядок) — данные; код — интерпретатор без чисел.

**Принято: (в).** Тип планеты — производный ярлык, вычисляемый правилами справочника типов (секция `planet_types` файла `config/biome_catalog.json`). Полный JSON-сид — приложение §3; формат:

```json
{ "id": "вулканическая", "predicates": [
    { "type": "tag_sum", "tag": "вулканический", "min": 20.0 } ] }
```

Предикаты: `settleable`, `life`, `radioactive_core`, `is_gas_giant`, `dominant_form`, `share_of` (форма, min), `tag_sum` (тег, min), `temperature` (lt/gt), `water_percent` (lt/gt), `any_of` (список форм, min), `and`/`or` (композиция). Порядок правил — сверху вниз, первое сработавшее → тип; фолбэк «скалистая (базовая)».

**Следствия:**

- **Пороги 15/20/25% больше не диктуют «как выглядит планета»:** доли биомов — физика (§6), тип — ярлык поверх; пороги — редактируемые данные.
- **Все 12 ГД-типов покрыты правилами** (находка @critic №3): «радиоактивная» — `radioactive_core`, **первое правило списка** (газовый гигант — отдельный флаг вне списка — как в `classify.go`: гигант → радиоактивная → остальные; находка @critic №10), добавлена в сид (приложение §3); таблица покрытия — приложение §3. Потребители (аудит `checkRadioactiveConsistency`, `descriptions_mapping.go`, UI/фильтры/статистика) тип не теряют.
- **Конфликт @balancetester (В2) снят:** старые пороги калибровались под старые веса полосы; теперь веса — физика, пороги — данные справочника. Калибровка = смоук распределения + правка порогов/`weight_base` в админке (не код). Ожидаемые доли типов и метод калибровки — §21.
- **Код `classify.go` становится интерпретатором правил** (без чисел); `AllGameDesignTypes` — из справочника (для UI/фильтров/статистики).
- **Новые типы — открытый класс** (контент справочника), в этот релиз не вводятся (гейт-вопрос Ж).

## 12. surface_bias / subterrain_bias (99.2.10) — перенос на новую базу

**Проблема:** ручки профиля региона умножают веса полосы (`cascade.go:386-387`, `ApplyMultMap` на `baseSurface`/`baseSubterrain`). С переходом долей на физику веса полосы перестают быть источником долей — без переноса ручки станут мёртвыми (находка @critic, идея §8 п.4).

**Двойная точка применения (уточнение — находка @critic «§12 vs §4»):** `surface_bias` применяется в **двух местах**, и это не «замена», а добавление второй точки:

1. **Веса полосы для альбедо-прокси слоя 5** — как сейчас (`cascade.go:386-387`), механизм 99.2.20 не меняется: bias влияет на T₀ через альбедо.
2. **Физические веса биомов слоя 10** (новая точка, шаг 2 §6.2); `subterrain_bias` — физические веса недр (шаг 1 §8).

Обе — до whitelist-гейта (bands), джиттера и нормализации. Двойное влияние названо честно: профиль региона влияет и на T₀ (через альбедо), и на доли биомов — это ожидаемое поведение профиля (регион «плодородный» и греет, и даёт биосферу).

**Правило «форма вне шаблона» (O4) — переопределяется:** bias может усилить только форму, **возможную в полосе** (в `bands` биома). Форма вне bands — no-op. Гейт флага фильтрует по физике независимо от bias (bias «океаны» на горячей планете — no-op: флаг false, вес океанов = 0). Семантика мягкости (0.3/0.6/1.0 интенсивности) и валидация конфига — **без изменений**.

**Согласование с владельцем 99.2.10:** спека 99.2.10 §8 и §11 инвариант 6 «каскад не модифицируется» — дельта: точка применения surface_bias/subterrain_bias меняется с «веса полосы» на «физические веса биомов/недр»; O4-формулировка обновляется; инвариант → «сдвигаются входы и физические веса» (формулы физики 99.2.20 по-прежнему не трогаются). `resource_bias` (P2) — без изменений.

## 13. Совместимость с 99.2.22 (подкрутка рас)

- Ручки 1–4, 6 (орбита, состав, давление, возраст, число планет) — входы каскада, **не меняются**.
- Ручки 7/7-холод (`SurfaceOverride`, A = 0.15) — влияют только на альбедо T₀ (слой 5). Биомы генерируются физикой от T_final — **не читают SurfaceOverride**. Расхождение «альбедо-оверрайд (0.15) vs финальные биомы» — та же абстракция, что зафиксирована в 99.2.22 §3.5б (косметическое, не ломает окна).
- **Синергия:** tuned-миры тепловых рас (молодой возраст → высокий F_int → высокий V) получают вулканические биомы; холодные tuned-миры — вулканы без лавы (Ио), ледники/мёрзлые газы по T.
- **Новое (решение п.19):** земные биосферные формы требуют нетоксичную атмосферу. tuned-миры рас с токсичными атмосферами (серные, метановые) получают экстремофилы/серные поля, а не земные леса — консистентно с окнами рас.
- `Race.Suitable` не читает поверхность — смоук 99.2.22 не зависит от биомов; прогон перепроверяется баланс-тестером (§21 п.8).

### 15.2. Роль полей `config/planet_archetypes.json`

Доли биомов/недр — физика (§6, §8).

Содержательная дельта (веса для альбедо-прокси и предварительных недр ядра становятся физически точными; whitelist-роль снята):

- `умеренный.base_surface`: + `вулканические_поля` (вес ~0.03) — вулканы возможны при любом T (Ио-правило);
- `холодный.base_surface`: + `вулканические_поля` (вес ~0.03), + `криовулканические_поля` (вес ~0.02);
- `умеренный.base_subterrain`: + `магматические_камеры` (вес ~0.03);
- `холодный.base_subterrain`: + `магматические_камеры` (вес ~0.02);
- `жаркий.base_surface`: + `серные_поля` (вес ~0.03) — едкая атмосфера + вулканизм;
- `экстремальный.base_surface`: + `магмовый_океан` (вес ~0.05) — молодые адские миры.

Веса остальных новых биомов в полосах — **опционально** (для точности альбедо-прокси T₀); по умолчанию слой 5 работает на существующих весах (горы/пески/океаны и т.д.), что достаточно для T₀. Калибровка §21.

**Честное описание влияния (находка @critic №3):**

1. **Альбедо слоя 5:** вулканические_поля (A = 0.12) ≈ горы (A = 0.15) — сдвиг T₀ пренебрежимо мал; у tuned-миров альбедо фиксировано оверрайдом 0.15. Магмовый океан (A = 0.60) в экстремальном — заметный сдвиг альбедо вниз → T₀ выше на горячих молодых мирах (эффект вторичный: экстремальные и так за пределами обитаемости; калибровка §21).
2. **Активность ядра (недр):** `determineCoreActivity` читает **предварительные недра** (bandSubterrain = base_subterrain × subterrain_bias). Добавление `магматические_камеры` (вес 0.02–0.03) в умеренный/холодный → ShareOf ~2–3% → Activity +3–4.5 пункта → V +0.01–0.02 → вулканические биомы чуть чаще (после нормализации ~0.1–0.3% доли). Приемлемо, названо; это следствие «одного корня» (недра → ядро → вулканизм), а не баг.
3. **RNG-поток:** добавление форм в полосы меняет число форм → сдвиг последовательности роллов (детерминизм по seed сохраняется внутри новой версии генератора; «золотых» значений нет — PITFALLS «точные значения не детерминированы»).

### 16.1. Прототип поселения — оверрайды через каскад (находка @critic №1)

**Проблема:** `GeneratePrototypePlanet` применяет оверрайды (`temperature=288 / water_percent=80 / liquid_water_possible=true / life=true`) **после** каскада (пост-правка JSON, `planet_data_generate.go:497–515`) → биомы (генерируются в каскаде от фактических T_final/воды) разойдутся с данными: прототип покажет «землеподобная», а биомы будут от каскадной физики (орбита 1 G-звезды без форсирования → T_final ≈ 365 K — пустыни/степи вместо лесов).

**Решение (рекомендую): провести ручные параметры через каскад как оверрайды входов.** В `cascadeInput` добавляются поля (паттерн существующих оверрайдов MassOverride/SizeOverride/FVolOverride):

- `FinalTempOverride float64` — применяется после слоя 7 (жизненный проход): `res.TFinal = FinalTempOverride`; **флаг жидкой воды пересчитывается** от оверрайда (`liquidWaterPossible(FinalTempOverride, pressure)`) — инвариант «флаг ⟺ (P, T_final)» сохраняется;
- `WaterPercentOverride float64` — применяется до слоя 8: `res.WaterPercent = WaterPercentOverride`;
- `ForceLife` (уже есть) — форсирует жизнь (жизненный проход → азотно-кислородная атмосфера).

`GeneratePrototypePlanet`: вместо пост-оверрайдов JSON — входы каскада (`FinalTempOverride=288`, `WaterPercentOverride=80`, `ForceLife=true`); в данные пишется отметка `"prototype_forced": true` (для аудита/осознанности). Биомы генерируются от форсированных значений → согласованы с данными (леса/луга/океаны при T=288, вода=80, life).

Альтернатива (отклонена): пост-пересчёт биомов после оверрайдов — биомы живут внутри каскада, пересчёт снаружи дублирует конвейер (риск расхождения).

## 17. Инварианты

1. **Сумма биомов = 100**, сумма зон недр = 100 (нормализация; аудит `surface_sum_not_100`/`subterrain_sum_not_100` не срабатывают).
2. **Форма биома / тип недр — из справочника** (валидация на сборке по загруженному справочнику, не по константам; неизвестное имя — ошибка, не молчаливый пропуск). Старые миры с неизвестными именами — фолбэк (§16).
3. **Косметика не противоречит физике** (инвариант 99.2.20): биомы — функция от (T_final, P, флага, воды, состава, ядра, атмосферы), не наоборот.
4. **Лава только при T ≥ 500** (гейт smoothstep; аудит `lava_in_cold` не срабатывает). **Вулканы возможны при любой T** (Ио).
5. **Вулканизм и магмакамеры — один корень V** (F_int + активность ядра; V — техническая величина); костыль поверхность→недра удалён.
6. **Аддитивность:** `surface_composition`/`subterrain_composition` — производные от объектов; генератор пишет объекты, карты считаются одной функцией.
7. **Детерминизм по seed:** draft (слой 8) не потребляет энтропию RNG; биомы — фиксированная позиция роллов в конвейере; тот же seed → те же планеты (для новой версии генератора).
8. **Старые миры без биомов не падают** (фолбэк nil/пусто; потребители читают старые карты).
9. **Газовые гиганты без биомов/недр** (пусто, не ошибка).
10. **Все типы планет возможны** (профили 59a и подкрутка 99.2.22 не ломаются: bias/ручки — множители > 0, bands не запрещают физически возможное).
11. **surface_bias O4:** форма вне bands полосы — no-op (мягкость профиля сохраняется).
12. **Земные биосферные формы: life + жидкая вода + нетоксичная атмосфера** (решение п.19; аудит `biosphere_without_conditions`).
13. **Вода и метан/аммиак/CO₂ несовместимы на одной поверхности** (жидкость-гейт, авто-матрица §5.6; вертикальное разделение — будущее).
14. **Минимум 1 биом** (страховка `fallbackComposition`; аудит `empty_biomes` — только «ключ есть и пуст»).
15. **Тип планеты — из правил справочника типов** (код — интерпретатор без чисел; пороги 15/20/25 — данные).

## 18. Кандидат ГД-сущности (Вопрос → Ответ; в текущие числа НЕ входит)

**Вопрос:** даёт ли фича «биомы объектами + справочник» естественных кандидатов на новые ГД-сущности?

**Ответ (кандидаты):**

1. **«Освоение биома»** (из v1) — состояние на объекте биома (`state`: здоровье/освоен/загрязнён), которое меняется игроком/поселением: терраформирование куска поверхности, загрязнение промышленностью, истощение ресурсов биома. Биом-объект — готовая точка привязки (создатель: «Дальше с ними можно будет работать, изменять их состояние»). Зависимость: фича смены состояния биомов — отдельная, после визуализации; в числа этой спеки не входит.
2. **«Сад нулевого тяготения»** (визитка @writer) — регион с аномально слабой гравитацией (плотное ядро с полостью): парящие скалы, реки вверх. Требует особой модели гравитации — отложено из набора биомов (§5.4) как кандидат на отдельную фичу. В числа не входит.

6. **Токсичность (решение п.19):** земные леса/луга/джунгли только при нетоксичной атмосфере (0 срабатываний `biosphere_without_conditions`); кислотные дебри/серные поля — на токсичных мирах с life; доля токсичных миров с земными лесами = 0. **Согласование с генерацией** (находки @critic №3/@balancetester): CH₄-порог 1% (генерация даёт строго <5%, порог «>5%» мёртв); жаркие серные миры (SO₂ ≈ 1%) — токсичны; холодные метановые (CH₄ 1–5%, внешняя зона) — токсичны; **умеренные токсичные (кислотные_дебри, T 260–320) — только tuned 99.2.22** (на фоне 0 — ожидаемо, заявлено).

## 27. Инварианты и проверки (TDD)

1. **Суммы = 100** (юнит): биомы и зоны недр после конвейера дают сумму 100; пустой вход → фолбэк (`fallbackComposition`) — минимум 1 биом.
2. **Формы/типы — из справочника** (юнит): валидатор на сборке отклоняет неизвестное имя формы/типа (по загруженному справочнику, не по константам); **биом с пустыми `bands`, расхождением bands↔t_range или недостижимым признаком атмосферы — ошибка загрузки** (инвариант 17; находка @critic №8).
3. **Лава ↔ T** (юнит): при T < 500 лавовые_поля = 0; при T ≥ 500 и V > 0 лава > 0; вулканические_поля > 0 возможны при любой T (Ио-тест: T = 130, V = 0.9 → вулканы есть, лавы нет).
4. **Один корень** (юнит): V одинаков для поверхности и недр (магматические_камеры = f(V)); костыль «лава → магмакамеры» удалён (тест на отсутствие правила).
5. **Draft без энтропии** (юнит): draft (слой 8) детерминирован — два вызова с тем же входом дают тот же результат; RNG-поток не сдвигается.
6. **Аддитивность** (юнит): `surface_composition` = производная от `biomes`; `subterrain_composition` = производная от `subterrain`.
7. **Whitelist API** (юнит/интеграция): `models.Planet` + `populatePlanetFromJSON` отдают `biomes`/`subterrain`; отсутствие ключа → nil, не ошибка.
8. **Старые миры** (юнит): planet.data без `biomes` → потребители работают на старых картах; `empty_biomes` НЕ срабатывает (отсутствие ключа ≠ пусто).
9. **Газовые гиганты** (юнит): `runCascadeGiant` не заполняет `biomes`/`subterrain`; API отдаёт пусто/omitempty.
10. **Биосфера ↔ условия** (юнит): земная биосферная форма (тег «биосферный» + `no_toxic`) при отсутствии life/жидкой воды/нетоксичной атмосферы — вес 0; экстремофилы (кислотные дебри `toxic`/хемосады/радиационные ковры) — возможны при life без нетоксичной; `biosphere_without_conditions` — 0 срабатываний.
11. **Жидкость-гейт** (юнит): вода, метан, аммиак и CO₂ попарно несовместимы на одной поверхности (авто-матрица §5.6).
12. **Правила типов** (юнит): интерпретатор справочника типов даёт те же типы, что старый `classify.go`, на эталонных наборах (Земля → землеподобная, Венера → вулканическая/стеклянная, Марс → пустынная/скалистая, Титан-профиль → ледяная, радиоактивное ядро → радиоактивная); **все 12 типов покрыты правилами**; пороги читаются из справочника, не из кода.
13. **Прототип (критик №1)** (юнит/интеграция): `GeneratePrototypePlanet` с оверрайдами через каскад — биомы согласованы с данными (T=288, вода=80, life → леса/луга/океаны; флаг true; `prototype_forced` в данных).
14. **Справочник-редактируемость** (юнит/интеграция): загрузка `biome_catalog.json` (валидация, битый JSON → лог + сид); PATCH-хендлеры пишут файлы атомарно + hot-reload store; правка `weight_base` меняет распределение (смоук).
15. **surface_bias O4** (юнит): bias «океаны» на горячей планете (флаг false) — no-op; bias «луга» в «плодородном» регионе — усиливает вес до нормализации; bias применяется в двух точках (альбедо слоя 5 + веса биомов слоя 10).
16. **Не-регрессия:** тесты каскада 99.2.20 (Земля/Венера/Марс/O-звезда/гигант), 99.2.10 (регион-профили), 99.2.22 (смоук 20 рас), `planet_data_simple_test` (примитивные ≈ 3.5%) — зелёные.
17. **Смоук распределения** (§21): типы планет не вырождаются (океаническая ≥ 3–5%, ледяная ≥ 8–12%, скалистая < 45%); вулканизм коррелирует с F_int; число биомов 4–9 типично; **все 57 биомов достижимы (каждый встречается в смоуке; азотно-ледяная тундра — по гейту co2+oxygen_free; метановые — во внешней зоне; аммиачные — в смоуке с tuned 99.2.22)**; земные леса только на нетоксичных.
18. DoD: `go build ./...`, `go vet ./...`, `go test -race ./...` (локально, AGENTS.md §2).
