# 99.2.28-ui — «Справочник биомов» в админке: раздел справочника на вкладке «Основное» (UI/UX-ТЗ)

**Статус:** дизайн — на проверку
**Дата:** 2026-09-20
**Связи:** спека docs/specs/99.2.28-biomes-planet-surface.md §22 «Что нужно от админки» (данные/поля/валидации — источник истины), приложение §5.4 «Справочник биомов»; код-паттерны админки: settlementSettings.js (карточка + PATCH + тосты), 	abs.js (вкладки + ленивая инициализация), worlds.js (список/поиск/пагинация/таблица), uth.js (getAdminRole, etchWithAuth), main.js (сокрытие вкладки «Пользователи» по роли), dmin.html #tab-main (карточки §5.1/§5.2), dmin.css (.card, .compact-row, .chip, .seg, .btn).

**Что это:** UI-дельта-ТЗ поверх 99.2.28 §22. Проектирует интерфейс «Справочника биомов» (биомы поверхности, типы недр, типы планет, полосы климатов, матрица несовместимости, параметры). **Дизайн вклад-дизайн:** макеты, компоненты, состояния, реактивность, валидации, права. **Код не пишу** (зона @developer); серверные хендлеры GET/PATCH /admin/biome-catalog — зона @developer по спеке §22 п.9. Стилевые константы использую существующие из dmin.css; новые стили — только если нужны (помечаю как предложение).

**НЕ в скоупе:** семантика данных и числа баланса (зона @designer/@balancetester); калибровка весов; логика генерации/долей; стилистика мира (зона @gdesigner). Правки справочника **применяются только к новым мирам** — бэкфилл запрещён (инвариант 17).

---

## 1. Цель и принципы

Дать создателю инструмент правки справочника биомов, не выходя из админки, по паттерну
уже работающей карточки «Настройки населения» (settlementSettings.js): открыл вкладку —
увидел текущее состояние, отредактировал, сохранил, получил тост. Справочник — **данные,
а не код**: админка пишет файл config/biome_catalog.json атомарно (tmp + rename),
store перезагружается hot-reload, правки применяются к новым мирам.

**UX-принципы:**

1. **Реактивность от первого кадра:** список и формы — не пустышки: лоадер-строка,
   пустые состояния, тосты (паттерн worlds.js/
otifyError/
otifySuccess).
2. **Никаких голых полей «на веру»:** каждый редактор сопровождается подсказкой
   (что поле означает, где гейт), валидация клиентская + серверная, ошибки — тостом.
3. **Правка не мгновенна:** подпись «применяется к новым мирам; бэкфилл запрещён» +
   кнопка-переход на вкладку «Генерация».
4. **Изменено/сохранено — всегда видно:** индикатор на карточке, без «молчаливого» статуса.
5. **Права:** правка — роль dmin; чтение — dmin + skycomposer (read-only, §6).

## 3. Признаки атмосферы (приложение §0) — единый источник для мультивыбора

Сервер валидирует: **bands биома не пуст** и **признаки атмосферы из перечня §0** (инвариант 17). Поскольку в спеке §0 признаки передаются **явным enum в данных биома** (в отличие от ярлыков 99.2.17), мультивыбор в формах **биома** и **типа недр** строится из полного списка признаков §0. **Используем минимальное редактируемое подмножество** (гейт §4): атмосферные поля редактируются **только через признаки §0**, а не свободным списком газов — консистентно с инвариантом 17 и §0 приложения.

Таблица признаков (определение/порог — данные, зона @developer проектирует валидацию по §0; UI показывает только имена + подсказку):

┌────────────────┬──────────────────────────────────────────────────────────┐
│ Признак        │ Значение / подсказка                                      │
├────────────────┼──────────────────────────────────────────────────────────┤
│ no_toxic       │ нет токсичных газов выше порога                           │
│ toxic          │ любой токсичный газ выше порога                           │
│ acidic         │ SO₂+H₂S+HCl+HF > 0.1% (не в whitelist биомов — наличие) │
│ methane        │ CH₄ > 1% (гейт since 99.2.20: CH₄ ≤ 5%)                  │
│ nitrogen       │ N₂ > 50%; на сверх холодных — азотная примесь не участвует│
│ co2            │ CO₂ > 50%                                                │
│ oxygen_free    │ O₂ < 1%                                                  │
│ dense          │ P > 1 атм                                                │
└────────────────┴──────────────────────────────────────────────────────────┘

**Правила достижимости признаков** этими гейтами — зона @developer; в UI для каждого
признака — hint: «требует атмосферу с [состав]» (как в §4.5 спеке) + ссылка-подсказка
«признаки достижимы генератором §0».

## 4. Полосы климатов — bands (мультивыбор э/ж/у/х)

Строго из §22 п.1: **bands у биома и типа недр — мультивыбор э/ж/у/х** (whitelist,
находка @critic №1: «полосы климатов — для биомов, а не в whitelist полос»). В UI это —
selector четырёх чекбоксов/чипов э/ж/у/х. В чекбоксах НЕ редактируются
флаг-гейты полос: whitelist полос — это bands биома. Данные ands заполняются при
создании из полосы по умолчанию, но редактируются всегда (в band биома).

Чип-паттерн — существующий .chip из dmin.css (уже используется в таблицах
списков биомов). Активная полоса — chip active; клик — toggle.

## 5. Матрица несовместимости

Ручная матрица несовместимости биомов — **список пар** (бездilатерalьный, двусторонний).
Только через ands несовместимости НЕ гоняются — матрица отдельная структура (§22 п.5).
Дополнительно отображается **авто-правила недр** (§22 §5): авто-правила от жидкости —
read-only, чтобы не ломать консистентность каскада. Эти авто-правила — зона @developer.

**Как выглядит:** таблица пар + кнопка «➕ Добавить группу» (добавляет пару) и кнопка
удаления пары. Каждая пара — две ячейки (biom_a, biom_b), чиповый мультивыбор биома.

## 6. Редактор записи биома — полная форма (§22 п.1)

Правая панель при выборе записи из списка. Заголовок: id (моно) + имя + категория-чип.
Поля — все из §22 п.1, сгруппированы в компактные подблоки (ieldset-стиль внутри
карточки), чтобы 26 полей не висли одной отвесной простыней:

### 6.1. Группа «Основное»
- **id** — текстовое, **read-only** при правке существующей записи (подсказка вида
  «🔒 id не редактируется: на него ссылаются планеты. Переименование = миграция
  данных»). При создании — активное.
- **имя** («Отображаемое имя») — текст.
- **категория** — <select> enum из перечня категорий §1 справочника (лито/вода/био/
  крио/вулк — как в каталоге биомов) + «+ экзотика» если в данных.
- **описание** — <textarea rows=3>.

### 6.2. Группа «Условия появления»
- **T_min / T_max** (K), **P_min / P_max** (атм), **вода_min / вода_max** (%).
- **iron/ice/rock_min** (0–1, шаг 0.05), **g_min | g_max** (в ед. g).
- Порог токсичности атмосферы — **число в %** (для раздела «Параметры» §9, сюда
  не дублируем — одно место истины).

### 6.3. Группа «Признаки и гейты»
- **needs_light** — один чекбокс (физ. свет).
- **жидкость** — <select> enum: вода / метан / аммиак / co2 + «-» (нет).
- **признаки атмосферы — мультивыбор (§3)**: чипсы из §0.
- **вулканизм** — <select> enum.
- **requires_radiation / requires_tidal_lock** — два чекбокса.
- **bands — мультивыбор э/ж/у/х (§4).**
- **requires_life / requires_liquid_water** — два чекбокса.
- **теги типа — мультивыбор** из набора тегов (чипы; набор — из справочника §5.1;
  автодоверло в узкое поле поиска не делаем — список конечный, раскрывается).
- **weight_base** (0–10, шаг 0.1, с live-подсветкой числа), **albedo** (0–1, шаг 0.05).

**Live-подсказки** под каждой группой минимальны, общий hint в шапке редактора:
«Изменения применяются к новым мирам; бэкфилл запрещён (99.2.28 §16)».

Индикатор «изменено/сохранено» на редакторе — как в settlementSettings (сохраняю
на кнопку, PATCH одного подраздела).

## 7. Подразделы и их активность (сверху-решение ⇒ подраздел-паттерн)

Подразделы §1–6 — это **список+редактор** (биомы/типы недр/типы планет/полосы/матрица/
параметры). Переключение — сегмент-кнопки .seg .seg-btn (паттерн «полосы климатов»).
Сохранение — одна кнопка «💾 Сохранить» в строке действий внизу блока, пишет **весь
активный подраздел атомарно** файлом (GET/PATCH /admin/biome-catalog по подразделу,
паттерн tmp+rename + hot-reload store, решение п.22 §6).

**Индикатор активного подраздела:** вкладка-подраздел подсвечивается, заголовок
блока «📖 Справочник биомов · [Биомы]».

**Drag&drop порядка** — в подразделах «Типы планет» (порядок правил = первое
сработавшее, §22 п.3) и «Полосы климатов» (порядок полос). Паттерн: HTML5
draggable на строке + handle‑иконка ⠿; подпись «порядок сверху вниз: первое
сработавшее правило решит тип».

## 11. За пределами скоупа (для @developer)

1. **API-хендлеры:** GET/PATCH /admin/biome-catalog (справочник) — по подразделам
   (биомы/типы недр/типы планет/полосы/матрица/параметры); серверная валидация:
   дубликат клиентской + **достижимость биома: bands не пусты + признаки атмосферы из

2. **Отдельный файл полос** (§22 §5): GET/PATCH /admin/planet-archetypes — веса + 
   allowed-списки гидросфер/атмосфер/биосфер; whitelist биомов — **не здесь** (в bands биома).
3. **Права:** правка — dmin; чтение — dmin + skycomposer (гейт-вопрос З).
4. **Бэкфилл запрещён** — см. спека §16, инвариант 17; UI показывает предупреждение.

## 12. Что не трогаем (инварианты)

1. Данные/механика/баланс (99.2.28 §1–§21) — зона @designer/@balancetester.
2. Логика доли/физики планет (§13–§16) — зона @developer (@designer/@developer).
3. Возможность правки/хранение в справочнике не меняет генератор (интерпретатор —
   данные, пороги из кода уезжают — решение п.В §16, обсуждает создатель).
4. Признаки атмосферы §0 — данные, не ярлыки; в справочник не пишем отдельные
   enum-поля «атмосфера», используем мультивыбор из §0.
5. Не вводим новых библиотек/фреймворков (vanilla JS, существующий admin.css).

## 13. Валидация и предупреждения (клиентская + серверная)

1. **Дубли id** — тост «id уже существует»; сервер тоже режектит (дубликат).
2. **min > max** (T/P/вода/g) — «мин > макс» тост; поля подсвечены.
3. **Ссылки на несуществующие теги/формы** — жёлтый тост предупреждения.
4. **Удаление биома, на который ссылается планета** — confirm: «Удалить биом
   „N“? Он используется планетами — планеты останутся без биома (бэкфилл запрещён)».
5. **Биом не в whitelist ни одной полосы** — предупреждение-тост «не будет рождаться».
6. **Удаление типа планет, используемого фильтрами** — confirm-подтверждение.

## 14. Показатели готовности кода (для @developer, критерий проверки @developer)

1. Новая карточка «📖 Справочник биомов» присутствует на вкладке «Основное» ниже
   «Настройки населения»; выглядит как существующие карточки.
2. Подразделы, поиск/фильтр/сортировка в списке, редактор записей, drag&drop порядка —
   работают; лоадеры/пустые состояния/тосты — как в остальной админке.
3. После PATCH работает hot-reload store; файл записан атомарно (запись читается
   после рестарта сервера).
4. Роль admin редактирует; роль skycomposer видит read-only, без кнопок сохранения.
5. Та же валидация — на сервере; сообщения ошибок — тостом с текстом сервера.
