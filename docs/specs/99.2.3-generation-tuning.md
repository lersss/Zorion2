## 1. Цель и скоуп

Реализовать решения создателя из §4и идеи 29a про админку-генераторы (раздел D ТЗ):

1. **Подвкладки-дропдаун** на генеративных вкладках: Звёзды, Планеты,
   Поселения, Гипотезы, NPC-агенты.
2. **Генератор звёзд** (в подвкладке «Звёзды»): параметры вселенной + блок
   весов спектральных классов O–Y + блок весов типов систем/объектов +
   таблица «среднее количество планет по типу звезды».
3. **Генератор планет** (в подвкладке «Планеты»): **без весов** (решение
   создателя §4и.2 — весов не будет), числовые поля; применяется поверх
   планет, сгенерированных генератором звёзд.

**НЕ в скоупе** (остаётся будущим, в старой «идее» было заявлено): вынос всех
хардкод-констант (альбедо, парниковые факторы, пороги классификатора, ядро,
композиция) в конфиг админки. Здесь конфигурируются ТОЛЬКО веса «Звёзд» и
средние планет — это единственное, что заказно §4и. Модель хранения (JSON-+
override в БД) закладывается сразу, чтобы будущие блоки констант легли в неё
без переделки (см. §3).

## 2. Навигация: подвкладки-дропдаун

- Вкладка «🌌 Генерация» (`tab-generation` в `web/admin.html`) получает
  **дропдаун-селектор подвкладок** сверху: `Звёзды | Планеты | Поселения |
  Гипотезы | NPC-агенты | Фракции` (6 подвкладок).
- Текущее содержимое вкладки (форма «Создать мир» + «Генерация вселенной» с
  пресетами) переезжает в подвкладку **«Звёзды»** без потери поведения —
  генерация вселенной и есть генерация звёзд (миров).
- Подвкладка **«Поселения»** перенесена полностью (не заглушка).
- Подвкладки-заглушки (Гипотезы, NPC-агенты, Фракции): лениво инициализируются
  (паттерн `tabs.js` `activateTab`), показывают «в разработке» + при
  необходимости кнопку, ведущую на существующие разделы (поселения —
  `settlements`-инструменты статы, NPC — вкладка `tab-npc` админки, см.
  `docs/specs/_archive/26a.1-bulk-npc-generation.md`). Никаких новых хендлеров на заглушки.
- Реализация: существующий механизм вкладок `web/static/js/admin/tabs.js`
  (STORAGE_KEY `adminActiveTab` — хранит подвкладку тоже), `generation.js`
  получает функции `showStarsSub(...)` / `showPlanetsSub(...)`; разметка — в
  `web/admin.html` под `tab-generation`.

## 3. Хранение настроек генерации

Решение: **JSON-дефолты в коде + override-таблица в БД** (паттерн уже принят
в проекте — матрица совместимости, `docs/DB.md`).

- Таблица `generation_config` (миграция `000031_generation_config.sql` +
  down): `key TEXT PRIMARY KEY`, `payload JSONB NOT NULL`, `updated_at
  TIMESTAMPTZ NOT NULL DEFAULT now()`.
- Ключи: `star_weights` (спектральные классы + типы систем/объектов),
  `planet_means` (среднее число планет по типу), `stellar_mass_ranges`
  (диапазоны массы звёзд min–max M☉ по классу/типу, дефолты физические —
  идея 29a §4м), `universe_params`
  (MapSize/minDist/кластеры/выбросы — дубль-не-создаётся: эти поля УЖЕ живут в
  формах генератора и применяются напрямую; в БД их не дублируем, если не
  решено иначе на гейте — см. §6 «развилка»).

**Развилка «куда писать настройки универсума»:**
- Вариант A (рекомендую): веса и средние — в `generation_config`; параметры
  вселенной — как сейчас (поля формы, `applyPreset`), в БД — нет. Цена:
  параметры не переживают рестарт — но они и сейчас не переживают; менять
  поведение вне потребности фичи не будем.
- Вариант B: всё в `generation_config`, форма читает при открытии. Цена:
  шире правка, зато «конфиг генерации» одна сущность. Принимается, если
  создатель хочет единый источник.
На всякий случай: правило «сущность с двумя экземплярами — не сущность» —
таблица НЕ плодит сущности; это реестр конфигов, он один, расширяемый
будущими блоками §1.

## 4. Генератор звёзд (подвкладка «Звёзды»)

Собирает обычную форму «Генерация вселенной» + **два блока весов** + **таблицу
средних** (все — из спеки 99.2.4 §4.1/§4.2/§5.2 как дефолты):

### 4.1. Блок «Веса спектральных классов O–Y»

- 10 полей (O, B, A, F, G, K, M, L, T, Y), значения ≥ 0.
- Под полями — автоподсчёт: сумма и проценты («M — 32% от обычных звёзд»).
- Сохранение: кнопка «Сохранить конфиг» → `generation_config['star_weights']`.
- Применение: используется при следующей генерации вселенной; валидация:
  сумма > 0 иначе 409; нормализация к 100 выполняется при генерации.
- Дефолт — текущие `spectralWeights` из `galaxy.go` (не меняются, 99.2.4 §4.2).

### 4.2. Блок «Веса типов систем/объектов»

- 8 полей: single 85, binary 5, multiple 2, black_hole 1, neutron 1,
  white_dwarf 2, protostar 1, exotic 3 (дефолты 99.2.4 §4.1).
- Автоподсчёт суммы и процентов («одиночные — 85% всех систем»);
  валидация: сумма > 0.
- Сохранение: в тот же `generation_config['star_weights']` (двумя блоками).

### 4.3. Таблица «Среднее количество планет по типу звезды»

- 10 строк О–Y + 4 строки экзотики (black_hole 0.1, neutron 0.05,
  white_dwarf 0.3, protostar 0) + строка прочей экзотики (0.1) + строки-
  множители двойных (wide ×0.9, close mean 0.2) и кратных (×0.9) —
  редактируемые числа (float, точность 2 знака).
- **Границы поля: 0 ≤ mean ≤ 8.** Верхняя граница — жёсткий предел, ниже
  которого работает честное среднее: `E[n] = mean` выполняется только при
  mean ≤ 8 (механика `floor + Бернулли`, потолок 8; 99.2.4 §5.2). Mean > 8
  молча обрежет распределение — `E[n] ≠ mean`, поэтому значение **отклоняется
  валидацией** (не клампится!): вход 422 с сообщением «mean ≤ 8» (см. §4.5,
  тесты §7).
- Дефолты — 99.2.4 §5.2; сохранение: `generation_config['planet_means']`.
- Семантика «среднее» фиксирована: `n = floor(mean) + Бернулли(frac)`,
  потолок 8 (99.2.4 §5.2) — в UI не выводится, документируется здесь.

### 4.4. Поведение кнопки «Генерировать вселенную»

1. Читает конфиги из БД (если есть) или дефолты.
2. Генерирует миры по весам (galaxy + ветки экзотики, спека 99.2.4).
3. Для каждого мира генерирует планеты по средним (существующий flow
   planet-генерации, вызывается как сейчас).
4. Очистка старых данных — существующий механизм `clearUniverseTx`
   (`admin_universe.go`, truncateTables), не меняется.

### 4.5. API (новые/изменённые админ-хендлеры)

- `GET /admin/generation/config` → `{star_weights, planet_means}` (дефолты,
  если в БД пусто).
- `PUT /admin/generation/config` body `{star_weights, planet_means}` —
  валидация: веса ≥ 0 и сумма > 0 (иначе 409), **mean в [0, 8]** (иначе 422),
  запись в `generation_config`, ответ — сохранённый конфиг.
- Существующие `POST /admin/generate*` — читают конфиги при обработке
  (минимальная правка: `worlds`-генератор берёт веса из `generation_config`).
- Файл правки: `internal/handlers/admin_universe.go` (+ новые методы), модель
  `generation_config` — в `internal/models/` по образцу соседних.

## 5. Генератор планет (подвкладка «Планеты»)

Решение создателя §4и.2: **весов НЕ будет** — только числовые поля.

- Поля формы: количество миров (или «для всех сгенерированных»),
  минимальное/максимальное число планет на мир (0–8), чекбоксы категорий
  (обычные/двойные/экзотика — включить ли в пересчёт), кнопка «Перегенерировать
  планеты».
- Семантика: НЕ создаёт новых миров; удаляет планеты выбранных миров и
  генерирует заново по равномерному счёту из полей (для обычных звёзд —
  общий путь `generatePlanet`, для экзотики — `generateExoticPlanet`,
  спека 99.2.4 §5.3). Средние из «Звёзд» НЕ применяются — это ручной
  пересчёт, а не конфиг-генерация (важно: инструмент-«лекарство», не второй
  генератор).
- Подтверждение перед выполнением («перезапишет планеты N миров, отменить?»)
  — по образцу существующих живых прогонов (AGENTS.md §23: не запускать поверх
  чужого джоба — проверить статус генерации перед стартом).
- API: `POST /admin/regenerate-planets`, body — поля формы; в ответ — сколько
  миров/планет пересчитано. Живой прогон пишет в `planets` — без параллельных
  с генерацией вселенной.

## 6. Связь с 99.2.4 и будущее

- Дефолты всех полей — **источник один**: `99.2.4-exotic-stars.md` §4.1/§4.2/
  §5.2; спека 99.2.3 ссылается, не дублирует числа.
- Старая «идея» 99.2.3 (вынос всех констант) — НЕ отменена, перенесена в
  «будущее»: модель `generation_config` уже готова под новые ключи; когда
  понадобится конфигование альбедо/классификатора/ядра — добавится ключ и
  блок формы без миграций схемы.
- Модификаторы (§4.3 в 99.2.4) весами в админке НЕ выставляются (создатель
  не заказывал) — их вероятности остаются кодом; при желании — отдельный
  будущий блок.

## 7. Что проверить @balancetester

- Автоподсчёт процентов: веса → проценты корректны (сумма 100 после
  нормализации; у спектральных — относительно обычных звёзд, у типов — всех
  систем).
- Валидация: отрицательные/нулевые суммы отклоняются (409), **mean > 8
  отклоняется (422, не клампится)**; крайние значения (mean 0 → 0 планет;
  mean 8 → потолок 8) не ломают генератор.
- Семантика средних: `floor + Бернулли` даёт ожидаемое среднее по выборке
  (юнит-тест на распределение).
- Пересчёт планет (`/admin/regenerate-planets`) не трогает миры, поселения,
  аудит-лог (таблицы вне списка truncateTables).
- «Перезапись планет у экзотики»: ветка `generateExoticPlanet` соблюдает
  аудит-гейты 99.2.4 §6.2.
