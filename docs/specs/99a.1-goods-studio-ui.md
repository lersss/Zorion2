## 1. Цель и скоуп

Довести UI студии товаров до видения создателя (конспект п.7, дословно): «приятный
современный интерфейс со слотами, куда кладутся карточки ресурсов, от топ вниз;
каждый листик связан с другими. Карточка товара; отдельный просмотр "что делается
ИЗ этого товара"; добавление/удаление слотов составляющих; заполнение слотов
сгенерированными товарами; новые товары становятся листиками графа. Zoom и drag.
Правая колонка — "неиспользуемые"… отдельный переключатель на "забаненные"».

**В скоупе:** доработка `cmd/goods-studio/web/index.html` (разметка, стили, JS):
обратные рёбра и блок «Используется в:», состояния (загрузка/пусто/ошибка/
генерация), модалки (удаление, экспорт с warnings), переименование/смена
категории в детали, drag&drop с заменой заполненного слота, «удалить слот»,
индикатор генерации с моделью, disabled-состояния, оверлеи графа, localStorage,
точечная a11y, аккуратный современный вид (тёмная тема, как сейчас, но ровнее:
отступы, hover/focus, согласованные контролы).

**НЕ в скоупе (см. §6, §8):** серверный Go (контракты не меняются); стилистика
мира (@gdesigner — не зовём для инструмента, но финальные палитра/шрифты —
решение менеджера, см. §9); новые API; машинные окна свойств; валидаторы
перекосов; свободный лейаут узлов (спека §17); роботы/постройки.

### 2.2. Чего не хватает / что расходится (это и есть тело доработки)

1. **«Отдельный просмотр "что делается ИЗ этого товара"» — НЕТ.** В детали нет
   блока «Используется в:» (спека §10.7); «обратные рёбра» рисуются для **всех**
   товаров сразу, а не для выбранного (спека: «у выбранного товара»). Главный
   пробел против видения создателя.
2. **Нет переименования товара вообще** (PUT /api/goods/{id} существует на
   сервере, UI не использует): имя из ИИ нельзя поправить — приходится удалять
   и создавать заново. Блокер workflow.
3. **Нет смены категории товара в детали** (PUT /api/goods/{id} `category_id`).
4. **Нет кнопки «удалить слот»** (DELETE /api/goods/{id}/slots/{n} существует):
   слот можно только очистить («×»), лишние слоты не убрать.
5. **Заполненный слот не принимает drop** (ondrop только у `.slot.empty`, строка
   347): замена составляющей — два действия («×» + перетащить) вместо одного
   (спека §10.4: «заполнение пустого **или замена** содержимого заполненного»).
6. **Нет подсветки drop-target** при перетаскивании (спека §10.4).
7. **Отчёт о генерации показывается при каждом опросе** (showReport вызывается в
   каждом fetchState, пока `state.report` непуст; `lastReport` живёт до следующей
   генерации — сервер его не очищает) → тост мигает каждые 3 с. Нужно: показывать
   один раз, по изменению содержимого.
8. **Индикатор генерации без модели** («⚙ генерация...» вместо «⚙ генерация…
   (модель M)», спека §10.8); кнопка «заполнить комплектующие» **не disabled**
   во время генерации (спека: «кнопка disabled у всех товаров»); клик при
   отсутствии пустых слотов не даёт дружелюбного тоста «Сначала добавьте слот»
   (спека §10.8).
9. **Нет модалки экспорта с warnings** (§10.9): экспорт пишется сразу, создатель
   видит предупреждения только после записи в тосте; поле пути не используется.
10. **Нет модалки подтверждения удаления товара** (§10.10): «Удалить товар «X»?
    Слоты, ссылающиеся на него (N), очистятся» — удаление необратимо и затирает
    чужие рецепты, подтверждение обязательно.
11. **Нет состояний графа:** первичная загрузка (спиннер/скелетон), «Реестр пуст —
    добавьте первый товар» + CTA, «ничего не найдено», «нет связи, повтор через
    3 с» (спека §10.10) — сейчас пустой canvas и молчаливый `catch(e){}`.
12. **Нет тултипов на карточках графа** (hover: полное имя, категория, тир; спека
    §10.2): имя обрезается `trunc` до 26 символов, полное не увидеть.
13. **Клик по карточке палитры не выбирает товар на графе** (спека §10.4: «клик —
    выбор ресурса на графе»).
14. **Клик по пустому месту графа — pan, а не сброс выбора** (спека §10.1: «клик
    по пустому месту — сброс выбора»). Сброс добавить на click без движения.
15. **localStorage неполный** (спека §10.12): сохраняются только zoom/pan; нужны
    также активная категория фильтра, переключатели «забаненные»/«обратные рёбра».
16. **Новый товар не выбирается автоматически**: после «+ товар» создатель ищет
    его на графе глазами — ломает поток «создал → заполнил → согласовал».
17. **Забаненные: клик по карточке не открывает деталь** (спека §10.5: «выбор
    карточки — деталь с "Вернуть"/"удалить"»), только кнопка «Вернуть».
18. **warnings нигде не видны до экспорта** (спека §8: прогон при чтении
    состояния; UI их не показывает) — предложение, см. §3.6 (P2).
19. **Вид не «современный»:** всё на одном `#main` без воздушности, разнобой
    отступов, нет hover/focus-состояний, нет disabled-стилей, курсоры местами
    неверные (например, у карточек палитры `cursor:grab` без drag-цели —
    карточки banned `cursor:default`). Не стиль мира, а аккуратность инструмента.

### 2.3. Замечания по фактам (не баги, учесть при доработке)

1. `visibleGoods` исключает товары по фильтру/поиску, и **рёбра к скрытым не
   рисуются** — при фильтре по категории граф «рвётся». Спека §10.6 разрешает
   (ресурсы видны всегда, остальное — по фильтру). Оставить как есть.
2. `renderPalette` пересобирает палитру на каждый рендер; при 131 ресурсе это
   ровно, но innerHTML-пересборка сбрасывает scroll палитры — сохранить scroll
   или пересобирать только по изменению (как сделано для графа через
   `lastGoodsJSON`).
3. Фильтр «все категории» (`catFilter.value === ""`) + категория ресурсов —
   ресурсы в графе имеют категорию-код (например `mineral`), которая не
   совпадает с категориями студии: при выборе конкретной категории студии
   ресурсы из графа пропадают (рёбра обрываются). Проверить по §10.6: «ресурсы
   (нижний ряд) видны всегда» — сейчас НЕ видны при активном фильтре. Это
   расхождение со спекой: ресурсы должны оставаться на графе при фильтре
   категории (можно приглушёнными). **Доработать** (см. §4.3, п.2).

## 3. Проектирование доработки

### 3.1. Решение по подаче графа

Оставляем каркас «canvas-граф + правая HTML-колонка (деталь + палитра)» — он уже
соответствует видению (ряды по тиру, zoom/drag, карточки-обзор). Дополнительные
виды (список/дерево) **не вводим**: видение создателя — граф («на экран всё не
влезет» → zoom/drag), спека §17 запрещает ручной лейаут. Обратные рёбра подаём
двумя способами (оба были в видении):
- **блок «Используется в:»** в детальной панели — кликабельный список родителей
  (это и есть «отдельный просмотр "что делается ИЗ этого товара"» + навигация);
- **режим «обратные рёбра»** — подсветка рёбер родителей **только выбранного**
  товара (исправить текущее «для всех»).

Техника рендера карточек графа (canvas против HTML-оверлея) — зона @developer
(спека §10): требования ниже обязательны при любой технике.

### 3.2. Целевая компоновка (дельта к §10.1)

Верхняя панель — без структурных изменений (3 ряда), кроме: в 1-й ряд добавить
**бейдж warnings** «⚠ N» (P2, §3.6). Основная область: слева граф + оверлеи
состояний (§4.2), справа колонка: деталь (с новым блоком «Используется в:»,
§4.1) → палитра → забаненные (по переключателю). Слой поверх: тосты (как есть,
но с фиксом §4.5), модалка удаления, модалка экспорта (§4.4).

### 3.3. Основной UX-поток (целевой)

```
«+ товар» → товар создан, ВЫБРАН, деталь открыта (новый пункт)
→ «+ слот» ×N (пипсы на карточке растут)
→ «заполнить комплектующие» → индикатор «⚙ генерация… (модель M)»,
   кнопки fill disabled у всех товаров
→ авто-обновление приносит карточки в слоты; отчёт-тост один раз
→ правка: перетащить другую карточку на заполненный слот (замена) /
   «×» очистить / «удалить слот» / переименовать в детали
→ «Используется в:» — проверить, что из товара делается
→ Согласовать → Экспорт (модалка с warnings, если есть) → тост «Экспорт записан»
```

### 3.4. Доработки по элементам (было → станет + почему)

Каждый пункт — отдельная правка `index.html` (CSS/HTML/JS).

1. **Деталь — блок «Используется в:»** (спека §10.7).
   Было: нет. Станет: под шапкой детали (после слотов, перед кнопками) блок
   «Используется в:» — список родителей (товары, в чьих слотах есть этот товар),
   каждый кликабельный (клик — `selected` на родителя, деталь перерисовывается).
   Пусто — «нигде не используется». Показывать и для ресурсов (полезно: где
   применяется ресурс). Реализация: фильтр по `state.goods` из данных, сервер
   не меняется.
2. **Обратные рёбра — только выбранный** (спека §10.7).
   Было: рисуются для всех товаров сразу. Станет: при включённом переключателе
   рёбра родителей рисуются только у `selected` (или ничего, если выбор пуст).
   Цвет отличить от прямых (например #a62, как сейчас).
3. **Деталь — inline-переименование и смена категории** (спека §10.3).
   Было: имя и категория — статичный текст. Станет: имя — клик → `<input>` →
   Enter/Blur → `PUT /api/goods/{id}` `{name}` (409 — тост); категория — селект
   категорий студии, change → `PUT ... {category_id}`. Для `kind=resource` —
   доступно (ресурсы без привилегий, идея переноса §1.2).
4. **Слоты — кнопка «удалить слот»** (спека §10.3).
   Было: только «×» (очистить). Станет: у каждого слота кнопка-иконка «удалить
   слот» (`DELETE /api/goods/{id}/slots/{n}`) с тултипом «удалить слот целиком»;
   «×» остаётся «исключить из рецепта». У последнего слота удаление разрешено
   (товар станет листом, тир 0 — допустимо по §6.1).
5. **Drag&drop — замена заполненного слота** (спека §10.4).
   Было: drop только на пустой слот. Станет: заполненный слот тоже drop-target;
   сброс — `PUT slots/{n}` (сервер заменит ссылку; заменяемый товар остаётся в
   реестре — уже так на сервере). Визуально подсветить «можно заменить».
6. **Подсветка drop-target** (спека §10.4).
   Было: нет. Станет: при `dragover` над слотом — обводка/фон слота (класс
   `.drop-target`), при уходе — снять. Цикл-409 — тост «Цикл: товар X не может
   входить в состав Y» (текст сервера), слот без изменений (уже работает через
   `api()`).
7. **Отчёт генерации — один раз** (спека §10.8 + фикс мигания).
   Было: тост при каждом опросе `/api/state`. Станет: хранить `lastShownReport`
   (JSON-строка), показывать тост только если `state.report` изменился
   (непустой). Авто-скрытие 8 с (как есть).
8. **Индикатор и disabled генерации** (спека §10.8).
   Было: «⚙ генерация...», кнопки активны. Станет: индикатор
   «⚙ генерация… (модель M)» (модель уже есть в `state.model`); кнопка
   «заполнить комплектующие» `disabled` при `state.generating` (у всех товаров)
   и при отсутствии пустых слотов (тултип «Сначала добавьте слот»); клик при
   отсутствии пустых слотов, если кнопка активна (крайний случай) — тост
   «Сначала добавьте слот («+ слот»)».
9. **Модалка экспорта** (спека §10.9).
   Было: экспорт сразу + тост. Станет: если `state.warnings` непуст — модалка:
   заголовок «Предупреждения перед экспортом», список warnings (строки `message`),
   поле «Путь (пусто — дефолт)», кнопки [Экспортировать всё равно] [Отмена];
   warnings пусты — экспорт сразу. `POST /api/export` `{path}` — поле пути уже
   поддержано сервером. После: тост «Экспорт записан: <путь>» (+ warnings,
   если появились).
10. **Модалка подтверждения удаления товара** (спека §10.10).
    Было: удаление сразу. Станет: кнопка «удалить» → модалка «Удалить товар «X»?
    Слоты, ссылающиеся на него (N), очистятся» (N — посчитать в UI по
    `state.goods`), [Удалить][Отмена]. После подтверждения — DELETE как сейчас,
    `selected = null`.
11. **Оверлеи состояний графа** (спека §10.10) — см. §4.2.
12. **Тултипы карточек графа** (спека §10.2).
    Было: нет (имя обрезано). Станет: hover карточки — HTML-тултип (позиция у
    курсора/карточки): полное имя, категория, тир, статус. Для canvas —
    HTML-оверлей-тултип (не canvas title).
13. **Клик по карточке палитры/неиспользуемых/забаненных** (спека §10.4/§10.5).
    Было: только drag. Станет: клик — `selected` на этот товар (деталь
    открывается; для ресурса — деталь без слотов (ресурс — лист); для забаненного — деталь с
    «Вернуть»). Для карточек banned добавить onclick (сейчас `cursor:default`).
14. **Клик по пустому месту — сброс выбора** (спека §10.1).
    Было: mousedown без карточки → pan. Станет: pan сохраняется, но если
    mouseup без движения (click) на пустом месте — `selected = null`.
15. **localStorage полный** (спека §10.12).
    Было: zoom/pan. Станет: + `catFilter`, `showBanned`, `reverseEdges`
    (применять при старте, сохранять при изменении).
16. **Авто-выбор нового товара** (улучшение workflow).
    Было: созданный товар не выбран. Станет: после успешного `POST /api/goods` —
    `selected` = id нового товара (ответ сервера содержит товар),
    `newGoodName` очищается; деталь открывается сразу. Пометить как улучшение
    потока (спека не запрещает).
17. **A11y и контролы** (§3.5).
18. **Аккуратность вида** (§3.7).

### 3.5. Доступность (точечная, не перегруз)

- Кнопки-иконки («×», «удалить слот») — `aria-label`/`title`.
- `:focus-visible` на кнопках/инпутах (обводка, не только hover).
- `disabled`-стили для кнопок (приглушённый вид).
- Курсоры: карточки палитры — `cursor:grab` (drag есть) + клик; banned —
  `cursor:pointer` (теперь кликабельные).
- Enter в поле имени товара уже работает (строка 476) — добавить Enter для
  поля имени категории (есть, 477) — ок; Enter в inline-переименовании — по §4.1.

### 3.6. Предложение P2 (не блокер, решает менеджер)

**Бейдж warnings в шапке:** «⚠ N» (N = `state.warnings.length`; 0 — скрыт), клик —
модалка со списком предупреждений (+ [Прогнать валидацию] через существующий
`GET /api/validate`). Соответствует §8 («прогон при чтении состояния») и делает
предупреждения видимыми до экспорта. Если менеджер не одобрит — экспортная
модалка §4.4 всё равно покрывает главное.

### 3.7. Вид («приятный современный» — ориентир, не стиль мира)

Остаёмся в текущей тёмной теме (палитра #111/#1c1c1c/#26a/#2a7/#a62/#a33 —
консистентна с админкой и арт-студией), но приводим в порядок:
- Единый вертикальный ритм (gap 8/12, отступы панелей 10–12px).
- Состояния: hover (фон кнопки/карточки +1 тон), active, focus-visible, disabled.
- Скругления и рамки единообразны (6–8px, border #333/#444).
- Колонка справа — стабильная ширина 300px, аккуратный скролл (как сейчас).
- Тосты/модалки — один компонентный стиль (заголовок, действия справа).
- Иконки-кнопки — одинаковый размер hit-таргета (≥24px).
- **НЕ вводить** анимации-«парады», градиенты, кастомные шрифты без запроса.

## 4. Спецификация компонентов и состояний

### 4.1. Детальная панель (целевая структура)

```
[имя (клик — inline-редактирование)]      ← переименование
[категория ▾ селект] · тир N · [статус-бейдж] · [ИИ]   ← смена категории
— слоты —
  слот 1: [имя составляющей · тир · reason] [×] [🗑 удалить слот]
  слот 2: (пусто — перетащите сюда карточку) [🗑 удалить слот]
  …
[+ слот] [заполнить комплектующие]   ← fill disabled: ген. идёт / нет пустых
[Согласовать][Исключить][Забанить] / [Вернуть] (для banned)
[Используется в:]  ← список родителей, кликабельно (для товаров и ресурсов)
[удалить] → модалка подтверждения (ресурсы — тоже, без привилегий)
```

Заполненный и пустой слоты — оба drop-target (§3.4, п.5–6). У последнего слота
«удалить слот» допустим (товар → лист, тир 0).

### 4.2. Оверлеи графа (состояния)

| Состояние | Условие | Оверлей (поверх canvas, центр) |
|---|---|---|
| Загрузка (первичная) | первый `/api/state` ещё не пришёл | спиннер «Загрузка…»; панели неактивны |
| Пустой реестр | `state.goods.length === 0` (после загрузки) | «Реестр пуст — добавьте первый товар» + кнопка [«+ товар»] (фокус на поле имени) |
| Пустой поиск/фильтр | есть товары, но `visibleGoods` пуст | «ничего не найдено» |
| Сеть потеряна | fetch упал (повтор 3 с идёт) | пилюля внизу графа: «нет связи, повтор через 3 с»; последние данные и выбор остаются |

Оверлеи не перекрывают правую колонку (только canvas). Приоритет: загрузка >
пусто > ничего не найдено. Пилюля сети — пока не восстановится.

### 4.3. Палитра и неиспользуемые (дельта к §10.4)

1. Клик по карточке — выбор на графе (§3.4, п.13).
2. **Ресурсы видимы на графе при фильтре категории** (фикс §2.3, п.3): при
   активном фильтре категории студии ресурсы (нижний ряд) остаются на графе
   приглушёнными (всегда, спека §10.6 «видны всегда») — иначе рёбра обрываются.
   Реализация: в `visibleGoods` ресурсы не исключаются фильтром категории
   (поиск их по-прежнему фильтрует), приглушение — стиль рендера.
3. Сохранять scroll палитры при пересборке (§2.3, п.2).

### 4.4. Модалки (общий компонент)

Один контейнер модалки (fixed, overlay #000c, центрирование), содержимое —
по случаю:
- **Удаление товара:** «Удалить товар «X»? Слоты, ссылающиеся на него (N),
  очистятся» → [Удалить][Отмена].
- **Экспорт:** «Предупреждения перед экспортом» + список + поле пути (placeholder
  «goods_data/export.json») + [Экспортировать всё равно][Отмена].
- (P2) **Warnings:** список + [Прогнать валидацию][Закрыть].
Esc — закрыть; Enter на первичной кнопке — подтвердить. Авто-обновление не
сбрасывает открытую модалку (спека §10.12).

### 4.5. Тосты

Как есть (правый нижний угол, авто-скрытие 8 с, `#report`), + фикс: показывать
только при изменении содержимого `state.report` (§3.4, п.7). Ошибки действий
(409/403) — тот же тост (уже работает через `api()`).

### 4.6. Реактивность (дельта к §10.11)

| Действие | Результат |
|---|---|
| «+ товар» | товар на графе + `selected` = новый (деталь открыта) |
| «+ слот» | слот в детали + пипс на карточке (как есть) |
| «заполнить комплектующие» | индикатор «⚙ генерация… (модель M)», fill disabled у всех; по завершении — карточки в слотах, отчёт-тост один раз |
| Drop на заполненный слот | замена составляющей; товар остаётся в реестре; перерисовка (тиры пересчитаны) |
| Переименование / смена категории | обновление детали + карточки; 409 — тост, без изменений |
| «удалить слот» | слот исчезает; при пустом рецепте тир → 0, карточка-лист |
| «×» на слоте | слот очищен, товар в реестре (как есть) |
| Удалить товар | модалка → DELETE → карточка исчезает, ссылавшиеся слоты очищены (сервер), `selected = null` |
| Клик «Используется в:» → родитель | деталь родителя открывается, блок обновляется (навигация по графу) |
| Включение «обратных рёбер» | подсветка рёбер родителей выбранного |
| Экспорт | warnings есть → модалка; нет → сразу; после — тост с путём |
| Клик по карточке палитры | выбор товара на графе, деталь открыта |
| Клик по пустому месту (без движения) | сброс выбора |
| Фильтр/поиск | перерисовка графа; ресурсы при фильтре категории — приглушены, но видны; выбор и деталь не сбрасываются |
| localStorage | категория, showBanned, reverseEdges, zoom, pan — сохраняются и применяются |

Все мутации — через API без оптимистичных обновлений (как сейчас, спека §10.11).

## 5. Критерии приёмки (проверка @tester после разработки)

1. **Поток «создал → заполнил → согласовал → экспорт»:** «+ товар» → товар выбран,
   деталь открыта → «+ слот» ×2 → «заполнить комплектующие» → индикатор
   «⚙ генерация… (модель M)», кнопки fill disabled у всех товаров → карточки в
   слотах + отчёт-тост ровно один раз (не мигает при опросах).
2. **Обратные рёбра:** блок «Используется в:» показывает родителей (для товаров
   и ресурсов), клик — переход к родителю; режим «обратные рёбра» подсвечивает
   рёбра только выбранного товара.
3. **Drag&drop:** перетаскивание на пустой слот — заполнение; на заполненный —
   замена (заменяемый товар остаётся в реестре); подсветка drop-target; цикл —
   тост, слот без изменений.
4. **Слоты:** «удалить слот» удаляет слот (в т.ч. последний — товар-лист, тир 0);
   «×» очищает, товар остаётся.
5. **Редактирование:** переименование в детали (клик → input → Enter) и смена
категории работают через PUT; дубликат имени — тост 409; для ресурсов —
    тоже доступны (ресурсы без привилегий, идея переноса §1.2).
6. **Модалки:** удаление товара — подтверждение с числом ссылающихся слотов;
   экспорт с warnings — модалка (список + путь + [всё равно]/[отмена]), без
   warnings — сразу; после — тост «Экспорт записан: <путь>».
7. **Состояния:** загрузка (спиннер), «Реестр пуст» + CTA, «ничего не найдено»,
   пилюля «нет связи, повтор через 3 с» при остановленном сервере (данные и
   выбор остаются).
8. **Фильтр:** при выборе категории студии ресурсы (нижний ряд) остаются на
   графе приглушёнными.
9. **localStorage:** категория, showBanned, reverseEdges, zoom, pan переживают
   перезагрузку страницы.
10. **Инварианты спеки не сломаны** (см. §7): бан-фильтр ИИ, тиры производные,
    1 слот = 1 единица (поля количества нет), ресурсы без привилегий (слоты недоступны), экспорт только
    согласованных, одна генерация.
11. **DoD разработки:** `go build ./...`, `go vet ./...`, `go test -race ./...`
    (сервер не меняется — тесты сервера должны остаться зелёными без правок;
    UI-фичи покрываются критериями 1–9 вручную @tester, автотесты JS в проекте
    не приняты — не вводить).

## 7. Что не трогать (инварианты UI — перенос из 99a.1 §10.13)

- **Статусы и семантика (§5.2):** бан/исключённое ИИ не предлагается — UI не
  обходит локальный фильтр; разбан в один клик, без подтверждения.
- **Тиры — производные от графа (§6.1):** UI только отображает.
- **1 слот = 1 единица (§6.4):** поле количества не появляется нигде.
- **Ресурсы без привилегий (§1.2 идеи переноса, С1/С3):** переименование/удаление/
  смена категории/тир/статусы доступны; слоты недоступны (ресурс — лист, 403).
- **Экспорт = только согласованные (§11):** модалка не меняет правило.
- **DAG и уникальность имён (§6.2/§6.3):** UI показывает ошибки сервера, не
  обходит (цикл 409 — слот без изменений).
- **Одна активная генерация (§7.1):** повторный fill недоступен во время
  генерации (disabled + серверный 409).
- **Авто-обновление 3 с без сброса выбора/зума/пана/модалок (§12.3).**
- **Не менять API-контракты и серверный Go** (§6 этой спеки).
- **Карточки на графе остаются обзором** (кнопок на canvas-карточках не
  добавлять — редактирование в детали, §10.2).
