## 1. Цель и скоуп

Доработать студию товаров под решения создателя 2026-09-19 (идея 99a.3): канвас
переходит в режим **«вокруг выбранного»** (фокус-подграф, по умолчанию), полный
граф — отдельной галкой; вводится **тир-оверрайд** (ручное поле в карточке товара,
полная свобода значений); «палитра» переименовывается в **«справочник»** — список
всех товаров с поиском, галками-фильтрами, кнопкой «+ товар» и подгрузкой списка
названий. Логика слотов и количество **не трогаются** (создатель 2026-09-19:
«ничего не прошу сверх того, что сейчас есть по слотам»).

**В скоупе:** режимы канваса (фокус-подграф / всё дерево), `Good.tier_override`
(модель/API/UI/экспорт/промпт), справочник (список/поиск/фильтры/драг), кнопка
«+ товар» в справочнике, подгрузка списка (`POST /api/goods/bulk`), DoD, дельта в
99a.1/99a.1-ui. Код — зона @developer по этой спеке.

**НЕ в скоупе (§15):** код Go; логика слотов и количество (99a.2 — как есть);
слоты-приёмники на канвасе (не возвращаем — решение создателя, вердикт критика
№1 снят); Пакет 3 «тир сверху вниз» (ИИ строит цепочку вниз — остаётся открытым
в родительской идее, «Открытые пункты»); правка `allow_resource` в промпте/apply
(отдельной задачей); маппинг категорий на игровую модель; валидаторы перекосов.

## 3. Природа сущностей (разбор по правилу «событие/лог/атрибут»)

1. **`tier_override`** — **атрибут существующей сущности** (поле `Good`), не событие
   и не лог. Владелец — один объект (товар); расширяемость — один тип (int|null).
   Отдельной таблицы/записей не вводим. Хранится в `state.json` как поле товара,
   null = вычисляется (99a.1 §6.1).
2. **Подгрузка списка (bulk)** — **операция** (событие), не сущность: результат —
   мутация `state.json` (создание товаров) + отчёт в ответе эндпоинта (лог
   операции, не хранится). Паттерн импорта (99a.2 §4.2).
3. **Справочник** — клиентское представление `state.goods`, не сущность: список,
   поиск и фильтры считаются в UI из уже приходящего состояния (развилка 4).
4. **Фокус-подграф** — режим рендера канваса, не сущность: подграф вычисляется на
   клиенте из `state.goods` (родители/дети через `recipe`), сервер не меняется.

## 4. Модель — `Good.tier_override`

### 4.1. Поле

```go
type Good struct {
    // … существующие поля (99a.1 §5.1) …
    TierOverride *int `json:"tier_override,omitempty"` // ручной тир; null = вычисляется (99a.3 §4.2)
}
```

- `null` (поле отсутствует) = оверрайда нет, тир вычисляется (текущее поведение).
- Заданное значение — **полная свобода**: любое целое ≥ 0, в т.ч. ниже
  вычисленного (решение создателя 2026-09-19, ответ на звоночек критика №2:
  «Нужна полная свобода. Ограничений нет»). Отрицательные отклоняются (400):
  шкала 0-базовая (0 = ресурсы, 99a.1 §6.1), отрицательный тир не имеет смысла
  на шкале и сломает экспорт (complexity < 0).
- Нормализация при загрузке не требуется (null/число — оба валидны; старые
  state.json без поля = null, миграции нет).
- Ресурсы (`kind=resource`): оверрайд **доступен** (тир ресурса назначаемый, С3,
  идея переноса §1.2); без оверрайда тир ресурса = 0 (вычисленный, рецепта нет).

### 4.2. Эффективный тир

```
тир_вычисленный(товар) = 1 + max(тиры_вычисленные заполненных слотов)   (99a.1 §6.1, graph.Tier)
тир_эффективный(товар) = tier_override ?? тир_вычисленный
тир_эффективный(ресурс) = tier_override ?? 0
```

- **Отображение (бейджи карточек, деталь, слоты) и экспорт (complexity) — по
  эффективному тиру.**
- **Промпт ИИ «заполнить комплектующие» — по вычисленному тиру** (критик №10:
  оверрайд не влияет на генерацию, только на отображение/экспорт). `buildFillPrompt`
  не меняется (`graph.Tier`, 99a.1 §7.2).
- Оверрайд **не влияет** на: структуру графа, глубину (depthOf), валидаторы
  (99a.1 §8), проверку циклов, раскладку. Тир остаётся производным от графа для
  всех структурных механик; оверрайд — только ручная правка значения наружу.

### 4.3. Реализация (зона @developer)

- `graph/tier.go`: добавить `EffectiveTier(g, byID) int` = `TierOverride ?? Tier`
  (ресурс — `TierOverride ?? 0`). `Tier` остаётся вычисленным (промпт, валидаторы
  не трогаем).
- `handlers/state.go`: `GoodView` + `tier` (**эффективный**), `tier_computed` (int),
  `tier_override` (int|null). `SlotView.Tier` — эффективный тир составляющей
  (консистентность отображения).
- `export/export.go`: `Complexity: graph.EffectiveTier(g, byID)`.

## 5. Канвас: режим «вокруг выбранного» (фокус-подграф, по умолчанию)

### 5.1. Подграф

При выбранном товаре на канвасе рисуется **только**:

- **выбранный товар**;
- **прямые родители** — товары, в чьих рецептах есть выбранный (1 уровень, не
  вся цепочка);
- **прямые дети** — составляющие из рецепта выбранного (1 уровень);
- **плейсхолдеры пустых слотов выбранного** (пунктирные карточки, как сейчас).

**Ресурсы, попавшие в подграф, видны всегда** (дети-ресурсы выбранного; родители-
ресурсы невозможны — у ресурсов нет рецептов). Чекбокс «показать ресурсы» в
фокус-режиме **отсутствует** (требование идеи §1; критик №3).

### 5.2. Раскладка — переиспользование depthOf/computeLayout (развилка 1)

`computeLayout` параметризуется множеством товаров: фокус-режим передаёт подграф,
режим «всё дерево» — `visibleGoods()` (как сейчас). `depthOf` считает глубину в
пределах переданного множества: родители выбранного — корни (глубина 0), выбранный
— 1, дети — 2, плейсхолдеры — 3. Древесный алгоритм (`colsOf`/`place`), орто-рёбра
и рёбра к плейсхолдерам работают без изменений. Редкие DAG-случаи (родитель
является родителем другого родителя) обрабатываются алгоритмом автоматически —
спец-кода нет. Известный **косметический эффект** (вердикт критика М4,
зафиксировано): такой родитель может лечь не в свой ряд (глубина зависит от
положения в подграфе) — **не чиним** (не влияет на логику, только на вид).

Плейсхолдеры рисуются **только для пустых слотов выбранного** (слоты родителей и
детей — вне окна 1 уровня).

### 5.3. Навигация и состояния

- Клик по карточке родителя/ребёнка на канвасе = **новый выбор** → подграф
  перестраивается вокруг него (hitTest не меняется — работает по множеству
  раскладки). Клик на канвасе — **навигация по графу, попап не открывается**
  (решение §2, развилка 6; попап — отдельным действием, §10.3).
- Клик по пустому месту = сброс выбора (как сейчас).
- **Пустое состояние (ничего не выбрано):** канвас пуст, поверх — подсказка
  «Кликните товар в справочнике» (новый оверлей, рядом с существующими
  «загрузка/реестр пуст/ничего не найдено», 99a.1 §10.10).
- Выбор из справочника (клик по карточке) = выбор на канвасе + подграф вокруг
  него, **без открытия попапа** (§8.3).
- Авто-обновление 3 с не сбрасывает выбор (как сейчас); при удалении выбранного
  товара — `selected = null` → пустое состояние (уже так в коде).

### 5.4. Взаимодействие с топбар-фильтрами

В фокус-режиме поиск по имени и фильтр категорий **на канвас не влияют** (подграф
полный по построению — фильтрация разорвала бы окно 1 уровня). Предложение
(гейт-вопрос, §20): в фокус-режиме топбар-поиск и фильтр категорий скрыты
(справочник имеет собственный поиск/фильтры); в режиме «всё дерево» работают как
сейчас. Кнопка «⟲ на верхний тир» — только в режиме «всё дерево».

## 6. Режим «всё дерево»

- Отдельная **галка «всё дерево»** в шапке (localStorage `gs_fullTree`, дефолт
  выкл). Выкл = фокус-подграф (§5); вкл = текущая логика полного графа
  (`visibleGoods()` + `depthOf` по всему графу, ряды по глубине — решение
  создателя 2026-09-19, критик №4: не «ряды по тиру»).
- **Чекбокс «показать ресурсы» остаётся только для режима «всё дерево»** (критик
  №3): вкл — ресурсы на графе видны, выкл (по умолчанию) — скрыты. В фокус-режиме
  чекбокс скрыт (ресурсы видны всегда, §5.1).
- localStorage: `gs_fullTree`, `gs_showResources` (как сейчас).

## 7. Тир-оверрайд: правила и инварианты

1. **Хранится** `Good.tier_override` (int|null), null = вычисляется (§4.1).
2. **Эффективный тир** = override ?? вычисленный; ресурс = 0 без оверрайда
   (тир назначаемый, С3; §4.1).
3. **Полная свобода значений**: любое целое ≥ 0, в т.ч. ниже вычисленного;
   отрицательное — 400 (решение создателя 2026-09-19 + обоснование §4.1).
4. **Очистка** = вернуть к вычисленному: `PUT {tier: null}` (критик №9).
5. **Экспорт**: `complexity` = эффективный тир (§12).
6. **Промпт ИИ**: вычисленный тир, оверрайд не влияет на генерацию (критик №10).
7. **Оверрайд не влияет** на: граф, глубину, валидаторы, циклы, раскладку (§4.2).
8. **Ресурсы**: оверрайд доступен (тир ресурса назначаемый, С3); без оверрайда
   тир = 0 (§4.1).
9. **Предупреждение при расхождении** (критик №2): UI показывает жёлтую метку
   «⚠ отличается от вычисленного (N)» — не блокер, полная свобода сохраняется.
10. **Импорт** (top-каталог/деревья Т8) создаёт товары без оверрайда (null) —
    правка форматов импорта не требуется.

## 8. Справочник (бывшая «палитра» — переименовать)

### 8.1. Состав

Правая панель: раздел **«Справочник»** вместо «Ресурсы (палитра)» + «Неиспользуемые»
(развилка 5 — единый список). Содержит **все товары**: товары (`kind=good`) и
ресурсы (`kind=resource`). **Забаненные скрыты по умолчанию** (галка-фильтр
«забаненные» в справочнике, §8.2; отдельная панель «Забаненные» **убирается** —
развилка 7; «Вернуть» — в попапе забаненного, §10.3).

### 8.2. Поиск и фильтры

- **Поиск по имени** — инкрементальный, по всем товарам (у ресурсов был, теперь
  распространяется на товары; требование идеи §4).
- **Галки-фильтры** (по умолчанию **все выключены** — виден весь список):
  - **«используемые»** — входящая степень > 0 (`used[good_id]`: товар входит в
    чей-то рецепт; считается на клиенте из `state.goods`, как в `renderPalette`);
  - **«неиспользуемые»** — входящая степень 0 (вхождения в чей-то рецепт; **БЕЗ
    исключения бана** — забаненный с in-degree 0 попадает в «неиспользуемые»,
    если его галка включена; ресурсы с in-degree 0 тоже попадают — «показать все
    неиспользуемые ресурсы», требование идеи; вердикт критика М1);
  - обе галки **комбинируются** (обе включены = все товары, **включая забаненных,
    если их галка тоже включена**; гибкость идеи §4);
  - **«T0»** — только ресурсы (`kind=resource`; критик №5: трактовка по виду, не
    по тиру; товары с пустым рецептом — тоже тир 0, но это рабочие черновики, их
    **не прячем** — при выключенной «T0» они в списке, при включённой — нет);
  - **«забаненные»** — показать забаненных в списке (приглушённые карточки,
    localStorage `gs_spravBanned`, по умолчанию выключена; развилка 7). Группа
    «забаненные» пересекается с остальными фильтрами как «T0».
- Галки **ортогональны** (вердикт критика М1): «используемые» и «неиспользуемые»
  — дополняющие друг друга, но каждая пересекается с «забаненные» и «T0»
  (возможны «используемые ∩ забаненные» и т.п.). Между группами — пересечение.
  Поиск применяется поверх.

### 8.3. Карточки

Карточка: имя, категория, тир (эффективный), бейдж статуса. **Draggable** — источник
drag&drop в слоты попапа как палитра сейчас (`dragStart` → `dropOnSlot`,
существующая логика; логику слотов НЕ трогаем, §11). Поведение:

- **клик по карточке** = выбор на канвасе + подграф вокруг него (фокус-режим),
  **попап не открывается** (навигация по списку, §5.3);
- **двойной клик** по карточке = выбор (`selected` = товар, подграф
  перестраивается) + **открытие попапа-детали** на этом товаре (§10.3);
- **кнопка «деталь» (ⓘ)** на карточке = открытие попапа-детали **без смены
  `selected`** (для ресурсов — деталь без слотов, ресурс — лист);
- забаненные (при включённой галке) — приглушённые карточки; попап забаненного
  содержит «Вернуть»/«удалить» (как сейчас в попапе забаненного).

### 8.4. Кнопка «+ товар»

В справочнике — кнопка **«+ товар»** (имя + категория), дублирует addbar в шапке
(критик №8: оставить обе, поведение одинаковое — `POST /api/goods`, черновик с
одним пустым слотом, авто-выбор). Обе кнопки работают как сейчас.

### 8.5. Подгрузка списка (bulk)

В справочнике — сворачиваемый блок **«подгрузка списка»**: текстовая область,
каждая строка **«название | категория»** (категория по имени из категорий студии,
нормализованное совпадение — паттерн 99a.2 §4.3; **разделитель — первый «|»,
название с «|» невозможно** — правило §9.2), кнопка «Создать из списка» →
`POST /api/goods/bulk` (§9). Созданные товары — **карточки-черновики** (draft,
один пустой слот, quantity 1, source=manual). Результат — тост-отчёт по строкам
(§9): создано N, пропущено M (дубликаты), ошибок K (с номерами строк).

## 9. HTTP API (дельта к 99a.1 §9)

| Метод/путь | Параметры | Ответ |
|---|---|---|
| `PUT /api/goods/{id}/tier` | `{tier: int\|null}` — установить оверрайд; `null` — очистить (вернуть к вычисленному) | обновлённый `GoodView`; 400 — тир < 0 / не число; 404 — товар не найден |
| `POST /api/goods/bulk` | `{lines: ["имя \| категория", …]}` — строки подгрузки | отчёт `{created, skipped, errors}` (см. ниже) + обновлённое состояние; 400 — `lines` пуст/не массив |

### 9.1. `PUT /api/goods/{id}/tier`

- Роутинг: новый под-путь в `handleGoodByID` (`/api/goods/{id}/tier`, паттерн
  `allow_resource`).
- Body: `{"tier": 5}` — установить; `{"tier": null}` — очистить. Поле `tier` —
  `*int`: nil = очистка, число = установка (непереданное поле неотличимо от null
  и трактуется как очистка — контракт простой: PUT всегда означает «оверрайд =
  tier», где null = нет оверрайда).
- Валидация: `tier < 0` → 400 «тир не может быть отрицательным»; неизвестный
  id → 404 (ресурс — не 403: тир ресурса назначаемый, С3).
- Персист `state.json` атомарно (как все мутации).

### 9.2. `POST /api/goods/bulk` — подгрузка списка

Body: `{"lines": ["Стальной каркас | конструкционные материалы", …]}`.

Разбор каждой строки:

- **Разделитель — первый `|`** (вердикт критика М2): строка «название | категория»
  режется по **первому** «|»; остальные «|» — часть категории
  («Смазка термостойкая | химикаты» → имя «Смазка термостойкая», категория
  «химикаты»). **Название с «|» невозможно**: первый «|» всегда разделитель —
  если «|» нужен в названии, либо менять имя, либо использовать другой
  разделитель; правило не меняется (поправка 2026-09-19: прежний пример
  «Кислота A | B | химикаты» → имя «Кислота A | B» противоречил правилу — по
  первому «|» имя = «Кислота A», категория = «B | химикаты»).
- **Номер строки в отчёте = физический индекс в textarea (1-based)** (вердикт
  критика М2): пустые строки пропускаются молча и **не нумеруются** (в отчёте не
  появляются), но их позиции учитываются при нумерации остальных строк.

1. Пустая строка (после trim) → игнорируется молча (не ошибка, не считается, в
   отчёте не появляется).
2. Нет разделителя `|` → **ошибка строки** «нет разделителя „|"».
3. Имя пустое после trim → **ошибка строки** «пустое имя».
4. Категория пустая после trim → **ошибка строки** «пустая категория».
5. Категория не найдена (нормализованное совпадение с категориями студии,
   `graph.NormalizeName`, паттерн 99a.2 §4.3) → **ошибка строки**
   «категория не найдена: <имя>» (критик №7).
6. Имя — дубликат (нормализованное совпадение с существующим товаром ИЛИ с уже
   созданным в этой пачке) → **пропуск с предупреждением** «товар с таким именем
   уже есть» (критик №7: пропуск, не ошибка).
7. Иначе → создание товара: `draft`, один пустой слот (quantity 1), `source=manual`,
   категория = найденный id (паттерн `POST /api/goods`).

**Частичный успех** (строки независимы, паттерн ИИ-вставки 99a.1 §7.4): валидные
строки создаются, проблемные — в отчёте; состояние не откатывается.

```json
{
  "created": [{"id": "g55", "name": "Стальной каркас"}],
  "skipped": [{"line": 3, "name": "Дубликат", "reason": "товар с таким именем уже есть"}],
  "errors":  [{"line": 2, "reason": "категория не найдена: футур-материалы"}]
}
```

- `lines` отсутствует/пуст/не массив строк → 400.
- Защита от активной генерации **не требуется** (bulk только добавляет товары,
  не сносит; мутации сериализуются `s.mu`).
- Персист после пачки (одна запись, не на строку).

### 9.3. `GET /api/state` — дельта `GoodView`

```json
{
  "id": "g42", "name": "Штурмовой корабль", "category": "c1",
  "status": "approved", "kind": "good", "source": "manual",
  "tier": 7,             // эффективный (override ?? вычисленный)
  "tier_computed": 5,    // вычисленный (graph.Tier)
  "tier_override": 7,    // int | null (хранимое)
  "recipe": [ … ]
}
```

`SlotView.Tier` — эффективный тир составляющей (консистентность отображения).
`GoodView.tier` — эффективный тир (override ?? вычисленный). **Клиент использует
серверные поля для отображения** (бейджи карточек, подписи слотов, справочник,
«Используется в:») — локальный расчёт тиров на клиенте не используется (вердикт
критика М5, §11).

## 10. UI (дельта к 99a.1 §10 / 99a.1-ui)

### 10.1. Шапка

- Добавить галку **«всё дерево»** (localStorage `gs_fullTree`).
- Чекбокс **«показать ресурсы»** — виден только при включённом «всё дерево»

- Кнопка **«⟲ на верхний тир»** — только в режиме «всё дерево» (в фокус-режиме
  скрыта/disabled — центрирование по верхушкам не имеет смысла).
- Топбар-поиск и фильтр категорий — в фокус-режиме скрыты (§5.4, предложение);
  в режиме «всё дерево» — как сейчас.

### 10.2. Канвас

- Фокус-режим: подграф по §5. Пустое состояние — оверлей «Кликните товар в
  справочнике» (новый, приоритет после «загрузка/реестр пуст», 99a.1 §10.10).
- Клик по карточке — **только выбор** + перестроение подграфа; позиция/зум
  сохраняются (кликнутая карточка уже видна). Попап не открывается (навигация,
  §5.3).
- Выбор из справочника — подграф вокруг выбранного; предложение (гейт-вопрос):
  авто-центрирование на выбранном с сохранением зума (товар может быть далеко
  от текущего вида). Попап не открывается (§5.3).
- Двойной клик по карточке = выбор + открытие попапа-детали (§10.3).

### 10.3. Попап-деталь (вместо постоянной панели `#detail`)

**Требование создателя 2026-09-19:** «то, что над справочником в правой панели,
нужно вынести в попап, и открывать при клике на товар, а не показывать постоянно.
Справа останется только справочник и фильтры».

- Вся деталь товара (бывшая `#detail` из правой колонки) — **модальное окно
  (попап)** поверх канваса: имя (inline-переименование), категория (селект),
  тир-поле (§10.4), слоты с количеством и галкой `allow_resource`, кнопки
  («+ слот», «заполнить комплектующие», статусы, «добавить родителя», «удалить»),
  блок «Используется в:». Содержимое — как в 99a.1 §10.3 / 99a.1-ui §4.1,
  переносится без изменений логики.

**Привязка к товару попапа (вердикт критика С1):** попап держит **явный объект
`popupGoodId`**, отдельный от глобального `selected` — попап может быть открыт на
товаре X при selected=Y. **Все действия в попапе** (dropOnSlot, setQuantity,
setStatus, rename, category, addSlot/clearSlot/delSlot/setAllowResource, fillGood,
addParent, tier, delete) шлют PUT/POST в `/api/goods/{popupGoodId}` — **не в
`selected`**. Закрытие попапа выбор не сбрасывает.

**Открытие** (отдельным действием, §2 развилка 6):
- **двойной клик** по карточке (канвас или справочник) = выбор (`selected` =
  товар, подграф перестраивается) **+** попап на этом товаре;
- **кнопка «деталь» (ⓘ)** на карточке справочника = попап на этом товаре **без
  смены `selected`** (подграф не перестраивается);
- **контекстное меню → «открыть деталь»** на карточке канваса = как двойной клик
  (выбор + попап; пункт уже есть в `showCtxMenu`).

**Навигация «Используется в:»** (клик по родителю в попапе) = открыть попап на
родителе **и выбрать его** (`selected` = родитель, подграф перестраивается, попап
показывает родителя).

**Закрытие**: Esc / крестик / клик по подложке. **Закрытие не сбрасывает
выбор** — подграф остаётся вокруг выбранного.

**Удаление товара попапа (вердикт критика М3):** если товар, на котором открыт
попап, удалён (кнопка «удалить» в попапе или извне — импорт, авто-обновление,
другая сессия) — попап закрывается (`popupGoodId = null`); `selected`
сбрасывается, если удалённый был выбран.

- Один попап одновременно; открытие попапа другого товара заменяет содержимое.
- Попап перетаскиваемый (drag заголовка); размер фиксированный или по контенту
  (решает @uidesigner). Авто-обновление 3 с не сбрасывает открытый попап
  (99a.1 §10.12), но перерисовывает содержимое из свежего состояния.
- Ресурс в попапе — деталь без слотов (ресурс — лист; переименование/категория/
  тир/статусы/удаление доступны — ресурсы без привилегий, идея переноса §1.2);
  забаненный — деталь с «Вернуть»/«удалить».

### 10.4. Тир в попапе

Строка тира (для товаров и ресурсов): **«тир: [input number] (вычислен N)»**:

- input пустой = оверрайда нет, тир вычисленный (текущее поведение);
- ввод числа → `PUT /api/goods/{id}/tier` `{tier: X}` (change/blur; ошибка — тост,
  значение возвращается);
- очистка input → `PUT {tier: null}` → снова вычисляется (критик №9);
- при заданном оверрайде ≠ вычисленному — жёлтая метка «⚠ отличается от
  вычисленного (N)» (не блокер, критик №2);
- для ресурсов — тир-поле как у товаров (оверрайд; тир ресурса назначаемый, С3).

Бейдж «тир N» на карточках графа, в справочнике и подписи слотов — **эффективный
тир из серверных полей** (`GoodView.tier` / `SlotView.Tier`, §9.3); клиентский
`tierOf` для отображения не используется (вердикт критика М5, §11).

### 10.5. Справочник (правая панель — единственный постоянный раздел)

Структура раздела:

```
[Справочник]
[поиск по имени ........................]
[ ] используемые  [ ] неиспользуемые  [ ] T0  [ ] забаненные
[+ товар]  [▾ подгрузка списка]
— список карточек (все товары; banned — только при галке) —
```

- Список: все товары + ресурсы из `state.goods` (развилка 4), фильтры/поиск по
  §8.2; пересборка без сброса scroll (как сейчас для палитры).
- Карточки: draggable (`dragStart`), клик — выбор на канвасе (§8.3), двойной
  клик / кнопка «деталь» (ⓘ) — попап (§10.3).
- «+ товар»: имя + селект категории + кнопка (поведение как addbar, §8.4).
- «Подгрузка списка»: сворачиваемый блок — textarea (placeholder
  «название | категория» по строке) + кнопка «Создать из списка» → `POST
  /api/goods/bulk` → тост-отчёт (создано/пропущено/ошибки с номерами строк).
- Секции «Ресурсы (палитра)», «Неиспользуемые» и панель «Забаненные»
  **убираются** (развилки 5, 7; фильтры покрывают). `fetchResources`/`/api/resources`
  остаются в коде, но UI справочник их не использует (обратная совместимость,
  эндпоинт не трогаем).
- Переключатель «забаненные» в шапке (показ забаненных карточек на графе)
  остаётся для режима «всё дерево» (99a.1 §10.5); в фокус-подграфе забаненные
  родители/дети показываются приглушёнными **всегда** (структура подграфа полная,
  рёбра не обрываются — уточнение к 99a.1 §10.5, гейт-вопрос №7).

## 11. Что не трогать (инварианты UI — перенос из 99a.1 §10.13 + 99a.1-ui §7)

- **Логика слотов не меняется** (создатель 2026-09-19): слоты живут в попапе-детали
  (перенос из правой панели без изменения логики), `dropOnSlot`/`setQuantity`/
  `allow_resource` — как есть; количество в слоте — как есть (99a.2); на канвас
  слоты-приёмники и количество **не добавляются**.
- **Действия попапа идут по `popupGoodId`** (вердикт критика С1), не по
  `selected`: dropOnSlot/setQuantity/setStatus/rename/category/addSlot/clearSlot/
  delSlot/setAllowResource/fillGood/addParent/tier/delete — в
  `/api/goods/{popupGoodId}`; попап может быть открыт на X при selected=Y.
- **Клиент не вычисляет тиры для отображения** (вердикт критика М5): бейджи и
  подписи слотов берутся из серверных полей `GoodView.tier` / `SlotView.Tier`
  (эффективный тир, §9.3).
- **Статусы и семантика (§5.2):** бан/исключённое ИИ не предлагается; разбан в
  один клик; забаненные скрыты из справочника по умолчанию (галка «забаненные»,
  §8.2), «Вернуть» — в попапе забаненного.
- **Тиры структурно — производные от графа (§6.1):** оверрайд — только ручная
  правка значения наружу (§4.2); граф, глубина, валидаторы, циклы не зависят.
- **Ресурсы без привилегий (§1.2 идеи переноса, С1/С3):** переименование/удаление/
  смена категории/оверрайд тира/статусы доступны (тир ресурса назначаемый, С3);
  слоты недоступны (ресурс — лист, 403).
- **Экспорт = только согласованные (§11):** правило не меняется; меняется только
  источник `complexity` (эффективный тир).
- **DAG и уникальность имён (§6.2/§6.3):** UI показывает ошибки сервера, не обходит.

**Критерии приёмки (проверка @tester после разработки):**
1. Создатель открывает студию → канвас пуст с подсказкой «Кликните товар в
   справочнике»; клик по товару в справочнике → подграф вокруг него (родители
   сверху, дети снизу, ресурсы видны), попап НЕ открывается.
2. Клик по родителю/ребёнку на канвасе → подграф перестраивается вокруг нового
   выбора (попап не открывается); клик по пустому месту → сброс к подсказке.
3. Галка «всё дерево» → полный граф (как раньше); чекбокс «показать ресурсы»
   появляется только в этом режиме; «⟲ на верхний тир» работает только здесь.
4. Попап-деталь: двойной клик по карточке (канвас/справочник) = выбор + попап;
   кнопка «деталь» (ⓘ) = попап **без смены selected** (попап на X при selected=Y,
   все действия попапа идут по X); Esc/крестик/подложка закрывают, выбор и
   подграф сохраняются; попап перетаскивается; содержимое = бывшая деталь
   (слоты, тир, кнопки, «Используется в:»); клик по родителю в «Используется в:»

   (selected сбрасывается, если это был он).
5. В попапе поле тира: пусто = вычисленный; ввод 7 → бейджи/попап/справочник

   вычисленный; экспорт: complexity = 7.
6. Оверрайд не влияет на «заполнить комплектующие» (промпт/ответ ИИ — по
   вычисленному тиру).
7. Справочник: поиск по товарам и ресурсам; галки «используемые»/«неиспользуемые»/
   «T0»/«забаненные» фильтруют (комбинации); забаненные видны только при галке
   (приглушённые), попап забаненного содержит «Вернуть»; карточки перетаскиваются
   в слоты попапа.
8. Подгрузка списка: «Стальной каркас | конструкционные материалы» → создан
   черновик; «X | несуществующая» → ошибка с номером строки; повтор «Стальной
   каркас | …» → пропуск с предупреждением.
9. Логика слотов/количество не изменились (регрессия 99a.1/99a.2: dropOnSlot,
   setQuantity, allow_resource, импорт).
10. Игровой сервер не затронут: `go build ./...` чистый.
