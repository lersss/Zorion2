## 1. Цель и скоуп

Довести UI студии до решений создателя 2026-09-19 (идея 99a.3): канвас по умолчанию
работает в режиме **фокус-подграфа** («вокруг выбранного»), полный граф — галкой
«всё дерево»; деталь товара выносится из правой панели в **попап** (открывается
отдельным действием); правая панель = **только справочник** (все товары + ресурсы,
поиск, галки-фильтры, «+ товар», подгрузка списка); тир-оверрайд — поле в попапе.

**В скоупе:** режимы канваса (фокус / всё дерево) и видимость топбар-элементов;
пустое состояние «Кликните товар в справочнике»; авто-центрирование при выборе
из справочника; попап-деталь (перенос `renderDetail` без изменения логики,
тир-поле, открытие/закрытие, перетаскивание, навигация «Используется в:»);
справочник (единый список, поиск, галки-фильтры, карточки с ⓘ, «+ товар»,
подгрузка списка); фильтр тиров (пилюли вместо «T0»); попап категорий
(создание/переименование/удаление, inline-rename); структура шапки (сегменты
по функции); состояния забаненных; localStorage новых переключателей.

**НЕ в скоупе:** Go-код (зона @developer по 99a.3); логика слотов и количество
(99a.2 — как есть, переносится в попап без изменений); слоты-приёмники на канвасе
(не возвращаем); стилистика мира (@gdesigner не зовём — как 99a.1-ui §1/§3.7).

### 2.2. Что меняется / появляется

1. **Канвас — фокус-подграф по умолчанию** (99a.3 §5): рисуется только выбранный +
   прямые родители + прямые дети (1 уровень) + плейсхолдеры пустых слотов выбранного.
   Сейчас рисуется весь граф.
2. **Галка «всё дерево»** в шапке (localStorage `gs_fullTree`): включает старую
   логику полного графа. Сейчас её нет.
3. **Топбар по режимам** (99a.3 §10.1): в фокус-режиме скрыты поиск по графу,
   фильтр категорий, «показать ресурсы», «⟲ на верхний тир», «забаненные» (канвас),
   «обратные рёбра»; в полном дереве — видны. Сейчас все видны всегда.
4. **Правая панель — только справочник**: секции «Ресурсы (палитра)» (`#resList`),
   «Неиспользуемые» (`#unusedList`), панель «Забаненные» (`#bannedPanel`) убираются
   (99a.3 §8.1, развилки 5/7). `fetchResources`/`/api/resources` остаются в коде,
   UI их не использует (обратная совместимость).
5. **Деталь → попап**: `#detail` из правой панели уезжает в модальное окно поверх
   канваса (99a.3 §10.3, требование создателя). Открытие — отдельным действием.
6. **Тир-оверрайд** — поле в попапе (99a.3 §10.4); бейджи тира на карточках
   показывают **эффективный** тир (`tier` из GoodView).
7. **Пустое состояние** фокус-режима — оверлей «Кликните товар в справочнике».
8. **Авто-центрирование** при выборе из справочника (зум сохраняется, 99a.3 §10.2).

### 2.3. Замечания по фактам (учесть)

1. `hitTest` считает `computeLayout()` каждый вызов — в фокус-режиме множество
   меньше, пересчёт дешевле; замечание остаётся как есть (не оптимизируем сверх
   скоупа).
2. `renderAll` сохраняет scroll правой панели через `$("right").scrollTop` —
   сохранить и для справочника (длинный список).
3. `visibleGoods()` фильтрует по галке «забаненные» (`showBanned`) — в фокус-режиме
   этот фильтр не применяется (подграф полный по построению, §3.1), а галка скрыта.
4. Контекстное меню не показывается для ресурсов (read-only) — сохраняется; пункт
   «открыть деталь» должен открывать попап ресурса (read-only деталь) — уточнение:
   для ресурсов контекстное меню скрыто сейчас, попап ресурса открывается из
   справочника (ⓘ/двойной клик) и с канваса (двойной клик).

## 3. Канвас: режимы и состояния

### 3.1. Фокус-подграф (режим по умолчанию, `gs_fullTree` выкл)

**Множество раскладки** (вычисляется на клиенте из `state.goods`):
- **выбранный** товар;
- **прямые родители** — `state.goods.filter(p => (p.recipe||[]).some(s => s.good_id === selected))` (1 уровень, не цепочка);
- **прямые дети** — заполненные составляющие из `recipe` выбранного (1 уровень);
- **плейсхолдеры пустых слотов выбранного** (пунктирные карточки, как сейчас).

Ресурсы, попавшие в подграф (дети-ресурсы выбранного), **видны всегда** —
чека «показать ресурсы» в фокус-режиме нет (99a.3 §5.1). Родители-ресурсы
невозможны (у ресурсов нет рецептов).

**Раскладка** — параметризация существующего `computeLayout(subset)` (99a.3 §5.2):
`depthOf` в пределах множества → родители глубина 0, выбранный 1, дети 2,
плейсхолдеры 3. Древесный алгоритм, орто-рёбра, рёбра к плейсхолдерам — без
изменений. Редкие DAG-случаи обрабатываются алгоритмом автоматически.

**Визуальный результат компоновки:**
```
[родитель A]   [родитель B]        ← ряд 0 (прямые родители, сверху)
     │  \        /
   [ВЫБРАННЫЙ]                     ← ряд 1 (центр, выделен)
    ╱    │     ╲
[дочь 1] [дочь 2] [⚙ ресурс]       ← ряд 2 (прямые дети, снизу)
  [плейсхолдер пустого слота]      ← ряд 3 (только пустые слоты выбранного)
```

**Выделение выбранного** (усиление существующего): рамка #8cf остаётся (lineWidth 2),
добавляется **подсветка фона** карточки (заливка на 1 тон светлее обычной карточки,
например `#4a4a4a` против `#3d3d3d`) — выбранный читается как «центр подграфа»
с первого взгляда. Родители/дети — обычные карточки (рамка #5a5a5a).

**Индикатор режима:** статичный бейдж в левом нижнем углу канваса (над областью
канваса, под оверлеями): фокус — «фокус: вокруг выбранного», полное дерево —
«всё дерево». Маленький (11px, #666, фон #1c1c1ccc, radius 6px), не кликабелен,
не перекрывает карточки. Плюс видимость топбар-элементов (§3.4) уже сигнализирует
режим; бейдж — страховка для неочевидного случая «выбор есть, но подграф не
построен».

**Пустое состояние** (выбор сброшен, товары есть): канвас пуст, поверх — оверлей
**«Кликните товар в справочнике»** (текст + иконка-стрелка вправо `→` как намёк на
правую панель). Приоритет оверлеев: загрузка > реестр пуст > «Кликните товар в
справочнике» (только фокус-режим) > «ничего не найдено» (только полное дерево).
Оверлей исчезает при первом же выборе (клик по карточке справочника/канваса).

**Навигация:**
- Клик по карточке родителя/ребёнка = **новый выбор** → подграф перестраивается
  вокруг него; попап НЕ открывается (клик = навигация).
- Клик по пустому месту без движения = сброс выбора → пустое состояние.
- Двойной клик по карточке = выбор + открытие попапа (§4.2).
- Выбор из справочника = выбор + подграф + **авто-центрирование** (§3.3); попап
  НЕ открывается.
- Авто-обновление 3 с: выбор сохраняется; удалён выбранный товар → `selected=null`
  → пустое состояние (уже так в коде).

### 3.2. Режим «всё дерево»

- Галка **«всё дерево»** в шапке (localStorage `gs_fullTree`, дефолт выкл).
- Вкл = текущая логика полного графа: `visibleGoods()` + `depthOf` по всему графу,
  ряды по глубине (решение создателя 2026-09-19, критик №4).
- Чекбокс **«показать ресурсы»** — только в этом режиме (дефолт выкл, как сейчас,
  `gs_showResources`). В фокус-режиме скрыт.
- «⟲ на верхний тир» (`centerTop`) — только в этом режиме (в фокус-режиме
  центрирование по верхушкам бессмысленно).
- «Забаненные» (канвас-галка `showBanned`) — только в этом режиме (в фокус-режиме
  забаненные в подграфе приглушены всегда, §5).
- «Обратные рёбра» (`reverseEdges`) — только в этом режиме (в фокус-режиме
  родители подграфа уже связаны с выбранным прямыми рёбрами; обратная подсветка
  избыточна — предложение, §7 «Открытые вопросы»).
- Поиск по графу и фильтр категорий (`#search`/`#catFilter`) — только в этом
  режиме (в фокус-режиме скрыты: подграф полон по построению, справочник имеет
  собственные поиск/фильтры).

### 3.3. Авто-центрирование при выборе из справочника

Клик по карточке справочника → `selected = id` → подграф построен → **panX/panY
пересчитываются так, чтобы выбранный оказался в центре канваса** (формула как в
`centerTop`, но по позиции выбранного из свежей раскладки), **zoom не меняется**.
Обоснование: товар может быть далеко от текущего вида канваса (список длинный,
подграф маленький) — без центрирования подграф мог бы оказаться вне экрана.
При клике по карточке на самом канвасе центрирование НЕ выполняется (карточка
уже видна, позиция сохраняется — решение 99a.3 §10.2).

### 3.4. Видимость топбар-элементов по режимам

| Элемент шапки | Фокус-подграф | Всё дерево |
|---|---|---|
| Галка «всё дерево» | видна | видна |
| Поиск по графу `#search` | **скрыт** | виден |
| Фильтр категорий `#catFilter` | **скрыт** | виден |
| «показать ресурсы» `#showResources` | **скрыт** | виден |
| «забаненные» `#showBanned` (канвас) | **скрыт** | виден |
| «обратные рёбра» `#reverseEdges` | **скрыт** (предложение) | виден |
| «⟲ на верхний тир» `#btnTop` | **скрыт** | виден |
| Экспорт / Импорт | видна | видна |
| Модель ИИ / индикатор генерации | видно | видно |

Скрытие — `display:none` (не `disabled`): не занимает место, не сбивает раскладку
шапки. Переключение галки «всё дерево» → перерисовка канваса + пересборка
видимости элементов (§6). Компоновка сегментов шапки (какие элементы в какие
группы собраны) — §13.

## 4. Попап-деталь (вместо `#detail` в правой панели)

### 4.1. Контейнер и позиционирование

Новый элемент `#detailPopup` — **absolute внутри `#main`** (поверх `#canvasWrap`,
НЕ fixed по окну), поверх канваса, с затемняющей подложкой `#detailOverlay`
(absolute внутри `#main`, `background:#000a`, z-index ниже попапа, выше канваса).
**Правая панель справочника подложкой НЕ перекрывается и остаётся активной** —
иначе drag&drop карточки из справочника в слоты попапа был бы невозможен
(ключевой workflow: слоты теперь живут в попапе).

Параметры (решение @uidesigner, 99a.3 §10.3 «решает»):
- ширина **фиксированная 400px** (хватает слоту: имя + тир + количество + две
  кнопки-иконки);
- высота **по контенту**, максимум 80% высоты `#main`, внутренний scroll
  (`overflow-y:auto`);
- стартовая позиция — центр канваса; **перетаскивается за заголовок** (mousedown
  на заголовке → move → mouseup; при движении курсор `grabbing`), позиция живёт
  в пределах сессии (в localStorage не сохраняем — не критично);
- заголовок: имя товара (или «Деталь: <имя>» для ресурсов) + кнопка-крестик `×`
  (справа), курсор `move`.

**Псевдо-HTML:**
```
<div id="main">
  <div id="canvasWrap"> … канвас, оверлеи, бейдж режима … </div>
  <div id="detailOverlay" style="display:none"></div>   ← подложка канваса
  <div id="detailPopup" style="display:none">           ← попап-деталь
    <div class="popup-head" title="перетащить"> <имя> [×] </div>
    <div class="popup-body"> … содержимое бывшей #detail … </div>
  </div>
  <div id="right"> … справочник … </div>
</div>
```

### 4.2. Открытие и закрытие

**Открытие** (отдельным действием, 99a.3 §10.3; решение гейт-вопроса №6):
- **двойной клик** по карточке на канвасе = выбор + попап;
- **двойной клик** по карточке справочника = выбор + попап;
- **кнопка «деталь» (ⓘ)** на карточке справочника = попап **без смены выбора**
  (попап — отдельное окно; клик по карточке = выбор, ⓘ = деталь);
- **контекстное меню → «открыть деталь»** (пункт уже есть в `showCtxMenu`,
  сейчас вызывает `selectGood`) = выбор + попап.

Один попап одновременно; открытие попапа другого товара (двойной клик по другой
карточке, ⓘ другой карточки, клик «Используется в:») **заменяет содержимое**.

**Закрытие:** Esc / крестик в заголовке / клик по подложке. **Выбор и подграф
сохраняются** (закрытие не сбрасывает выбор — 99a.3 §10.3). Esc работает только
когда нет открытой модалки подтверждения (приоритет у `#modalOverlay`).

**Авто-обновление 3 с:** открытый попап не сбрасывается, содержимое
перерисовывается из свежего `state` (как сейчас `renderDetail` при каждом
`renderAll`).

### 4.3. Содержимое (перенос `renderDetail` без изменения логики)

```
┌──────────────────────────────────────────────┐
│ «Стальной каркас»                      [×]   │  ← заголовок, drag; имя клик = inline-rename
│ категория ▾ · тир: [ 7 ] (вычислен 5) ⚠      │  ← тир-поле (§4.4); для ресурсов «тир 0» статично
│ [✓ согласовано] · [ИИ]                       │  ← статус-бейдж, источник
│ ─ слоты ─                                    │
│   слот: «Болт М8» · тир 2 ×[3]  [×] [🗑]      │  ← заполненный: имя · тир · количество · «×» · «🗑»
│        (reason ИИ)                           │
│   слот: пусто — перетащите карточку   [🗑]    │  ← пустой: подсказка + allow_resource галка
│        [✓] заполнять ресурсом                │
│ [+ слот] [заполнить комплектующие]           │  ← fill disabled: генерация / нет пустых
│ [Согласовать] [Исключить] [Забанить]         │  ← статусы (banned → [Вернуть])
│ [Используется в:]                            │
│   «Штурмовой корабль» · тир 7   ← кликабельно │
│ [добавить родителя] [удалить]                │  ← удалить → модалка подтверждения (как сейчас)
└──────────────────────────────────────────────┘
```

- **Имя** — inline-переименование (клик → input → Enter/Blur → `PUT /api/goods/{id}`),
  как сейчас; для ресурсов — статичный текст.
- **Категория** — селект категорий студии (change → PUT), как сейчас; для
  ресурсов — текст.
- **Слоты** — дословно текущая разметка `renderDetail` (слоты 668–684):
  заполненный (`имя · тир эффективный · ×quantity input · reason · «×» · «🗑»`),
  пустой (`пусто — перетащите сюда карточку` + галка `allow_resource` + «🗑»);
  оба — drop-target (`slotDragOver`/`slotDragLeave`/`dropOnSlot`);
  `setQuantity`/`setAllowResource`/`clearSlot`/`delSlot` — без изменений.
  Тир в заполненном слоте — **эффективный** (`SlotView.Tier`, 99a.3 §4.3).
- **Кнопки** — «+ слот», «заполнить комплектующие» (disabled при `state.generating`
  или без пустых слотов, тултип как сейчас), статусы (Согласовать/Исключить/
  Забанить/Вернуть), «добавить родителя» (модалка выбора родителя — как сейчас),
  «удалить» (модалка подтверждения). Для ресурсов — только «Забанить»/«Вернуть».
- **«Используется в:»** — список родителей (кликабельно). Клик по родителю =
  **новый выбор + подграф вокруг него + содержимое попапа заменяется на родителя**
  (навигация внутри попапа, 99a.1-ui §4.6 «деталь родителя открывается»). Пусто —
  «нигде не используется».
- **Забаненный** в попапе — кнопка «Вернуть» (один клик, без подтверждения) и
  «удалить» (модалка), как сейчас в `#bannedPanel`.

### 4.4. Тир в попапе (99a.3 §10.4)

Строка тира для `kind=good`:

```
тир: [input number min=0] (вычислен N)
```

- input **пустой** = оверрайда нет → тир вычисленный (текущее поведение);
  рядом подпись «(вычислен N)» — всегда видна;
- **ввод числа** (change/blur) → `PUT /api/goods/{id}/tier` `{tier: X}`; ошибка —
  тост, значение возвращается (перерисовка из state);
- **очистка input** → `PUT {tier: null}` → снова вычисляется (критик №9);
- **расхождение** override ≠ computed — жёлтая метка под полем:
  `⚠ отличается от вычисленного (N)` (цвет #fa0, не блокер, полная свобода);
- input с числом показывает значение оверрайда; бейджи на карточках графа и в
  справочнике показывают **эффективный** тир (`tier` из `GoodView`) — обновляются
  после PUT (перерисовка из свежего state).
- **Ресурсы:** статичный «тир 0», поля нет (read-only).

## 5. Справочник (правая панель — единственный постоянный раздел)

### 5.1. Структура

```
[Справочник · N]                              ← заголовок + счётчик видимых карточек
[поиск по имени .........................]     ← инкрементальный, по всем товарам и ресурсам
[ ] используемые  [ ] неиспользуемые          ← одна группа (объединение)
[ ] забаненные                                ← отдельная группа (пересечение)
тир: [0] [1] [2] [3] [4] [5] [6] [7] [8]     ← фильтр тиров (пилюли, динамические; пусто = все)
[+ товар]  [▾ подгрузка списка]
— список карточек (все товары + ресурсы; banned — только при галке) —
```

- **Заголовок** «Справочник» + счётчик «· N» (число карточек после поиска/фильтров;
  как сейчас `resTitle` «Ресурсы (палитра) · N»).
- **Поиск** — по имени, по всем товарам и ресурсам (инкрементальный, `input` →
  пересборка списка без сброса scroll).
- **Галки-фильтры** (по умолчанию все выключены — виден весь список):
  - **«используемые»** — входящая степень > 0 (`used[good_id]`, как в
    `renderPalette`);
  - **«неиспользуемые»** — входящая степень 0 (не забаненные; ресурсы с in-degree 0
    тоже — «показать все неиспользуемые ресурсы»);
  - обе галки **комбинируются** (обе вкл = все товары);
  - **«забаненные»** — показать забаненных (приглушённые карточки),
    localStorage `gs_spravBanned`, дефолт выкл.
  - Группы: «используемые/неиспользуемые» — объединение; «забаненные» —
    отдельная; между группами пересечение. Поиск применяется поверх.
- **Фильтр по тиру** (вместо галки «T0», решение создателя 2026-09-19) — §5.3.
- **«+ товар»** — имя + селект категории + кнопка (дублирует addbar в шапке —
  обе работают одинаково: `POST /api/goods` → черновик с одним пустым слотом →
  авто-выбор + подграф; критик №8: оставить обе).
- **«Подгрузка списка»** — сворачиваемый блок (`▾`/`▸`):
  - textarea (placeholder «название | категория» — по строке);
  - кнопка «Создать из списка» → `POST /api/goods/bulk` → **тост-отчёт**:
    «Создано N, пропущено M, ошибок K» + построчно с номерами строк (пример:
    «строка 2: категория не найдена: футур-материалы»);
  - после успешного ответа textarea очищается (созданные строки ушли в реестр,
    проблемные — в отчёте);
  - созданные товары — карточки-черновики в списке (приходят с `/api/state`).

### 5.2. Карточки

```
┌──────────────────────────────┐
│ Имя товара            [ⓘ]    │  ← draggable (grab), ⓘ = попап
│ Категория · тир N  [бейдж]   │  ← тир эффективный, бейдж статуса
└──────────────────────────────┘
```

- **Draggable** — `dragStart` (как сейчас `renderPalette`), источник drag&drop в
  слоты **попапа** (`dropOnSlot`; логика слотов не меняется).
- **Клик** = выбор на канвасе + подграф + авто-центрирование (§3.3); попап НЕ
  открывается.
- **Двойной клик** = выбор + попап (§4.2).
- **ⓘ** = попап без смены выбора (§4.2).
- **Тир** на карточке — эффективный (99a.3 §4.2). **Бейдж** — статус
  (`b-approved`/`b-draft`/`b-excluded`/`b-banned`/`b-resource`), как сейчас.
- **Забаненные** (при включённой галке) — приглушённые карточки (opacity .55,
  серый фон), попап забаненного с «Вернуть»/«удалить» (§4.3).
- Пересборка списка — без сброса scroll (`$("right").scrollTop`, как сейчас).

### 5.3. Фильтр по тиру (вместо галки «T0»)

**Решение создателя 2026-09-19:** «Вместо галки "Т0" давай сделаем возможность
выбора любого тира, или нескольких тиров». Галка «T0» (`#fT0`) **удаляется**
(из разметки, стилей и логики `renderSprav`); её роль берёт фильтр тиров:
ресурсы — тир 0, их видимость теперь управляется выбором тира 0.

#### 5.3.1. Выбранный вариант: пилюли-чекбоксы тиров

Из трёх вариантов выбран **(б) — ряд маленьких чекбоксов-пилюль «0..N»**:

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| (а) dropdown-мультивыбор | компактный (1 контрол) | нужен кастомный JS (открытие/закрытие/фокус), лишний клик, скрытые опции | нет |
| **(б) пилюли-чекбоксы** | все тиры видны сразу, один клик, нативный HTML/JS (как существующие галки), ортогональность очевидна | ряд шире одного контрола | **да** |
| (в) два числа (от-до) | очень компактно | нельзя выбрать «0 и 3, но не 1–2» (нужна комбинация), теряется смысл «нескольких тиров» | нет |

Обоснование: (а) скрывает варианты за кликом и требует кастомного dropdown-кода
в узкой панели 320px; (в) не выражает дискретный мультивыбор (создатель: «любого
тира, или нескольких тиров»). Пилюли показывают ВСЕ тиры (0..~8 в текущих данных),
выбираются кликом, по стилю согласованы с существующими галками фильтров.
Тиров мало (0..8 при 394 товарах) — ряд помещается в панель; при росте числа
тиров пилюли аккуратно переносятся на вторую строку (flex-wrap).

#### 5.3.2. Список тиров — динамический

- Строится из `state.goods`: уникальные **эффективные** тиры (`g.tier` из
  `GoodView`, 99a.3 §4.3), отсортированные по возрастанию.
- Пилюли пересобираются при пересборке справочника (в `renderSprav`), но выбор
  сохраняется: состояние хранится в `tierSel` (JS-сет), пилюли рисуются по нему.
- Тиров 0..8 в текущих данных; ряд переносится — не ломается.

#### 5.3.3. Поведение

- **Пустой выбор** (ничего не отмечено) = фильтр тиров выключен → видны все
  товары (и ресурсы — тир 0). По умолчанию пусто.
- **Отмечены тиры {T}** → в списке только товары с `g.tier ∈ T`. Ресурсы (тир 0)
  видны **только если отмечен 0** (задача: «выбор "только тир 3" показывает
  товары тира 3, и ресурсы — только если выбран 0»).
- **Ортогональность**: фильтр тиров пересекается (AND) с галками «используемые»/
  «неиспользуемые»/«забаненные» и поиском (как раньше галка «T0»).
- Клик по пилюле — мгновенная пересборка списка, без сброса scroll, без сброса
  выбора на канвасе и без закрытия попапа (как галки-фильтры, §6).
- localStorage: выбор тиров **не сохраняется** (по умолчанию пусто при каждом
  заходе; как галки «используемые»/«неиспользуемые»).

#### 5.3.4. HTML-структура (в `.sprav-head`, после `.filters`)

```html
<div class="tierf">
  <span class="tierf-label" title="Фильтр по тиру (эффективному); пусто = все тиры">тир:</span>
  <span id="tierPills">
    <!-- пилюли строятся динамически из state.goods: -->
    <label class="pill"><input type="checkbox" value="0" ...>0</label>
    <label class="pill"><input type="checkbox" value="1" ...>1</label>
    ...
  </span>
</div>
```

- `.tierf` — строка-обёртка: `display:flex;align-items:center;gap:4px;
  flex-wrap:wrap;margin-bottom:6px`.
- `.tierf-label` — подпись «тир:», 11px, #666, `white-space:nowrap`.
- `.pill` — пилюля: `display:inline-flex;align-items:center;gap:3px;font-size:11px;
  background:#222;border:1px solid #444;border-radius:10px;padding:1px 8px;
  cursor:pointer;color:#ddd`. Внутри — нативный чекбокс (скрытый визуально:
  `input{appearance:none;width:0;height:0;margin:0}`), подпись — цифра тира.
- `.pill.on` — отмеченная пилюля: `background:#26a;border-color:#26a;color:#fff`
  (акцент как у `.gen`).
- Пилюля «0» — `title="тир 0 — ресурсы"` (подсказка, что 0 = ресурсы).
- `.pill:hover` — `background:#363636;border-color:#5a5a5a` (как карточки).

#### 5.3.5. Что происходит с галкой «T0»

- `#fT0` удаляется: из `.filters` разметки, из `renderSprav` (строка
  `if (!fT0 && g.kind === "resource") return false;`), из обработчика
  `$("fT0").addEventListener` и из инициализации. localStorage для неё не было.
- Товары с пустым рецептом (тир 0, рабочие черновики) — по-прежнему видны в
  списке по умолчанию (пустой фильтр тиров); при отмеченном 0 — вместе с
  ресурсами. Решение критика №5 («товары с пустым рецептом не прячем»)
  сохраняется.

## 6. Реактивность (дельта к 99a.3 §10.6)

| Действие | Результат |
|---|---|
| Переключение «всё дерево» | перерисовка канваса (подграф ↔ полный граф); видимость топбар-элементов §3.4; выбор и справочник не сбрасываются |
| Клик по карточке на канвасе (родитель/ребёнок) | новый выбор, подграф перестроен; попап не открывается |
| Клик по пустому месту канваса | сброс выбора → оверлей «Кликните товар в справочнике» (фокус-режим) |
| Клик по карточке справочника | выбор + подграф + авто-центрирование (зум сохранён); попап не открывается |
| Двойной клик (канвас/справочник), ⓘ, «открыть деталь» | попап открывается / заменяет содержимое |
| Клик по «Используется в:» → родитель | выбор на родителя, подграф вокруг него, содержимое попапа заменяется |
| Esc / крестик / подложка попапа | попап закрыт; выбор и подграф сохраняются |
| Ввод/очистка тира в попапе | PUT tier → перерисовка (бейджи, попап, справочник); ошибка — тост, значение возвращается |
| Галки-фильтры справочника (используемые/неиспользуемые/забаненные) | пересборка списка (счётчик «· N»); выбор и канвас не сбрасываются |
| Пилюли фильтра тиров (§5.3) | клик по пилюле — мгновенная пересборка списка по `g.tier ∈ tierSel`; пустой выбор = все тиры; выбор/канвас/попап не сбрасываются |
| Поиск в справочнике | пересборка списка по имени, без сброса scroll |
| «Создать из списка» | POST bulk → тост-отчёт по строкам; новые карточки-черновики в списке; textarea очищена |
| «+ товар» (справочник или addbar) | товар создан, выбран, подграф вокруг него; addbar-поле очищено |
| Авто-обновление 3 с | выбор/зум/пан/попап/модалки не сбрасываются; содержимое попапа перерисовано |
| Удаление выбранного товара (авто-обновление) | `selected = null` → пустое состояние с подсказкой (фокус-режим) |

Все мутации — через API без оптимистичных обновлений (как сейчас, 99a.1 §10.11).

**localStorage:** `gs_fullTree` (новое, дефолт выкл), `gs_spravBanned` (новое,
дефолт выкл), `gs_showResources`/`gs_showBanned`/`gs_reverseEdges`/`gs_catFilter`
(есть — применяются только в режиме «всё дерево»), zoom/pan (есть). Фильтр тиров
в localStorage **не пишется** (пусто при каждом заходе, §5.3.3).

## 7. Состояния (забаненные, оверлеи)

### 7.1. Забаненные

- **В фокус-подграфе** — забаненные родители/дети показываются **приглушёнными
  всегда** (независимо от галок): структура подграфа полная, рёбра не обрываются
  (99a.3 §10.5, гейт-вопрос №7). Приглушение — как сейчас `#3a3a3a` + бейдж «⛔ бан».
- **В полном дереве** — по канвас-галке «забаненные» (`gs_showBanned`, как сейчас).
- **В справочнике** — по галке «забаненные» (`gs_spravBanned`), приглушённые
  карточки; «Вернуть» — в попапе.

### 7.2. Оверлеи канваса (приоритет сверху вниз)

| Состояние | Условие | Оверлей |
|---|---|---|
| Загрузка | первый `/api/state` не пришёл | спиннер «Загрузка…» (как есть) |
| Реестр пуст | `state.goods.length === 0` | «Реестр пуст — добавьте первый товар» + [«+ товар»] (как есть) |
| Нет выбора (фокус-режим) | товары есть, `selected == null`, `gs_fullTree` выкл | **«Кликните товар в справочнике»** (+ стрелка `→` вправо) |
| Ничего не найдено | полное дерево, `visibleGoods()` пуст | «ничего не найдено» (как есть) |
| Сеть потеряна | fetch упал | пилюля «нет связи, повтор через 3 с» (как есть) |

Оверлеи не перекрывают правую панель. Бейдж режима (§3.1) — под оверлеями.

## 8. Критерии приёмки (проверка @tester после разработки)

1. **Фокус-режим по умолчанию:** открыл студию → канвас пуст с оверлеем
   «Кликните товар в справочнике»; клик по товару в справочнике → подграф вокруг
   него (родители сверху, дети снизу, ресурсы видны, выбранный — подсвечен),
   попап НЕ открывается, вид авто-центрирован, зум сохранён.
2. **Навигация подграфа:** клик по родителю/ребёнку → подграф перестраивается
   вокруг нового выбора (попап не открывается); клик по пустому месту → сброс к
   оверлею; двойной клик → попап.
3. **«Всё дерево»:** галка вкл → полный граф (как раньше); поиск/фильтр категорий/
   «показать ресурсы»/«⟲ на верхний тир»/«забаненные»/«обратные рёбра» видны и
   работают; галка выкл → фокус-режим, элементы скрыты. Бейдж режима на канвасе.
4. **Попап-деталь:** двойной клик (канвас/справочник), ⓘ и «открыть деталь»
   открывают; Esc/крестик/подложка закрывают; после закрытия выбор и подграф
   сохраняются; попап перетаскивается за заголовок; содержимое = бывшая деталь
   (слоты с количеством и галкой allow_resource, кнопки, «Используется в:»);
   drag карточки из справочника в слот попапа работает; правая панель при открытом
   попапе активна.
5. **Тир:** поле «тир: [ ] (вычислен N)» — пусто = вычисленный; ввод 7 → бейджи/
   попап/справочник показывают 7, метка «⚠ отличается от вычисленного (N)»;
   очистка → снова вычисленный; ресурс — «тир 0» без поля; «заполнить
   комплектующие» работает по вычисленному тиру.
6. **Справочник:** единый список (товары + ресурсы), поиск фильтрует обоих;
   галки «используемые»/«неиспользуемые» (комбинируются), «забаненные»
   (приглушённые, «Вернуть» в попапе) работают; **пилюли тиров** (вместо «T0»):
   по умолчанию пусто = все тиры; отметка «3» → только товары тира 3, ресурсы
   скрыты; отметка «0» → ресурсы (и тир-0 товары); «0»+«3» → оба; счётчик «· N»;
   старых секций «Ресурсы (палитра)»/«Неиспользуемые»/«Забаненные» нет; scroll
   не сбрасывается.
7. **«+ товар»** (в справочнике и в addbar) — черновик создан, выбран, подграф
   вокруг него.
8. **Подгрузка списка:** «Стальной каркас | конструкционные материалы» → создан
   черновик, textarea очищена; «X | несуществующая» → тост «строка N: категория

11. **DoD разработки:** `go build ./...`, `go vet ./...`, `go test -race ./...`

## 9. Что не трогать (инварианты UI — 99a.1-ui §7 + дельта 99a.3 §11/§13)

- **Авто-обновление 3 с без сброса выбора/зума/пана/модалок/попапа.**
- **Не менять API-контракты 99a.1/99a.2** (кроме дельт 99a.3 §9).
- **Карточки на графе остаются обзором** (кнопок на canvas-карточках не добавлять;

## 12. Гейт-вопросы продукт-спеки 99a.3 §20 (решения UI с обоснованием)

Решения создателя НЕ меняются; ниже — предложения по умолчанию, принятые в этой
спеке, с обоснованием:

1. **Топбар-фильтры в фокус-режиме: скрыть?** — **Да, скрыть** (§3.4).
   Подграф полон по построению (окно 1 уровня) — фильтрация разорвала бы его;
   справочник имеет собственные поиск/фильтры; скрытие `display:none` не занимает
   место в шапке. При включении «всё дерево» элементы возвращаются.
2. **Авто-центрирование при выборе из справочника?** — **Да** (§3.3).
   Товар может быть далеко от текущего вида; без центрирования подграф мог бы
   оказаться вне экрана. Зум сохраняется (только pan пересчитывается). Клик по
   карточке на канвасе центрирования не требует (карточка уже видна).
3. **Секции «Ресурсы»/«Неиспользуемые» поглотить справочником?** — **Да** (§5.1).
   Один список + фильтры «используемые/неиспользуемые» + фильтр тиров покрывают
   обе секции; два списка одного и того же — дублирование и два места scroll.
4. **Отрицательный тир-оверрайд: 400?** — **Да** (§4.4). Шкала 0-базовая
   (0 = ресурсы, 99a.1 §6.1), отрицательный тир бессмыслен и сломал бы экспорт
   (`complexity < 0`). UI дополнительно ставит `min=0` на input, но серверная
   валидация — окончательная (тост из `api()`).
5. **«⟲ на верхний тир» в фокус-режиме: скрыть?** — **Да** (§3.4).
   Центрирование по верхушкам не имеет смысла в подграфе вокруг выбранного;
   в полном дереве работает как сейчас.
6. **Попап-деталь: открытие отдельным действием?** — **Да, зафиксировано** (§4.2).
   Модальный попап при каждом клике блокировал бы навигацию по подграфу (главная
   фича фокус-режима) и просмотр справочника; отдельное действие (двойной клик /
   ⓘ / «открыть деталь») даёт деталь в один лишний клик. Клик остаётся чистой
   навигацией.
7. **Забаненные в правой панели: галка-фильтр; в фокус-подграфе приглушены
   всегда?** — **Да** (§7.1). Галка-фильтр консистентна с остальными фильтрами
   справочника (единый список, «Вернуть» — в попапе). В фокус-подграфе забаненные
   родители/дети приглушены всегда: структура подграфа полная по построению —
   скрытие забаненного родителя оборвало бы окно 1 уровня и связь с выбранным.

**Дополнительные уточнения UI (в рамках скоупа, решения не меняют):**

- **«Обратные рёбра» скрыты в фокус-режиме** (§3.4): родители подграфа уже
  связаны с выбранным прямыми рёбрами; обратная подсветка избыточна. Только в
  режиме «всё дерево».
- **Попап не перекрывает правую панель** (§4.1): подложка затемняет только канвас —
  иначе drag&drop из справочника в слоты попапа был бы невозможен.
- **Попап: ширина 400px, высота по контенту (max 80% канваса), drag за заголовок**
  (§4.1) — решение @uidesigner по 99a.3 §10.3.
- **ⓘ на карточке справочника не меняет выбор** (§4.2): попап — отдельное окно;
  клик по карточке = выбор, ⓘ = деталь.
- **«Используется в:» в попапе — навигация внутри попапа** (§4.3): клик по
  родителю заменяет содержимое попапа и перестраивает подграф.
- **Счётчик «Справочник · N»** (§5.1) — видимое число карточек после фильтров.
- **Бейдж режима канваса** (§3.1) — индикатор «фокус: вокруг выбранного» /
  «всё дерево» в левом нижнем углу.

## 13. Структура шапки (группировка топбара)

**Дата:** 2026-09-19 (итерация 2, пожелание создателя: «сейчас в шапке всё в
каше — можно как-то структурировать через UX дизайнера?»).

### 13.1. Проблема

Верхняя область страницы — «каша»: 3 контейнера (`#topbar`, `#catbar`,
`#addbar`) с 17+ контролами вперемешку, без группировки по функции (строки
113–149 `index.html`): статус, фильтры графа, галки отображения, переключатели
режимов, фильтры справочника, экспорт/импорт, создание товара, управление
категориями — всё в одном потоке с одинаковыми label-подписями.

### 13.2. Решение: сегменты по функции + сворачиваемые блоки

Шапка делится на **3 строки**:

```
Строка 0 (заголовок):  [h1 Студия товаров] ········ [modelInfo] [genIndicator]
Строка 1 (инструменты): [Режим графа] [Действия]
Строка 2 (вторичное):  [Категории]                 ← кнопка, открывает попап (§14)
```

- **Статус** (`#modelInfo`, `#genIndicator`) — пассивная информация, уходит из
  инструментального ряда в строку заголовка (справа,
  `justify-content:space-between`).
- **Сегмент «Режим графа»** — `#fullTree`, `#search`, `#catFilter`,
  `#showResources`, `#showBanned`, `#reverseEdges`, `#btnTop`. В фокус-режиме
  `applyModeUI` скрывает всё, кроме `#fullTree` → сегмент **аккуратно
  схлопывается** до `[Режим графа: ☐ всё дерево]` (подпись остаётся — это
  осознанное состояние, а не «дыра»).
- **Сегмент «Действия»** — `#btnExport`, `#btnImport` (всегда видим).
- **Кнопка «Категории»** (`#btnCatOpen`) — компактная кнопка-сегмент в ряду
  `head-secondary` (стиль `.tool-seg`, но это кнопка): клик → **попап категорий**
  (§14). Бывший `<details> #segCat` (селект + поле + 3 кнопки) **упраздняется**
  полностью — управление категориями уезжает в попап (решение создателя
  2026-09-19: «Категории — сделай отдельным попапом»).
- **Контролы справочника** (поиск, галки-фильтры, пилюли тиров, «+ товар»,
  подгрузка) — **в правой панели** (`.sprav-head`, §5), НЕ в шапке: быстрый
  путь создания — «+ товар» в справочнике (единственный, addbar удалён по
  решению создателя 2026-09-19), поиск/фильтры работают у списка, к которому
  относятся.

### 13.3. Результирующая HTML-структура (псевдо)

```html
<header id="headbar">
  <div class="head-row head-title">
    <h1>Студия товаров</h1>
    <span class="head-status">
      <span id="modelInfo">Модель ИИ: —</span>
      <span id="genIndicator"></span>
    </span>
  </div>
  <div class="head-row head-tools">
    <div class="tool-seg" id="segGraph">
      <span class="seg-label">Режим графа</span>
      <label><input type="checkbox" id="fullTree"> всё дерево</label>
      <input id="search" type="text" placeholder="поиск по графу">
      <span class="seg-sub">категория:</span>
      <select id="catFilter">…</select>
      <label><input type="checkbox" id="showResources"> показать ресурсы</label>
      <label><input type="checkbox" id="showBanned"> забаненные</label>
      <label><input type="checkbox" id="reverseEdges"> обратные рёбра</label>
      <button id="btnTop">⟲ на верхний тир</button>
    </div>
    <div class="tool-seg" id="segActions">
      <span class="seg-label">Действия</span>
      <button class="warn" id="btnExport">Экспорт</button>
      <button class="warn" id="btnImport">Импорт</button>
    </div>
  </div>
  <div class="head-row head-secondary">
    <button class="tool-seg" id="btnCatOpen" title="Управление категориями">Категории</button>
  </div>

```

**Контролы справочника** (поиск, галки, пилюли тиров, «+ товар», подгрузка) — в
правой панели `.sprav-head` (§5), не в шапке (факт реализации 2026-09-19).
Бывший `<details> #segCat` заменён кнопкой `#btnCatOpen` → попап категорий (§14).

**Порядок внутри «Режима графа»** — логический: переключатель режима
(`#fullTree`) первым, затем фильтры (`#search`, `#catFilter`), затем опции
отображения (`#showResources`, `#showBanned`, `#reverseEdges`), затем действие
(`#btnTop`).

- `.headbar` — flex-колонка, `gap:6px`, `margin-bottom:8px` (заменяет `#topbar`).
- `.head-row` — flex, `gap:8px`, `align-items:center`, `flex-wrap:wrap`.
- `.tool-seg` — сегмент-группа: `display:inline-flex;align-items:center;gap:8px;
  flex-wrap:wrap;padding:4px 10px;border-radius:8px;background:#1d1d1d;
  border:1px solid #333`. Визуально — «карточка» группы с рамкой и фоном.
- `.seg-label` — подпись группы: `font-size:11px;color:#888;letter-spacing:.5px;
  text-transform:uppercase;white-space:nowrap`. Для `summary` — тот же вид +
  `cursor:pointer` + маркер «▸/▾» (нативный `list-style:none` снят).
- `.seg-sub` — мини-подпись перед одиночным контролом («категория:»), 11px #666.
- `.seg-body` — содержимое развёрнутого `<details>`: `display:flex;gap:8px;
  align-items:center;flex-wrap:wrap;margin-top:6px`.
- Единый стиль полей: селектор `#topbar select,#topbar input,#catbar input,
  #addbar input,#addbar select` (строки 8–9) → `.tool-seg input,.tool-seg select`

### 13.6. Что не менять

- **ID контролов шапки сохраняются** (`#search`, `#catFilter`, `#fullTree`,
  `#btnExport`, `#btnImport`, `#btnTop`, `#spravSearch`, `#fUsed`, `#fUnused`,
  `#fBanned`, `#spravNewName`, `#spravNewCat`, `#btnSpravAdd`) — JS работает
  без правок (`applyModeUI`, `spravAddGood` и т.д.).
- **Контролы категорий уезжают из шапки в попап (§14)**: `#catManage`,
  `#newCatName`, `#btnAddCat`, `#btnRenameCat`, `#btnDelCat` из `#segCat`
  упраздняются как элементы шапки; функции `addCategory`/`renameCategory`/
  `deleteCategory` и селект `#catManage` переезжают в попап (новые ID —
  см. §14.4). **`renderCatSelects` сохраняет заполнение `#catFilter` (фильтр
  графа) и `#spravNewCat` (категория нового товара)** — эти два селекта
  остаются, заполняются как сейчас.
- **`applyModeUI` не трогается**: она скрывает элементы по id/родителю, а не по
  контейнерам; сегменты сами схлопываются за счёт скрытия содержимого.
- Контейнеры `#topbar`/`#catbar`/`#addbar` упразднены (факт реализации);
  шапка = `#headbar` + сегменты.
- Подпись перед `#catFilter` — мини-подпись «категория:» внутри сегмента.
- `h1` остаётся первой строкой (внутри `.head-title`), не меняется.

1. **Решение создателя 2026-09-19:** «Категории — сделай отдельным попапом» —
   управление категориями не должно занимать место в шапке (это редкая
   настройка, а не рабочий инструмент).
2. **Высота шапки**: полная компоновка = 3 строки (заголовок + инструменты +
   управление категориями). С кнопкой + попапом — 2 компактные строки, шапка
   не растёт при открытии (попап — поверх канваса).
3. **Фокус**: в попапе категорий есть место для списка всех 13 категорий со
   счётчиками товаров и inline-редактированием (нельзя уместить в сегмент
   шапки 320px).
4. **Инвариант «правая панель = только справочник» соблюдён**: попап категорий
   не трогает правую панель.

## 14. Попап категорий (вместо `#segCat` в шапке)

**Дата:** 2026-09-19 (итерация 4; решения создателя: «Категории — сделай
отдельным попапом», «Кнопка "переименовать" — абсолютно неудобно, спроси у UX
как лучше сделать»).

### 14.1. Цель

Управление категориями (создание/переименование/удаление) уезжает из шапки
(бывший `<details> #segCat` — селект + поле + 3 кнопки) в **отдельный попап**.
В шапке остаётся только кнопка «Категории» (`#btnCatOpen`, §13). Попап строится
по образцу попапа-детали (§4.1): absolute поверх канваса, подложка, drag
заголовка, Esc/крестик/подложка закрывают.

### 14.2. Переименование: выбранный вариант

Варианты:
| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| (а) двойной клик → inline-редактирование | единый паттерн с попапом-деталью (клик по имени → input, Enter/Blur сохранить, Esc отмена); 0 лишних контролов | неочевиден (двойной клик надо «открыть»); одиночный клик по строке — что делает? | **основа** |
| (б) иконка-карандаш у каждой строки | видимый аффорданс, один клик | 13 иконок (визуальный шум); карандаш мелкий в 320px | **вспомогательно** |
| (в) select + поле (как сейчас) | уже реализовано | создатель: «абсолютно неудобно» (выбор + поле + кнопка в 3 шага) | нет |

**Выбор: (а) двойной клик по строке → inline-редактирование** — как основной
способ, единый паттерн с попапом-деталью (§4.3 «имя — клик → inline-rename»):
- двойной клик по имени категории → строка превращается в `<input>` с текущим
  именем (значение выделено), Enter/Blur — `PUT /api/categories/{id}`,
  Esc — отмена без сохранения; ошибка (409 дубликат / 400 пустое) — тост,
  значение возвращается к старому;
- **одиночный клик по строке** — ничего не делает (нет действия «выбрать
  категорию» в попапе: категории не фильтруют список здесь) — снимает
  конфликт «клик vs редактирование»;
- **(б) иконка-карандаш «✏» у каждой строки** — видимый аффорданс, клик по
  ней = то же inline-редактирование (для тех, кто не знает про двойной клик).

Обоснование: единый паттерн с деталью товара (пользователь уже знает его по
переименованию товара), ноль новых контролов в списке (только тонкая иконка),
нет промежуточного селекта — редактирование происходит прямо на месте имени.

### 14.3. Удаление: счётчик товаров + блокировка непустых

**Факт (проверено по `handlers/state.go` §handleCategoryByID, строки 183–188):**
`DELETE /api/categories/{id}` возвращает **409 «категория не пуста — сначала
перекатегоризуйте товары»**, если в категории есть товары. Товары НЕ остаются
с осиротевшим `category` — сервер не даёт удалить. Удаляются только пустые.

Дизайн (UI не ждёт ошибки сервера, а предупреждает заранее):
- у каждой строки — **счётчик товаров** категории (посчитан на клиенте из
  `state.goods` по `g.category === cat.id`, включая ресурсы? — **нет: только
  товары `kind=good`**, ресурсы имеют категорию-код и не считаются);
- **иконка-корзина «🗑»** у строки:
  - категория пуста (счётчик 0) → клик → **модалка подтверждения** `openModal`
    «Удалить категорию «X»?» [Удалить] [Отмена] → `DELETE`;
  - категория непуста (счётчик > 0) → иконка `disabled` (приглушена, тултип
    «сначала перекатегоризуйте товары (N)») — **блокировка до действия**,
    серверный 409 как страховка (если всё же придёт — тост текстом сервера).

### 14.4. Создание

В попапе, над списком: строка-форма `[input «имя категории»] [+ категория]`:
- `POST /api/categories` {name}; пустое имя — не отправляем (кнопка disabled);
- дубликат — тост 409 «категория с таким именем уже есть»;
- Enter в input = клик по «+ категория»;
- после успеха — input очищается, новая категория появляется в списке (и в
  `#catFilter`/`#spravNewCat` через `renderCatSelects`).

### 14.5. Компоновка попапа

```
┌─────────────────────────────────────┐
│ Категории                      [×]  │  ← popup-head, drag (как #detailPopup)
│ [имя категории...........] [+ категория] │  ← создание (§14.4)
│ ─ список (scroll) ─                 │
│   «Конструкционные материалы»  · 12 │  ← ✏ двойной клик/✏ = inline-rename
│        ✏ [🗑]                       │  ← счётчик товаров, корзина (§14.3)
│   «Футур-материалы»  · 3  ✏ [🗑]     │
│   «Пустая категория»  · 0  ✏ [🗑]    │  ← пустая — корзина активна
│   …                                 │
└─────────────────────────────────────┘
```

Строка категории: `[✏] [имя (dblclick = rename)] · [N] [🗑]`. Пустая категория
в списке не прячется (видна всегда; удаление — по корзине).

### 14.6. HTML-структура (псевдо)

```html
<div id="main">
  …
  <div id="catOverlay" style="display:none"></div>   ← подложка (как #detailOverlay)
  <div id="catPopup" style="display:none">           ← попап категорий
    <div class="popup-head" id="catPopupHead"><span class="ptitle">Категории</span>
      <button id="catPopupClose" title="закрыть (Esc)">×</button></div>
    <div class="popup-body">
      <div class="cat-add">
        <input id="catNewName" type="text" placeholder="имя категории">
        <button class="gen" id="catAddBtn">+ категория</button>
      </div>
      <div id="catList"></div>                       ← строки категорий (динамика)
    </div>
  </div>
  <div id="right"> … справочник … </div>
</div>
```

**Параметры** (как §4.1): absolute в `#main`, ширина **360px** (13 строк +
счётчики + иконки), высота по контенту max 80% `#main` со scroll списка,
подложка затемняет только канвас (правая панель активна), drag за заголовок,
Esc/крестик/подложка закрывают, авто-обновление 3 с попап не сбрасывает
(перерисовывает список из свежего state).

**CSS-принцип:** переиспользовать классы попапа-детали (`.popup-head`,
`.popup-body`), строки — `.cat-row` (flex, gap 8px, padding 4px 6px, hover
подсветка), иконки — кнопки 24px hit-таргет (как `.card .info`), счётчик —
`#888` 11px.

### 14.7. Поведение (дельта к §6)

| Действие | Результат |
|---|---|
| Клик «Категории» в шапке (`#btnCatOpen`) | попап открывается, список перерисован из свежего state |
| Двойной клик / ✏ по строке | inline-редактирование (input на месте имени, Enter/Blur — PUT, Esc — отмена; 409/400 — тост, возврат имени) |
| 🗑 у пустой категории | модалка подтверждения → DELETE → строка исчезает |
| 🗑 у непустой категории | disabled (тултип «сначала перекатегоризуйте товары (N)») |
| «+ категория» / Enter в поле | POST → строка в списке, input очищен; 409 — тост |
| Esc / крестик / подложка | попап закрыт; выбор на канвасе и справочник не тронуты |
| Авто-обновление 3 с | попап открыт, список/счётчики перерисованы из свежего state |

**JS-перенос** (для @developer, не UI): `renderCatSelects` заполняет только
`#catFilter` и `#spravNewCat` (селект `#catManage` упраздняется); функции
`addCategory`/`renameCategory`/`deleteCategory` переписываются на новые ID
попапа; счётчик товаров и блокировка корзины — на клиенте из `state.goods`.
