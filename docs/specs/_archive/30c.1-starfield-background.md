## 0. Резюме

На близких зумах (scale ≥ 1.0) за реальными звёздами галактики рисуется **фон «звёздное небо»** — два слоя мелких полупрозрачных точек с параллакс-смещением. Ближний слой (PARALLAX = 0.06) — заметные точки; дальний (PARALLAX = 0.006, в 10 раз медленнее, alpha 0.05–0.12) — тусклая «подложка». Это создаёт ощущение глубины при перелётах. Фон генерируется **один раз** при загрузке/ресайзе в два offscreen-тайла и копируется на canvas через `createPattern` + `fillRect`. Стоимость — две операции fill за кадр (по одной на слой).

---

## 1. Решения создателя (зафиксированы)

1. Фон **только** на близких зумах (scale ≥ 1.0). На дальних — не нужен.
2. Параллакс — пробуем (фон едет медленнее реальных звёзд).
3. Плотность фоновых звёзд — **средняя**.
4. Не конкурировать с реальными звёздами: **мельче, тусклее, без свечения/подписей**.
5. **Очень дёшево** для браузера.

---

## 2. Параметры (числа и пороги)

### 2.1 Порог включения и альфа-рамп

```
STARFIELD_FADE_IN  = 1.0    // начало плавного появления
STARFIELD_FULL     = 1.5    // полная непрозрачность
```

Формула альфа-фона:

```
alpha = clamp((scale - STARFIELD_FADE_IN) / (STARFIELD_FULL - STARFIELD_FADE_IN), 0, 1)
```

- scale < 1.0 → alpha = 0, фон не рисуется
- scale 1.0..1.5 → плавное появление от 0 до 1
- scale > 1.5 → alpha = 1

Почему 1.0–1.5: зум полёта всегда ≥ 1.0 (`navigation.js:27`), имена появляются с 0.5, сетка с 2.0. Диапазон 1.0–1.5 — **между** именами звёзд и сеткой: фон плавно входит, когда игрок начинает «приближаться», и полностью виден до того, как появится сетка.

### 2.2 Тайл (offscreen canvas)

```
TILE_SIZE   = 256          // px — стандартный тайл для createPattern
TILE_COUNT  = 60           // точек на тайл → плотность «средняя»
```

Расчёт плотности: 60 точек / (256×256 px) ≈ 0.00092 точки/px² → одна точка в среднем на 33×33 px area. Для экрана 1920×1080 ≈ 1920×1080 / (256×256) ≈ 32 тайла на экран → ~1920 фоновых точек. Это **средняя плотность**: достаточно для ощущения «неба», но не превращает фон в шум.

### 2.3 Параметры точек

| Параметр | Значение | Обоснование |
|---|---|---|
| `size` | 1–2 px (случайно 1.0..2.0) | Мельче реальных звёзд (minRadius = 1.5 при scale ≥ 1.0, но реальные звёзды рисуются с кластерным размером ~5–21 px) |
| `alpha` | 0.15–0.35 (случайно) | Тусклее: реальные звёзды — alpha 0.8–1.0. Фон не конкурирует. |
| `color` | `#c8d6e5` (холодный бело-голубой) | Фиксированный для всех фоновых точек. Не пересекается с палитрой `starColors` (там '#9bb0ff'..'#4d3b2b'), визуально «дальше» и «холоднее». |
| `glow` | нет | Инвариант: никаких `shadowBlur`, `radialGradient` — только `arc` + `fill` |

### 2.4 Параллакс (двухслойный, с накоплением)

**Два слоя:**

| Слой | `PARALLAX` | Альфа точек | Роль |
|---|---|---|---|
| Ближний | 0.06 | 0.15–0.35 | Заметные фоновые точки |
| Дальний | 0.006 (в 10× медленнее) | 0.05–0.12 | Тусклая «подложка», даёт ощущение глубины |

Дальний слой рисуется **первым** (под ближним) — тусклые точки не перекрывают более яркие.

**Механика накопления (важно):**

Фон **не** привязан напрямую к `offsetX`/`offsetY` — вместо этого используются накопленные `bgX`/`bgY`, которые растут **только при панорамировании** (когда `scale` не менялся между кадрами):

```js
if (prevScale !== scale) {
    // Зум — фон стоит (дальние звёзды не едут от масштаба)
    prevScale = scale;
    prevOffsetX = offsetX;
    prevOffsetY = offsetY;
} else {
    // Панорама — фон копит смещение
    bgX += (offsetX - prevOffsetX) * PARALLAX;
    bgY += (offsetY - prevOffsetY) * PARALLAX;
    prevOffsetX = offsetX;
    prevOffsetY = offsetY;
}
```

**Почему так, а не `offsetX * PARALLAX`:** `offsetX` пересчитывается при зуме (масштаб меняет экранные координаты центра), и прямое умножение даёт «прыжок» фона при зуме — неестественно. Накопление смещения только при панораме избавляет от этого артефакта.

Почему 0.06 (ближний):
- Меньше 0.03 → фон почти неподвижен, параллакс не ощущается
- Больше 0.1 → фон едет слишком быстро, конкурирует с реальными звёздами
- 0.06 — заметное, но мягкое движение

### 2.5 Источник мелкого шума

Для естественности каждый кадр к альфе слоя добавляется микро-дрожь (мерцание):

```
shimmer = 0.85 + 0.15 * sin(timeMs * 0.001)
```

- Частота ~1 Hz, амплитуда ±15% — еле заметное мерцание
- Один `sin` на кадр, применяется ко **всему слою** (общий множитель `rampAlpha * shimmer` для обоих слоёв), а не к каждой точке отдельно: per-point дрожь потребовала бы `sin` на каждую точку и не видна глазом на точках 1–2 px
- **Стоимость:** один `sin` + одно умножение на кадр. При любом числе точек — пренебрежимо

Это **не** анимация точек (точки не двигаются), только мерцание яркости. Для анимации движения потребовался бы `timeOffset` в параллаксе — дороже и конфликтует с «очень дёшево».

## 3. Реализация

### 3.1 Новый файл: `web/static/js/map/starfield.js`

Отдельный модуль (ES-модуль, стиль соседних файлов). ~120 строк.

```js
// web/static/js/map/starfield.js
// Фон «звёздное небо» на близких зумах (спека 30c.1).
// Генерирует offscreen-тайлы один раз (init + resize); рисует два fillRect за кадр.
// Не зависит от config.js — все параметры локальны.

const TILE_SIZE   = 256;
const TILE_COUNT  = 60;
const FADE_IN     = 1.0;
const FULL_ALPHA  = 1.5;
const PARALLAX    = 0.06;
const PARALLAX_DIM = PARALLAX * 0.1; // дальний слой — в 10 раз медленнее
const BASE_COLOR  = [200, 214, 229]; // #c8d6e5

let tileCanvas = null;     // offscreen canvas с тайлом (ближний слой)
let tileDimCanvas = null;  // offscreen canvas с тайлом (дальний, тусклый)
let tilePattern = null;    // CanvasPattern ближнего слоя (пересоздаётся при ресайзе)
let tileDimPattern = null; // CanvasPattern дальнего слоя (пересоздаётся при ресайзе)
let bgX = 0, bgY = 0;      // накопленное экранное смещение фона
let prevOffsetX = 0, prevOffsetY = 0, prevScale = -1;

// initStarfield() — генерирует два тайла. Вызывается при загрузке и при resize.
export function initStarfield() { ... }

// drawStarfield(ctx, canvasWidth, canvasHeight, scale, offsetX, offsetY, timeMs)
// Рисует фон. Вызывается из draw() ПОСЛЕ clearRect, ДО drawGrid.
export function drawStarfield(ctx, w, h, scale, offsetX, offsetY, timeMs) { ... }
```

### 3.2 Генерация тайла (`initStarfield`)

```
function initStarfield() {
    tileCanvas    = makeTile(0.15, 0.2);   // ближний слой: alpha 0.15..0.35
    tileDimCanvas = makeTile(0.05, 0.07);  // дальний слой: совсем тусклый 0.05..0.12

    // TilePattern создаётся ПОСЛЕ resize canvas (чтобы размер совпадал)
    tilePattern = null;    // сброс — будет создан при первом drawStarfield
    tileDimPattern = null;
}

// makeTile(alphaMin, alphaRange) — один offscreen-тайл с точками.
// Детерминировано: seeded random от фиксированного seed.
function makeTile(alphaMin, alphaRange) {
    const c = document.createElement('canvas');
    c.width  = TILE_SIZE;
    c.height = TILE_SIZE;
    const tctx = c.getContext('2d');

    // Чёрный фон тайла — совпадает с CSS canvas (#0a0f1a)
    tctx.fillStyle = '#0a0f1a';
    tctx.fillRect(0, 0, TILE_SIZE, TILE_SIZE);

    const rng = mulberry32(42); // простой seeded PRNG
    for (let i = 0; i < TILE_COUNT; i++) {
        const x = rng() * TILE_SIZE;
        const y = rng() * TILE_SIZE;
        const r = 1.0 + rng();                    // 1.0..2.0 px
        const a = alphaMin + rng() * alphaRange;

        tctx.globalAlpha = a;
        tctx.fillStyle = `rgb(${BASE_COLOR[0]},${BASE_COLOR[1]},${BASE_COLOR[2]})`;
        tctx.beginPath();
        tctx.arc(x, y, r, 0, Math.PI * 2);
        tctx.fill();
    }
    tctx.globalAlpha = 1;
    return c;
}
```

**PRNG `mulberry32`** — 8 строк, детерминирован, не нужен import. Seed фиксирован (42) → каждый тайл одинаков при каждом вызове `initStarfield`.

### 3.3 Отрисовка (`drawStarfield`)

```
export function drawStarfield(ctx, w, h, scale, offsetX, offsetY, timeMs) {
    // 1. Альфа-рамп
    if (scale < FADE_IN) return;
    const rampAlpha = Math.min(1, (scale - FADE_IN) / (FULL_ALPHA - FADE_IN));

    // 2. Паттерны (ленивое создание)
    if (!tilePattern) {
        tilePattern = ctx.createPattern(tileCanvas, 'repeat');
        tileDimPattern = ctx.createPattern(tileDimCanvas, 'repeat');
    }

    // 3. Накопление смещения ТОЛЬКО при панорамировании (scale не менялся).
    //    Зум меняет scale — фон в этом кадре не двигаем (дальние звёзды стоят).
    if (prevScale !== scale) {
        prevScale = scale;
        prevOffsetX = offsetX;
        prevOffsetY = offsetY;
    } else {
        bgX += (offsetX - prevOffsetX) * PARALLAX;
        bgY += (offsetY - prevOffsetY) * PARALLAX;
        prevOffsetX = offsetX;
        prevOffsetY = offsetY;
    }

    // 4. Микро-мерцание (среднее по всем точкам — один sin на кадр)
    const shimmer = 0.85 + 0.15 * Math.sin(timeMs * 0.001);

    // 5. Два слоя параллакса: дальний (тусклый, в 10 раз медленнее) под ближним
    drawLayer(ctx, w, h, tileDimPattern, bgX * 0.1, bgY * 0.1, rampAlpha * shimmer);
    drawLayer(ctx, w, h, tilePattern,    bgX,       bgY,       rampAlpha * shimmer);
}

// drawLayer — один fillRect с паттерном, сдвинутым на (bgX, bgY).
function drawLayer(ctx, w, h, pattern, bgX, bgY, alpha) {
    ctx.save();
    ctx.globalAlpha = alpha;
    ctx.translate(bgX % TILE_SIZE, bgY % TILE_SIZE);
    ctx.fillStyle = pattern;
    ctx.fillRect(
        -(bgX % TILE_SIZE) - TILE_SIZE,
        -(bgY % TILE_SIZE) - TILE_SIZE,
        w + TILE_SIZE * 2,
        h + TILE_SIZE * 2
    );
    ctx.restore();
}
```

**Стоимость за кадр:**
- 1 `Math.sin` + 3 умножения (shimmer)
- 2 × (`ctx.save` + `ctx.restore` + `ctx.translate`)
- 2 `ctx.fillRect` с repeat-паттернами (браузер оптимизирует: тайлы уже в памяти GPU)

Это **дешевле**, чем текущий `drawGrid` (который делает N.beginPath +.moveTo +.lineTo +.stroke). Оценка: < 0.1 ms на mid-range device.

### 3.4 Встраивание в `draw()` (`map_render.js`)

Изменение в `map_render.js` — **3 строки** (import + вызов):

```js
// Строка 2: добавить import
import { drawStarfield } from './starfield.js';

// В draw(), ПОСЛЕ clearRect (строка 97), ДО drawGrid (строка 99):
drawStarfield(ctx, canvasWidth, canvasHeight, scale, offsetX, offsetY, Date.now());
```

**Порядок слоёв (полный):**
```
clearRect          → обнажает CSS #0a0f1a
drawStarfield      → фон «звёздное небо» (2 слоя параллакса: дальний под ближним)
drawGrid           → сетка (только scale > 2)
регионы            → регионы (малый зум)
кластеры/звёзды    → реальные звёзды галактики
имена              → подписи
NPC                → агенты
полёт              → анимация корабля
FPS                → плашка
```

**Почему ПОСЛЕ clearRect, а ДО сетки:**
- Фон рисуется поверх `#0a0f1a` (CSS) — совпадает по цвету, поэтому на дальних зумах (alpha = 0) незаметен
- Сетка (scale > 2) рисуется поверх фона — линии сетки `#1e293b` полупрозрачные, фон «просвечивает» — это нормально
- Реальные звёзды рисуются поверх фона — конкуренции нет: фон мельче (1–2 px vs 5–21 px), тусклее (alpha 0.15–0.35 vs 0.8–1.0)

## 4. Инварианты

| # | Инвариант | Цена нарушения |
|---|---|---|
| И1 | Фон **только** при scale ≥ 1.0 | На дальних зумах ~100k+ фоновых точек → визуальный шум, конкуренция с реальными звёздами |
| И2 | Фон **мельче и тусклее** реальных звёзд | Конкуренция за внимание: игрок не отличит фон от реальных звёзд |
| И3 | Не более 2 `fillRect` за кадр (по одному на слой) | Больше операций → FPS падает на mid-range devices |
| И4 | Тайлы генерируются **один раз** (init + resize) | Per-frame генерация → сотни ms на кадр |
| И5 | Параллакс < 1.0 (0.06 / 0.006) | Если PARALLAX ≥ 1.0, фон едет как камера → нет ощущения глубины |
| И6 | Фон двигается **только при панорамировании**; при изменении scale стоит | Привязка к `offsetX * PARALLAX` даёт «прыжок» фона при зуме (offset пересчитывается от масштаба) |

## 5. Режим отказа

| Ситуация | Поведение |
|---|---|
| `createPattern` не поддерживается (старый браузер) | `initStarfield` ловит ошибку → `tilePattern = null` → `drawStarfield` пропускает отрисовку. Фон = CSS `#0a0f1a` (status quo) |
| Ресайз canvas | `initStarfield()` вызывается из `resizeCanvas()` → пересоздаёт тайл и паттерн |
| FPS падает ниже 30 | Отключение фона через консоль: `window.__starfieldDisabled = true` — пока нет UI-переключателя (учесть на будущее) |

---

## 6. Чего НЕ делать

1. **Не анимировать движение точек** — только мерцание. Анимация движения = per-frame смещение каждой точки = дорого.
2. **Не добавлять `shadowBlur` / `glow`** — самая дорогая операция Canvas 2D.
3. **Не перекрывать фон сеткой** — сетка рисуется поверх, это нормально (линии полупрозрачные).
4. **Не менять CSS `background`** — фон рисуется в canvas, а не через CSS.
5. **Не добавлять UI-переключатель** — пока нет решения создателя; консольный флаг для отладки.
6. **Не дублировать** — два тайла, два паттерна, два fillRect (ровно по одному на слой). Никаких дополнительных слоёв.

---

## 7. Что проверять

1. **Визуально:** на zoom 1.0 → фон плавно появляется, на 1.5 → полная видимость. На zoom 0.5 → фон не виден.
2. **Параллакс:** при полёте (followShip) фон едет медленнее звёзд; дальний слой едет в 10 раз медленнее ближнего. Проверка: звезда в центре экрана «убегает» быстрее фоновых точек на том же направлении; две группы фоновых точек движутся с разной скоростью.
3. **Зум:** при изменении масштаба (колесо мыши) фон стоит на месте, не «прыгает» — смещение копится только при панорамировании.
4. **Конкуренция:** фоновые точки **не сливаются** с реальными звёздами. Реальные звёзды крупнее и ярче.
5. **FPS:** открыть FPS-плашку (admin/skycomposer), сравнить с/без фона. Дельта < 1 ms.
6. **Ресайз окна:** после resize фон корректно заполняет canvas, нет артефактов.

## 10. Открытые вопросы

1. **Мерцание (shimmer):** unanimous — или отключить, если создатель сочтёт лишним? Мерцание почти незаметно (±15% альфы), но требует `sin` на кадр.
2. **UI-переключатель:** нужен ли кнопкой, или достаточно консольного флага для отладки?
3. **Цвет фона:** `#c8d6e5` (холодный бело-голубой) — ок, или создатель хочет другой оттенок?
