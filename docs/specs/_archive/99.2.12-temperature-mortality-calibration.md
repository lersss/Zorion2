## Проблема

Четыре абсурда текущей модели (численно проверено 2026-09-14, копия формул
прогнана standalone-симулятором — результаты совпадают с таблицей ниже):

1. **500 K (227 °C)** — физически смерть за минуты, по модели t50% ≈ 5.8 дня.
2. **50 K (−223 °C)** — то же самое (симметрия жары/холода при равном отклонении).
3. **Насыщение на 650 K**: 650 K и 5000 K убивают одинаково (через сутки
   остаётся 79%). Нарушен инвариант 18a «секунды-минуты смерти = жёсткий ноль
   (население там быть не может)».
4. **Даже на максимуме** severity=1 t50% = 69 ч (~3 дня).

Корень: `MaxRatePerHour = 0.01` (слабый масштаб) × линейная кривая
`TwoSidedSeverity` с `SaturateAt = 300` (пологая, с капом на 1).

### H3. Асимметрия жары и холода: `SaturateCold=350 / SaturateHot=200`, жёсткий ноль холода не задан

Сравнение при одинаковом отклонении от края комфорта (равное отклонение 50 K:

| холод 150 K (dev 50) | t50% = 110.9 ч | t50% = 339.6 ч (14.2 дн) |
| холод 100 K (dev 100) | t50% = 27.7 ч | t50% = 84.9 ч (3.5 дн) |

Обоснование: (а) 18a прямо разрешает («перегрев и переохлаждение не обязаны
иметь одинаковую тяжесть»); (б) география игры: холодный архетип генератора
(`config/planet_archetypes.json`: 50–200 K) задуман как «тяжёлый, но обитаемый

12.3 ч на нижней границе холодного архетипа (50 K), что стирает разницу между
«ледяной спутник» и «раскалённая пустыня». **Принят.**

## Решение

**Действующая модель — дискретная рекурсия по R(T) (финальная модель,
решение создателя 2026-09-14).** `w`-сброс, хвосты λs и полюса жары **убраны**.

```
pₙ₊₁ = pₙ · (1 − R_total(T))                 — рекурсия за 1 секунду
R_total(T) = R_ест + R_темп(T) + (будущие компоненты; положительные = рост, 1−R > 1)
p(Δt) = p_чек · (1 − R_total(T))^Δt_сек     — ленивый пересчёт: дискретная экспонента, инвариантна к числу пересчётов
порог: p < 1 → поселение мёртвое
рампа: T < 15 °C → R_total = 0; 15–30 °C → R_total = R_ест·(T−15)/15 (только естественная); 30 °C+ → R_total = R_ест + R_темп(T)
момент смерти: t_смерти = ln(p0) / |ln(1−R_total)| сек от создания; дата = created_at + t_смерти
```

**Модульность (решение создателя 2026-09-14):** изменение населения = сумма
независимых компонент. `R_ест` — отдельная константа-компонента, **не входит**
в температурную формулу; `R_темп(T)` — чисто температурная (0 при T ≤ 30 °C);
будущие компоненты складываются (положительные = прирост/рост населения,
тогда `1−R > 1` и население растёт — дискретная экспонента это допускает).
Терминология 2026-09-14: «смертность/убыль» → «изменение населения» (дельта ±);
`r_per_sec` — дельта за секунду (может быть < 0 = рост); `decay_lambda` →
`lambda_per_hour`.

**Два типа компонент:** (1) **доли** — складываются в `R_total` (R_ест,
R_темп, прочие λ, будущие; положительная = рост); (2) **возрастные
ограничения** — применяются как проверка возраста, не слагаемое (сейчас одно:
максимальная продолжительность жизни 120 лет).

**Компоненты (приняты 2026-09-14):**

```
R_ест = 1/СПЖ = 1/50 лет ≈ 6.34·10⁻¹⁰ /сек (2%/год, t50 ≈ 34.7 года)  — естественная компонента (СПЖ 50 лет), отдельная константа
потолок: age = now − created_at ≥ 120 лет → p = 0   — возрастное ограничение (максимальная продолжительность жизни)
R_натур_темп(T) = c·(T_°C−30)²,  c = 3.71·10⁻¹²   — температурная «естественная зона» (30–~90 °C)
R_тепл_темп(T) = 1 − exp(−a·((T_°C−30)/100)^n),  a = 2.92·10⁻⁴, n = 2.581   — тепловая зона (~90–4000 °C)
σ(T) = 1/(1 + exp(−kσ·(T_°C−T_сш))),  kσ = 1.0, T_сш = 90 °C   — сшивка зон
R_темп(T) = R_натур_темп(T)·(1−σ(T)) + R_тепл_темп(T)·σ(T),  T_°C ≥ 30;  R_темп = 0 при T ≤ 30 °C
R_total(T) = R_ест + R_темп(T),  T_°C ≥ 30
```

> **Контрольная точка «+30 → ~1000 лет» пересмотрена (2026-09-14):** при
> +30 °C (только естественная компонента) полное вымирание = **СПЖ 50 лет,
> полное ≤ 120 лет (возрастной потолок)** — для ЛЮБОГО p0, без артефакта
> ln(p0). Температурные контрольные точки R_темп НЕ менялись (модульность).

`R_темп(30) = 0` (квадратичная от T−30), `R_темп(70) = 5.94·10⁻⁹` (целевая
R_total(70) = 6.6·10⁻⁹ минус R_ест); сшивка — сигмоида с центром 90 °C
(«порог кипения»), непрерывна и гладкая; R_темп → 1 при T → ∞. Контрольные
точки — **критерий тестера** (не узлы). Подробности, таблица близости и
тесты — §Концепция 2.0.

**История калибровки ниже (H1–H5, V2, полюсная B, концепция 2.0: w/λs/формулы
V1) — заменена рекурсивной R-моделью для жары; полюсная B остаётся
действующей только для холода (временно, до перевода холода на R-модель):**

```
severity = (dev/Sat_стороны)² / (1 − (dev/HardZero_стороны)²)   — полюс при dev = HardZero (вариант B, холод)
λ = severity × MaxRatePerHour          — MaxRatePerHour = 0.1 (общий на все факторы)
dev ≥ HardZero_стороны → λ = +Inf      — полюс/точка невозможности; guard: при dev ≥ H severity НЕ считается
p(t) = p0·exp(−λ·Δt)                   — формула не меняется
```

> **Особенность формулы B (обязательно к имплементации):** при `dev ≥ HardZero`
> знаменатель `(1 − (dev/H)²)` неположителен (при dev = H — ноль, при dev > H —
> отрицателен) → severity была бы +Inf или отрицательной (λ < 0 → население
> растёт). Поэтому guard обязателен: `dev ≥ HardZero → λ = +Inf` проверяется
> ДО вычисления severity (см. §Изменения в коде, `TwoSidedSeverity`).

**Исключение влияния укрытий (анти-двойной учёт, 2026-09-14).** Кривая
смертности калибрована по **«голой среде»** — референс «племя без технологий»

строятся) — её влияние исключено из калибровки. При будущем введении укрытия —
**отдельный слой/множитель** над этой формулой, без повторного влияния на неё:

## Как это видно игроку и админу (слой ощущений)

Человекочитаемая карта «температура планеты → что увидит игрок / что
произойдёт с поселением» по числам новой модели (°C = K − 273.15; t50% — время
до половины населения, проверил по формуле: `sev = (dev/Sat)²/(1−(dev/H)²)`,
`λ = sev·0.1`, `t50% = ln2/λ`; жара `Sat = 60`, холод `Sat = 350`, полюс
`H = 100` у обоих):

| Температура планеты | Что видит игрок / происходит с поселением |
|---|---|
| 288 K (15 °C) | Здорово, стабильно: λ = 0, население не меняется |
| 373 K (100 °C) | Умирающая зона: быстрое убывание, t50% ≈ 1.9 сут («дни» — референс @writer «+100 °C → большинство гибнет за дни») |
| 400 K (127 °C) | Умирающая зона: критичное убывание, t50% ≈ 7.5 ч |
| 425 K (152 °C) | Умирающая зона: часы, t50% ≈ 1.9 ч |
| 449 K (176 °C) | Умирающая зона: минуты, t50% ≈ 3 мин |
| **≥ 450 K (≥ 177 °C)** | **«Поселение невозможно»: население 0 (полюс жары)** |
| 150 K (−123 °C) | Умирающая зона: медленное убывание, t50% ≈ 10.6 сут |
| 123 K (−150 °C) | Умирающая зона: убывание, t50% ≈ 2.4 сут |
| 101 K (−172 °C) | Умирающая зона: часы, t50% ≈ 1.7 ч (плавная сходимость B — было 3.6 сут) |
| **≤ 100 K (≤ −173 °C), в т.ч. 73 K (−200 °C)** | **«Поселение невозможно»: население 0 (полюс холода)** |

Что именно покажет интерфейс после внедрения (реализация — этап разработки):

- **Админский предпросмотр `/admin/mortality-preview`:** для T ≥ 450 K и
  T ≤ 100 K — `uninhabitable = true`, все точки проекции 0,
  `lambda_per_hour` клампится (`MaxSerializedLambda = 100`, t50% ≈ 25 с) —
  админ видит «поселение невозможно», а не огромные числа.
- **Модалка системы (карточка планеты):** население 0 для планеты за жёстким
  нулём (мгновенная гибель); в умирающей зоне — убывание по формуле
  `p0·exp(−λ·Δt)` с возрастом данных (клиент экстраполирует косметически,
  `extrapolate.js` уже защищён `isFinite(lambda_per_hour)`; ранее
  `decay_lambda` — переименовано 2026-09-14).
- **Подпись «поселение невозможно»** в карточке планеты — опционально,
  не в этом блоке.

## Риски

- **`MaxRatePerHour` глобальный**: ×10 по всем трём факторам. Гравитация и
  радиоактивность сохраняют форму и константы, но их λ в 10 раз выросла
  (например, 3 g: t50% ≈ 15 ч вместо 6.4 дня). Константы grav/rad — черновые
  (открытый вопрос 18a №2), их калибровка — отдельный блок; здесь осознанно не
  трогаем, чтобы не калибровать два фактора в одной фиче.
- **Жёсткий ноль на 450 K**: у существующих галактик поселения на горячих
  планетах (450–900 K) обнулятся при первом же пересчёте после деплоя. Это
  шире, чем при 700 K: под ноль попадает часть «жаркого» архетипа генератора
  (400–600 K, `config/planet_archetypes.json`) — «жаркий, но обитаемый» мир
  становится невозможен. Ожидаемое следствие калибровки по эталону «300 °C →
  минуты», не баг. Оставшаяся «умирающая» зона — 350–449 K (t50% от ~1.9 сут
  у 373 K до 3 мин у нуля; плавная сходимость B).
- **Жёсткий холодный ноль на 100 K**: холодный архетип генератора (50–200 K,
  `config/planet_archetypes.json`) перестаёт быть «тяжёлым, но обитаемым при
  снабжении» в диапазоне 50–100 K — планеты ≤ 100 K обнуляются при первом
  пересчёте (ожидаемое следствие эталона «−200 °C → минуты», не баг).
  Оставшаяся «умирающая» зона холода — 100–200 K (t50% от 1.7 ч у 101 K до
  10.6 сут у 150 K): классическая жёсткая потребность «отопление» (GLOSSARY)
  живёт, но в узком окне 100 K шириной.
- **Полюсная форма B требует guard** `dev ≥ HardZero → +Inf` ДО вычисления
  severity: при dev = H знаменатель `1 − (dev/H)²` = 0, при dev > H
  отрицателен (отрицательная severity → λ < 0 → население растёт). Guard в
  `TwoSidedSeverity` — обязателен, не опционален (см. §Изменения в коде).
- **Изломы культуры данных** не затрагиваются: миграций БД нет, колонка
  `population_exact` и механика чек-поинтов не меняются.
- **Холод «мягче» жары на промежуточных температурах** — осознанное следствие
  асимметрии H3 (`SaturateCold = 350` сохранён): 150 K (−123 °C) убивает за
  t50% 10.6 сут, хотя физически человек без снабжения не живёт и суток. Это
  решённый компромисс (эталон холода 2026-09-14 задаёт жёсткий ноль и
  симметрию, но не перекалибровку кривой; зона 100–200 K — «умирающая», а не
  «здоровая»). Если создатель захочет крутой холод — это новая калибровка
  `SaturateCold`, отдельное решение.

## Концепция 2.0 — дискретная рекурсия по R(T) (финальная модель, 2026-09-14)

**Статус: готова к проверке создателем** (рекурсивная R-модель задана
создателем 2026-09-14 как финальная, ждёт проверки). `w`-сброс, хвосты λs
и полюса жары **убраны** — их роль выполняет одна кривая R(T).

### Проблема предыдущих моделей (история)

Единая экспонента `sev=(dev/Sat)²/(1−(dev/H)²)` (полюс B) и двухфазная
модель (мгновенная доля w + хвост λs, формулы V1) не отражали реальность:
создатель перешёл к **дискретной рекурсии** — «сколько процентов гибнет за
секунду от текущего населения» — простой, инвариантной к пересчётам и
однозначной (методологический промах, что не перешли к ней раньше).

### Контрольные точки R(T) (критерий ТЕСТЕРА, НЕ узлы для хардкодинга)

«Полное вымирание» = момент, когда `p₀·(1−R)^t < 1` для p₀ = 8·10⁹ (Земля):
`t_вымир = ln(p₀)/|ln(1−R)|` сек. Точки задают **логику** (монотонный рост R,
порядок «годы → часы → секунды»); формула — гладкая аналитическая, значения
в точках — БЛИЗКИЕ (допуск тестера: порядок).

| T, °C | Полное вымирание | R (за 1 сек) |
|---|---|---|
| +30 | **СПЖ 50 лет, полное ≤ 120 (потолок; было ~1000 лет)** | 6.34·10⁻¹⁰ |
| +70 | 100 лет | 6.6·10⁻⁹ |
| +100 | 2 дня | 1.2·10⁻⁴ |
| +200 | 5 часов | 1.15·10⁻³ |
| +300 | 1 час | 5.8·10⁻³ |
| +500 | 20 мин | 0.017 |
| +1000 | 5 мин | 0.067 |
| +2000 | 30 сек | 0.5 |
| +4000 | 5 сек | 0.98 |

R ∈ (0, 1), монотонно растёт с T. Ниже +30 °C — комфорт/естественная: рампа
[15, 30] °C → R = R_ест·(T−15)/15; T < 15 °C → R = 0 (комфорт; стык с холодом
на +30 описан в §Решение).

> **Контрольная точка «+30 → ~1000 лет» пересмотрена 2026-09-14** (реализация
> `change_components.go`): естественная компонента = R_ест = 1/СПЖ 50 лет ≈
> 6.34·10⁻¹⁰/сек + возрастной потолок 120 лет → полное вымирание ≤ 120 лет
> для ЛЮБОГО p0 (без артефакта ln p0). Температурные точки R_темп не менялись.

### Кривая R(T) — РЕШЕНИЕ: модульная сумма компонент (принята 2026-09-14)

**Структура (решение создателя):** изменение населения = сумма независимых
компонент —
`R_total(T) = R_ест + R_темп(T) + (будущие компоненты)`. `R_ест` —
отдельная константа (естественная компонента, СПЖ 50 лет), **не вшита** в
температурную формулу; `R_темп(T)` — чисто температурная (0 при T ≤ 30 °C).
Будущие компоненты складываются (положительные = прирост/рост населения,
`1−R > 1`).

**Формулы (приняты):**

```
R_ест = 1/СПЖ = 1/50 лет ≈ 6.34·10⁻¹⁰ /сек (2%/год)          — естественная компонента (СПЖ 50 лет)
R_натур_темп(T) = c·(T−30)²,  c = 5.94·10⁻⁹/40² = 3.71·10⁻¹²   — температурная «естественная зона»
R_тепл_темп(T) = 1 − exp(−a·((T−30)/100)^n),  a = 2.92·10⁻⁴, n = 2.581   — тепловая зона
σ(T) = 1/(1 + exp(−kσ·(T−T_сш))),  kσ = 1.0, T_сш = 90 °C          — сшивка зон
R_темп(T) = R_натур_темп(T)·(1−σ(T)) + R_тепл_темп(T)·σ(T),  T ≥ 30 °C;  R_темп = 0 при T ≤ 30 °C
R_total(T) = R_ест + R_темп(T),  T ≥ 30 °C
рампа: T < 15 °C → R_total = 0; 15–30 °C → R_total = R_ест·(T−15)/15 (только естественная)
```

Температурная «естественная зона» — квадратичная от T−30: `R_темп(30) = 0`
(гладкое включение, производная в нуле = 0), `R_темп(70) = 5.94·10⁻⁹`
(целевая R_total(70) = 6.6·10⁻⁹ минус R_ест) — полное вымирание ~100 лет.
Тепловая зона — та же, что в двухрежимной сшивке (держится 100…4000).
Сигмоида с центром 90 °C («порог кипения») делает переход гладким (C∞).
R_темп → 1 при T → ∞; R_total → 1 + R_ест (гипотетический предел).
Контрольные точки — критерий тестера, в коде их нет (никаких узлов).

**Варианты отклонены (история):** одна гладкая кривая (R_ест вшита в
формулу) — не модульна, естественная компонента неотделима; простые формы
(экспонента/степенная/Аррениус) — не держат скачок 70→100.

### Стык зон (проверка непрерывности)

В точке сшивки T_сш = 90 °C: σ(90) = 0.5, R_темп(90) = 0.5·R_натур_темп(90)
+ 0.5·R_тепл_темп(90) ≈ 0.5·(1.34·10⁻⁸ + 6.6·10⁻⁵) ≈ 3.3·10⁻⁵ — обе зоны
дают одинаковый вклад; R_темп непрерывна и гладкая (сигмоида C∞).
Монотонность: R_натур_темп и R_тепл_темп монотонно растут, σ растёт —
итог монотонен; R_total = R_ест + R_темп монотонен.

### Момент смерти (аналитический, рекурсивная модель)

```
p(Δt) = p_чек·(1−R)^Δt_сек   →  p < 1 → поселение мёртвое
t_смерти = ln(p0) / |ln(1−R)| сек от создания
дата_смерти = created_at + t_смерти
```

Формула выводится из `p0·(1−R)^t = 1` → `t = ln(p0)/|ln(1−R)|`. Согласовано
с событием «Вымерло» (`18b_settlement_log.md`, §«Дата смерти»): `t_death = computed_at +
ln(pop)/|ln(1−R)|` (заменяет прежние формулы через λ); `NDead` — механизм
разового обвала `18_needs.md` §18.3.1 (потребности/стабильность) остаётся
отдельно, к температурной смерти не привязан (порог температуры — p < 1).

### `uninhabitable`/витрина — «поселение не выживет»

**Решение: витринный порог «t_смерти(p₀) < 1 ч» → `uninhabitable = true`**
(жара): если поселение с текущим населением вымирает за час —
показывать «поселение не выживет» (проблема создателя «50 тыс. живут при
600 °C»). Условие: `R > 1 − exp(−ln(p0)/3600)`. Для p₀ = 10⁶: R > 3.8·10⁻³
→ T ≳ +300 °C. Механика гладкая — порог только витринный; админский
предпросмотр показывает t_смерти, а не «население живо». Холод — по-прежнему
λ = +Inf за 100 K (временно).

  обнуления по температуре нет (порог «p < 1» — на населении).

### Что меняется в коде (код пишет разработчик по этой спеке)

1. **`change_components.go` — компоненты вынесены в отдельный файл** (реализовано
   2026-09-14): `NaturalComponent`, `HeatTemperatureChangeRate`,
   `OtherChangeRate`, `ChangeComponents`; константы `LifeExpectancySeconds`
   (СПЖ 50 лет), `MaxLifespanSeconds` (возрастной потолок 120 лет).
2. **`mortality.go` — жаркая ветка:** прежние w/λs/полюсная формула
   **удаляются**; вводится **модульная сумма компонент** (решение 2026-09-14):
   `R_total(T) = R_ест + R_темп(T)`, где `R_ест = 1/СПЖ = 1/50 лет ≈ 6.34·10⁻¹⁰/сек`
   (2%/год, t50 ≈ 34.7 года) — отдельная
   константа, а `R_темп(T)` — температурная сшивка зон:
   `R_натур_темп = c·(T−30)²` (c=3.71·10⁻¹²), `R_тепл_темп = 1−exp(−a·((T−30)/100)^n)`
   (a=2.92·10⁻⁴, n=2.581), `σ = 1/(1+exp(−kσ·(T−T_сш)))` (kσ=1.0, T_сш=90 °C),
   `R_темп = R_натур_темп·(1−σ) + R_тепл_темп·σ` (0 при T≤30);
   рампа [15,30] °C — только `R_ест·(T−15)/15`, T<15 → 0.
   **Возрастной потолок:** `age = now − created_at ≥ MaxLifespanSeconds →
   p = 0` (компонента-ограничение, не доля).
   **Реализация — формулы, а не таблицы узлов** (никаких `piecewiseLinear`);
   структура кода отражает модульность (сумма компонент, будущие компоненты
   добавляются слагаемыми, положительные = рост). `TwoSidedSeverity`/
   `TotalLambda` для жары не используются.
2. **`Population`:** сигнатура меняется на рекурсивную:
   `Population(p0, r, deltaSeconds)` → `p0·pow(1−r, Δt_сек)`; guard
   `Δt ≤ 0 → p0`; **порог `p < 1 → 0`** (поселение мёртвое). Для холода
   (временно) сохраняется экспонента `exp(−λ·Δt)` — совместная формула
   `p = p_чек·(1−R_total)^Δt·exp(−Σλ_др·Δt)`; `r = R_total` (сумма
   компонент; при росте r < 0 — `pow(1−r, Δt) > 1` корректно).
3. **`NDead`/событие «Вымерло»:** температурная смерть — по порогу p<1;
   `NDead` остаётся механизмом `18_needs` (потребности), не температурным.
4. **`Uninhabitable`:** витринный порог «t_смерти(p₀) < 1 ч» (см. выше).
5. **Сериализация/фронт:** сервер отдаёт **`r_per_sec` = R_total(T_планеты)**
   (одно число — рекомендация: сумма компонент считается на сервере, клиент
   делает один `pow(1−r, Δt)`; раздельная передача r_ест/r_темп модульнее,
   но клиенту нужна та же сумма — выгоды нет, пока нет знаковых компонент)
   + прежние λ_др; клиент: `p = p_чек·(1−r)^Δt_сек·exp(−λ_др·Δt)` —
   `extrapolate.js` меняется: для жары `pow(1−r, Δt)` вместо `exp(−λ·Δt)`
   (защита `isFinite`; при росте r<0 pow > 1 — допустимо).
6. **`w`-сброс удалён** — двухфазность выражается самим R (при большом R за
   первую секунду гибнет R·p₀).

### Критерии готовности — тесты (дополнение к §Критерии готовности)

`mortality_test.go` (жара, R-модель; **допуск на якоря — порядок/±50% от
ориентира контрольной точки**):

1. `TestRTotalCurve` — R_total по формуле в контрольных точках с допуском:
   R_total(30)=6.34·10⁻¹⁰ (±50%, = R_ест = 1/СПЖ 50 лет); R_total(70)=6.6·10⁻⁹ (±50%);
   R_total(100)≈1.16·10⁻⁴ (±50%); R_total(200)≈1.15·10⁻³ (±50%);
   R_total(500)≈0.016 (±50%); R_total(2000)≈0.47 (±50%);
   R_total(4000)≈0.98 (±50%); R_total(288 K)=0; R_total(303 K)=R_ест;
   рампа: R_total(295 K)=R_ест·7/15.
2. `TestRTempIsZeroBelow30` — **R_темп(30)=0**, R_темп(25)=0 (рампа — только
   R_ест: R_total(25)=R_ест·10/15); R_total(15)=0.
3. `TestRModularity` — R_total = R_ест + R_темп (проверка декомпозиции:
   R_темп(70) = R_total(70) − R_ест = 5.94·10⁻⁹); будущая компонента
   складывается: R_total_new = R_total + r_компонента.
4. `TestRMonotonic` — R_total монотонно растёт на [15, 4000] °C; R_total < 1
   при конечных T (R_ест + R_темп < 1 + R_ест).
5. `TestRSpliceContinuity` — стык зон: R_темп непрерывна в 85–95 °C (нет
   скачка); σ(90)=0.5; производная непрерывна (сигмоида C∞).
6. `TestRPopulation` — `Population(1000, 0.00115, 3600) == 1000·(0.99885)^3600`

7. `TestRDeathThreshold` — `Population(1, 0.00115, 3600) < 1` → 0;
   `Population(0.5, r, Δt) == 0`.
8. `TestREtalonTimes` — «полное вымирание» `ln(1e9)/|ln(1−R_total)|`:
   +30 → ≤ 120 лет (возрастной потолок; НЕ ~1000 лет от ln p0), +70 → ~100 лет,
   +100 → ~2 дня, +200 → ~5 ч, +500 → ~20 мин, +2000 → ~30 сек, +4000 →
   ~5 сек (допуск «порядок»).
9. `TestNaturalLife` — естественная компонента: R_ест = 1/СПЖ = 1/50 лет =

10. `TestDeathMomentR` — t_смерти: p0=1000, R=0.00115 → t = ln(1000)/0.00115
