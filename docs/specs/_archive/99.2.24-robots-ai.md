## 1. Цель и скоуп

Спроектировать новое семейство рас **«Роботы и AI»** — 10 рас (50 → 50+), карточки в
формате 99.2.21 §3.1 с новым слоем потребления **`robotic`** (энергия + сырьё вместо
13 биоосей) и первым исключением из кластерной модели (§7.1: территория по условиям
среды, не по соседству). Семейство строится **от контраста по всем осям** (кредо
создателя: «они вообще не обязаны иметь что-то общее; первичная генерация семейств
показалась мне блеклой»), **стержня нет** — это явный список, не кластеризация §6.

**В скоупе:** схема слоя `robotic` (поля/типы), 10 карточек (окна T/P/рад/яды,
атрибуты, robotic, home, bulge, forage-каркас), поле `territory` (исключение из
regions.race_id-модели, концепция), флаги механик-кандидатов как данные карточки,
инварианты, границы, решения белых пятен конспекта.

**НЕ в скоупе (границы — §7):** код/миграции/конфиги (карточки в `config/races.json`
ложатся при разработке); голос/личность/стиль общения; конкретные ресурсы и числа
слоя `robotic.materials` (каркас, данные при 99.2.5); механики-кандидаты
(heat_twist, «выключенные» колонии, агрессия при голоде) — только флаги в карточке
и описание, реализация отдельными фичами; догма 19.5 (заводы игрока) — не трогается;
числа баланса (проверит @balancetester на гейте; здесь — предположение дизайнера).

## 2. Природа сущности — разбор по правилу «сущность с двумя экземплярами»

1. **Природа.** Семейство роботов — **справочные записи каталога** (10 карточек в
   `config/races.json`, как 50 био-рас 99.2.21 §2), НЕ событие и НЕ лог. Проявление
   в мире — поселения (`settlements.race_id`, существующая схема). «Вымерло» —
   запись лога поселения (`settlement_log`, механизм 18b), раса остаётся в каталоге.
   Слой `robotic` — **атрибут карточки** (данные), не отдельная сущность.
2. **Владелец.** Одна раса → много поселений (1:N, как у био-рас). Расширяемость
   закладывается сразу: `robotic` — блок карточки, 51-я раса роботов = новая запись
   каталога, схема не меняется.
3. **Расширяемость.** 10 типов сразу — каталог с типами. Схема переживает 11-ю
   расу роботов и 51-ю био-расу по построению. Поле `territory` — опциональное
   (дефолт `"adjacency"`), био-расы не трогаются.

**Анти-ловушка «сущность вне игры»:** сущность «конфигуратор подкрутки» (99.2.22)
в игре отсутствует, но на числа карточек **не влияет** (это потребитель карточек,
не вход) — двойного учёта нет. Сущность «ресурсная модель 99.2.5» — каркас
`robotic.materials.basic_resources` пуст, в числа не входит. Механики-кандидаты
(§8) — флаги в карточке, в текущие числа не входят (анти-двойной учёт).

## 3. Карточка робота — расширение схемы 99.2.21

Карточка робота = карточка 99.2.21 §3.1 **минус** `consumption` (13 биоосей,
пуст) **плюс** блок `robotic` и три опциональных поля. Био-расы не меняются.

### 3.1. Слой robotic — схема полей

```
robotic: {
  power_source: [string],      // ≥1: "солнце" | "геотерма" | "реактор" | "термопары" | "тепло"
  materials: {
    categories: [string],      // категории ресурсов 09_resources §9.1.3: 🪨 ⭐ 🔥 💨 💧 🌿
    axes: { ось: "high"|"low" },   // оси свойств §9.1.2 (10 осей), направление окна
    basic_resources: []        // каркас: конкретные ресурсы при 99.2.5 (как forage.basic_resources)
  },
  heat: string,                // "радиаторы" | "горячая_работа" | "лёд" | "среда"
  heat_twist: bool             // подъём T планеты у больших колоний (механика-кандидат, §8.1)
}
```

- **power_source** — массив (основной + резервный). «Тепло» = раса живёт теплом
  среды (работа горячими, тепло как богатство — полюс оси из конспекта).
- **materials.categories** — «что ест» из категорий ресурсов (бытовые «металлы/
  кремний» в данных отсутствуют — поправка создателя, зафиксирована в 73a).
- **materials.axes** — «какие свойства важны»: ось из 10 + направление окна
  («проводимость high» = нужно проводящее). Числовые окна — при 99.2.5.
- **heat** — способ сброса тепла: радиаторы / работа горячими (1000+ K) / лёд
  (испарение льда как охлаждение) / среда (холодный мир сам — радиатор).
- **heat_twist** — флаг механики-кандидата «большие колонии поднимают среднюю T
  планеты» (вред соседям при подселении). Данные карточки, механика — §8.1.

### 3.2. Поле territory — территория по условиям

```
territory: "adjacency" | "conditions"    // дефолт "adjacency" (био-расы, 99.2.21 §7.1)
```

У всех 10 роботов — `"conditions"`: территория расы определяется **условиями среды**
(окна карточки), а не соседством кластеров; территория разорванная/разбросанная.
Это первое исключение из regions.race_id-модели (99.2.21 §7.1) — концепция в §5.

### 3.3. Флаги механик-кандидатов (данные карточки, не числа)

```
dormancy: bool           // «выключенные» колонии: полностью мёртвые, перезапуск за ресурсы (§8.2)
famine_aggression: bool  // абсолютная агрессия ко всем при сырьевом голоде (§8.3)
```

Флаги инертны до реализации механики; в текущие числа не входят. Не прятать в
числа (не выражать «агрессией 100» — теряется условность «при голоде»).

### 3.4. Стык robotic.materials с forage.basic_resources (99.2.5)

- `forage` у роботов заполняется как у всех: `source` (описание корма),
  `works_where` = «окна выживания расы», `basic_resources` = **пусто**.
- Конкретные ресурсы роботов живут в **`robotic.materials.basic_resources`**
  (тот же хук универсального слоя 99.2.5 §9.2.2, что и `forage.basic_resources`
  био-рас, но в слое роботов). При 99.2.5: ресурсы подбираются по
  `materials.categories` + `materials.axes` (окна свойств), результат ложится в
  `basic_resources`. Двух пустых хуков не плодим: у роботов заполняется один —
  в `robotic.materials`.

## 5. Кластерная привязка — исключение из модели (концепция)

Решения создателя (73a, тема 2; уточнение 2026-09-17): своя территория есть, но
**по условиям среды, а не по соседству** (вариант Б); территория
разорванная/разбросанная; **разные роботорасы стремятся не жить рядом**
(рассеивание по галактике) — правило мягкое: соседство допустимо как
маловероятная случайность, жёсткого запрета нет (решение создателя 2026-09-17).
Это первое исключение из 99.2.21 §7.1 (regions.race_id = территория по соседству).

**Как выражается (концептуально, не код):**

1. **Назначение кластеров** (regions.race_id) — как у всех рас: роботы получают
   кластеры-дома (решение создателя «раса-дом своих кластеров»). Конфигуратор
   99.2.22 работает по карточкам роботов без изменений (ручки 1/3/5/7 из окон
   T/P/home.star_classes; обогащение газов не срабатывает — need у роботов пуст;
   тепло-ручка 4 — только у Горнила, heat_flux Lo > 0).
2. **Новое правило назначения — стремление к рассеиванию (мягкое):** разные
   роботорасы стремятся не назначаться в соседние кластеры (рассеивание по
   галактике); соседство допустимо как маловероятная случайность, жёсткого
   запрета нет (решение создателя 2026-09-17). Ограничение на этапе раздачи
   race_id, не на этапе поселений. **Best-effort:** при невозможности разнести
   все 10 роботорас (малая галактика и т.п.) — разносится сколько возможно,
   остальные назначаются в любые свободные территории; в отчёт генерации
   добавляется пометка о неразнесённых расах.
3. **Размещение поселений** — для `territory: "conditions"`: поселения расы
   размещаются не только в кластере-доме, но в **любом регионе**, где планеты
   проходят `Race.Suitable` (конъюнкция surv-окон + атмосфера, 99.2.21 §16.4).
   Кластер-дом — зона максимальной плотности (подкрутка 99.2.22 даёт там больше
   подходящих планет); остальное — рассеянные поселения по условиям среды.
   Регионы вне кластера-дома ищутся перебором по всем регионам (планеты проходят
   `Race.Suitable`), выбор детерминирован по seed; приоритет плотности
   кластера-дома обеспечивает подкрутка 99.2.22, а не код поселений. Территория
   разорванная/разбросанная по построению.
4. **Совпадение окон двух роботорас** на одной планете: селится один робот.
   Приоритет у расы-дома кластера; если раса-дом непригодна на этой планете
   (не проходит `Race.Suitable`) — робот, чей кластер-дом ближайший к планете
   и при этом проходит `Race.Suitable`; если ни один не проходит — поселения
   роботов на планете нет (пусто). Выбор детерминирован по seed. Две роботорасы
   на одной планете не селятся (кустов из нескольких роботорас не возникает).
5. **Сосуществование роботов с био-расами** — выводится из карточек как обычно
   (99.2.21 §16.5): пересечение окон + отсутствие взаимных ядов. 52/58/60
   (O₂/H₂O-яд) не сосуществуют с людьми; 51/56 — могут.

Пометка для 53a (легаси-коррекция 99.2.21 §7.1): исключение «территория по
условиям» — расширение модели, не ломка общего правила; био-расы не меняются
(дефолт `territory: "adjacency"`).

## 6. Инварианты

1. **Окна:** `opt ⊆ surv` по каждой оси; `surv` в пределах диапазонов каскада

   **off_cascade-пометка не требуется** (решение по слоту 4 — §9.1).

5. **territory = "conditions"** у всех 10 роботов; био-расы — дефолт "adjacency"
   (не-регрессия).
6. **Пригодность планеты** = конъюнкция surv-окон + атмосфера (99.2.21 §16.4) —

7. **Сосуществование** выводится из карточек (пересечение окон + отсутствие

8. **Флаги механик-кандидатов** (heat_twist, dormancy, famine_aggression) — данные

## 8. Механики-кандидаты (вынесены, не прятать в числа)

Три механики из конспекта оформлены как **флаг в карточке + описание кандидата**.
Флаги инертны; реализация — отдельные фичи после ресурсной модели (99.2.5) и
R-модели рас (99.2.23).

### 8.1. heat_twist — подъём T планеты (флаг у 53, 57, 58, 60)

Большие колонии расы поднимают среднюю T планеты (сброс тепла в масштабе
планеты): «мирные, но сильно мешают жить другим расам, если присоседились
поселением». У кого флаг: Горнила (работа горячими ~1500 K), Миры-машины
(инфраструктура всей планеты), Санитары (заводские рои), Эхо чужих (чужой
субстрат). Механика: дельта T планеты от населения/производства колонии →
сдвиг окон соседей. Числа — при реализации.

### 8.2. «Выключенные» колонии (флаг dormancy у 54 Спящие)

Колония полностью мёртва (не «вымерла», а выключена), перезапуск = привезти тонну
ресурсов. Механика: находка игроком спящей колонии → вложения → перезапуск →
поселение расы (новая рабочая сила; не заводы игрока — догма 19.5 не нарушается).
Числа — при реализации.

### 8.3. Абсолютная агрессия при сырьевом голоде (флаг famine_aggression у 52, 58)

При нехватке сырья агрессия расы становится абсолютной ко всем (био и не-био):
«вы — сырьё». Не выражается базовой агрессией (85/70 — база, при голоде → 100
условно). Механика: условие голода → модификатор агрессии. Числа — при реализации.

## 9. Белые пятна конспекта — решения

### 9.1. Слот 4 «Сверхпроводники 4 K» — ниже каскада (решено: сдвиг в каскад)

**Решение: сдвиг окна в каскад — T opt [20, 35], surv [20, 50] K, без
off_cascade-пометки.** Обоснование:

- Пол каскада 20 K (кламп 99.2.20 §3.5) — планеты 20–50 K существуют (далёкие
  орбиты тусклых звёзд, мёртвые тела; F9 живёт на 20–200 K). Дыры в каскаде нет.
- «4 K» — **внутренняя температура субстрата** (криоохлаждение сверхпроводящих
  схем), инженерная деталь, не окно планеты. Планетное окно 20–50 K.
- off_cascade — тяжёлый флаг («планет в каскаде для расы нет», как раса 40
  Водородные с P 1000+). Для Спящих планет **есть** — пометка была бы ложной дырой.
- Хрупкая сторона — жара (> 50 K ломает сверхпроводимость). Пометка в карточке:
  bulge hot — единственное направление расширения (пол каскада 20 K).

**Гейт-вопрос создателю** (§13.1): подтвердить сдвиг 20–50 K (рекомендовано) или
настаивать на 4 K с off_cascade (тогда у расы нет планет в каскаде — дыра, как у
расы 40).

### 9.2. Веса полюсов происхождения (3/3/3/1) — подтверждено по-расово

Черновик «3/3/3/1» — опечатка счётчика: таблица слотов (принята, «Оставляй»)
даёт люди 1 / самозародившийся 4 / другие био 3 / другие ИИ 2 (см. §4.1).
Стратегии 3/3/4 подтверждены. Распределение зафиксировано по-расово.

### 9.3. Роботы вне кластеризации §6 — да, подтверждено

У роботов нет consumption-векторов (слой robotic — качественный, не 13-осевой
вектор) — евклидова кластеризация 99.2.21 §6 к ним неприменима по построению.
Семейство держится на явном списке от контрастов (кредо создателя). Зафиксировано
в инварианте 4.

### 9.4. «Хрупкая» сторона T по расам — распределена

Холод хрупок: 51, 52, 53, 56, 57, 58 (7 рас, bulge hot). Жара хрупка: 54, 55, 59,
60 (4 расы, bulge cold у 55/59/60; 54 — особый случай, §4.1 прим.¹).
