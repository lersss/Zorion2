## 1. Цель и скоуп

Подключить перенесённый UI студии (`web/studio.html`) к новому API игрового сервера
(`/studio/api/*`, JWT admin/skycomposer) и перевести витрину «Реальные вещества» (94a)
на чтение из БД. **Итерация B — UI-слой**: авторизация, маппинг контракта, «+ ресурс»,
второе подтверждение удаления, перенос OR-фильтров, адаптация e2e-смоука, витрина на БД.

**В скоупе B:**
1. `web/studio.html`: все вызовы `/api/*` → `/studio/api/*` (api(), fetchState, все
   действия); авторизация JWT (Bearer, localStorage `adminToken`, оверлей логина,
   401/403 поведение); маппинг полей старого UI → контракт iterA §7
   (категории / `category_id`, kind, слоты).
2. OR-фильтры справочника (коммит 5f9c7c2) — перенос вместе с UI, проверка на новом API.
3. «+ ресурс»: кнопка создания ресурса в справочнике (kind=resource, категория ресурсная,
   без слотов); попап ресурса — без слотов, с тир-полем, всеми статусами, удалением,
   переименованием, сменой категории (ресурсы без привилегий, идея §1.2).
4. Удаление — UI-слой второго подтверждения при `cleared_links > 0`.
5. Витрина «Реальные вещества» (94a): серверная часть — real/real_summary/families из БД
   (goods kind=resource с props JSONB); клиентская часть — проверка/правка resources.js.
6. e2e-смоук: новый файл `tools/e2e/goods-studio-server-check.js` под `/studio`
   (JWT, base-url, «+ ресурс», кириллица, OR-фильтры).

**НЕ в скоупе B (итерация C):** ИИ «заполнить комплектующие» (fill); импорт
top-каталога/деревьев Т8; экспорт JSON; удаление `cmd/goods-studio` + `goods_data/`;
перевод читателей Go-каталога на БД, кроме real-части витрины (слой 20, покрытие рас,
gaps, chemotypes — остаются в Go, §5.1); кнопки Экспорт/Импорт/ИИ — скрываются (§4.6).

## 4. Спецификация — студия на `/studio/api/*`

### 4.1. Авторизация (инлайн-копия паттерна админки, развилки 1–3)

**Токен:** `localStorage['adminToken']` (общий с админкой). Вход — `POST /login`
(публичный роут, main.go:274), ответ `{token, user:{role,...}}`. Роли — `admin`/`skycomposer`
(player → «Недостаточно прав»).

**Код (в `studio.html`, инлайн, ~60 строк, стиль auth.js):**
- `ADMIN_ROLES = ['admin','skycomposer']`; `studioToken` из `localStorage['adminToken']`.
- `ensureStudioAuth()` на старте: токен пуст → оверлей логина; иначе `GET /me` с Bearer
  → 401/!ok → сброс токена, оверлей; роль не admin/skycomposer → оверлей с текстом
  «Недостаточно прав: нужна роль администратора».
- `studioLogin()` из оверлея: `POST /login {username, password}` → !ok → «Неверный логин
  или пароль»; роль не та → «Недостаточно прав…»; ok → сохранить токен, скрыть оверлей,
  запустить `start()`.
- `studioFetch(url, options)` — аналог fetchWithAuth: добавляет `Authorization: Bearer`;
  на 401 — сброс токена, оверлей, тост «Сессия истекла — войдите снова».

**Интеграция:**
- `api(method, url, body)` (975): `fetch(url, ...)` → `studioFetch(url, ...)`.
- `fetchState()` (260): `fetch("/api/state")` → `studioFetch("/studio/api/state")`.
- Старт: вместо прямого `fetchState()` (1547) — `ensureStudioAuth().then(ok => { if (ok)
  start(); })`; `start()` = `fetchState()` + интервал (как сейчас).
- Оверлей логина: `position:fixed; inset:0`, z-index выше модалок, стиль — тёмная тема
  студии (адаптация admin.html:968–979: `studioLoginUsername`/`studioLoginPassword`/
  `studioLoginError`, кнопка «Войти», Enter в пароле).
- **401/403:** 401 — оверлей + тост «Сессия истекла»; 403 — тост с текстом сервера
  (`api()` уже показывает `e.error`).

### 4.4. OR-фильтры справочника — перенос без изменений логики

- Логика `renderSprav` (1107–1157) переносится как есть: пилюли тиров (`g.tier`), галки

### 4.7. Удаление — второе подтверждение при `cleared_links > 0`

Контракт: `DELETE /studio/api/goods/{id}` → `{deleted: id, cleared_links: N}` (iterA §7).

1. Клик «удалить» → модалка 1: «Удалить товар «X»?» [Удалить][Отмена].
2. Если N > 0 (посчитано на клиенте: `state.goods.reduce(...)` — слоты с `good_id === id`;
   код уже есть, строки 804/1053) → модалка 2 (заменяет модалку 1):

3. DELETE → из ответа `cleared_links`: тост «Удалено. Очищено ссылок: K» (K — из ответа;

   тост показывает фактический K из сервера (источник правды — ответ).

## 8. Инварианты

1. **БД — источник правды каталога (С1):** UI читает/пишет только `/studio/api/*`;
   Go-каталог — только сид; витрина real читает БД (real_summary пересчитывается из БД).
2. **Ресурс — лист:** UI не предлагает слотов/«+ слот»/fill ресурсу (сервер 403 — UI
   не обходит); «добавить родителя» разрешено (ресурс как составляющая).
3. **Категория соответствует kind:** селекты разделены (товар → товарные, ресурс →
   ресурсные); серверные 400/403 — тост, не обход.
4. **Имена уникальны:** 409-тост, поле возвращается к прежнему значению (как сейчас).
5. **Тиры:** отображение — по серверным `g.tier`/`SlotView.Tier` (эффективный);
   клиент тиры не считает (М5); оверрайд ресурса — через тир-поле (С3).
6. **Статусы:** бан/разбан в один клик; забаненные скрыты из справочника по умолчанию
   (галка «забаненные»); «Вернуть» — в попапе.
7. **Удаление:** второе подтверждение при N > 0; фактический счётчик — из ответа
   `cleared_links`; удаление атомарно на сервере (iterA §9).
8. **Одна активная ИИ-генерация** — не в B (fill скрыт; `generating:false`).
9. **Авто-обновление без сброса выбора/зума/пана/попапа/модалок** (как сейчас).
10. **localStorage `gs_*`** — ключи и значения не меняются (переживают перенос).
11. **Фильтры OR** — семантика «тир + галка обязательны; галки OR-группы; категория/
    поиск AND» не меняется (перенос 1:1).
12. **Каталог не очищается** (ClearUniverse не трогает categories/goods/goods_slots —
    iterA §12.10).
13. **Витрина 94a:** real — из БД; слой 20/chemotypes/покрытие — из Go до C;
    пользовательские ресурсы без props в витрину не попадают.
