## 1. Проблема: пресеты-фильтры не изолируют гипотезу

Пресеты генерации поселений (65a: старый генератор скрыт — пресеты больше не используются) работали как **фильтры сверху**: брали случайную вселенную и отбирали планеты по правилам (AND по полям `planet.data`). Ловушка:

**Пример «Горячие ядра» (`young_worlds`).** Правило одно: `system_age ∈ [0.1, 2]`. Но:

1. Внутри пула — всё разнообразие вселенной: газовые гиганты, лёд, радиоактивные, жара, сушь. Все эти оси доминируют над дельтой населения сильнее, чем возраст ядра. Гипотеза «геотермальный ресурс держит фронтир» на таком пуле не читается: дельта — конгломерат десятков эффектов.
2. Корреляция «возраст → температура» зашита в сам генератор: молодое ядро греет в разы сильнее, а возраст берётся от спектрального класса — «молодость» в данных тащит за собой «жару».

**Вывод (решение игрока 2026-09-13):** пулы должны быть **детерминированными близнецами** — планеты групп идентичны побайтово, кроме ровно одной варьируемой оси. Тогда дельта атрибутируется одной оси без шума. Это полноценный инструмент анализа, на постоянное место в админке.

**Критерий успеха:** вкладка «Проверка гипотез» даёт «эксперимент + контроль» — два набора идентичных планет, отличающихся одной осью, с заданной стратегией поселений. Пул строится клонированием шаблона, а не фильтром.

## 2. Цель и не-цели

### Цель

1. **Генератор «близнецов»** — канонический шаблон планеты (`base`) клонируется N раз; в группе переопределяется ровно одна варьируемая ось + необходимые для консистентности поля.
2. **Подсистема «Проверка гипотез»** — вкладка в админке: очистка галактики, генерация миров/планет/поселений по TwinSpec, прогресс/отмена, тег группы в `data` для будущего анализа дельты.

### Не-цели

- **Не** переписывать природный генератор вселенной (`GeneratePlanetsForWorlds` и его путь) — остаётся как есть.
- **Не** реализовывать экономику/дельту населения (`13_tiers_impl.md`) — инструмент строит **тестовый полигон**; чтение дельты — следующий этап.
- **Не** создавать заводы/товары: гипотезы вокруг населения, заводы — отдельная ось.
- **Не** сохранять историю экспериментов в БД. Универсум транзиентный: следующий прогон перетирает предыдущий.
- **Не** реализовывать «оазис» и прочие природные аномалии в близнецах: пул должен быть чистым по плану, а не «живым».

## 3. Генератор «близнецов»

### 3.1. Где живёт

`internal/generator/planet/twin.go` — `TwinSpec`/`TwinGroup` + `GenerateTwins`. Природный генератор не трогается.

### 3.2. Контракт (`TwinSpec`)

```jsonc
{
  "id": "young_worlds",
  "base": { "temperature": 288, "water_percent": 70, "...": "полный data-слой планеты" },
  "groups": [
    {
      "id": "young", "name": "Молодые",
      "overrides": { "system_age": 1 },           // ось + поля консистентности
      "planets_per_world": 1,
      "settlement": { "chance": 1.0, "population": { "kind": "fixed", "fixed": 100000000 } }
    },
    { "id": "old", "name": "Старые", "overrides": { "system_age": 10 }, "...": "..." }
  ]
}
```

- `base` — канонический шаблон `planet.data`. Клонируется побайтово; `overrides` группы перезаписывают поля.
- Внутри группы планеты идентичны; между группами отличаются только `overrides`.
- **Идентичность доведена до поселений**: население по умолчанию фиксированное (иначе планеты получают разный старт), `chance: 100` (все заселены).

### 3.3. Варьируемая ось

У пресета есть `axis` — поле, которым группы различаются по замыслу (например `system_age`). Оно же — обычное поле в `overrides`. В UI ось — дроп-даун всех полей реестра (`GET /admin/settlement-fields`), её можно сменить руками; смена синхронизируется в группе-близнеце. Ось может быть `null` — тогда варьируется только стартовое население (гипотезы «Реквием», «Сеятель-сеть»).

### 3.4. Звёзды

На группу — **одна звезда**; звезды двух групп стоят визуально рядом: группа i на координате `(i*600, 0)`. Реализм не нужен; регионы не создаём.

### 3.5. Тег группы в данных

Каждая сгенерированная планета получает в `planet.data`:

```json
"_experiment": { "id": "young_worlds", "group": "young" }
```

Единственная «память» об эксперименте в БД, для SQL-анализа дельты: `WHERE data->>'group' = 'young'`. Миграция не нужна — поле в JSON.

## 4. Подсистема «Проверка гипотез»

### 4.1. Бэкенд

`internal/handlers/admin_hypothesis.go`, джоб `generator.JobHypothesis` в `internal/generator/status.go`, `statusManager` переиспользуется.

**Конвейр (в фоновой горутине):**

1. `clearUniverseTx` — та же очистка, что в `GenerateUniverse`: TRUNCATE без CASCADE + явный список таблиц + временное снятие FK `users`.
2. `GenerateTwins(spec)` — звёзды и планеты-близнецы по группам.
3. Поселения: шанс + стратегия населения группы, вставка только в `settlements` (`uuid, planet_id, population, stability`). Заводы/товары не создаются.
4. После успеха — `h.recomputePlanetStats()` и `h.mapCache.LoadAsync(h.db)`.

### 4.2. Endpoint

```
POST /admin/hypothesis/run
{ "id": "young_worlds", "base": {...}, "groups": [...] }   // полный TwinSpec из тела
→ 202 { "status": "started" }
→ 409, если другой джоб уже крутится
```

Сервер принимает **полный TwinSpec** с фронта (фронт — источник правды пресетов, как в поселениях). Статус — `/admin/generate-status?job=hypothesis`.

### 4.3. Отчёт о «невозможных»

По завершении прогона аудит (движок `audit.Run` + `auditplanet.AllRules`) считает планеты с **High-проблемами** («глобальные противоречия»; оазис ≤1% и прочие объяснимые аномалии medium/low — не в счёт). Отчёт уходит в статус джоба (поле `report`) и показывается фронту: «Создано планет: N, поселений: M, невозможных: K (code ×n)».

Сопутствующие правки генератора для чистоты пулов:

- **Гейт `generateWater`** (`properties.go`): водные/ледяные гидросферы только в своём температурном окне (океаны/озёра ≤ 400 K, подлёдная/ледяной покров < 273 K), вне — 0. Природный генератор не меняется (температуры архетипов всегда в окне).
- **Порог `checkOceansInHeat`** (`audit/planet/checks_physics.go`): доля океанов `> 1%` — локальный оазис ≤1% объясним и «невозможным» не считается.

### 4.4. Фронт

- Вкладка «🔬 Гипотезы» в `web/admin.html`.
- `web/static/js/admin/hypothesisPresets.js` — 12 пресетов-«близнецов»: канонический шаблон `base`, `axis`, группы с `overrides` и поселениями.
- `web/static/js/admin/hypothesis.js` — крутилки как в поселениях: карточка группы = имя, варьируемая ось (дроп-даун), планеты у звезды, население (фикс/рандом), композиции «форма → процент» (селекты известных форм, зеркало `composition_forms.go`), свёрнутые «другие поля» (числовые/строковые, редактируемые; добавление полей; копирование ⇄ в группу-близнеца).
- Температура в UI — °C, в данных — K (конверсия на сборе, как в поселениях).

## 5. Формат пресета (пример «Горячие ядра»)

```jsonc
{
  "id": "young_worlds",
  "name": "Горячие ядра",
  "hypothesis": "Гипотеза возраста: возраст системы — скрытый запас энергии (геотерма)...",
  "axis": { "key": "system_age", "label": "Возраст системы", "unit": "млрд лет", "type": "number" },
  "base": { "temperature": 288, "water_percent": 70, "...": "полный data-слой" },
  "groups": [
    { "id": "young", "name": "Молодые", "axisValue": 1,
      "overrides": {}, "planets_per_world": 1,
      "chance": 100, "population": { "kind": "fixed", "fixed": 100000000 } },
    { "id": "old", "name": "Старые", "axisValue": 10,
      "overrides": {}, "planets_per_world": 1,
      "chance": 100, "population": { "kind": "fixed", "fixed": 100000000 } }
  ]
}
```

Правило «близнецов»: контроль повторяет эксперимент с точностью до варьируемой оси. Для гипотез, где ось ломает консистентность (температура на живой планете, стерильность и т.п.), baked-`overrides` правят композицию/тип/жизнь.

## 6. Что закрыто при реализации (2026-09-13)

1. **Генератор близнецов** — `internal/generator/planet/twin.go` (`TwinSpec`/`TwinGroup`, `GenerateTwins`, `tagExperiment`, звёзды рядом). Параметрический генератор с планами осей (первый заход) **заброшен как переусложнённый**: каскад и «разрыв корреляций» заменены клонированием шаблона.
2. **Конвейр** — `internal/handlers/admin_hypothesis.go` (`RunHypothesis`, `runHypothesisJob`), джоб `JobHypothesis`, маршрут `/admin/hypothesis/run`, статус через `GenerateStatus`.
3. **Отчёт о невозможных** — счётчики `EntitiesWithHighIssue`/`HighIssuesByCode` в движке аудита, поле `report` в статусе джоба.
4. **Гейт `generateWater`** + порог `oceans_in_heat > 1%`.
5. **Фронт** — вкладка «🔬 Гипотезы»: крутилки, композиции, «другие поля», копирование; 12 пресетов-близнецов.
6. **DoD**: `go build`/`go vet`/`go test ./...` зелёные; живой прогон: 2 звезды рядом, планеты внутри группы идентичны, между группами — только ось, 0 невозможных.

## 7. Открытые вопросы

1. **Перетирание универсума.** Эксперимент сносит текущую вселенную. Приемлемо для инструмента анализа (подтверждение в диалоге перед запуском).
2. **Число планет.** Дефолт 1 планета на звезду × 2 звезды = 2 планеты на группу — достаточно ли для статистики дельты? Калибровать на прогонах.
3. **Геотермальная ветка.** Для «горячих ядер» нужен атрибут `core.age`/`heat` на планете как **вход** в формулу прироста (будущий экономический слой).
4. **Термины тега.** `_experiment.{id,group}` — зафиксировать один раз (влияет на SQL-запросы анализа).
