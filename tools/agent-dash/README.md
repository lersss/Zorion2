# Живой учёт агентов (agent-dash)

Отдельный локальный веб-сервис: сколько денег, времени и рабочей памяти тратят
агенты проекта — по субагентам (ролям) и по фичам (дерево сессий: вкладка
менеджера + её подсессии). Игровой сервер не трогает, работает своим процессом.

Создан по идее `docs/gamedesign/ideas/100c...`. Сторож зацикливания — идея `100b`.

## Запуск

```powershell
.\tools\agent-dash\start.ps1
```

Открыть <http://127.0.0.1:8790>. Страница сама обновляется раз в 5 секунд.

Остановить — Ctrl+C в том же окне.

## Настройки (переменные окружения)

| Переменная    | По умолчанию                                    | Зачем                          |
| ------------- | ----------------------------------------------- | ------------------------------ |
| `OPENCODE_DB` | `%USERPROFILE%\.local\share\opencode\opencode.db` | хранилище сессий opencode      |
| `PORT`        | `8790`                                          | порт сервиса                   |
| `HOST`        | `127.0.0.1`                                     | слушает только локально        |
| `PROJECT`     | `Zorion`                                        | фильтр по каталогу проекта     |
| `GUARD_LOG`   | `<репозиторий>\.opencode\loop-guard.log`         | журнал сторожа зацикливания    |
| `GUARD_MEM_WARN` | `700000`                                      | порог памяти для полосы и напоминания |
| `GUARD_MEM_STOP` | `900000`                                      | порог памяти, на котором сторож гасит сессию |
| `DASH_RECENT_MIN` | `15`                                          | окно «текущей задачи» в минутах для повторов |
| `DASH_BATCH`  | `10`                                            | сессий за один шаг досчёта     |

## Что показывает

- **Активные сейчас** (верхний блок) — кто работает прямо сейчас: роль, сессия и
  её фича, цена, **дельта цены с прошлого обновления**, память, **полоса бюджета
  памяти** (процент и остаток до порога, на котором сторож гасит сессию),
  ответы, **повторы за окно задачи** (по умолчанию 15 минут — сколько раз агент
  повторил один и тот же вызов в текущей работе) и срабатывания сторожа.
  Повторы и сторож — плашками: серые при нуле, оранжевые при ненулевых, красные
  при большом числе. Цифры обновляются раз в 20 секунд, таймер активности —
  каждую секунду. «Активная» — последнее действие меньше 5 минут назад.
- **По субагентам** — роль, сессий, цена, ответов агента, пик рабочей памяти,
  вызовов инструментов, повторов, срабатываний сторожа, сжатий памяти, активность.
- **По фичам** — то же по дереву сессий: корень (вкладка менеджера) + подсессии
  разработчика/тестера/дизайнера и т.д. Цена фичи — сумма по дереву.
- **Последние сессии** — 40 самых свежих.
- Период: **сегодня / 7 дней / всё время**. Заголовки таблиц сортируют.

## Как считается

- Читается **только на чтение** живое хранилище сессий opencode (SQLite, WAL) —
  можно держать сервис открытым при работающих агентах.
- Данные **догружаются по ходу работы**: новые сессии, цена, память и время
  активности обновляются сами (тяжёлые счётчики изменившихся сессий
  пересчитываются в фоне). Перезапуск сервиса нужен только после его правки.
- Цена и память режутся по дням (по отметкам сообщений), поэтому «сегодня» — это
  настоящая активность за сегодня, а не цена всей сессии.
- **Повторы — счётчик за всю сессию целиком** (считается по истории вызовов), он не
  режется по периоду.
- **Срабатывания сторожа** берутся из журнала сторожа
  (`.opencode/loop-guard.log`, пишет сам сторож) и режутся по периоду. В карточках
  они разделены: «напомнил про бюджет» (мягкое предупреждение агенту),
  «обрезал вызов», «погасил сессию» (жёсткие вмешательства). В колонке «Сторож»
  таблиц — только жёсткие. Пока журнал появится, счётчики будут нулевыми —
  журнал наполняется с новых сессий после перезапуска opencode.
- «Пик памяти» — максимальный рабочий контекст агента (вход + чтение из кэша).
- Досчёт тяжёлых счётчиков идёт в фоне порциями после старта: сначала самые
  дорогие сессии, поэтому цифры появляются сверху вниз. Результат кладётся в
  `.cache.json` рядом с сервисом (в git не попадает) — следующий запуск стартует
  сразу, пересчитываются только изменившиеся сессии.

## Проверка

```powershell
cd tools\agent-dash
node stats.test.mjs
```

Прогон на синтетическом хранилище: агрегаты по ролям, дерево фич, период по
дням, повторы/сторож/сжатия, кэш, догрузка изменений вживую (38 проверок).
