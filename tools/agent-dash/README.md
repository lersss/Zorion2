# Живой учёт агентов (agent-dash)

Отдельный локальный веб-сервис: сколько денег, времени и рабочей памяти тратят
агенты проекта — по субагентам (ролям) и по фичам (дерево сессий: вкладка
менеджера + её подсессии). Игровой сервер не трогает, работает своим процессом.

Создан по идее `docs/gamedesign/ideas/100c...`. Сторож зацикливания — идея `100b`.
Цена идеи целиком (вкладка «Идеи») — идея `100e`.

## Запуск

```powershell
.\tools\agent-dash\start.ps1
```

Открыть <http://127.0.0.1:8790>. Страница сама обновляется раз в 5 секунд.

Остановить — Ctrl+C в том же окне.

## Настройки (переменные окружения)

| Переменная    | По умолчанию                                    | Зачем                          |
| ------------- | ----------------------------------------------- | ------------------------------ |
| `OPENCODE_DB` | `%USERPROFILE%\.local\share\opencode\opencode.db` | хранилище сессий opencode      |
| `PORT`        | `8790`                                          | порт сервиса                   |
| `HOST`        | `127.0.0.1`                                     | слушает только локально        |
| `PROJECT`     | `Zorion`                                        | фильтр по каталогу проекта     |
| `GUARD_LOG`   | `<репозиторий>\.opencode\loop-guard.log`         | журнал сторожа зацикливания    |
| `GUARD_MEM_WARN` | `700000`                                      | порог памяти для полосы и напоминания |
| `GUARD_MEM_STOP` | `900000`                                      | порог памяти, на котором сторож гасит сессию |
| `DASH_RECENT_MIN` | `15`                                          | окно «текущей задачи» в минутах для повторов |
| `DASH_RATE_MIN` | `60`                                            | окно «расхода в час» в минутах |
| `DASH_WORK_NOTE_MIN` | `15`                                      | порог активного времени сессии для жёлтой цифры |
| `DASH_WORK_WARN_MIN` | `30`                                      | порог для оранжевой цифры      |
| `DASH_WORK_BAD_MIN` | `60`                                       | порог для красной цифры        |
| `DASH_BATCH`  | `10`                                            | сессий за один шаг досчёта     |

## Что показывает

- **В шапке — расход в час**: цифра вида `$2.00/ч` — сколько денег ушло за
  последние 60 минут (`DASH_RATE_MIN`). Наводишь — видно окно. От кнопок периода
  не зависит: это живой темп трат.
- **Активные сейчас** (верхний блок) — кто работает прямо сейчас: роль, сессия и
  её фича, цена, **дельта цены с прошлого обновления**, память, **полоса бюджета
  памяти** (процент и остаток до порога, на котором сторож гасит сессию),
  ответы, **повторы за окно задачи** (по умолчанию 15 минут — сколько раз агент
  повторил один и тот же вызов в текущей работе) и срабатывания сторожа.
  Повторы и сторож — плашками: серые при нуле, оранжевые при ненулевых, красные
  при большом числе. Рядом с зелёным кружком — **живое активное время работы
  сессии** (часы и минуты без секунд); «N назад» (когда была последняя
  активность) — в подсказке при наведении. Цифра времени подкрашивается по
  длительности: больше `DASH_WORK_NOTE_MIN` (15) — жёлтым, больше
  `DASH_WORK_WARN_MIN` (30) — оранжевым, больше `DASH_WORK_BAD_MIN` (60) —
  красным; менеджера и диспетчера не красим (их вкладки по природе длинные).
  Цифры обновляются раз в 20 секунд, таймер активности — каждую секунду.
  «Активная» — последнее действие меньше 5 минут назад.
- **Токены** — карточка «Токенов за период (вх / вых)» (два числа) и отдельная
  карточка «Прочитано из кеша». Кеш-чтение показываем отдельно: оно на порядки
  больше входа/выхода, и смешивать их в одно число нельзя.
- **По субагентам** — роль, сессий, цена, токены (вход / выход) и кеш, ответов
  агента, пик рабочей памяти, вызовов инструментов, повторов, срабатываний
  сторожа, сжатий памяти, активность.
- **По фичам** — то же по дереву сессий: корень (вкладка менеджера) + подсессии
  разработчика/тестера/дизайнера и т.д. Цена и токены фичи — сумма по дереву.
- **Последние сессии** — 40 самых свежих.
- Период: **сегодня / 7 дней / всё время**. Заголовки таблиц сортируют.

## Вкладка «Идеи» — цена идеи целиком

Переключатель **«Обзор | Идеи»** в шапке. Вкладка «Идеи» отвечает на вопрос
«сколько мне стоила та или иная идея»: одну идею обычно разрабатывают в нескольких
вкладках менеджера, поэтому привязка — не к названию окна сессии, а к **файлу
идеи** `docs/gamedesign/ideas/*.md`, который сессия создала (`write`) или правила
(`edit`). Упоминание файла в тексте/контенте не считается — только сам вызов
записи (иначе чтение чужих идей даёт шум).

- **Линия идей** — список по убыванию цены: название, сколько файлов, сессий,
  ролей, цена, токены. Клик по линии раскрывает, из каких сессий сложилась цена,
  сколько съела каждая роль и какие файлы затронуты.
- **Склейка семей** — файлы вида «ведущий номер + необязательная одна буква +
  точка» считаются одной линией: `96a…96j` → `№96`, `100a…100d` → `№100`,
  `99a.3-…` → `№99`. **Дата-названные** файлы (`2026-09-25_…`) не склеиваются — у
  них ключ равен полному имени файла.
- **Атрибуция дерева сессий** (вкладка менеджера + её подсессии) — к семье, где
  затронуто больше всего файлов; при равенстве — к той, где файл **создан**
  (`write` сильнее `edit`). Каждая сессия считается ровно один раз, поэтому сумма
  цен линий + «Непривязанных» = общие траты. Прочие затронутые семьи — пометкой в
  детали, без деления цены.
- **Непривязанные** — деревья, не писавшие и не правившие ни одного файла идей
  (разговоры, разведка). Их цена показана отдельным блоком — деньги не теряются.
- Период — **сегодня / 7 дней / всё время** (цена режется по дням, как в «Обзоре»).

Привязка считается отдельно от `/api/stats` (эндпоинт `GET /api/ideas?period=…`),
чтобы тяжёлый проход не гонялся на каждом 20-секундном обновлении главной. Разбор
частей сессий кэшируется в `.ideas-cache.json` (в git не попадает), ключ — время
изменения сессии; первый проход по хранилищу может занять несколько секунд.

## Кнопка «дать работать» (индульгенция сторожа)

На плашке активной сессии и в таблице сессий есть кнопка **«дать работать»**:
сторож зацикливания слушается **только явного указания создателя** и действует
**на срок** — сброс счётчиков (повторы/память/файлы/семейства команд) и пропуск
проверок **до** порога памяти; гашения нет, контекст вкладки сохраняется. Цикл по
содержимому и порог памяти продлением не снимаются. Разбор — идея
`docs/gamedesign/ideas/2026-09-22_устойчивость-агентов-обёртка-шелла-и-разбор-зависаний.md`
§4a.

## Как считается

- Читается **только на чтение** живое хранилище сессий opencode (SQLite, WAL) —
  можно держать сервис открытым при работающих агентах.
- Данные **догружаются по ходу работы**: новые сессии, цена, память и время
  активности обновляются сами (тяжёлые счётчики изменившихся сессий
  пересчитываются в фоне). Перезапуск сервиса нужен только после его правки.
- Цена, память и токены режутся по дням (по отметкам сообщений), поэтому
  «сегодня» — это настоящая активность за сегодня, а не итог всей сессии.
  Токены считаются раздельно: вход, выход и чтение из кеша — три отдельные суммы
  (кеш показывается своей цифрой, а не суммируется со входом/выходом).
- **Повторы — счётчик за всю сессию целиком** (считается по истории вызовов), он не
  режется по периоду.
- **Активное время сессии** — тоже по сессии целиком: сумма промежутков между
  соседними сообщениями, но пауза дольше 10 минут в счёт не идёт (сон, ожидание
  человека не раздувают цифру). Считаем по всем сообщениям (роль неважна:
  opencode прячет служебные под ролью `user`). У живой сессии на странице к сумме
  добавляется текущий промежуток «сейчас − последнее сообщение» — счётчик тикает.
- **Срабатывания сторожа** берутся из журнала сторожа
  (`.opencode/loop-guard.log`, пишет сам сторож) и режутся по периоду. В карточках
  они разделены: «напомнил про бюджет» (мягкое предупреждение агенту),
  «обрезал вызов», «погасил сессию» (жёсткие вмешательства). В колонке «Сторож»
  таблиц — только жёсткие. Пока журнал появится, счётчики будут нулевыми —
  журнал наполняется с новых сессий после перезапуска opencode.
- «Пик памяти» — максимальный рабочий контекст агента (вход + чтение из кэша).
- Досчёт тяжёлых счётчиков идёт в фоне порциями после старта: сначала самые
  дорогие сессии, поэтому цифры появляются сверху вниз. Результат кладётся в
  `.cache.json` рядом с сервисом (в git не попадает) — следующий запуск стартует
  сразу, пересчитываются только изменившиеся сессии.

## Проверка

```powershell
cd tools\agent-dash
node stats.test.mjs
node ideas.test.mjs
```

`stats.test.mjs` — агрегаты по ролям, дерево фич, период по дням, токены
(вход/выход/кеш) по периодам, повторы/сторож/сжатия, расход в час, активное время
сессии, кэш, догрузка изменений вживую (54 проверки).

`ideas.test.mjs` — привязка к идеям: склейка семей (`96a+96c → 96`), приоритет
созданного файла, дата-названные не склеиваются, непривязанные деревья, нарезка
цены по периоду, кэш привязки (32 проверки).
